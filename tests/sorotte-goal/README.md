# そろってゴールのテスト

ルールのテスト（エミュレーター不要）と、隔離した Firebase エミュレーター＋Playwright の E2E。
**本番の Firebase には接続しない**（共通の `rtdb-utils.js` をエミュレーター向けに差し替えた写しを使い、本番あての通信が出たら失敗にする）。

| ファイル | 内容 |
|---|---|
| `engine.test.cjs` | ルール（かべ・とびら・重い箱・橋・カギ・星・同時におさえるスイッチ・3人以上で押す箱・詰み）、おまかせステージの形（2〜12人 × 3段階 × 60番 = 1,980個）、総当たりでクリアできること（2人はやさしい40・ふつう20・むずかしい12・げきむず12個、3人はやさしい4個と、3人で押す箱の入ったふつう1個。1人だけでは解けないことも）、とびらの先のカギ、ルームに置く形（1歩ごとに書く所だけを当てていくと同じ状態になる・こわれた値の読み方）。`node --max-old-space-size=6000 tests/sorotte-goal/engine.test.cjs`（総当たりがあるので3〜4分） |
| `e2e1.cjs` | 作成・参加・待合室（番号・むずかしさ4つ・設定・ホストも遊ぶ）・はじめる・1歩の同期・進めない1歩は書かない・ひとこと（一覧・吹き出し・5秒に1回・消える）・総当たりで見つけた手順でクリアまで・クリアの出し分け（ホスト／参加者／みんなにみせる画面）・finish は1回・次のステージへ・途中から入った人は次から・退出した人のコマをホストが動かす・入りなおし・やりなおす・読み込み直し（参加者・ホスト）・待合室へ・端末なしの参加者・ルームを閉じる・スマホ幅 |
| `e2e2.cjs` | 名前の検査（空・記号・同じ名前）・参加用のリンク・3人が同時に押しても食いちがわない（同じマスに2人いない・どの画面もサーバーと同じ）・ホストが切れている間は1歩も書かない（切断の検知を待つので1〜2分）・12人のステージ・13人目は入れない・いなくなった人のコマをホストがえらべる |

## 実行

作業フォルダ（リポジトリの外）を決めて、次の順に行う。Java（エミュレーターに必要）・Playwright の場所は環境に合わせる。

```bash
export SG_WORK=/tmp/sorotte-goal-e2e
export PLAYWRIGHT=（playwright のフォルダ）

# 1. 写しを作る（アプリを直すたびにやり直す）
bash tests/sorotte-goal/sync-site.sh

# 2. エミュレーターを起動する（別の端末で。設定とルールは作業フォルダに置く）
cp tests/sorotte-goal/firebase.json database.rules.json "$SG_WORK"/
(cd "$SG_WORK" && npx --yes firebase-tools@15.29.0 emulators:start --only auth,database --project demo-roomk-sg)

# 3. 1本ずつ流す
node tests/sorotte-goal/e2e1.cjs
node tests/sorotte-goal/e2e2.cjs
node tests/sorotte-goal/e2e3.cjs
```

- `E2E_PORT` を変えると、同じエミュレーターで2本を並べて流せる（例 `E2E_PORT=6892 node tests/sorotte-goal/e2e2.cjs`）
- ポートを別のセッションが使っていたら、相手は止めずに、`firebase.json`・`sync-site.sh`・`lib.cjs` のポートをそろえて変える
- 終わったらエミュレーターを止め、ポートが空いたことを確かめる

## 検査を書くときの注意

- **キーを押す前に、その画面がサーバーに追いついているのを待つ**（`e2e1.cjs` の `synced`）。相手の1歩が届く前に押すと、手元では「まだ進めない」と判定されて書かれない（とびらが開いた直後など）
- 画面の中でくじを引くときは、大きい数のかけ算を使わない（桁があふれて、同じ向きばかり押す。2026-11-13 に「同時に押すと進まない」と見まちがえた）
- 砂時計の残り時間は、ステージを始めてすぐは「3:00」のまま（エミュレーターは速いので、始めてから1秒たっていないことがある）。減ることを見るときは、少し待ってから読む
- サーバーの値の人には歩数（`n`）も入っている。場所をくらべるときは `x`・`y` だけを見る
