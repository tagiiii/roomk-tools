# ねむらせ基地の E2E

隔離した Firebase エミュレーターと Playwright で、ホスト・参加者を別々のブラウザとして動かして確かめる。
**本番の Firebase には接続しない**（ねむらせ基地の `firebase-config.js` をエミュレーター向けに差し替えた写しを使い、本番あての通信が出たら失敗にする）。

| ファイル | 内容 |
|---|---|
| `engine.test.cjs` | ルール（マップ・位置の形・役・勝ち負け・途中で抜けた人・票）。エミュレーター不要。`node tests/nemurase-kichi/engine.test.cjs` |
| `e2e1.cjs` | 作成・リンクで参加・名前の検査・待合室（設定・ロボット）・はじめる・役・歩く（1秒に3回まで・止まったら送らない・かべ・行き止まりの小部屋）・かべの向こうの人は描かれない（canvas の色）・仕事・停電・ねむらせる（位置が p から g へ）・ねむってからの仕事・見つけた（かべごしには出ない）・会議（会議中は送らない）・投票・結果・おしまい・待合室へ・会議ボタン・同じ数の票・ねむらせ屋の勝ち・時間切れ・幅 375px・ルームを閉じる |
| `e2e2.cjs` | 進行だけのホスト・ロボット（歩く・投票する）・途中から入った人（見学・位置を受け取らない）・読み込み直し・ウィンドウを閉じた人（在室と位置が消える・票を待たない・30秒で抜けた人になり、のこりの仕事が全体の数から外れる・投票の相手に選べない）・ホストの切断と戻り・ホストの読み込み直し・参加者が短く切れて戻る（位置を送り直す）・会議の途中の時間切れ・退出・ねむらせ屋がゲームの途中で退出すると隊員の勝ち（「ねむらせ屋がいなくなった」）・ロボットが歩いている途中でルームを閉じる（何も残らない） |
| `traffic.cjs` | 通信量（ホスト＋参加者1人＋ロボット6つの8人で40秒。参加者のブラウザが受け取った量から、8人の部屋の1時間あたりを見積もる。目標は40MB 以下） |
| `lib.cjs` | 共通の部品（配信用サーバー・本番あて通信の検出・WebSocket のフレームの量と位置の送信の数・画面の操作・マップの canvas の色を読む `pixelAt`） |
| `sync-site.sh` | `apps/shared` と `apps/nemurase-kichi` を作業フォルダに写し、接続先をエミュレーターに差し替え、テスト用に中の状態（`window.__NK__`）を読めるようにする（写しだけ。本体には入れない） |
| `firebase.json` | エミュレーターのポート（auth 9881・database 9882・hub 4881・logging 4981）。配信は 6881 |
| `rules.json` | **本番の `roomk-nemurase` のルールの正本**（コンソールに貼るのはこの中身）。軽い決まり: ルームコードの形の場所だけ・部屋の中は `r`・`p`・`g` だけ・位置は短い文字列だけ。`lib.cjs` がテストのはじめにエミュレーターへ入れる |

## 実行

作業フォルダ（リポジトリの外）を決めて、次の順に行う。Java（エミュレーターに必要）・Playwright の場所は環境に合わせる。

```bash
export NK_WORK=/tmp/nemurase-e2e
export PLAYWRIGHT=（playwright のフォルダ）

# 1. 写しを作る（アプリを直すたびにやり直す）
bash tests/nemurase-kichi/sync-site.sh

# 2. エミュレーターを起動する（別の端末で。設定とルールは作業フォルダに置く）
cp tests/nemurase-kichi/firebase.json tests/nemurase-kichi/rules.json "$NK_WORK"/
(cd "$NK_WORK" && npx --yes firebase-tools@15.29.0 emulators:start --only auth,database --project demo-roomk-nk)

# 3. 1本ずつ流す
node tests/nemurase-kichi/e2e1.cjs
node tests/nemurase-kichi/e2e2.cjs
node tests/nemurase-kichi/traffic.cjs
```

- 役・待ち時間・15分の時刻は、エミュレーターの `r/game` を直接書きかえて決める（`patchGame`）
- **ルールの入れ方**: エミュレーターは `firebase.json` の rules を、テストが使う名前空間（`ns=demo-roomk-nk`）には当てない（だれでも読み書きできる状態になる）。そのため `lib.cjs` の `loadRules()` が、はじめに `rules.json` を `/.settings/rules.json?ns=demo-roomk-nk` へ直接入れ、入ったことを確かめてから始める（2026-10-26 に気づいて直した。それより前のテストはルールなしで動いていた）
