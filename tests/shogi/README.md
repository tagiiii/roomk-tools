# 将棋の E2E

隔離した Firebase エミュレーターと Playwright で、ホスト・対戦する2人・観戦・みんなにみせる画面を別々のブラウザとして動かして確かめる。
**本番の Firebase には接続しない**（共通の `rtdb-utils.js` をエミュレーター向けに差し替えた写しを使い、本番あての通信が出たら失敗にする）。作りはリバーシの E2E（`tests/reversi/`）と同じ。

| ファイル | 内容 |
|---|---|
| `engine.test.cjs` | 盤のルール（はじめの局面からの手の数を既知の値と照合・二歩・打ち歩詰め・王手・成り・持ち駒・千日手・表記・入玉宣言・でたらめ対局）。エミュレーター不要。`node tests/shogi/engine.test.cjs` |
| `e2e1.cjs` | 作成・参加・席・観戦・みんなにみせる画面・盤えらび・補助・対局の同期・盤の向き・指せない理由・番でない人・1手もどす・投了・詰み・結果・もう一回（補助もついていく）・待合室へ・端末なしの参加者・本将棋の成り・幅 375px・退出・ルームを閉じる |
| `e2e2.cjs` | 対局中に入った人は観戦・古い選択が消える・ホストの切断と戻り・席の人の切断とホストが代わりに指す・席の名前は別の人に使えない・再読み込み（参加者・ホスト）・相手の番の投了・入玉宣言の流れ |
| `e2e3.cjs` | 1台の画面（盤えらび・名前・指す・成る・持ち駒を打つ・表記・盤の向き・1手もどす・読み込み直し・投了・詰み・終わった対局の読み込み直し・もう一回・盤と補助を変える・幅 375px） |
| `lib.cjs` | 共通の部品（配信用サーバー・本番あて通信の検出・画面の操作） |
| `sync-site.sh` | `apps/shared` と `apps/shogi` を作業フォルダに写し、エミュレーター向けに差し替える。ルールとエミュレーターの設定も写す |
| `firebase.json` | エミュレーターのポート（auth 9881・database 9882・hub 4881・logging 4981）。配信は 6881 |

## 実行

作業フォルダ（リポジトリの外）を決めて、次の順に行う。Java（エミュレーターに必要）・Playwright の場所は環境に合わせる。

```bash
export SH_WORK=/tmp/shogi-e2e
export PLAYWRIGHT=（playwright のフォルダ）

# 1. 写しを作る（アプリを直すたびにやり直す）
bash tests/shogi/sync-site.sh

# 2. エミュレーターを起動する（別の端末で）
(cd "$SH_WORK" && npx --yes firebase-tools@15.29.0 emulators:start --only auth,database --project demo-roomk-sh)

# 3. 1本ずつ流す（その2は切断の検知を待つので1〜2分かかる）
node tests/shogi/e2e1.cjs
node tests/shogi/e2e2.cjs
node tests/shogi/e2e3.cjs
```

- エミュレーターはルールを自動では当てないことがあるので、その1・その2ははじめに `.settings/rules.json` へルールを読み込ませる
- 詰みの局面は、決まった種のくじで作った5五将棋の記録をエミュレーターに直接入れ、最後の1手だけ画面で指す
- 入玉宣言の条件（27点法）はルールのテストで確かめる。その2では、条件の判定を差しかえて、ボタンから結果までの流れだけを見る
- ポートを別のセッションが使っていたら、相手は止めずに、`firebase.json`・`sync-site.sh`・`lib.cjs` のポートをそろえて変える
- 終わったらエミュレーターを止め、ポートが空いたことを確かめる
- 2026-11-14 の結果（二重レビューの指摘を直したあと）: ルール 14件・その1 67項目・その2 34項目・その3 32項目、すべて合格
