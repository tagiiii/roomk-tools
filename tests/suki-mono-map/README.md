# 好きなものマップの E2E

隔離した Firebase エミュレーターと Playwright で、ホストと参加者を別々のブラウザとして動かして確かめる。
**本番の Firebase には接続しない**（共通の `rtdb-utils.js` をエミュレーター向けに差し替えた写しを使い、本番あての通信が出たら失敗にする）。
ルール（`database.rules.json`）はエミュレーターに明示的に読み込ませるので、`sukimonomap_rooms` の名前空間がルールにあることも確かめられる。

## 実行

```bash
export SM_WORK=/tmp/suki-mono-map-e2e
export PLAYWRIGHT=（playwright のフォルダ）

# 1. 写しを作る（アプリを直すたびにやり直す）
bash tests/suki-mono-map/sync-site.sh

# 2. エミュレーターを起動する（別の端末で。Java が要る）
cp tests/suki-mono-map/firebase.json database.rules.json "$SM_WORK"/
(cd "$SM_WORK" && npx --yes firebase-tools@15.29.0 emulators:start --only auth,database --project demo-roomk-sm)

# 3. 流す（1回およそ1分ずつ）
node tests/suki-mono-map/e2e1.cjs
node tests/suki-mono-map/e2e2.cjs
node tests/suki-mono-map/e2e3.cjs   # およそ5分（実時間で2分待つ）
node tests/suki-mono-map/e2e4.cjs   # Node 22 以上（Node の WebSocket を使う）

# 説明スライドだけなら、エミュレーターなしで流せる（配信は 6923。SM_WORK を指定すると画面の写真を残す）
node tests/suki-mono-map/slides.cjs
```

## 切断の作り方（e2e2）

- 切断は、タブを別のページ（`about:blank`）へ移して作る。サーバーがすぐ気づくので待ち時間が短い。同じタブで戻れば sessionStorage が残っていて、同じルームに戻る
- 2分の期限は実時間では待たず、サーバーが切断を記録したあとで `hostDisconnectedAt` を2分5秒前へ書きかえて早送りする

## 通信が止まる形の作り方（e2e4）

- Playwright の `connectToServer` は、ページ側が閉じるとサーバー側もすぐ閉じるので、片側だけ開いた状態を作れない。サーバー側の接続は Node の `WebSocket` で自分で持ち、ページ側とのやりとりを中継する
- 「止める」は、両方向のやりとりを捨てる（どちらの接続も開いたまま）。「サーバーが先に気づく」はサーバー側だけ閉じる。「ブラウザがあきらめる」はページ側を閉じる（SDK がつなぎなおす）
- **ページがつなぎなおすと、サーバーは同じ端末の古い接続をその場で閉じる**（つなぎなおしのときに前の接続の番号を渡す決まり）。なので「つなぎなおしたあとで、古い接続の切断にサーバーが遅れて気づく」順番は起きない（2026-11-11 に確かめた）
- 送信したあとの切断は、transaction の送信（`"a":"p"` と `"h"` を含む）をサーバーへ通したあと、応答を捨ててページ側を閉じる（rtdb.md「作成・参加の送信後の切断」の再現方法）

## まだ確かめていないこと

- 本番のサーバーが、やりとりの止まった接続に気づくまでの時間（エミュレーターでは、こちらでサーバー側を閉じて作っている）
- 実際の日本語入力・Safari・実機のスマホ
