# しるしでヒント（試作）

状態: `drafts/` の試作（drafts は GitHub Pages に配信されないので未公開）。2026-10-19 作成・同日に個人戦へ作り直し。
**2026-10-19 オーナー承認で `apps/shirushi-hint/` に本体化した（アイコン68個・お題89個で確定）。本体の仕様の正本は `apps/shirushi-hint/AGENTS.md`。** この試作（BroadcastChannel のモック）と `tools/pick.html`（候補を選ぶページ）は記録として残している。
名前は「しるしでヒント」に決まった（2026-10-19 オーナー決定。ほかの案も出したうえで、この名前のままにした）。フォルダ名 `shirushi-hint` は本体に移すときに決める。**アイコンとお題は仮**で、本番の候補はオーナーが選ぶ。

伝える人がアイコン（しるし）を1つずつ出してお題を伝え、ほかの人は12個の候補から当てる個人戦。
少ないしるしで当てるほど点が高く、当てた人と伝えた人の両方に点が入る。一巡ごとに順位を出す。

**この試作は通信しない。** 同じブラウザでひらいたウィンドウの間だけでつながる（BroadcastChannel）。
別の端末どうしではつながらない。フォントとアイコンだけは、公開中のアプリと同じく Google Fonts から読み込む。

## 開き方

リポジトリのルートで次を実行する。

```bash
python3 -m http.server 8090
```

1. `http://localhost:8090/drafts/shirushi-hint/` を開き、ニックネームを入れて「ルームを作る」（ホスト）
2. 「リンクをコピー」を押し、同じブラウザの別のウィンドウでそのリンクを開いて「入る」（遊ぶ人が2人以上で始められる）
3. 画面共有するときは「みんなにみせる画面」を押し、ひらいたウィンドウを共有する（お題は映らない）

画面を更新したのに古い動きのままなら、`index.html` の `?v=` の値を上げる。

|---|---|

| 答え合わせ | まだ当てていない人が全員選んだら、そのしるしの答え合わせ。伝える人が次のしるしを出したときも締まる（待たなくてよい） |
| 消える候補 | だれかが選んではずれた候補は、全員の画面で消える（線を引いて「×」） |
| 点 | ①つ目で当てたら3点、②つ目で2点、③〜⑥つ目で1点。当てた人それぞれに入る。伝えた人は、最初に当たったしるしの点を1回だけもらう |
| はずれ | はずれるたびに1点減る（持ち点はマイナスになってもよい。マイナスは「−2点」と書き、赤い字にする）。「このしるしでは選ばない」は減らない。伝える人は減らない。はずれた人にだけ「はずれ（−1点）」と案内する |
| 終わり | まだ当てていない人がいなくなるか、6つ目の答え合わせが済むか、伝える人が「答えを見せる」を押したとき |

| 遊んでいる間 | 「伝える順番と点」に、参加した順で点を出す |

## 答えがなかったので仮に置いたこと

オーナーの確認が要る。試して違えば変える。

- **点の高さ**（3・2・1点）と**しるしは6つまで**
- **はずれの −1点は、そのしるしの答え合わせのときに引く**（選んだ時点ではない）。⑥つ目まで当たらずにはずれ続けると、1問で最大 −6点
- **伝えた人の点は、最初に当たったしるしの点を1回だけ**（当てた人の数では増えない）。何人に当てさせても同じなので、「みんなに分かるしるし」を出す理由は弱い。人数ぶん増やす案もあるが、2026-10-19 オーナーから「おまかせ」で今のままにした（人数ぶん増やすと、遊ぶ人数で点の差が大きく変わるため）
- **候補12個は、お題と同じなかまを6個まで（お題をふくむ）、残りをほかのなかまから選ぶ**。仮のなかまは5つ（生き物24・食べ物21・乗り物13・自然14・もの17）で、`data.js` の `kinds` にある。たとえばお題が「ハチ」なら、生き物が6個並ぶので、「動物」「虫」だけではまだ決まらない
- **はずれた候補はだれのはずれでも全員の画面から消える**（ほかの人のはずれが手がかりになる）
- **何を選んだかは、答えの画面でも出さない**（当たったしるしの番号だけ出す）
- **伝える順番は入った順**（ホストが遊ぶときはホストが最初）。途中から入った人は順番の最後に入り、次のしるしから当てられる
- **「答えを見せる」は確認あり**
- **一巡の順位はホストが「順位を見る」を押してから出す**（最後の問の答えの画面を見る時間を取るため）

## 端末がない子の参加（メンターが代わりに押す）

2026-10-19 オーナー判断。当てる人が自分の端末で候補を選ぶルールなので、端末のない子はメンターが代わりに操作する。

| 場面 | 作り |
|---|---|
| 待合室 | メンター（ホスト）が「端末なしの参加者を足す」で名前を足す（同じ名前は足せない・はじめる前なら「外す」）。「端末なし」の印はメンターの画面にだけ出す |
| メンターは進行だけ | 端末なしの子が1人でもいると、「自分もプレイヤーとして参加する」は外れて押せなくなる（メンターがその子のお題や選んだ候補を知るため） |
| 候補の記号 | 12個の候補に A〜L の記号を付ける（全員の画面・みんなにみせる画面）。端末なしの子は「C」のように言える |
| 当てる番 | しるしが出ると、メンターの画面に「代わりに押す」欄が出る。子ごとに A〜L と「選ばない」のボタン（消えた候補は押せない）。押すとその子が選んだことになり、点も −1点もその子につく |
| 伝える番 | メンターの画面に「○○さんが伝える番（代わりに選ぶ）」とお題の候補が出る。お題を選ぶと「○○さんのお題」と、しるしを出す道具が出る |
| 切断 | 端末なしの子は切れない扱い（答え合わせで待たれる。待てないときは、メンターが「選ばない」を押す） |

運用の想定（画面には書かない。本体にするときは AGENTS.md に書く）:
- 端末なしの子は、選んだ記号を**メンターへの個別のチャット**で伝える（声で言うと、何を選んだかがほかの子に分かってしまう）
- その子が伝える番では、メンターが**お題を個別のチャットで**知らせる。子が声で言ったしるし（「動物を出して」）をメンターが出す。しるしは全員に見えるので、声で言ってよい
- メンターの画面には端末なしの子のお題が出るので、画面共有は「みんなにみせる画面」のウィンドウで行う
- はじめる前だけ足せる（遊んでいる途中には足せない）

## 正式な候補を選ぶページ

`tools/pick.html`（サーバーを立てたまま `http://localhost:8090/drafts/shirushi-hint/tools/pick.html`）。
`data.js` のアイコン68個・お題89個を、はじめはチェック済みで並べる（`pick.js` の「追加の候補」に足したものは、チェックなしで並ぶ。今は空）。
2026-10-19 に挙げた追加の候補（アイコン23個・お題49個）は、オーナーの判断ですべて `data.js` に入れた。

- 使うものにチェックを付ける。アイコンの名前・お題の文字は押すと書きかえられる。お題のなかまは選びなおせる
- お題を足せる（同じお題は足せない）。なかまが6個より少ないと注意が出る
- 「2通り」は、選んだアイコンで2通り以上の伝え方ができるか、人が確かめた印（ゲームには入らない）
- チェックと書きかえはそのブラウザの localStorage に残る。「はじめにもどす」で最初の状態に戻る
- 「選んだ結果をコピー」で JSON をコピーする。チャットに貼ってもらえば `data.js` に反映する

追加の候補は AI が仮に挙げたもの（学校・勉強・こわいもの・恋愛を連想させるものは入れていない）。どれを使うかはオーナーが決める。
`tests/pick.cjs` で 19 項目を確かめた（アイコン68個がすべて記号で出る・選ぶ／外す・書きかえ・なかまの移動・足す・同じお題の注意・読み込み直しで残る・はじめにもどす・幅 375px・コンソールのエラーなし）。

## 仮のアイコン（68個）とお題（89個）

`data.js` にある。アイコンは Material Symbols Rounded（公開中のアプリと同じ）。

- 何の仲間？（20）: 動物・鳥・魚・虫・植物・食べ物・飲み物・乗り物・道具・建物・おもちゃ・スポーツ・音楽・空・天気・服・ゲーム・機械・画面・おかし・葉っぱ
- 色（12）: 白・黒・赤・青・黄色・緑・茶色・ピンク・オレンジ・紫・灰色・水色
- 形・大きさ（9）: 丸い・四角い・三角・長い・大きい・小さい・高い・つぶつぶ・細い
- ようす・動き（16）: 飛ぶ・水・走る・速い・熱い・冷たい・光る・音が出る・甘い・電気・回る・浮かぶ・見る・時間・料理・泳ぐ
- 場所・とき（11）: 海・山・空・町・夜・夏・森・家の中・冬・雨・公園
- お題（89）: 生き物24・食べ物21・乗り物13・自然14・もの17。はじめの40個の後ろに49個を足した（番号を変えないため）

**アイコンの絵や名前が、お題そのものに見える組**（そのしるし1つで当たりやすい）:
飛ぶ（飛行機の絵）→飛行機／夏（太陽の絵）→太陽／夜（月の絵）→月／空（雲の絵）→雲／スポーツ（サッカーボールの絵）→サッカーボール／
甘い（ケーキの絵）→ケーキ／公園（木の絵）→木／画面（テレビの絵）→テレビ／時間（時計の絵）→時計／光る（電球の絵）→電球／
料理（なべの絵）→なべ／冬（雪の絵）→雪／海→海／山→山。
2026-10-19 オーナーから「おまかせ」で、**お題もアイコンも消さず、お題ごとの「出せないしるし」にした**（`data.js` の `blocked`）。
雪は「冬」と「冷たい」（雪の結晶の絵）の2つを出せない。伝える人のアイコン一覧では、点線の枠と禁止の印で押せなくなる。
ホストの側でも、そのお題で出せないしるしは受けない。お題やアイコンを差しかえたら、この一覧も見直す

仮に選んだときに気づいたこと（選ぶときの参考）:

- 「おもちゃ」のアイコンは車の形（`toys`）だと「乗り物」とまぎれるので、パズルのピース（`extension`）にした
- 「空」が「空・天気」（何の仲間？）と「空」（場所）の2つにある。どちらかにまとめてもよい
- 「甘い」（`cake`）、「魚」（`set_meal`、皿の上の魚）は、絵から意味が伝わりにくいかもしれない。ラベルがあるので試作ではそのまま
- 人・顔・気持ちのアイコンは入れていない（気持ちを答えさせるお題にしないため）
- 候補を並べる遊び方では、**似たお題が同じ問に並ぶほど**しるしを考える楽しさが出る。お題を選ぶときは、どのなかまにも6個以上あると、同じなかまで候補をそろえやすい

## 試作の限界

- 同じブラウザのウィンドウの間でしかつながらない
- ゲームの状態はホストのウィンドウのメモリにだけある。ホストが読み込み直すとルームは閉じる
- 参加者の匿名の ID はタブごと。タブを閉じて開きなおすと別の人として入る（本体の RTDB では同じブラウザなら同じ人に戻れる）
- お題とだれが何を選んだかは全ウィンドウに届き、画面に出さないだけ（性善説。本体でも同じ扱いの想定）

## 本体にするときに決めること

`apps/` への移植と公開はオーナーの判断。そのときに決める点:

1. ツール一覧の利用シーンと説明文（名前は「しるしでヒント」に決定。「かぶらずヒント」と「ヒント」が重なるので、説明文で遊びのちがいが分かるようにする）
2. アイコンとお題の正式な候補と、お題のなかまの分け方（同じなかまを何個そろえるか）
3. 点の高さ・しるしの数・伝えた人の点の入り方
4. 着想元の書き方 → 2026-10-19 決定: 作り直した遊びは『コンセプト』と別物なので着想元としては書かず、早見表は系統ラベル（アイコン連想系）にした
5. 端末なしの子の運用（個別のチャットで記号やお題をやりとりする手順を AGENTS.md に書く）
6. スマホで、上のしるし・候補と、下のアイコンが離れる（伝える人の画面が縦に長い）
