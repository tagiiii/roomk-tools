# ひらめき大喜利（試作・仮の名前）

状態: `drafts/` の試作（drafts は GitHub Pages に配信されないので未公開）。2026-10-29 作成。
**名前・お題は仮。** フォルダ名 `oogiri` も本体に移すときに決める。名前に番組名（IPPON）は使わない。

お題に、思いついた答えを何回でも出す大喜利。出た答えは1つずつ、だれのか伏せてみんなの画面に出る。
「おもしろい！」を押した人が、押せる人の何割か（ホストが選ぶ）に届いたら「一本！」。順位も点もない。

2026-10-29 の要望「IPPONグランプリのような大喜利ができるツール」から、オーナーと相談して決めた形。
いまある [たとえグランプリ](../../apps/tatoe-gp/AGENTS.md)（1人1回答える→匿名で1票→点数と順位）とは別の遊び。

**この試作は通信しない。** 同じブラウザでひらいたウィンドウの間だけでつながる（BroadcastChannel）。
別の端末どうしではつながらない。フォントとアイコンだけは、公開中のアプリと同じく Google Fonts から読み込む。

## 開き方

リポジトリのルートで次を実行する。

```bash
python3 -m http.server 8090
```

1. `http://localhost:8090/drafts/oogiri/` を開き、ニックネームを入れて「ルームを作る」（ホスト）
2. 「リンクをコピー」を押し、同じブラウザの別のウィンドウでそのリンクを開いて「入る」
3. 画面共有するときは「みんなにみせる画面」を押し、ひらいたウィンドウを共有する

画面を更新したのに古い動きのままなら、`index.html` の `?v=` の値を上げる。

## 答えがなかったので仮に置いたこと

オーナーの確認が要る。試して違えば変える。

- **お題はホストが3つの候補から選ぶ**（「ほかの候補」で入れかえられる）。参加者がお題を選ぶ・自分でお題を書く、はまだない
- **答えは40文字まで**
- **1人が順番待ちにできる答えは2つまで**（1人が続けて出し続けて、ほかの人の答えが出なくならないように）。出た答えは数えない
- **一本の名前**: 押している間は、だれの答えか出さない（仲のよさで押すのを避けるため）。一本になったときだけ「○○さん」と出す。
  一本にならなかった答えは、「出た答え」の一覧でも名前を出さない（自分の答えには、自分の画面でだけ「あなた」の印）
- **押すボタンの名前は「おもしろい！」**。1つの答えに1回だけ押せる（取り消せない）
- **一本は3.5秒大きく出す**。そのあと次の答えへ。一本でないときは次の答えまで0.9秒あける
- **押せる人の数は、答えが出ている間に通信が切れたり参加のしかたを変えたりすると、その場で数えなおす**
- **ホストの確認**: 確認を待っている答えは、ホストの画面の「確認する答え」に名前つきで出る（ほかの人には出ない）。
  書いた本人の画面には「ホストが確認中」と出る。確認待ちと順番待ちを合わせて1人2つまで。
  締め切ったあと（時間・ホスト）も確認でき、確認待ちが残っているあいだは結果へ進まない（確認していない答えを結果に出さないため）。
  一本で区切ったあとに確認した答えは、画面に出さずに結果の「ほかに出た答え」に並べる
- **ホストは、このあと出る答えと、いま出ている答えを「かくす」ことができる**（まずい答えが出たとき用）。
  かくした答えは、書いた本人の画面にだけ「ホストがかくした」と出る
- **お題の区切りのはじめは「一本が出たら」**。一本が出たらその場で答えを締め切り、一本を出し終えたら結果へ。
  順番待ちだった答えは出さずに、結果の「ほかに出た答え」に名前なしで並べる
- **「時間で」は2分・3分・5分（はじめは3分）**。お題の下に「のこり 2:34」と出す。時間になったら答えを締め切り、
  順番待ちの答えが出終わったら結果へ。時間内は何回でも一本が出せる。時間が近づいても音は鳴らさない
- **どちらの区切りでも、ホストはいつでも「答えを締め切る」で区切れる**（一本が出ないときなど）
- **ホストが「答えを締め切る」と、新しい答えは出せなくなり、順番待ちの答えが出終わったら結果へ**
- **結果の画面**: このお題の一本（名前つき）と、ほかに出た答え（名前なし）。一本がなかったら「このお題では一本は出なかったよ」
- **おしまいの画面**: 「一本の数」（人ごと）と「お題ごとの一本」。2026-10-29 にオーナーが「人ごとの数を出す」と決めた。
  順位はつけず、参加した順に並べる。同日オーナー判断で**1本以上の人だけ並べる**（0本の子が目立たないように）。だれも一本がなければ「一本は出なかったよ」
- 遊んでいる途中からも入れる

## 端末のない参加者（2026-10-30 オーナーの依頼で追加）

スマホやパソコンで入れない子のぶんを、ホストが代わりに書いたり押したりする。しるしでヒント・ことばメーターと同じ考え方。

- ホストが「端末のない参加者」で名前を足す（4人まで。ほかの人と同じ名前は不可）。足せるのは**待合室と結果の画面**（お題の間）。
  **外せるのは待合室だけ**（おしまいの画面の一本の数が消えないように）
- 足した子は、ほかの参加者と同じく参加者の一覧に出る。「端末なし」の印はホストの画面にだけ出す（子どもどうしの画面で区別しない）
- 投票する人に数える（切断しない扱い）。はじめられる条件の「投票する人2人以上」にも入る
- 遊ぶ画面では、ホストの操作の枠のいちばん上に「端末のない参加者のぶん」を出す
  - 子ごとの「おもしろい！」: いま出ている答えに、その子のかわりに投票する。その子の答えには押せない（「本人の答え」）
  - 「代わりに答えを書く」: 名前を選んで書き、「代わりに出す」。ホストが書いたので確認はせず、そのまま順番に入る。順番待ちは1人2つまで（ほかの人と同じ）
- 一本になったら、その子の名前で出し、おしまいの画面の一本の数にも入る
- 進め方の想定: 子が答えや「おもしろい！」を**メンターへの個別のチャット**で送り、メンターが代わりに入れる（声で言うと、だれの答えか分かってしまう）。
  端末のない子がいると、ホストの画面に名前が出るので、共有は「みんなにみせる画面」で行う（もともと届いた答えに名前が出るので同じ）
- 仮に置いたこと: 端末のない子が押さないままだと、その子も投票する人に数えるので一本が出にくくなる。気になるなら待合室で外す

## 画面の並び（2026-10-29 「UIUXがわかりづらい」を受けて作りなおし）

- **遊ぶ画面**: 上にお題（区切り・のこり時間・締め切りの案内もここ）。広い画面は2列で、左に「いま出ている答え」と「あなたの答え」（入力欄と自分の答えの状態を1枚にまとめた）、右にホストの操作と「これまでに出た答え」
- **ホストの操作**は、水色の点線の枠に「ホストの画面にだけ出ているよ」とまとめた（届いた答え・このあと出る答え・答えを締め切る・ここでおしまい）。せまい画面では「いま出ている答え」のすぐ下に出す
- 「いま出ている答え」に見出しと「おもしろかったら押して投票してね」の案内。みんなにみせる画面では「自分の画面で押してね」
- 投票だけで答えがない人には「あなたの答え」を出さない。参加のしかたは小さめにして、遊ぶ画面では自分の答えの下に置く
- **待合室**: 参加する人（＋参加用のリンクをコピー）→ ルール（一本になる数・お題の区切り。ホストだけ）→ あなたの参加のしかた → はじめる → あそびかた（5行）
- 2026-10-30「はじめてホストをする人でもわかりやすいか」を受けて:
  - 待合室にホストにだけ「ホストのすること」（画面共有は「みんなにみせる画面」で・お題を選ぶ・「みんなに出す」・「次のお題へ」）と「みんなにみせる画面をひらく」ボタン。
    ホストの画面には、だれの答えかが出るので、そのまま共有しないように
  - 遊ぶ画面のホストの枠の見出しにも「この画面は共有しないでね」
  - 「端末のない参加者を足す」は、参加する人のカードの中にたたんで置く（開くと出る）
  - お題を選ぶ・結果の画面の「あなたの参加のしかた」を、ほかのカードと同じ幅に
- 言葉は「押せる人」をやめて「投票する人」にそろえた。答えの一覧は「届いた答え」「このあと出る答え」「あなたの答え」「これまでに出た答え」

## 試作の限界

- 同じブラウザのウィンドウの間でしかつながらない
- ゲームの状態はホストのウィンドウのメモリにだけある。ホストが読み込み直すとルームは閉じる
- 参加者の匿名の ID はタブごと。タブを閉じて開きなおすと別の人として入る（読み込み直しなら同じ人に戻る）
- だれが何を押したか・だれの答えかは全ウィンドウに届き、画面に出さないだけ（性善説。本体の RTDB でも同じ扱いの想定）
- 時間はホストのウィンドウの時計で決める（本体では `.info/serverTimeOffset` を使う）
- テスト用に、ホストのアドレスに `?fast=1` を付けると、押せる時間（3分の1）などが短くなる。`?fast=1&min=2000` で「時間で」の1分を2秒にする

## 本体にするときに決めること

`apps/` への移植と公開はオーナーの判断。そのときに決める点:

1. 名前とフォルダ名・ツール一覧の利用シーンと説明文（たとえグランプリとの違いが分かるように）
2. お題（今は仮の104個。`data.js`。2026-10-29 にオーナーの「お題を増やして」で32個から足した）。お題のかたちを増やすか（「写真で一言」のような絵のお題など）
3. 押せる時間（10・15・20秒、はじめは15秒）・順番待ちの数（2つ）・答えの文字数（40文字）・区切りの時間（2・3・5分）
4. 端末のない子の参加（10-30 に試作へ追加。人数4人・足せる時・投票する人に数えるか）
5. 一本の数の並べ方（今は参加した順・1本以上の人だけ）
