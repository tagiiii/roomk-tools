# よく見て漢字（試作）

状態: `drafts/` の試作（drafts は GitHub Pages に配信されないので未公開）。2026-10-13 作成。
**2026-10-13 本体化済み**: オーナーの指示で `apps/yokumite-kanji/` に本体を作った（別の端末どうしでつながる）。現在の仕様の正本は `apps/yokumite-kanji/AGENTS.md`。このフォルダは試作の記録。
社会・理科の用語の漢字を、にせものの混ざった部品から組み立てるパズル。メンターは、子どもの
画面の動きを「見る画面」で見られる。

**この試作は通信しない。** 見る画面は、同じブラウザでひらいた2つのウィンドウの間だけでつながる
（BroadcastChannel）。別の端末どうしではつながらない。パズルの手ごたえと、見る画面の流れを
確かめるためのもの。フォントとアイコンだけは、公開中のアプリと同じく Google Fonts から読み込む。

## 開き方

リポジトリのルートで次を実行する。

```bash
python3 -m http.server 8090
```

1. `http://localhost:8090/drafts/yokumite-kanji/` を開く。一人で遊ぶなら、そのまま単元を選ぶ
2. 見る画面をためすときは、「見る画面をつくる（メンター用）」を押す（メンター側）
3. 「リンクをコピー」を押し、同じブラウザの別のウィンドウでそのリンクを開いて
   「見せてはじめる」を押す（子ども側）
4. 2つのウィンドウを横に並べて、子ども側でパズルを動かす

画面を更新したのに古い動きのままなら、`index.html` の `?v=` の値を上げる。

## きっかけと経緯（2026-10-13）

作戦会議で、中学1年生が国語以外の教科のテストで、漢字のまちがいで減点されたことが分かった。
計画支援コーディネーターから「進度に合った単元の漢字を学習すれば減らせるのでは」と提案があった。
字形を覚えていない様子で、本人は PC を使う。オーナーの心配は「書き問題にすると、書けないことで
自信をなくさないか」。

同じ外し方をくり返さないために、作り直しの経緯を残す。

| 版 | 内容 | オーナーの評価 |
|---|---|---|
| 第1版 | 見る → 似た字さがし → 見ながら紙に書く → かくして書く | 「全然面白くありません」。つまらない所は「ゲームが単調」「押すだけで受け身」 |
| 第2版 | 組み立てパズル。レベル3つ（部品＝見本あり／にせものあり／一画ずつ） | 「にせものありは面白い。部品と一画ずつは不要」 |
| 第3版（現行） | にせものありだけ。メンターの見る画面を足した | これから |

第1版の原因は、自信をなくさないようにと点数・時間・失敗を全部外し、手ごたえまで外したこと。
練習の手順にゲームの名前を付けただけだった。第2版から、遊ぶこと自体が字の形を覚えることになる
形にした。時間制限と記録（前回より速い・多い）は入れない（オーナー決定）。

置き場所は、はじめ `~/dev/roomk-programs`（特別プログラム集）に作った。見る画面には別の端末との
同期が要り、その公開先と Firebase がそろっているのは roomk-tools なので、こちらへ移した
（オーナー決定。作戦会議チャットと同じく、ツール一覧には載せない想定）。

## あそびかた

1. 単元を選ぶ（進度はアプリには分からないので、本人かメンターが選ぶ）
2. 語を選ぶ。語の中の「よく見る1字」がバラバラになる
3. 部品をドラッグして、わくの中の正しい場所で放すと、はまって黒くなる。正しくない場所では
   はまらず、置いた所に残るだけ（×は出さない）
4. 全部はまると、書き順どおりに字が書き直され、語と「見るポイント」が出る
5. 「紙にも書いた」は任意のチェック。押さなくても先へ進める

- 部品は、へん・つくりなどのかたまり3〜4個と、にせものの部品2〜3個。見本は出さない
- **にせもの**は、似た字（`data.js` の `sim`）の「ちがう所」を先に使う（「遣」に「遺」の「貝」、
  「墾」に「懇」の「心」）。まちがえやすい所そのものを、自分で選ぶ形にするため。足りない
  ときは、ほかの字の部品から借りる
- **見本を見る**は、押すと2.5秒だけ見本が出る。回数の制限も減点もない
- **同じ形の部品はどの場所にもはまる**（「晶」の3つの「日」）。見分けられないものを「ちがう」と
  返さないため。完成時に正しい形へ書き直す
- 画面に字を書かせない（マウスの字はだれでも崩れる）。紙に書くかどうかは本人が決める
- 点数・正解率・×印・時間制限・ランキング・音はない
- 組み立てた語には星が付く。記録は端末の localStorage（`yokumite-kanji:v2`）だけに残す。
  残すのは「組み立てた」と「紙にも書いた」だけ

## 見る画面（メンターが、子どもの操作を見る）

オーナーの希望: 「子どもの操作をメンターが観られると、より楽しい」。

- メンターがトップの「見る画面をつくる（メンター用）」を押すと、ルームコードができる。
  「リンクをコピー」で `?room=コード` の付いたリンクを子どもに送る
- 子どもがリンクをひらくと、「メンターの画面にも出る」ことの説明が出て、
  「見せてはじめる」「見せずに一人でやる」を選ぶ。**見せるかどうかは本人が決める**
- 見せている間は、子どもの画面の上に「メンターに見せています」の帯と「見せるのをやめる」が出る
- 見る画面には、子どもの今の画面（単元を選んでいる／語を選んでいる／パズル）がそのまま出る。
  パズルでは、部品の動き・はまった部品・「見本を見る」・完成が映る。見る側からは操作できない
- 送るのは、どの語か・にせものの部品・部品の位置・はまったかどうかだけ。名前は送らない
- 再読み込みしても、同じウィンドウなら元の役（見る側・見せる側）でつなぎ直す
- 名前とコードの手入力はない（1対1でリンクから入るため。ルーム型の「名前 → コード → 参加する」
  とはちがう。本体にするときに、このままでよいか決める）

### しくみ

`link.js` が「1つの木を、パスを指定して書きかえる」つなぎを受け持つ。見せる側が
`view`（今の画面）と `puzzle`（語・にせもの・部品の位置）を書き、見る側はそれを読んで同じ盤面を
組む。部品を動かしている間は、その部品の位置だけを 0.08 秒おきに送る。

## 語のデータ（`data.js`）

- 語は学習指導要領の単元から制作者個人が選ぶ。**教科書の一覧を写さない**。教科書会社は不明
- 「まちがえやすい」は見立てで、誤答の統計にもとづくものではない
- 見るポイントは1語に1つ。字の形についての事実だけを書き、書く前に字を調べて確かめる
  （例: 「徳」は14画で、「罒」と「心」の間に横線は入らない）
- 似た字（`sim`）は、へんやつくりの一部だけがちがう常用漢字を選ぶ
- 単元の `id` は記録のキーに使う。公開後は変えない。語を足すときは末尾に足す
- 教科書によって表記がちがう語（例: 「は虫類」と「爬虫類」）は、学校で求められる書き方を優先する
- 入っている単元（**見本・オーナー未確認**）: 理科「身のまわりの物質」12語、
  社会「古代までの日本」13語

## 字のデータ（`kvg-data.js`）

- KanjiVG（kanjivg.tagaini.net、© Ulrich Apel、CC BY-SA 3.0）の筆順データから作った二次的な
  データ。**このファイルも CC BY-SA 3.0**。画面下のクレジットを消さない
- 手で直さない。**字のデータを作り直す**ときは:
  1. `tools/build.py` の `TARGETS`（よく見る字）と `SIMS`（似た字）に字を足す
  2. KanjiVG の GitHub リポジトリ（KanjiVG/kanjivg）の `kanji/{5けたの16進}.svg` を、
     空のフォルダに取得する（取得はオーナーの許可を得てから。2026-10-13 に56字分を取得）
  3. `python3 -I tools/build.py <取得したフォルダ> kvg-data.js`
- 部品の分け方は KanjiVG の入れ子に従い、「3つ以上になるまで」「8画以上の部品がなくなるまで」
  大きい部品から分ける
- `data.js` の `k` に字のデータがない語は、一覧に出ない
