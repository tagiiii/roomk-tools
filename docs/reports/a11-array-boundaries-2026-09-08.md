# A-11 配列経由の追跡境界（2026-09-08）

## 対象と結論

基準は `92bf5e5`。直前に追加した `.trim()` の限定追跡から、配列経由で外部入力の根拠が失われる最初の地点を調べ、単純な配列リテラルから固定添字で取り出す raw の限定追跡を実装した。変更は検査器本体・恒久 fixture 20件・本記録。アプリ・共有コード・rules・lint は変更していない。配列要素の safe/html 認定は追加していない。

変更前は直接の外部入力から別名への代入は既存 fixture `DOM input through alias` 等で `raw` を保持した。一方、`const raw = location.hash; const values = [raw]; const picked = values[0];` では、添字参照より前の **`[raw]` の評価時点**で `unknown` になった。配列要素を保持する処理がなく、`statement()` は右辺が `unknown` の代入で `env.clear()` を行うため、配列だけでなく先に得た `raw` の根拠もここで失効していた。添字参照 `values[0]` も独立に未対応だった。

## 恒久ケースと観測

`scripts/tests/sec1-dataflow-fixtures.json` に20件を追加した。既存76件は変更していない。全件が複数行の直接 `innerHTML` テンプレートに `${picked}` を1つ持つ。既存ランナーは判定列に加え、検出件数・unknown件数・ERROR件数・終了コードを照合するため、sink を見落として0件になれば失敗する。

| 入力経路 | 現在の判定 | 固定する境界 |
|---|---|---|
| `[raw]` → `[0]` | raw | 新たに裸の外部入力を追跡する |
| `[escapeHtml(raw)]` → `[0]` | unknown | 同じ入力・sink のエスケープ有無の対。呼出し要素を安全認定しない |
| 配列変数を `other` へ再代入 | unknown | 古い要素の根拠を再利用しない |
| 配列の別名から `[0]` を上書き | unknown | 別名の副作用を見落として安全認定しない |
| 固定文字列/raw 混在配列を動的添字で読む | unknown | 添字が未確定なのに要素を選ばない |
| 空配列の `[0]` | unknown | 要素不存在を安全な値に近似しない |
| 1要素配列の `[1]` | unknown | 範囲外参照を安全な値に近似しない |
| `mutate(values)` 後の `[0]` | unknown | 未知の呼出し前の根拠を再利用しない |
| DOM列挙コールバック内で `push(input.value.trim())` | unknown | コールバック・収集・添字参照を一度に認定しない |
| 既知のエスケープ済み別名を配列へ入れる | unknown | 配列を経た safe/html 認定を追加しない |
| 固定文字列・数値の後にある raw 要素 | raw | 固定添字で選んだ要素だけを評価する |
| length変更／添字上書き／通常プロパティ書込み（3件） | unknown | 配列の根拠を失効させる |
| 穴／spread／呼出し要素／ネスト（4件） | unknown | 配列全体を認定対象外にする |
| `[raw, 'fixed']` の `[0]` ／ `[1]`（2件） | raw / unknown | 選択要素の区別と安全認定の不拡張 |

先頭の対は `escapeHtml(raw)` と `raw` 以外が同一。変更前はどちらも unknown だったが、裸の要素だけ raw へ更新した。呼出しを含む配列は未対応、事前にエスケープした別名でも結果は unknown である。unknown の期待値は解析限界を固定するもので、将来も対応を拒む仕様ではない。配列変更の対照ケースは対応対象の `[raw]` を起点とし、変更が入ると古い raw 根拠を使わないことを確認する。

変更前の読み取り専用 `evaluate()` プローブでも、`raw` は `raw`、`[raw]` は `unknown`、`escapeHtml(raw)` は `safe`、`[escapeHtml(raw)]` は `unknown` と観測した。`values[0]` は仮に既存 env の `values` を `safe` にしても `unknown` だった。`scan_js()` で配列代入直後に `${raw}` と `${values}` を置くと両方 unknown になり、単純別名だけを挟む対照では raw が維持された。これは検査器のローカル実行であり、fixture 内の JavaScript 自体は実行していない。

## 実装した保証範囲と失効

「同じ直線ブロック内で新しく作った単純配列リテラルを、変更せず、範囲内の整数リテラル添字で読む」までの要素単位の根拠を別表に保持する。要素は単一トークンの数値・文字列・既知 raw/safe/html の裸識別子に限定する。既存の評価結果 `raw` / `safe` / `html` / `dom` / `unknown` は増やさず、`evaluate()` の既存4引数呼出しも維持した。既存の裸参照検出範囲を増やさず、`const picked = values[0]` のような途中代入から既存 sink へ接続する。選択要素が raw のときだけ raw を返し、それ以外は unknown とする。

現行の全 `env.clear()` に要素表のクリアを連動させた。配列の再代入、別名への受け渡し、要素・length・通常プロパティの変更、未知の関数呼出しでは古い根拠を破棄する。動的添字・空配列・範囲外・穴・spread・ネスト・アクセサ・未対応の構文は推測せず unknown を維持する。副作用のない単純な要素だけをクリア前に捕捉し、呼出しを含む配列は丸ごと拒否する。巨大な添字は桁数で範囲外と判断し、無制限の整数変換を避ける。

本拡張は raw の伝播だけに限定し、escaped 要素の safe/html 認定は追加しない。今回の20件は全構文・全副作用を覆う十分条件ではなく、検査器自体も完全な JavaScript 解析器ではない。新しい構文を追跡対象に追加する際は、その範囲に対応した反例が別途必要になる。

value-card の既存メモ収集全体には、DOM列挙、コールバック境界、push、動的添字、条件式、テンプレート累積が残る。この最小案だけで同アプリの既存 unknown を解消できるとは扱わない。

## 検証結果と非対象

`python3 scripts/tests/test-sec1-dataflow.py` は恒久96件・shell連携9件・欠落ファイル失敗確認を通過。追加20件のうち3件が新たに raw、17件は unknown。現行アプリは71ファイル、裸参照44件、ERROR 0、unknown 44で変化なし。`bash scripts/lint.sh` 全16項目通過。テスト上の限定経路の検出能力は増えたが、現行アプリの未判定削減・新規の安全認定はない。

実装とは別コンテキストのサブエージェントによる独立レビューを実施し、修正要求なし。96件・shell連携9件の再実行、既存76件の保持、失効条件・判定値の不拡張、報告内容との一致を確認した。追加の読み取り専用11境界例も unknown を確認した。同系統の別コンテキストによるレビューであり、別系統モデルとの二重レビューではない。

本番 Firebase・ネットワーク・ブラウザ・iPhoneの操作、アプリ修正、コミット・push・PR・デプロイは行っていない。
