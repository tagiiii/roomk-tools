### 開き方

1. リポジトリ直下で配信する（既存の起動設定 `roomk-root` と同じ）。

   ```bash
   python3 -m http.server 8090
   ```

2. ブラウザで **http://localhost:8090/drafts/career-sugoroku/** を開く。
   - `localhost` で開く（`127.0.0.1` や LAN の IP だと、API キーのリファラー制限で認証できない）。
3. 遊び方だけ見る: 入口の「はじめてガイド」（ゲーム中も上のバーの「ガイド」から開ける）。
4. ひとりで全体の流れを見る: 「ルームを作る」→ 待合室の「端末なしで参加する人を追加」で1〜2人追加 →「はじめる」。ホストの画面で全員分を操作できる。
5. 端末ごとの参加を試す: 同じ PC で別ウィンドウ（またはシークレットウィンドウ）を開き、ルームコードで「ルームに参加する」。タブごとに別の参加者になる。「見学する」を選ぶと見学専用。
6. 終わったら、ホストの「ルームを閉じる」（進行パネル・結果画面）でデータを消す。

`?emu=1` を付けると、ローカルの Firebase エミュレーター（127.0.0.1:9100 / 9199）だけに接続する（自動テスト用）。

### 画面の流れ

```
入口 ─ ルームを作る（自分も参加／進行だけ）
     ├ ルームに参加する（ゲームに参加／見学）
     └ はじめてガイド（5ステップ: やること／職業カードの見かた／1回の手番／作戦のコツ／最後の仕上げ）
待合室: ルームコード・参加者・見学者・端末なしの人の追加・設定（時間チップ・選ぶ時間・暮らし・進路）・最後の仕上げの説明・目安の時間
準備（全員同時）: 理想の職業（まだ決めないも可）→ 最初の適性カード3枚 → 当面の目標（3枚から）
本編: 手番（サイコロ→分かれ道→止まったマスで選ぶ→結果→手番を終える）
      ＋ 進路のラウンド（全員同時に「進路→そこでの体験」を選び、適性カード1枚）
最後の職業選び（全員同時）: 持っている職業から1つ → 仕上げのサイコロ（出目＋準備チップで0〜3点）
結果発表（職業の点＋仕上げの内訳）
```

ホストは右上の「進行」から、一時停止・代わりに操作・手番のスキップ・次の1周で終了・すぐに終了・各プレイヤーの見学/戻す/参加を終える・見学者の一覧・時間の計測・ルームを閉じる を使える。

**試作用の早送り**: 「進行」→「本編の終わりまで自動で進める」で、全員の分をおまかせで進め、最後の職業選びの手前で止まる（止めるときは上のバーの「自動を止める」）。流れの確認用で、自動で進めた回の計測は参考にしない。

#### 得点と仕上げのサイコロ

- **職業の点**（最大19点）＝ 中心の適性の枚数×2 ＋ 関連の適性2種類の枚数 ＋ 3種類がそろうと＋3。適性は1種類4枚まで（2026-09-28 オーナー決定。前は3枚・最大15点）。
- **準備チップ**（2枚まで）: イベント・コラボの判定でカードが取れなかったとき＋1（出目1〜2、受け取れる適性がない、別の適性を選ぶ前に手番が終わった）。2人でコラボしてサイコロを振ったときは2人とも＋1（相手が振る前に見送られたあと、ひとりで振ったときは付かない）。
- **仕上げのサイコロ**: 最後の職業を決めたあと、出目＋準備チップの合計で点を加える。

  | 合計 | 1〜2 | 3〜4 | 5〜6 | 7〜8 |
  |---|---|---|---|---|
  | 加わる点 | ＋0 | ＋1 | ＋2 | ＋3 |

  準備チップ0枚なら最大＋2、2枚なら最低でも＋1。加わるのは最大3点なので、3点差は同点どまり、4点以上の差は逆転しない。画面の説明も「3点以上の差は逆転しない（3点差は同点まで）」と書き、「2点差なら逆転できる」とは書かない（準備チップの枚数によっては同点が最大のため）。
- **ガイドの表示**: 選択肢には「目標の中心×2」「目標の関連×1」「目標には入っていない」と、その選択で目標の職業の点がいくつ増えるか（「目標の点＋N」。イベントは「成功で目標の点＋N」＝2枚ふえたとき。3枚の上限で切る）を出す。手札には「目標までのみちのり」（いま○点／15点と、3つの適性それぞれ「次の1枚で＋N」）と準備チップ。

| 得点の差 | 適性の上限を4枚（最大19点）にして差がつきやすくした。1位の同点が多すぎないか、途中で「もう勝てない」と感じる子がいないか |
| 仕上げのサイコロ | 盛り上がったか。順位の入れ替わりに納得していたか（3点以上の差は逆転しない） |
| 画面共有での見え方 | 子どもの側（Zoom / Meet の受け手）で、盤面と選択肢の文字が読めるか。受け手の画面を1枚撮ってもらえると後で直しやすい。**特に職業カード**（準備の「理想の職業」と「最後の職業選び」）: 説明と適性名が11〜12px（1280×720 の画面で測った値）で、小さな窓で見ると読みにくいおそれがある。手番・待合室・結果の画面は13px 未満の文字が1割未満 |

### 見直しの目安

| 試遊で分かったこと | 見直す候補 |
|---|---|
| 1手番の平均が上の上限を超えた／合計が45分を超えた | 推奨の時間チップを1枚減らす。それでも長ければ、選ぶ時間の既定を60秒に |
| 差がつきすぎて、途中で「もう勝てない」と感じる子がいた | 適性の上限を3枚に戻す（`data.js` APT_CAP。最大15点になる）か、仕上げの段を見直す |
| 仕上げのサイコロで、いつも同じ人が上がる・入れ替わりが多すぎる | 仕上げの段の区切り（いまは合計1〜2/3〜4/5〜6/7〜8 → ＋0〜3）と準備チップの上限（2枚） |
| ガイドが読まれない・長い | はじめてガイド（5ステップ）を短くする、ヒントを減らす |
| 受け手の画面で職業カードの文字が読めない | 職業カードの説明・適性名の文字を大きくする（いまの11〜12px を13〜14px に。カードの並びは要確認） |
| 進路・暮らしで気まずそうな子がいた | その回は待合室で「なし」に。続くようなら収録範囲をオーナーが見直す |

決め方: 気づいたことを HANDOFF.md に書き、見直しはオーナーが決める（数値の調整は実装モデルに頼める）。
