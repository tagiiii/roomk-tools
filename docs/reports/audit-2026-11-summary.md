## これからの作業で守ること（今回決まった・変わったこと）

- **RTDB の新しいアプリは、公開の前に `database.rules.json` へ `{appname}_rooms` を足す。** 11-08 からルールはワイルドカードでなく名前空間の一覧。足さないとそのアプリだけルームを作れない。変更禁止パスなのでオーナーの承認のもとで行い、lint [RULES-1] で確かめる（[firebase.md](../development/firebase.md)）。
- **作戦会議の札を付けるカードは `data-speech`・`data-self` が必須**で、そのアプリの `AGENTS.md` の「セッション条件」の欄も同じ値にする（lint PORTAL-2・[app-registration.md](../development/app-registration.md)）。値は事実だけで決め、子どもへの合い方は書かない。
- **画面の下に固定する帯**（`position: sticky; bottom: 0`）は、右下の丸ボタンに重ならないよう、帯の側で幅の狭い画面に下の余白をとる。ページの最後の余白は howto.js がとる（[shared-modules.md](../development/shared-modules.md)）。
- **ワードウルフのお題の組は位置で覚える**（`usedPairs`）。差し替えは同じ位置で行い、並べかえや途中への挿入はしない。たとえグランプリ・好きなものビンゴなど、位置で覚える配列は同じ。
- **重複監査は警告ゼロで通る状態を保つ。** 要確認・構造一致は0、禁止題材の候補語（`[forbidden-topic]`）は0。別の意味と確かめた語は `FORBIDDEN_TOPIC_ALLOWED` に理由を添えて足す。
- **内省ツールの「答えない・やめる」**: すきタイプチェック・つよみカード・どんな人・バリューカードは「今日はここまで」を常設。キャパグラフ・塗り絵カレンダーは開いたとき「つづきから／まっさらではじめる」。ブラウザに残すのは本人の所有物としての意図的な仕様（audit-prompts.md §0.5-1）。
- **オーナーが「今のまま」と決めたもの**は、各 `AGENTS.md` に「次の監査で同じ理由だけでは出さない」と書いた（トークテーマカードの3枚・興味スゴロクの状態の答え・どっちにする？の追い質問例）。P7・P8 の分担・負荷のほかの項目・4軸は「今は作らない」（決着履歴）。

## 確かめるときの落とし穴（今回つまずいたこと）

- **隔離エミュレーターは、`firebase.json` のルールを自動では当てないことがある。** `?ns=demo-…` に対する読み書きが、未ログインでも通ってしまった。ルールを確かめるときは `PUT {DB}/.settings/rules.json?ns=…`（`Authorization: Bearer owner`）で明示的に読み込ませる（`tests/feedback/e2e.cjs` と同じ）。既存の多くの E2E はルールを読み込ませておらず、ルールなしで通っている。
- **本番の API キーにはリファラー制限がある。** REST で匿名ログインするときは `Referer: https://tagiiii.github.io/roomk-tools/` を付ける。付けないと ID トークンが取れず、書けるはずの所まですべて 401 に見える。
- **「重なり」「見えている」を DOM で数えるときは、閉じた `<details>` の中を除く。** `getClientRects()` は閉じた折りたたみの中の要素でも幅を返すことがあり、誤検出した。
- **GitHub Pages の公開が syncing_files で10分の時間切れをくり返したときは、失敗したジョブの再実行や同じ SHA の workflow_dispatch では直らない。** 空のコミットで新しい SHA にして push すると通った（11-07）。公開されたかは、変えたファイルの中身（shasum）を公開中のものとマージ後のものとで比べて確かめる。
- **サービスアカウント（フィードバック用）は Cloud Monitoring を読めない。** 同時接続のピークは、オーナーの Chrome で Firebase コンソールの使用状況を読む。
