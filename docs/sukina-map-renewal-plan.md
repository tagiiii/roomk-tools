## 1. 背景と課題

旧 `apps/sukina-map/`(すきなことマップ)は「子どもの発言をメンターが自由入力してカード化し、じぶんの周りに置く」方式。実運用で以下の課題があった。

- 「好きなことを言って」で言葉が出てこない子には、白紙からの自由入力はハードルが高い
- メンターが画面共有しながらタイピングする操作コストが大きい
- 回をまたいで JSON を持ち回る運用が重い

## 2. 方針転換(哲学の変更点)

旧 AGENTS.md の「診断・タイプ分け・おすすめ表示はしない」を**意図的に撤廃**(キャパグラフの「数値化しない」転換に続く例)。断定・ランキング・数値も含めて診断らしい見せ方を採用する。理由: タイプを知ること自体が会話を広げる。診断は評価ではなく会話のタネ。

残すガードレールは次の2つだけ。

- **タイプ間に優劣をつけない**: どのタイプの説明文も同じ熱量・同じ長さで肯定的に書く。欠点・苦手の記述はしない
- **コンテンツガイドライン**(リポジトリ共通): 学校・勉強・成績・登校・恋愛・ダーク系を質問・結果に出さない

## 3. コンセプト(確定)

- **18問・5件法**の選択式診断。1問ずつ表示し、クリックだけで進む
- 6軸×3問。最高スコアの軸を「あなたは 〇〇タイプ！」と断定表示し、抽象的なタイプ説明を出す
- 結果画面に全6軸のスコアをパーセントバーで一覧表示(スコア順)
- 保存機能なし(JSON入出力を廃止)。1回の作戦会議30分で完結
- 結果はテキストコピーで Metalife チャットに貼れる(絵文字なし)

### 対象・利用シーン

- 小学校高学年〜中学生。言葉は平坦すぎなくてよい(通常の漢字使用OK)。この年代は診断系コンテンツへの親しみがあり、「タイプ判定＋パーセントバー」の見せ方はそれ自体が楽しい
- 作戦会議(1対1・30分)。メンターが画面共有し、読み上げながら子どもが答える
- 時間見積: 説明2分＋回答10分(18問×30秒)＋結果を眺めて話す15分前後

## 4. 画面フロー

```text
screen-start   … 説明＋「はじめる」
  → screen-question  … 1問ずつ。進捗「n / 18」表示。「ひとつ前にもどる」あり
  → screen-result    … タイプ発表＋全軸バー＋結果コピー＋「もういちどやる」
```

- 選択肢は5件法「あてはまる／やや当てはまる／**どちらでもない**／あまり当てはまらない／当てはまらない」(①〜⑤)。「どちらでもない」は中間位置に置き、まよったとき・答えたくないときの受け皿を兼ねる(パスは置かない)
- 回答すると自動で次の問へ。「ひとつ前にもどる」で答え直せる
- リロードで最初に戻る(永続化ゼロ)。**beforeunload 警告は出さない**(保存なしツールとして潔く。再実行は10分)

## 5. 6軸と質問セット(確定・18問)

質問は「どういうときに心が動くか」の抽象的な聞き方で統一。具体的な活動名の列挙はしない。

### ① からだ・うごき → うごいて楽しむタイプ
1. 体を動かしているときが、いちばん自分らしいと感じる
2. 頭で考えるより、まず動いてみたいほうだ
3. 体を思いきり動かしたあとの爽快感が好きだ

### ② つくる・ためす → つくってためすタイプ
4. 何かを自分の手で完成させたときの達成感が好きだ
5. うまくいく方法をあれこれ試すのが楽しい
6. 「自分ならこう作る」「こう直したい」と考えることがある

### ③ 表現する → ひらめきをかたちにするタイプ
7. 自分の中にあるイメージや気持ちを、形にして伝えたくなる
8. 心が動いたものを、自分なりに表現してみたくなる
9. 自分のつくったもの・表現したものを、だれかに見てもらえるとうれしい

### ④ しらべる・きわめる → とことんしらべるタイプ
10. 気になったことは、納得するまで調べたくなる
11. 物事の仕組みや理由を知ると、わくわくする
12. ひとつのことを深く掘り下げていくのが好きだ

### ⑤ あつめる・ととのえる → あつめてととのえるタイプ
13. 好きなものが少しずつそろっていく感覚が好きだ
14. ものや情報がきれいに整理されていると気持ちいい
15. 「全部そろえたい」と思うことがある

### ⑥ ひとと関わる → いっしょに楽しむタイプ
16. だれかと一緒にやるほうが、楽しさが大きくなると感じる
17. 自分の好きなものの話を、人と共有したくなる
18. 人が喜んでくれると、自分もうれしくなる

### 出題順(確定)

同じ軸が連続しないよう、**軸①→⑥を1問ずつ3周**する固定順とする(Q1=①-1, Q2=②-4, Q3=③-7, Q4=④-10, Q5=⑤-13, Q6=⑥-16, Q7=①-2, …)。シャッフルはしない(画面共有での読み上げ再現性のため)。

## 6. スコアリング(確定)

- あてはまる=4 ／ やや当てはまる=3 ／ どちらでもない=2 ／ あまり当てはまらない=1 ／ 当てはまらない=0
- 軸スコア = その軸3問の平均。パーセント表示は `平均 ÷ 4 × 100`(四捨五入)
- **タイプ判定 = 最高スコアの軸**
- **1位同点**: 「あなたは 〇〇×△△ のハイブリッドタイプ！」と2つを掛け合わせて発表。説明文は両タイプを短縮して併記。3軸以上同点の場合は軸定義順の上位2つで表示
- **フラット判定**: 全軸の最大平均が 2.0 以下(どの軸も「どちらでもない」を超えない) → 「**すきさがしタイプ**」(今は「これ！」をさがしている途中。肯定的に書く)。全問「どちらでもない」もここに落ちる

## 7. 結果表示(確定)

### 構成(上から順に)

1. **タイプ発表**: 「あなたは 〇〇タイプ！」＋タイプ対応アイコン(Material Symbols)
2. **タイプ説明(抽象)**: 2〜3文
3. **好きかもリスト(具体・補足)**: 「こういうものが好きかも」6〜8個
4. **全軸バー**: 6軸すべてパーセントバー(スコア順・数値テキスト併記)。2位に「〇〇タイプの気質もあります」の一言
5. **会話プロンプト**: 「近いなと思うところ、ちがうなと思うところはある？」
6. **結果コピー** ＋ **もういちどやる**

### タイプ定義(確定)

| 軸 | タイプ名 | 説明の方向性(抽象・2〜3文に肉付け) | 具体例(補足) |
|---|---|---|---|
| からだ・うごき | うごいて楽しむタイプ | 考えるより先に、まず体が動く。実際にやってみることで世界を確かめていく | スポーツ、ダンス、サイクリング、アスレチック |
| つくる・ためす | つくってためすタイプ | 手を動かして形にしていく過程が楽しい。試して、直して、だんだん良くなるのが好き | 工作、料理、プラモデル、DIY、ゲーム制作 |
| 表現する | ひらめきをかたちにするタイプ | 頭の中のイメージを外に出して伝えたい。表現することで気持ちが動く | イラスト、マンガ、音楽、動画づくり、物語 |
| しらべる・きわめる | とことんしらべるタイプ | 「なぜ？」を追いかけて深くもぐる。知れば知るほど面白くなる | 生き物、宇宙、歴史、鉄道、ゲーム攻略 |
| あつめる・ととのえる | あつめてととのえるタイプ | そろえる・整える・ながめることに喜びがある。少しずつ完成に近づくのが好き | カード、フィギュア、標本、写真、図鑑 |
| ひとと関わる | いっしょに楽しむタイプ | 楽しさは人と分かち合うと大きくなる。だれかと一緒だから力が出る | みんなで遊ぶゲーム、おしゃべり、教えること |
| (フラット用) | すきさがしタイプ | 今は「これ！」をさがしている途中。出会いはこれからいくらでもある | — |

- どのタイプも同じ熱量・同じ長さで肯定的に書く。欠点・苦手の記述はしない
- 具体例の語彙はコンテンツガイドラインの範囲で実装時に肉付け(各6〜8個)

### 結果コピー(Metalife チャット用・絵文字なし)

・とことんしらべる 92%

## 8. 技術方針

- **新フォルダ `apps/suki-type-check/`** に `index.html` + `app.js` + `style.css` の talk-card 型オフライン構成で新規実装。Firebase 不使用
- **旧 `apps/sukina-map/` はリダイレクトスタブ化**(codenames 等と同じ16行パターン)
- 永続化 API(localStorage / sessionStorage / IndexedDB / Cookie)は一切呼ばない。JSON入出力・fileMarker・インポート検証は持ち込まない
- CSS 接頭辞は **`stc-`** + BEM(新フォルダのため新規採番)。`.screen` / `.active` 命名継続
- `stats.js?v=1` 組み込み。記録イベントは「診断開始」「結果表示」の回数のみ(回答内容・タイプ結果は送らない)
- `howto.js` 組み込み。旧マップの JSON ファイルについて「以前の『すきなことマップ』で保存したファイルは、このツールでは使いません」と一言添える
- 絵文字禁止・Material Symbols Rounded のみ。パーセントバーは CSS で描画(ライブラリ不使用)
- アクセシビリティ: 選択肢は `role="radiogroup"`、44×44px 以上、`:focus-visible`、`prefers-reduced-motion` 対応、バーは数値テキスト併記(色だけにしない)

## 9. AGENTS.md(新規 `apps/suki-type-check/AGENTS.md`)

- 目的: 選択式で「好き」の傾向を診断し、会話のタネにするツール。旧すきなことマップからの方針転換の経緯(診断・断定・数値OK、ただし優劣なし)を明記
