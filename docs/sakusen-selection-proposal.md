# 作戦会議アプリ選択の語彙・メタデータ 確定案（判断待ち P票①②の材料）

2026-07-13 作成。監査プロンプト集 [audit-prompts.md](./audit-prompts.md) の **P7/P8 停止ゲート**に対する起票候補。
複数エージェントで一次情報（`docs/content-plan.html` ＋ 各 `apps/*/AGENTS.md`）を抽出し、別系統モデルの検証を経てまとめた。

> **停止ゲートの趣旨**: 作戦会議の19アプリを横断で「どの子にどれ」と評価する監査は、
> 下記2つのP票（①語彙・②メタデータ項目）が**人間承認されるまで走らせない**。
> この文書はその**承認に付す確定案**であって、アプリ選択の最終マッピングではない。
> 末尾の観察表は「承認後にこの形で埋まる」ことを示す**素材**（値は観察事実のみ・
> 子どもの適合判断や4軸割り当ては含まない）。

## 設計の絶対条件（全体ガード）

`docs/content-plan.html:140-150`（Codex 相談で確定済みの共通原則）に従う。

- **子どもの固定ラベルを作らない。** 「不安が強い子」「意欲が低い子」等の属性語彙を語彙・メタデータに一切入れない。絞り込みは「その日の本人の希望」＋「観察可能なセッション条件」で行う。
- **本人の希望は都度その場で本人が選ぶ。** 推定・保存・履歴化・採点・推薦・順位付けをしない（前回の希望を記録して次回に引き継ぐ・スコア化する等をしない）。アプリが子どもの状態を推定・記録することも提案しない。
- **非序列。** 「話さなくてよい」「弱い関心」「パス（今日はえらばない・答えない）」を欠落・下位ではなく**それぞれ独立した同格の値**として扱う（灰色・小さく・末尾に置かない）。これらは opt_out（アプリの離脱導線）とは別に、選択語彙・回答語彙の第1級の値として置く。
- **4軸（関係性/興味/自己理解/自己実現）は AI が推定しない。** content-plan に軸割り当て表は無く、人間判断。今回のスキーマには **`axis` を含めない**（後述）。
- 選び方情報は**子ども向け画面に出さない**（スタッフ閲覧面＝ポータルのカード裏／専用資料）。

## P票①（承認対象）— 非序列の支援機会語彙

### セット1: 「その日の本人の希望」語（本人の言葉・素直な動詞・閉じたリスト）
`content-plan.html` の役割記述と各 AGENTS.md の目的文から抽出。どれも他より上位でない。

- かるく遊びたい／ウォームアップしたい
- えらぶ・きめる練習をしたい
- すきなこと・きになることの話をしたい
- きもちを ことばにしたい
- じぶんのことを 知りたい／見てもらいたい
- やってみたいことを ためしておきたい
- せかいを のぞいてみたい
- ばめん・できごとを 話す／語る練習をしたい
- **きょうは 話をきくだけでいたい／そっとしておいてほしい**（第1級の値。`bamen-card` の「きくだけ」・`minna-ranking` の「1人・話さなくてよい」等が実装済み）
- **きょうは えらばない・パスしたい（答えなくてよい）**（第1級の値。`kimochi-map` の「きょうは えらばない」・`checkout-card` の「きょうはパス」が実装済み）
- **すこし気になる程度で参加したい（弱い関心でよい）**（第1級の値。`sukina-map` の③④「ちょっと気になる／見るのはあり／まえはすきだった」が実装済み）

### セット2: セッション条件軸の「値の言葉」（各軸フラット・序列なし）

各軸は **`記載なし（unknown）` を許容**。境界のある帯は「境界値は長い/上の帯に含む」規約で重複を排す。

| 軸 | 値の語彙（非序列・単一/複数は P票②の型定義に従う） |
|---|---|
| 所要の目安 | ごく短い（〜5分）／短い（5〜10分）／じっくり（10〜15分）／記載なし ＊境界は長い帯に含む＝空白も重複もなし |
| 想定人数 | 1on1 ／ 少人数（3〜4人）／ 1人でも成立（複数可） |
| 発話量 | 選ぶだけ ／ ひとことで ／ 語る・説明する ／ **話さなくてよい（眺める・聞く・書く）**（複数可） |
| 自己開示（**単一スコアにせず分解**） | ①自分の話が要る／外の題材で成立 ②過去想起あり／なし ③全体共有が要る／本人が選べる／1on1でメンターと共有（各分解軸は単一選択＋unknown） |
| 記録 | その場で消える ／ 端末に残る（localStorage）／ 任意で書き出し（JSON/PNG）／ 回をまたいで蓄積（JSON読込） |

補足: **「個人情報を入力させない」は19アプリ共通の不変条件**（固定注意文言や入力欄なしで担保）。軸ではなく前提として1行記す。

### 語彙ガード（この票の核）
- 「褒められるのが苦手な子」等（content-plan のリスク欄）は**子ども属性でなくアプリの設計特性**として言い換える（例: `tsuyomi-card`＝「断定形にしない・褒め演出なし」）。
- 「向く子／向かない子」を作らない（個別適合は人間専任）。
- `kyapa-graph` の「登校を頑張りすぎている場面向け／不登校の子には別ツール」は、AI の推定ではなく**アプリ自身の宣言**なので、後述 `self_declared_scope` 項目にそのまま写す。

## P票②（承認対象）— ポータル選択メタデータ項目（スキーマ）

`data-scenes`（＝どの場で使うか）は**残したまま**、その上にスタッフ閲覧用の選択メタを足す。値は P票① の語彙で埋める。子ども向け画面には出さない。

| 属性キー | 取りうる値 | 型 | 埋め方 |
|---|---|---|---|
| `duration` | 〜5分／5-10分／10-15分 | 単一＋`unknown` | 観測（境界は長い帯） |
| `party` | 1on1／少人数（3〜4人）／1人でも成立 | 複数可＋`unknown` | 観測 |
| `voice` | 選ぶだけ／ひとこと／語る・説明する／話さなくてよい | 複数可＋`unknown` | 観測 |
| `disclosure_selfstory` | 自分の話が要る／外の題材で成立 | 単一＋`unknown` | 観測（分解1） |
| `disclosure_recall` | あり／なし／お題次第 | 単一＋`unknown` | 観測（分解2） |
| `sharing` | 1on1でメンターと共有／集団共有が要る／本人が選べる | 単一＋`unknown` | 観測（分解3） |
| `record` | なし／端末保存／任意で書き出し／蓄積 | 複数可＋`unknown` | 観測 |
| `opt_out` | 正式導線あり（パス等）／やり直し・退出のみ | 単一＋`unknown` | 観測 |
| `self_declared_scope` | アプリ自身の対象宣言（AGENTS.md の原文を転記・任意） | 表示専用（`nullable string`・原文転記） | 観測 |

- **`axis`（4軸）は今回のスキーマに含めない（未実装）。** content-plan に割り当て表がなく AI 推定は禁止のため、4軸マッピングを人間が確定した時点で**別P票**として追加する。今回は「予約するが常に未設定」という曖昧さを避けるため予約フィールドも置かない。
- **`self_declared_scope` は表示専用。** 型は `nullable string`（宣言がなければ `null`）。アプリ自身が AGENTS.md で宣言する対象（例 `kyapa-graph`）の**原文を転記**し（要約・解釈を加えない）、スタッフに見せるだけ。**子どもの属性推定・絞り込み条件・適合判定には使わない**。
- 心理的負荷は**単一スコアにしない**。`disclosure_selfstory`／`disclosure_recall`／`sharing`／`voice` の分解項目で読む（content-plan の「心理的負荷」1語カラムを、選択メタでは分解する）。

## 2つの P票（kaizen-backlog 判断待ちへの起票文・番号は人間が最終付与）

### P-8 相当 — 非序列の支援機会語彙の確定
- **判断する一文**: ツール選択に使う語彙を、子どもの固定ラベルではなく「その日の本人の希望」を表す上記 P票① セット1（本人の希望語＋第1級の値〈きくだけ／パス／弱い関心〉）で確定してよいか。
- **承認対象の範囲**: P票① セット1（本人の希望語＋3つの第1級の値）を**語彙**として確定する。セット2のセッション条件軸（所要／人数／発話量／自己開示／記録）は語彙ではなく **P票② のメタデータ属性**として持つ（役割分担）。
- **2〜3案**: ①セット1＋セット2の両方を語彙として確定 ②セット1を語彙として確定し、セット2はメタデータ（P票②）へ分離 ③当面確定せず、次回の選び方ガイド相談まで保留。
- **推奨案**: **案②**（語彙は本人の希望を表す最小の非序列セットに絞り、構造化された条件は P票②で持つ。承認面を小さくして部分承認を通しやすく）。
- **禁止事項（承認に含める）**: 子ども属性ラベルを作らない／希望を推定・保存・履歴化・採点・推薦・順位付けしない／「きくだけ・パス・弱い関心」を同格に置く。
- **影響**: 承認で P7 個別監査の「語彙」前提が満たされる（P票②と両方そろって初めて横断監査を解禁）。却下/保留なら現状維持・横断監査は停止継続。可逆（文書上の定義・コード非依存）。
- **関連 finding**: P8-1（sakusen 19カードが同一タグのみ）・P8-2（自己開示の交互運用の手がかり不足）。

### P-9 相当 — ポータル選択メタデータ項目の確定
- **判断する一文**: `data-scenes`（場所）を残し、上記 P票② の**観測可能な9属性**（`axis` は含めない）をスタッフ閲覧面に足すスキーマで確定してよいか。
- **承認対象の範囲**: `duration`／`party`／`voice`／`disclosure_selfstory`／`disclosure_recall`／`sharing`／`record`／`opt_out`／`self_declared_scope` の9属性と、各属性の型（単一/複数/unknown）。`axis`（4軸）は**含めない**（4軸マッピングを人間が確定してから別P票で追加）。
- **2〜3案**（前案で推奨した「観測可能項目を採用・`axis` 除外」を案①に整理）: ①観測可能な9属性を採用し `axis` は別P票 ②属性は付けず、スタッフ用の静的な選択一覧表（別資料）だけを正本にする（ポータル改修ゼロ）③最小サブセット（duration/party/voice/opt_out）だけ先行し自己開示系は後日。
- **推奨案**: **案①**（観測可能な9属性を先に固め、`axis` は 4軸確定後の別P票）。＝前案の推奨内容と同一で、番号のみ整理。
- **禁止事項（承認に含める）**: `self_declared_scope` は表示専用（絞り込み・適合判定に使わない・原文転記）／子ども向け画面に出さない／子どもの状態の推定・保存・履歴化・**採点・自動推薦・順位付け**をしない。
- **影響**: 承認で P8-1/P8-2 の実装前提（属性の置き場）が定まる。子ども画面は不変、変更は `data-scenes` への**追加のみ**（後方互換）。承認後のポータル実装は Tier D ではなく通常 **B**。可逆。
- **関連 finding**: P8-1・P8-2。
