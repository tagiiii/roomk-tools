自由時間コンテンツ 制作計画

roomK MetaLife 自由スペース向けコンテンツの制作ロードマップ ／ 2026-07-06 作成
この計画書の使い方
  • 上から順に1本ずつ作ります。各コンテンツの「実装プロンプト」をコピーして、Claude Code（Fable 5）にそのまま貼り付ければ実装が始まります。
  • 1本作るごとに「実装 → メンター実機確認 → 文言の別視点監査 → コミット → 自由時間に投入」まで回してから次に進みます。
  • ツールを作る前に「ステップ0（ツールなしで始める）」を先に運用し、子どもの反応を見てから着手する順番でもかまいません。

0. 前提と設計原則

前提（2026-07-06 確認済み）
  • 場: MetaLife 内の自由スペース。プログラムと同じ45分間、参加は最大4人程度。
  • 参加形態: マイクON参加とチャット参加の子どもが混在する。
  • 操作形態: 子どもが自分の端末で URL を開いて操作するのが基本（メンターの画面共有に依存しない）。スマホ・タブレット対応必須。
  • 進行: メンターが常に仕切れるとは限らない。誰も仕切らなくても成立するコンテンツにする。

自由時間コンテンツ共通の設計原則

  • 始まりも終わりもない。途中参加・途中離脱・見てるだけが全部正式な参加形態。「今から始めます」「最後までやろう」を前提にしない。
  • マイクとチャットで体験差を作らない。すべての操作がタップと短い文字入力で完結する。声が出せないと不利になる要素を入れない。
  • 沈黙で成立する。誰もしゃべらなくても気まずくならない。会話は「起きたらいいな」であって必須条件にしない。
  • 痕跡が残る。前に来た子の気配（投票・質問・図鑑のページ）が、次に来た子のきっかけになる。ただし個人の評価物・証拠物には見えないようにする。
  • 評価・比較・数値化・ランキング蓄積・連続記録・バッジ・賞賛演出を入れない（お題として遊ぶ「おにぎりの具ランキング」は例外。人や成果のランキングは禁止）。
  • 学校・勉強・成績・登校・恋愛・ダーク系の話題は出さない（AGENTS.md コンテンツガイドライン準拠）。
  • 常設型は新しいパラダイム。既存アプリの「セッション終了後削除」原則に対し、自由時間の非同期コンテンツは意図的にデータを残す（bulletin-board に次ぐ常設型）。各アプリの AGENTS.md にその旨と掃除ルールを明記する。

1. ステップ0 — ツールなしで今週から始める

実装ゼロで先に試せるもの。ここでの反応がツール化の判断材料になります。

  • 既存ボドゲの自由時間解禁: うそつき辞書・ピッタリメーター・かくれナンバーは回答をチャットで書けるので混在参加に強い。「クラブの時間じゃなくても勝手に遊んでいい」と掲示するだけでコンテンツになる。
  • MetaLife ホワイトボードの常設落書きコーナー: お題があってもなくてもいい。前回の絵を消さずに残すのがポイント。
  • 手書きの2択ボード: ホワイトボードに「きのこ vs たけのこ」を書いてスタンプを置いてもらう。これが盛り上がるなら「きょうの2たく」をツール化する価値がある。
  • 絵しりとり・お絵かき伝言: ホワイトボードだけで成立する。声が要らない代表格。

2. 全体ロードマップ

順コンテンツフェーズ主な役割型データ心理的負荷
1きょうの2たく先行 常設の投票ボード・気配づくり常設・非同期RTDB（7日で掃除）最小
2みんなでランキング先行 2人以上いたら始まる遊びその場で遊ぶなし最小
3しつもんポスト様子見 非同期の交換日記・交流常設・非同期RTDB（常設）低〜中
4みんなの図鑑様子見 長期の共同制作・また来る理由常設・共同制作RTDB（常設）低〜中

この順番の理由

  • 1 が先頭: 実装が最も軽く、参加ハードルが最小（スタンプを1個置くだけ）。「非同期の痕跡が交流になるか」という自由時間コンテンツの核仮説を最速で検証できる。
  • 2 は実装コスト最小のリアルタイム系: オフライン構成・保存なしで、2〜4人いるときの「たわいない盛り上がり」を担当する。1 と 2 で「1人でも楽しい／複数人でも楽しい」の両方をカバー。
  • 3・4 は運用判断: 常設で文章が蓄積するため、荒れ対策・掃除運用の負担が 1 より大きい。1 の運用で「子どもが非同期の場に書き込むか」を確認してから着手する。
  • 4 は実装がいちばん大きく、完結しないことが価値（「続きやろう」が次に来る理由になる）。3 の運用が回ってからで遅くない。
常設型（1・3・4）に共通する注意
  • RTDB の書き込みはオープン（既存ルールのまま）。クローズドコミュニティの性善説運用が前提で、厳密な認証はしない。個人情報を書かない前提の場として設計する。
  • メンターの「かたづけ」機能（削除）を必ず付ける。URL パラメータによる簡易表示切替であり、本気のアクセス制御ではないことを各 AGENTS.md に明記する。
  • 文字数上限・件数上限を必ず設け、無料枠と荒れの両方を抑える。

3. 制作の進め方（1本ごとの手順）

  1. 下の実装プロンプトをコピーして Claude Code に貼り付ける。
  2. 実装完了後、bash scripts/lint.sh の通過とローカル動作を確認する。
  3. お題・テンプレ等のコンテンツデータを別セッションのエージェントに監査させる（プロンプト例: 「apps/○○/ のお題データを AGENTS.md のコンテンツガイドラインに照らして全件監査して」）。
  4. メンター（自分）が実機で一巡する。常設型はスマホからも必ず確認する。
  5. コミットして GitHub Pages へデプロイし、MetaLife の掲示物（URL / QR）から自由スペースに導線を張る。
  6. 1〜2週間の使用感メモ（書き込み件数・子どもの反応）を残してから次のコンテンツへ。

4. フェーズ1（先行2本）

1. きょうの2たく

フェーズ1 RTDB 単一ファイル・常設（日付キー・7日で掃除） 　常設の投票ボード　・　1回30秒〜

日替わりの軽い2択が貼ってあり、来た子がスタンプを置いていくだけの常設ボード。正解がなく、置いた瞬間に「○○ちゃんそっちなんだ」という会話の種になる。前に来た子のスタンプが残っているのが核で、リアルタイムに人がいなくても成立する。

リスクと対策: 最小リスク。ただし「多数派が勝ち」に見える集計演出（人数の数字・棒グラフ・多い方の強調）は一切入れない。少数派・未投票が悪目立ちしない画面にする。

2. みんなでランキング

フェーズ1 オフライン単一構成・保存なし 　2人以上いたら始まる遊び　・　10〜20分

「コンビニおにぎりの具 最強ランキング」のような正解のないお題を、みんなでわいわい並べ替える遊び。1人が操作して（画面共有でも各自の端末でもよい）、他の子はマイクでもチャットでも意見を出せる。完成したランキングをテキストでコピーして MetaLife のチャットに貼れば、チャット参加の子も結果を持ち帰れる。

リスクと対策: ランキング形式だが対象は「もの」だけ。人・成果・行動を並べるお題（クラスの人気者、がんばった人など）はデータに入れない。順位で揉めたときのために「同率」も置けるようにする。

5. フェーズ2（様子見2本・叩き台プロンプト）

「きょうの2たく」の運用で、子どもが非同期の場に書き込むかどうかを確認してから着手します。プロンプトは現時点の叩き台で、着手前に見直します。

3. しつもんポスト

フェーズ2 RTDB 単一ファイル・常設（固定パス） 　非同期の交換日記　・　1回1〜5分

「だれかへの質問」を投函しておくと、あとから来た子が好きなときに答えを書き足す非同期Q&A。リアルタイムで会話しなくても交流が成立するので、チャット参加の子・沈黙が好きな子にいちばんやさしい形式。質問テンプレのガチャで「何を聞けばいいかわからない」を防ぐ。

リスクと対策: 自由入力の常設蓄積は荒れ・個人情報・重い相談の3リスクがある。文字数と件数の上限、メンターのかたづけ機能、「こまったときはメンターに話してね」の一言を必ず入れる。悩み相談ツールにしない（それはメンタリング本体の仕事）。

4. みんなの図鑑

フェーズ2 RTDB 単一ファイル・常設（固定パス） 　長期の共同制作　・　1体3〜10分

架空のいきものを1体ずつ登録していく「roomKいきもの図鑑」。来た子が好きなときに1体足していき、図鑑が少しずつ育つ。45分で完結しないことがむしろ強みで、「続きやろう」「新しいの見た？」が次に来る理由になる。絵を描く機能は持たず、アイコン＋色の組み合わせで「みため」を作るので、絵が苦手な子も差がつかない。

リスクと対策: 作品の出来に優劣がつく見え方をしないよう、いいね・人気順・作者ランキングを入れない。並びは登録順（図鑑No.）だけ。他人のいきものは編集できない。

6. 運用しながら決めること（未決事項）

今決めなくてよい事項。フェーズ1の運用中に判断します。

  • 常設型の荒れ対策をどこまでやるか（まずは性善説＋メンターかたづけ。問題が起きたら合言葉方式などを検討）
  • MetaLife 内の導線の張り方（掲示物に URL / QR を置く場所、ボードの前にオブジェクトを置くか）
  • きょうの2たくのお題を子どもから募集するか（しつもんポストが育ったら「お題ポスト」を検討）
  • 図鑑をいきもの以外（架空の街マップ・お店図鑑など）に広げるか（第2巻の形）
  • 既存ボドゲの自由時間解禁で「進行役なしでも遊べているか」（遊べていないなら進行役なし用の簡易モード追加を検討）
  • プログラム45分との住み分け（自由時間で人気が出たコンテンツをプログラム側に昇格させるか）
