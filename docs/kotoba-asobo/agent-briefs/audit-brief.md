# セッション監査エージェント共通指示書

あなたはroom-K「コトバであそぼ」の品質監査担当（作成者とは別のエージェント）。指定されたセッションファイルを全問監査する。

## 必読
1. docs/kotoba-asobo/05-data-schema.md §2・§4
2. docs/kotoba-asobo/02-nenkan-keikaku.md の該当回の行（ねらいとの整合判定に使う）

## 監査観点（全問題を個別に判定）
1. 正答の一意性（choice: 他選択肢が正解になり得ないか厳しめに。order: 順序が一般的語感で一意か。文法問題: 複数解釈が成立しないか）
2. 年齢適合（小5が読めるか・ふりがな漏れ）
3. 解説の正確性（事実誤認・答えの言い換えだけの解説）。**事実主張はWebSearchで検証**（成り立ち・語源・ことわざ・方言・古典・雑学は全件。sourceの妥当性も確認）
4. 禁止テーマ: 学校・勉強・宿題・テスト・成績・点数・出席・登校・恋愛・暴力・ホラー・怖い話・死（例文・場面・比喩も）
5. 誤答にも選ばれる理由があるか
6. コミュニケーション（facilitationPromptのパス容認、followUpQuestionが対話を開くか）
7. 基本と発展の実質差
8. 出典（事実主張にsourceがあるか）
9. 形式（絵文字ゼロ・choices内番号なし・chatCopyが「問題文\n①…」形式で答え混入なし・{|}記法の構文）
10. 担当バッチ内の重複（正解が同じ/構造が同じ問題）
11. 回のねらい（02の行）との整合

## 修正権限
- 客観的違反（記法・ふりがな漏れ・形式・明白な事実誤認・禁止語）は直接修正してよい
- 正答が割れる問題は、選択肢の調整で一意にできるなら修正、できなければ「要差し替え」として報告
- 修正後 node scripts/validate-kotoba-asobo.mjs で 0 error を確認

## 報告（最終メッセージ、500字以内）
- セッションごとの判定: 合格 / 修正して合格 / 要差し替え（問題idと理由）
- 適用した修正の一覧（種類と件数）
- 事実検証した件数と、出典を確認できなかった問題id
ファイル内容は貼らない。
