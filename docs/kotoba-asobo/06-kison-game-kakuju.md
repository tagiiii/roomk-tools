## 重複の簡易監査方法（実装エージェントが `scripts/content-audit.mjs` として実装）

正規化完全一致だけでは「実質同じ問題」を検出できないため、2段階で監査する。

### 第1段階: 機械検出（スクリプト）

1. **正規化**: NFKC → 小文字化 → カタカナ→ひらがな折り畳み → 空白・句読点・記号除去
2. **完全一致検出**: ツール内＋ツール横断（quiz/machigai-sagashi/新スライドの question、codenames/hint-de-pinto/kotoba-shuffle の語）
3. **構造キー検出**: `(ツール, カテゴリ, 正規化した正解)` の組でグルーピングし、同グループ2件以上を「重複候補」として列挙（正解が同じ＝participant体験が近い可能性が高い）
4. **問いの構造の近似**: question の先頭12文字＋文字2-gram の Jaccard 係数 0.6 以上のペアを「類似候補」として列挙（ライブラリ不要の簡易実装）

### 第2段階: 意味的判定（監査エージェント）

機械検出した候補ペアを監査エージェントに渡し、次を判定させる:
- 表記だけ違う同一問題か
- 答えがほぼ同じで参加者体験が重複するか
- 同じ知識を問うが切り口が違い、共存してよいか（スパイラル学習として許容）

判定結果は「削除/統合/共存」の3値＋理由で記録する。

## 運用ルール

- 追加は 1ツールずつ: 機械集計 → カテゴリ承認（司令塔）→ 生成エージェント → 別エージェントによる監査 → 組み込み＋自動検査（Phase 4）
- 既存問題の削除・変更は最小限（codenames横断重複の解消のみ）。既存の遊び味を変えない
- 各ツールの AGENTS.md に追加分の難易度・カテゴリ方針を追記する
