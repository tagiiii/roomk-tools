## 優先順位の考え方

1. **プロトタイプ最優先**（I-1〜I-3 = Phase 2）: 45分の実運用に耐えるかを1回分で確かめてから量産する
2. **コンテンツは使用時期順**（I-5→I-6）: U1から順に。プログラム開始後も制作が並走できる（各回独立設計のため）
3. **既存ツール拡充は使用回が近いものから**: kotoba-tantei の重複解消と kotoba-gacha（回11で必要）を先行
4. 学習指導要領対応の再検証は不要（一次資料確認済み）。新規に対応を書き足す場合のみ調査エージェントで一次資料を確認する

## 司令塔の手を空ける進め方

- **司令塔が行うのは**: 各バッチのカテゴリ・方針承認、監査結果のサンプリング確認（全件再読はしない）、AGENTS.md・スキーマ変更のレビュー、Phase間の統合判断
- 生成・監査・実装・検証の全量作業はサブエージェントに委譲する（08参照）
- **監査は「作成したのと別のエージェント」を必ず使う。** これは能力の問題ではなく独立性の担保なので、モデルが強くなっても兼任させない（→ [../ai-roles.md](../ai-roles.md)）
