# 08 サブエージェント向けタスク一覧

> **この計画は Phase 1〜5 すべて完了済み**（進捗は [PROGRESS.md](./PROGRESS.md)）。
> 以降は「同種の年間プログラムを作るときの型」として参照する記録。役割名の定義は [../ai-roles.md](../ai-roles.md)。

原則: **生成と監査は必ず別エージェント**（能力の問題ではなく独立性の担保。モデルが強くなっても兼任させない）。
1バッチ = 最大5回分（コンテンツ）または1ツール（拡充）。

当時の担当は CX 系（実装・機械調査）を別系統モデル、ST 系（コンテンツ・監査・調査）を同系統のサブエージェントが受け持ち、承認は司令塔が行った。同じ型を再利用するときは、CX 系を実装モデルが直接担うかたちでもよい（レーンの分離が目的なので、担当の割り当ては固定ではない）。
各タスクは自己完結のプロンプトとして発行する（このリポジトリの規約・05の品質基準・禁止題材リストを毎回添付）。

## バッチ運用（Phase 3の例）

```
ST-2(U1: 回1〜5) → ST-3(監査) → 修正 → CX-4(組込)
→ ST-2(U1残り+U2前半: 回6〜10) → ...（以降5回分ずつ）
```

- 各バッチのプロンプトには「既出問題の一覧（question要約＋正解）」を含め、バッチ間重複を防ぐ
- 監査で不合格が3割を超えたバッチは、生成プロンプトを修正してからやり直す（個別修正で押し切らない）
- 司令塔は各バッチの監査サマリ（合格率・代表的な指摘）のみ確認する

## 全タスク共通の制約（プロンプトに毎回含める）

- 絵文字禁止・丸数字①②③統一・Material Symbols Rounded
- 禁止題材: 学校・勉強・宿題・テスト・成績・出席・登校・不登校・恋愛・暴力・ホラー・死。文法等の学習内容自体は可だが例文・場面設定に上記を使わない
- ふりがな記法 `{漢字|かんじ}`。生HTML禁止
- 正解を強要しない・パスを認める・好みを否定しない・個人情報や家庭事情を答えさせない
- チャットコピー形式（問題文→①②③、答えを混ぜない）
