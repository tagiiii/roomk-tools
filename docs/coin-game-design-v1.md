# 小銭の合計あて（仮） 設計書 v1

作成: 2026-11-04 ／ ステータス: **同日 `drafts/coin-baton/` で試作 → オーナー承認で `apps/charin-baton/`（ちゃりんバトン）に本体化**。本体の仕様の正本は [apps/charin-baton/AGENTS.md](../apps/charin-baton/AGENTS.md)。この設計書は検討の記録として残す

テレビ番組『THE FLOOR』（日本テレビ系）のジャンル「小銭」から着想した、並んだ硬貨の合計金額を答えるゲーム。
2026-11-04 にスタッフからの DM（「子どもと見ていて面白かった。お金の話もできて、生活にも役立つ」）を受けて、オーナーが仕様検討を依頼。

## 0. 調べてわかったこと

### 番組の対決（デュエル）のルール

番組の公開情報（日本語版・海外版の Wikipedia、番組紹介記事）で確認できたこと。

| 項目 | 番組のルール |
|---|---|
| 出題 | 画面に画像が出る（すべて画像・映像を見て答える「ビジュアルクイズ」） |
| 回答 | 2人が**交互に**声で答える（早押しではない）。挑戦する側が先 |
| 持ち時間 | 1人45秒。自分の番の間だけ自分の時計が減る（チェスの時計と同じ） |
| 正解 | すぐ相手の番になり、相手に次の問題が出る |
| まちがい | ペナルティーなし。正解するまで何回でも答えられるが、その間も時計は減る |
| パス | できる。次の問題が出るまで3秒待たされる（＝3秒失う） |
| 決着 | 先に持ち時間がなくなった人の負け |

番組全体は、32人が床のマス（陣地）を持ち、となりの人に挑んで勝つと相手の陣地をもらう陣取り。

### 「小銭」の回について

- 出演者の中間淳太さんのジャンルが「小銭」であることは確認できた
- 放送は 2026-11-04 の3時間スペシャル（子どもたちが見ていた回と思われる）。出題の中身を書いた公開情報は見つからなかった
- 出題の中身は、DM の説明（「ランダムに小銭が置かれていて、合計いくらかを当てる」）と、**オーナーが放送を見て確かめたこと（2026-11-04）** を正本にする
  - 出るのは**硬貨だけ**（お札はない）
  - **2枚から始まり、だんだん増えて4〜5枚くらいまで**で対戦していた

### 硬貨の絵を描くときの注意

財務省の FAQ によると、通貨及証券模造取締法は「貨幣と紛らわしい外観のもの」の製造・販売を禁じており、似ているかどうかは図柄・大きさ・材質などから総合的に判断される。
→ **本物の図柄（桜・稲穂・平等院など）は描かない**。色・穴・大きさ・数字だけの、ひと目で絵とわかる硬貨にする。子どもにとっても数字があるほうが読みやすい。

## 1. 位置づけとねらい

- **core value**: 硬貨を数えることが、そのまま遊びになる。番が行ったり来たりするテンポで盛り上がり、終わったあと「50円玉2枚と100円玉1枚は同じだね」とお金の話につなげやすい
- **利用シーン**: ボドゲクラブ（`bodoge`）・ひろば（`hiroba`）・作戦会議（`sakusen`。メンターと1対1でも遊べる）
- **対象**: 小学校中学年〜中学生。所要時間 1回3〜5分（何回もくり返して遊ぶ）
- **勉強に見せない**: 中身は算数なので、画面・名前・説明に「計算」「練習問題」「ドリル」「算数」などのことばを使わない。テーマは「おさいふ」「お店のレジ」に寄せる
- **競争について**: 番組と同じく勝ち負けのある対決にする（ピタハメ・リバーシと同じく、意図して競争を残す）。ただし、計算の得意・不得意がそのまま勝ち負けに出やすいので、**人ごとの硬貨の種類・持ち時間（ハンデ）** と、**時間なしのモード** を用意する。通算成績・ランキング・正答率は残さない

## 2. モード

| モード | 通信 | 内容 |
|---|---|---|
| ① 対決（ルーム） | RTDB ルーム | 2人がそれぞれの端末で答える。ほかの人は観戦。番組と同じ持ち時間ルール |
| ② 対決（1台の画面） | なし | メンターが画面共有し、子どもが声で答えた数字をメンターが入れる。Zoom / Meet で**いちばん使いやすい形**と考えている |
| ③ いっしょに数える（1台の画面） | なし | 時間なし・勝ち負けなし。硬貨を見て、みんなで数えて、「答えを見る」で答え合わせ。お金の話をするとき用 |

- ③は v1 では1台の画面だけにする（ルームで全員が答えを入れる形は、答えをそろえて比べる形になりやすいので見送る）
- 1対1（メンター対子ども）でも、子どもどうし（メンターが進行）でも遊べる

## 3. 対決のルール

| 項目 | 内容 | 初期値 |
|---|---|---|
| 人数 | 2人（ルームの3人目からは観戦） | — |
| 持ち時間 | 30秒・45秒・60秒・90秒から選ぶ。人ごとに変えられる（ハンデ） | 45秒（番組と同じ。1問が2〜5枚と少ないため） |
| 先攻 | 待合室でホストが決める（くじ・A・B） | くじ |
| はじまる前 | 3・2・1 を出す。小銭はかくし、時計は止める（試作で追加） | 3秒 |
| 正解 | 小銭を見せたまま、トレーの下に「正解！ 280円」と内訳を1.5秒出す（**この間はふたりとも時計を止める**）→ 相手の番になり、相手に新しい問題 | — |
| まちがい | 入れた数字を消して「もう一回数えてみよう」。何回でも答えられる。時計は止めない | — |
| パス | 「パス」で次の問題へ。3秒へる（3秒待つ間も自分の時計が減り、問題はかくれる） | 3秒 |
| 決着 | 持ち時間が0になった人の負け。「○○の勝ち！」 | — |
| もう一回 | ホストが「もう一回」（先攻を入れかえる）・「対戦する人を選びなおす」 | — |

- 正解のあとの1.5秒の間は番組にない。答えの金額をみんなが目で見て確かめられるようにするため（数えまちがいを、その場でふりかえれる）
- 音は鳴らさない（残り時間は色の変化だけ）

### 結果の画面

- 「○○の勝ち！」と、その対決で出た問題を一覧で出す（硬貨の絵の小さな版と合計）。だれがどれを解いたかは出さない（正答数を比べる画面にしない）
- 一覧の問題を押すと大きく出せる（メンターが「これは何円玉が何枚？」と話をふるため）
- 記録は残さない（もう一回やると消える）

## 4. 問題（硬貨の出し方）

### 硬貨

| 硬貨 | 色 | 穴 | 大きさ（実物の直径） |
|---|---|---|---|
| 1円 | 白っぽい銀 | なし | 20.0mm |
| 5円 | 金 | あり | 22.0mm |
| 10円 | 銅（茶） | なし | 23.5mm |
| 50円 | 銀 | あり | 21.0mm |
| 100円 | 銀 | なし | 22.6mm |
| 500円 | 金（ふちだけ色を変える） | なし | 26.5mm |

- 大きさは実物の比で描く（500円が大きく、1円が小さい）
- **硬貨の中に金額の数字を大きく書く**（色だけに頼らない。色覚の多様性への配慮）
- 図柄は描かない（0章の模造の注意）。お札は v1 では出さない

### 枚数（だんだん増える）

番組に合わせて、**2枚から始めて、正解するごとにだんだん増やす**（2026-11-04 オーナー確認）。

| その人が正解した数 | 0〜1問 | 2〜3問 | 4〜5問 | 6問から |
|---|---|---|---|---|
| 硬貨の枚数 | 2枚 | 3枚 | 4枚 | 5枚（上限） |

- 枚数は**その人の正解の数**で決める（ふたりが同じ順で増える。パスでは増えない）
- 上限はホストが選ぶ（4枚・5枚・6枚・8枚。初期値は番組と同じくらいの5枚）

### 硬貨の種類（人ごとに選べる）

| 種類 | 使う硬貨 | 初期値 |
|---|---|---|
| ぜんぶ | 1・5・10・50・100・500円 | ◯ |
| 3種類だけ | 1・10・100円（同じ数字が並ぶので数えやすい） | |

- 人ごとに選べる（ハンデ。メンター対子どもや、得意さがちがう子どうしのとき）
- 問題はその場でくじで作る（問題集は持たない）。ただし次を守る
  - 同じ硬貨は3枚まで
  - 直前の問題と同じ組み合わせにしない
- 枚数の増え方・上限・持ち時間は仮置き。試作で触って調整する

### 並べ方

| 並べ方 | 中身 | 初期値 |
|---|---|---|
| ばらばら | トレーの上にくじの位置・向きで置く。重ならない | ◯ |
| そろえる | 金額の大きい順に並べる（数えやすい。はじめての子の補助） | |

- 並べ方はホストが待合室で決める（人ごとではない）

## 5. 答え方

- 画面に**数字のボタン**（0〜9・けす・こたえる）を出し、「◯◯円」を入れて「こたえる」。キーボードの数字キーでも入れられる（Enter で答える）
- 文字入力欄は使わない（日本語入力の変換で数字がずれる問題を避ける。`ui.md`「文字入力欄と日本語入力」）
- 判定はアプリが自動で行う
- ②1台の画面: 子どもが声で言った数字を、メンターが入れて「こたえる」
- ①ルームの**端末なしの参加者**: その人の番は、ホストの画面に数字のボタンが出て、ホストが代わりに入れる（リバーシと同じ）

> 番組どおり「声で答えて、メンターが正解・ちがうを押す」形も考えたが、画面共有中はメンターだけに答えを見せられないため、数字を入れて自動で判定する形にした。

## 6. 画面

### 対決の画面

```
┌───────────────────────────────┐
│  あおい  0:42        ゆうと  0:58  │ ← 番の人の札を強調。残り10秒から色を変える
├───────────────────────────────┤
│  あおいの番                         │
│  ┌───────────────────────┐   │
│  │   (100) (10)  (50)        │   │ ← 硬貨のトレー
│  │ (10)   (1)   (100)        │   │
│  └───────────────────────┘   │
│        [  2 8 0 ] 円               │
│   0〜9 の数字ボタン ／ けす ／ こたえる   │
│                     パス（−3秒）    │
└───────────────────────────────┘
```

- 番でない人・観戦の人・みんなにみせる画面: 同じ硬貨のトレーを出す。番の人が入れている途中の数字は出さず、正解したときだけ金額を出す
- 広い画面（900px 以上）では、ふたりの札をトレーの左右に置く（画面共有で見やすく）
- ボタン階層: 塗りつぶしの主ボタンは「こたえる」1つ

### そのほかの画面

- トップ: 「ルームを作る」（主ボタン）・「ルームに参加する」・「1台の画面であそぶ」（対決／いっしょに数える）・「みんなにみせる画面をひらく」
- 待合室: 対戦する2人（A・B）・持ち時間と硬貨の種類（人ごと）・枚数の上限・並べ方・先攻・端末なしの参加者を足す・「はじめる」
- ③いっしょに数える: トレー・「答えを見る」→「◯◯円（100円玉2枚・50円玉1枚・10円玉3枚）」・「次の問題」。枚数（2〜8枚）・種類・並べ方はその場で変えられる

## 7. 技術の方針（実装時に詰める）

- 分割型（`index.html`・`app.js`・`engine.js`・`style.css`）。硬貨の問題作り・判定は `engine.js` に分けて node でテストする
- RTDB のルーム型。ルームコード・参加用リンク・QR コード・ホスト参加の選択・端末なしの参加者・みんなにみせる画面など、共通の型にそろえる（`docs/development/rtdb.md`）
- 問題（硬貨の種類・位置・向き）は番が来るたびに作って RTDB に書き、全員が同じ配置を見る。答えも DB に入るが、性善説で許容（AGENTS.md「セキュリティ方針」）
- 時計はリバーシの1手の制限時間と同じ作り（番の始まりをサーバーの時刻で記録し、残り時間は各端末で数える。正解・時間切れは transaction で1回だけ通す。**ホストが切れている間は時計を止める**）
- 硬貨は SVG で描く（画像ファイルを持たない）
- 新しいアプリの横断更新（ポータルのカード・早見表・updates.json・lint・content-audit・howto.js・stats.js・説明スライド）は `new-app-scaffold` スキルに従う

## 8. v1 に入れないもの（あとで考える）

- 番組の陣取り（床のマス）・勝ち抜き戦。v1 は1回ずつの対決だけ
- お札（紙幣は模造の注意がより厳しく、絵も複雑になる）
- 「おつり」「これで何が買える？」の問題（お金の話はメンターがその場でふる。画面で促さない）
- 硬貨の数字をかくす上級（色・穴・大きさだけで見分ける）
