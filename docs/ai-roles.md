# AI の役割定義（モデル固有名の正本）

このリポジトリのドキュメントで「司令塔」「実装モデル」「別系統モデル」などと書かれている役割の定義。
**モデルの固有名（世代名）を書くのはこのファイルだけ**とし、他の文書は役割名で書く。
モデル世代が変わったときに更新するのはこのファイル1枚で済むようにするためのもの。

最終更新: 2026-07-28（**実装モデルに Sonnet 5 を追加し「Opus 5 または Sonnet 5」に。司令塔は Fable 5 のまま変更なし**）

## 役割

| 役割名 | 現行の担当 | 何をするか |
|---|---|---|
| **司令塔** | **Fable 5** | 方針・カテゴリの承認、設計の確定、監査サマリのサンプリング確認（全件再読はしない）、フェーズ間の統合判断、規約・スキーマ変更のレビュー |
| **実装モデル** | **Opus 5 または Sonnet 5**（Claude Code。旧: Opus 4.8） | 設計の具体化・実装・監査・ブラウザ動作確認・コミット。日々の作業の全量 |
| **別系統モデル** | Codex（ChatGPT 系・MCP 経由。`codex` / `codex-reply` ツール） | 実装モデルの成果物への**独立レビュー**。同じ盲点を共有しにくいことに価値があり、能力の高低で選んでいるのではない |
| **サブエージェント** | 実装モデルと同系統の別コンテキスト | 並列調査、生成と監査の分離、読み取り専用の横断棚卸し |
| **オーナー**（人間） | — | 体験判断、変更禁止パスの解除、コンテンツ本体投入、支援方針。**代替不可** |

- **司令塔と実装モデルは別**。司令塔の直接作業は承認・レビュー（テキスト確認中心）にとどめ、全量作業は実装モデルとサブエージェントに委譲する
- 「二重レビュー」＝ 実装モデル（またはサブエージェント）＋ 別系統モデル の2系統
- 「別エージェント監査」＝ 生成したのと別コンテキストのサブエージェント。同系統でよい
- オーナーの判断は司令塔でも代替できない。司令塔は AI であって決定権者ではない

## ガードレールの2種類（モデル世代が上がったときの扱い）

各文書のガードレールは、**能力由来**か**権限由来**かで扱いが変わる。混ぜないこと。

### 権限由来 — モデルが強くなっても一切緩めない

理由が「AI の精度」ではなく「決めてよい人が誰か」にあるもの。

- 子どもの体験・発達・支援方針の判断（`audit-prompts.md` §P6「AI は結論を出さない」）
- 変更禁止パス（`firestore.rules` / `database.rules.json` / `firebase.json` / `apps/shared/**` / `.github/**`）
- 新規コンテンツの本体投入（Tier D-3）
- `drafts/` から `apps/` への移植・公開
- roomK 哲学ガード（`audit-prompts.md` §0.5）

**2系統のモデルが一致しても、権限由来の判断の根拠にはならない。** 一致は精度の話であって権限の話ではない。司令塔の承認も同じで、オーナー判断の代わりにはならない。

### 能力由来 — 実測してからなら再調整してよい

- 1イテレーションの差分量の目安（分割可能性の目安。可逆性の担保でもあるので撤廃はしない）
- 1回の監査で返す finding の上限（※ただし後述）
- 生成と監査を別エージェントに分ける運用（独立性の担保でもあるので撤廃はしない）

再調整するときは「緩めてみた結果どうだったか」を記録に残す。勘で緩めない。

### 能力由来に見えて実は違うもの

- **`audit-prompts.md` の「最大5件」**: モデルが5件しか見つけられないという意味ではなく、**人間の判断キューへの流入制御**。世代が上がっても緩めない。
- **`kaizen-backlog.md` の「1アプリ × 1関心事 × 1コミット」**: 精度ではなく**revert しやすさ**のため。緩めない。
- **司令塔と実装モデルの分離**: 実装モデルが強くなっても、承認と実装を同じコンテキストで兼ねさせない（自己承認になる）。

## モデル世代が変わったときにやること

1. このファイルの表と「最終更新」を書き換える（**どの役割を差し替えたのかを明記する**。司令塔と実装モデルは別々に更新されうる）
2. 進行中の B+ シャドー判定（`kaizen-backlog.md`）の集計を**世代でリセット**する。世代をまたいだ判定を混ぜて誤承認率を出さない
3. 他の文書に固有名が混入していないか確認する:

```bash
git ls-files '*.md' | grep -v '^docs/reports/' | xargs grep -nE "Opus|Sonnet|Haiku|Fable|Codex"
```

次は**事実記録なので固有名のまま残す**（当時どのモデルで何をしたかの記録に価値がある）。上のコマンドがこれらを拾っても書き換えない。

- `docs/reports/**`
- `docs/kaizen-backlog.md` の完了済みエントリ・決着履歴・`<details>` 内の提案原文
- `docs/kotoba-asobo/PROGRESS.md`（バッチごとの実績）
- `apps/{app}/AGENTS.md` の設計経緯（「〜レビュー指摘による設計変更」など）
- `docs/content-candidates/**`、`docs/pitahame-design-v1.md` などの完了済み設計・候補文書
