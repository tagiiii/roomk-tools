作戦会議コンテンツ 制作計画

room-K オンラインメンタリング「コンテンツ実施」枠の新規ツール制作ロードマップ ／ 2026-07-04 作成
この計画書の使い方
  • 上から順に1本ずつ作ります。各コンテンツの「実装プロンプト」をコピーして、Claude Code（Fable 5）にそのまま貼り付ければ実装が始まります。
  • 1本作るごとに「実装 → メンター実機確認 → 文言の別視点監査 → コミット → 実際のセッションで使用」まで回してから次に進みます。
  • フェーズ2の4本は、フェーズ1の運用で見えたことを反映してから着手します（プロンプトは叩き台として掲載）。

0. 決定事項と設計原則

決定事項（2026-07-04 確認済み）
  • 操作形態: メンターの画面共有が基本。子どもが URL を開いて操作する回もある前提で、スマホ・タブレットでも使えるようにする（ルームコード同期は使わない）。
  • 記録方針: サーバー保存なし。回をまたぐコンテンツは「さくせん会議」と同じ JSON 書き出し／読み込み方式。使い捨てでよいものは保存機能自体を持たない。
  • 規模: フェーズ1の4本を先行制作し、フェーズ2の4本は運用の様子を見て着手判断。

全コンテンツ共通の設計原則（codex 相談で確定）

  • 「パス」「わからない」「保留」「なんとなく」を正式な回答として設計する。ボタンとして用意し、選んでも進行が止まらない。これが最重要原則。
  • 評価・比較・数値化・ランキング・連続記録・バッジ・賞賛演出を入れない（数値化は「キャパグラフ」だけの意図的な例外）。
  • 「答えられない自分」を意識させない。0件・無回答でも画面が成立する。
  • 成果物（JSON・画面）が子どもへの評価物・証拠物に見えないようにする。
  • 学校・勉強・成績・登校・恋愛・ダーク系の話題は出さない（AGENTS.md コンテンツガイドライン準拠）。
  • 年間の使用バランスとして、自己理解系ばかり連続させない。「毎回自分について語らされる」状態を避け、遊び寄りコンテンツと交互に使う。

1. 全体ロードマップ

順コンテンツフェーズ主な役割所要記録心理的負荷
1どっちにする？先行 自己決定の練習・関係構築5〜10分なし最小
2チェックアウトカード先行 面談の締め・次回への接続1〜2分なし最小
3すきなことマップ先行 興味関心の可視化・蓄積10〜15分JSON低〜中
4きもちのことばマップ先行 感情の言語化5〜10分なし中（設計で低減）
5つよみカード様子見 自己理解（強みの発見）10〜15分JSON（任意）中
6チャレンジのたね様子見 自己実現（さくせん会議の前段）10分JSON中
7みらいの引き出し様子見 選択肢と世界との接続10〜15分JSON（任意）中
8ばめんカード様子見 経験の整理・語りの練習10〜15分なし中〜高（再設計済み）

この順番の理由

  • 1・2 が先頭: 実装が最も軽く、心理的リスクが最小で、毎週どの子にも使える。制作→運用のサイクルを最速で1周させ、以降の型を作る。
  • 3 で蓄積型の型を作る: JSON 入出力（さくせん会議方式）を新コンテンツで初めて使う。今後のコンテンツ選びの土台（その子の興味データ）にもなる。
  • 4 は重要だが慎重に: 感情を直球で聞く設計になりやすいため、1〜3 の運用感覚を得てから作る。
  • 5〜8 は運用判断: つよみ・チャレンジ・みらい・ばめんは、子どもとの関係性やフェーズ1の反応を見てから。特に 7・8 は codex 指摘を受けて当初案から再設計済み（職業→世界の入口、実話→架空も可）。
codex 相談で当初案から変えた点
  • 順番を「自己理解系が先」から「低負荷・遊び寄りが先」に組み替え（毎回自分を語らされる負荷の回避）。
  • 「チェックアウトカード」は独立コンテンツではなく超軽量ミニツールとして位置づけ、将来は全ツール共通の終了部品化も検討。
  • 「みらいの引き出し」は職業カタログをやめ、場所・自然・ものづくり等の「世界の入口」に変更。反応も数値でなく「のぞいてみる／あとで見る／今はいい」。
  • 「ものがたりカード」は実話の語り直しをやめ、「今日の小さな場面／好きな作品の場面／架空の主人公」も選べる「ばめんカード」に再設計。
  • 「チャレンジのたね」はさくせん会議への入口専用と明確化。「ながめる・保留・やめる」も成功扱い。

2. 制作の進め方（1本ごとの手順）

  1. 下の実装プロンプトをコピーして Claude Code に貼り付ける。
  2. 実装完了後、bash scripts/lint.sh の通過とローカル動作を確認する。
  3. カード文言・お題などのコンテンツデータを別セッションのエージェントに監査させる（プロンプト例: 「apps/○○/ のお題データを AGENTS.md のコンテンツガイドラインに照らして全件監査して」）。kotoba-asobo で実績のある手順。
  4. メンター（自分）が実機で一巡し、文言・テンポ・負荷感を調整する。
  5. コミットして GitHub Pages へデプロイし、実際のセッションで使う。
  6. 使用感メモ（子どもの反応・詰まった箇所）を残してから次のコンテンツへ。

3. フェーズ1（先行4本）

1. どっちにする？

フェーズ1 オフライン単一構成・保存なし 　自己決定の練習／関係構築　・　5〜10分

軽い2択のお題カードをめくり、どちらかを選んで話すだけのツール。「自分で選んでいい」という感覚を、いちばん小さな形で毎週練習できる。理由は聞かなくてもよく、「なんとなく」が正式な回答。

リスクと対策: 最小リスク。ただし「理由を言って」が圧にならないよう、理由の入力欄や必須化は作らない。優劣・正誤がつく2択（どっちが正しい？系）はデータに入れない。

2. チェックアウトカード

フェーズ1 オフライン単一構成・保存なし 　面談の締め・次回への接続　・　1〜2分

面談の最後に1問だけ引く超軽量ツール。「今日の体験を次回につなげる」ための問いを、評価に見えない形で投げかける。作戦会議の流れに「チェックアウト」を正式に組み込むための道具。

リスクと対策: 「今日どうだった？」はメンターからの評価質問に見えることがある（codex 指摘）。問いプールは「次はどれがよさそう？」「今日はここまででOK？」など、子どもが選ぶ・決める形の問いに寄せる。

3. すきなことマップ

フェーズ1 オフライン + JSON入出力（さくせん会議方式） 　興味関心の可視化・蓄積　・　10〜15分

「すき」「ちょっと気になる」を書き出してマップに置いていく、回をまたいで育てる蓄積型ツール。数週間〜数か月かけてその子の興味の地形図ができ、以降のコンテンツ選び・お知らせ（イベント案内）の土台になる。

リスクと対策: 「好きなことがない」と感じる子に負荷がかかる（codex 指摘）。「すき」より弱い関心──「ちょっと気になる」「見るのはあり」「まえはすきだった」──を正式な置き場所として用意し、0個でも成立する導入お題から始める。kyoumi-sugoroku（会話のきっかけ）とは「蓄積する」点で役割分担。

4. きもちのことばマップ

フェーズ1 オフライン単一構成・保存なし 　感情の言語化　・　5〜10分

感情のことば（60〜80語）をゆるいグループでマップ表示し、「今日の気持ちに近いことば」を探して眺めるツール。「なんとなく嫌」「疲れた」を、その子のペースで少しずつ細かい言葉に置き換えていく。checkin（今の状態共有）との違いは「語彙を増やす・近い言葉を探す」こと。

リスクと対策: 気持ちを直球で聞かれるとしんどい子がいる（codex 指摘）。「わからない」「どれでもない」「今日は選ばない」を正式ボタンにし、強さは数値でなく「ちいさめ・ふつう・おおきめ」の3語。記録は残さず使い捨て（気持ちを証拠化しない）。

4. フェーズ2（様子見4本・叩き台プロンプト）

フェーズ1の運用で見えたこと（子どもの反応・使いやすさ・JSON運用の負担感）を反映してから着手します。プロンプトは現時点の叩き台で、着手前に見直します。

5. つよみカード

フェーズ2 オフライン + JSON書き出し（任意） 　自己理解（強みの発見）　・　10〜15分

「〜なところがあるかも」と語尾を弱めた強みカードを、子どもとメンターがそれぞれ選んで見せ合うツール。value-card（価値観＝大事にしたいこと）とは「強み＝たまに出る力」という軸の違いで住み分ける。

リスクと対策: 褒められるのが苦手な子にはきつい（codex 指摘）。カードは断定形にしない・「メンターから見えたところ」というフレーミングにする・褒め演出を入れない。

6. チャレンジのたね

フェーズ2 オフライン + JSON入出力 　自己実現（さくせん会議の前段）　・　10分

「ちょっとやってみたいかも」を集めておく、たねポケットのようなツール。さくせん会議（GPDC）が「決めて試す」段階なのに対し、こちらは「まだ決めない」段階専用。たねは「ためす」だけでなく「ながめる・ほりゅう・やめる」も全部正式な扱い。

リスクと対策: 「やること」を決めさせると失敗の証拠になりやすい（codex 指摘）。たねの状態に成功/失敗の概念を持ち込まない。さくせん会議とのカニバリを避けるため、このツールでは計画を立てない。

7. みらいの引き出し

フェーズ2 オフライン + JSON書き出し（任意） 　選択肢と世界との接続　・　10〜15分

職業カタログではなく「世界の入口」（場所・自然・動物・ものづくり・音・食べもの…）を引き出しを開けるように眺めるツール。反応は「のぞいてみる／あとで見る／今はいい」の3種類だけ。すきなことマップの運用データが溜まってから作ると精度が上がる。

リスクと対策: 職業・将来を前面に出すと進路圧になる（codex 指摘で当初案から再設計）。「しょうらい」「しごと」「しんろ」という語をUIに出さない。

8. ばめんカード

フェーズ2 オフライン単一構成・保存なし 　経験の整理・語りの練習　・　10〜15分

当初案「ものがたりカード（実話の語り直し）」を再設計したもの。「今日の小さな場面」「すきな作品の場面」「架空の主人公の場面」の3モードから選べるため、自分の話をしたくない日は作品や架空の話で語りの練習ができる。8本の中で最も負荷が高いため最後。

リスクと対策: 実話モードは家庭・学校の話題に触れやすい（codex 指摘）。実話を強制しない3モード構成にし、語られた内容をアプリは一切記録しない。

5. 運用しながら決めること（未決事項）

codex 相談で挙がったが、今決めなくてよい事項。フェーズ1の運用中に判断します。

  • 低学年寄りの子と中学生で文言セットを分けるか（まずは全年齢ひらがな多めで統一）
  • メンター専用メモ（子どもに見せない画面）が必要か（まずは作らない）
  • 保護者・運営に共有する成果物を作るか（まずは作らない。「証拠化しない」哲学を優先）
  • チェックアウトカードを全ツール共通の終了部品に組み込むか（単体運用で価値検証後）
  • JSON ファイルの管理がメンター運用として続けられるか（負担が大きければ再検討）
  • 年間の「遊び系 : 自己理解系」の使用比率（運用ログを見て調整）
  • センシティブな話題が出たときのメンター対応手順（ツール外の運用ルールとして整備）
