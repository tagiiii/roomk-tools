# フィードバック機能の「説明を求められたときの答え」

作成: 2026-10-30。画面には出さない（オーナー判断）。保護者・room-K の運営・スタッフから聞かれたときに、この内容で答えられるようにしておくメモ。
法律の判断は弁護士のものではない。最終的な判断は room-K の運営（子どもと保護者に責任を負う事業者）が行う。

## 0. 「どういう仕組みで、どこに溜まって、どう管理しているか」への答え（2026-10-30 追記）

**仕組み**: 各ツールの右下にあるフィードバックのボタンを押すと、送信ページが別のタブで開きます。
「どのツールか」「どんな種類か」「何があったか（300字まで）」の3つを選んで・書いて送ると、それがサーバーに届きます。
名前・メールアドレス・だれが送ったかは送られません。

**どこに溜まるか**: 2か所だけです。
1. **Firebase**（Google のデータベース。ツールのルーム機能と同じ場所。サーバーはシンガポール）の `feedback` という区画。
   ここは「書けるが読めない郵便ポスト」の設定で、ツールやブラウザからはだれも読めません。
2. 制作者が取り込んだあとは、制作者だけが開ける **claude.ai の非公開ページ（フィードバックボード）**。
   取り込んだ分は Firebase から消えるので、同じ内容が2か所に残り続けることはありません。

**どう管理しているか**: 制作者が、ボードで1件ずつ「直す／保留／見送り」を決めます。
直すと決めたものは、AI（Claude Code）が修正案を作り、制作者が内容を確認してから公開します。
対応が終わったものはボードから消します。本文を GitHub など公開の場所に貼ることはありません。

**読めるのはだれか**: 制作者だけ（Firebase 側は管理者の鍵、ボード側は本人のログイン）。room-K の運営から求めがあれば、本文を見せずに「どんな声がどれだけあったか」を伝えられます。

## 1. 短い答え（30秒版）

> ツールの「フィードバックを送信する」は、困ったことや直してほしいことを送る仕組みです。
> 記録するのは「どのツールか・どんな種類か・本文（300字まで）・送った日時」の4つだけで、
> 名前・メールアドレス・だれが送ったか・端末の情報は記録しません。
> 送られた内容は制作者だけが読み、整理が終わったら消します。

## 2. 何を集めて、何を集めないか

| 集めるもの | 集めないもの |
|---|---|
| ツール名（`app`・リンクから自動） | 名前・ニックネーム |
| 種類（`kind`・6つから選ぶ） | メールアドレス・連絡先 |
| 本文（`text`・300字まで） | だれが送ったか（ログインの ID＝UID も書かない） |
| 送った日時（`at`・サーバーの時刻） | 端末・ブラウザ・IP アドレス（アプリ側では記録しない） |

- 欄はこの4つに**ルールで固定**している（ほかの欄は書けない。`docs/feedback-loop/database.rules.feedback.md`）
- 画面には「名前などは書かないでください」と出している
- それでも本文に名前などが書かれた場合は、整理の段階で伏せ字にし、原文は消す（§4）

## 3. どこに保存され、だれが読めるか

- 保存先: Firebase Realtime Database（Google のサービス。サーバーはシンガポール `asia-southeast1`）の `feedback/`。1時間に1回、制作者だけが見られる非公開の GitHub リポジトリの Issue に移され、RTDB からは消える
- 読めるのは: Firebase プロジェクトの管理者（制作者）と、制作者が設定した整理用の仕組み（routine A）だけ。
  **アプリやブラウザからは、送った本人を含めてだれも読めない**（ルールで `.read: false`）
- 一度送ったものは、本人でも書き換え・削除できない（改ざん防止）
- GitHub などの公開の場所には、原文は置かない。置くのは伏せ字済みの要約だけ

## 4. いつ消すか

- RTDB の原文は、Issue になった時点（1時間以内）で消える
- 非公開リポジトリの Issue は、対応が終わったら閉じる・消す。公開リポジトリの PR には技術的な要約だけを書き、本文は貼らない

## 5. 法律の論点と、今の設計での考え方

| 論点 | 考え方 |
|---|---|
| 個人情報保護法 | 名前・連絡先・ID を集めない設計なので、原則として「個人情報」を取得していない。同意・利用目的の通知は不要と考えている。本文に書かれてしまった場合は、伏せ字と早期削除で「残さない」 |
| 海外のサーバー | 個人情報を外国の事業者に預ける場合の規律（越境移転）は、個人情報を集めない以上、原則として対象外。**既存のアプリもすでに同じ Firebase を使っており、条件は同じ** |
| 電気通信事業法の外部送信規律 | 端末から外部へ情報を送る仕組みの通知・公表義務。このサイトは広告・解析ツールを入れておらず、`stats.js` は回数だけ、フィードバックは上の4つだけ。サイト全体としてどう扱うかは、今回の変更で初めて生じる論点ではない。求められれば「送っている情報の一覧」を1ページ用意できる |
| 子どもが相手 | 子どもから同意を取るのではなく「最初から集めない」設計。海外の子ども向け規制（COPPA など）が直接及ぶ想定ではないが、同じ考え方に沿っている |
| room-K との関係 | ツールは制作者個人の制作物（`AGENTS.md`）。room-K の運営には「フィードバックの仕組みを入れた。名前などは集めない」と伝えておくのがよい。運営のプライバシーポリシーとの整合は運営側の判断 |

## 6. よくある質問

- **「だれが送ったか本当に分からないのか」** → アプリは UID・名前・端末情報を書かない。ルールで欄が固定されているので、アプリを改造しても書けない。Firebase 側に残る接続のログ（IP など）は Google の管理で、制作者は本文と結びつけて見ない
- **「子どもが自分の悩みを書いてしまったら」** → ツールの改善には使わず、伏せ字にしたうえで原文を消す。内容が深刻なら、制作者から room-K の運営に「こういう声があった」とだけ伝える（本文は渡さない）。→ この運用は運営と事前に決めておく
- **「送った内容を消してほしい」** → 送った本人を特定できないので、個別には消せない。整理が終わると自動で消える
- **「送るのをやめたい」** → ボタンを押さなければ何も送られない。ボタン自体を消す設定（`feedback: false`）もアプリごとに入れられる
