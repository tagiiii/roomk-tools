クイズパック 難問増強 制作計画（D案）

apps/quiz/ ／ 現場の「問題が少ない・簡単すぎる」への根本対応 ／ 2026-07-08 作成
この計画書の使い方
  • 上から順に1バッチ（＝1パックに10問追加）ずつ作ります。各パックの「実装プロンプト」をコピーして、Claude Code にそのまま貼り付ければ実装が始まります。
  • 1バッチ作るごとに「実装 → 既存問題との重複＆事実監査（別視点） → bash scripts/lint.sh → メンター実機 → コミット」まで回してから次に進みます。
  • Phase 3・4 は Phase 1・2 の運用で見えたことを反映してから着手します。

0. なぜやるか（背景と決定事項）

現場から「クイズの問題が少ない・簡単すぎる」という声が出ていた。2026-07-08、まず出し方（UI）を改善済み：問題数（5問／10問／ぜんぶ）× 手ごたえ（ふつう／チャレンジ）を選べるようにし、チャレンジは d3（むずかしめ）中心で出題する。

ただし1点だけ在庫の限界が残った。多くの10問パックは d3 が4問しかなく、10問チャレンジに必要な d3:7 を満たせない。そのため現状の実装では、10問パックで10問／ぜんぶを選ぶと手ごたえが自動で「ふつう」に固定される（配分を変えられないため）。この根本を埋めるのが D案＝難問コンテンツの増強である。

設計原則（codex 相談で確定）

主軸は「既存10問パックの20問化」。新しい難問パックを増やすより先に、よく使う既存パックの d3 在庫そのものを増やす。パックを分裂させず、TOP を複雑にしない。
1パックあたりの目標在庫
  • 現状の多くの10問パック： d1:2 / d2:4 / d3:4（計10問）
  • 目標： d1:3 / d2:7 / d3:10（計20問）
  • 追加する10問の内訳： d1:+1 / d2:+3 / d3:+6

これで「5問ふつう／10問ふつう／5問チャレンジ／10問チャレンジ」がすべて成立する。d3 は7ぴったりではなく10問持たせ、1回目の10問チャレンジ成立に余裕を出す（20問中 d3:10 が「ずっと考えさせられる疲れ」を出さない上限感）。※2回連続の10問チャレンジを重複なしで完全成立させるには d3:14 必要だが、そこまでは狙わない。

「d3（理由を話したくなる）」の良問の作り方

判定基準：答えを知らなくても、選択肢を見て理由を話せるなら d3。知らないと何もできないなら、難問ではなく「マニアック問題」なので不採用。

  • 問いは「なぜ？」「どれがいちばん近い？」「どう考えると自然？」に寄せる。
  • 選択肢は3つとも一応それっぽくする。ただし意地悪なひっかけにはしない。
  • 正解後に「なるほど」と言える理由がある。
  • 「知らないと無理」な固有名詞・年号・専門知識に依存させない。
  • 間違いを責めず、「そう思いやすいけど、ここを見ると…」の形にする。

表現・非評価ルール（既存 AGENTS.md 準拠）

  • 問題・解説は学校／成績／恋愛／暴力／ホラーを避ける。
  • 絵文字は使わず Material Symbols を使う（データ側は問題文・解説のトーンの話）。
  • 解説は先生っぽくしない。「覚えておこう」「正しくは」ではなく「ここを見るとわかりやすい」「そう考えると自然」。
  • スコアは出すが、体験は「面白かった問題」に寄せる（room-K の非評価思想）。

この順番の理由

  • Phase 1（基本4パック）：いちばん使われる基本パックから。ここが20問化すれば「10問チャレンジ」がまず主力パックで成立する。
  • Phase 2（ことば系3パック）：ことばであそぼ連携で使う3本。ことばであそぼ総集編 は混合パックで重複が起きやすいため優先度を下げ、当面は増強しない。
  • Phase 3（難読7本）：個別に増やすか、難読まぜこぜ（母数十分）前提で据え置くかを運用で判断。急がない。
  • Phase 4（新テーマ）：主要パック増強後、「もっと手ごたえがほしい」層への拡張。例：身近ななぜ？クイズ／ことばの使い分けクイズ／くらしの推理クイズ。新規は10問ずつ2回に分けて品質を担保。

Phase 1・2 で7パックが20問化すると、d3 総在庫は現状 +42問（各パック d3:+6）。10問チャレンジが主要パックで成立し、体感の「少ない・簡単すぎる」はほぼ解消する見込み。

2. 制作の進め方（1バッチ＝1パックに10問追加）

  1. 下の実装プロンプトをコピーして Claude Code に貼り付ける。
  2. 実装後、別視点で監査：(a) 既存問題と題材・正解・解説が重ならないか、(b) 事実系（雑学・漢字由来など）にもっともらしい誤情報が入っていないか。
  3. bash scripts/lint.sh を通す。
  4. apps/updates.json に quiz の更新を反映（同日の複数パックは1エントリにまとめる。プロンプト内に指示あり）。
  5. メンター実機で数問出してみて、d3 が「相談すると考えが進む」になっているか確認。
  6. コミット。次のバッチへ。

3. Phase 1（基本4パック）

1. 雑学3択クイズ を20問化

Phase 1 id: zatsugaku-3choice 　+10問（d1:+1 / d2:+3 / d3:+6）

身のまわりの生き物・自然・食べもの中心の3択雑学。d3 は「なぜそうなる？」を選択肢で考えられる問いにする。

2. 連続2択クイズ を20問化

Phase 1 id: series-2choice 　+10問（d1:+1 / d2:+3 / d3:+6）

「どっちがホント？」の2択形式（choices は2つ）。d3 は「どちらもありそう」に見せて、理由で片方に絞れる問いにする。

3. ことばクイズ を20問化

Phase 1 id: kotoba-quiz 　+10問（d1:+1 / d2:+3 / d3:+6）

ことばの意味・由来・使い分けの3択。d3 は「文脈でどれが自然か」を考えられる問いにする。

4. 漢字クイズ を20問化

Phase 1 id: kanji-quiz 　+10問（d1:+1 / d2:+3 / d3:+6）

漢字の形・意味・成り立ちの3択。d3 は「成り立ちから意味を推理する」問いにする。読みの難しさで殴らない。

4. Phase 2（ことば系3パック）

Phase 1 の運用で d3 のトーンが固まってから着手。手順は Phase 1 と同一（+10問／d1:+1・d2:+3・d3:+6）。

5. 漢字のひみつ を20問化

Phase 2 id: kanji-himitsu 　+10問（d1:+1 / d2:+3 / d3:+6・id は khm11〜khm20）

成り立ち・部首・音訓・熟語から漢字の面白さを深掘りするパック。d3 は「なぜこの部首？」を推理させる。

6. ことばの文化 を20問化

Phase 2 id: kotoba-bunka 　+10問（d1:+1 / d2:+3 / d3:+6・id は kbn11〜kbn20）

慣用句・ことわざ・故事成語・敬語・方言など。d3 は「この場面ではどの言い回しが自然か」を考えさせる。

7. ことばの雑学王2 を20問化

Phase 2 id: zatsugaku-king-2 　+10問（d1:+1 / d2:+3 / d3:+6・id は zk211〜zk220）

言葉の由来・世界の言葉・日本語のふしぎ。d3 は「由来から意味を推理する」問いにする。

5. Phase 3・4

Phase 3：難読7本は据え置きで確定（2026-07-08・codex 相談）
  • 個別の難読7パックは各10問のままとし、20問化しない。
  • 理由：難読まぜこぜ（nandoku-shuffle）が7本合計70問・d3:28を持ち、まぜこぜ側では10問チャレンジが成立しているため。
  • 難読地名・駅名は実在情報の確認コストが高く、70問追加すると読み・表記・地域バランスの誤り混入リスクが大きい。d3の「理由で考える」思想とも相性がやや悪い（知っているか勝負になりやすい）。
  • 今後、特定地域パックへの強い運用ニーズが出た場合のみ、個別増強を再検討する。
Phase 4：新パック「くらしの推理クイズ」を追加・完了（2026-07-08）
  • id kurashi-suiri／アイコン manage_search／20問（d1:3 / d2:7 / d3:10）を questions.js に追加。app.js の CHALLENGE_PACK_IDS に登録し、TOP の「手ごたえあり」セクションに表示。
  • 方向性は「雑学」ではなく観察ゲーム。日常の場面（かげ・かわき方・風・温度差・光など）を手がかりに、知識ではなく筋道で答えを推理する。既存の理科雑学（雑学3択の追加分）と差別化。
  • 歯止め：犯人当て・うそを見抜く・失敗の原因さがしにはしない。事故・ケガ・叱責につながる場面を避ける。問いは「いちばん考えやすいのは？」、解説は「手がかり→考え方→答え」。
  • 今後さらに増やす場合の候補テーマ：ことばの使い分けクイズ など（配分は同原則 d1:3/d2:7/d3:10）。
Phase 5（方針転換）：難読7本を20問化・完了（2026-07-09）
  • 現場から「個別パック（例：関西編だけ）を繰り返し遊ぶと10問では答えを覚えてしまう」という声があり、Phase 3の据え置き判断を見直した。
  • codex 相談の結論：「難読まぜこぜ」ではなく個別パック反復が課題のため20問化が妥当。7パック一括で d1:+1/d2:+3/d3:+6（計+70問）を実施し、候補作成と検証を分けて事実確認の質を担保する。
  • 実施方法：パックごとに調査エージェントを分担し、自治体公式サイト・鉄道会社公式サイト・総務省/デジタル庁の公的地名データなど最低2つの一次情報源で読みを確認（Wikipediaは候補探しのみ）。読みが割れる候補は不採用。
  • 7パック横断で表記・読みの重複が2件発生（分倍河原の重複、「ごうど」読みの重複）し、該当パックの担当エージェントに再調査させて解消。
  • Codex監査で、断定しすぎる由来表現・子ども向けに生々しい表現（動物を投げ入れる等）・d3として弱い解説を12件指摘し、すべて修正のうえ実装。
  • 結果：23パック・460問（難読7パックは各20問、合計140問）。
Phase 6：新パック「難読地名・駅名クイズ 関東・甲信越編」を追加・完了（2026-07-09）
  • Phase 5後、現場から「関東地方などがない」という指摘。地域別パック（北海道・東北／関西／九州・沖縄／中国・四国／東海・北陸）だけが揃っていて、関東・甲信越（東京・神奈川・埼玉・千葉・茨城・栃木・群馬・山梨・長野・新潟）だけ独立パックが無かった。
  • codex相談の結論：既存の nandoku-chimei / nandoku-station に関東の地名が混ざっていたが再編せず、新規20問（d1:3/d2:7/d3:10）の独立パックを新設する方が既存パックの性格を崩さず安全。
  • id nandoku-kanto／アイコン location_city。関東7都県14問＋甲信越3県6問を担当エージェントで分担調査。事実確認はPhase 5と同方針に加え、由来の説明文も最低2ソース確認する基準を追加。
  • Codex監査で、選択肢が不自然（俗語っぽい誤答）・死者関連の表現・d3として弱い解説などを4件指摘し修正（そのうち1件は「五霞町が茨城県で唯一利根川の南側にあり、1987年まで本土と陸続きでなかった」という地理トリビアに差し替えて解決）。
  • 既存 nandoku-chimei / nandoku-station は無変更。結果：24パック・480問（難読パックは8本・合計160問）。

6. リスクと歯止め（codex 相談）

  • 難易度インフレ：20問中 d3:10 を上限感とする。増やしすぎると「ずっと考えさせられる疲れ」が出る。
  • 解説が説教臭くなる：「覚えておこう」「正しくは」を使わない。「ここを見るとわかりやすい」「そう考えると自然」。
  • 既存問題との重複：似た題材でも問いの角度・正解・解説が重なるなら避ける。各バッチで既存 id と突き合わせ監査する。
  • 事実系の誤情報：雑学・漢字由来・語源は、もっともらしい誤りが混ざりやすい。制作後に別視点で事実監査を入れる。
  • マニアック化：「知らないと無理」は d3 ではない。選択肢を見て理由を話せるかを毎問チェックする。
