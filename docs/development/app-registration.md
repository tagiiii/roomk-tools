# app-registration — room-K 実装資料

共通の権限・品質基準は [AGENTS.md](../../AGENTS.md)。本文のコードパスはリポジトリルート基準。該当機能を実装・変更・監査するときだけ読む。アプリ固有の明文化された例外を尊重する。

### アプリのファイル構成パターン

バックエンドの種類によってファイル構成が異なる。

| パターン | 使用DB | ファイル構成 | 採用アプリ |
|---------|--------|------------|----------|
| **単一ファイル** | Realtime Database | `index.html` のみ（CSS・JS インライン、共有 `rtdb-utils.js` は参照可） | do-mannaka, word-wolf, name-change |
| **分割ファイル** | Firestore | `index.html` + `app.js`（+ 必要なら `style.css`） | 現在該当なし |
| **オフライン** | なし | `index.html` + `app.js` | talk-card |

### 新しいアプリを追加するとき

1. `apps/{app-name}/` フォルダを作成
2. 上表のパターンを参考にファイルを作成
3. `apps/index.html` のツール一覧にカードを追記（下記「利用シーンタグ」の `data-scenes`、公開日の `data-added`、種類の `data-genre` を必ず付ける）
4. アプリ固有の仕様を `apps/{app-name}/AGENTS.md` に記載
5. `apps/updates.json` の先頭に更新情報を追記（下記「更新情報」参照）
6. 共通の「あそびかた／つかいかた」モーダル（`apps/shared/js/howto.js`、[shared-modules.md](shared-modules.md)「howto.js」参照）を組み込む
7. `apps/guide/` の早見表（スタッフ向け「ゲームえらび早見表」）に1行追加
8. `scripts/content-audit.mjs` の台帳に登録（コンテンツがなくても必須。下記「重複監査の台帳」参照）

### アプリ名のつけかた

- 表示名・フォルダ名（URL）とも、実在のゲーム・番組・商品の名称やそのもじりは使わず、オリジナルの名前をつける（権利面の配慮。既存名の使用可否を個別に判断しない）
- **例外: 伝統ゲーム・トランプの一般名称は使ってよい**（例: 人狼、ブラックジャック）。誰の商品名でもない遊びの一般名称が対象で、市販ボードゲーム・番組・漫画等の固有名は引き続き不可（2026-08-31 追記）
- 遊びの動きがそのまま伝わる、ひらがな・カタカナ中心の短い名前にする（例: ピタハメ、おしつけずかん、かぶらずヒント）
- 着想元の市販ゲーム・番組がある場合は、名前ではなく次の段階のどれかで記述的に紹介する。**既定は段階1**。段階2・3はオーナーが決め、どれにしたかをアプリの AGENTS.md に書く。どの段階でも、アプリ名・画面・検索のキーワード（`data-keywords`）には着想元の名前を入れない。「Web版」「オンライン版」「無料版」等の表現は使わない

  | 段階 | 早見表（`apps/guide/` の「近い遊び」） | `updates.json` の紹介文 | 例 |
  |---|---|---|---|
  | 1（既定） | 『◯◯』から着想 | 『◯◯』から着想 | kakure-kaito・kanpe-housou・nemurase-kichi |
  | 2 | 『◯◯』から着想 | 書かない | charin-baton（テレビ番組。2026-11-04 オーナー） |
  | 3 | 系統ラベルだけ（`gd-origin--genre`。例「落ちものパズル系」） | 書かない | suton-block（2026-11-02 オーナー） |

- 着想元に「寄せる」とオーナーが決めたときも、写すのはルール・数の表など遊びのしくみまで。名前・キャラクター・技や役の呼び名・絵・音・見た目は写さず、独自の名前で呼ぶ（suton-block の対戦の表、nemurase-kichi の役職）

### 利用シーンタグ（ポータルの絞り込み）

ポータルのカードは `data-scenes` 属性で利用シーンを持ち、検索欄の下の「くわしく絞り込む」の中のチップで
絞り込める（指定しているあいだは「くわしく絞り込む」に「Nつ指定中」を出す）。シーンバッジはこの属性から自動描画されるので、カード HTML にバッジを
手書きしない。1つのツールが複数シーンに属してよい（スペース区切り）。
`data-scenes` の有無とキーの妥当性は lint（PORTAL-2）で検証される。
同じく必須の `data-added` は公開日（`YYYY-MM-DD`。`updates.json` の `"new"` と同じ日）、`data-genre` は下の表の種類で、どちらも並び順に使う（lint PORTAL-2 で検証）。

選択中の種類とシーンは URL ハッシュと同期する（例: `…/apps/#scene=bodoge`、`…/apps/#genre=kotoba&scene=bodoge`）。
チャットに貼れば、その種類・シーンで絞り込んだ状態で開ける。

一覧の上の**種類のタブ**（すべて＋下の表の6つ。アイコン・名前・本数）は `data-genre` で絞り込む。
`ranking.json` を読めたときは「すべて」の次に**「人気」タブ**も出す。押すと `order` の上位12本を、その順に順位の数字つきで並べる（回数は出さない。人気のあいだは「並び順」を使えない。URL は `#genre=popular`）。
タブ・検索欄（ツール検索）・シーン・人数・目安時間は組み合わせて使える（すべてに合うカードだけを出す）。
検索対象はカードの名前・説明・メタバッジ・フッター・サムネイルの `alt`・利用シーン名
（`data-slides` のカードは「説明スライド」も）で、
表示中のカードから自動で作る。
ひらがな／カタカナ・全角／半角・大文字／小文字は区別しない。
検索語は URL に入れない。

画面に出ない補足として、カードに次の属性を付けられる（いずれも任意・複数は「、」区切り）。

| 属性 | 中身 | 使われ方 |
|------|------|----------|
| `data-yomi` | 名前の読み（ひらがな）。名前に漢字・英字があるときだけ | 検索・入力中の候補 |
| `data-old-names` | 改名前の表示名 | 検索・入力中の候補（「前の名前: ○○」と添える） |
| `data-keywords` | 説明文に出てこないジャンルのことば（例: 正体隠し、ブラフ） | 検索 |

`data-keywords` の「1対1」は、メンターと子どもの2人で成り立つツールに付ける（作戦会議の内面・対話ツールと、2人から遊べるゲーム）。
検索語は言い換えを同じものとして扱う（`SYNONYMS`。例: 1on1・面談・個別・マンツーマン → 1対1）。

**着想元の市販ゲーム名は入れない**。画面に出さずに他社の名前で自分のツールへ誘導する形になり、
商標の面で避けたい使い方のため（記述的な紹介は早見表で行う。上記「アプリ名のつけかた」）。

チップの下の「人数」「目安時間」でも絞り込める（検索・シーンと AND）。
どちらもカードの人数バッジ（`group` アイコン）・時間バッジ（`schedule` アイコン）の表示から読み取るので、
カードの表記は次のどれかにそろえる（読み取れないカードは、その条件では隠さない）。

| 種類 | 読み取れる表記 | 扱い |
|------|----------------|------|
| 人数 | `人数制限なし`（後ろに注記があってもよい）／`3人〜`／`2〜9人`／`ホスト＋2〜4人`／人数バッジなしで `1対1向け` | ホストは1人に数える。`1対1向け` は1〜2人 |
| 時間 | `5〜15分`／`30分前後`／`15分ほど`／`1ラウンド2〜3分` | いちばん短い時間が「目安時間」以下なら出す |

絞り込みの結果は、パネルのいちばん下の行に「全N件中 M件にしぼりこみ中」と出す（入力したその場で変化が見えるように、カード一覧の上ではなくパネルの中に置く）。
絞り込み中はこの行の色を変え、検索・シーン・人数・時間をまとめて戻す「条件をクリア」を出す。
選択中のチップと指定中の人数・時間は、淡いティールの塗り＋ティールの枠で示す（濃いネイビーの塗りは目にきついという声があったため。ページ上部の帯はネイビーのまま）。

検索欄は入力中にツール名の候補を最大5件出し、選ぶとそのツールを開く。
候補は日本語入力の変換中も読みで出す（一覧の絞り込みは変換の確定後）。
1文字だけのときは名前・読みの前方一致だけを出す。
検索欄が空のときと0件のときは、検索のヒント（`HINT_WORDS`）をチップで出す。
ヒントのことばは、どれを押しても複数のツールが出るものにする。

一覧の見出し（「ツール N件」）の右の「並び順」で、カードの並びを変えられる（絞り込みとは別。「条件をクリア」では戻さない・URL にも入れない）。

| 並び順 | 並べ方 |
|--------|--------|
| 種類順（初期値） | `data-genre` の種類ごとに小見出しを付け（下の表の順）、種類の中は `data-added` の新しい順 |
| 新しい順 | `data-added` の新しい順（小見出しなし） |
| よく開かれた順 | `ranking.json` の `order` の順（小見出しなし）。`ranking.json` を読めないときは選択肢に出さない |

同じ日・`order` にないカードは、`apps/index.html` に書いた順で後ろに並ぶ（HTML の並びは画面の並びに関係しないので、カードはどこに足してもよい）。
絞り込みで1件もなくなった種類は、小見出しごと隠す。種類名は検索の対象にも入る。

| `data-genre` | 種類（小見出し） | 入れるもの |
|---|---|---|
| `kotoba` | ことばのゲーム | ことばを考える・言い合う・当てるゲーム |
| `puzzle` | クイズ・パズル | クイズ・パズル・リズムなど、ひとりでも遊べるもの |
| `suiri` | 推理・正体かくし | 正体をかくした人を話し合いで見つけるゲーム |
| `atekko` | 当てっこ・協力ゲーム | 絵・数字・気持ちなどを当て合う、協力するゲーム |
| `board` | カード・ボードゲーム | トランプ・カードゲーム・盤のゲーム |
| `talk` | 話す・自分を知る | トーク・内省・キャリアのツール（「好き」を見せ合うゲームを含む） |

種類分けは 2026-11-02 にオーナーが決めた。新しいツールの種類も、迷うときはオーナーが決める。
タブ・小見出しのアイコンは `apps/index.html` の `PORTAL_GENRES`、色は同じファイルの CSS `[data-genre="…"]`（2026-11-05 から）。種類を足すときは、この表・`PORTAL_GENRES`・CSS・lint PORTAL-2 をそろえる。

```html
<a class="app-card" href="{app-name}/" data-added="2026-07-06" data-genre="talk" data-scenes="hiroba sakusen" data-yomi="…" data-keywords="…、…">
```

| キー | シーン |
|------|--------|
| `kotoba` | コトバであそぼ！（国語ワークショップ） |
| `bodoge` | ボドゲクラブ |
| `hiroba` | ひろば（フリータイム・常設） |
| `circle` | サークルタイム（チェックイン→ジブンチェック→みんなで遊ぶ→翌日の案内。10人程度） |
| `sakusen` | 作戦会議（週1回30分の1on1。内面ツールと3〜4人の少人数遊びを含む） |

### 更新情報（`apps/updates.json`）

ポータル上部の「更新情報」欄と、アプリカード右上の NEW / 更新 フラグ（直近14日）は
`apps/updates.json` から自動描画される。**新しいアプリの追加時と、既存アプリへの
お題・問題の追加や機能改修時に、配列の先頭へ1エントリ追記する。**

```json
{ "date": "2026-07-06", "app": "minna-ranking", "type": "new", "text": "「みんなでランキング」を追加。……" }
```

| フィールド | 内容 |
|-----------|------|
| `date` | `YYYY-MM-DD` 形式 |
| `app` | `apps/{app}/` のフォルダ名。複数アプリ横断の更新は `null` |
| `type` | 新アプリは `"new"`、既存アプリの拡充・改修は `"update"` |
| `text` | 1行の説明。**スタッフ向けなので漢字表記でよい**（子ども向け文言ルールの対象外） |

軽微な bugfix やリファクタリングは追記不要。スタッフに知らせたい変化（新アプリ・お題追加・見た目や遊び方が変わる改修）だけを書く。

### よく開かれたツール（`apps/ranking.json`）

ポータルの「ツール一覧」の見出しのすぐ下（種類のタブの上）に「この1週間よく開かれたツール」を上位5つまで、カードと同じ図柄（種類の色とアイコン）の小さなカードで出す（スマホでは横にスワイプ）。`apps/ranking.json` から描画し、ファイルがない・載せるアプリがないときは欄ごと出さない。

- 週1回、`/ranking-update`（`node scripts/ranking-build.mjs`）で作り直してコミットする。利用回数（`stats/`）は月ごとしかないため、実行のたびに各アプリの `open` の累計を `scripts/ranking-snapshots.json` に残し、6日以上前のうち最も新しいスナップショットとの差で並べる。比べるスナップショットがないときは先月の回数で並べ、見出しは「◯月によく開かれたツール」になる
- **回数は `ranking.json` にも画面にも出さない**（順位だけ）。ポータルは画面共有で子どもが見ることもあるため（stats.js「子ども向け画面に計測値を表示しない」）
- 対象はポータルにカードがあるアプリだけ。1週間に3回未満のアプリは載せず、載せられるのが3つ未満なら欄を出さない
- `ranking.json` の `apps` は欄に出す上位、`order` はポータルの全アプリの順番（ツール一覧の並び順「よく開かれた順」に使う。同じ回数なら累計の多い順）
- 数え方の癖: `open` は端末・読み込みごとの数なので、ルーム型は参加者の人数ぶん増える。公開直後の新作は、本番での動作確認の分も入る（区別できない）
- アプリを改名したときは、旧名の回数は新名に引き継がれない（その週は新名の差が大きく出る）

### 重複監査の台帳（`scripts/content-audit.mjs`）

`apps/` 直下のディレクトリは、アプリかどうか・コンテンツの有無にかかわらず、次の台帳のどれか1つに登録する。新規アプリのほか、改名で残すリダイレクトスタブや、アプリでないページ・フォルダを足すときも同じ。削除・改名したときも台帳を合わせる。

| 台帳 | 登録するもの |
|------|------------|
| `COVERED_APPS` | お題・問題・カードなど、数えられるテキストコンテンツを持つアプリ。`collectEntries()` に抽出も追加する |
| `NO_CONTENT_APPS` | テキストのお題集を持たないアプリ（内省ツール、カードゲーム・パズルの部品だけのアプリなど） |
| `NON_APP_DIRS` | アプリではないディレクトリ（`shared`、旧URLのリダイレクトスタブ、`guide`、`stats-view`、`assets` など） |

完了条件は、`node scripts/content-audit.mjs` の stderr に `[coverage]` 警告が出ないこと。警告があっても終了コードは0なので、標準出力の JSON を捨てて stderr だけを見る。

```bash
node scripts/content-audit.mjs > /dev/null   # 何も表示されなければ合格
```
