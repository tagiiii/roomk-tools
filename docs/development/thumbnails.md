Firebase を止めるときは SDK の読み込みと認証・データ用のドメインだけを遮断する。`googleapis.com` 全体を遮断すると Google Fonts も止まり、アイコンが文字のまま写る。

## 表示と更新

- 一覧では16:10の領域に `object-fit: contain` で表示する。盤面・文字・選択肢を途中で切らず、ゲームの特徴を大きく見せる。
- 開始画面より、遊んでいる場面や操作中のカードを優先する。縦長の一覧は必要に応じて先頭数枚に絞る。
- 画像の `alt` は写っているものを説明し、`width` / `height` はPNGの実寸に合わせる。
- 最初の3枚は通常読み込み、それ以降は遅延読み込み。読み込みに失敗した画像は隠し、背景の既存アイコンを見せる。
- 画像は固定の画面例。参加者の実際の名前・回答・セッションのスクリーンショットは使わない。
- 各ツールの画面構成を変えたときは、対応する画像の更新要否も確認する。

## 撮影方法

リポジトリルートで `python3 -m http.server 8080` を起動し、`http://localhost:8080/apps/{app}/` をブラウザで開く。
オフラインツールは通常のUI操作で進める。ピタハメは「ひとりで練習」を使用する。

複数人ゲームは撮影ブラウザ内だけで架空のルーム・手札・回答を渡し、アプリの既存の描画関数で表示した。
Firebase SDKを撮影用の無通信スタブへ差し替え、データ・認証のリクエストを遮断した。本番のルームは作成していない。
ことば探偵は撮影時のレスポンス上だけでサービスを無通信化し、既存の `renderCards` と単語セットを使用した。
これらの撮影用処理は公開ファイルに含めていない。

塗り絵カレンダー・キャパグラフの入力も架空の画面例。実際の回答・成長評価の保存・採点・比較・推薦の機能は追加していない。
ゲームの名前や回答に使用した「そら」「みどり」「あお」なども撮影用の架空データ。

撮影時はフォントとアニメーションの完了を待ち、カード・盤面の要素の範囲をスクリーンショットにする。
固定のヘルプボタンが写り込む場合は撮影時だけ隠す。画面例に使うお題・カード語は既存データを使用し、本体の内容を変更しない。
