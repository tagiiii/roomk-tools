# いろつなぎ 仕様書

## 目的・使用シーン

上から2つ1組で落ちてくる玉を回して置き、同じ色を縦か横に4つ以上つなげて消す落ちものパズル。

- **core value**: 手を動かすだけで遊べる。消えたあとに玉が落ちてまたつながる「れんさ」で、置き方を考える楽しさがある。ルームではみんな同じ順番で玉が出るので、運ではなく置き方の差で点をくらべられる。盤がいっぱいになっても、からにして続ける設定があるので途中で抜ける子が出ない
- 対象: 小学校中学年〜中学生。ひろば・ボドゲクラブ（`data-scenes="hiroba bodoge"`）
- ルームはホスト＋ゲスト8人まで。ひとりでも遊べる（通信しない）
- 1ラウンド2〜5分

> 経緯: 2026-11-13 フィードバックボードに「特定の市販の落ちものパズル（同じ色を4つつなげて消すもの）を入れてほしい」という要望が届いた。特定のゲームの再現はしない（名前・キャラクター・見た目・音・点や送る数の表を写さない）ため、オーナーの選択で同日 `drafts/iro-tsunagi/` に独自の名前と見た目で試作 → 同日オーナーが「すとんブロックに届いた要望で、同じように来そうなものを先に直して本体に」と指示し、下の「先に入れたもの」を足して本体化・公開（PR #223）→ 同日オーナーの依頼で、ルーム・対戦・音楽・ツール一覧のイラストを足した。
> 着想元のゲーム名は、画面・検索のキーワード・早見表・更新情報のどこにも書かない。早見表では系統ラベル「落ちものパズル系」で紹介する（app-registration.md「アプリ名のつけかた」の段階3。すとんブロックにならった。段階を変えるならオーナーが決める）。
> 玉に目や口は付けない（着想元のキャラクターに似るため）。ツール一覧のイラストを作ったとき、2枚目は玉に顔が付いたので使わなかった。

### 先に入れたもの（すとんブロックに届いた要望から）

すとんブロック（同じ落ちものパズル）に届いた要望28件のうち、このツールにも同じことが言われそうなものを、本体化のときに先に入れた（2026-11-13）。

| すとんブロックに届いた要望 | いろつなぎで入れたこと |
|---|---|

| 横の押しっぱなしで速くなるまでが遅い | 左右はOSのくり返しにたよらず、はじめに1マス→0.13秒待って→0.03秒ごとに1マス（キーも画面のボタンも同じ） |
| 下の押しっぱなしを同じ速さに・加速後より遅く | 下は押したときに1マス、そのあと0.08秒ごとに1マスの同じ速さ（途中で速くしない） |
| W・A・S・D でも動かしたい | A・D で左右、S で下、W で右に回す（大文字でも） |
| 入らないはずの回転が入る | 1列のすき間で縦のまま回せないときは、1回目は回らず、0.35秒以内にもう一度回すと上下が入れかわる（`engine.js` の `rotate(g, dir, flip)`） |
| 送ったときなどの一言が盤にかぶって邪魔 | 「◯れんさ！」「全部消えた！」「◯◯に◯こおくったよ」は盤にかぶせず、盤の左の外（スマホは盤の上の行）に出す |
| 7種類で1周がなくなった？（出かたの仕組みを知りたい） | 色の袋（どの色も4つずつ入れて混ぜ、2つずつ出す・からになったら入れなおす）。あそびかたの「玉の出かた」に書いた |
| 盤を空にした回数・全部消した回数を記録 | 結果に「全部消した ◯回」「からにした ◯回」 |
| やられたとき、なぜかわかりづらい | 盤がいっぱい・ここまでのとき、ふさがった「玉が出る所」を赤くぬる |
| わかりやすいサウンドがほしい・音楽がほしい | 効果音・音楽（どちらもはじめは切・その端末だけ） |
| ハードドロップ・ライン消しのアニメーション | 一気に落とした列に残像、消えると玉がふくらんで消え粒が飛ぶ。動きを減らす設定では、消える玉に白い縁を付けるだけ |
| 対戦がほしい・盤がいっぱいになったら終わりか続けるか選びたい | ルームの「対戦」。「その人はここまで」「からにしてつづける」をホストが選ぶ |

入れなかったもの: 送る相手を選ぶ・ねらってきた人みんなに送る・ねらわれた人数で増やす（すとんブロックであとから足したもの。要望が来てから考える）。

## 技術スタック

- Realtime Database（`irotsunagi_rooms`。`database.rules.json` に足した）。ひとりであそぶは通信しない。Firebase の SDK を読めない端末でも、ひとりであそぶは動く（ルームは「つながらなかった」と出す）
- ファイル構成: `index.html` + `engine.js`（ルールだけ。画面に触らない）+ `app.js`（画面・操作・ルーム）+ `style.css`。4つはセットで変わるので、変えたら `?v=` をそろえて上げる
- 盤と玉は canvas に描く
- 効果音 `sfx/*.mp3`（すとんブロックと同じ音を写した7つ）・音楽 `bgm/play.mp3`（ElevenLabs で作った歌なしの78秒。作り方は `scripts/iro-tsunagi/bgm.py`）。どちらも「入」にした端末だけが読む
- CSS 接頭辞: `.it-`
- テスト: `tests/iro-tsunagi/`（ルールのテスト・ひとりの E2E・エミュレーターのルームの E2E。README.md）。URL に `?seed=` を付けると、ひとりのときの玉の順番が決まり、`?test=1` のときだけ `window.__iro` から状態を読める（画面からは使わない）

## ルール

| 項目 | 内容 |
|---|---|
| 盤 | 横6・たて12。その上に見えない段が1段ある（y = −1。あそぶ画面では半分だけ淡い帯で見える） |
| 出る所 | 軸の玉が左から3列目のいちばん上（x = 2, y = 0）、もう1つがその上の見えない段。ここ（x = 2, y = 0）がふさがっていると盤がいっぱい |
| 色 | 3〜5色（はじめは4色）。色ごとに中の形を変える（1 赤・丸／2 青・三角／3 緑・四角／4 黄・星／5 紫・ひし形）。じゃまの玉（9）は灰色で、白い点が3つ |
| 出かた | 色の袋（`PER_COLOR` = 4 つずつ）を混ぜて2つずつ出す。はじめの1袋（6組）は3色だけ。ルームでは、回の種（`round.seed`）でみんな同じ順番 |
| 回す | 右回り・左回り。入らないときは、反対へ1つずらす → 1つ上げる、の順にためす。1列のすき間は上の「2回押し」 |
| 置く | 着地して 0.45 秒で置かれる（着地したまま動かす・回すと待ち時間がもどる。10回まで）。一気に落とすとすぐ置く |
| 消える | 置いた2つの玉は、下があいていればそれぞれ落ちる。同じ色が縦か横に4つ以上つながると消える（見えない段の玉は数えない）。落ちてまた消えると、れんさ。じゃまの玉はつながらず、となりの玉が消えるといっしょに消える |
| 点 | 消えた玉の数 × 10 × れんさの数 ×（同時に消えたまとまりが2つ以上ならその数）。独自の数え方（着想元の表は写さない）。じゃまの玉は数えない |
| 盤がいっぱい | 「からにしてつづける」なら、出る所を赤くぬって1.3秒見せてから盤をからにして続く。ひとりの「おしまい」は結果へ、対戦の「ここまで」はその人の回がおわる |
| 時間 | ひとり: なし（はじめ）・2・3・5分。ルーム: 2・3・5分（はじめは3分）。対戦の「ここまで」だけ「なし」も選べる（30分で区切る） |
| 落ちる速さ | ゆっくり 0.9秒・ふつう 0.6秒・はやい 0.35秒に1マス |

### 対戦（じゃまの玉）

- 送る数（独自の数え方。`engine.js` の `chainSend`・`attackOf`）: れんさ1つめは5つ以上で消したぶん（4つなら0）、2れんさ目から 3・6・10・14…（4ずつ増える）に、そのれんさで5つ以上消したぶんを足す。全部消えたら＋6
- 送る相手: あそぶ人の並び（`round.players`）で自分のつぎの、のこっている人（「ここまで」の人はとばす）
- 来るじゃまは、自分が送るぶんで先にへらす（へらしたぶん、送る数も少なくなる）
- のこったじゃまは、つぎに置いて消えなかったとき（れんさ0）に、上から30こまで落ちる（`JAMA_MAX`）。6つごとに1段そろい、あまりはばらばらの列。見えない段より上にはみ出したぶんは入らない
- 順位: 「その人はここまで」= のこった人が上（その中は送ったじゃまの数）、ここまでの人は、あとまでのこった人が上。「からにしてつづける」= 送ったじゃまの数

## 画面構成・フロー

```
はじめの画面（入口の型 .app-entry・ツール一覧と同じ絵）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（あそんでいる回の途中なら、おわるまで待合室で待つ）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 ├── 「ひとりであそぶ」 → 色の数・速さ／くわしい設定（時間・いっぱいになったら・効果音・音楽）（screen-solo） → あそぶ画面
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting）: あそぶ人・効果音と音楽（各自）・設定（ホスト: ホストもあそぶ・あそびかた／たたんだ「くわしい設定」に 盤がいっぱいになったら（対戦）・時間・速さ・色の数／参加者: いまの設定）・「はじめる」（下に固定）
  ↓「はじめる」（3・2・1のカウントダウン）
あそぶ画面（screen-play）: 左に一言、盤、右に つぎ・のこり・点（対戦は送ったじゃま）・最高れんさ・来るじゃま（対戦）・ほかの人の盤（広い画面。せまい画面は盤の下に名前の一覧）
  （ホストが「ホストもあそぶ」を外したとき・みんなにみせる画面は、あそぶ人の盤をならべて見る画面 screen-watch）
  ↓ 時間・早めにおわる・対戦でのこりが1人
結果（screen-result）: 順位。ホストは「もう一回」（→ 待合室）
```

- ルームバー（ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」））は待合室と結果だけに出す。あそんでいる間は盤を大きく出すため出さない（あそぶ画面の右に「早めにおわる」（ホスト）／「退出する」（参加者）／「とめる」「おわる」（ひとり））
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、ひとり「はじめる」、待合室「はじめる」、結果「もう一回」）
- キーボード: ← →（A D）・↓（S）・スペース・↑（W）か X で右回し・Z で左回し・P か Esc でとめる（ひとりのとき）
- 効果音・音楽の入・切は、その端末の localStorage（`irotsunagi:sfx`・`irotsunagi:bgm`）に残す（読めなければ切）。ひとりの設定と待合室のどちらで変えても同じ
- 音楽は、あそんでいる間（カウントダウンのあと・とめていない・画面が表）だけ流す。ルームでは回のはじまりがホストの操作なので、待合室などで何か押したときに音を出さずに1回 play() しておく（Safari 向け。すとんブロックと同じ）。切にすると読んだ曲を手放す

## status 遷移

```
waiting ─はじめる（ホスト）→ play ─時間・早めにおわる・対戦でのこり1人→ result ─もう一回（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
irotsunagi_rooms/{roomCode}/
  ├── status:             'waiting' | 'play' | 'result'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastRoundId:        number
  ├── hostPlays:          boolean（ホストもあそぶ。はじめは true）
  ├── settings:           { mode: 'score'|'battle', full: 'out'|'clear', time: 0|120|180|300, speed: 'slow'|'normal'|'fast', colors: 3|4|5 }
  │                              # time 0（時間なし）は mode 'battle'・full 'out' のときだけ。full は battle のときだけ使う
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── round/                         # 「はじめる」で作り、「もう一回」で消す
  │    ├── id, seed, startedAt（ServerValue.TIMESTAMP）, mode, full, time, speed, colors
  │    ├── players: [名前...]         # はじめた時点のあそぶ人（入った順。ホストは hostPlays のとき）
  │    └── endedAt:                   # 「早めにおわる」の時刻
  ├── roundUids/{name}:   その回の人の匿名ID（その名前は、回の間は同じ人だけが使える）
  ├── boards/{name}:      { round, b: 78文字の盤（見えない段もふくむ。0〜5・9）, score, bestChain, pops, clears, allClears, taken, sent, pending, done, out, outAt }
  │                              # taken は出した組の数（落ちている途中の組はふくめない）。読み込み直しで同じ順番の続きにする
  ├── jama/{name}/{pushId}: { round, n, from }   # 来るじゃま。受けた端末が数えて消す
  └── result:             { id, mode, full, at, rows: [{ name, score, bestChain, sent, clears, allClears, out, outAt }] }
```

- 読み込むときは壊れた値を読み飛ばす（`roundOf`・`settingsOf`）。盤は `unpackBoard` が長さ・文字を確かめる

## transaction 設計

すとんブロックと同じ。ルーム全体への `transaction()`。ホストの操作は `hostUid` を確かめる（`hostTransaction`）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | 名前が空いている（ホストと同じ名前は不可。同じ名前の在室が残っていれば不可）・ゲスト8人未満（その回の人が戻るときは上限を見ない）・その回の人の名前は同じ匿名IDの人だけ → `players/{name}`（`transactRetry`） |
| 設定・ホストもあそぶ | ホスト | `waiting`。続けて変えても取りこぼさないよう二度押しよけのロックを使わない |
| はじめる | ホスト | `waiting`・あそぶ人がいる → `round` を作り、`boards`・`jama`・`result` を消す（種は transaction の外で1回だけ作る） |
| 盤を送る | あそぶ人 | `boards/{自分}` への update（自分だけが書く）。置いて落ち着いたとき・からにしたとき・回がおわったとき |
| じゃまを送る | あそぶ人 | `jama/{相手}` への push を、自分の盤（送った数・来るじゃま）と同じ1回の update で |
| じゃまを受ける | あそぶ人 | 受けとったじゃまを消すのと、`boards/{自分}/pending` を書くのを同じ1回の update で（先に消すと、置く前に読み込み直したとき来るじゃまがなくなる）。書けなかったら数えたぶんをもどす |
| 早めにおわる | ホスト | `play`・回の id が一致・まだ `endedAt` がない → `round.endedAt` |
| 結果を出す | ホスト（時間の1.5秒後。対戦でのこりが1人になってから0.8秒後）・その回の人（どちらも4秒後） | `play`・回の id が一致 → `boards` から集めて `result`、`status: 'result'`、`jama` を消す |
| もう一回 | ホスト | `result` → `waiting`。回の記録を消す |
| 退出 | ゲスト | 自分の在室を消す（その回の盤は残し、結果に出る）。対戦の「ここまで」の回の途中なら、同じ transaction で自分の盤を `out: true` にする |

## 接続・切断・再接続

すとんブロックと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- **読み込み直し**: 同じタブなら sessionStorage（`irotsunagi_session`）から同じルームへ戻る。あそんでいる回の途中なら、`boards/{自分}` から盤・点・出した組の数・送ったじゃま・来るじゃまを戻し、同じ種で `taken` まで進めて同じ順番の続きにする（落ちていた途中の組は、はじめの位置から出なおす）
- 切れた人・退出した人は、ほかの人の画面で「いまはいない」と出る（盤をうすく）
- ホスト切断中、待合室と結果の画面では共通のオーバーレイ。期限はふだん切れてから2分、あそんでいる回は時間で結果が出て2分たつまで、結果は出てから2分たつまでのばす（`expiryAt`）。**あそんでいる間はオーバーレイで盤をかくさず**、あそぶ画面の右に「ホストの通信が切れています」と出す。期限のタイマーは、期限が変わったら仕掛けなおす（`orphanAt`）。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- アドレスの `?room=` は、つないだときに `room` だけを外す（テスト用の `test`・`seed` は残す）

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。結果のあとも自動削除しない（「もう一回」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: players に入らない・切断予約をしない・期限切れのルームも消さない・結果も出さない
- 待合室では「参加のしかた」とルームコードを大きく出す。あそんでいる間は、あそぶ人の盤をならべて出す（ホストが「ホストもあそぶ」を外したときのホストの画面と同じ）。結果は順位
- 秘密の情報はないので、ホストの画面をそのまま共有してもよい

## ひとりであそぶ

- 通信しない。色の数・速さ／くわしい設定（時間・いっぱいになったら・効果音・音楽）を選んで「はじめる」
- 「とめる」（キーボードは P・Esc）で止められる。止めている間は落ちず、時間も進まない。あそびかたを開いたとき・画面が裏に回ったときも止まる
- 読み込み直したら、はじめから（保存しない）

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る。engine.js は DOM に触らない
- **ホスト以外も書く**: あそぶ人が自分の盤（`boards/{自分}`）とじゃま（`jama/{相手}`）を書く・その回の人も結果を出す（ホストのタブが裏に回っても止まらないように）
- **あそんでいる間はホスト切断のオーバーレイを出さない**・**ルームバーを出さない**
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **順位を出す**（点・送ったじゃまの比較。結果画面だけで、記録はしない。すとんブロックにならった）
- **途中から入った人は、その回にはあそべない**（待合室で待ち、つぎの回から）
- **端末なしの参加者はいない**（自分で操作するゲームなので、ホストが代わりに動かす形は作らない。すとんブロックと同じ）

## 入れない機能

- 失敗の音（いっぱい・ここまで・からにしたときは鳴らさない）。じゃまが来た・送った音もなし（すとんブロックの音のファイルに合うものがないため。要望が来たら考える）
- 速さが時間とともに上がる・れんさのお手本や手順の教え込み
- 成績・最高記録の保存、ランキングの記録

## 既知の制約

- 対戦の「ここまで」で、通信が切れたまま戻らない人は「ここまで」にならない（戻ってくるかもしれないため）。決着がつかないときは、ホストの「早めにおわる」で結果にする。時間「なし」でも30分で結果になる
- ほかの人の画面の盤は「置いて落ち着いた時点」のもの（落ちている途中の組は見えない）
- じゃまの玉の落ちる列は、受けた端末が決める（`Math.random`）
- 時間の判定は各端末の `RoomkRTDB.now()` なので、端末によって0.数秒ずれることがある。最後の盤が届くのを待ってから結果を出す
- 同じブラウザの「タブを複製」でできたタブは再接続の記録も写るので、同じ名前で2つの画面がつながる（ほかのルーム型ゲームと共通）

- 対戦の「ここまで」は、早くここまでになった子が待つ時間が長くなる。人数が多いときや、まだ慣れていない子がいるときは「からにしてつづける」で
