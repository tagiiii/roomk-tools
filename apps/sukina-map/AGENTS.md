# すきなことマップ — アプリ固有仕様

## 目的

- room-K の1対1オンライン面談で、メンターが画面共有しながら操作するオフラインツール（子どもの発言をメンターが入力する）。
- 好き・気になるものをカードに書き出して「じぶん」のまわりに置き、回をまたいで興味の地形図を育てる。興味関心を広げる対話の土台にする。
- 所要時間は1回10〜15分。初回はまっさら、2回目以降は前回の JSON を読み込んで続きから。
- マップは眺めて話すための材料。診断・タイプ分け・おすすめ表示はしない。

## 技術

- `index.html` + `app.js` + `style.css` の talk-card 型オフライン構成。Firebase 不使用。
- 永続化 API（localStorage / sessionStorage / IndexedDB / Cookie）は一切呼ばない。
- 記録は JSON ファイルのダウンロード／アップロードのみ。エクスポートは Blob + `<a download>`、インポートは `<input type="file">` + FileReader。
- 共有 `../shared/css/design-system.css` と Material Symbols Rounded を使う。絵文字は禁止。
- CSS は `sm-` 接頭辞 + BEM（`sk-` は sakusen-kaigi が使用済みのため）。`.screen` / `.active` と `screen-xxx` 命名を使う。
- 状態は `const state = { record, dirty, currentScreen, draft }` にまとめる。
- ユーザー由来文字列の DOM 挿入は必ず `esc()` を通す。
- dirty フラグと `beforeunload` を使い、ダウンロード成功で dirty をクリアする。record を変更する操作（カードの追加・編集・削除）だけが dirty を立てる。

## 画面フロー

```text
screen-start
  → screen-map（はじめてマップをつくる）
screen-start
  → screen-load-confirm → screen-map（前回のファイルをひらく）

screen-map
  → カード追加・編集はマップ画面内のインラインエディタで行う
  → screen-save →（ダウンロード後）screen-map / screen-start
```

## マップの設計（近さレーン方式）

- ドラッグ配置ではなく「近さレーン方式」を採用。上端の「じぶん」ノードの下に、近さ4段階のレーンを縦に並べる。上のレーンほど「じぶん」に近い。
- 近さは数値ではなく4段階の言葉。UI・データとも `closeness: 1-4` に対応する。
  - ① だいすき・よくやる
  - ② すき
  - ③ ちょっと気になる
  - ④ 見るのはあり・まえはすきだった
- レーンの視覚差は背景色と左ボーダーの濃さ（近いほど濃い）のみ。順位・比較の演出はしない。
- カード（付箋風チップ）をクリックするとエディタが開き、なまえ・ジャンル・近さの変更と削除ができる。削除は確認ダイアログなしで即時（重い確認は不要という仕様）。
- 近さを下げる移動も同じエディタ操作で行い、否定的な演出を出さない。エディタに「近さは あとから いつでも うごかせるよ」と明記する。
- マップが空のときは「さいきん見たもの・さわったものから さがしてみよう」の導入お題と、弱い関心（③④）から置いてよいことを示すガイドを表示する。

## データ構造

- `record.app = "sukina-map"`、`schemaVersion = 1`。
- `fileMarker` は個人を特定しない色×動物（sakusen-kaigi と同方式・同辞書）。
- `items` は最大100件。`items: [{ id, label, category, closeness, createdAt }]`。
  - `label`: 20文字以内の自由入力。
  - `category`: カテゴリ id（`game / video / music / make / draw / animal / vehicle / sports / food / research / collect / other`）または null（未選択可）。
  - `closeness`: 1〜4 の整数。
  - `createdAt`: ISO 8601 または null。
- 並び替え・ランキング・件数の集計は保持しない。

## インポート検証

- エクスポートのファイル名は `sukina-map_{animal-romaji}-{color-romaji}_YYYY-MM-DD.json`。めじるし辞書にローマ字対応表を内蔵する。
- サイズは 512KB 以下。JSON.parse 成功、`app === "sukina-map"` が必須。
- `schemaVersion > 1` は「このファイルは新しいバージョンでつくられています。アプリを更新してから開いてください」で拒否。
- `schemaVersion < 1` または欠落、app 不一致、parse 失敗、サイズ超過は「このファイルは読み込めませんでした。すきなことマップでほぞんしたファイルか、たしかめてください」で拒否。
- `items` が配列でない、または100件超は「記録の内容が正しくないため読み込めませんでした」で拒否。
- `label` は20文字に切り詰めて受理。切り詰め後に空になるアイテムは除外。
- `closeness` は 1〜4 の整数以外は 3（ちょっと気になる）に正規化。
- `category` は既知 id 以外は null に正規化。
- 日時は parse 不能なら null。表示は「—」。
- 未知フィールドは破棄し、既知フィールドのみで record を再構築する。
- ID は信用せず再採番する。
- 不正ファイルでクラッシュさせず、`screen-start` にエラー表示して復帰する。

## 心理的安全設計

- 「すきなことがない」でも成立する。空マップのガイドで弱い関心（③④）から置けることを最初に示す。
- アイテム数の目標・ノルマ・達成表示を出さない。読み込み確認画面でも件数は表示しない（カードの見本を最大6枚表示するだけ）。
- 100件の上限に達したときだけ追加ボタンを消し、件数を強調しない文言で案内する。
- 近さが下がる操作に否定的な演出を付けない。興味は変わっていいというトーンで統一する。

## アクセシビリティ

- 選択カード・チップ・マップ上のカードは `<button>`。
- 単一選択群（ジャンル・近さ）は `role="radiogroup"` + `aria-checked`。
- 選択状態は枠色 + 背景 + check アイコンで表す。色だけにしない。
- 近さの選択肢は `①②③④` の丸数字で番号付けし、`aria-label` に番号を含める。
- `:focus-visible` を明確にし、タップターゲットは最小 44×44px。
- `prefers-reduced-motion` でアニメーションを無効化する。
- toast は `role="status"`、エラーは `aria-live="assertive"`。

## 入れない機能

- localStorage / sessionStorage / IndexedDB / Cookie。
- Firebase、外部 API、外部保存。
- 並び替え・ランキング・件数の集計表示・「増えた数」の強調。
- 評価・比較・数値化・バッジ・連続記録・達成演出。
- 診断・タイプ分け・おすすめ表示。
- ドラッグ&ドロップ配置（近さレーン方式で代替。将来入れる場合もレーン＝closeness の対応は変えない）。
- 仕様にない画面、設定、便利機能。

## コンテンツガイドライン

- カテゴリ・例・文言に、学校・勉強・成績・登校を連想させるもの、恋愛、ダーク系を使わない（「しらべる」は趣味的な探究の意味で使用）。
- 自由記述欄の注意書きとして「なまえ・学校名などの個人じょうほうは書かないでね」を固定文言として使う。
