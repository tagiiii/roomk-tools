# いくつ言える？ 仕様書

## 目的・使用シーン

ホストが出したお題(例:「最近ハマっていることは？」)に対して、参加者が制限時間内に思いついた答えをできるだけ書き出し、終了後にみんなの回答を眺めて「そんな答えもあるんだ」と発想の広がりを共有するゲーム。

**競技ではなく発想を広げる共有ゲーム**として設計する。

| ロール | 説明 |
|--------|------|
| ホスト | メンター(スタッフ)。お題を出し、開始・終了・次のお題を操作 |
| 参加者 | 参加者(小中学生)。自分の回答を入力し、終了後に全員の回答を眺める |

### 相性のよい使い方
- ウォームアップのアイスブレイク
- 発想のトレーニング
- 共感ポイントの発見(「同じ答えがあったね」)

---

## 技術スタック

- Realtime Database + 単一ファイル(`index.html` にインライン)
- ※お題データのみ `themes.js` に分離(保守性のため)
- 共通デザインシステム(`apps/shared/css/design-system.css`)を使用
- Firebase SDK v8 (compat 版、単一ファイルアプリ共通)

### Realtime Database パス

```
ikutsu_rooms/{roomCode}/
  host: string                       // ホストのニックネーム
  hostConnected: boolean
  hostDisconnectedAt: number | null  // orphan TTL 判定用(サーバー時刻)
  status: 'waiting' | 'input' | 'review' | 'finished'
  round: number                      // 現在のラウンド番号(1-indexed)
  theme: string                      // 現在のお題(input/review 中のみ値が入る)
  endAt: number                      // 入力終了時刻(ms, サーバー時刻同期用)
  durationSec: number                // 制限時間(秒)。ホストが設定
  players/{nick}/
    isHost: boolean
    joinedAt: number
    answers: string[]                // 現ラウンドの回答配列
  history/{round}/
    theme: string
    answers: { [nick]: string[] }    // review 固定用スナップショット
```

**なぜスナップショットを作る?**: 入力中は `players/{nick}/answers` が可変。`review` 移行時にホストが `history/{round}` へコピーを書き込み、以降の表示はここを参照することで確定値として扱う(最終振り返りでも使う)。

## 画面構成・status 遷移

```
screen-top
  ├─(ルーム作成)→ screen-waiting [status: waiting]
  └─(参加)─────→ screen-waiting [status: waiting]

screen-waiting
  └─(ホストがお題+時間を入力して開始)→ screen-input [status: input]

screen-input
  └─(タイマー終了 or ホスト強制終了)→ screen-review [status: review]

screen-review
  ├─(ホスト: 次のお題)→ screen-waiting [status: waiting]
  └─(ホスト: 終了)───→ screen-finished [status: finished]

screen-finished
  └─(退出)→ screen-top
```

### screen-top
- アプリタイトル + サブ説明
- 「ルームを作る」/「ルームに参加」切替
- ニックネーム入力(最大8文字、同ルーム内重複NG、空NG)
- 参加時は6桁ルームコード入力

### screen-waiting
- ルームコード表示(コピーボタン付き)
- 参加者一覧(ホストバッジ・あなたバッジ)
- **ホスト専用 UI**
  - お題の入力(自由記入) / またはお題リストから「ランダムに1つ」ボタン
  - 制限時間の選択(60秒 / 90秒)
  - 「このお題で始める」ボタン
- ゲスト側はお題非表示(開始時にドン、で出す演出)

### screen-input
- お題を大きく表示
- 残り時間(カウントダウン。`endAt` を基準に各端末で計算)
- 入力欄(1行 text input) + 「追加」ボタン(Enter でも追加)
- 自分の回答リスト(入力順に表示。削除可)
- 自分の個数のみ表示(「○個」)
- **煽り表現は出さない**(「あと◯秒!」「残り少ない!」等はNG)
- ホスト専用: 「時間前に終了する」ボタン

### screen-review
- お題表示
- 全員の回答をタイル表示
  - 1タイル = 1回答(デフォルトは匿名)
  - 同じ回答同士を自然にハイライト(かぶりを「発見」として見せる)
- 自分の個数のみ表示(他人の件数は出さない)
- ホスト専用:
  - 「次のお題」ボタン → `screen-waiting` へ戻る(次ラウンド)
  - 「終了する」ボタン → `screen-finished`
  - **匿名/ニックネーム切替(ホスト画面のローカル state のみ。Firebase には書き込まない)**
    - 画面共有前提のため、ホスト画面の表示が変われば全員見える。全員同期させる必要はない。

### screen-finished
- 全ラウンドの振り返り(`history` を順に表示)
- 「退出する」ボタン

## 共通モジュール・ルールの適用

| 項目 | 適用内容 |
|------|---------|
| ルームコード | 6桁英数字(紛らわしい文字除外)、`RoomkRTDB.generateRoomCode()` をローカル alias で利用 |
| ニックネーム | 最大8文字、重複NG、空NG |
| viewport | `maximum-scale=1` を指定 |
| 状態管理 | `const state = { role, nickname, roomCode, roomRef, currentScreen, timerInterval, ... }` |
| 画面遷移 | `.screen` / `.active` パターン + `showScreen(id)` |
| ホスト識別 | `players/{nick}/isHost` |
| ホスト切断 | `hostConnected`/`hostDisconnectedAt` + `onDisconnect().update(...)` + orphan TTL 2分 + overlay |
| ゲスト切断 | `onDisconnect().remove()` |
| リスナークリーンアップ | 退出時に `roomRef.off()` + `clearInterval` |
| セッション自動削除 | `finished` 遷移から30秒後に `roomRef.remove()` |
| 再接続 | `sessionStorage: ikutsu_session` |
| XSS対策 | `esc()` を使って `innerHTML` へ |
| 最小参加人数 | 制限なし(1人からでも成立) |

### お題作成ガイドライン(room-K コンテンツ方針に準拠)

- **OK**: 好き・楽しい・やってみたい・気になる・集めたくなる などポジティブで開かれた軸
- **NG**: 学校・勉強・出席・恋愛・暴力・ホラー・比較を促す問い
- 正解のない開かれた質問に限定
- 「複数思いつきやすい」のが大前提(名詞の種類を挙げやすいお題を優先)
- 例: 「最近ハマっていること」「つい集めたくなるもの」「雨の日にしたいこと」「好きな音」

## 特有のルール・制約

### 個数の見せ方
- **自分の個数のみ**を表示する。他人の件数・ランキング・最多記録は**一切出さない**
- `review` 画面でも個数の大小をソート基準にしない(ニックネーム順 or 投稿順)
- 0件でもエラー扱いにせず、review へ合流できる

### タイマー同期
- ホストが開始時に `endAt`(サーバー時刻基準)を書き込む
- 各端末は `RoomkRTDB.now()` で補正した `endAt - RoomkRTDB.now()` で残り時間を計算
- Firebase リスナーから同じ `endAt` が流れるたびにカウントダウンを再起動しない(値が変わったときのみ再初期化)
- 0 になった瞬間にゲストは自動で `review` 表示に切り替わる(`status` 変更待ち)
- `status` 更新は**ホストのみ**が行う(ゲストが勝手に進めない)

### 競合回避(transaction)
- ゲスト参加: `status === 'waiting'` でのみ成立(`input`/`review`/`finished` の途中参加は弾く)。期限切れルームはトランザクション側で `null` を返して確実に削除
- ラウンド開始(`startRound`): ルーム全体の `transaction()` で `status`/`theme`/`round`/`endAt`/`players.answers=[]` を一括更新。開始直前の参加者が消えない
- 確定(`moveToReview`): `input → review` も `transaction()` 化。終了直前に書き込まれた回答が `history` から落ちるのを防ぐ

### 回答の扱い
- 空文字・空白のみの回答は追加しない
- 最大文字数: 24文字(長文は弾く)
- 同一ニックネーム内での重複は自動削除せず、そのまま残す(参加者自身が気づいて削除)
- かぶり(他人との同一回答)は**減点なし**。review で同色ハイライトなど発見的に見せる

### 煽らない設計
- 「あと◯秒!」「残り少ない!」「速く!」の類は**出さない**
- タイマーは淡々と減るだけ
- 終了後の評価文言(「すごい!」「頑張った!」)も出さない

### ホスト切断時
- ゲストは `host-off-overlay` を出し、「退出する」ボタンのみ
- 再参加経路は sessionStorage から

### データ削除
- `status === 'finished'` になってから 30秒後に `roomRef.remove()`
- 1ラウンドごとのデータは最終振り返りで使うため、ラウンド途中削除はしない

## デプロイ前チェック

本番(GitHub Pages)反映後に複数端末で以下を順に確認する。NG パターンに該当する挙動が出た場合は報告する。

### 1. 複数端末参加
- **手順**: 端末A(ホスト)でルーム作成 → 端末B・端末C(ゲスト)でコード入力して参加
- **期待**: A の `screen-waiting` 参加者リストに A/B/C の 3 人が並ぶ。各端末の「あなた」タグが自分の行にだけ付く
- **NG**: 参加した人がリストに出ない / 重複表示される / ホストタグが複数人に付く

### 2. 開始直前参加の競合
- **手順**: 端末A が「このお題で始める」を押すのと**ほぼ同時**に端末C が参加
- **期待**: C は `screen-waiting` に入れず「このゲームはすでに始まっています」が出るか、または A の `screen-input` に C が含まれて始まる(どちらかに確定)。残った参加者の `answers` は必ず空リストになっている
- **NG**: C だけ `screen-waiting` のまま孤立する / C の旧回答が残ったまま input に入る / 開始後に C の行だけ消える

### 3. 同時入力
- **手順**: `screen-input` 中に端末A・B・C が別々の回答を同時に追加・削除する
- **期待**: 各端末で「自分の回答リスト」「自分の個数」だけが更新される。他人の回答・個数はどこにも見えない
- **NG**: 他端末の追加が自分のリストに混ざる / 他人の個数が見えるランキング表示が出る / 追加直後にタイマーが一瞬巻き戻る

### 4. 時間切れでの review 移行
- **手順**: 誰も操作せず `endAt` までタイマーを進める
- **期待**: 全端末が自動で `screen-review` に切り替わる。タイル数は `input` 終了時点の全員の回答合計と一致
- **NG**: ゲストが `input` 画面のまま取り残される / `endAt` 直前に書き込んだ回答が review に載らない / review 移行が 2 回発火する

### 5. ホスト強制終了
- **手順**: `screen-input` 中にホストが「時間前に終了する」を押す
- **期待**: 全端末即時に `screen-review`。その瞬間までに書き込まれた回答は全員分タイル表示される
- **NG**: 一部ゲストが input のまま残る / 押下直前に送られた回答が欠落する / ボタン連打で review が 2 回発火する

### 6. かぶり回答ハイライト
- **手順**: 端末A・B で意図的に同じ回答(例: 「ねこ」)を入れて review へ
- **期待**: 「ねこ」タイルが 2 枚とも `.ii-tile--dup`(紫系ハイライト)で表示される。大文字小文字・前後空白のみの差はかぶり扱い
- **NG**: 同じ回答がハイライトされない / 一部のみハイライトされる / 別の回答が誤ってハイライトされる

### 7. ホスト切断と再接続
- **手順**: `screen-input` 中にホスト端末の Wi-Fi を切る → 30秒後に復帰させる
- **期待**: ゲストに `host-off-overlay` が即時表示。復帰するとオーバーレイが消えて元の画面に戻る。2 分(`ORPHAN_TTL_MS`)を超えて切断が続くとルームが自動削除されゲストはトップに戻る
- **NG**: オーバーレイが出ない / 復帰してもオーバーレイが消えない / 2 分経っても自動削除されない

### 8. ゲストの sessionStorage 復帰
- **手順**: ゲスト端末で `screen-input` 中にタブをリロード
- **期待**: 再接続オーバーレイが一瞬表示された後、同じルーム・同じニックネームで現フェーズに復帰する。自分の回答リスト(現ラウンド分)がそのまま表示される
- **NG**: トップ画面に飛ばされる / 別名で参加し直す羽目になる / 自分の回答が消える

### 9. finished 後の自動削除
- **手順**: ホストが review で「終了する」→ `screen-finished` 表示 → 30 秒放置
- **期待**: 30 秒後にホスト端末から `roomRef.remove()` が走り、ゲスト端末はトップに戻る。Firebase Console で `ikutsu_rooms/{code}` が消えている
- **NG**: 30 秒経ってもデータが残る / ホストがタブを閉じていると削除されない(ホスト復帰まで残るのは仕様だが、1 日以上残り続けるなら別途調査)

### 10. トップへ戻る / 退出後の再入室
- **手順**: 各端末で「退出する」→ トップへ戻る → 同じニックネームで再入室
- **期待**: ホストが退出した場合はルームが消え、ゲストの再入室は「ルームが見つかりません」。ゲストのみ退出なら、別ニックネームや新規コードで普通に再入室できる。`sessionStorage` が確実にクリアされ、次の画面遷移に古い情報が残らない
- **NG**: 退出後もリロードで勝手に再接続する / ゲスト退出後にホスト画面の参加者リストに残り続ける / 再入室時に「ニックネーム使用中」エラーが不当に出る
