# サークルタイム — 固有仕様

午前（9:00〜9:30）と午後（14:00〜14:30）のサークルタイムを、ひとつのルームで進める参加型の画面。
画面共有している「みんなにみせる画面」を見ながら、自分の端末のボタン・チャット・声のどれでも答えられる。
2026-11-07 にオーナーの判断を聞いて設計し、同日 drafts で試作した。2026-11-09 にオーナーの依頼で本体化した（下の「本体化（2026-11-09）」）。

## オーナーの判断（2026-11-07）

- 場は MetaLife。子どもは主に PC。進行はスタッフ1人で、画面共有と操作の両方をする
- ジブンチェックの番号（心・体の1〜5）は、いまの口頭と同じく**みんなの画面にも出す**
- 午後のチェックインは「トークテーマカードなどの軽めのお題」。ふりかえりは **5段階と決まった言葉のひとこと、両方**
- 天気・今日は何の日のような日替わりは、できるだけ自動で用意する
- 作る範囲は午前・午後の流れごと。見た目はあそびのたなに合わせる

## 画面と流れ

- 画面の型は11: 表紙（opening）・目次（agenda）・移動の案内（closing）・表示（show）・5段階（scale）・選択肢（choice）・天気（weather）・お題（talk）・ふりかえり（review）・自由タイム（free）・ゲーム（game）
- 午前: 表紙 → 自由タイム → 目次 → 心 → 体 → 全国の天気 → 今日は何の日（準備で3つ入れたときだけ）→ 今日のプログラム → 移動の案内（1コマ目のプログラムと場所）
- 午後: 表紙 → 目次 → チェックイン（お題）→ ふりかえり → みんなでゲーム → 明日のプログラム → 移動の案内（エントランスへ）
- 表紙・目次以外の画面（セクション）には、それぞれ表紙がある（`room.view = 'cover'`）。「次へ」で表紙 → 中身、「前へ」で中身 → 表紙。一覧の名前から移ると表紙から。表紙・目次・移動の案内には表紙をつけない
- 心・体の5段階・ふりかえり・天気の「きみのところは？」・ゲームの票は、押したらすぐ段やカードに名前が出る（`mode: 'open'`。心・体は 2026-11-08 オーナー判断で「伏せる」から変更）。今日は何の日とその場で聞く選択肢は「そろうまで伏せて、せーので見せる」（`mode: 'hide'`）。伏せているあいだは、答えた人の名前と人数だけ出る
- 答え方3通り（ボタン・チャット・声）と「パスもOK」を、答える画面の足元に毎回出す。チャットと声の分はホストが「代わりに入れる」で入れる
- ホストの画面は共有しない。別の窓で `?watch=コード` を開いて共有する。矢印キーで前後、スペースで見せる／しめきる
- 流れは、一覧からどこへでも飛ぶ・飛ばす（目の印）・並べかえ（矢印）・その場で文を直す・その場で2〜6択を足す、ができる。2026-08-06 の作戦会議スライド（進行の器として負けて破棄）への対策

## データ

- `circletime_rooms/{code}`。`steps` は流れの配列（ホストだけが transaction で丸ごと書く）、`cur` はいまの画面の id、`answers/{stepId}/{playerId}`、`hands/{stepId}/{playerId}`、`reveal`・`closed`・`answerShown` は画面ごとの印、`weather` はホストが準備のときに取った13都市
- 在室は `players/{id}/connections/{pushId}`（kotoba-meter と同じ）。端末のない参加者は `players/{id}` に `proxy: true`（在室なし）。24人まで
- **残さない**: ルームは「ルームを閉じる」で消す。日をまたぐ記録・集計・くらべる表示は作らない（内省の回答に保存・採点・比較を足さない方針）。ホストの端末に残すのは名前と「今日は何の日」の出し方と、自由タイムのあそび・前の回のゲームと、「はじめに」を出さない印だけ（`localStorage`）
- 天気は気象庁の公開 JSON（`www.jma.go.jp/bosai/forecast/data/forecast/{府県予報区}.json`。CORS 可）を**ホストの端末だけ**が準備のときに取り、ルームに入れる。参加者とみんなにみせる画面は取りにいかない。出典は画面に「気象庁」と書く
- お題はトークテーマカードの `app.js`、ことばあそびはことばみっけの `app.js` を読んで配列を取り出し、クイズはクイズパックの `questions.js` を読みこむ（**本体化のときに共通のデータファイルへ出す**）。取れなければ少しの予備

## 2026-11-07 夕の追加（オーナーの依頼）

- **プログラムを自動で**: room-K ポータル（`https://katariba.notion.site/room-K-277e1247489c4bbe979b0322df284a73`。カタリバの Notion の公開ページ）の「日中のプログラム（9:00〜14:30）」にある2つのデータベース（曜日ごとの「2026年秋冬学期のプログラム」と、日付ごとの「単発実施プログラム」）を `scripts/circle-time/program.mjs` が読み、`daily/YYYY-MM-DD.program.json` に書く。公開ページの読み取り用の口（`/api/v3/queryCollection`）を使う。ログインも鍵もいらない。接続中の Notion（オーナーのワークスペース）からは読めなかった
  - 曜日は「実施曜日」、時刻は「開催時間」の `HH:MM~HH:MM`、場所は「実施場所」のうち URL と長い注意書きを除いたもの。「サークルタイム」自身は入れない。名前に「第3月曜」などがあれば、その週だけ。絵文字は外す。「対象」の申し込み制は使わない（2026-11-08 オーナー: マイスタは申し込み制ではない。列の値が実際と合わないため、印そのものを出さない）。ページの表紙画像があれば `thumb` に、公開ページの画像の配信口（`katariba.notion.site/image/…`）のアドレスを入れる。画像はリポジトリに写さない
  - 単発は「日付」が同じ日だけ。「この日だけ」の印
  - **ページの作り（データベースや列の名前・id）が変わると読めなくなる**。読めないときは準備の画面に「まだ用意されていません」と出て、手で書ける
  - 同じ道具が `daily/once.json`（単発実施プログラムのうち、きょうから先のもの。日付・時刻・名前・場所・カテゴリー）も書く。読むのは作戦会議（`apps/sakusen-kaigi`）の「お知らせ」（2026-11-12）。`--once` を付けると、これだけ書く
  - 午前は「今日のプログラム」、午後は「明日のプログラム」（次の平日）。画面では時刻ごとに1行にまとめ、場所と印を添える
- **天気に日本地図**: Natural Earth（1:10m の国境。パブリックドメイン）から日本だけを取り出し、天気の図の座標（1168×500）に投影して簡略化した輪郭を `JAPAN` に埋めこんだ（約16KB）。南西諸島は左下の枠に同じ縮尺で入れた。都市のカードは地図にかぶらない場所（`WX_SLOTS`）に置き、点と線でつなぐ。カードの気温は、しるしの右に2段（上が最高・下が最低。「21/10」と横に並べると、しるしに重なって読めなかった。2026-11-10 オーナーの指摘）。「きみのところは？」は地図の左上
- **自由タイムを「なにかしたい子」向けに**: 「おしゃべりのお題」（トークテーマカードの100枚）・「クイズ」（クイズパックの雑学3択・都道府県・くらしの推理から）・「ことばあそび」（ことばみっけの頭文字×テーマ）の3つ。**ホストも参加者も**、あそびを変える・「つぎ」・クイズの「答えを見る」を押せる。続けて押されないよう、変えたあと2.5秒は押せない。話したい・クイズの答えは、あそびが変わるたびにまっさらになる（`answers/free{n}`・`hands/free{n}`）。やらなくてもよいことを画面に書く
- **準備は自動**: 午前・午後は時刻で選ぶ（日本時間で12時より前は午前）。天気・何の日・プログラム・自由タイムのあそびのようすを4行で出し、「はじめる」を押すだけ。直す欄は「中身を確かめる・直す」にたたむ。入力が残るのはニックネーム（端末に覚える）だけ。ゲームの名前とリンクは準備から外し、「みんなでゲーム」の画面でホストが参加用リンクを貼る（名前はツール一覧から引く）

## 2026-11-08 の見直し（オーナーの依頼）

- **表紙と目次**: サークルタイムの表紙（午前／午後・日付・ルームコード）のあとに目次（きょうの流れ。済んだものは薄く）。各セクションに表紙（番号／全体・アイコン・見出し・何をするかの一文）。表紙と目次では上の帯を出さない
- **ジャンプ率**: 画面ごとに伝えることを1つにする。小さな見出し（アイコンとセクション名）の下に、問いを大きく（46px）。上の帯は小さく、日付・ルームコード・「きているひと」・ポータルの案内の箱は外した。ルームコードは表紙と自由タイムだけ。答える画面の足元は「ボタン・声・チャット（数字）、どれでもOK。パスもOK」の1行
- **自由タイムは3択から**: はじめは「なにしてすごす？」で、おしゃべりのお題・クイズ・ことばあそびを番号つきの3枚で出す。だれかが押すとそのあそびに。「えらびなおす」で3択に戻る（`free.mode = null`）
- **みんなでゲームは3択から**: ツール一覧（`apps/index.html`）のカードから、利用シーンに「サークル」があり、種類が当てっこ・推理・ことば・パズルのもの（ことばみっけは自由タイムで使うので除く）を、種類がなるべく重ならないように3つ選ぶ（準備のとき）。サムネイルとひとことつきで出し、参加者は自分の端末で票を入れる（名前つきで、すぐ出る）。ホストが「これにする」で1つに決め、ゲームのルームのリンクを貼る。「候補を入れかえる」で別の3つに。候補にないゲームのリンクを貼ると、それが4つ目の候補になって決まる。候補の選び方はオーナーが「いまの形のまま」を選んだ（定番リストから・毎朝のタスクが選ぶ、の案は見送り）
- **番号**: ①②③の文字をアクセント色で出す。丸い背景の中には入れない（2026-11-08 オーナー「丸の中に丸があるデザインをやめて」。ui.md の丸数字の型とも同じ）
- **心チェックはその場で見せる**: オーナーが4案（名前を押すと1人ずつ・押したらすぐ段に出る・数はすぐ名前はせーの・本人が見せるか選ぶ）から「押したらすぐ段に出る」を選んだ。進行役の操作はいらない。体も同じ

## 今日は何の日の用意

- 毎朝の手順は `.claude/commands/circle-daily.md`（`/circle-daily`）。Wikipedia の日付ページの「記念日・年中行事」から、子ども向けに合う本当の記念日を2〜4つと、作り話を2つ用意して `daily/YYYY-MM-DD.json` に書く。`note` は自分の言葉で40文字まで
- 形と中身は `node tests/circle-time/daily-check.mjs` で確かめる（本当の記念日がその日のページにある・作り話がない・長さ・絵文字なし）。漢字やカタカナの言いかえは手で確かめる
- 準備の画面は、その日のファイルがあれば自動で入れる。「1つだけ本当」（初期値。本当の記念日の位置は日付で変わる）・「3つとも本当」（本当が3つ以上の日だけ。答えを見せるとカードごとに由来）・「別の候補にする」を選べる。最後に選んだ出し方はホストの端末に覚える。ファイルがない日は空のまま（手で入れる。空なら飛ばす）
- 3つとも本当の答えは `answer: 'all'`、カードごとの由来は `notes`
- 平日の朝（6:30。少しずれて6:41ごろ）に手順（プログラム・何の日・ニュース）を回す定期タスク `circle-time-daily`（「【平日の朝】サークルタイムの今日は何の日」）を 2026-11-07 にオーナーの許可で作った。Auto モードで動き、完了の通知はしない。アプリが閉じていると、次に開いたときに動く
- うまくいかなかったときだけ通知する（2026-11-10 オーナー判断。定期タスクの指示に書いてある）。終わる前に、きょうの3つのファイル（何の日・プログラム・ニュース）が main に載ったかを確かめ、push できない・どれかが載っていない・手順に入れなかった、のどれかのときに `PushNotification` で1行知らせる。3つとも載っていれば知らせない。タスクそのものが動かなかった日（Mac が眠っている・アプリが閉じている）は、この通知も出ない
- 2026-11-07・09・10・11 の分は手で作って検査に通した
- 本体化してからは、毎朝のファイルを main に push しないとページに届かない。2026-11-09 オーナー判断で、定期タスクが `apps/circle-time/daily/` のファイルだけをコミットして main に push する（手順は `.claude/commands/circle-daily.md`）

## 2026-11-10 きょうやることを先に決める（オーナーの依頼）

- オーナー: 自由タイム・チェックイン・みんなでゲームは、子どもたちの多数決で決めるより、進行役が先に決めておいたほうが問題が起きにくい。ただ、子どもたちの声でゲームを変えることはある。自由タイムで、その日か前の日の子ども向けニュースを紹介できるとよい
- オーナーが選んだ形: **準備の画面で決める**（はじめたあとに決める案は見送り）。**子どもの希望を聞くしくみはなくして、変えるボタンだけ**（自由タイムの「やりたいものをえらぶ」とゲームのくじ・3つの候補は外した）。**ニュースは毎朝のタスクが自分の言葉で書く**（子ども向けサイトの見出しとリンクを出す案は、話題を選べないので見送り）
- 準備の画面に「きょうやること」の欄。午前は自由タイムのあそび（ニュース・おしゃべりのお題・クイズ・ことばあそび・なし）。前に選んだものを端末に覚え（`freeMode`）、ニュースのない日はおしゃべりのお題。午後はチェックインのお題（トークテーマカードから1つ入り、「別のお題」か手で直す）と、みんなでゲーム（えらべるものを名前の順に並べた選択欄。はじめは前の回と違うものをくじで1つ入れる。前の回のものは `lastGame` として端末に覚える）
- 自由タイムは、決めたあそびの中身から始まる（`free.mode`）。「なし」は「すきなことをして、ゆっくり過ごそう」だけを出す（`free.mode = null`）。進行役は「自由タイムのあそびを変える」で変えられる。参加者が押せるのはクイズの答えだけ
- 自由タイムの会話は MetaLife のチャットでする。2026-11-10 オーナー判断で、自由タイム（ニュース・おしゃべりのお題）の「話したい」「チャットに書いたよ」の印と、「やらなくてもOK」などの文言は外した（午後のチェックインの印はそのまま）
- **ニュース**: 毎朝のタスクが `daily/YYYY-MM-DD.news.json`（`items: [{ title, text, ask?, source, url, on }]`。3本）に書く。紹介は、どこの・だれ／なにが・いつを固有名詞で具体的に書く（2026-11-10 オーナー「どこの動物園など話が抽象的すぎる」「3つくらいあるといい」）。準備の画面は、きょうの分がなければ前の日の分を読み、ルームの `news` に入れる。画面には見出し・紹介・問いかけ・出典（名前と日付）だけを出す。写真（`img: { src, credit, license }`）があれば左に出し、下に「写真（イメージ）: 撮影者・ライセンス・Wikimedia Commons」を添える。2026-11-10 オーナー判断で、写真は記事のもの（報道各社の著作物）ではなく、Wikimedia Commons の自由に使えるもの（CC0・パブリックドメイン・CC BY・CC BY-SA）から毎朝のタスクが探す（`scripts/circle-time/commons-image.mjs`）。ページは `upload/thumb.wikimedia.org` のアドレスだけを受けつけ、検査は Commons の記載（ライセンス・撮影者）と合うかを確かめる。参加者の端末には「くわしく読む」（元の記事）。「つぎのニュース」で次の1本へ。検査は `node tests/circle-time/news-check.mjs`（形・長さ・絵文字・リンク・選ばない話題の言葉のおおまかな網）
- ニュースの「くわしく読む」は、参加者の端末に出すときにも https のリンクだけを出す（ファイルから読むときの検査に加えて。2026-11-10）。2026-11-10 の分のニュースは手で作って検査に通した（定期タスクがニュースを作るのは 11-11 の朝が初めて。失敗しても前の日の分が出る）
- みんなでゲームの画面は、決めたゲーム（`step.game`）をはじめから出す。進行役の「ゲームを変える」で、えらべるものから別のゲームに変える（ルームのコードとリンクはとける）。「○○のルームを作る（タブを開く）」からあとは前と同じ
- 2026-11-08 の「自由タイムは3択から」「みんなでゲームは3択から」は、この変更で置きかえた
