# しるしでヒント 仕様書

## 目的・使用シーン

伝える人が、アイコン（しるし）を1つずつ出してお題を伝え、ほかの人が12個の候補の中から当てる個人戦。
しるしが1つ出るたびに候補を1回だけ選べ、少ないしるしで当てるほど点が高い。当てた人と伝えた人の両方に点が入る。

- **core value**: 言葉を思いつかなくても「選ぶ」だけで参加できる。しるしが増えるたびに、みんなの予想が変わっていく過程と、はずれた候補が消えて答えが絞れていく様子を楽しむ。どのしるしを先に出すかの悩みが、伝える人の面白さ
- 対象: 小学校中学年〜中学生。ボドゲクラブ・サークルタイム（`data-scenes="bodoge circle"`）
- 遊ぶ人 **2人から**（ゲスト8人まで＋端末なしの参加者4人まで。ホストは既定で進行だけ）
- 所要時間 1問2〜3分。みんなが1回ずつ伝えると一巡で、順位が出る

> 経緯: 2026-10-19 オーナーの仕様案（得点なしの協力・答えは声やチャット・「関係するもの」の枠）で drafts に試作 → オーナーが触って「関係するものの使いどころがわからない」「ゲーム性に乏しく盛り上がりに欠ける」 → 同日、オーナー判断で個人戦（候補をタップ・当てた人と伝えた人に点・順位あり・はずれ −1点）へ作り直し、端末なしの子の参加（ホストが代わりに押す）を足して、本体化を承認。試作は `drafts/shirushi-hint/`（README に経緯と判断の記録）。
> 表示名「しるしでヒント」はオーナー決定（2026-10-19。ほかの名前の案も出したうえで、この名前のままにした）。
> 最初の案（「何の仲間？」「関係するもの」の枠）はボードゲーム『コンセプト』に近い形だったが、作り直したあとの遊び（12個の候補から選ぶ・しるしを1つずつ・個人戦の点）は別物になった。名前・見た目・アイコンの絵も使っていない。そのため着想元としては書かず、早見表では系統ラベル（アイコン連想系）で紹介する（2026-10-19、オーナーから「おまかせ」）。

## ルール

| 項目 | 内容 |
|---|---|
| 順番 | 「はじめる」の時点の遊ぶ人を、参加した順に固定（ホストが遊ぶときはホストが最初）。伝える人は順番に1問ずつ |
| お題を選ぶ | 伝える人に、ルームで使っていないお題を先に3つ出す。「ほかの候補」で何度でも引きなおせる（いま出ている3つとは重ならない）。「この番をパスする」で次の人へ |
| 候補 | お題を選ぶと、全員に12個の候補を同じ並びで出す。**お題と同じなかまを6個まで（お題をふくむ）**、残りはほかのなかまから。候補には A〜L の記号 |
| しるし | アイコンを1つ選び「②つ目のしるしを出す」で全員に出る（出す前の見本は伝える人だけ）。1問に6つまで。同じしるしは2回出せない。出したしるしは取り消せない |
| 出せないしるし | アイコンの絵や名前がお題そのものに見える組は、そのお題では出せない（`data.js` の `BLOCKED`。例: 飛行機に「飛ぶ」、時計に「時間」、海に「海」） |
| 当てる | しるしが1つ出るたびに、候補から1回だけ選べる。「このしるしでは選ばない」もできる。何を選んだかは、ほかの人には出さない（選んだかどうかだけ出す） |
| 答え合わせ | まだ当てていない人が全員選んだら、そのしるしの答え合わせ。伝える人が次のしるしを出したときも締まる（待たなくてよい） |
| 点 | ①つ目で当てたら3点、②つ目で2点、③〜⑥つ目で1点（当てた人それぞれ）。伝えた人は、最初に当たったしるしの点を1回だけ |
| はずれ | はずれるたびに1点減る（持ち点はマイナスになってもよい）。選ばなければ減らない。伝える人は減らない。はずれた候補は全員の画面で消える |
| 問の終わり | ゲームの当てる人がみんな当てた・6つ目の答え合わせが済む・伝える人の「答えを見せる」（確認あり）。まだ当てていない人が抜けて、いる人がみんな当てていれば、抜けた人を待たずに終える（退出のとき・ホストの見はり） |
| 次へ | 答えの画面でホストが「次の人へ」。最後の人のあとは「順位を見る」で一巡の順位（点の高い順・同じ点は同じ順位）。「もう一巡」で点は続く |
| おしまい | ホストの「ここでおしまい」（確認あり）。おしまいの画面にも順位。「もう一回あそぶ」で待合室へ（点は消える） |

オーナー決定（2026-10-19）: 個人戦・候補をタップして答える・当てた人と伝えた人の両方に点・順位をつけて並べる・はずれは −1点でマイナス可・「関係するもの」の枠は入れない・端末なしの子はホストが代わりに押す・アイコン68個とお題89個で確定。
「おまかせ」で決めたこと（同日）: 候補をお題と同じなかまでそろえる・1つで当たる組は「出せないしるし」にする（お題もアイコンも消さない）・伝えた人の点は人数で増やさない（人数で点の差が大きく変わるため）。

## 端末なしの参加者（ホストが代わりに押す）

- 待合室でホストが「端末なしの参加者を足す」で名前を足す（はじめる前だけ。4人まで。ほかの人・ホストと同じ名前は不可。「外す」で外せる）。ルームの `proxies/{name}` に置く。在室（`players`）には入れず、切断しない扱い
- 端末なしの参加者が1人でもいると、**ホストは進行だけ**（`hostPlays: false` にして、チェックを押せなくする）。ホストがその子のお題や選んだ候補を知るため
- 「端末なし」の印は、ホストの画面にだけ出す（子どもどうしの画面で区別しない）
- 当てる番: しるしが出ると、ホストの画面に「代わりに押す」欄が出る。子ごとに A〜L と「選ばない」のボタン（消えた候補は押せない）。点と −1点はその子につく
- 伝える番: ホストの画面に「○○さんが伝える番（代わりに選ぶ）」とお題の候補・「○○さんのお題」・しるしを出す道具が出る

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み） → 待合室
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（waiting）: 参加者、ホストは「自分もプレイヤーとして参加する」「端末なしの参加者を足す」「はじめる」
  ↓「はじめる」（遊ぶ人 2人以上）
お題を選ぶ（pick）: 伝える人に3つの候補・「ほかの候補」・「この番をパスする」。ほかの人は待つ
  ↓ お題を選ぶ
しるし（hint）: しるし・候補12個・だれが選んだか。伝える人はアイコンの一覧と「しるしを出す」「答えを見せる」。ホストは「代わりに押す」欄（端末なしの子がいるとき）
  ↓ 全員当てた／6つ目／「答えを見せる」
答え（reveal）: 答え・出したしるし・この問の点。ホストは「次の人へ」（最後の人のあとは「順位を見る」）
  ↓
一巡（lap）: 順位。ホストは「もう一巡」
おしまい（end）: 順位。ホストは「もう一回あそぶ」（→ 待合室）
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）
- ホストは遊んでいる間、画面の下に「この問を終えて次の人へ」（お題を選ぶ・しるしの間。確認あり。ここまでの点は残る）・「ここでおしまい」（確認あり）
- しるしごとの答え合わせのあと、「○○さんが当てた！」「このしるしでは、まだだれも当たらなかったよ」を2.6秒だけ大きく出す（**音は鳴らさない**。答えの画面には重ねない。途中から見た人には出さない）
- ボタン階層: 各画面の塗りつぶしの主ボタンは1つ（待合室「はじめる」、しるし「しるしを出す」、答え「次の人へ」、一巡「もう一巡」、おしまい「もう一回あそぶ」）。お題の候補3つは同格の選択肢（①②③）
- 候補12個は丸数字ではなく A〜L の記号（しるしの番号①〜⑥と見分けるため。声やチャットで「C」と言える）

## status 遷移

```
waiting ─はじめる→ pick ─お題を選ぶ→ hint ─全員当てた／6つ目／答えを見せる→ reveal ─次の人へ→ pick（次の人）
   pick ─パス／この問を終えて→ pick（次の人）       hint ─この問を終えて→ pick（次の人）
   最後の人のあとは → lap ─もう一巡→ pick
pick / hint / reveal / lap ─ここでおしまい（ホスト）→ end ─もう一回あそぶ→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

- `hint → reveal` は、最後に選んだ人・しるしを出した伝える人・「答えを見せる」の伝える人・退出した人・抜けた人を待たずに締めるホストのどれかが行う
- しるしの答え合わせ（`judge`）の「みんな当てた」は、いま抜けている人もふくめた、ゲームの当てる人で見る（再読み込みの一瞬に、伝える人の次のしるしで答えへ進まないように。2026-10-19 レビューの指摘）
- `pick → hint`（お題を選ぶ）・パス・しるしを出すは伝える人（端末なしの子の番はホスト）。そのほかはホストだけ

## Firebase データ構造（Realtime Database）

```
shirushi_rooms/{roomCode}/
  ├── status:             'waiting' | 'pick' | 'hint' | 'reveal' | 'lap' | 'end'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostPlays:          boolean   # 自分もプレイヤーとして参加する（初期値 false。端末なしの参加者がいると false）
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── usedTopics:         [番号...]  # このルームで出したお題（使い切ったら最初から）
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}:     { joinedAt }                # 端末なしの参加者（待合室でホストが足す）
  └── game/                          # 「はじめる」で作り、「もう一回あそぶ」で消す
       ├── id, order: [name...], uids: {name: uid}, joined: {name: joinedAt}, proxy: {name: true}
       ├── scores: {name: 点}, lap, turn（いまの人の順番の位置）, qn（問の通し番号）
       └── q/                        # いまの問
            ├── n, teller, cands: [番号×3]
            ├── topic: 番号, board: [番号×12]          # お題を選んでから
            ├── signs: [アイコンの id...], judged: 答え合わせが済んだしるしの数
            ├── picks: {name: 候補の位置 | -1}         # いまのしるしで選んだもの（-1 は選ばない）
            ├── crossed: [候補の位置...], solved: {name: 何つ目で当てたか}, misses: {name: はずれの数}
            ├── tellerPts: 伝えた人の点
            └── last: { n, hit: [name...], missed: [name...] }   # いちばん新しい答え合わせ
```

- お題は番号で、しるしはアイコンの id で置く（`data.js` のお題の並べ替え・途中の削除・アイコンの id の変更をしない理由）
- 読み込むときは壊れた値を読み飛ばす（`questionOf`）

## transaction 設計

すべてルーム全体への `transaction()`。乱数（候補・並び）は transaction の外で作った種から決める（`seededRandom`）。
問の中の操作は、押した時点の `game.id` と `q.n` を捕まえて、中で一致を確かめる（`questionTransaction`。古い操作で次の問を変えない）。ホストの操作は `hostUid` を確かめる（`hostTransaction`）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | `waiting`・名前が空いている（ホスト・端末なしの子と同じ名前は不可）・ゲスト8人未満 → `players/{name}`。遊んでいる途中は `game.uids` の持ち主だけ入りなおせる（`transactRetry`。自分の在室が残っていれば入りなおし） |
| 設定・端末なしの子を足す／外す | ホスト | `waiting` |
| はじめる | ホスト | `waiting`・遊ぶ人2人以上 → `game` を作り、最初の人の問 |
| お題を選ぶ・ほかの候補・パス | 伝える人（端末なしの子の番はホスト） | `pick`・id/n 一致 |
| しるしを出す | 同上 | `hint`・id/n 一致・6つ未満・同じしるしでない・出せないしるしでない。前のしるしの答え合わせがまだならここで締める |
| 答えを見せる | 同上 | `hint` → 締めてから `reveal` |
| 選ぶ | 本人（端末なしの子はホスト） | `hint`・id/n とそのしるしの番号が一致・選べる状態・まだ選んでいない・消えた候補でない。全員そろえば同じ transaction で答え合わせ |
| 退出 | ゲスト | 自分の在室を消す。残りが全員選んでいれば答え合わせ、残りがみんな当てていれば答えへ（同じ transaction。`judgeIfReady(room, true)`） |
| 抜けた人を待たない答え合わせ | ホスト | ルームが変わるたびに見て、いる人が全員選んでいる・いる人がみんな当てているなら、同じ状況（同じ問・答え合わせの段階・顔ぶれ。`judgeKey`）が4秒続いたら（`JUDGE_GRACE_MS`。再読み込みの一瞬は待つ）答え合わせ・答えへ（`hostJudgeIfReady` → `judgeIfReady(room, true)`）。状況が変わったら待ちなおす |
| 次の人へ・この問を終えて・もう一巡・おしまい・もう一回あそぶ | ホスト | それぞれの status・id/n 一致 |

## 接続・切断・再接続

スタンプあてゲームと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- 点・名前の予約はゲームにあるので、在室が消えても残る。戻ると続きから（伝える人なら、お題と道具が戻る）
- 当てる人が切れたら、4秒待ってから、その人を待たずに答え合わせ（ホストの端末が進める）。戻れば次のしるしから選べる
- 伝える人が切れたら、全員に案内し、ホストには「戻るのを待つか、下の「この問を終えて次の人へ」で交代できます」を出す。順番が来たときにいない人はとばす
- ホスト切断中、ゲストと見る画面には共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- 遊んでいる途中に新しい名前では参加できない（「もうゲームが始まっているよ」）
- 「はじめる」の瞬間に通信が切れていてゲームに入れなかった人は、戻ると見るだけの参加者になり（順番と点に入らない）、次の「もう一回あそぶ」から遊べる（スタンプあてゲームと同じ）

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おしまいの画面では自動削除しない（「もう一回あそぶ」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 「もう一回あそぶ」で `game`（お題・点）を消す。端末なしの参加者（`proxies`）は待合室に残る

## みんなにみせる画面（画面共有用・見るだけ）

ホストが遊ぶとき・端末なしの子の番を代わりに操作するときは、ホストの画面にお題が出る。ホストは別のタブで「みんなにみせる画面」を開き、それを共有する（スタンプあてゲームと同じ作り）。

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。players に入らない・切断予約をしない・期限切れのルームも消さない
- **出さないもの**: お題（答えまで）・お題の候補3つ・だれが何を選んだか・操作のボタン
- しるしと候補は大きめに出す（`.is-watch`）

### 秘匿情報の扱い（性善説）

- お題は答えまで、伝える人（端末なしの子の番はホスト）の画面にだけ出す。当てた人には、自分が当てた候補に「当たり」の印を出す（自分で選んで当てたので、新しく知ることはない）。だれが何を選んだかは画面に出さない（ホストの「代わりに押す」欄の、代わりに選んだ分だけ出す）。DevTools でルームを見れば分かることは、共通のセキュリティ方針どおり許容する

## 利用回数（stats.js）

「1回」は1問（お題1つ）。ホストが好きなところで終える型。

| 項目 | 数えるとき・端末 |
|---|---|
| `room-create` | ルームができた（ホスト） |
| `start`・`players-{N}` | お題を選んだ（選んだ端末。N はそのときいる遊ぶ人の数。進行だけのホストは含めない） |
| `finish` | 答えの画面に進んだ（答え合わせ・答えを見せる・退出・ホストの見はりで、答えへ進めることを確定させた端末） |
| `again` | 答えのあと「次の人へ」で次の問へ進んだ・一巡の順位のあと「もう一巡」・「もう一回あそぶ」（ホスト）。答えから一巡の順位へ進んだときは数えない |

## お題とアイコンの方針（`data.js`）

- 2026-10-19 のアイコン68個（5つのまとまり）・お題89個（5つのなかま）はオーナーが確定。新しいお題・アイコンを本体に入れるのはオーナーが決める（ルート AGENTS.md「新規コンテンツの本体投入は人間専任」）
- ルームではお題を番号で、しるしを id で共有するので、**お題の並べ替え・途中の削除・アイコンの id の変更はしない。お題の追加は末尾だけ**。重複は content-audit で弾く
- どのお題もどれか1つのなかま（`TOPIC_KINDS`）に入れる。どのなかまにも6個以上あると、候補をそろえやすい
- お題やアイコンを足したら、`BLOCKED`（絵や名前がお題そのものに見えるしるし）を見直す
- 学校・勉強・登校・恋愛・暴力・ホラー・死を連想させるものは入れない。人・顔・気持ちのアイコンは入れていない（気持ちを答えさせるお題にしないため）
- 候補の選び直し用のページは `drafts/shirushi-hint/tools/pick.html`（オーナーが選ぶための一覧。本体には入れない）

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は index.html しか見ないので、app.js の `ORPHAN_TTL_MS` と `clearInterval`・`clearTimeout` は rtdb-audit で手確認する
- **進行の一部をホスト以外も行う**: 伝える人がお題を選ぶ・しるしを出す・答えを見せる、最後に選んだ人の選択が答え合わせ・答えへ進める（全員同時に選ぶゲームのため。スタンプあてゲームと同じ考え方）
- **ホストの初期値は進行だけ**（`hostPlays: false`）。秘密が絡むゲームの横断決定（2026-10-01）と同じ
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **候補の記号は丸数字でなく A〜L**（しるしの番号①〜⑥と見分けるため）
- **個人の点と順位を出す**（オーナー判断。マイナスも出す）。内省ツールではなくゲームの得点
- **端末なしの参加者は在室を持たない**（`proxies`。切断しない。ホストが代わりに操作する）

## 入れない機能

- 時間制限・音（しるしごとの結果も音なし）
- 自由入力の答え・自動の表記ゆれ判定・アプリ内チャット
- 「関係するもの」の枠（2026-10-19 オーナー判断で外した）
- しるしの取り消し・同じしるしの重ね出し
- 前の問のヒント・答えの一覧（おしまいの画面は順位だけ）
- 遊んでいる途中の新しい参加者・端末なしの参加者の途中追加

## 既知の制約（v1）

- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- 当てる人が全員いなくなる（伝える人だけ残る）と、答え合わせが進まない。伝える人の「答えを見せる」か、ホストの「この問を終えて次の人へ」で進める
- ホストが切断している間は、抜けた人を待たない答え合わせ（`hostJudgeIfReady`）が進まない（ほかの人が選べば進む）
- 壊れた候補（`board`）は詰めずに、候補なしとして扱う（位置がずれて別の候補を採点しないように。その問は「答えを見せる」か交代で終える）

## メンター向けの心得（画面には出さない）

- 進行だけのときは、ホストの画面を最初から最後まで共有してよい（お題は出ない）。**「自分もプレイヤーとして参加する」をオンにしたとき・端末なしの参加者がいるときは、ルームバーの「みんなにみせる画面」を開いて、そちらを共有する**（ホストの画面に、伝える人のお題が出るため）
- 端末なしの子が当てる番では、選んだ記号（「C」など）を**メンターへの個別のチャット**で送ってもらい、「代わりに押す」欄で押す（声で言うと、ほかの子に答えが分かってしまう）
- 端末なしの子が伝える番では、お題を**個別のチャット**で知らせる。子が声で言ったしるし（「動物を出して」）をメンターが出す。しるしは全員に見えるので、声で言ってよい
- 伝える人は、ことばでヒントを言わない（しるしだけで伝える）。当てる人どうしは、予想を声に出し合ってよい
- はずれは1点減るので、自信がない子には「このしるしでは選ばない」で待ってもいいことを伝える。マイナスになった子がいたら、「次のしるしで取り返せるよ」と声をかける
- 1つ目のしるしは「何の仲間？」から出すと伝わりやすい。色・形・ようすを足していくと絞れる
