# ブラックジャック 仕様書

## 目的・使用シーン

トランプの定番ゲーム「ブラックジャック」。ディーラー（アプリ）と勝負するカードゲーム。
カードを引いて手札の合計を21にできるだけ近づけ、21を超えたらバースト。ラウンドごとに
ポイント（1・2・3・5）をかけて、ディーラーより21に近ければかけたポイントがもらえる。

- **core value**: 全員が「ディーラー対 自分」で戦う構図。子ども同士が直接対決しないため
  「あの子に負けた」が発生せず、運の比重が大きいので実力差がそのまま勝敗にならない。
  1ラウンドが短く、負けてもすぐ次が始まる（ピタハメの「負け体験を持ち越さない」と同系）。
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば（`data-scenes="bodoge hiroba"`）。
- **1〜8人**。相手がディーラーなので1人でも遊べる。**ホストもプレイヤーとして参加する**。
- 音声なしでチャット参加する子も完全に遊べる（全アクションはボタン操作で完結）。

> 名称は「ブラックジャック」をそのまま使う。トランプの**伝統ゲームの一般名称**であり、
> ルート AGENTS.md 命名ルールの「伝統ゲーム・トランプの一般名称は使ってよい」に該当する
> （先行事例: 人狼。2026-08-31 オーナー判断で「ギリギリ21」から改名）。
> ただし2枚で21の**役名**は「ブラックジャック」と呼ばず「ピッタリ21」とする
> （ゲーム名との混同を避ける・子どもに直感的なため）。

## ゲームルール

### カード

- トランプ2デッキ（104枚）。**毎ラウンド配り直す**（カードカウンティング要素なし）。
- A（エース）は 1 でも 11 でも数えられる（21を超えない範囲で自動で有利なほうに数える）。
  J・Q・K は 10。スートは勝敗に関係しない。

### ラウンドの流れ（回数無制限・ホストが終わるまで）

1. **betting**: 全員が同時に、かけるポイントを 1・2・3・5 から選ぶ（残りポイント以下のみ）。
2. 全員かけたら自動で配る: 各プレイヤーに2枚（全員に公開）、ディーラーに2枚（2枚目は伏せる）。
   最初の2枚で21（**ピッタリ21**）の人は自動でストップ扱いになる。
3. **acting**: 各自が自分のタイミングで「カードを引く」か「これでストップ」を選ぶ（同時進行・
   手番なし）。21を超えたらバースト。ちょうど21になったら自動ストップ。
4. 全員決まったらディーラーの伏せカードが公開され、ディーラーは**合計17以上になるまで**引く
   （全員がバーストまたはピッタリ21のときは引かない）。
5. **settled**: 勝敗とポイントの増減を表示。ホストは「次のラウンド」か「ここで終わる」を選ぶ。

### ポイント

- 開始時 **20ポイント**。かけられるのは 1・2・3・5（残りポイント以下の選択肢のみ有効）。
- 勝ち: +かけた分 ／ 負け・バースト: −かけた分 ／ 引き分け: ±0 ／
  **ピッタリ21: +かけた分×2**（ディーラーもピッタリ21なら引き分け）。
- ディーラーがピッタリ21のときは、ピッタリ21の人以外は（21で止まっていても）負け。
- **0ポイントになったら自動で10ポイントチャージ**（「ポイントが0になったから、10ポイント
  チャージしたよ」と明るく表示）。脱落・見学落ちを作らないための意図的な設計。
  ベットは残りポイントが下限1あれば必ずできる（チャージにより常に1以上）。

### 勝敗のまとめ

- ホストが「ここで終わる」を押した時点の持ちポイント一覧を表示。いちばん多い人をやわらかく
  表示（同点は全員）。順位表・煽り文言は出さない。
- ラウンド途中で「途中で終わる」（確認ダイアログ付き）した場合、そのラウンドは精算されない
  （それまでのポイントでまとめを表示）。

## 画面構成・フロー

```
TOP（screen-top）
 ├── ルームを作る → ニックネーム入力 → ロビー（screen-lobby）
 └── 入る → ニックネーム + コード入力 → ロビー or ゲーム（途中参加）
                      ↓（ホストが「始める」/ 1〜8人）
            ゲーム画面（screen-game）
              betting → acting → settled をラウンドごとに繰り返す（画面遷移はしない）
                      ↓（ホストが「ここで終わる」/「途中で終わる」）
            まとめ（screen-result）
              ホスト: 「もう一度」（接続中メンバーで20ポイントから仕切り直し）
                      「トップへ戻る」（ルーム削除）
              ゲスト: 「トップへ戻る」（自分の退出のみ）
```

- 観戦（みるだけ）モードは**置かない**: プレイヤーの手札は全員に公開で、秘匿情報はディーラーの
  伏せカード（全員に等しく非表示）だけ。どのプレイヤーの画面を画面共有しても情報漏れがない。

## status 遷移

```
waiting → playing → result（ここで終わる／途中で終わる）
result →（もう一度）→ playing
```

| status | 説明 |
|--------|------|
| `waiting` | ロビー。1〜8人 |
| `playing` | ゲーム中。`match/phase` が betting / acting / settled を持つ |
| `result` | ポイントまとめ。ホストは「もう一度」「トップへ戻る」 |

- `waiting → playing`（開始）、`result → playing`（もう一度）、`playing → result`（終わる）は
  **ホストのみ**。ラウンド内のフェーズ進行（配り・精算）は下記のとおり各メンバーの transaction が行う。

### 途中参加（このアプリ固有）

回数無制限のラウンド制でひろば運用も想定するため、**ゲーム開始後も参加できる**:

- `playing` かつ `phase === 'settled'`（ラウンドの合間）: `players` と `match/members` に追加され、
  20ポイントで次のラウンドから参加。
- `playing` のラウンド中（betting / acting）: 参加は拒否し「いまのラウンドが終わったら入れるよ」
  と案内（もう一度押せば入れる）。
- `result`: `players` にだけ追加され、「もう一度」で参加（まとめ画面に案内文を表示）。
- ロビー同様、上限8人・ニックネーム重複チェックは同じ transaction 内で行う。

## Firebase データ構造（Realtime Database）

パス: `blackjack_rooms/{roomCode}/`（共通命名規則。セキュリティルール変更不要）

```
blackjack_rooms/{roomCode}/
  ├── host / hostConnected / hostDisconnectedAt / status / createdAt   # 共通
  ├── players/                          # presence: 「いま接続している人」のみ（ノードの有無が接続状態）
  │    └── {nickname}/ { isHost, seat }
  └── match/                            # 開始・「もう一度」で丸ごと上書き
       ├── matchId: number              # ゲーム世代（開始=1、もう一度で+1）
       ├── members/ {nickname}: { seat } # 対戦者集合（settled 中の途中参加でのみ増える）
       ├── points/  {nickname}: number  # 持ちポイント（精算 transaction が更新）
       ├── round:   number              # 1始まり・上限なし
       ├── phase:   'betting' | 'acting' | 'settled'
       ├── deck:    [number × 104]      # 0〜103 のカードID。ラウンド開始時にシャッフル済みで固定
       ├── pos:     number              # deck の次に配る位置（配り・引き・ディーラーで単調増加）
       ├── bets/    {nickname}: number  # このラウンドのかけポイント。無ければ absent
       ├── hands/   {nickname}: [cardId, ...]
       ├── dealer:  [cardId, ...]       # [0] は常に公開、[1] は settled まで UI で伏せる
       ├── done/    {nickname}: 'stand' | 'bust' | 'bj'
       └── outcome/ {nickname}: { res: 'win'|'lose'|'push'|'bj', delta, charged? }
```

- カードID: `id % 52` で1デッキに畳み、`% 13` がランク（0=A…12=K）、`÷ 13` がスート。
- `bets` / `hands` / `done` / `outcome` は「次のラウンド」で null にリセット。読み取りは必ず
  `|| {}` / `|| []` で補う（RTDB は空オブジェクト・空配列を保存しない）。
- ディーラーの伏せカードは RTDB 上は平文（**性善説**・共通方針どおり）。表示だけ
  `phase !== 'settled'` の間 `dealer[1]` を裏面にする。

### ラウンド進行の純関数と transaction 設計

進行ロジックは3つの**純関数**（乱数なし・入力を破壊的変更しない）に集約:

- `dealRound(match)`: `deck[pos]` から seat 順に2枚ずつ→ディーラー2枚を配り、ピッタリ21を
  `done='bj'` にする。
- `settleRound(match)`: ディーラーが `deck[pos]` から17以上まで引き（`stand` の人がいるときだけ）、
  全員の勝敗・ポイント増減・チャージを確定する。
- `advanceIfReady(match)`: betting で全員かけたら配る→（全員ピッタリ21なら続けて精算）、
  acting で全員済みなら精算する。**かける・引く・ストップ・退出の各 transaction が最後に通す**。

deck はラウンド開始時（開始・次のラウンド・もう一度）にホストが transaction の**外**で
シャッフルして書き込むため、配り・ディーラーの引きは `deck[pos]` からの順次消費＝決定的。
どの端末の transaction が進行を確定しても同一結果になる（esadori の judge と同じ考え方）。

| 操作 | 実行者 | transaction 内の検証 → 書き込み |
|------|--------|--------------------------------|
| 作成 | ホスト | `room == null` → 初期ルーム一式 |
| 参加 | ゲスト | 上記「途中参加」参照（waiting / settled / result で可） |
| 開始 | ホスト | `status==='waiting'`・host 本人・1〜8人 → `status:'playing'` + match 一式（deck は外で生成） |
| かける | 各メンバー | `phase==='betting'`・matchId/round 一致・未ベット・選択肢∈{1,2,3,5}・残ポイント以上 → bets 追加 + `advanceIfReady` |
| 引く | 各メンバー | `phase==='acting'`・未確定 → `deck[pos]` を手札に追加・pos+1。21超で bust、21ちょうどで自動 stand + `advanceIfReady` |
| ストップ | 各メンバー | `phase==='acting'`・未確定 → `done='stand'` + `advanceIfReady` |
| 次のラウンド | ホスト | `phase==='settled'` → round+1・新 deck（外で生成）・bets/hands/dealer/done/outcome を null |
| ここで終わる | ホスト | `status==='playing'` → `status:'result'`（match は残す） |
| もう一度 | ホスト | `status==='result'` → 接続中の players で members/points(20) を作り直し・matchId+1 |
| ゲスト退出 | 各自 | players と match（members/points/bets/hands/done/outcome）から自分を削除し、最後の待ち人だった場合は `advanceIfReady` で進行を進める（下記） |

- クライアントは操作時点の `matchId` / `round` / `phase` を捕捉し transaction 内で再検証
  （ABA 対策・esadori と同じ）。
- かける・引く・ストップは `state.actionBusy` で連打をガード。
- 21ちょうどでの自動ストップは「21で誤って引いてバースト」を防ぐ子ども向けの意図的な仕様。
- deck は104枚で、8人が引き続けても実質尽きない（引く際に `pos >= deck.length` なら abort する
  保険のみ入れてある）。

## 接続・切断・再接続

esadori の presence「ノードの有無方式」をそのまま採用:

| 役割 | onDisconnect 予約 |
|------|------|
| ホスト | `roomRef.onDisconnect().update({ hostConnected:false, hostDisconnectedAt:TIMESTAMP, 'players/{host}': null })` |
| ゲスト | `players/{nick}` への `onDisconnect().remove()`（全フェーズ共通） |

- ゲーム データ（points / hands / bets）はすべて `match/` 側にあるため、presence ノードが消えても
  失われない。切断表示は「members に居て players に居ない人」。
- `.info/connected` を購読し、復帰のたびに**復帰の書き戻し transaction**（`writeBackPresence`）で
  presence を再作成 → 成功後に onDisconnect 予約を張り直す。epoch ガードで「書き戻し中に退出」を無効化。
- sessionStorage キー **`blackjack_session`**（roomCode / nickname / isHost / matchId）。
  リロード時 `tryReconnect()` で復帰。RTDB の値から画面を完全再構築できる。
- **result 中の復帰はメンバーでなくても許可**（result 途中参加者が自動再接続で弾かれないため。
  members に居ない guest は players にのみ戻る）。playing 中は members に居なければ復帰不可。
- ホスト切断: ゲストにオーバーレイ + 2分カウントダウン（`ORPHAN_TTL_MS = 2 * 60 * 1000`）。
  TTL 判定は `RoomkRTDB.now()` / `isRoomExpired()`（サーバー時刻補正）。

### 切断中の進行

- 切断中のメンバーの「かける」「引く」も**待つ**（進行が止まる）。軽い通信切れは
  `.info/connected` 復帰で解消。長い離脱はホストの「途中で終わる」か、本人の明示退出で解消する。
- **明示的なゲスト退出は match からも自分を抜く**（esadori は presence のみ削除だが、本アプリは
  回数無制限で退出者を待ち続けると永遠に止まるため）。自分が最後の待ち人だった場合は退出
  transaction 内で `advanceIfReady` を通し、配り・精算まで進める。

## 終了とデータ削除

- `result` 画面ではルームを**自動削除しない**（「もう一度」と振り返りのため。公認バリアント
  「ふりかえり画面滞在中は削除しない」を採用。先行事例: esadori, tatoe-narabe）。
- クリーンアップ経路は3つ: ①ホストの「トップへ戻る」で即時 `remove()` ②ホスト切断
  onDisconnect + 2分 TTL ③次回アクセス時（join / tryReconnect / ルーム監視）の期限切れ判定。
- すべての退出・削除経路で `remove()` の前に必ず `cancelRoomOnDisconnect()` を await する。
- 期限切れ削除は transaction（`room => isRoomExpired(room) ? null : undefined`）。abort した場合は
  自分の presence ノードだけ削除して残留を防ぐ。壊れルーム（status/host 無し）も同様に掃除。

## 文言・UX ガイド

- 通常表記（漢字まじり。ルート AGENTS.md「表記トーン」参照）。
- 「賭ける」ではなく**ひらがなの「かける」**を使う（カジノ・ギャンブル色を薄める）。
  カジノ風の装飾（緑のフェルト・ドル記号・チップ演出）は置かない。普通のトランプの見た目。
- 負けは淡々と（「負け… −3ポイント」）。バーストは「バーストしちゃった…」と軽く。
  チャージは明るく（「ポイントが0になったから、10ポイントチャージしたよ」）。責める演出はしない。
- まとめの「いちばん多かったのは◯◯さん！」はやわらかく祝う。順位表・煽りは出さない。
- ベットの選択肢はチャットで番号回答する場面ではないため、丸数字（①②）の採番ルールは適用しない。

## 共通規約からの逸脱の明文化

- **競争要素（ポイント・いちばん）を意図的に残す**: 「比較を促さない」の例外案件
  （先行事例: ピタハメ、エサドリ、ピッタリメーターの個人得点制）。かけひきの緊張感がゲームの核。
  ただし対戦相手はディーラーであり、子ども同士の直接対決は構造上存在しない。
- **ポイントの自動チャージ**: 原典に無い独自ルール。「脱落して見ているだけ」を作らないための
  意図的な設計（負けの固定を避ける）。
- **最小人数 1人**: 対ディーラー戦のため1人で成立する（既存アプリの2〜3人下限より少ない）。
- **途中参加あり**: waiting 以外（settled / result）でも参加できる本リポジトリ初のパターン
  （ひろばのドロップイン運用のため）。
- **match の更新はホスト以外も行う**: フェーズ進行（配り・精算）は最後にアクションした端末の
  transaction が確定する（esadori と同じ）。
- **明示退出で match からも自分を抜く**: esadori（presence のみ削除）からの意図的変更。上記参照。
- **result 後の自動削除なし**: 公認バリアント採用。
- **観戦モードなし**: プレイヤー間に秘匿情報が無いため不要（上記「画面構成」参照）。

## メンター向け進行のコツ

- このゲームの本体は**「もう1枚引くか、ここで止まるか」のドキドキ**。「いま16。引く？止まる？」と
  声に出して聞くと、チャットの子も「ひく！」と参加しやすい。
- ディーラーは17以上まで引く、というルールを最初に一度だけ説明しておくと、「ディーラーは
  いま何点で止まりそうか」の読みが立ち上がる。
- かけるポイントの大小に良し悪しはない。大きくかけて負けた子には淡々と、チャージは
  「復活！」くらいの軽さで扱う。
- 全員の手札が見えるので、どのプレイヤーの画面を共有してもよい。
- 1ラウンドは2〜3分。45分枠なら10ラウンド前後 + まとめ、くらいのペース感。
- 途中で抜けたい子は「退出する」で抜けてよい（進行は止まらない）。通信が切れたまま戻らない子が
  いたら「途中で終わる」→「もう一度」で仕切り直せる。
