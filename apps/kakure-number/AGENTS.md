# かくれナンバー 仕様書

## 目的・使用シーン

コヨーテ風の「自分の数字だけ見えない」推理ゲームを、脱落なし・全員同時参加のポイント制にアレンジしたオンラインゲーム。
各ゲストの画面には他の全員のニックネームと数字が見え、**自分の数字だけ「？」で表示**される。
さらに**誰にも見えない「隠しカード」が1枚**場に配られ、これも合計に含まれる。
「ぼくの数字、大きい？」のように声やチャットで探り合いながら、全部の数字の合計（自分の？と隠しカードも含む）を予想する。

- **core value**: 「自分にだけ見えない情報」というオンライン＋各自端末ならではの体験。この駆け引き（声での探り合い）がゲームの本体で、画面はその補助。
- **隠しカードの意図**: 未知が自分の数字1枚だけだと、声で探り合った時点で合計がほぼ確定してしまい「当てるのが簡単すぎる」（2026-08-17 実機フィードバック）。誰にも見えない1枚を足して未知を2枚にすることで、探り合いの価値は残したまま、ぴったり賞が適度に難しくなる。全員に等しくかかるブレなので、自分の数字をよく推理した人が有利という構図は変わらない。
- 対象: 小学校中学年〜中学生。メンターがホスト（ファシリテーター）としてルームを作り、画面共有しながら進行する。
- ホストは待合室で「自分もプレイヤーとして参加する」を選べる。**初期値は進行だけ**（数字を配られず、推理にも参加しない＝従来どおり）。遊ぶ人（数字を配られる人）3〜8人で遊ぶ。下の「ホストの参加」節を参照。

> 原作「コヨーテ」にインスパイアされた派生ルール。脱落・ライフ制をなくし、
> 「いちばん近い予想」を称えるポイント制に変更している。

## 画面構成・フロー

```
TOP（screen-top）
 ├── ホスト → ニックネーム入力 → ルーム作成・待機（screen-host-setup）
 ├── ゲスト → ニックネーム＋コード入力 → 待機（screen-waiting）
 └── みんなにみせる画面 → コード入力（screen-spectate-join）→ 共有画面（screen-spectator）
                     ↓（ホストが「はじめる」/ 遊ぶ人3〜8人）
           予想タイム（screen-thinking）
             ゲスト: 他の全員の数字が見える。自分と隠しカードが「？」。
                     合計をステッパーで入力 →「きめた」
             ホスト: 進行欄に提出状況のみ表示（数字・合計・予想の値は一切出さない）
                     遊ぶときは、その上にゲストと同じ表示（自分と隠しカードが「？」・予想の入力）
                     全員提出で自動遷移 / 「締め切る」で強制遷移
                     ↓
           こたえあわせ（screen-reveal）
             全員の数字・本当の合計・各自の予想・得点を一覧表示
             ホスト: 「つぎへ」（数字を配り直して thinking へ）/「おわる」
                     ↓
           おしまい（screen-done）
             累計ポイントを控えめに表示。30秒後にルーム自動削除
```

- ラウンド数の上限はなし。ホストが「おわる」を押すまで繰り返す。
- 画面共有用の「みんなにみせる画面」は下の節を参照（数字は答え合わせまで出さない）。
- 予想入力はタブレット向けの大きめステッパー（−／＋ボタン 64px + 数値直接入力、`inputmode="numeric"`）。
- 予想値は理論上の合計範囲 **(人数+1)×1 〜 (人数+1)×10**（+1 は隠しカードの分）でバリデーション（範囲は配った時点の人数で固定し `round/minSum` `round/maxSum` に保存）。
- 参加用のリンク `?room=CODE` と「リンクをコピー」（2026-10-05）。共通仕様は docs/development/rtdb.md「参加用のリンク」。このアプリの入口は末尾の `init()`（`?watch=` → `?room=` → sessionStorage の順）、参加画面は `screen-guest-join`（`openJoinFromLink` がコード欄 `#guest-room-code` に入れ、`#joinLinkHint` を出す）。`?room=` はつないだとき `startRoomListener()` の先頭で外す（みんなにみせる画面では触らない）
  - 「リンクをコピー」（`#btnCopyLink`）はホストの待機（`host-step-room`）の「コードをコピー」の下だけ（ゲストの待合室にはもともとコピーのボタンがない）。コピーは共通の `RoomkRTDB.copyRoomLink`（`copyToClipboard` はコード専用の `copyRoomCode` なので使わない）
  - 固有: みんなにみせる画面の記録（`role: 'spectator'`）が同じコードで残っていても再接続を優先しない（記録を消して参加画面へ）。参加画面の欄名に合わせ、ヒント・あそびかたは「名前」でなく「ニックネーム」
- 参加フォームからの入室は `waiting` 中のみ。ゲーム開始後の名前だけによる再入室は拒否し、復帰は同じタブの保存済みsessionによる `tryReconnect()` のみとする（2026-09-09 P-12）。sessionStorageは認証境界ではなく、別端末の本人確認を追加したものではない。ホスト名の参加拒否は維持する。

## みんなにみせる画面（画面共有用）

2026-10-01 オーナー決定で追加。ホストのタブとは別に、画面共有するための読み取り専用の画面（`#screen-spectator`）。
見ている全員（遊ぶ本人も）が見てよい情報だけを出す。正本は `apps/kaburazu-hint/AGENTS.md` の同名の節で、作りをそろえている。

### 入口（3つ）
1. **URL `?watch=CODE`**（最優先）: 起動時に既存の sessionStorage を破棄してから検証（NFKC・大文字化・`/^[A-Z0-9]{6}$/`）。無効・ルームなし・期限切れはトースト＋TOP（sessionStorage へフォールバックしない）。`?watch=`（空）も同じ扱い。`?watch=` がないときだけ参加用のリンク `?room=`・sessionStorage を見る
2. **TOP**: 「みんなにみせる画面をひらく」→ コード入力 →「画面をひらく」。成功したら `history.replaceState` で URL を `?watch=CODE` にそろえる（リロードで戻れる）
3. **ホストの画面**: 待合室・予想タイムの進行欄・答え合わせの操作欄にある「みんなにみせる画面をひらく」。クリックの中で同期的に `window.open(url, '_blank', 'noopener')`

### 完全分岐・書き込みゼロ
- `state.role = 'spectator'`。ルーム購読の入口で `handleSpectator(room)` へ分岐し、host/guest の処理（切断オーバーレイ・期限切れの `remove()`・自動 reveal・加点・30秒後削除・onDisconnect・players への読み書き）に入らない
- RTDB には一切書き込まない（players にも入らない）。匿名認証だけは行う（ルールが `auth != null`）
- sessionStorage `kakure_session` に `{ nickname: '', roomCode, role: 'spectator' }` を保存。保存済みセッションからの復帰でも、期限切れのルームを `remove()` しない
- 「トップへ戻る」（`spectatorLeave()`）: 購読を外し、セッション削除・`?watch` を URL から除去して TOP。ルームには触らない

### フェーズ別の表示
**数字（各自の数字・隠しカード・本当の合計）を DOM に書くのは reveal / done 以降だけ**（thinking 中は `round/numbers` のキー＝名前だけを使い、値・`fieldNumber`・`total` を読まない）。名前・予想は `esc()` を通す。

| status | 表示 | 出さないもの |
|--------|------|------------|
| waiting | ルームコード・参加者一覧・「はじまるのを待っています」 | — |
| thinking | ラウンド・「n 人 / m 人がきめた」・名前ごとの「きめた／考え中…／退出中」 | 各自の数字・隠しカード・合計・予想の値 |
| reveal | 本当の合計・全員の数字と予想・いちばん近い／ぴったり・これまでのポイント（全員に公開される段階） | 操作ボタン |
| done | おしまい・きょうのポイント | 操作ボタン |
| （未知） | 「準備しています…」 | — |

### 切断・終了
- `hostConnected === false`（done 以外）: 共有画面用のオーバーレイ `#spec-host-off-overlay`（ボタンは「トップへ戻る」）。TTL 超過は `remove()` せず「このルームは終了しました」に切り替え。更新が来なくてもローカルタイマー（`state.specTimer`）で TTL を判定し直す
- ルームが消えた（snapshot null）: おしまいを表示済みならその画面を残し、それ以外は「このルームは終了しました」。どちらも `stopSpectatorWatch()` で購読とタイマーを止める（同じコードが将来使われたときに別のゲームを映さないため）

## status 遷移

```
waiting → thinking → reveal → thinking（次ラウンド）…
                        └→ done（30秒後にルーム削除）
```

| status | 説明 |
|--------|------|
| `waiting` | ロビー。このフェーズのみ新規入室可。遊ぶ人3〜8人（ホストが遊ぶならホストも数える）。ホストの参加はこのあいだだけ変更可 |
| `thinking` | 数字を配布済み。ゲストが合計を予想して提出する時間（＝声での探り合いタイム） |
| `reveal` | 全数字・本当の合計・予想・得点を一斉公開 |
| `done` | 終了。累計ポイント表示。ホストが30秒後に `roomRef.remove()` |

- `status` の更新はホストのみ（UIで制御）。
- `waiting → thinking` と `reveal → thinking` は同じ `hostStartRound()` の `transaction()` で行い、その時点の遊ぶ人（ゲスト＋遊ぶならホスト）に 1〜10 のランダムな数字（重複あり）を配る。あわせて場の隠しカード（1〜10）も1枚引く。
- `thinking → reveal` は「配布済みかつ在室中の人全員が提出」でホスト端末が自動実行。未提出者がいても、予想が1件以上あればホストが「締め切る」で強制遷移できる。

## Firebase データ構造（Realtime Database）

パス: `kakure_rooms/{roomCode}/`（共通命名規則 `{appname}_rooms` に準拠。セキュリティルール変更不要）

```
kakure_rooms/{roomCode}/
  ├── host:                string          # ホストのニックネーム
  ├── hostConnected:       boolean         # 切断検知用
  ├── hostDisconnectedAt:  number | null   # 切断時のサーバータイムスタンプ（ms）
  ├── status:              string          # waiting | thinking | reveal | done
  ├── settings/
  │    └── hostPlays:      boolean         # ホストも遊ぶか（待合室のあいだだけホストが変更）。キーなし＝false＝進行だけ
  ├── players/
  │    └── {nickname}/
  │         ├── isHost: boolean
  │         └── score:  number             # 累計ポイント（進行だけのホストは常に0で加点対象外）
  └── round/                               # 現在のラウンド（配り直しで丸ごと上書き）
       ├── number:      number             # 1始まり
       ├── numbers:     { [nickname]: 1〜10 }  # 配った数字。配布時点で固定
       ├── fieldNumber: number             # 場の隠しカード 1〜10。誰にも見せず、合計にだけ含める
       ├── total:       number             # 本当の合計（numbers の総和 + fieldNumber）。配布時点で固定
       ├── minSum:      number             # 予想の下限（(配布人数+1)×1）
       ├── maxSum:      number             # 予想の上限（(配布人数+1)×10）
       ├── guesses:     { [nickname]: number } | null  # 各ゲストの予想
       └── scoreDeltas: { [nickname]: number } | null  # reveal 確定時の加点（+2 / +3）
```

### データ操作の注意点

- **ルーム作成・参加・ラウンド開始**はすべてルームルートへの `transaction()`。参加時は `status === 'waiting'`・ニックネーム重複・ゲスト上限8人のチェックと `players` 追加を同一 transaction 内で行う
- **数字の配布**も `hostStartRound()` の transaction 内で行う（その時点の `players` から遊ぶ人を列挙して `numbers` / `fieldNumber` / `total` / `minSum` / `maxSum` を確定）
- **予想の提出**は各ゲスト（と遊ぶホスト）が `round/guesses/{nickname}` に `set()` するだけ（キーが分かれるので競合なし）
- **reveal への遷移と加点**はホスト端末が `update()` で一括書き込み（`status` + `round/scoreDeltas` + `players/*/score`）。二重集計はホストローカルの `revealTriggered` フラグで防止

## 切断時の挙動

| 役割 | 挙動 |
|------|------|
| ホスト切断 | `onDisconnect().update({ hostConnected: false, hostDisconnectedAt: ServerValue.TIMESTAMP })`。ゲストにはカウントダウン付きオーバーレイを表示し、TTL（`ORPHAN_TTL_MS = 2分`）超過で期限切れ扱い→ルーム削除を試みて退出 |
| ゲスト切断 | `onDisconnect().remove()` で `players/{nickname}` のみ削除 |

- TTL 判定は `RoomkRTDB.initServerTime(db)` + `RoomkRTDB.now()` / `RoomkRTDB.isRoomExpired()` でサーバー時刻寄りに補正。
- `joinRoom` / `tryReconnect` / ルーム監視の各タイミングで期限切れルームを検知したら `remove()` を試みる。
- 再接続: sessionStorage キー **`kakure_session`**（nickname / roomCode / role / score）。リロード時に `tryReconnect()` で復帰。ホストは `hostConnected: true` / `hostDisconnectedAt: null` を書き戻す。ゲストは `players/{nickname}` が消えていれば保存済みスコアで再追加する。

### ラウンド途中でゲストが抜けた場合の方針（明文化）

- **合計は配った時点の数字で固定**する。`round/numbers` `round/fieldNumber` `round/total` はゲストの退出では変更しない（退出者の数字も合計に含まれたまま）。予想範囲 `minSum` / `maxSum` も配布時点のまま固定。
- 退出者の `players/{nickname}` は消えるが、`round/numbers/{nickname}` は残るため、他のゲストの画面には退出者の数字が引き続き表示される（reveal では「（退出）」表示）。
- **自動 reveal の判定**は「配布済みかつ在室中のゲスト」だけを対象にする（退出者の提出は待たない）。
- **得点計算**からは、reveal 確定時点で `players` にいないゲストの予想を除外する。
- 同じタブの保存済みsessionから復帰する場合、配られていた数字・提出済みの予想はそのまま有効。名前だけを入力する再入室では復帰できない。

## ホストの参加（hostPlays）

2026-10-01 オーナー決定: 待合室でホストの参加を選べる（初期値は進行だけ＝従来どおり）。

- 待合室のホストの画面に「自分もプレイヤーとして参加する」（`#set-host-plays`、初期値オフ）。`waiting` のあいだだけ、ルームへの `transaction()` で `settings/hostPlays` を書き換える（開始後は変えない。「つぎへ」は同じ設定のまま配り直す）
- 判定は `room.settings.hostPlays === true`。キーがない部屋（旧版が作った部屋）は進行だけ
- **遊ぶ人だけで数える**: 数字を配る相手・最少3人／最大8人・予想の範囲（(遊ぶ人+1)×1〜×10）・自動 reveal の「全員提出」・得点・ポイントのチップ。開始ボタンは遊ぶ人が足りないと無効になり「遊ぶ人があと N人必要です」を出す。参加 transaction は遊ぶ人が8人なら弾く。ゲストがすでに8人いるときは、ホストはチェックを入れられない（トースト）
- 進行だけのホストは一覧のバッジが「ホスト・進行役」。予想タイムは従来どおり進行欄（提出状況と「締め切る」）だけ
- 遊ぶホストの画面はゲストと同じ見え方（他の人の数字が見え、自分と隠しカードは「？」・予想の入力）＋その下に進行欄（提出状況・締め切る・みんなにみせる画面をひらく）。進行欄にも数字・合計・予想の値は出さない。答え合わせ以降はゲストと同じ一覧に自分の行（あなた）が出る
- 遊ぶホストの数字はゲストの画面に普通に表示される（他の人の数字なので）。みんなにみせる画面では答え合わせまで出ない
- 再接続: ホストは `tryReconnect()` でホストとして戻る（遊ぶときは配られた数字・提出済みの予想もそのまま）

## 得点ルール

各ラウンドの reveal 時に確定:

- 本当の合計に**いちばん近い**予想をした人: **+2点**（同着は全員 +2）
- **ぴったり**（差0）はさらに **+1点**（計 +3点）
- それ以外は加点なし（減点なし・脱落なし）

累計スコアは reveal / done 画面で小さなチップ表示のみ。**順位づけ・並べ替え・優勝表示はしない**（表示順はニックネーム順で固定）。進行だけのホストは加点対象外（遊ぶときはゲストと同じに加点・チップ表示）。

## 共通規約からの逸脱の明文化

- **最終結果で順位・優勝者を表示しない**: do-mannaka 等の対戦系と異なり、winner ブロック・ランキングを意図的に置かない。「いちばん近い」をラウンド内で軽く称えるにとどめ、累計は控えめなチップ表示のみ（比較を促さないコンテンツガイドラインに寄せた設計）。
- **進行だけのホストは数字を持たない**（初期値）: `players/{host}` は存在する（プレイヤーリスト表示・isHost 判定用）が、`round/numbers` には含めない。ホスト画面には thinking 中、数字・合計を一切表示しない（ホスト画面は画面共有されうるため。提出状況のみ表示）。ホストが遊ぶときは数字を配り、ホストの画面はゲストと同じ見え方になる（ホストのタブは共有しない前提）。
- **秘密情報（自分の数字・隠しカード）は UI レベルの非表示のみ**: RTDB の構造上、自分の数字も `round/fieldNumber` も端末に届いている。DevTools で見ようと思えば見えるが、共通のセキュリティ方針（性善説・スタッフ監視下での使用）どおり許容する。
- **遊ぶ人の上限あり（8人）**: 数字カードの一覧性と1〜10×人数の予想レンジが破綻しない範囲として、参加 transaction で遊ぶ人9人目以降を弾く（ホストが遊ぶときはゲスト7人まで）。
- それ以外（transaction・onDisconnect・TTL 2分・30秒後削除・sessionStorage 再接続・esc() による XSS 対策・6桁ルームコード・ニックネーム8文字）は共通規約どおり。

## メンター向け進行のコツ

- このゲームの本体は画面ではなく**声の探り合い**。thinking 中は「『わたしの数字、大きい？』って聞いていいよ」「ウソはなし？あり？はみんなで決めよう」と最初に促すと動き出しやすい。
- 「？」が2枚あることは最初に一度だけ説明する。**自分の数字は聞けば分かるが、隠しカードは誰にも分からない**——ここが「ぴったり当てにくい」理由なので、「隠しカードは運。自分の数字をどれだけ絞れたかで勝負」と伝えると納得しやすい。
- 数字についてのやりとりは正直に答えても、あいまいに答えてもよい（「ウソあり」にするかはグループで合意を取ると盛り上がる）。
- 進行だけのときは、ホスト画面は数字が出ないので、そのまま画面共有してよい。別のタブで「みんなにみせる画面」をひらいて、そちらを共有してもよい（数字は答え合わせまで出ない）。こたえあわせ（reveal）は全員に公開される前提の画面。
- **ホストが遊ぶときは、みんなにみせる画面を共有し、ホストのタブは共有しない**（ホストのタブにはゲストと同じく他の人の数字が出る）。待合室で「自分もプレイヤーとして参加する」にチェックを入れたら、待合室の「みんなにみせる画面をひらく」でひらいて、そちらを共有に切り替える。
- 予想が出ない子がいても「締め切る」で先に進める（未提出は「よそうなし」表示になるだけで、責める演出はない）。
- 1ラウンドは2〜4分程度。5〜8ラウンドで20分前後が目安。
- 終わるときは reveal 画面で「おわる」→ おしまい画面が出て30秒後にルームは自動で消える。
