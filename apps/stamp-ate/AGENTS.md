# スタンプあてゲーム 仕様書

## 目的・使用シーン

丸・四角・長方形・三角の4つのスタンプだけで、こっそり配られたお題を表し、当てる人が「どの絵がどのお題か」を当てる協力ゲーム。
押せる回数は1回目の5回から1回ずつ減り、5回目は1回だけ。少ない手数で伝えるために、回を重ねるうちに生まれる「この形はこういう意味」というチームの共通の言葉を楽しむ。

- **core value**: 絵のうまさがいらない（形と色が決まっている）。押す・選ぶだけで参加でき、話さなくても主役になれる。全員が同じチームで、競争や順位はない。
- 対象: 小学校中学年〜中学生。ボドゲクラブ・サークルタイム（`data-scenes="bodoge circle"`）。
- 遊ぶ人 **3〜9人**（当てる人1人＋押す人2〜8人）。ゲストは8人まで。ホストは既定で進行だけ。待合室の「自分もプレイヤーとして参加する」で遊ぶ人に入れる。
- 所要時間 15〜20分（全5回）。

> 着想元は『スタンプ絵作りクイズ インクdeリンク！』（原題 Ink It!、Bankiiiz Editions／日本語版 ケンビル、2024）。名称・見た目・お題は使わない。紹介文・早見表では「『インクdeリンク！』から着想」と記述的に紹介し、「Web版」「オンライン版」「無料版」等の表現は使わない。
> 表示名「スタンプあてゲーム」・フォルダ `stamp-ate` はオーナー決定（2026-10-03）。

## ルール

原作どおり:

- 全5回。1回ごとに **当てる人** が1人決まり、ほかの全員が **押す人** になる。当てる人は、ゲーム開始時にシャッフルして固定した順番（`game/order`）で1回ずつ回る（`order[(回 − 1) % 人数]`）。人数が5人より多いときは、当てる人にならない人がいる。
- 押す人には、自分だけのお題が1つずつ配られる。お題はスタンプで紙に表す。
- スタンプは4種類で、**形ごとに色が決まっていて変えられない**（赤い丸・青い四角・黄色い長方形・緑の三角）。大きさも変えられない。
- 押せる回数は1回目が5回で、回ごとに1回ずつ減る（5・4・3・2・1）。
- 紙は縦長。押す人は紙の向きを90度ずつ回せる（当てる人には、回した向きで見える）。原作の「紙の向きを決めて出してよい」に当たる。
- 押す人が全員「完了」したら当てる番。絵をまぜて番号（①②…）をつけ、お題の一覧もまぜて出す。当てる人は、絵ごとにお題を選んで「これで決める」。
- 答え合わせで、伝わった数・ちがった数を出す。**ちがった数の合計がチームの人数（遊ぶ人の数）までならクリア**。
- 追加ルール「よけいなお題」（原作の「はみ出し者」）: 待合室で「よけいなお題を2つまぜる」をオンにすると、どの絵のものでもないお題が2つお題の一覧にまざる。

room-K 向けに変えたもの（オーナー決定 2026-10-03）:

- **必ず5回目まで遊ぶ**。原作は、ちがった数がチームの人数をこえた時点で全員の負けになって終わるが、ここでは途中で終わらせず、最後に「クリア！」か「今回はここまで」を出す。押せる回数が1回になる最後の回まで、みんなでたどり着くため。
- **「1つ戻す」で押したスタンプを取り消せる**（「完了」の前まで）。原作のインクは取り消せないが、タッチの押し間違いで困らないようにするため。
- **当てる人は参加者の順番回し**（原作どおり）。

そのほか room-K 向けに足したもの:

- **スタンプの向き**: 「スタンプの向きを回す」で45度ずつ回せる（8方向）。原作のスタンプは手で好きな向きに押せるため。選んでいるスタンプの見本と、マウスで紙の上にいるときの薄い形（押す位置の目安）も同じ向きで出す。
- **ほかのお題にする**: まだ1つも押していないときだけ、お題を引きなおせる（原作の、子どもには難しいお題は引きなおす遊び方）。ほかの人のお題・よけいなお題とは重ならない。
- **なおす**: 「完了」のあとも、全員がそろう前なら「なおす」で戻せる。
- **しめきる**: 通信が切れた人などで全員がそろわないとき、ホストは「しめきる」（確認あり）で、今ある絵のまま当てる番に進める。スタンプを1つも押していない人の絵とお題は、その回の当てる対象から外す（答え合わせに「今回は○○さんの絵はなかったよ」と出す）。1枚も絵がないときは進めない。
- **ホストの代わりの選択**: 当てる番では、ホストも当てる人と同じ操作ができる。当てる人の通信が切れたときや、声・チャットで答えてもらったときに、ホストが代わりに選ぶため（キャリアすごろくのホスト代理と同じ考え方）。
- **ゲームをやめる**: ホストは遊んでいる途中（おしまいの画面を除く）に「ゲームをやめて待合室へ戻る」（確認あり）で待合室に戻れる。

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室
 ├── 参加用のリンク `?room=CODE` → 参加画面（ルームコード入力済み・名前だけ入れる） → 待合室
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting / status: waiting）
   ホスト: 参加者（遊ぶ人 N人）、「自分もプレイヤーとして参加する」、「よけいなお題を2つまぜる」、「はじめる」
   ゲスト: 待機表示
        ↓「はじめる」（遊ぶ人 3〜9人）
スタンプを押す（screen-stamping / status: stamping）
   押す人: あなたのお題・あと○回・紙・4つのスタンプ・「スタンプの向きを回す」「紙を回す」「1つ戻す」・「完了」/「なおす」
   当てる人: 「あなたが当てる番だよ」と進み具合（お題は出さない）
   進行役のホスト・見る人: 進み具合。ホストは「しめきる」
        ↓ 押す人が全員「完了」／ホストの「しめきる」
当てる（screen-guessing / status: guessing）
   全員: 番号つきの絵と、お題の一覧。当てる人の選び途中もそのまま見える
   当てる人とホスト: 絵を選ぶ → お題を選ぶ（次のまだ決めていない絵へ進む）。全部決めたら「これで決める」
        ↓「これで決める」
答え合わせ（screen-reveal / status: reveal）
   全員: ○枚のうち○枚 伝わったよ・ここまでのちがった数・絵ごとのお題と当てた答え
   ホスト: 「つぎの回へ」（5回目は「結果を見る」）
        ↓ 1〜4回目 → スタンプを押す（次の回） ／ 5回目 → おしまい
おしまい（screen-end / status: end）
   全員: 「クリア！」か「今回はここまで」・それぞれの回の伝わった数
   ホスト: 「もう一回あそぶ」（→ 待合室）
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）
- 参加用のリンク `?room=CODE` と「リンクをコピー」（2026-10-05）。共通仕様は docs/development/rtdb.md「参加用のリンク」（作りはカギあわせと同じ）。このアプリの入口は app.js 末尾の起動時の処理（`?watch=` → `?room=` → 保存した記録の順）、参加画面は `screen-join`（ヒント `#joinLinkHint`・`openJoinFromLink`）。`?room=` は `connectToRoom` でアドレスから外す
- ボタン階層: 各画面の塗りつぶしの主ボタンは1つ（待合室「はじめる」、押す人「完了」、当てる人「これで決める」、答え合わせ「つぎの回へ」、おしまい「もう一回あそぶ」）。「しめきる」は枠線の副ボタン
- 絵の番号は丸数字（①②…）。お題の一覧には番号を付けない（下記「意図的な逸脱」）

## status 遷移

```
waiting ─はじめる→ stamping ─全員完了／しめきる→ guessing ─これで決める→ reveal ─つぎの回へ→ stamping（次の回）
                                                                              └─結果を見る（5回目）→ end ─もう一回あそぶ→ waiting
stamping / guessing / reveal ─ゲームをやめる（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

- `stamping → guessing` は、最後に「完了」を押した押す人の transaction（全員そろった判定と同じ transaction）か、ホストの「しめきる」が行う
- `guessing → reveal` は当てる人かホスト。それ以外の遷移はホストだけ

## Firebase データ構造（Realtime Database）

パス: `stampate_rooms/{roomCode}/`（共通命名規則。セキュリティルール変更不要）

```
stampate_rooms/{roomCode}/
  ├── status:             'waiting' | 'stamping' | 'guessing' | 'reveal' | 'end'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostPlays:          boolean   # 自分もプレイヤーとして参加する（待合室で変更）
  ├── extraTopics:        boolean   # よけいなお題を2つまぜる（待合室で変更）
  ├── hostConnected / hostDisconnectedAt
  ├── createdAt:          ServerValue.TIMESTAMP
  ├── lastGameId:         number    # 最後に始めたゲームの番号（初期値 0）
  ├── usedTopics:         [番号...]  # このルームで配ったお題（使い切ったら空にして最初から）
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  └── game/                          # 「はじめる」で作り、「もう一回あそぶ」「ゲームをやめる」で消す
       ├── id:        number          # lastGameId + 1
       ├── order:     [name...]       # 遊ぶ人の順番（開始時にシャッフルして固定）
       ├── uids:      {name: uid}     # 名前の持ち主（ゲームの間の名前の予約）
       ├── joined:    {name: joinedAt}# 入りなおしたときの参加順
       ├── extra:     boolean         # 開始時の extraTopics を固定
       ├── round:     1〜5
       ├── captain:   name            # 当てる人
       ├── topics:    {name: 番号}     # 押す人のお題（TOPICS の番号）
       ├── decoys:    [番号, 番号]     # よけいなお題（extra のときだけ）
       ├── sheets/{name}: { o: 0〜3, s: [{k, x, y, r}...], done: boolean }
       │                               # o 紙の向き（90度ずつ）、k 形 0〜3、x 0〜600、y 0〜800、r 向き 0〜7（45度ずつ）
       ├── slots:     [name...]       # 当てる番の絵の並び（スタンプのある絵だけ、まぜる）
       ├── choices:   [番号...]        # お題の一覧（slots のお題＋よけいなお題、まぜる）
       ├── guess:     { p{絵の番号}: お題の一覧の番号 }   # 当てる人の選び途中（配列にならないよう p を付ける）
       ├── result:    { ok, total }   # その回の答え合わせ
       ├── misses:    number          # ちがった数の合計
       └── history/r{回}: { captain, ok, total }   # おしまいの画面の一覧
```

- お題はルームに番号だけを置く（TOPICS の並べ替え・途中の削除をしない理由）
- 回が変わると `topics`・`decoys`・`sheets`・`slots`・`choices`・`guess`・`result` を作りなおす。前の回の絵は残さない（おしまいの画面は `history` の数字だけ）
- 読み込むときは、範囲外のスタンプ・壊れた値を読み飛ばし、その回の押せる回数より多いスタンプは数えない（`sheetOf`）

## transaction 設計

すべてルーム全体（`stampate_rooms/{code}`）への `transaction()`。乱数（順番・お題・並び）は transaction の外で作った種から決める（`seededRandom`）。押した時点の `game.id`・`round` を捕まえて、transaction の中で一致を確かめる。ホストの操作は `hostUid` を確かめる。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム |
| 参加 | ゲスト | `waiting`・名前が空いている・ゲスト8人未満 → `players/{name}`。遊んでいる途中は、`game.uids` の持ち主本人（同じ匿名ID）だけが入りなおせる |
| 設定 | ホスト | `waiting` → `hostPlays` / `extraTopics` |
| はじめる | ホスト | `waiting`・遊ぶ人 3〜9人 → `game` を作り、1回目を配る |
| スタンプを押す・1つ戻す・紙を回す | 押す人 | `stamping`・id/round 一致・自分が押す人（uid）・完了していない・押せる回数以内 → `sheets/{自分}` |
| 完了 | 押す人 | 同上・スタンプ1つ以上 → `done: true`。押す人が全員完了なら、同じ transaction で `guessing` へ |
| なおす | 押す人 | 同上・`stamping` のまま → `done: false` |
| ほかのお題にする | 押す人 | 同上・スタンプ0・完了していない → `topics/{自分}` を、ほかのお題・よけいなお題と重ならない番号に |
| しめきる | ホスト | `stamping`・id/round 一致・スタンプのある絵が1枚以上 → `guessing` |
| お題を置く | 当てる人・ホスト | `guessing`・id/round 一致 → `guess`（同じお題がほかの絵にあれば外して移す。同じ絵の同じお題は外す） |
| これで決める | 当てる人・ホスト | 全部の絵に置いてある → `reveal`・`result`・`misses`・`history` |
| つぎの回へ | ホスト | `reveal`・id/round 一致 → 次の回を配る／5回目は `end` |
| もう一回あそぶ | ホスト | `end`・id 一致 → `waiting`・`game: null` |
| ゲームをやめる | ホスト | `waiting` 以外・id 一致 → `waiting`・`game: null` |

- スタンプの操作は `state.busy` で止めない（連続で押せるように）。transaction は SDK が順番に送り、どれも最新の値で押せる回数を確かめる
- 参加・再接続は `warmRoomCache`（先に値を購読）してから transaction する（空のキャッシュで中止されないため）

## 接続・切断・再接続

気持ち当てゲームと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- 押した絵とお題は `game` にあるので、在室が消えても残る。戻ると、同じ絵の続きから押せる
- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す。つながっているのに在室が消えている（古い接続の予約があとから発火した等）ときも3秒に1回まで書き戻す
- 再読み込み: sessionStorage から同じルームに戻る。タブを閉じた子は「ルームに参加する」から同じ名前で入りなおせる（同じブラウザなら匿名IDが同じ）。ほかの人がその名前を使うことはできない（`game.uids` の予約）
- 遊んでいる途中に新しい名前では参加できない（「もうゲームが始まっているよ」）。開始の瞬間に通信が切れていてゲームに入れなかった人は、戻ると見るだけの参加者になり、次の「もう一回あそぶ」から遊べる
- 押す人の通信が切れたら、ホストの画面に「○○さんの接続が切れています。戻るのを待つか、「しめきる」で…」を出す
- 当てる人の通信が切れたら、全員に知らせ、ホストには「声やチャットで答えを聞いて代わりに選んでね」を出す
- ホスト切断中、ゲストには共通のオーバーレイ（2分）を出す。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- 戻るときの人数の上限: 遊んでいるゲームの人（`game.uids` の持ち主）は上限を見ずに戻れる。それ以外（待合室・見るだけの人）は、その間にほかの人でゲストが8人になっていたら戻らず、「このルームはいっぱいだよ」でトップへ戻る（古いタブからの再接続で上限をこえないため。Codex レビュー 2026-10-03 の指摘）

### 既知の制約（v1）

- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る。片方を閉じる・片方で「退出する」と、もう片方がつながっていても在室が消え、最大3秒ほどで書き戻されるまで「接続が切れています」と出る（気持ち当てゲームなどほかのルーム型ゲームと共通の作り。Codex レビュー 2026-10-03 の指摘）。その数秒のあいだにホストが「はじめる」を押すと、その人はゲームに入らない。接続ごとの在室（お絵描き伝言ゲームの sid のような作り）にすれば防げるが、v1 では入れていない

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おしまいの画面では自動削除しない（「もう一回あそぶ」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 「もう一回あそぶ」「ゲームをやめる」で `game`（お題・絵）を消す。ルームを閉じずにタブを閉じた場合は、TTL 後の掃除まで最後のゲームが残る（rtdb.md の共通の制約）

## みんなにみせる画面（画面共有用・見るだけ）

ホストも遊ぶと、ホストの画面には自分のお題が出る。そこでホストは別のタブで「みんなにみせる画面」を開き、それを共有する（気持ち当てゲームと同じ作り）。

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ。クリックの中で同期的に `window.open(..., 'noopener')`）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`（起動時に再接続の記録を消してから入る）
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。値を読むリスナーだけで、players に入らない・切断予約をしない・期限切れのルームも消さない
- **出すもの**: 待合室（参加者・ルームコード）／スタンプを押す（当てる人・進み具合）／当てる（絵・お題の一覧・当てる人の選び途中）／答え合わせ／おしまい
- **出さないもの**: 押す人のお題（答え合わせまで）・押している途中の絵・ルームの操作ボタン
- 見分けやすさ: タブの題名を「みんなにみせる画面 | …」にし、見出しの下に札を出す

### 秘匿情報の扱い（性善説）

- お題は答え合わせまで、押す本人の画面にだけ出す。当てる人・見る人・進行役のホストの画面（DOM）には書かない。DevTools でルームを見れば分かることは、共通のセキュリティ方針どおり許容する
- 押している途中の絵は、押す本人の画面にだけ出す（当てる番になってから全員に出す）

## お題の方針（`TOPICS`）

- 押す人が1人で読むので、**漢字は小学4年までに習う字にとどめる**（それより上の字の語はひらがなで書く。例: しょうぼう車・かんらん車・たんじょう日）。メンターが読み上げると当てる人に聞こえてしまうため
- 4つの形の組み合わせで表せそうな、身近なもの・できごとを中心にする。少し考えがいのあるもの（お月見・魚つり・まほうつかい など）も混ぜる
- 学校・勉強・登校・恋愛・暴力・ホラー・死を連想させるものは入れない。商品名・キャラクター名は入れない
- ルームでは番号で共有するので、**並べ替え・途中の削除はしない。追加は末尾だけ**。重複は content-audit で弾く
- 新しいお題を本体に入れるのはオーナーが決める（ルート AGENTS.md「新規コンテンツの本体投入は人間専任」）。2026-10-03 の初版132語（7分類）はオーナー承認済み

## 意図的な逸脱

- **分割構成の RTDB アプリ**（気持ち当てゲームと同じ）: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は index.html しか見ないので、app.js の `ORPHAN_TTL_MS` と `clearInterval`・`clearTimeout` は rtdb-audit で手確認する
- **お題の一覧に番号を付けない**: 絵に①②…を付けるので、お題にも丸数字を付けると見分けにくい。お題は各自の端末で押して選ぶので、チャットで番号を答える必要もない
- **当てる番の遷移をホスト以外も行う**: 押す人の最後の「完了」が当てる番へ進め、当てる人の「これで決める」が答え合わせへ進める（全員同時に押すゲームのため。お絵描き伝言ゲームの回の進行と同じ考え方）
- **ホストの初期値は進行だけ**（`hostPlays: false`）。ホストも遊ぶと自分のお題がホストの画面に出るため（秘密が絡むゲームの横断決定 2026-10-01 と同じ）
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **遊んでいる途中でも、そのゲームで遊んでいた名前は入りなおせる**（新しい名前は不可）

## 入れない機能

- 点数・順位・個人の成績（だれの絵が伝わったかの集計）。チームのちがった数だけを数える
- 時間制限・自動で進む処理（全員そろったときの当てる番への移行を除く）
- スタンプの大きさ・色の変更、ペンでの描き足し（形と色が決まっていることがこのゲームの面白さのため）
- 前の回の絵の保存・書き出し・ギャラリー
- チャットだけで参加する子の当てる役（押す・当てるは自分の端末で行う）

## メンター向けの心得（画面には出さない）

- 進行だけのときは、ホストの画面を最初から最後まで共有してよい（お題は出ない）。**「自分もプレイヤーとして参加する」をオンにしたときは、ルームバーの「みんなにみせる画面」を開いて、そちらを共有する**。ウィンドウ単位で共有するときは、そのタブを別のウィンドウに切り離してから共有する
- 当てる人が考えている間は、押した人がヒントを言わないように声をかける（原作のルール）。答え合わせでは、押した人に「どう表したの？」と聞くと盛り上がる
- 伝わらなかった絵は、当てる人のせいでも押した人のせいでもない。「そう見えるね」「その発想はなかった」と一緒に面白がる
- 4回目・5回目（2回・1回）は難しい。前の回までに出てきた「この形はこういう意味」をみんなで思い出すように声をかけると、伝わりやすくなる
- 子どもが少ない日（2人）は、メンターも遊ぶ人に入ると3人になって遊べる
- 読めないお題・知らないお題が配られた子には、「ほかのお題にする」を案内する（声に出して読まない）
