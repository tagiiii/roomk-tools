# ばめんカード — アプリ固有仕様

## 目的・使用シーン

- room-K のオンラインメンタリング（1対1）で、メンターが画面共有しながら操作するオフラインツール。1回10〜15分。
- 「場面」をひとつ切りとって話す練習。出来事を整理して語る力を、実話に限定せず、すきな作品や架空の話でも育てる。
- アプリは場面カードと問いを出すだけ。**語られた内容は口頭で完結**し、アプリには何も入力しない・残さない。

## 最重要の設計方針

- **モードは4つ全部同格。実話モード（今日の小さなばめん）を推奨扱いしない。** 並び順・色・大きさで差をつけず、丸数字 ①〜④ を付けるだけにする。
  1. 今日の小さなばめん — 最近の小さな場面をひとつ（「朝、ねこが窓の外にいた」レベルを例示）
  2. 好きな作品のばめん — ゲーム・アニメ・動画・本などの好きな場面
  3. 想像の主人公のばめん — 主人公カード（架空設定）のある日の場面を想像して話す
  4. 今日は話を聞くだけでもOK — メンターが主人公カードで話し、子どもは聞き役
- **語りの上手さを評価する要素を入れない。** タイマー・文字数・採点・枚数カウント・達成表示はすべて禁止。
- パス・引き直しは自由。**入口カード1枚だけ（またはゼロ枚）で終わっても成立する**ことを画面文言でも保証する（「1枚だけで終わってもじゅうぶん」）。
- 入口カードは場面を**描写する**ための軽い問いに限る。**「なんで？」系（理由の追及）は入れない。** 5W1H の詰問トーンにしない。
- **「ばめん」の定義は「写真1枚ぶんのできごと」**。モード選択画面のリード文で一度だけ説明し、比喩の派生語（シャッター・アルバム等）を増やさない。操作文言は素直な動詞を使う。
- **本体画面は「まず（ばめんをひとつ決める）→ つぎに（入口カードで話す）」の2ステップ構造**にし、入口カードが「決めたばめん」に向いた問いであることを見出しと説明文でひも付ける（実機確認で「入口カードが浮いて見える」との指摘への対応）。聞くだけモードでは入口カードを「メンターに聞いてみるカード」として位置づける。
- UI・カード文言は**通常表記（漢字まじり）**（2026-08-06 ユーザー判断で分かち書きから刷新。ルート AGENTS.md「表記トーン」参照。読めない子にはメンターが読み上げる。「ばめん」「といかけ」などかな書きが自然な語はそのまま）。
- メンター向けの心得・注意書きは画面に出さない（本ファイルに書く）。「メンターが話すよ」のような子ども向けのモード説明は可。

## 技術

- `index.html` + `app.js` + `style.css` の talk-card 型オフライン構成。Firebase 不使用。
- **永続化 API（localStorage / sessionStorage / IndexedDB / Cookie）・記録・保存・JSON 入出力は一切呼ばない。** テキスト入力欄も作らない。
- 共有 `../shared/css/design-system.css` と Material Symbols Rounded を使う。絵文字は禁止（主人公カードのアイコンも Material Symbols から選ぶ）。
- CSS は `bm-` 接頭辞 + BEM。`.screen` / `.active` と `screen-xxx` 命名を使う。600px 以下でレスポンシブ。
- 状態は `const state = { currentScreen, modeId, hero, entryCard }` にまとめる。
- 動的 HTML への文字列挿入は静的データ由来でも必ず `esc()` を通す。
- カードは `shuffle()`（utils.js）でプール化し、使い切ったら補充。引き直し直後に同じカードが出ないようにする。

## 画面フロー

```text
screen-mode（モード選択 4択・丸数字付き。リード文で「ばめん＝写真1まいぶんの できごと」を説明）
  → screen-talk（モード別の本体画面。「まず / つぎに」の2ステップ構造）
      [まず] ばめんを ひとつ きめる
      - 今日の小さなばめん: 小ささの例示3つ
      - 好きな作品のばめん: 例示3つ
      - 想像の主人公のばめん: 主人公カード（自動で1枚・引き直し自由）
      - きくだけ: 主人公カード（メンターが話す）
      [つぎに] 入口カードを ひいて、ばめんを 話す
      - きくだけモードのみ「入口カードで、メンターに きいてみる」
  → 「モードを えらびなおす」でいつでも screen-mode へ
```

- 入口カードは「引く」を押すまで表示しない（引かない選択を保証する）。
- 画面切り替えの演出は 0.22s のフェードのみ。`prefers-reduced-motion` で無効化。

## コンテンツデータ

- `HEROES`（そうぞうの主人公カード）: 24枚。`{ icon, name }`。**ユーモラスで安全な架空設定のみ**（例: 雲の上でパンやをやってる人）。
- `ENTRY_CARDS`（話の入口カード）: 18問。場面を描写するための軽い問いのみ。
- 追加・変更時の禁止チェック:
  - 学校・勉強・登校の場面例
  - 家族関係に踏み込む問い（「家でどうだった？」等）
  - 嫌だった場面・失敗談を促す問い
  - 「なんで？」「どうして？」系の理由追及
  - 恋愛、怖い話・ホラー・死、暴力
  - 語りの評価・比較につながる文言

## 入れない機能（意図的に未実装）

- localStorage / sessionStorage / IndexedDB / Cookie、Firebase、外部 API、JSON 入出力。
- 語られた内容を入力・記録する欄（メモ欄含む）。
- タイマー、文字数、採点、スコア、枚数カウント、達成率、バッジ、ランキング。
- 実話モードへの誘導（デフォルト選択・おすすめ表示・並び順の特別扱い）。

## アクセシビリティ

- モード・カード操作はすべて `<button>`。Tab / Enter / Space で操作でき、`:focus-visible` を明確にする。タップターゲットは最小 44×44px。
- モード4択には規約どおり ①〜④ の丸数字を付け、`aria-label` で番号と説明を読み上げる（画面共有越しに「2番」と答えられるように）。
- 入口カード・主人公カードは1枚ずつの提示のため番号なし。

## コンテンツガイドライン例外

- なし（共通ガイドラインに全面準拠）。
