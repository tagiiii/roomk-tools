# ことばガチャ 仕様書

## 目的・使用シーン
ひとこと（助詞）を入れ替えると、文の「空気」がどう変わるかを**クイズ形式**で遊ぶ言葉アプリ。
メンターが画面共有しながら、参加者と「どれが合う？」を一緒に当てにいく対話のきっかけに使う。

**文法を学ぶアプリではなく、言い方で空気が変わるのを遊ぶアプリ**という振り切りが企画の芯。
「正解」は文法の正しさではなく **「空気にぴったり合うのはどれか」** を指す。
UI上は「助詞」「てにをは」などの文法用語を一切出さない。

| ロール | 説明 |
|--------|------|
| 操作者 | メンター（参加者全員の総意で1つ選んでクリック） |
| 閲覧者 | 生徒（画面共有で閲覧・声で予想を出し合う） |

## 技術スタック
- 単一アプリ（Firebase 不要・ログイン不要）
- 共通デザインシステムを使用
- CSS 接頭辞: `.kg-`

## 画面構成
```
[TOP 画面]
  タイトル「ことばガチャ」/ サブ「ぴったりな一言、あててみよう」
  → はじめる

[出題画面]
  右上に控えめな進捗 (1 / 10)
  お題の「空気」（ヒント文）を大きく表示
  完成文カード（2〜3枚、それぞれ別の助詞入り）
  クリックで答え合わせ
    - 正解カードを緑でハイライト
    - 不正解を選んだ場合は赤枠
    - 全候補のヒント文も同時に開示（空気の違いを並べて味わう）
  → つぎのお題 / TOPにもどる

[おしまい画面]
  10問ぜんぶ見たよ
  「10問中 X問あたったよ」
  → もう一回（シャッフルして再スタート）/ TOPにもどる
```

## お題リスト
`app.js` 内の `const QUESTIONS = [...]`（30問）。初版10問 + 監査済み拡充20問。
追加時は既存 template と助詞組み合わせの正規化重複を避け、候補ごとの「空気」が明確に分かれるものだけを末尾へ追加する。

### お題作成ガイドライン（重要）
- **文法用語は UI に出さない**（内部の変数名として `particle` は使ってよい）
- クイズとして成立させるため、**候補ごとにヒント文（空気の感じ）がはっきり区別できる**ことを優先
- どの選択肢も文として**自然に成立**することを維持（文法の正誤で判定しない）
- ヒント文は感覚語のみ（「〜な感じ」「〜っぽい」）、10〜18字程度
- お題は「食べ物」「気持ち」「人との関係」などトピックを分散させる
- `こそ` `って` `で / に` は初版では不採用（固い／正誤寄りになりやすい）

## 特有のルール・制約
- お題ごとに候補（助詞）は**固定**。ランダムに混ぜない
- **出題のたびに、どの候補の「空気」を正解にするかをランダム選出**（同じお題でも毎回問われる空気が変わる）
- 選択肢（完成文カード）の表示順もお題ごとにシャッフル
- 1問につき回答は1回。答え合わせ後は全候補のヒント文が開示される
- 完成文中の助詞は `--color-accent` で色付け
- お題は起動時に `shuffle()` でランダム順
- セッション中の正解数をカウントし、おしまい画面に表示
