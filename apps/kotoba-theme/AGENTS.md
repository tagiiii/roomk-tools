# コトバのテーマクイズ 仕様書

## 目的・使用シーン

「コトバであそぼ！」（国語ワークショップ・週1回45分）の冒頭にある
**「きょうのコトバのテーマ」スロット（5〜10分）**を担うオフラインアプリ。
その日のゲームで使う「コトバのテーマ」を3択ミニクイズで先に見せ、最後に
**「きょうのゲームでつかってみよう」**でその日のゲームへ橋渡しする。

- 正本: [docs/requirements.md](../../docs/requirements.md)（第6行で本アプリの追加を規定。第7.1章の
  「テーマ紹介は口頭＋あそびかたモーダルの画面共有」という記述を本アプリが上書きする）
- 対象: 小学校中学年〜中学生。`data-scenes="kotoba"`
- 時間: 1テーマあたり4問で5分程度（テーマ紹介スロットは5〜10分）

| ロール | 説明 |
|--------|------|
| 操作者 | ゲームマスター（支援者）。画面共有し、テーマをえらび、問題をチャットにコピーし、答えを出す |
| 閲覧者 | 子ども。Metalife のチャットに「②」のように番号で答える（声でもよい） |

利用形態は `apps/quiz/`（クイズパック）と同じ **画面共有型のオフラインクイズ**。
違いは「点数を出さない」「1テーマ=4問で必ず止まる」「最後にゲームへ送り出す」の3点。

## テーマ術スタック

```
apps/kotoba-theme/
├── AGENTS.md    # この仕様書
├── index.html   # マークアップ（4画面ぶん）
├── app.js       # ESモジュール。画面遷移とレンダリング
├── style.css    # アプリ固有スタイル
└── waza.js      # テーマデータ（通常スクリプト。window.KotobaWaza に載せる）
```

- **オフライン**（Firebase 不要・ログイン不要・保存なし）
- `../shared/css/design-system.css` のトークン・`btn` / `card` / `badge` を再利用
- `../shared/js/utils.js` から `copyToClipboard` / `popIn` / `shuffle` を import
  （`shuffle` は ES モジュールの named export。`window.shuffle` としては生えていない）
- `stats.js`（`?v=1` defer・howto.js の直前）／`howto.js`（title は **「つかいかた」**。進行補助ツールのため）
- CSS 接頭辞: **`kw-`**（BEM）
- viewport に `maximum-scale=1` は付けない（非 RTDB アプリ。lint VIEWPORT-2）
- 表記は**通常表記（漢字まじり）**。絵文字は使わずアイコンは Material Symbols Rounded

### waza.js の読み込み順

`waza.js` は `window.KotobaWaza` に代入するだけの**通常スクリプト**で、`index.html` では
`app.js`（`type="module"` = defer 相当）より前に置く。これで app.js の評価時には必ずデータが揃う。

```html
<script src="waza.js"></script>
<script type="module" src="app.js"></script>
```

## 画面構成・フロー

```
TOP（screen-top / 入口は2つ）
  タイトル → 説明1文 → 注意点2つ
  ┌ 主: 「きょうのゲームからえらぶ」= ゲームカード（ゲーム名＋「合うテーマ n個」）
  └ 副: 「テーマのいちらんからえらぶ」= <details> で折りたたんだグループ見出し＋テーマチップ
  → 保存しない旨（TOP に主ボタンは置かない）
    ↓（ゲームカードを押した場合）
ゲーム別のテーマえらび（screen-game / 逆引き）
  「きょうのゲーム」＋ゲーム名＋「このゲームに合うテーマが n個あります。」
  テーマカード（テーマ名＋label＋「このゲームでのつかいどころ」= 当該ゲームの hint）
  「ゲームえらびにもどる」（弱ボタン。arrow_back アイコン付き）
    ↓（テーマチップ／テーマカードのどちらを押しても、ここから先は同じ）
クイズ（screen-quiz）… 1問ずつ・level 昇順（1→2→2→3）
  テーマ名バッジ／「n問目 / 4」
  問題文（大きく）＋選択肢 ①②③（押せない表示専用）
  「問題をチャットにコピー」→ Metalife に貼る
  「答えを見る」→ 正解ハイライト＋「答え」カード（答え＋解説）
  「次へ」→ 次の問題。最終問はラベルが「まとめを見る」に変わる
  「テーマえらびにもどる」（弱ボタン。いつでも中断できる）
    ↓
まとめ（screen-summary / 橋渡し）
  テーマ名＋label＋catch を大きく表示
  「きょうのゲームでつかってみよう」= games のカード（ゲーム名＋つかいどころ1行／`../{app}/` へ同タブ遷移）
  「TOPにもどる」（弱ボタン）
```

- 画面切替は `showScreen('top'|'game'|'quiz'|'summary')`。`hidden` 属性の付け外しで行い、
  切り替えのたびに `window.scrollTo({ top: 0 })` する（画面共有中に前の画面のスクロール位置を残さない）
- 選択肢は `<li>`（`.kw-choice`）で**クリックできない**。押して正誤判定が出る作りにしない
- 答えを出したときは正解だけを緑で強調し、ほかは薄くするだけ（赤＝まちがいの色は使わない）
- `state` は `{ wazaId, gameApp, questions, index, revealed }`。
  `localStorage` / `sessionStorage` は使わない（`questions` も画面を離れれば消える）
- クイズ画面の「テーマえらびにもどる」は**入ってきた入口に戻す**。ゲームから入ったなら
  そのゲームのテーマえらび（`state.gameApp`）、テーマのいちらんから入ったなら TOP。
  まとめ画面の「TOPにもどる」はラベルどおり常に TOP

### ゲームからの逆引き（TOP の主の入口）

「どのゲームでどのクイズをすればいいのかわからない」への答え。
**ゲームとテーマの対応表は持たない。`wazas[].games` を実行時に走査して導出する**
（`buildGameIndex()`）。テーマを1つ足せばゲーム側の一覧にも自動で載る＝二重管理をしない。

| 表示 | どこから来るか |
|---|---|
| ゲーム名 | `games[].name`（最初に見つかったものを採用） |
| 「合うテーマ n個」 | その app を `games[]` に持つテーマの件数 |
| 「このゲームでのつかいどころ」 | 当該テーマの `games[]` のうち**このゲームの** `hint` |

- 並び順は `app.js` の `GAME_ORDER` を優先し、**そこに無い app は末尾（出現順）**。
  waza.js に新しいゲームが登場しても落ちない。並べたい位置があるときだけ `GAME_ORDER` に足す
- 1つのゲームに紐づくテーマの並びは `wazas` の定義順（＝グループ順）
- `games` が1件も無いデータのときは、ゲーム入口ごと隠してテーマのいちらんを開いた状態にする

### 橋渡し先の原則（2026-08-10 オーナーFB）

**`games[]` に入れてよいのは「遊び」のツールだけ。クイズ・ドリル・パズルの
「問題を解く」形式（quiz・kotoba-shuffle 等）には橋渡ししない。**
テーマクイズ自体が3択問題なので、直後にまた問題形式が続くと飽きる
（「3択問題の後にゲーム性のないコンテンツは避けたい」）。
このFBで riyuu→quiz と kouzou/junjo→kotoba-shuffle の橋渡しを削除し、
kouzou はコトバペア「文のまえとうしろ」へ差し替えた。
各テーマは必ず1件以上の「遊び」への橋渡しを持つこと。

### 問題の抽選（リピーター対策）

「一回使うと次回以降同じクイズを答える人が出てくる」への答え。
**クイズを始めるたびに 4問を引き直す**（`selectQuestions()`）。保存しないので
「もういちど」でも再入室でも中身が変わる。

- カーブは **level 1 から1問・level 2 から2問・level 3 から1問**（`LEVEL_PLAN`）。
  出題は **level 昇順（1→2→2→3）**＝入口 → 少し迷う → 核心、の順に上がる
- 各バケットは `shared/js/utils.js` の `shuffle`（Fisher-Yates）でシャッフルしてから取る。
  同じ level の中の順番も毎回変わる
- **足りないバケットは level が近いバケットから補い、合計4問を必ず満たす**（`takeNearest()`）。
  補充が起きても並びは level 昇順のまま
- **後方互換**: `questions` が **4問以下**、または **level が1問でも欠けている／1〜3以外**のテーマは、
  従来どおり**配列順に先頭から最大4問**（シャッフルしない）。level なしの旧データでも壊れない
- 進行表示「n問目 / 4」は実際の出題数から描く（3問しかないテーマなら「/ 3」になる）

### チャットにコピーする文字列

1行目が問題文、以降が `①②③`。**「答え」「正解」などの語は入れない**（貼った時点で答えが漏れないように）。

```
「とても大きい」を、ひとことで言いかえるなら？
① 巨大
② 小型
③ 大量
```

## waza.js スキーマと追加方法

```js
window.KotobaWaza = {
  groups: [                                  // TOP の見出し。この配列順に並ぶ
    { id: 'hikidashi', name: 'ことばのひきだし' },
    { id: 'bun',       name: '文のしくみ' },
    { id: 'tsutaeru',  name: '伝えるわざ' },
    { id: 'yomitoku',  name: 'くらべる・読みとる' },
  ],
  wazas: [
    {
      id: 'goi',                             // 一意。stats の項目名 `waza-{id}` になる
      name: 'ことばのひきだし',                // 子どもに見せるテーマ名（チップ・まとめの見出し）
      label: '語彙',                          // 支援者向けの正式名（チップ内とまとめに小さく出る。省略可）
      group: 'hikidashi',                     // groups[].id のどれか
      catch: '同じことでも、言い方はひとつじゃない。',  // まとめ画面の一言
      questions: [                            // 8問（level1×2・level2×4・level3×2）
        {
          q: '問題文',
          choices: ['①の文', '②の文', '③の文'],  // 原則3つ（表示順は固定。シャッフルしない）
          answerIndex: 0,                     // 正解の index
          explanation: '解説1〜3文',
          level: 1,                           // 1=入口 / 2=少し迷う / 3=核心。抽選のバケット
        },
      ],
      games: [                                // まとめ画面のカード＋TOP のゲーム逆引きの元データ
        { app: 'kotoba-pair', name: 'コトバペア', hint: '「にてることば」パックで、意味でつながる2枚を探そう' },
      ],
    },
  ],
};
```

### 追加・差し替えのしかた

1. `wazas` に1件足す（`group` は `groups[].id` のいずれか）。**app.js の変更は不要**
2. `questions` は **1テーマ8問（level1×2・level2×4・level3×2）** が標準。ここから毎回4問を引く。
   出題数そのもの（4問）は `app.js` の `LEVEL_PLAN` が決めるので、**`index.html` の説明文
   「4問・5分くらい」と食い違わせたいときは `LEVEL_PLAN` と説明文の両方**を直す
3. `games[].app` は `apps/{app}/` のフォルダ名。リンクは `../{app}/`。存在しないフォルダを書くと 404 になる。
   **TOP のゲーム一覧もここから導出される**ので、`name` はゲームごとに統一し、`hint` は
   「そのテーマをこのゲームでどう使うか」を1行で書く（TOP の逆引き画面にそのまま出る）
4. `choices` は `answerIndex` を含めて**順番が固定**。解説で「②や③をえらんだ人も」のように
   番号に触れてよい（並びが変わらないことが前提）
5. `level` は**同じテーマの8問すべてに付ける**。1問でも欠けるとそのテーマだけ後方互換の
   「配列順に先頭4問」に落ちる（壊れはしないが、抽選が効かなくなる）
6. 追加後は `node --check apps/kotoba-theme/waza.js` と `bash scripts/lint.sh`

### 現在のデータ状況

`waza.js` は 4グループ・17テーマ。**`level` 付き（1テーマ8問）への増補は統合担当が
`waza.js` 1ファイルの置きかえで行う**。`app.js` はどちらの形でも動く
（level なし・4問なら従来どおり配列順、level あり・5問以上なら 1-2-1 の抽選）。

## 設計思想

| 決めごと | 理由 |
|---|---|
| **正解数を数えない・成績を出さない** | テーマを知るのが目的でテストではない。カウンタ自体を持たない（`state` にスコアがない） |
| **1テーマ=4問で必ず止まる** | 45分枠の冒頭5〜10分に収める。「もっと解く」導線を作らず、ゲームに時間を渡す |
| **選択肢は押せない** | 押した瞬間に正誤が出ると「当てるゲーム」になる。答えるのはチャット、出すのは支援者 |
| **テーマ名は子ども向け表現、`label` に正式名** | 「語彙」ではなく「ことばのひきだし」で入り、支援者は `label` で何のテーマか把握できる |
| **まとめ＝橋渡し画面** | クイズの終わりを「結果発表」にせず、その日のゲームの入口にする |
| **保存しない** | 答えも履歴も残さない。回数だけ stats.js で匿名記録（`waza-{id}`） |
| 「勉強」「テスト」「不正解」を画面に出さない | room-K の非評価思想（AGENTS.md コンテンツガイドライン） |
| **ゲームからの逆引きを主の入口にする** | 支援者が最初に決めているのは「きょうやるゲーム」。テーマ名から入らせると選べない（2026-08-10 オーナー実機フィードバック） |
| **テーマのいちらんは残すが折りたたむ** | ゲームを決めていないときの経路を消さない。ただし主の入口と同格には見せない |
| **毎回4問を引き直す** | 同じ子が2回目に同じ問題に当たると「知ってる」で終わる（同上のフィードバック）。level のカーブは保つので難度感は変わらない |

- テーマが1つも属していないグループは、見出しごと表示しない（空グループが並ばないように）
- TOP に主ボタンを置かないのは、ゲームカードもテーマチップも「同格の選択肢群」だから
  （AGENTS.md「ボタン階層の定石」の例外条項）。逆引き画面も同じ（テーマカード＋弱ボタンのみ）。
  クイズ画面の主ボタンは「答えを見る」→「次へ」と入れ替わるので、常に1画面1主ボタンになる

## メンター向けの心得（画面には出さない。ここにだけ書く）

- **テーマえらびは「きょうのゲームからえらぶ」で入る。** 先にゲームを決めていれば、そのゲームで
  生きるテーマだけが「つかいどころ」つきで並ぶ。迷ったら一番上のテーマでよい
- **全問やらなくていい。** 場があたたまったら「テーマえらびにもどる」で切り上げてゲームに移ってよい。
  4問は上限であって、こなすノルマではない
- **2回目でも同じ問題にはならない。** 4問は毎回引き直している。同じテーマをちがう回に使ってよいし、
  「前と同じ問題だ」と言われたら偶然（同じ level から引き直しているため似た手ざわりにはなる）
- **チャットの答えは番号でも声でもOK。** 「②」だけの返事も、言葉での説明も同じように受ける。
  無反応でも待ちすぎない（答えが出そろわなくても「答えを見る」を押してよい）
- **誰が当てたかを数えない・言わない。** 「①が多かったね」のように答えの分布に触れるのはよいが、
  人と正解を結びつけない
- **まちがいの選択肢を拾う。** 解説は「そうえらぶ人も多い」トーンで書いてある。
  そこを読み上げると、外した子が置いていかれない
- **解説を講義にしない。** 1〜3文を読んだら次へ。掘り下げたくなったらゲーム中の会話に回す
- **まとめ画面は映したままでよい。** catch を出しっぱなしにして、その裏でゲームのルームを作る。
  ゲームカードのリンクは同タブ遷移なので、押すとこの画面から離れる（戻るのはブラウザバック）
- **テーマ名は言い換えて構わない。** 「きょうは、ことばのひきだしの日」くらいの軽さで導入し、
  「語彙」という語は無理に使わない

## 統合担当が行う横断更新

- `apps/index.html` にカード追加（`data-scenes="kotoba"`）
- `apps/updates.json` 先頭に `type: "new"` エントリ
- `apps/guide/` のゲームえらび早見表に1行追加
- **`waza.js` を `level` 付きデータ（1テーマ8問 = level1×2・level2×4・level3×2）に差し替え。
  `waza.js` がデータの正本で、差し替えはこの1ファイルで完結する**（`app.js` は変更不要）。
  差し替え後は TOP のゲームカードの「合うテーマ n個」が増減するので、
  `GAME_ORDER` に無いゲーム（末尾に回る）が出ていないか一度だけ目視する
- `scripts/lint.sh` への追加は**不要**（非 RTDB アプリのため `RTDB_HTML_FILES` に入れない）
