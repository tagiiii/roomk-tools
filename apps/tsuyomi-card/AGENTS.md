# つよみカード 仕様書

## 目的・使用シーン

不登校の小中学生との1対1オンライン面談で使う「自分の強みさがし」カードワーク。
強みカードを1枚ずつ提示し、「こういうところ、ありそう？」の問いかけに
「ある」「ない」「どちらでもない」の3択で答えていく。最後に「ある」と答えた
カードをながめながらメンターと話し、自己理解と関係構築につなげる。
所要時間 10〜15分（会話込み）。

| ロール | 説明 |
|--------|------|
| 操作者 | メンター（子どもの指示で代理操作） |
| 閲覧者 | 子ども（Zoom/Meet等の画面共有で閲覧） |

**2026-08-06 刷新**: 旧版は42枚一覧から選ぶ方式＋メンター選択ターン＋JSON保存だったが、
「一覧がいきなり出て選びづらい」「〜かも の語尾が幼い」というフィードバックを受けて
1枚ずつ提示方式に作り直した（すきタイプチェックの画面フローを踏襲。診断化はしない）。
同日の追いフィードバックで、答え方を「もっておく/次へ」の2択から
**「ある」「ない」「どちらでもない」の3択**に変更（「ありそう？」への素直な答え方に
合わせるユーザー判断）。カード・ボタンにアイコンを追加し、カード文字を拡大、
サブアクションを控えめなテキストボタンにした。

## 技術スタック

- オフラインアプリ（Firebase不要・ログイン不要・永続化なし。リロードで最初に戻る）
- 分割ファイル構成: `index.html` + `app.js` + `style.css`（talk-card / suki-type-check 型）
- 共通デザインシステム（design-system.css）+ Material Symbols Rounded
- 外部ライブラリなし

## 画面構成・フロー

```
TOP → CARD（1枚ずつ提示）→ SUMMARY（まとめ）
```

- TOP: パネル1枚構成（suki-type-check の start と同型）。タイトル＋説明＋
  注意3点（正解はない／どちらでもないOK／今日はここまでOK）＋「はじめる」
  （主ボタン1つだけ）＋「保存されない」旨。あそびかたのインライン展開は持たず、
  説明は howto.js のモーダル（つかいかた）に一本化する
- CARD: 進捗「n / 20」＋見出し「こういうところ、ありそう？」＋カード1枚
  （アイコン＋大きめの本文）＋答えの3択「ある」（○）「ない」（✕）
  「どちらでもない」（△）＋控えめなサブアクション「ひとつ前にもどる」
  （1枚目は disabled）「今日はここまで」（常設）
- 答えを押すと自動で次のカードへ。20枚答え終わるか「今日はここまで」で SUMMARY へ
- 「ひとつ前にもどる」で前のカードに戻れる。前の答えはボタンの選択表示
  （アクセント色反転＋aria-pressed）で示し、押し直せば上書きされる
- SUMMARY: 「ある」と答えたカードの一覧＋アクション3つ。ボタンは
  **塗り→枠線→テキストの3段階**（主アクションは1画面に1つだけ）:
  「結果をコピー」（btn-primary）＋「カードのつづきを見る」（btn-secondary・
  未消化カードがあるときだけ表示）＋「最初にもどる」（.ty-quiet-btn・全リセットで TOP へ）

## カードデータ

20枚。`app.js` の `CARD_DEFS` 配列（`text` + `icon`）を直接編集する。
`icon` は Material Symbols Rounded の名前で、カード内容を表すものを1枚ずつ割り当てる。
系統（人とのかかわり／気づく・感じる／調べる・不思議がる／つくる・表現する／
自分のペース／動く・続ける／考えて動く）が連続しないよう混ぜた**固定順**
（画面共有での読み上げ再現性のため、シャッフルはしない）。

### カード文言ガイドライン（必ず守る）

- **カードは素の記述形**（例:「細かいところに気づく」）。「あなたは〇〇だ」という
  宣告文は禁止。非断定は画面の問いかけ「こういうところ、ありそう？」に
  本人が3択で答える構造が担保する
- **通常表記（漢字使用）**。読めない子にはメンターが読み上げる運用
- 学校・勉強文脈の強み（成績・テスト・発表・宿題など）は禁止
- 他人との比較（「〜より」「だれよりも」「いちばん」）は禁止
- 「ときどき顔を出す力」のトーン。毎回出せることを前提にしない

## 心理的安全設計（このツールの核）

- **3択は同格**。「どちらでもない」を小さくしたり色を落としたりしない
  （suki-type-check の5件法と同思想。まよったとき・答えたくないときの受け皿で、
  パスは別に置かない）
- **「ない」と答えたカードの一覧を作らない・表示しない・数えない**。
  まとめに並ぶのは「ある」だけ（「ない」の集まり＝弱みリスト、という見え方を作らない）
- **「ある」の枚数に上限なし・枚数を数え上げない・比較しない**
- **全部答えることを目標にしない**。「今日はここまで」は常設で、途中終了を
  正式な終わり方として扱う（とがめる文言を出さない）
- **「ある」0枚も正式な答え**。まとめ画面で「今日は「ある」を選ばなかった」＋
  尊重の一言「「ある」がない日があってもいい。」を表示する（なぐさめ・分析はしない）
- 一致判定・祝福演出・スコア・診断・タイプ分けをしない

## 結果コピー（JSON保存の後継）

Metalifeチャット貼り付け用のプレーンテキスト（絵文字なし）。

```text
つよみカード
・細かいところに気づく
・自分のペースを持っている
```

- 「ある」0枚のときは「今日は「ある」を選ばなかった」の1行
- コピー失敗時は**無反応にせず**エラートーストを出す（監査提案11の教訓）。
  連打（コピー完了表示のリセット待ち＝`copyBusy`）はエラー扱いにしない

## stats（回数のみ・内容は送らない）

- `open`: stats.js の自動計上
- `start`: 「はじめる」押下
- `finish`: まとめ画面の初回表示（1プレイ1回。`state.counted` でガード）

## CSS命名規則

接頭辞: `.ty-`（tsuyomi-card。`tc-` は talk-card が使用済みのため不可）

| クラス | 用途 |
|--------|------|
| `.ty-stage` / `.ty-stage__icon` / `.ty-stage__text` | カード1枚の提示枠・アイコン・本文（本文が tabindex="-1" のフォーカス先） |
| `.ty-choice-btn` | 「ある」「ない」「どちらでもない」の同格3択ボタン（data-answer 属性で識別） |
| `.ty-choice-btn--active` | もどってきたカードで前の答えを示す状態（アクセント色反転） |
| `.ty-quiet-btn` | 「ひとつ前にもどる」「今日はここまで」の控えめなテキストボタン |
| `.ty-progress` | 進捗「n / 20」 |
| `.ty-summary-card` / `.ty-summary-card__icon` | まとめ画面のカード表示とアイコン |

## アクセシビリティ

- カードを描画したら `.ty-stage__text`（`tabindex="-1"`）にフォーカスを移す。
  `showScreen()` を描画・focus より先に呼ぶこと（非表示要素への focus() は効かない）
- 3択ボタンは `aria-pressed` で現在の答えを示す。選択状態はアクセント色の
  反転（背景＋文字色）で表し、細い枠色の変化だけに頼らない
- 3択のアイコンは ○（radio_button_unchecked）✕（close）△（change_history）の
  日本の慣習に合わせる
- タップターゲットは最小 44×44px、`:focus-visible` を明確にする
- `prefers-reduced-motion` でカード切り替えアニメーションを無効化する

## メンター向けの心得（画面には出さない）

- カードは漢字表記。読むのが難しそうなら、メンターが読み上げて伝える
- メンターの選択ターンは廃止した。子どもが答えているのを見ながら
  「こういうところもありそうじゃない？」とその場の言葉で返すほうが自然に働く
- 「ない」「どちらでもない」が続いても急かさない・問い直さない。
  「ある」0枚で終わってもそのまま受け取る

## 入れない機能（意図的に未実装）

- メンターの選択ターン（口頭での関わりに一本化。2026-08-06 廃止）
- JSON入出力・fileMarker（2026-08-06 廃止。記録はチャットコピーで足りる）
- 「ない」と答えたカードの一覧表示（弱みリスト化になるため）
- 「ある」の枚数上限・枚数表示・両者比較
- 診断・タイプ判定・スコア・祝福演出・ランキング
- カードのシャッフル・問数の可変
- 永続化（localStorage 含む）・履歴・`beforeunload` 警告

## 既存ガイドラインからの例外

- **通常表記（漢字使用）**: ひらがな中心・分かち書きの他アプリと異なり、
  カード・UI文言とも通常表記にする（幼い印象を避けるためのユーザー判断、2026-08-06）。
  読めない子にはメンターが読み上げる。howto.js の文言も同トーン
