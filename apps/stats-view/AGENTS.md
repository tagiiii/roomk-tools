# 利用状況ダッシュボード 仕様書

## 目的・使用シーン

**開発者専用**の閲覧ページ。`shared/js/stats.js` が貯めた利用回数（匿名・回数のみ）を月単位で眺め、
「どのアプリ・どのコンテンツが使われているか」を改善判断の材料にする。

| ロール | 説明 |
|--------|------|
| 想定利用者 | 開発者（本人）のみ |
| 開き方 | URL 直打ち（`.../stats-view/`）。どこからもリンクしていない |
| 子ども・メンター | 利用対象外。画面共有で見せる想定はない |

**このページは子ども向けの導線に一切載せない。** ポータル・早見表・チャットで配る URL に含めない。
（AGENTS.md「stats.js」の「計測値やランキングを子ども向け画面に表示しない」規約との関係は下記「意図的な逸脱」参照）

## 技術スタック

- ファイル構成: `index.html` + `app.js` + `style.css`（分割構成。otona-talk と同パターン）
- Firebase モジュール版 SDK 10.14.1 を CDN から `import`。Realtime Database + 匿名認証
  - `signInAnonymously()` の完了を **await してから** 読む
  - Firebase アプリは名前付き（`roomk-stats-view`）で初期化する
- **読み取り専用。** `set` / `update` / `remove` / `transaction` は一切書かない
- グラフライブラリは使わない（横棒は CSS の `width` だけ）
- CSS 接頭辞: `.sv-`（BEM）

## データ構造（読み先）

`stats.js` が書き込む Realtime Database のパスをそのまま読む。**正本は `apps/shared/js/stats.js`。**

```
stats/{アプリ名}/{YYYY-MM}/{項目}   … 回数（数値）
```

| 項目の例 | 意味 |
|---|---|
| `open` | アプリの起動回数（stats.js の読み込みで自動加算） |
| `pack-{id}` | quiz のパック選択 |
| `session-{id}` | kotoba-asobo のセッション開始 |

- アプリ名は `stats.js` の `detectAppName()` が URL パスから決める。ポータルは `portal`
- 記録されているのは回数のみ。UID・ニックネーム・入力内容は存在しない

### 読み方の制約（重要）

- セキュリティルール（`$app_rooms/$roomId` の2階層ワイルドカード）上、**`stats` 直下の一括 get は Permission denied になる。**
  必ず **アプリごとに** `get(ref(db, 'stats/' + app))` で読む
- データがないアプリは `null` が返るだけ。**正常系として扱う**（エラー表示しない）
- 1件も読めなかったときだけ認証・通信の失敗としてエラー表示する

## アプリ一覧の取得（ハードコードしない）

`fetch('../index.html')` → `DOMParser` → `a.app-card[href]` の `href` 先頭セグメントをフォルダ名として集め、
`portal`（`EXTRA_APPS`）を足す。**アプリ名の固定リストは持たない。**

- ポータル（`apps/index.html`）がアプリ一覧の正本。新アプリ追加時にこのページの変更は不要
- ポータルのカードのマークアップ（`<a class="app-card" href="{folder}/">`）を変えるときは、
  ここのセレクタも合わせて確認する
- フォルダ名は `/^[A-Za-z0-9_-]+$/` で検証してからパスに連結する（`.` `#` `$` `[` `]` を混ぜない）
- ポータルに載っていないアプリ（改名前のリダイレクトスタブなど）の数値は表示されない。
  必要になったら `EXTRA_APPS` に足す

## 画面構成・フロー

```
[読み込み]
  ポータルからアプリ一覧を取得 ＋ 匿名認証 → アプリごとに stats を get
  → 見つかった月キー（YYYY-MM）を降順に並べ、最新月を選択

[本体]
  選択月のアプリ別 open 回数を多い順にテーブル表示（アプリ名 / 起動 / 最大値との比の横棒）

[行を押す]
  → そのアプリの全項目（open, pack-*, session-* など）を回数付きで展開（open が先頭、以降は回数の多い順）

[月セレクタ]
  → 選択月を切り替えて再描画（DB は読み直さない）

[再読み込み]
  → 取得からやり直す
```

## 状態表示

| 状態 | 表示 |
|---|---|
| 読み込み中 | `.spinner` + 「読み込み中…」 |
| 月キーがゼロ | 「まだデータがありません」 |
| 選択月にデータなし | 「{月}のデータはありません」（月セレクタは残す） |
| 失敗 | 日本語の固定文言（`MSG`）＋「もう一度読み込む」。**生の英語エラーは出さない** |

## 意図的な逸脱（共通規約から外している点）

開発者専用の閲覧ページであり、子ども・メンターの導線に載せないため、以下を **意図的に** 行っていない。

| 共通規約 | このアプリの扱い | 理由 |
|---|---|---|
| ポータル（`apps/index.html`）にカードを追記 | **登録しない**（`data-scenes` も持たない） | 子ども・メンターの一覧に開発者向けページを出さない |
| `apps/updates.json` に更新情報を追記 | **記載しない** | スタッフに知らせる変化ではない |
| `apps/guide/` の早見表に1行追加 | **掲載しない** | 遊びのツールではない |
| `shared/js/howto.js`（あそびかたモーダル） | **組み込まない** | 読者が開発者のみ。`scripts/lint.sh` の `HOWTO_EXEMPT` に登録済み |
| `shared/js/stats.js` の読み込み | **読み込まない** | ダッシュボード自身の閲覧を計測すると数値が汚れる（自己計測しない） |
| 子ども向け文言ルール（ひらがな中心・比喩は一度だけ等） | **対象外**（日本語・漢字表記でよい） | 読者が開発者。ただしトーンは他アプリと揃える |
| セッションデータの自動削除・TTL・`onDisconnect` | **該当なし** | ルームを作らない読み取り専用ページ |
| viewport の `maximum-scale=1` | **付けない** | RTDB のゲームアプリ向けの指定。ここは拡大してよい |

### 「計測値を子ども向け画面に出さない」規約との関係

`AGENTS.md`「stats.js」は **計測値やランキングを子ども向け画面に表示しない** ことを求めている。
このページは計測値そのものを表示するが、規約と矛盾しない。理由は次の3点。

1. **子ども向け画面ではない。** ポータル・早見表・`updates.json` のどこからもリンクせず、URL 直打ちでしか到達しない
2. **画面共有で開かない。** 参加者に見せる想定がなく、他アプリからの遷移も存在しない
3. **表示するのは回数だけ。** 個人を識別する情報は DB に存在しないため、誰がどれだけ使ったかは表示できない

このページの URL を子ども・保護者に配ったり、他アプリからリンクしたりしないこと。
**リンクを1本足した時点で規約違反になる。**

## 特有のルール・制約

- 書き込みコードを足さない（監査でここを見る）
- 月キーは `/^\d{4}-\d{2}$/` に一致するものだけを月として扱う（想定外のキーは無視）
- 回数は `Number.isFinite()` で検証し、数値でない値は 0 として扱う
- 行の開閉はアプリ名の `<button>`（`aria-expanded` / `aria-controls`）で行い、キーボードでも操作できる。
  クリックは行全体で受けるが、ハンドラは `<tr>` 側だけに置く（button の click はバブリングで届く）
- `innerHTML` は使わず `createElement` + `textContent` で組み立てる（DB 由来のキー名をそのまま描画するため）
- モバイル幅（600px 以下）でも崩れないこと。テーブルは `overflow-x: auto` の中に置く
