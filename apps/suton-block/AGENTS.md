# すとんブロック 仕様書

## 目的・使用シーン

上から落ちてくるブロックを回してすき間に入れ、横1段をそろえて消す落ちものパズル。

- **core value**: 手を動かすだけで遊べる。ルームではみんな同じ順番でブロックが出るので、運ではなく置き方の差で段の数をくらべられる。盤がいっぱいになっても、からにして続くので途中で抜ける子が出ない
- 対象: 小学校中学年〜中学生。ひろば・ボドゲクラブ（`data-scenes="hiroba bodoge"`）
- ルームはホスト＋ゲスト8人まで。ひとりでも遊べる（通信しない）
- 1ラウンド2〜5分

> 経緯: 2026-11-02 フィードバックボードに「落ちものパズル（特定の市販ゲーム）を入れてほしい・対戦もできれば・回転は SRS で」という要望が2件届いた。特定のゲームの再現はしない（名前・回転の表・対戦の攻撃ルールを写さない）ため、同日 `drafts/suton-block/` で独自ルールの落ちものパズルとして試作 → 回転のずらし方を独自に作りなおし（要望の「SRS」に近い手ざわり）→ じゃまブロック（設定・はじめはなし）・とっておく・ひとりの時間を追加 → 同日オーナーが「この内容で本体化」と承認。
> 2026-11-02（同日）: フィードバックボードの「ブロックを L・J・S・Z・I・O・T にしてほしい」「入らないはずの回転入れが入る（ふつうは上に弾かれる）」を受けて、オーナーが「著作権に配慮しつつ、ブロックと回し方は着想元どおりに」と決めた。ブロックを4マスの7種類にし（裏返すはなくした）、回せないときのずらし方を、よく知られた回し方の表（向きの組み合わせごとに5通り）と同じにした。
> 配慮として、名前・ロゴ・音楽・形ごとの色の組み合わせは写さない（色はこのアプリで決めた組み合わせ。よく知られた組み合わせと同じ形・同じ色にならないようにした）。対戦の攻撃ルール（じゃまの送り方）も独自のまま（「段の数をくらべる」のじゃまブロック）。
> 2026-11-04: フィードバックボードの「消した段を競うか対戦かを選べるように・対戦はいっぱいで終わりか続けるかを選べるように・盤を空にした数を記録・相手に送る火力を着想元の対戦と同じに」を受けて、オーナーが「着想元に寄せて」と決めた（同日チャット）。待合室の「あそびかた」に「対戦」を足し、対戦で送るじゃまの数は、よく知られた対戦の表と同じにした（下の「対戦」）。時間はオーナーの指示で「ここまで」のときも選べる（なし・2・3・5分）。「からにしてつづける」の順位は、オーナーの指示で送ったじゃまの数。表の数のほかは写さない（名前・技の呼び名・音・見た目）。画面では技を「回し入れ」「つづけて大技」「れんぞく」「全部消えた」と呼ぶ。
> 着想元のゲーム名は、画面・検索のキーワード・早見表・更新情報のどこにも書かない。早見表では系統ラベル「落ちものパズル系」で紹介する。

## ルール

| 項目 | 内容 |
|---|---|
| 盤 | 横10・たて20。上にはみ出した部分は空きとして扱う |
| ブロック | 4マスの7種類（I・O・T・S・Z・L・J。コードの `kind` もこの文字）。7種類を1回ずつ混ぜた袋から順に出る。はじめの向きは平らな面が下（I は横・T は出っぱりが上）。2026-11-02 までは1〜4マスの8種類＋裏返すだった |
| 色 | I ピンク・O 青緑・T 緑・S 黄・Z 青・L 紫・J オレンジ（`app.js` の `COLORS`。よく知られた組み合わせと重ならないように決めた。変えるときも重ねない） |
| 操作 | 左右・下（押しっぱなしでくり返す）・すとんと落とす・左に回す・右に回す・とっておく。画面のボタン・キーボード・マウスで操作できる。画面のボタンは2段で、2段目は回す2つと、横長の「とっておく」 |
| キーボード | ← → 動かす・↓ 下へ・スペース すとん・↑ か X 右に回す・Z 左に回す・C か Shift とっておく・P とめる（ひとりのときだけ）（2026-11-02 フィードバックボードの要望で、とっておくを C・Shift に。同日、裏返すをなくしたので A は何もしない） |
| マウス（2026-11-02 追加） | 盤の上で左右に動かすと、ブロックのまん中がその列へ動く（かべ・ブロックに当たったらそこで止まる）。左クリックですとん、右クリックで右に回す、ホイールで回す（上で左回り・下で右回り。0.15秒に1回まで）。まん中のボタンは何もしない（裏返すをなくしたため）。とっておくは画面のボタンか C・Shift。マウス以外（タッチ・ペン）の盤の操作は受けつけない（画面のボタンを使う） |
| 回せないとき | よく知られた回し方の表と同じずらし方で試す（下の表） |
| つぎ | 5つ先まで出す（1つ目は大きく、2つ目からは小さく）。横の列（とっておく・消した段・来るじゃま・スマホのほかの人の一覧）が盤より長くなるときは、収まる数まで減らす（2つより減らさない。`layout()`）。2026-11-02 に2〜3つから増やした |
| とっておく | いまのブロックをはじめの向きでしまい、しまってあったもの（なければ、つぎ）を出す。1つのブロックにつき1回（置いたら、また使える）。使ったあとは箱がうすくなる |
| 着地 | 着地してから0.5秒は動かせる。着地したまま動かす・回すと待ちがのびる（15回まで） |
| 消える | 横1段がうまると消える。点は「消した段の数」だけ（何段いっしょでも1段は1） |
| 速さ | ゆっくり 1.0秒・ふつう 0.65秒・はやい 0.38秒で1マス落ちる。時間がたっても上がらない |
| いっぱい | ブロックが出せない・上にはみ出して置いた（消えもしなかった）とき。ひとりは「からにしてつづける（はじめの値）」か「おしまい」を選ぶ。ルームの「段の数をくらべる」はいつも「からにしてつづける」。対戦は「その人はここまで（はじめの値）」か「からにしてつづける」を選ぶ |
| からにした回数 | 盤をからにしてつづけた回数（`resets`）。ルームの結果（「対戦」の「ここまで」のときはからにしないので出さない）と、ひとりの「からにしてつづける」の結果に出す。記録はしない（2026-11-04） |
| 落ちる先 | 盤の中に枠で出す |

回し方（`engine.js` の `SHAPES`・`kicksFor`）:

- 向きは 0 = はじめ・1 = 右に1回・2 = 2回・3 = 左に1回（`piece.rot`）。形は箱（I は4×4・O は2×2・ほかは3×3）の中で回す
- 回した形がそのまま入らないときは、「いまの向き > 回した先の向き」ごとに決まった5通りのずらし方を順に試し、最初に入ったところで回る。どれも入らなければ回らない
- 表は I とそれ以外（J・L・S・T・Z）で分かれる。O は回しても形が変わらないので、その場だけ
- 2026-11-02 の要望の盤（左向きの T を右に回す）は、下の穴には入らず、上へ2マスずれて回る（しくみのテストに入れてある）
- それまでの独自のずらし方（下に1マス・下に2マス＋横に1マスを先に試す）はなくした。屋根の下の深いすき間へ T を縦に入れて3段・2段を消す置き方（同日の別の要望）は、表のずらし方でもできる（しくみのテストに入れてある）
- ねじこんでもボーナス点はない

盤とブロックのしくみは `engine.js`（画面と通信に触らない。`window.SutonEngine`、node では `module.exports`）。

## ルーム

- みんな同じ種（`round.seed`）でブロックが出る（とっておいても、出る順番の列は変わらない）
- 待合室の「あそびかた」で「段の数をくらべる（はじめの値）」か「対戦」を選ぶ（`settings.mode`: `lines` / `battle`）
- 段の数をくらべる: 時間（2・3・5分。はじめは3分）のうちに消した段の数をくらべる。結果は順位（同じ段の数は同じ順位）と段の数・からにした回数
- 「はじめる」から3.5秒のカウントダウン（3・2・1）のあと落ちはじめる。音は鳴らさない
- 時間の起点はサーバーの時刻（`round.startedAt` に `ServerValue.TIMESTAMP`）。残り時間の表示と時間切れの判定は各端末の `RoomkRTDB.now()`
- 置くたびに自分の盤を `boards/{名前}` に送る（200文字につめた盤＋段の数＋読み込み直しに要るもの）。ほかの人の盤は、広い画面では右の列に小さく（6人まで）、スマホ（幅480px以下）では名前と段の数だけ（4人まで）。対戦では段の数の代わりに送ったじゃまの数（「送った◯段」）と「ここまで」を出す
- ホストの「早めにおわる」（確認あり）は `round.endedAt` を書き、そこで時間切れと同じにする

### じゃまブロック（待合室で選ぶ。はじめは「なし」）

- 2段いじょういっしょに消すと、（消した段数−1）段のじゃまを送る。送る先は、あそぶ人の並び（`round.players`）で自分のつぎの人（最後の人は最初の人へ）。ひとりだけなら送らない
- 届いたじゃまは「来るじゃま」にたまり、つぎに段を消さずに置いたとき、盤の下から灰色の段として入る。どの段も同じ1列があいている（列は入るたびにでたらめ）
- 来るじゃまがあるときに段を消すと、消した段の数だけ来るじゃまがへる。へらしたぶん、送るじゃまも少なくなる
- じゃまで上にはみ出したら、いっぱいと同じく盤をからにしてつづける
- 送るのは `jama/{相手}` への push。受けた端末が数えたら消す（同じじゃまを二度数えないよう、受けとったキーを覚える）
- 結果は、じゃまありでも消した段の数でくらべる

### 対戦（2026-11-04）

- じゃまはいつもあり（じゃまブロックの設定はかくす）。送る相手は「じゃまブロック」と同じく並びのつぎの人。「ここまで」になった人はとばす。送り先がいない（ひとりの回・ほかがみんなここまで）ときは、送ったじゃまの数に入れない
- 送るじゃま（`jama/{相手}/{pushキー}`）は、自分の盤（送ったじゃまの数・来るじゃま）と同じ1回の update で書く（片方だけ届いて、読み込み直したときに数がずれないように）
- 「ここまで」になったのを知る前に送られて、ここまでの人あてに届いたじゃまは、その人のつぎの、のこっている人が受けとる（ここまでの人の端末は受けとらない）
- 送るじゃまの数（`engine.js` の `attackOf`。よく知られた対戦の表と同じ）:

| 消し方 | 送る |
|---|---|
| 1段・2段・3段・4段 | 0・1・2・4 |
| T の回し入れで 1段・2段・3段 | 2・4・6（消さずに回し入れても0） |
| 小さな回し入れ | ふつうに消したのと同じ（1段0・2段1） |
| つづけて大技（4段か回し入れを、ふつうの消し方をはさまずに続けた。消さずに置くのははさんでも切れない） | ＋1 |
| れんぞく（消さずに置くまで続けて消した回数。1回目から 0・0・1・1・2・2・3・3・4・4・4・5、12回目からは5） | 足す |
| 盤が全部消えた | 10（ほかの数は足さない） |

- 回し入れの見分け方（`spinOf`）: 最後の動きが回す（回したあとに横・下へ動いた・すとんで落ちたら回し入れではない）、T のまん中のまわり4すみのうち3つ以上がうまっている（かべ・床もうまっている扱い）。出っぱりの側の2すみの片方があいていれば小さな回し入れ。ただし5番目のずらし方で回ったときはふつうの回し入れ
- 来るじゃまがあるときに送るぶんができたら、来るじゃまを先にへらし、のこりを送る（相殺）。消さずに置くと、来るじゃまがすべて盤の下から入る（どの段も同じ1列があく）
- 大技・れんぞく・送った・へらしたときは、盤の上に一言（「回し入れ！」「つづけて大技！」「3れんぞく！」「4段おくったよ」など）を1.4秒出す
- 「盤がいっぱいになったら」（`settings.full`）:
  - **その人はここまで**（`out`。はじめの値）: いっぱいになった人の盤は止まり、`boards/{名前}` に `out: true`・`outAt`（その端末の `RoomkRTDB.now()`。1回だけ決める）を書く。のこりが1人（ひとりであそぶ回は0人）になったら結果（ホストは最後に「ここまで」になってから0.8秒後・その回の人は4秒後）。時間（なし・2・3・5分）を選べ、時間で区切ったときも結果。時間「なし」は、ルームが残りつづけないよう内部では30分で区切る（画面には時間を出さない）。回の途中で退出した人は、その場で「ここまで」になる
  - **からにしてつづける**（`clear`）: いっぱいになったら盤をからにして続ける。時間（2・3・5分）で区切る
- 順位: 「ここまで」は、のこった人が上（のこった人どうしは送ったじゃまの数）、ここまでになった人は、あとまでのこった人が上。「からにしてつづける」は送ったじゃまの数。結果には「のこった／ここまで」・消した段・からにした回数（からにしてつづけるとき）も出す

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（あそんでいる回の途中なら、おわるまで待合室で待つ）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 ├── 「ひとりであそぶ」 → 速さ・時間・いっぱいになったら（screen-solo） → あそぶ画面（通信しない）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting）: あそぶ人・設定（ホスト: ホストもあそぶ・時間・速さ・じゃま／参加者: いまの設定）・「はじめる」
  ↓「はじめる」（あそぶ人が1人以上）
あそぶ画面（screen-play）: 盤・とっておく・つぎ・消した段・来るじゃま・ほかの人・操作のボタン
  （ホストが「ホストもあそぶ」を外したとき・みんなにみせる画面は、あそぶ人の盤をならべて見る画面 screen-watch）
  ↓ 時間（または「早めにおわる」）
結果（screen-result）: 順位と段の数。ホストは「もう一回」（→ 待合室）
```

- ルームバー（ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」））は待合室と結果だけに出す。あそんでいる間は盤を大きく出すため出さない（あそぶ画面のバーに残り時間と「早めにおわる」（ホスト）／「退出する」（参加者）を出す）
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「はじめる」、結果「もう一回」）
- 「あそびかた」を開いている間は、キーを受けつけない（あそぶ画面が inert になる）

## status 遷移

```
waiting ─はじめる（ホスト）→ play ─時間・早めにおわる→ result ─もう一回（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
sutonblock_rooms/{roomCode}/
  ├── status:             'waiting' | 'play' | 'result'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastRoundId:        number
  ├── hostPlays:          boolean（ホストもあそぶ。はじめは true）
  ├── settings:           { mode: 'lines'|'battle', full: 'out'|'clear', time: 0|120|180|300, speed: 'slow'|'normal'|'fast', jama: boolean }
  │                              # time 0（時間なし）は mode 'battle'・full 'out' のときだけ。full は battle のときだけ使う
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── round/                         # 「はじめる」で作り、「もう一回」で消す
  │    ├── id, seed, startedAt（ServerValue.TIMESTAMP）, mode, full, time, speed, jama（battle はいつも true）
  │    ├── players: [名前...]         # はじめた時点のあそぶ人（入った順。ホストは hostPlays のとき）
  │    └── endedAt:                   # 「早めにおわる」の時刻（ServerValue.TIMESTAMP）
  ├── roundUids/{name}:   その回の人の匿名ID（その名前は、回の間は同じ人だけが使える）
  ├── boards/{name}:      { round, b: 200文字の盤, lines, pieces, resets, taken, hold, holdUsed, b2b, combo, sent, pending, done, out, outAt }
  │                              # b2b・combo は読み込み直しで対戦の続きに要るもの。sent は送ったじゃまの数。out・outAt は対戦の「ここまで」
  ├── jama/{name}/{pushId}: { round, rows, from }   # 来るじゃま。受けた端末が数えて消す
  └── result:             { id, mode, full, at, rows: [{ name, lines, sent, resets, out, outAt }] }
```

- 読み込むときは壊れた値を読み飛ばす（`roundOf`・`settingsOf`）。盤は `unpackBoard` が長さ・文字を確かめる

## transaction 設計

ルーム全体への `transaction()`。ホストの操作は `hostUid` を確かめる（`hostTransaction`）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | 名前が空いている（ホストと同じ名前は不可。同じ名前の在室が残っていれば、同じ匿名ID＝同じブラウザの別のタブでも不可）・ゲスト8人未満（在室とその回の人を合わせて数える。その回の人が戻るときは上限を見ない）・その回（あそんでいる途中・結果）の人の名前は同じ匿名IDの人だけ → `players/{name}`（`transactRetry`。送信後の切断のやり直しで、この参加の書き込み（同じ `joinedAt`）が届いていればそのまま使う） |
| 設定・ホストもあそぶ | ホスト | `waiting`。続けて変えても取りこぼさないよう二度押しよけのロックを使わない |
| はじめる | ホスト | `waiting`・あそぶ人がいる → `round` を作り、`boards`・`jama`・`result` を消す |
| 盤を送る | あそぶ人 | `boards/{自分}` への set（transaction ではない。自分だけが書く） |
| じゃまを送る | あそぶ人 | `jama/{相手}` への push。受けた人が自分の分を消す |
| 早めにおわる | ホスト | `play`・押した時点の回の id が一致・まだ `endedAt` がない → `round.endedAt` |
| 結果を出す | ホスト（時間の1.5秒後。対戦の「ここまで」で、のこりが1人になってから0.8秒後）・その回の人（どちらも4秒後） | `play`・回の id が一致 → `boards` から段の数・送ったじゃま・からにした回数・ここまでを集めて `result`、`status: 'result'`、`jama` を消す |
| もう一回 | ホスト | `result` → `waiting`。`round`・`roundUids`・`boards`・`jama`・`result` を消す |
| 退出 | ゲスト | 自分の在室を消す（その回の盤は残し、結果に出る）。対戦の「ここまで」の回の途中なら、同じ transaction で自分の盤を `out: true` にする（在室が切断で消えていても、その回の匿名IDが同じなら書く）。退出のあいだに盤を送って上書きしないよう、先にあそぶのを止める |

## 接続・切断・再接続

リバーシ・しるしでヒントと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- **読み込み直し**: 同じタブなら sessionStorage から同じルームへ戻る。あそんでいる回の途中なら、`boards/{自分}` から盤・段の数・とっておいたもの・来るじゃまを戻し、同じ種で「出る順番の列から取り出した数」（`taken`）まで進めて同じ順番の続きにする（`engine.js` の `restoreGame`）。落ちていた途中のブロックは、はじめの位置から出なおす
- 切れた人・退出した人は、ほかの人の画面で「いまはいない」と出る（小さな盤をうすく。ホストは `hostConnected` で見る。切れたのか退出したのかは区別できない）。結果にはその回の人として出る
- 来るじゃまは、受けとったじゃまを消すのと同じ1回の update で `boards/{自分}/pending` に書く（置く前に読み込み直しても消えない）。書けなかったら数えたぶんをもどし、つぎの更新でやりなおす
- ホスト切断中、待合室と結果の画面では共通のオーバーレイ。期限はふだん切れてから2分、あそんでいる回は時間で結果が出て2分たつまで、結果は出てから2分たつまでのばす（`expiryAt`）。**あそんでいる間（時間のあと結果を待つ間も）はオーバーレイで盤をかくさず**、あそぶ画面のバーに「ホストの通信が切れています」と出す（時間で結果が出るので、ホストがいなくても続けられる）。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- ホストのタブが裏に回る・切れているときも、その回の人の端末が時間の4秒後に結果を出す（どの端末が出しても同じ結果。`finish` は transaction が通った端末だけが数える）

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。結果のあとも自動削除しない（「もう一回」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 「もう一回」で回の記録（`round`・`roundUids`・`boards`・`jama`・`result`）を消す

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。players に入らない・切断予約をしない・期限切れのルームも消さない・結果も出さない
- 待合室では「参加のしかた」とルームコードを大きく出す。あそんでいる間は、あそぶ人の盤をならべて出す（ホストが「ホストもあそぶ」を外したときのホストの画面と同じ）。結果は順位
- ホストが切れている間、あそんでいる回はオーバーレイで盤をかくさず、バーに「ホストの通信が切れています」と出す。バーの「トップへ戻る」でいつでも抜けられる
- 秘密の情報はないので、ホストの画面をそのまま共有してもよい

## ひとりであそぶ

- 通信しない（Firebase に書き込まない）。速さ・時間（なし・2・3・5分。はじめは なし）・いっぱいになったら（からにしてつづける・おしまい）を選んで「はじめる」
- 時間を選ぶと残り時間が出て、0になったら結果（消した段・置いたブロック）。「おわる」でいつでも結果へ
- 「とめる」（あそぶ画面のバー。キーボードは P）で止められる。止めている間は盤に「とめています」と「つづける」を重ね、落ちるのも残り時間も止まり、キー・ボタン・マウスで動かない。「つづける」か P で、止めたところから続く（止めていたぶん、着地の待ちと残り時間をずらす。「あそびかた」を開いている間と同じしくみ）。2026-11-02 フィードバックボードの要望で追加。ルームでは出さない（みんなの時間がそろっているため）
- 読み込み直したら、はじめから（保存しない）

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る。engine.js は DOM に触らない
- **ホスト以外も書く**: あそぶ人が自分の盤（`boards/{自分}`）とじゃま（`jama/{相手}`）を書く・その回の人も結果を出す（ホストのタブが裏に回っても止まらないように）
- **あそんでいる間はホスト切断のオーバーレイを出さない**（上の「接続・切断・再接続」）
- **あそんでいる間はルームバーを出さない**（盤を大きく出すため。待合室と結果では出す）
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **順位を出す**（消した段の数の比較。結果画面だけで、記録はしない）
- **途中から入った人は、その回にはあそべない**（待合室で待ち、つぎの回から）
- **端末なしの参加者はいない**（自分で操作するゲームなので、ホストが代わりに動かす形は作らない）

## 入れない機能

- 音（落ちる・消える・時間切れの音もなし）
- 段をまとめて消したときのボーナス点・特別な回し方の点（「段の数をくらべる」の段の数は1段1のまま。対戦で送るじゃまの数だけは表で決める）
- 速さが時間とともに上がる
- じゃまの攻撃先を選ぶ・いちばん多く消した人へ送るなど
- 成績・最高記録の保存、ランキングの記録

## 既知の制約（v1）

- 対戦の「ここまで」で、通信が切れたまま戻らない人は「ここまで」にならない（戻ってくるかもしれないため）。決着がつかないときは、ホストの「早めにおわる」で結果にする。時間「なし」でも30分で結果になる
- 「ここまで」の時刻は各端末の `RoomkRTDB.now()` なので、ほぼ同時にここまでになった2人の順位は、端末の時計のずれで入れかわることがある

- 盤は置くたびに送るので、ほかの人の画面の盤は「置いた時点」のもの（落ちている途中のブロックは見えない）
- じゃまのあく列は、受けた端末が決める（`Math.random`）。同じ回でも人によって違う
- 時間の判定は各端末の `RoomkRTDB.now()` なので、端末によって0.数秒ずれることがある。最後の盤が届くのを待ってから結果を出す（ホストは1.5秒、その回の人は4秒あと）。そのあとに届いた盤は結果に入らない
- 読み込み直したとき、落ちていた途中のブロックは、はじめの位置から出なおす。ひとりのときは読み込み直すとはじめから
- 同じブラウザの別のタブから、在室している名前で「参加する」はできない（同じ盤を2つの画面で動かさないため）。ただし、ブラウザの「タブを複製」でできたタブは再接続の記録も写るので、同じ名前で2つの画面がつながる（ほかのルーム型ゲームと共通。両方が同じ `boards/{name}` に書き、あとから書いたほうが残る）
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（共通方針どおり、少なめに出る側の誤差として扱う）

## メンター向けの心得（画面には出さない）

- はじめての子が多いときは「ゆっくり」・じゃま「なし」で。慣れてきたら速さを上げ、じゃまを「あり」に
- 対戦の「ここまで」は、早くここまでになった子が待つ時間が長くなる。人数が多いときや、まだ慣れていない子がいるときは「からにしてつづける」で
- 盤がいっぱいになっても、からにして続くので、積み上がっても慌てなくていいと伝える
- 段の数で落ち込む子には、うまく入れられた場面や、まとめて消せた場面をほめる
- ホストがあそばずに「あそぶ人の盤」を画面共有すると、みんなの様子をいっしょに見られる
