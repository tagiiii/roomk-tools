# カギあわせ 仕様書

## 目的・使用シーン

全員が数字のカギ（1〜8 または 1〜12、同じ数字が4本ずつ）を小さい順に並べて持ち、見えるのは自分のカギだけ。
自分の番に、自分のカギ1本と仲間のカギ1本を選んで「あわせる」。同じ数字なら両方あき、ちがえば警報ランプが1つつく。
数字のカギを全部あけたら宝箱があいてクリアの協力推理ゲーム。

- **core value**: 「小さい順に並んでいる」「見えている数字」から、仲間のカギの数字を一緒に推理する。全員が同じチームで、点数・順位はない。話さなくても、選んで押すだけで参加できる。
- 対象: 小学校中学年〜中学生。ボドゲクラブ・作戦会議（`data-scenes="bodoge sakusen"`。作戦会議はオーナー決定 2026-10-03）。2人でも遊べる（検索キーワードに「1対1」）。
- 遊ぶ人 **2〜5人**。ゲストは5人まで。ホストは既定で進行だけ。待合室の「自分もプレイヤーとして参加する」で遊ぶ人に入れる。
- 所要時間 10〜25分（1〜8 でおよそ10〜15分、1〜12 でおよそ20〜25分）。

> 着想元は『ボムバスターズ』（Bomb Busters、林尚志）。名称・爆弾の設定・見た目は使わない。紹介文・早見表では「『ボムバスターズ』から着想」と記述的に紹介し、「Web版」「オンライン版」「無料版」等の表現は使わない。
> 爆弾・爆発・時限装置はコンテンツガイドライン（暴力・ダークな内容）に近いので、宝箱のカギに置きかえた（赤いワイヤー→ワナのカギ、起爆ダイヤル→警報ランプ、ワイヤーを切る→カギをあける）。
> 表示名「カギあわせ」・フォルダ `kagi-awase`・テーマ（宝箱）・ルールの範囲はオーナー決定（2026-10-03）。

## ルール

オーナー決定（2026-10-03）:

- 基本ルールのみ（黄色いワイヤー・装備カード・ミッションは入れない）。待合室で「カギの数字」（1〜8 みじかめ／1〜12 ふつう）と「ワナのカギ」（なし／1つ／2つ）を選べる。初期値は 1〜8・ワナ1つ
- **失敗はその場で終わる（原作どおり）**。警報ランプは遊ぶ人の数だけあり、全部ついたあとにさらにまちがえるか、ワナのカギを選ぶと「今回はここまで」。まちがえてよい回数＝遊ぶ人の数
- **さいしょに1本ずつ見せる**: 始めると、全員が自分のカギ（ワナ以外）を1本選んで「このカギを見せる」。全員がそろったら最初の人の番
- 遊ぶ人は2〜5人

カギと並び:

- 数字 1〜N を4本ずつ（N=8 で32本、N=12 で48本）＋ワナ。開始時にまぜて、遊ぶ順に1本ずつ配る（人数で割り切れないときは1本多い人がいる）
- ワナは数字と数字の間（1と2の間〜N-1とNの間）に入り、同じ間に2本は入れない。ワナの持ち主には「ワナ」と見え、ほかの人には見えない
- 各自のカギは小さい順に並べ、並びは最後まで変えない（あいても位置はそのまま）。見る人にわかるよう、カギの下に左からの番号（1, 2, 3…）を出す

自分の番にできること（どちらか1つ）:

1. **あわせる**: 自分のまだあいていない数字のカギ1本と、仲間のまだあいていないカギ1本を選んで「「7」であわせる」
   - 同じ数字 → 両方あく
   - ちがう数字 → 警報ランプが1つつき、選ばれた仲間のカギの本当の数字がみんなに見える（あくわけではない）
   - ワナ → その場で警報。今回はここまで
2. **ひとりであける**: のこりの同じ数字のカギ（まだあいていないもの）を全部自分が持っているとき、自分のカギを選ぶと「「7」のカギ2本を、ひとりであける」が出る。押すと全部あく（原作の、4本または残り2本を自分だけで切るルール）

- 手を打ったら、遊ぶ順で次の人の番。まだあけるカギ（ワナ以外）がない人はとばす
- 数字のカギを全部あけた人に残ったワナは、その時点でみんなに見せる（`h: true`）。見えているワナは選べない。位置が実質わかるのに選べてしまい、その場で終わるのを防ぐため（原作でも、ワナしか残っていない人はワナを見せる。独立レビュー 2026-10-03 の指摘で追加）
- 数字のカギが全部あいたらクリア（ワナはあけなくてよい）

room-K 向けに足したもの:

- **わかっているまちがいは押せない**: みんなに見えている数字とちがうカギを選ぶと「あわせる」が押せず、「そのカギは「5」だとみんなに見えているよ」と出す（押しまちがいでランプを減らさないため）
- **選びなおし**: 選んだカギをもう一度押すと外れる
- **さっきの手・これまでの流れ**: いちばん新しい手を文で大きく出し、動いたカギに黄色の目印を付ける。2手目からは「これまでの流れ」に新しい順で並べる（最大40手）
- **しめきる**（ホスト）: さいしょに見せる途中で、見せていない人がいても始められる（確認あり）。通信が切れた人などのため
- **この番をとばす**（ホスト）: 番の人の通信が切れているときだけ出る（確認あり）。確認している間にその人が戻ってきたら、とばさない（Codex レビュー 2026-10-03 の指摘）
- **ゲームをやめる**（ホスト）: 遊んでいる途中（おしまいの画面を除く）に「ゲームをやめて待合室へ戻る」（確認あり）
- おしまいの画面では、全員のカギの数字を全部見せる（ふりかえりのため）

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室
 ├── 参加用のリンク `?room=CODE` → 参加画面（ルームコード入力済み・名前だけ入れる） → 待合室
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting / status: waiting）
   ホスト: 参加者（遊ぶ人 N人）、「自分もプレイヤーとして参加する」、カギの数字、ワナのカギ、「はじめる」
   ゲスト・見る人: 参加者と「こんどのルール」
        ↓「はじめる」（遊ぶ人 2〜5人）
ゲーム（screen-game / status: setup → play → end。1つの画面で中身を切り替える）
   上から: 見出し／警報ランプとあいたカギの数／さっきの手／接続の注意／全員のカギの列／操作／これまでの流れ
   setup: 遊ぶ人は自分のカギを選んで「このカギを見せる」。ホストは「しめきる」
   play:  番の人は自分のカギ→仲間のカギ→「あわせる」（条件つきで「ひとりであける」）。ホストは条件つきで「この番をとばす」
   end:   「宝箱があいた！」か「今回はここまで」と全員のカギの数字。ホストは「もう一回あそぶ」（→ 待合室）
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）

### 参加用のリンク（`?room=CODE`。2026-10-05、ルーム型アプリでの先行導入）

共通仕様の正本は [rtdb.md](../../docs/development/rtdb.md)「参加用のリンク」（同日、ルーム型の全アプリへ展開）。以下は先行導入時の記録。

チャットにルームコードを貼る代わりに、リンクを貼れば、参加する人はコードを打たずに入れる（日本語入力のまま打って文字が重なる・全角になる問題の回避。2026-09-30 の実機報告が動機）。URL からの入室を提案されたのを受け、まずこのアプリだけで試し、横展開は実機で使ってみてから決める（オーナー承認 2026-10-05）。

- **「リンクをコピー」**（ルームバー）: `location.origin + location.pathname + '?room=' + code` をコピーする。**「コードをコピー」はコード単体のまま**（2026-08-10 の実機フィードバック。URL と案内文を組み立てない）。共通の `copyRoomCode` はコード専用なので、文字列用の `copyText` を app.js に置く（成功・失敗をトーストで通知、連打ガード）
- **入口**: 起動時に `?watch=` → `?room=` → 保存した記録（sessionStorage）の順に見る。`?room=` は `normalizeRoomCode`（全角→半角・大文字化）してから `ROOM_CODE_PATTERN` で検査する
  - 正しい形なら、参加画面を開き、コード欄に入れ、ヒント「リンクからひらいたので、ルームコードは入っているよ…」を出し、名前欄にフォーカスする。コード欄は直せるように残す（古いリンクで新しいコードを口頭で聞いたとき用）
  - 形が正しくなければ、トースト「ルームコードが正しくないよ」を出して `?room=` をアドレスから外し、そのあとはリンクなしで開いたときと同じにする（保存した記録があれば同じルームへ戻り、なければトップ。独立レビュー 2026-10-05 の指摘で明文化）
  - **再接続との優先順位**: 同じコードの記録が残っていれば再接続を優先し、戻れなければ記録を消して参加画面へ。別のコードの記録が残っていれば、記録を消してリンクのルームを優先する
  - ルームの存在は参加画面を開く時点では確かめない（既存の「参加する」の検査に任せる。終わったルームのリンクなら「ルームが見つからないよ」「このルームは終わったみたい」がフォーム内に出る）
- **アドレスの後片付け**: `?room=` は `connectToRoom`（参加・作成・再接続でつないだとき）に `history.replaceState` で外す。再読み込みで古いコードの参加画面に戻らず、保存した記録から同じルームへ戻れるようにするため。参加に失敗している間は残す（再読み込みしてもコードが入ったまま）
- トップの「ルームに参加する」から開いたときは、リンク用のヒントを隠す
- 参加の手順そのもの（名前 → コード → 参加する）・ニックネームの制約・参加の transaction は変えていない
- ボタン階層: 塗りつぶしの主ボタンは各場面で1つ（待合室「はじめる」、さいしょ「このカギを見せる」、番「あわせる」、おしまい「もう一回あそぶ」）。「ひとりであける」「しめきる」「この番をとばす」は条件つきで出る枠線の副ボタン
- 操作（「このカギを見せる」「あわせる」）は画面の下に固定する（カギの列が長く、スマホでスクロールしても押せるように）。幅 960px 以下では右下の「？」ボタンに重ならないよう右をあける
- 番の人の列は枠を太くし、列の見出しに「この人の番」（自分なら「あなたの番」）

## status 遷移

```
waiting ─はじめる→ setup ─全員が見せた／しめきる→ play ─全部あいた／ワナ／ランプをこえた→ end ─もう一回あそぶ→ waiting
setup / play ─ゲームをやめる（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

- `setup → play` は、最後に見せた人の transaction か、ホストの「しめきる」
- `play` の中の手と `play → end` は、番の人の transaction。それ以外の遷移はホストだけ

## Firebase データ構造（Realtime Database）

パス: `kagiawase_rooms/{roomCode}/`（共通命名規則。セキュリティルール変更不要）

```
kagiawase_rooms/{roomCode}/
  ├── status:             'waiting' | 'setup' | 'play' | 'end'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostPlays:          boolean   # 自分もプレイヤーとして参加する（待合室で変更）
  ├── maxNum:             8 | 12    # カギの数字（待合室で変更）
  ├── traps:              0 | 1 | 2 # ワナのカギの数（待合室で変更）
  ├── hostConnected / hostDisconnectedAt
  ├── createdAt:          ServerValue.TIMESTAMP
  ├── lastGameId:         number
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  └── game/                          # 「はじめる」で作り、「もう一回あそぶ」「ゲームをやめる」で消す
       ├── id:        number          # lastGameId + 1
       ├── order:     [name...]       # 遊ぶ順（開始時にシャッフルして固定）
       ├── uids:      {name: uid}     # 名前の持ち主（ゲームの間の名前の予約）
       ├── joined:    {name: joinedAt}
       ├── maxNum / traps             # 開始時の設定を固定
       ├── lamps:     number          # 警報ランプの数（= 遊ぶ人の数）
       ├── misses:    number          # まちがえた数
       ├── hands/{name}: [{ v, t?, o?, h? }...]
       │                              # 小さい順。v 数字、t ワナ（v と v+1 の間）、o あいた、h 数字がみんなに見えている
       ├── shown/{name}: true         # さいしょに見せた
       ├── turn:      name | null     # 番の人
       ├── seq:       number          # 手の通し番号（操作の取りちがえ防止）
       ├── log:       [{ n, r, by, to?, i?, v?, a?, m?, c?, ix? }...]
       │                              # r: hit / miss / trap / solo / skip。i 選ばれたカギの位置、a 本当の数字（miss）、
       │                              # m あわせた自分のカギの位置（hit）、c・ix ひとりであけた本数と位置（solo）。最大40件
       └── result:    null | 'clear' | 'trap' | 'alarm'
```

- カギの位置（配列の番号）は配ったあと変わらないので、手は位置で記録する
- 読み込むときは `tileOf` で真偽値・数字を正規化する

## transaction 設計

すべてルーム全体（`kagiawase_rooms/{code}`）への `transaction()`。配る乱数は transaction の外で作った種から決める（`seededRandom`）。遊ぶ人の操作は、押した時点の `status`・`game.id`・`game.seq` を捕まえて、transaction の中で一致を確かめる（ほかの人の手で状況が変わったあとの古い操作を弾く）。ホストの操作は `hostUid` を確かめる。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム |
| 参加 | ゲスト | `waiting`・名前が空いている・ゲスト5人未満 → `players/{name}`。遊んでいる途中は `game.uids` の持ち主本人だけが入りなおせる |
| 設定 | ホスト | `waiting` → `hostPlays` / `maxNum` / `traps` |
| はじめる | ホスト | `waiting`・遊ぶ人 2〜5人 → `game` を作って配る・`setup` |
| このカギを見せる | 遊ぶ人 | `setup`・id/seq 一致・まだ見せていない・ワナでないあいていないカギ → `h: true`・`shown`。全員そろったら同じ transaction で `play`・最初の番 |
| しめきる | ホスト | `setup`・id 一致 → `play`・最初の番 |
| あわせる | 番の人 | `play`・id/seq 一致・`turn` が自分・自分のカギはワナでなくあいていない・仲間のカギはあいていない → hit／miss／trap を書き、`log`・`seq`・次の番／`end` |
| ひとりであける | 番の人 | 同上・のこりの同じ数字を全部自分が持っている → 全部 `o: true`・次の番／`end` |
| この番をとばす | ホスト | `play`・id 一致・`turn` が確認したときと同じ・その人が在室していない → 次の番・`log` に skip |
| もう一回あそぶ | ホスト | `end`・id 一致 → `waiting`・`game: null` |
| ゲームをやめる | ホスト | `waiting` 以外・id 一致 → `waiting`・`game: null` |

- 遊ぶ人の操作は `state.busy` で二度押しを止める（同じ手を2回送らない）
- 参加・再接続は `warmRoomCache`（先に値を購読）してから transaction する（空のキャッシュで中止されないため）

## 接続・切断・再接続

スタンプあてゲームと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- カギは `game` にあるので、在室が消えても残る。戻ると同じカギの続きから遊べる
- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- 再読み込み: sessionStorage から同じルームに戻る。タブを閉じた子は「ルームに参加する」から同じ名前で入りなおせる（同じブラウザなら匿名IDが同じ）。ほかの人がその名前を使うことはできない（`game.uids` の予約）
- 遊んでいる途中に新しい名前では参加できない（「もうゲームが始まっているよ」）
- 番の人の通信が切れたら、ホストに「この番をとばす」を出す。ほかの人には「戻るのを待ってね」
- ホスト切断中、ゲストには共通のオーバーレイ（2分）を出す。`ORPHAN_TTL_MS = 2 * 60 * 1000`

### 既知の制約（v1）

- **抜けた人のカギで止まることがある**: 抜けた人のカギは、ほかの人が「あわせる」であけられる。ただし、ある数字ののこりを抜けた人だけが持っているときは、だれもあけられない（ひとりであけるのは持ち主だけ）。その場合や、抜けた人しかあけるカギが残っていない場合は、ホストが「ゲームをやめて待合室へ戻る」で終える
- 同じ名前・同じ匿名IDのタブを2つ開いたときの在室の揺れは、スタンプあてゲームの「既知の制約」と同じ
- 同じコードの記録があるタブで参加用のリンクをひらき、再接続の読み取りと最初の監視通知の間（ごく短い）にホストがルームを閉じると、再接続は成功扱いで `?room=` が外れたあとトップへ戻る。参加画面にはフォールバックしない（入力済みのコードは失われるが、リンクをもう一度ひらけばよい。独立レビュー 2026-10-05 の指摘。対策は入れていない）

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おしまいの画面では自動削除しない（全員のカギを見てふりかえる・「もう一回あそぶ」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 「もう一回あそぶ」「ゲームをやめる」で `game`（カギ）を消す

## みんなにみせる画面（画面共有用・見るだけ）

ホストも遊ぶと、ホストの画面には自分のカギの数字が出る。そこでホストは別のタブで「みんなにみせる画面」を開き、それを共有する（スタンプあてゲームと同じ作り）。

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ） ②トップの「みんなにみせる画面をひらく」 ③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。値を読むリスナーだけ
- **出すもの**: 待合室／全員のカギの列（あいた・見えているカギの数字だけ）・警報ランプ・さっきの手・これまでの流れ／おしまい（全部の数字）
- **出さないもの**: まだ見えていないカギの数字（DOM にも書かない。aria-label も「まだ見えない」）・ワナの位置・操作ボタン

### 秘匿情報の扱い（性善説）

- まだ見えていないカギの数字とワナは、持ち主の画面にだけ出す。ほかの遊ぶ人・見る人・進行役のホストの画面（DOM）には書かない。DevTools でルームを見れば分かることは、共通のセキュリティ方針どおり許容する

## 意図的な逸脱

- **分割構成の RTDB アプリ**（スタンプあてゲームと同じ）: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は index.html しか見ないので、app.js の `ORPHAN_TTL_MS` と `clearInterval`・`clearTimeout` は rtdb-audit で手確認する
- **カギの番号は丸数字にしない**: カギの下の左からの番号は、選択肢ではなく「○○さんの3番目」と声やチャットで場所を言うための目印。カギの数字と見分けやすいよう、小さな半角数字にする
- **遊ぶ人の操作が status を進める**: 最後に見せた人が `play` へ、番の人の手が `end` へ進める（手番制のため）
- **ホストの初期値は進行だけ**（`hostPlays: false`）。ホストも遊ぶと自分のカギがホストの画面に出るため（秘密が絡むゲームの横断決定 2026-10-01 と同じ）
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **遊んでいる途中でも、そのゲームで遊んでいた名前は入りなおせる**（新しい名前は不可）
- **ルームバーに「リンクをコピー」がある**（他のルーム型アプリは「コードをコピー」だけ）。参加用のリンク `?room=CODE` の先行導入のため。横展開するときは共通化（`apps/shared/**` はオーナー判断）を検討する

## 入れない機能

- 点数・順位・個人の成績（だれがまちがえたかの集計）。チームのランプとあいた本数だけを数える
- 時間制限・自動で進む処理
- 原作の黄色いワイヤー・装備カード・ミッション（オーナー決定で基本ルールのみ）
- 番の人の代わりにホストが手を打つ操作（ホストには番の人のカギが見えないため。切断時は「この番をとばす」）
- チャットだけで参加する子の手番（カギを選ぶのは自分の端末で行う）

## メンター向けの心得（画面には出さない）

- 進行だけのときは、ホストの画面を最初から最後まで共有してよい（まだ見えていない数字は出ない）。**「自分もプレイヤーとして参加する」をオンにしたときは、ルームバーの「みんなにみせる画面」を開いて、そちらを共有する**。ウィンドウ単位で共有するときは、そのタブを別のウィンドウに切り離してから共有する
- 原作では自分のカギの数字を口で言うのは反則。room-K でも「自分の数字は言わない」で遊ぶと推理が楽しくなる。初めての回は「◯◯さんの3番目は、左の2と右の5の間だから3か4だね」のように、並び順から考える声かけを
- 自分の番で迷っている子には、見えている数字（黄色いカギ）の近くから選ぶと当たりやすいことを伝える
- まちがえても、本当の数字が見えるので「ヒントが増えたね」と受け止める。ワナで終わったときも、だれのせいでもない。おしまいの画面で全員のカギを見て、どこにあったかを一緒にふりかえる
- 初めては 1〜8・ワナ1つ（初期値）、慣れたら 1〜12 やワナ2つに
- 子どもが1人の日は、メンターも遊ぶ人に入ると2人で遊べる
