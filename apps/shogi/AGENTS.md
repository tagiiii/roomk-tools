# 将棋 仕様書

## 目的・使用シーン

2人で交互に駒を動かし、相手の王（玉）を詰ませたら勝ちの、定番の盤ゲーム。5×5の小さい「5五将棋」と、9×9の「本将棋」から選べる。

- **core value**: 将棋を指したい子が、ルームでそれぞれの端末から指せる。はじめての子は「補助」で動ける所を見ながら指せ、反則は指せないようにして理由を出す。対戦しない子も、自分の画面や「みんなにみせる画面」で対局を見られる
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの1対1でも遊べる）
- 対戦は2人。観戦はゲスト20人まで（＋端末なしの参加者4人まで）
- 所要時間: 5五将棋は5〜10分、本将棋は30分以上かかることもある（カードは「10〜40分」）

> 経緯: 2026-11-14 スタッフから「将棋がほしい」という意見 → 盤の大きさをオーナーに聞き、「本将棋と5五将棋を選べる形」で `drafts/shogi/` に試作（PR #237） → 同日オーナーが「この内容で本体化。正式ルールで。おまかせします」。正式ルールとして、5五将棋の千日手（先手の負け）・指し手の正式な表記（上・引・寄・右・左・直・打）・本将棋の入玉宣言（27点法）を本体で足した。「おまかせ」の範囲で、投了のボタン（相手の番でもできる）を入れた。
> 名前「将棋」は伝統ゲームの一般名称なので、命名の例外（リバーシ・人狼と同じ。`docs/development/app-registration.md`「アプリ名のつけかた」）に当たる。早見表では系統ラベル「定番の盤ゲーム」で紹介する。

値はツール一覧（`apps/index.html`）のカードの札・`data-scenes`・`data-speech`・`data-self` と同じにする。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|

| 目安時間 | 10〜40分 |
| 利用シーン | ボドゲクラブ・ひろば・作戦会議 |

## ルール（engine.js）

日本将棋連盟のルールに合わせる。盤のルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/shogi/engine.test.cjs`。

| 項目 | 内容 |
|---|---|
| 盤 | 5五将棋（5×5・成れるのは奥の1段）／本将棋（9×9・奥の3段）。ルームはホストが待合室で、1台の画面は準備で選ぶ。はじめは5五将棋 |
| はじめの並び | 本将棋はふつうの並び。5五将棋は先手が下の段に左から 玉・金・銀・角・飛、玉の前に歩（後手は反対の向き）。先手が先に指す |
| 指せない手 | 二歩・打ち歩詰め・行き所のない所への打つ手と成らない手・王手を放っておく手・自分の王を取らせる手。押したら理由を画面に出す（`whyIllegal`） |
| 成る | 成れる所では「成りますか？」のダイアログで「成る／成らない」。行き所がなくなるときは自動で成る |
| おわり | 詰み（指せる手がなくなったときも勝ち）・投了・千日手・入玉宣言 |
| 千日手 | 同じ局面（盤・持ち駒・手番）が4回目。片方が王手をかけ続けていたら、その人の負け。それ以外は、本将棋は引き分け（指しなおしのかわり）、5五将棋は先手の負け |
| 入玉宣言 | 本将棋だけ。27点法（宣言する人の番・王が相手の陣・王手されていない・相手の陣に王のほかの駒が10枚以上・相手の陣の駒と持ち駒の点（飛角とその成りは5点、ほかは1点）が先手28点・後手27点以上）。条件がそろうと「入玉宣言で勝ちにする」が出る |
| 投了 | 「投了する」（確認あり）。ルームは自分の席の人なら相手の番でもできる。ホストは代わりに指している人（端末なし・通信が切れた人）の分もできる。1台の画面は番の人 |
| 表記 | 「▲７六歩」「△同銀」。同じ種類の駒が2枚以上そこへ指せるときは「上・引・寄」、決まらなければ「右・左・直」（龍・馬は直を使わない）。持ち駒は、盤の駒も同じ所へ指せるときだけ「打」。ピンされて動けない駒は数えない |
| 場所の言い方 | 盤の上に筋の数字（右から１〜９）、右に段の漢数字（上から一〜九）。盤の向きを変えると、どちらも反対から並ぶ |

- 千日手の5五将棋の扱い・入玉宣言の点数は、オーナーの「正式ルールで」による（2026-11-14）
- 持将棋の点数計算（24点法での引き分けなど）・最大手数は入れていない（アマチュアの大会のルールで、子ども向けには使う場面がないため。AI の判断）

## 補助（はじめての人向け）

| 項目 | 中身 | はじめの値 |
|---|---|---|
| 補助を使う人 | ふたりとも／先手だけ／後手だけ／使わない。その人の番のときだけ出る（ハンデにも使える） | ふたりとも |
| 動ける所を見せる | 駒・持ち駒を選ぶと、動ける所・打てる所に点（取れる所は輪）が出る | オン |
| 駒に動ける向きを出す | 駒のふちに、動ける向きの点（桂は緑の点・どこまでも進める向きは線）が出る。補助を使う人の駒にいつも出る | オフ |
| 取られそうな駒を知らせる | 番の人の駒のうち、相手の駒が利いているものに点線の枠 | オフ |

- 補助がなくても、直前の手（動かした先を濃く・元の所を薄く）・王手（王のますを赤く・「王手」の札）・番・指せない理由は、いつも出す
- 補助はホストが待合室で決め、遊んでいる間も「補助の設定」で変えられる（1台の画面も同じ）
- 「もう一回」「先手と後手を入れかえる」では、「先手だけ・後手だけ」も入れかえる（補助が人についていく。2026-11-14 レビューの指摘）
- はじめの値は AI の仮置き（2026-11-14 オーナー「おまかせします」）

## 端末なしの参加者（ホストが代わりに指す）

リバーシと同じ。待合室でホストが「端末なしの参加者を足す」（はじめる前だけ・4人まで）。席に選べ、その人の番はホストの画面に「▲先手（○○）の番。代わりに指してね」。「端末なし」の印はホストの画面にだけ出す。

## ホストも対戦するか

リバーシと同じ。ホストは自分で席に選んだときだけ対戦する（はじめは入らない。入った順にゲストが先手・後手へ）。

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（対局中なら観戦で対局の画面）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 ├── 「1台の画面であそぶ」 → 盤・名前・補助（screen-local） → 対局（通信しない）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting）: 対戦する人（先手・後手）・参加している人・盤・補助。ホストは席を選ぶ・入れかえる・端末なしの参加者を足す・「はじめる」
  ↓「はじめる」（席の2人がそろっている）
対局（screen-game）: 番の表示（王手の札）・相手の名前と持ち駒・盤・手前の人の名前と持ち駒・指せない理由・直前の手・（入玉宣言）・結果のあとのボタン・そのほかの操作
  ↓ 詰み・投了・千日手・入玉宣言
結果（同じ画面）: ホストは「もう一回（先手と後手を入れかえる）」「対戦する人を選びなおす」（→ 待合室）
```

- 盤の向き: 後手の席の人の画面は、後手が手前（盤を180度回す）。ほかの人・1台の画面は先手が手前。「盤の向きを変える」（だれでも。その端末だけ）で逆にできる。相手の駒は字ごと逆さまに出す
- 指し方: 自分の駒（または持ち駒）を押す → 動かす所を押す。もう一度押すと選ぶのをやめる。別の自分の駒を押すと選びなおす。指せない所を押すと理由を出して選ぶのをやめる
- 広い画面（900px 以上）では、相手の札を盤の左上、手前の人の札を盤の右下に置く（将棋の駒台の位置）
- そのほかの操作: 「1手もどす」（ホスト・1台の画面。投了・宣言のあとなら、それを取り消す）・「盤の向きを変える」・「補助の設定」（ホスト・1台の画面）・「投了する」・「この対局をやめる」（ホスト）／「最初からやりなおす」「トップへ戻る」（1台の画面）
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「はじめる」、結果「もう一回」）。入玉宣言は枠線のボタン

## status 遷移

```
waiting ─はじめる→ play ─（詰み・投了・千日手・宣言）→ play（おわった対局）
play ─もう一回（ホスト・おわったあと）→ play（新しい対局。先手と後手を入れかえる）
play ─対戦する人を選びなおす／この対局をやめる（ホスト）→ waiting
play で対局の記録が読めない（壊れた）→ ホストの端末が waiting にもどす
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
shogi_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── v:                  'mini' | 'hon'   # 盤（待合室で変更）
  ├── aid:                { who: 'both'|'s'|'g'|'none', spots, arrows, danger }   # 補助（いつでも変えられる）
  ├── seats:              { s: 名前, g: 名前 }   # 待合室で選んだ席（s 先手・g 後手）
  ├── players/{name}:     { isHost, uid, joinedAt }
  ├── proxies/{name}:     { joinedAt }           # 端末なしの参加者
  └── game/                                       # 「はじめる」で作り、待合室にもどると消す
       ├── id, v, seats: {s, g}, uids: {s?, g?}, proxy: {s?: true, g?: true}
       ├── moves: [{ f: 動かす前のます（打つときは -1）, t: 動かした先, d?: 打った駒（'P' など）, p: 成ったか }...]
       ├── resign: 's'|'g'（投了した人）, declare: 's'|'g'（入玉宣言した人）
       ├── rev: 局面が変わるたびに増える番号（指す・投了・宣言・1手もどす）。古い操作の照合に使う
       └── ended: 一度でもおわった（もどしても消さない。finish を1対局に1回だけ数える）
```

- ルームには指した手の記録だけを置き、局面（盤・持ち駒・番・王手・千日手の判定）は各端末で `engine.js` の手順で作りなおす（`app.js` の `engineOf`。作った局面を覚えておき、1手ずつ足す。本将棋250手でも30ms ほど）
- 読めない手（合法でない手・壊れた値）があれば、そこまでの局面にする。指す・もどすときは、読める手までにそろえて書く
- 入玉宣言の記録は、宣言した人の番で条件がそろっているときだけ有効に読む（壊れた記録で勝ちにしない）

## transaction 設計

すべてルーム全体への `transaction()`。ホストの操作は `hostUid` を確かめる（`hostTransaction`）。席・盤・補助の変更はロックを使わない（中で今の値から作りなおす）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`） |
| 参加 | ゲスト | リバーシと同じ（名前・人数・対局の席の名前は同じ匿名IDの人だけ） |
| 席・入れかえ・端末なしの参加者・盤 | ホスト | `waiting`。入れかえは補助の先手だけ・後手だけも入れかえる |
| 補助 | ホスト | いつでも |
| はじめる | ホスト | `waiting`・席の2人がそろっている → `game` を作る |
| 指す | 番の人（端末なしの人・通信が切れた人の番はホスト） | `play`・押した時点の game.id と `rev` が一致・おわっていない・その番に指せる人・合法な手 → `moves` に足し、`rev` を1増やす。おわったら `ended` |
| 投了 | 自分の席の人（相手の番でもよい）・ホストは代わりに指している人の分 | 同じ照合 → `resign` |
| 入玉宣言 | 番の人 | 同じ照合＋`canDeclare` → `declare` |
| 1手もどす | ホスト | game.id と `rev` が一致（確認の間に指された手を取り消さない）→ 投了・宣言があればそれを消す。なければ最後の手を消す。`rev` を1増やす |
| もう一回 | ホスト | おわった対局・game.id 一致・2人がまだいる → 先手と後手（と補助の先手だけ・後手だけ）を入れかえて新しい対局 |
| 待合室へ | ホスト | game.id 一致 → `waiting` |
| 退出 | ゲスト | 自分の在室を消す。待合室なら自分の席を空ける |

## 接続・切断・再接続・終了とデータ削除

リバーシと同じ作り（`apps/reversi/AGENTS.md`「接続・切断・再接続」「終了とデータ削除」）。

- ホスト: 切断予約で `hostConnected: false`・`hostDisconnectedAt`。ゲスト: `players/{name}` を remove。`.info/connected` のたびに予約を張り直し、在室を書き戻す（3秒に1回まで）
- 席の人が切れると、全員の札に「通信が切れた」、ホストに「代わりに指してね」。同じタブの読み込み直し（同じ名前・同じ匿名ID）で続きから
- ホスト切断中、ゲストと見る画面にオーバーレイ（`ORPHAN_TTL_MS = 2分`）。切れた時刻だけ新しくなったら期限のタイマーを仕掛けなおす（2026-11-13 の直し方のまま）
- 公認バリアント「**ふりかえり画面滞在中は削除しない**」（「もう一回」のため）。削除経路はホストの「ルームを閉じる」・ホスト切断＋2分・次回アクセス時の期限切れ掃除
- 将棋には持ち時間がないので、リバーシの「1手の制限時間」「CPU が代わりに置く」は入れていない

## みんなにみせる画面（画面共有用・見るだけ）

リバーシと同じ。入口はルームバーの「みんなにみせる画面」（ホスト）・トップの「みんなにみせる画面をひらく」・`?watch=CODE`。ルームへの書き込みゼロ（`state.role === 'spectator'`）。待合室では参加のしかたとコードを大きく出す。将棋には秘密の情報がないので、ホストの画面をそのまま共有してもよい。

## 1台の画面（メンターが操作する）

- 通信しない。盤・名前（なくてもよい）・補助を選んで「はじめる」
- 対局は sessionStorage（`shogi_local`）に置き、読み込み直すと続きから（終わった対局は結果のまま）。「トップへ戻る」で消す
- 結果のあと「もう一回」で先手と後手の名前（と補助の先手だけ・後手だけ）を入れかえる。「盤と補助を変える」で準備の画面へ
- CPU と対戦するモードは入れていない（オーナーへの最初の提案で「はじめは入れない」とした）

## 利用回数（stats.js）

「1回」は1対局。

| 項目 | 数えるとき・端末 |
|---|---|
| `room-create` | ルームができた（ホスト） |
| `start`・`players-2` | 対局が始まった（「はじめる」「もう一回」。ホスト） |
| `board-5`・`board-9` | 始めた対局の盤（5五将棋・本将棋。ルームはホスト、1台の画面はその端末） |
| `finish` | 対局がおわった（おわらせた手・投了・宣言を確定させた端末）。もどして終えなおしても数えない（`ended`） |
| `again` | おわったあと「もう一回」「対戦する人を選びなおす」（ホスト） |
| `local-start` | 1台の画面で対局を始めた（「はじめる」「最初からやりなおす」「もう一回」） |
| `local-finish` | 1台の画面の対局がおわった（もどしておわらせなおしても1回） |

## 意図的な逸脱

- **分割構成の RTDB アプリ**（リバーシと同じ）。engine.js は DOM に触らない
- **ホスト以外も進行の一部を行う**: 席の人が指す・投了する・宣言する・最後の手を確定させた端末が `finish` を数える・対局の記録が壊れたらホストの端末が待合室へもどす
- **観戦は参加者として players に入る**（席に入らない人）。見るだけの画面（書き込みゼロ）は別にある
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **端末なしの参加者は在室を持たない**（`proxies`）
- **勝ち負けを出す**（定番の対戦ゲームの結果。対戦成績の記録や順位はしない）

## 入れない機能

- 音（駒音も鳴らさない）
- CPU と対戦するモード・持ち時間・秒読み
- 待ったのやりとり（「1手もどす」はホストと1台の画面だけ）
- 棋譜の保存・書き出し、対戦成績の記録、順位
- 対局中の新しい対戦者（途中から入った人は観戦）

## 既知の制約（v1）

- 指し手の表記で、同じ種類の駒が3枚以上あって真ん中の駒が動くときなど、「右・左」で決まらない形は「上・引・寄」だけを付ける（めったにない）
- 盤の向きを変えると、筋の数字と段の漢数字も反対から並ぶ（盤といっしょに回る）
- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（少なめに出る側の誤差）
- イラスト・サムネイルはまだない（イラストは fal を使うので、作るかはオーナーに確かめる）

## メンター向けの心得（画面には出さない）

- はじめての子には5五将棋と「動ける所を見せる」から。駒の動きを覚えていない子には「駒に動ける向きを出す」も
- 1台の画面で遊ぶときは、子どもに「７六の歩を前に」のように言ってもらう。言いにくい子には、点のある所を指で示してもらう・チャットで送ってもらうでもよい
- 慣れてきたら「先手だけ」などにしてハンデとして使う。本将棋は時間がかかるので、セッションの残り時間を見て選ぶ
- 投了は自分で負けを認める大事な礼儀だが、子どもには無理に言わせない。「この対局をやめる」で区切ってもよい
- 勝ち負けで落ち込む子には、うまく取れた・詰ませかけた場面をほめる。観戦の子に「次はどこに指すと思う？」と聞くと、見ているだけの時間も楽しくなる
