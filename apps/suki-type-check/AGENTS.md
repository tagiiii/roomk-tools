# すきタイプチェック — アプリ固有仕様

仕様の正本は [docs/sukina-map-renewal-plan.md](../../docs/sukina-map-renewal-plan.md)。
質問文・タイプ定義・スコアリングを変えるときは、計画書とこのファイルを必ず同期させる。

## 目的

- 18問の選択式にこたえると「すき」の傾向がタイプとして出る診断ツール。結果は**会話のタネ**として使う。
- 対象は小学校高学年〜中学生。作戦会議（1対1・30分）でメンターが画面共有し、読み上げながら子どもが答える。
- 時間の目安は 説明2分＋回答10分（18問）＋結果を眺めて話す15分前後。
- 診断は評価ではない。当たっているかどうかではなく「近いところ・ちがうところ」を話すための材料。

## 方針転換の経緯（旧すきなことマップから）

旧 `apps/sukina-map/`（すきなことマップ）は、子どもの発言をメンターが自由入力してカード化し、
JSON で持ち回る方式だった。「好きなことを言って」で言葉が出てこない子には白紙からの入力が重く、
メンターの操作コストも大きかったため、選択式の診断に作り直した（旧フォルダはリダイレクトスタブ）。

旧 AGENTS.md の「診断・タイプ分け・おすすめ表示はしない」は**意図的に撤廃**した。
断定・全軸のパーセント表示・ランキング表示は**やってよい**（キャパグラフの「数値化しない」転換に続く例）。

残すガードレールは次の2つだけ。

- **タイプ間に優劣をつけない**: どのタイプの説明文も同じ熱量・同じ長さで肯定的に書く。欠点・苦手の記述はしない。
- **コンテンツガイドライン**（リポジトリ共通）: 学校・勉強・成績・登校・恋愛・ダーク系を質問・結果に出さない。

## 技術

- `index.html` + `app.js` + `style.css` の talk-card 型オフライン構成。Firebase 不使用。
- 永続化 API（localStorage / sessionStorage / IndexedDB / Cookie）は一切呼ばない。JSON入出力・fileMarker・インポート検証は持ち込まない。
- リロードで最初に戻る。**`beforeunload` 警告は出さない**（保存なしのツールとして潔く。再実行は10分）。
- CSS は `stc-` 接頭辞 + BEM。`.screen` / `.active` と `screen-xxx` 命名を使う。
- 共有 `../shared/css/design-system.css` と Material Symbols Rounded を使う。**絵文字は禁止**。
- パーセントバーは CSS のみで描画する（ライブラリ不使用）。
- `copyToClipboard` / `showToast` は `../shared/js/utils.js` から import する。
- 動的な DOM 挿入は必ず `esc()` を通す（現状ユーザー由来の文字列は存在しないが、流儀として維持する）。
- `stats.js?v=1` を組み込む。記録は「診断開始」`start` と「結果表示」`result` の**回数のみ**。回答内容・タイプ結果は送らない。
- `howto.js` を組み込む。旧マップの JSON について「以前の『すきなことマップ』で保存したファイルは、このツールでは使いません」と一言添える。

## 画面フロー

```text
screen-start    … 説明＋「はじめる」
  → screen-question … 1問ずつ。進捗「n / 18」表示。「ひとつ前にもどる」あり
  → screen-result   … タイプ発表＋全軸バー＋結果コピー＋「もういちどやる」
```

- 回答すると自動で次の問へ進む。「ひとつ前にもどる」で答え直せる（第1問では disabled）。
- 「もういちどやる」は回答をすべて捨てて `screen-start` に戻る。

## 質問セット（6軸 × 3問 = 18問）

質問は「どういうときに心が動くか」の抽象的な聞き方で統一する。具体的な活動名の列挙はしない。
軸の定義順（`AXES` の配列順）は、同点時の表示順にも使うため入れ替えない。

| # | 軸 | タイプ名 | アイコン |
|---|---|---|---|
| ① | からだ・うごき | うごいて楽しむ | `directions_run` |
| ② | つくる・ためす | つくってためす | `construction` |
| ③ | 表現する | ひらめきをかたちにする | `palette` |
| ④ | しらべる・きわめる | とことんしらべる | `travel_explore` |
| ⑤ | あつめる・ととのえる | あつめてととのえる | `inventory_2` |
| ⑥ | ひとと関わる | いっしょに楽しむ | `group` |
| — | （フラット判定用） | すきさがし | `explore` |

**出題順は 軸①→⑥を1問ずつ3周する固定順**（Q1=①-1, Q2=②-1, …, Q7=①-2, …）。
画面共有での読み上げ再現性のため、**シャッフルはしない**。

## スコアリング

- あてはまる=4 ／ やや当てはまる=3 ／ **どちらでもない**=2 ／ あまり当てはまらない=1 ／ 当てはまらない=0。
- 選択肢は**5件法を同格ボタン**で並べる。中間の「どちらでもない」だけ小さくしたり色を落としたりしない。まよったとき・答えたくないときの受け皿を兼ねる中間選択肢であり、パスは置かない。
- 軸スコア = その軸3問の平均。パーセント = `平均 ÷ 4 × 100`（四捨五入）。
- 全回答が採点対象になるため、判定対象外になる軸はない（回答途中の問だけが未計上）。
- **タイプ判定 = 最高スコアの軸**。
- **1位同点**: 「あなたは 〇〇×△△ のハイブリッドタイプ！」と2つを掛け合わせて発表し、説明文は両タイプの短縮版を併記する。3軸以上同点なら軸定義順の上位2つ。
- **フラット判定**: 全軸の最大平均が 2.0 以下（浮動小数対策で `2.0 + 1e-9` 以下、どの軸も「どちらでもない」を超えない） → 「すきさがしタイプ」（肯定的に書く）。

## 結果表示

上から順に固定。

1. タイプ発表（タイプ対応アイコン付き）
2. タイプ説明（抽象・2〜3文）
3. 「こういうものが好きかも」（具体例6〜8個）
4. 6軸すべてのパーセントバー（スコア順・数値テキスト併記・発表したタイプの軸だけアクセント色）
5. 2位への一言「〇〇タイプの気質もあります」
6. 会話プロンプト「近いなと思うところ、ちがうなと思うところはある？」
7. 「結果をコピー」＋「もういちどやる」

- 「2位への一言」は、**発表したタイプに含まれない軸のうち最上位**（0% は除く）を出す。ハイブリッド時は実質3位、該当なしのときは行ごと出さない。**すきさがしタイプ（フラット判定）のときも出さない**（見出しと矛盾して見えるため）。
- すきさがしタイプは具体例を持たないため、3 のかわりに「まずは、さいきん見たもの・さわったものから 話してみよう」の一文を置く。
- 結果コピーは Metalife チャット貼り付け用のプレーンテキスト（絵文字なし）。

```text
すきタイプチェック 結果
あなたは とことんしらべるタイプ！
・とことんしらべる 92%
・つくってためす 75%
（以下6軸すべて）
```

- コピー失敗時は**無反応にせず**エラートーストを出す（監査提案11の教訓）。連打によるリセット待ちはエラー扱いにしない。

## アクセシビリティ

- 選択肢は `<button>`、選択群は `role="radiogroup"` + `aria-checked`。
- 選択肢は `①〜⑤` の丸数字で番号付けし、`aria-label` に番号を含める（画面共有越しに「3番！」と答えられるように）。
- 選択状態は枠色 + 背景 + check アイコンで表す。色だけにしない。
- 次の問を描画したら、質問見出し（`tabindex="-1"`）にフォーカスを移す。画面の切り替え（開始→第1問・結果表示・「もういちどやる」）でも同様に見出しへフォーカスを移す。`showScreen()` を描画・focus より先に呼ぶこと（非表示要素への focus() は効かない）。
- タップターゲットは最小 44×44px、`:focus-visible` を明確にする。
- `prefers-reduced-motion` でアニメーションを無効化する。
- パーセントバーは必ず数値テキストを併記する（色と長さだけにしない）。

## 入れない機能

- 保存・JSON入出力・永続化（localStorage / sessionStorage / IndexedDB / Cookie / 外部保存）。
- タイプ間の優劣・順位づけ、欠点・苦手・「向いていないこと」の記述。
- 他人との比較、結果の共有ランキング、履歴・前回との差分表示。
- 質問のシャッフル、問数の可変、タイプの追加（軸は6つ＋フラットで固定）。
- おすすめの職業・進路の提示（`mirai-hikidashi` と同じく進路圧にしない）。
- 仕様にない画面・設定・便利機能。
