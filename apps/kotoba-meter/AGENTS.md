# ことばメーター

## 目的・使用シーン

出題者が思い浮かべた1〜5の程度をヒントから予想し、同時に公開する。数字は出題者の感覚で、感じ方の違いも楽しむゲーム。2〜20人、1ラウンド2〜3分。コトバ・ボドゲ・作戦会議。初回は大人（進行役）が出題すれば、子どもは数字のタップだけで参加できる。

Firebase Realtime Database + 匿名認証。単一 `index.html` にCSS/JSを収録し、`RoomkRTDB.initFirebase()`・サーバー時刻補正・共通CSS・howto・stats を使う。説明スライドは `slides.html`、E2E は `tests/kotoba-meter/`。

## 遊び方（ルール）

### ラウンドの流れ

`lobby`（準備）→ `hint`（出題者がヒントを考える）→ `vote`（予想）→ `result`（公開）→ 次のラウンド。進行役の「ここでおしまい」で `finished`。

- 進行役が制限時間と次の出題者を選んで「ラウンドを始める」。お題はランダム。
- 出題者は秘密の数字（1〜5）に合うことばを「ヒントを出す」（1〜60文字）。出題者は回答しない。進行役も出題者でなければ回答できる。
- ほかの人は1〜5をタップ。パス・選び直しは公開前まで。公開前は自分以外の回答値を出さない。
- 進行役の「回答を締め切って公開」で結果へ。未回答者がいれば確認ダイアログを出し、未回答のまま表示する。結果への遷移後は回答を受け付けない。
- 公開・やり直し・開始は進行役のみ。途中参加は lobby/result だけ（finished は不可）。
- 「正解」ではなく「出題者の数字」と表示する。メンターは共有用タブだけを画面共有し、感じ方の説明を必須にしない。成長評価・自動推薦は入れない。怖さ・学校等の題材は追加しない。

### 出題者の自動交代

`playerOrder` に作成・参加順のIDを保存し、参加者一覧もこの順に表示する。`rotationAfter` は完了したラウンドの出題者で、公開・時間切れで更新し、次の在室者を循環して選ぶ。退出したIDは順番の目印として残し、再参加は末尾。旧ルームは進行役を先頭にID順で補完する。

- 準備・結果画面で次の人を自動選択する。進行役の手動変更は `pendingPresenter` として room transaction で保存し、全画面・再読み込みに反映する（変更は進行役かつ lobby/result のみ）。手動で選んだ人の次は、その人の次の参加者。選ばれた人が抜けたら参加順の候補へ戻す。開始時に共有済みの選択と一致することを検査し、開始・公開・やり直しで手動指定を消す。結果の再読み込みで自動候補は変わらない。

### 制限時間

0（なし。初期値）・30・60・120・180秒。進行役が開始前に選ぶ。経過は全画面でサーバー補正時刻から計算し、再読み込みでリセットしない。

- 時間切れは進行役の timeout transaction で、参加順で次の出題者のラウンドへ進める（新しいお題・数字・開始時刻。古いヒント・回答・今回の点は破棄。点なし）。期限・フェーズ・round を再検査し、時間切れ後のヒント送信・お題変更は拒否する。
- 進行役が切断している間は進めず、復帰後に1ラウンドだけ進める。次の出題者が切断中、または2人未満なら lobby へ戻して止める。制限なしでは自動遷移しない。

### お題とヒント例

`THEMES` に21題（名前と1・5の目安）。開始時はランダムで、直前のお題とは続けない。お題は末尾に足す（「お題を変更する」は番号で送るので、開いたままの古いタブと番号の意味をそろえる）。個々のヒントに固定の正解数字を設定しない。「わくわく感」のヒントは本人の体験に限定せず、想像の場面でもよい。

- 出題者だけが hint フェーズで「お題を変更する」から別のお題を選べる。秘密の数字・開始時刻・入力中のヒントは変えない。送信時は現在のお題名も検査し、別タブでお題が変わったあとの古いヒント送信を拒否する。
- 出題中の出題者だけが、初期状態では閉じた「ヒント例を見る」を開ける。承認済みの21題×5例（`HINT_EXAMPLES`）を現在のお題に合わせて出し、数字は正解でなく感じ方の一例と説明する。秘密の数字に合わせた強調・自動入力はしない。回答者・みんなにみせる画面には出さず、ラウンド・出題者・お題が変わったら閉じる。例はクライアント内の参考文言で、ルームデータには保存しない。

### 点数（個人戦）

ピッタリメーター・ピタハメと同じく、競争を意図的に入れた例外（オーナー判断）。安全側へ勝手に戻さない。

- 予想した人: ぴったり2点、1つちがい1点、それ以外0点。パス・未回答は対象外。出題者: ぴったりの人が1人でもいれば2点、いなければ0点（端末なしの子が出題者でも同じ。進行役は代わりに出題したラウンドは予想しないので点なし）。
- 公開（reveal）の transaction で `roundPoints/{id}` を確定し、`scores/{id}` に足す。時間切れ・やり直しは点なし。開始・時間切れ・やり直しで `roundPoints` を消す。退出・外すとその人の `scores` も消す（入り直すと0点から）。
- 進行役は「そのほかの操作」の「点を0にもどす」（準備・結果の画面、確認あり）で `scores`・`roundPoints` を消せる。

### おしまい

進行役が「そのほかの操作」の「ここでおしまい」（準備・結果の画面、確認あり、1ラウンド以上たってから）で `finished` にする。点は残し、全員とみんなにみせる画面に「おしまい」「1位は○○さん！」（同点の1位は並べる。全員同点・点なしは「みんな同点！」）と最後の順位表を大きく出す。お題・ヒント・次の出題者は出さない。進行役の「もう一回あそぶ」で点を0にして lobby へ（`rotationAfter` も消し、参加した順の最初から）。ルームは消さない。

### 端末なしの参加者（しるしでヒントと同じ考え方）

- 進行役が「そのほかの操作」の「端末なしの参加者を足す」で名前を足す（準備・結果の画面。ニックネームの規則・同名不可・合計20人まで）。`players/{id}` に `proxy: true` で置き、`playerOrder` の末尾に加える。在室を持たないので、いつも遊べる人として扱う（接続待ちにならない・出題者の順番に入る・開始や時間切れの接続の検査を通る）。
- 「端末なし」の印は進行役の画面だけ。進行役は一覧の「外す」でいつでも外せる。
- 予想: 進行役の画面の「端末なしの参加者の予想（代わりに入力）」で子ごとに1〜5とパスを押す（`answer` に `as`）。入力値は公開前でも進行役の画面だけに出す（`proxyAnswers`）。
- 出題: その子が出題者の番は、進行役の画面に「○○さんの秘密の数字（代わりに入力）」とヒントの入力・ヒント例・お題の変更を出し、進行役がヒントを出す。そのラウンドは進行役は予想しない（サーバーでも止め、回答数と未回答の表示から除く）。
- 進め方（画面には出さない）: 予想の数字は**メンターへの個別のチャット**で送ってもらって入力する（声で言うと公開前にほかの子に分かる）。その子が出題者の番は、秘密の数字を個別のチャットで知らせ、子が考えたヒントを聞いて進行役が出す。進行役の画面に秘密の数字が出るので、共有するのは「みんなにみせる画面」にする。

## 画面

ヘッダー・パネル・ルームバー・フォーム・お題の枠は、しるしでヒント・スタンプあてゲームの型（`docs/development/ui.md`・`rtdb.md`「参加・共有の共通UI」）にそろえる。

- 入口: トップ（「ルームを作る」「ルームに参加する」「みんなにみせる画面をひらく」）→ それぞれの画面（「トップへ戻る」つき）。入力エラーはフォームの中、ルームの中のお知らせ・コピー結果は `RoomkRTDB.showToast` / `copyRoomCode` / `copyRoomLink`。
- ルームバー: コード・コピー（「コードをコピー」「リンクをコピー」「QRコードを出す」）・みんなにみせる画面・退出（進行役は「ルームを閉じる」）。「QRコードを出す」「みんなにみせる画面」のボタンと役割の札は進行役だけ。600px以下は「コード・役割・退出」と「コピーのボタン」の2行（進行役は3行）。進行役はPCでも「コード・役割・閉じる」と「ボタン」の2行（2026-10-22、「QRコードを出す」を足して1行に入らなくなったため。`:has(#watch-link:not([hidden]))`）。ルームの中ではヘッダーの説明文を隠す。
- 「QRコードを出す」（`id="show-qr"`。2026-10-22）: 「リンクをコピー」の隣で、進行役だけ（参加者のスマホのバーを2行のままにするため。参加者が QR を見せる場面はない）。スマホ・タブレットなど別の端末で入る人向けに、同じ参加用のリンクを QR コードにして画面の上に大きく出す（画面共有越しにカメラで読みとる）。`copyRoomLink` と同じ検査をしてから共通の `RoomkQR.show(code)`（`apps/shared/js/room-qr.js`）
- 進行の順: 見出し → 残り時間 → お題とヒント → 秘密の数字（出題者だけ）→ 予想 → 結果と点数 → 次のラウンド → そのほかの操作 → 参加している人。
- 表示を減らす（オーナー依頼「表示が多くてわかりづらい」）: 同じことを2回出さない（1・5の目安はお題の枠だけ。予想の欄に見出しを重ねない。結果の列に「出題者の数字」の札を付けない。進行役には「次の出題者」の帯を出さず選択欄だけ）。説明の一文は、することが画面から分からない場面だけ（準備・出題を待つ・時間切れ）。制限時間なしなら残り時間の行を出さない。予想したあとは「3 を選んだよ」だけ。
- 進行役がたまに使う操作（このラウンドをやり直す・点を0にもどす・ここでおしまい・端末なしの参加者を足す）は「そのほかの操作」（開くと出る）。主な操作（ラウンドを始める・回答を締め切って公開・もう一回あそぶ）は本文に置く。
- 1〜5は同じ5段階の色（`km-lv1`〜`km-lv5`）で、トップの飾り・予想のボタン・結果の列に使う。数字ボタンは同格の選択肢として主ボタンと混ぜない。結果は600px以下で1行ずつの並び。制限時間は丸いボタン（値は開始時に送るだけ）。
- 点数: 結果の名前に「+2」「+1」（0点には付けない）。その下に順位表（同点は同じ順位で次をとばす 1,1,3 方式。1位を金色。今回の点は「+◯」・出題者は「出題 +◯」・パス／未回答は「—」）。点がある間は待合室にも出す。
- 接続が切れたままの人には、進行役の一覧に「外す」を出す。一覧は内容が変わったときだけ作り直す（毎秒の再描画でボタンが消えないように）。

### みんなにみせる画面（`?watch=CODE`）

画面共有用。トップの「みんなにみせる画面をひらく」からコードを入れても開ける。操作権限を持たず、ヘッダーに目印を出す。1280×720・20人でも主要な部分を1画面に収める（E2E その5 で確認）。

- 待合室: 大きなルームコードと「①ルームに参加する ②ニックネーム ③コードを入れて参加する」。始まったら消す。次の出題者まで1画面に収める。
- お題とヒントは横に並べる。
- 結果: 結果の列（左2）と順位表（右1）を左右に並べる。結果のときだけ見出しの下の一文を消し、お題とヒントの枠を詰める。結果の1つの列に4人以上いれば数字ごとの横の行に切り替えて名前を詰める（`km-results--rows`）。順位表は上位8人までにし「ほか○人は、それぞれの画面で見られるよ。」と添える（参加者・進行役の画面は全員。下の順位の子を共有画面で目立たせない意味もある）。
- おしまい: 1位の発表と最後の順位表を大きく出す。

## データ（`kotobameter_rooms/{6文字コード}`）

- `status`: `lobby` / `hint` / `vote` / `result` / `finished`。進行役のやり直し、進行中の出題者の明示退出・外すで lobby に戻る。
- `host`（参加者ID）・`hostUid`（匿名認証UID）・`hostConnected` / `hostDisconnectedAt` / `createdAt` / `round`。参加者IDは参加ごとに作るUUIDで、ニックネームはキーにしない。
- `players/{id}`: `name`（1〜8文字、部屋内同名不可）・`uid`・`isHost`・`connections/{接続ID}: true`。端末なしの参加者は `proxy: true` で `uid`・`connections` を持たない。
- `playerOrder`（参加順のID。抜けた人の目印も残す）・`rotationAfter`・`pendingPresenter`。
- `hintSeconds`・`hintStartedAt`（サーバー時刻）・`timedOut`（直前の時間切れを知らせる表示用）。
- `theme`: `{name, low, high}`・`presenter`・`secret`（1〜5）・`hint`（最大60文字）。
- `answers/{id}`: 1〜5、パスは0。未回答はキーなし（RTDBのnullは削除になるため）。公開時の表示用データで0をnullへ変換する。
- `scores/{id}`（合計点）・`roundPoints/{id}`（今回の点。公開時に確定）。

## 操作と検査

作成・参加・開始・出題者の変更・お題の変更・ヒント・回答・公開・時間切れ・やり直し・外す・端末なしの参加者を足す・点を0にもどす・おしまい・もう一回あそぶ・退出は room transaction。操作開始時の round・役割・UID・部屋の有効期限・フェーズを再検査する。開始・時間切れの秘密の数字とお題の乱数は transaction の外で1回だけ決める。作成・参加は送信後切断を再試行し、同じ参加者ID・UIDが登録済みなら同じ参加として扱う。既存部屋は値の購読を先に始める。削除した部屋を古いデータで復元しない。

- 進行役だけ: 開始・出題者の変更・時間切れ・公開・やり直し・外す・端末なしの参加者を足す・点を0にもどす・おしまい・もう一回あそぶ。
- 出題者（端末なしの子の番は進行役）: お題の変更・ヒント。
- 回答: 本人（端末なしの子の分は進行役が `as` で）。端末なしの子の出題中は進行役自身の回答を止める。
- 外す: 接続が切れたままの参加者（`connections` が空）と端末なしの参加者だけ。進行役は外せない。退出と同じく行・回答・点を消し、出題中（hint/vote）の出題者ならラウンドをやり直す。外された人が戻ると参加の情報なしで参加画面へ戻り、同じニックネームで入り直せる。

## 秘密

出題者以外の画面には秘密の数字を出さない（端末なしの子が出題者のときは進行役にも出す）。公開前は自分以外の回答値を出さない（進行役が代わりに入力した端末なしの子の分は進行役にだけ出す）。**RTDBのデータそのものは匿名認証した利用者が読める**。ルートAGENTS.mdの性善説方針に従うUIレベルの秘匿。

## 切断・復帰・削除（意図的例外）

- ホストは onDisconnect で `hostConnected:false` / サーバー切断時刻を予約し、接続ごとに張り直す。ゲストはホスト切断中に操作を止める。
- ホスト切断中、参加者とみんなにみせる画面には「進行役の戻りを待っています」の待ち画面を重ねる（しるしでヒントと同じ形）。自分の通信の切断（「接続を確認しています」の帯）とは区別する。参加者は「退出する」、みんなにみせる画面は「トップへ戻る」で抜けられる。戻れば消えて続きから。進行役自身の画面には出さない。
- **ゲスト本体を切断時に消さない**。出題中の数字と回答を保つため、`connections/{接続ID}` のみ onDisconnect.remove する（たとえならべと同じ保持方式）。新しい接続IDに予約してから transaction で在室を検査・登録する。切断中は参加者一覧で「接続待ち」。進行役は未回答のまま公開・やり直し・外すができる。
- 同じタブの sessionStorage に部屋コード・参加者ID・UID・役割を保持する。復帰時に匿名認証UIDと保存役割、DB内の host/player を照合する。失われた参加者行は復元しない。別の端末や消したタブへの本人復帰は保証しない。
- ORPHAN_TTL_MS = 2分。サーバー時刻で判定し、次のアクセスで期限切れを transaction 削除。作成直後は切断中＋作成時刻とし、presence 未確立のまま送信元が消えても永久に部屋を残さない。
- **result・finished では自動削除しない**（話す時間と次ラウンドを保証する公認バリアント）。進行役の「ルームを閉じる」・切断TTL・次回アクセス時の掃除で削除。remove 経路の前に自接続の onDisconnect を取り消す。
- 画面の1秒タイマーは Firebase 購読済みキャッシュを読むだけで、1秒ごとのDB読み取りではない。退出・終了でタイマーとルームの listener を解除する。

## 利用回数

1回＝1ラウンド。進行を確定した端末だけで計測する。再描画・再読み込みでは計測しない。ニックネーム・ヒント・回答値は統計に送らない。

- `room-create`: 部屋作成と presence 確立後。
- `start` / `players-{N}`: 開始 transaction 確定後。Nは出題者・端末なしの参加者を含む全参加者。
- `again`: result からの次ラウンド開始確定後（start も加算）。
- `finish`: 一斉公開（reveal）transaction 確定後。**「ここでおしまい」の回数ではない**（おしまいは計測しない）。
