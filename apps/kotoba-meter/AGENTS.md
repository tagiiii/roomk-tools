# ことばメーター

## 目的・使用シーン

出題者が思い浮かべた1〜5の程度をヒントから予想し、同時に公開する。感じ方の違いを楽しむゲーム。2〜20人、1ラウンド2〜3分。コトバ・ボドゲ・作戦会議。初回は大人（進行役）が出題すれば、子どもは数字のタップだけで参加できる。

## 技術・ファイル構成

Firebase Realtime Database + 匿名認証、単一 `index.html` にCSS/JSを収録。`RoomkRTDB.initFirebase()`、サーバー時刻補正、共通CSS、howto、statsを利用する。

## 状態とデータ

`kotobameter_rooms/{6文字コード}`:

- `status`: `lobby → hint → vote → result`。進行役のやり直し、進行中の出題者の明示退出で lobby に戻る。
- `host` は参加者ID、`hostUid` は匿名認証UID。参加者IDは毎回の参加時に作るUUIDで、ニックネームはキーにしない。
- `hostConnected` / `hostDisconnectedAt` / `createdAt` / `round`
- `hintSeconds`: 0・30・60・120・180秒。0は制限なし（初期値）。`hintStartedAt`: サーバー時刻。`timedOut`: 直前の時間切れを知らせる表示用フラグ。
- `theme`: `{name, low, high}`、`presenter`: 出題者ID、`secret`: 1〜5、`hint`: 最大60文字。
- `players/{id}`: `name`（1〜8文字、部屋内同名不可）、`uid`、`isHost`、`connections/{接続ID}: true`。
- `answers/{id}`: 1〜5、パスは0。未回答はキーなし（RTDBのnullは削除になるため）。公開時の表示用データで0をnullへ変換する。

作成・参加・出題・回答・公開・やり直し・退出はroom transaction。操作開始時のround、役割、UID、部屋の有効期限、フェーズを再検査する。開始・時間切れ時の秘密の数字とお題の乱数はtransactionの外で1回だけ決める。作成・参加は送信後切断を再試行し、同じ参加者ID・UIDが登録済みなら同じ参加として扱う。既存部屋は値の購読を先に始める。削除した部屋を古いデータで復元しない。

## 秘密と遊び方

出題者以外の画面には秘密の数字を出さず、公開前は自分以外の回答値を表示しない。共有画面は `?watch=CODE` で開き、操作権限を持たない。**RTDBのデータそのものは匿名認証した利用者が読める**。これはルートAGENTS.mdの性善説方針に従うUIレベルの秘匿であり、サーバー側で秘密を隔離していた旧Python試作とは異なる。

出題者は回答しない。進行役も出題者でなければ回答できる。パス・回答変更は公開前まで可能。公開・やり直しは進行役のみ。回答前の人がいる公開は確認ダイアログを出す。参加者の途中入室はlobby/resultに限定。結果画面で出題者と制限時間を選び、次のラウンドを始める。「回答を締め切って公開」で未回答者がいても結果へ進め、未回答は未回答のまま表示する。結果への遷移後は回答を受け付けない。

得点・順位・成長評価・自動推薦は入れない。「正解」ではなく「出題者の数字」と表示する。メンターは共有用タブだけを画面共有し、感じ方の説明を必須にしない。怖さ・学校等の題材は追加しない。

## ランダムなお題と制限時間（2026-10-20 オーナー承認）

開始時のお題はランダムで、直前のお題とは連続させない。出題者だけがhintフェーズで別のお題を選んで変更できる。変更で秘密の数字・開始時刻・入力中のヒントは変えず、ヒント例は新しいお題に切り替えて閉じる。送信時は現在のお題名も検査し、別タブでお題が変わったあとの古いヒント送信を拒否する。

進行役が開始前に制限時間を選ぶ。経過時間は全画面でサーバー補正時刻から計算し、再読み込みでリセットしない。時間切れは進行役のtimeout transactionで参加順で次の出題者のラウンドへ進める（新しいお題・数字・開始時刻、古いヒント・回答は破棄）。期限・フェーズ・roundを再検査し、時間切れ後のヒント送信・お題変更は拒否する。進行役が切断している間は進めず、復帰後に1ラウンドだけ進める。次の出題者が切断中または2人未満ならlobbyへ戻して停止する。制限なしでは自動遷移しない。

## お題（2026-10-20 オーナー承認）

初期の大きさ・やわらかさ・あたたかさに、重さ・速さ・音の大きさ・甘さ・わくわく感を追加し、合計8題。1・5の目安は `THEMES` に定義する。「わくわく感」のヒントは本人の体験に限定せず、想像の場面でもよい。個々のヒントに固定の正解数字を設定しない。

出題中の出題者だけが、初期状態では閉じた「ヒント例を見る」を開ける。承認済みの8題×5例を現在のお題に合わせて表示し、数字は正解でなく感じ方の一例と説明する。秘密の数字に合わせた強調・自動入力はしない。回答者・共有画面には表示せず、ラウンドや出題者が変わったら閉じる。例はクライアント内の参考文言で、ルームデータには保存しない。

## 切断・復帰・削除（意図的例外）

- ホストは onDisconnect で `hostConnected:false` / サーバー切断時刻を予約。接続ごとに張り直す。ゲストはホスト切断中に操作を止める。
- **ゲスト本体を切断時に消さない**。出題中の数字と回答を保つため、`connections/{接続ID}` のみ onDisconnect.remove する（たとえならべと同じ保持方式）。新しい接続IDに予約してからtransactionで在室を検査・登録する。切断中は参加者一覧で「接続待ち」。進行役は必要なら未回答のまま公開・ラウンドをやり直せる。
- 同じタブのsessionStorageに部屋コード・参加者ID・UID・役割を保持。復帰時に匿名認証UIDと保存役割、DB内のhost/playerを照合する。失われた参加者行は復元しない。別の端末や消したタブへの本人復帰は保証しない。
- ORPHAN_TTL_MS = 2分。サーバー時刻で判定し、次のアクセスで期限切れをtransaction削除。作成直後は切断中＋作成時刻とし、presence未確立のまま送信元が消えても永久に部屋を残さない。
- **resultでは自動削除しない**。話す時間と次ラウンドを保証する公認バリアント。進行役の明示終了・切断TTL・次回アクセス時の掃除で削除。remove経路の前に自接続のonDisconnectを取り消す。
- ローカル表示確認の1秒タイマーはFirebase購読済みキャッシュを読むだけで、1秒ごとのDB読み取りではない。退出・終了でタイマーとルームのlistenerを解除する。

## 利用回数

1回＝1ラウンド。進行を確定した端末だけで計測する。

- `room-create`: 部屋作成とpresence確立後。
- `start` / `players-{N}`: 開始transaction確定後。Nは出題者を含む全参加者。
- `again`: resultからの次ラウンド開始確定後（startも加算）。
- `finish`: 一斉公開transaction確定後。

再描画・再読み込みでは計測しない。ニックネーム・ヒント・回答値は統計に送らない。

## 出題者の自動交代（2026-10-20 オーナー承認）

`playerOrder`に作成・参加順のIDを保存し、参加者一覧もこの順に表示する。`rotationAfter`は完了したラウンドの出題者。公開・時間切れで更新し、次の在室者を循環して選ぶ。退出したIDは順番の目印として残し、再参加は末尾。旧ルームは進行役を先頭にID順で補完する。結果画面では次の人を自動選択し、手動選択は同じ画面の更新で保持する。手動で選んだ人の次は、その人の次の参加者になる。結果の再読み込みでも自動候補は変わらない。時間切れでは次の人で自動開始するが、次の人が切断中なら準備画面で待つ（進行役の手動変更も可能）。
