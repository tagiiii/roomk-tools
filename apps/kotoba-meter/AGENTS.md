# ことばメーター

## 目的・使用シーン

出題者が思い浮かべた1〜5の程度をヒントから予想し、同時に公開する。感じ方の違いを楽しむゲーム。2〜20人、1ラウンド2〜3分。コトバ・ボドゲ・作戦会議。初回は大人（進行役）が出題すれば、子どもは数字のタップだけで参加できる。

## 技術・ファイル構成

Firebase Realtime Database + 匿名認証、単一 `index.html` にCSS/JSを収録。`RoomkRTDB.initFirebase()`、サーバー時刻補正、共通CSS、howto、statsを利用する。

## 状態とデータ

`kotobameter_rooms/{6文字コード}`:

- `status`: `lobby → hint → vote → result`（→ 進行役の「ここでおしまい」で `finished`）。進行役のやり直し、進行中の出題者の明示退出で lobby に戻る。
- `host` は参加者ID、`hostUid` は匿名認証UID。参加者IDは毎回の参加時に作るUUIDで、ニックネームはキーにしない。
- `hostConnected` / `hostDisconnectedAt` / `createdAt` / `round`
- `hintSeconds`: 0・30・60・120・180秒。0は制限なし（初期値）。`hintStartedAt`: サーバー時刻。`timedOut`: 直前の時間切れを知らせる表示用フラグ。
- `theme`: `{name, low, high}`、`presenter`: 出題者ID、`secret`: 1〜5、`hint`: 最大60文字。
- `players/{id}`: `name`（1〜8文字、部屋内同名不可）、`uid`、`isHost`、`connections/{接続ID}: true`。端末なしの参加者は `proxy: true` で、`uid`・`connections` を持たない。
- `answers/{id}`: 1〜5、パスは0。未回答はキーなし（RTDBのnullは削除になるため）。公開時の表示用データで0をnullへ変換する。

作成・参加・出題・回答・公開・やり直し・退出はroom transaction。操作開始時のround、役割、UID、部屋の有効期限、フェーズを再検査する。開始・時間切れ時の秘密の数字とお題の乱数はtransactionの外で1回だけ決める。作成・参加は送信後切断を再試行し、同じ参加者ID・UIDが登録済みなら同じ参加として扱う。既存部屋は値の購読を先に始める。削除した部屋を古いデータで復元しない。

## 秘密と遊び方

出題者以外の画面には秘密の数字を出さず、公開前は自分以外の回答値を表示しない。みんなにみせる画面は `?watch=CODE` で開き（トップの「みんなにみせる画面をひらく」からコードを入れても開ける）、操作権限を持たない。**RTDBのデータそのものは匿名認証した利用者が読める**。これはルートAGENTS.mdの性善説方針に従うUIレベルの秘匿であり、サーバー側で秘密を隔離していた旧Python試作とは異なる。

出題者は回答しない。進行役も出題者でなければ回答できる。パス・回答変更は公開前まで可能。公開・やり直しは進行役のみ。回答前の人がいる公開は確認ダイアログを出す。参加者の途中入室はlobby/resultに限定。結果画面で出題者と制限時間を選び、次のラウンドを始める。「回答を締め切って公開」で未回答者がいても結果へ進め、未回答は未回答のまま表示する。結果への遷移後は回答を受け付けない。

個人戦の点と順位を出す（2026-10-21 オーナー判断。下の「点数」節。ピッタリメーター・ピタハメと同じく競争を意図的に入れた例外。安全側へ勝手に戻さない）。成長評価・自動推薦は入れない。「正解」ではなく「出題者の数字」と表示する。メンターは共有用タブだけを画面共有し、感じ方の説明を必須にしない。怖さ・学校等の題材は追加しない。

## ランダムなお題と制限時間（2026-10-20 オーナー承認）

開始時のお題はランダムで、直前のお題とは連続させない。出題者だけがhintフェーズで別のお題を選んで変更できる。変更で秘密の数字・開始時刻・入力中のヒントは変えず、ヒント例は新しいお題に切り替えて閉じる。送信時は現在のお題名も検査し、別タブでお題が変わったあとの古いヒント送信を拒否する。

進行役が開始前に制限時間を選ぶ。経過時間は全画面でサーバー補正時刻から計算し、再読み込みでリセットしない。時間切れは進行役のtimeout transactionで参加順で次の出題者のラウンドへ進める（新しいお題・数字・開始時刻、古いヒント・回答は破棄）。期限・フェーズ・roundを再検査し、時間切れ後のヒント送信・お題変更は拒否する。進行役が切断している間は進めず、復帰後に1ラウンドだけ進める。次の出題者が切断中または2人未満ならlobbyへ戻して停止する。制限なしでは自動遷移しない。

## お題（2026-10-20 オーナー承認）

初期の大きさ・やわらかさ・あたたかさに、重さ・速さ・音の大きさ・甘さ・わくわく感を追加し、合計8題。2026-10-21 のオーナー承認で、明るさ・長さ・高さ・広さ・冷たさ・すっぱさ・からさ・いいにおい・キラキラ感・のんびり感・深さと、クスッと笑える方向のもふもふ度・びっくり度を追加し、合計21題（候補のうち、へんてこ度・くすぐったさ・むずむず感・はらぺこ度・ドヤ顔度・ずるずる度は採用しなかった）。お題は末尾に足す（「お題を変更する」は番号で送るので、開いたままの古いタブと番号の意味をそろえる）。1・5の目安は `THEMES` に定義する。「わくわく感」のヒントは本人の体験に限定せず、想像の場面でもよい。個々のヒントに固定の正解数字を設定しない。

出題中の出題者だけが、初期状態では閉じた「ヒント例を見る」を開ける。承認済みの21題×5例を現在のお題に合わせて表示し、数字は正解でなく感じ方の一例と説明する。秘密の数字に合わせた強調・自動入力はしない。回答者・みんなにみせる画面には表示せず、ラウンドや出題者が変わったら閉じる。例はクライアント内の参考文言で、ルームデータには保存しない。

## 切断・復帰・削除（意図的例外）

- ホストは onDisconnect で `hostConnected:false` / サーバー切断時刻を予約。接続ごとに張り直す。ゲストはホスト切断中に操作を止める。
- ホスト切断中、参加者とみんなにみせる画面には「進行役の戻りを待っています」の待ち画面を重ねる（2026-10-21。しるしでヒントと同じ形）。自分の通信の切断（「接続を確認しています」の帯）とは区別する。参加者は「退出する」、みんなにみせる画面は「トップへ戻る」で抜けられる。進行役が戻れば消えて続きから、2分戻らなければ既存のTTLでルームを終了する。進行役自身の画面には出さない。
- **ゲスト本体を切断時に消さない**。出題中の数字と回答を保つため、`connections/{接続ID}` のみ onDisconnect.remove する（たとえならべと同じ保持方式）。新しい接続IDに予約してからtransactionで在室を検査・登録する。切断中は参加者一覧で「接続待ち」。進行役は必要なら未回答のまま公開・ラウンドをやり直せる。
- 接続が切れたままの参加者（`connections` が空）は、進行役が参加者の一覧の「外す」で外せる（2026-10-21 オーナー依頼）。room transaction で接続なし・進行役でないことを再検査し、退出と同じく行と回答を消す（`playerOrder` の目印は残す）。出題中（hint/vote）の出題者ならラウンドをやり直して lobby へ。外された人が戻ると参加の情報なしで参加画面へ戻り、同じニックネームで入り直せる。つながっている人・進行役には出さない。一覧は内容が変わったときだけ作り直す（毎秒の再描画でボタンが消えないように）。
- 同じタブのsessionStorageに部屋コード・参加者ID・UID・役割を保持。復帰時に匿名認証UIDと保存役割、DB内のhost/playerを照合する。失われた参加者行は復元しない。別の端末や消したタブへの本人復帰は保証しない。
- ORPHAN_TTL_MS = 2分。サーバー時刻で判定し、次のアクセスで期限切れをtransaction削除。作成直後は切断中＋作成時刻とし、presence未確立のまま送信元が消えても永久に部屋を残さない。
- **resultでは自動削除しない**。話す時間と次ラウンドを保証する公認バリアント。進行役の明示終了・切断TTL・次回アクセス時の掃除で削除。remove経路の前に自接続のonDisconnectを取り消す。
- ローカル表示確認の1秒タイマーはFirebase購読済みキャッシュを読むだけで、1秒ごとのDB読み取りではない。退出・終了でタイマーとルームのlistenerを解除する。

## 利用回数

1回＝1ラウンド。進行を確定した端末だけで計測する。

- `room-create`: 部屋作成とpresence確立後。
- `start` / `players-{N}`: 開始transaction確定後。Nは出題者を含む全参加者。
- `again`: resultからの次ラウンド開始確定後（startも加算）。
- `finish`: 一斉公開transaction確定後。

再描画・再読み込みでは計測しない。ニックネーム・ヒント・回答値は統計に送らない。

## 出題者の自動交代（2026-10-20 オーナー承認）

`playerOrder`に作成・参加順のIDを保存し、参加者一覧もこの順に表示する。`rotationAfter`は完了したラウンドの出題者。公開・時間切れで更新し、次の在室者を循環して選ぶ。退出したIDは順番の目印として残し、再参加は末尾。旧ルームは進行役を先頭にID順で補完する。結果画面では次の人を自動選択し、手動選択は同じ画面の更新で保持する。手動で選んだ人の次は、その人の次の参加者になる。結果の再読み込みでも自動候補は変わらない。時間切れでは次の人で自動開始するが、次の人が切断中なら準備画面で待つ（進行役の手動変更も可能）。

## 次の出題者の共有表示（2026-10-20 オーナー承認）

準備・結果画面で、参加者全員とみんなにみせる画面に次の出題者を表示する。進行役の手動変更は`pendingPresenter`としてroom transactionで保存し、再読み込み・別画面にも反映する。変更は進行役かつlobby/resultのみ。選ばれた人の退出時は参加順の候補へ戻す。開始時に共有済みの選択と一致することを検査し、開始・公開・やり直しで手動指定を消す。表示はtextContentで行う。

## 画面の構成（2026-10-20 他アプリにそろえて刷新）

ヘッダー・パネル・ルームバー・フォーム・お題の枠は、しるしでヒント・スタンプあてゲームの型（`docs/development/ui.md`・`rtdb.md`「参加・共有の共通UI」）にそろえる。

- 入口: トップ（「ルームを作る」「ルームに参加する」「みんなにみせる画面をひらく」）→ それぞれの画面（「トップへ戻る」つき）。入力エラーはフォームの中に出し、ルームの中のお知らせ・コピーの結果は `RoomkRTDB.showToast` / `copyRoomCode` / `copyRoomLink` で出す。
- ルームバーにコード・コピー・みんなにみせる画面・退出（進行役は「ルームを閉じる」）をまとめる。「みんなにみせる画面」のボタンは進行役だけに出す（しるしでヒント・スタンプあてゲームと同じ。2026-10-21）。600px以下では「コード・役割・退出」と「コピーのボタン」の2行にする（進行役は3行）。みんなにみせる画面ではヘッダーに目印を出し、操作は出さない。
- 進行の順: 見出し → 残り時間 → お題 → 秘密の数字（出題者だけ）→ ヒント → 予想 → 結果 → 次のラウンド（準備・結果画面）→ 参加している人。
- 1〜5は同じ5段階の色（`km-lv1`〜`km-lv5`）で、トップの飾り・予想のボタン・結果の列に使う。数字ボタンは同格の選択肢として主ボタンと混ぜない。結果は600px以下で1行ずつの並びにする。
- 制限時間は丸いボタンで選ぶ（値は開始時に送るだけで、ルームデータの形は変えない）。
- みんなにみせる画面は1280×720で結果の「話してみよう」まで1画面に収める。20人でも収める（2026-10-21 E2E その5 で確認）。そのため、みんなにみせる画面ではお題とヒントを横に並べ、結果の1つの列に4人以上いるときは数字ごとの横の行に切り替えて名前を詰める（`km-results--rows`）。少人数のときは列のまま。
- みんなにみせる画面の待合室（lobby）では、大きなルームコードと「①ルームに参加する ②ニックネーム ③コードを入れて参加する」を出す（2026-10-21）。始まったら消す。1280×720で次の出題者まで1画面に収める。

## 端末なしの参加者（2026-10-21 オーナー依頼。しるしでヒントと同じ考え方）

- 進行役が準備・結果の画面で「端末なしの参加者を足す」で名前を足す（ニックネームの規則・同名不可・合計20人まで）。`players/{id}` に `proxy: true` で置き、`playerOrder` の末尾に加える。在室を持たないので、いつも遊べる人として扱う（接続待ちにならない・出題者の順番に入る・開始や時間切れの接続の検査を通る）。
- 「端末なし」の印は進行役の画面だけに出す（子どもどうしの画面・みんなにみせる画面で区別しない）。進行役は一覧の「外す」でいつでも外せる。
- 予想: 進行役の画面に「端末なしの参加者の予想（代わりに入力）」の欄を出し、子ごとに1〜5とパスを押す（`answer` に `as`）。サーバー側で進行役であること・相手が端末なしの参加者であることを検査する。入力した値は公開前でも進行役の画面だけに出す（確認用。`proxyAnswers`）。
- 出題: その子が出題者の番は、進行役の画面に「○○さんの秘密の数字（代わりに入力）」とヒントの入力・ヒント例・お題の変更を出し、進行役がヒントを出す（`theme`・`hint` を進行役にも許す）。そのラウンドは進行役は予想しない（サーバーでも止め、回答数と未回答の表示から除く）。
- 進め方（画面には出さない）: 端末なしの子の予想は、数字を**メンターへの個別のチャット**で送ってもらって入力する（声で言うと公開前にほかの子に分かる）。その子が出題者の番は、秘密の数字を個別のチャットで知らせ、子が考えたヒントを聞いて進行役が出す。進行役の画面に秘密の数字が出るので、共有するのは「みんなにみせる画面」にする。

## 点数（個人戦。2026-10-21 オーナー判断）

- 予想した人: ぴったり2点、1つちがい1点、それ以外0点。パス・未回答は点の対象外。出題者: ぴったりの人が1人でもいれば2点、いなければ0点（端末なしの子が出題者でも同じ。進行役は代わりに出題したラウンドは予想しないので点なし）。
- 公開（reveal）の transaction で `roundPoints/{id}`（今回の点）を確定し、`scores/{id}`（合計）に足す。時間切れ・やり直しのラウンドは点なし。開始・時間切れ・やり直しで `roundPoints` を消す。退出・外すとその人の `scores` も消す（入り直すと0点から）。
- 表示: 結果の名前に「+2」「+1」（0点には付けない）。その下に「点数」の順位表（同点は同じ順位で次をとばす 1,1,3 方式。1位を金色。今回の点は「+◯」・出題者は「出題 +◯」・パス／未回答は「—」）。点がある間は待合室にも出す。
- 進行役は「点を0にもどす」（準備・結果の画面、確認あり）で `scores` と `roundPoints` を消せる。
- みんなにみせる画面の結果では、結果の列（左2）と順位表（右1）を左右に並べ、順位表まで1280×720に収める（2026-10-21）。そのため結果のときだけ見出しの下の一文を消し、お題とヒントの枠を詰める。共有画面の順位表は上位8人までにして「ほか○人は、それぞれの画面で見られるよ。」と添える（参加者・進行役の画面は全員。下の順位の子を共有画面で目立たせない意味もある）。20人でも収まることを E2E その5 で確認。
- おしまい（2026-10-21 オーナー依頼）: 進行役が準備・結果の画面の「ここでおしまい」（確認あり。1ラウンド以上たってから）で `status: finished` にする。点（`scores`）は残し、全員とみんなにみせる画面に「おしまい」「1位は○○さん！」（同点の1位は並べる。全員同点・点なしは「みんな同点！」）と最後の順位表を大きく出す。お題・ヒント・次の出題者は出さない。おしまいの間は参加できない。進行役の「もう一回あそぶ」で点を0にして lobby へ（`rotationAfter` も消し、参加した順の最初から）。ルームは消さない（進行役の「ルームを閉じる」か、切断TTLで消える）。
