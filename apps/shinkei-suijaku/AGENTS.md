# 神経衰弱 — アプリ固有仕様

共通の権限・品質基準はルート [AGENTS.md](../../AGENTS.md)。

## 目的・使用シーン

裏になったカードを2枚めくって同じ絵をそろえる、定番の遊び。メンターなどとゆっくり遊ぶ。

> 経緯: 2026-11-12 オーナーの依頼（リバーシのようにメンターなどとゆっくり遊べる新しいツール・小学生でもルールがすぐわかるもの・幅広い層が遊べるよう激ムズも・CPU 対戦も）で `drafts/shinkei-suijaku/` に試作 → 同日オーナーが「この形で本体化」と承認。

> 2026-11-16 オーナー「神経衰弱をルーム型にしてほしい」。同日オーナーが決めた: ルームは2〜6人／1台の画面（CPU 対戦・人どうし）は残す／`database.rules.json` に `shinkeisuijaku_rooms` を足してよい。ルームまわりは [興味スゴロク](../kyoumi-sugoroku/AGENTS.md) の作り（1台の画面＋ルーム・2〜6人の手番制・端末なしの参加者・ホストも遊ぶかを選ぶ・切断と再接続）を土台にした。

- 名前は「神経衰弱」（伝統的なトランプ遊びの一般名称。app-registration.md「アプリ名のつけかた」の例外。2026-11-12 オーナー決定）
- 既製のカードの絵柄は使わない。絵は Material Symbols と、自前で描く図形

### セッション条件（ツール一覧のカードと同じ）

| 項目 | 値 |
|---|---|
| 人数 | 1〜6人（1台の画面: CPU と対戦は1人、人どうしは2〜4人。ルーム: 2〜6人） |
| 目安時間 | 5〜15分 |
| 利用シーン | ボドゲクラブ・ひろば・作戦会議（`bodoge hiroba sakusen`） |
| 話す量 | 選ぶだけ・話さなくてよい（`pick silent`） |
| 自分の話 | 外の題材で遊べる（`outside`） |

`silent` は、ルームで自分の端末からめくれるようになったので 2026-11-16 に付けた（1台の画面では、押すのはメンターで、子どもは番号を声かチャットで伝える）。

## 画面構成・フロー

1. **トップ**（`#screen-top`・入口の型 `.app-entry`）: 「ルームを作る」「ルームに参加する」「1台の画面であそぶ」
2. **1台の画面の設定**（`#screen-local`）: 対戦の相手・CPU の強さ（CPU のときだけ）・人数（人どうしのときだけ）・名前・むずかしさ →「はじめる」
3. **ルームを作る**（`#screen-create`）・**ルームに参加する**（`#screen-join`。名前 → ルームコード → 参加する）
4. **待合室**（`#screen-waiting`）: 遊ぶ人の一覧・むずかしさの要約。ホストは「ホストもいっしょに遊ぶ」・むずかしさ・端末のない人を足す・「はじめる」
5. **遊ぶ画面**（`#ss-app`。1台の画面・ルーム共通）: 上の帯（名前・むずかしさ・1台の画面は「設定にもどる」、ルームのホストは「待合室にもどる」）／名前の札（番の印・ペアの数）／ひとことの案内／盤。ルームでは上にルームのバー（コードをコピー・リンクをコピー・QRコードを出す・退出する／ルームを閉じる）
6. **おわり**: 盤の上に「ぜんぶそろった！」の面。1台の画面は「もう一回」（同じ設定・はじめの人を順に交代）と「設定にもどる」。ルームはホストだけ「もう一回」と「待合室にもどる」、ほかの人には「ホストが「もう一回」を押すのを待ってね。」

1台の画面は、読み込み直すとトップにもどる（続きは残さない）。ルームは読み込み直すと同じルームの同じ場面に戻る。

## ルールと設定

| 項目 | 内容 |
|---|---|
| 対戦の相手（1台の画面） | CPU（はじめの値）／人どうし（2〜4人・1台で交代） |
| むずかしさ | かんたん 12枚／ふつう 20枚／むずかしい 30枚／激ムズ 40枚（`data.js` の `levels`） |
| ふつうの絵 | Material Symbols の絵25種類からくじで選ぶ（`icons`） |
| 激ムズの絵 | 形（丸・三角・四角・星・ハート）× 数（1〜4）の20ペア。形も数も同じカードがペア。色は形ごとに決まっていて、色だけで見分ける所はない |
| 番 | 2枚めくって同じ絵ならもらえて、もう1回。ちがったら裏にもどして次の人 |
| カードの番号 | 裏にも表にも出す（画面共有で「5番と12番」と伝えられるように）。40まであるので丸数字ではなくふつうの数字（ui.md「選択肢・カードの番号付け」からの意図した例外） |
| 取ったカード | 表のまま薄くして場に残す。だれが取ったかは出さない |
| 待ち時間 | ちがったカードは1.6秒見せてからもどす。そろったカードは0.8秒。CPU は1枚ごとに0.9秒おく（`app.js` の `T`）。`?fast=1` で短くなる（確かめる用。ルームでも同じ） |
| 音 | 鳴らさない |

### CPU

| 強さ | 覚え方（`data.js` の `cpuLevels`） |
|---|---|
| よわい | めくられたカードを3割覚える。覚えているペアがあっても、半分は取りにいかない |
| ふつう（はじめの値） | 65%覚える |
| つよい | すべて覚える |

めくり方（`cpuTurn`）: 覚えているペアがあれば取る。なければ知らないカードを1枚めくり、相手を覚えていればそれを、いなければ知らないカードをもう1枚めくる。
覚えるのは、人がめくったカードも CPU がめくったカードも同じ（`observe`）。
強さの値は 2026-11-12 に AI が仮に決め、同日オーナーが「そのままで」と決めた。

### 結果の出し方

- 対戦中、名前の札に全員のペアの数を出す（0ペアもふくむ）。ふつうの神経衰弱と同じ形（2026-11-12 オーナーに「出したままにする」と伝えたうえで本体化の承認）
- おわりは、いちばん多く取った人の名前とペアの数だけ（全員同じなら「引き分け」）。順位の一覧は出さない

## ルーム（2026-11-16）

| 項目 | 内容 |
|---|---|
| 人数 | 遊ぶ人2〜6人（端末なしの参加者もふくむ）。端末なしの参加者は4人まで。2人そろうまで「はじめる」は押せない |
| ホストも遊ぶか | 「ホストもいっしょに遊ぶ」（`hostPlays`。はじめはオン。1対1で遊ぶことが多く、秘密の情報がないため）。外すとホストは進行だけ（一覧に「進行役」・札に出ない・人数に数えない）。切りかえは待合室だけ |
| むずかしさ | ホストが待合室で選ぶ（1台の画面と同じ4段階）。参加者の待合室には要約だけ |
| 順番 | 参加した順（ホストが遊ぶときはホストが最初）。「もう一回」ではじめの人を1人ずつずらす |
| めくれる人 | 番の人の端末と、ホスト（だれの番でも代わりにめくれる。端末なしの参加者の番はホストがめくる）。番でない人の盤は押せない |
| めくったカード | 1枚めは、みんなの画面ですぐ表になる。2枚めを押すと、その場で結果を決める（そろえば取って同じ人がもう1回、ちがえば次の人へ）。2枚は各端末でしばらく表のまま見せ（1台の画面と同じ時間）、その間はだれも押せない。見せている間の札の「番」とペアの数は、めくった人の番・増える前のまま |
| すばやく押したとき | 書き込みの途中・そろった2枚を見せている間に押したカードは、はじめの1枚だけ覚えて、終わってからめくる。押した時点と対戦か番が変わっていたら捨てる（ホストは番に関係なくめくれるので、続けて押したカードが次の人の1枚めにならないように。確かめは書き込みの中で行う）。ちがった2枚を見せている間に押したカードは覚えない（番が替わる所のため） |
| いない人 | めくる番の人が退出・切断して4秒もどらなければ、ホストの端末がめくりかけを裏にもどして次の人へとばす。自分の番で退出したときは、その場で次の人へ。名前とペアの数はゲームが終わるまで残り、札に「つながっていない」 |
| 途中参加 | 遊んでいる途中は新しく入れない（「カードがぜんぶなくなったら参加できるよ」）。このゲームで遊んでいた人は、同じ端末・同じ名前で入りなおせる。おわりの画面のあいだは新しい人も入れて（このゲームの名前は、その名前の端末だけが使える）、ホストの「もう一回」から遊ぶ人に入る（いない人は外れる） |
| 結果 | 1台の画面と同じ（いちばん多く取った人の名前とペアの数だけ。順位の一覧は出さない） |
| 端末なしの参加者 | ホストが待合室で足す・外す。印「端末なし」はホストの画面にだけ（待合室の一覧と札） |
| 参加用のリンク・QR | `?room=コード`・「QRコードを出す」（rtdb.md の共通の形） |
| ホストの切断 | ゲストに「ホストの戻りを待っています」（`data-roomk-blocking`）。2分もどらなければルームを消す（`orphanAt` で期限のタイマーを仕掛けなおす形） |
| 終わったあとの削除 | 公認バリアント「ふりかえり画面滞在中は削除しない」（ホストの「ルームを閉じる」・ホスト切断の期限・次に開いたときの期限切れの掃除で消す） |

## データ構造

1台の画面は、保存するものはない。状態は `app.js` の `setup`（設定）と `game`（`cards`・`players`・`turn`・`open`・`lock`・`memory`）だけで、メモリの中にある。
タイマーは `later()` で登録し、対戦が替わると（`game` が別の物になると）動かない。

ルーム（Realtime Database）:

```
shinkeisuijaku_rooms/{roomCode}/
  ├── status: 'waiting' | 'playing' | 'over'
  ├── host / hostUid / hostPlays / hostConnected / hostDisconnectedAt / createdAt / lastGameId
  ├── level: 'easy' | 'normal' | 'hard' | 'geki'（待合室の設定）
  ├── players/{name}: { isHost, uid, joinedAt }   （在室。ゲストは onDisconnect で消える）
  ├── proxies/{name}: { joinedAt }                （端末なしの参加者。在室を持たない）
  └── game/
       ├── id, level（はじめた時点で固定）, order: [名前…], uids: {名前: uid}, joined: {名前: joinedAt}, proxy: {名前: true}
       ├── deck: [絵のキー…]（ふつうの絵は Material Symbols の名前、激ムズは「形-数」。どの絵もちょうど2枚）
       ├── got: [true/false…]（取ったカード。だれが取ったかは持たない）, pairs: [人ごとのペアの数]
       ├── first, turn, open（めくってある1枚め。なければ -1）, flipNo（めくった回数。押した時点の値と同じときだけ書く）
       └── reveal: { a, b, match, turn, n }（直前に2枚めくった結果。n が1つ増えたのを見た端末が、2枚をしばらく表で見せる）
```

- 山札は「はじめる」を押した端末で作った種から決める（`logic.js` の `makeDeck`。transaction がやり直しても同じ並び）
- 読み込むときは壊れた値を読み飛ばす（`deckOf`・`gotOf`・`pairsOf`・`openOf`・`revealOf`）
- 2枚めの結果は書き込みの中で決めるので、時間で進める書き込み（見せおわったら裏にもどす、など）はない

### 利用回数

「1回」は1ゲーム（はじめてから、ぜんぶそろうまで）。

| 項目 | 数えるとき |
|---|---|
| `start`・`players-{N}` | ゲームがはじまった（「はじめる」と「もう一回」）。N は CPU をのぞいた人数 |
| `finish` | ぜんぶそろった |
| `again` | 「もう一回」を押した（そのまま次がはじまるので `start`・`players-{N}` も数える） |

CPU と対戦かどうか・むずかしさは分けていない。

ルーム（2026-11-16）は、1台の画面の数と混ざらないよう `room-` を付けた別の項目にした（1台の画面の項目は、それまでの数を続けるため名前を変えていない）。

| 項目 | 数えるとき |
|---|---|
| `room-create` | ルームを作った |
| `room-start`・`room-players-{N}` | ホストが「はじめる」「もう一回」を押した（N は端末なしの参加者をふくむ遊ぶ人の数） |
| `room-finish` | ぜんぶそろった（最後の2枚を確定させた端末だけ） |
| `room-again` | おわりのあと、ホストが「もう一回」を押した |

## 既知の制約（ルーム）

- 2枚を表で見せるのは各端末の動き。見せている間に読み込み直した端末は、見せずにいまの形（ちがった2枚は裏・そろった2枚は取ったカード）を出し、次の番の人ならすぐめくれる
- 同じ名前のタブを2つ開く・応答が届かないときの数え漏れは、ほかのルーム型と同じ

## 確かめたこと（ルーム。2026-11-16）

`tests/shinkei-suijaku/`（隔離した Firebase エミュレーター＋Playwright。本番に接続しない）。手順は `tests/shinkei-suijaku/README.md`。
ルールの単体テスト 15件・E2E その1（1台の画面・作成・参加・待合室・めくる・ホストの代わり・すばやく押したとき・再読み込み・おわり・もう一回・375px・進行だけのホスト・ルームを閉じる）74項目・その2（6人まで・途中参加・自分の番で退出・入りなおし・タブを閉じた人の番をとばす・おわりのあとの参加と名前・ホストの切断と復帰）37項目、すべて合格。
二重レビュー（2026-11-16）: Claude のレビュー役（サブエージェント）と Codex（CLI・読み取り専用）。直したもの: ホストが続けて押したカードが、番が変わったあと次の人の1枚めとしてめくられる／処理中に押したカードが待合室・次の対戦まで残る／同時に押したとき、手元の仮の2枚を見せたまま確定した2枚に見せなおさない／いない人をとばす書き込みが処理中で通らないと止まったままになる／おわりの画面で、抜けた人の名前を別の端末が使える。あわせて、処理中に3枚押すと2枚めが3枚めに上書きされる不具合と、保留のカードを手元の古い回数で書こうとして断られる不具合を E2E で見つけて直した。直す前の動きでは「ちがった2枚を見せている間に押したカード」の検査が落ちることを確かめた。
