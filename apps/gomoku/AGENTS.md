# 五目並べ 仕様書

## 目的・使用シーン

黒と白の石を交互に置き、たて・よこ・ななめのどれかに先に5つならべたほうが勝ちの、定番の盤ゲーム。

- **core value**: ルールが一言で分かり、1手ずつ考えて置ける。はじめての子は「補助」で、あと1つで5つになる場所やおすすめの手を見ながら遊べる。対戦しない子も、自分の画面や「みんなにみせる画面」で勝負を見られる
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの1対1でも遊べる）
- 対戦は2人。観戦はゲスト20人まで（＋端末なしの参加者4人まで）
- 所要時間 1回10〜20分

> 経緯: 2026-11-18 スタッフから「五目並べがほしい」という意見。オーナーが次を選んだ: ルールは禁じ手なし（5つ以上で勝ち）／リバーシと同じ形（1台の画面（2人・CPU）＋ルーム対戦2人＋観戦＋みんなにみせる画面。RTDB `gomoku_rooms` もこの回答で承認）／盤は 15×15／補助は「あと1つで5つのしるし」「おすすめの手」「直前の手のしるし」（はじめはオン）と「1手の制限時間」（過ぎたら CPU。はじめはなし）。drafts を経ずに本体として作った（チェスと同じ）。
> 名前「五目並べ」は伝統ゲームの一般名称なので、命名の例外（リバーシ・将棋と同じ。`docs/development/app-registration.md`「アプリ名のつけかた」）に当たる。早見表では系統ラベル「定番の盤ゲーム」で紹介する。
> 作りは `apps/reversi/` を写して盤とルールを入れかえた。進行・通信・切断の扱いはリバーシと同じなので、同じ所を直すときは両方を見る。

## セッション条件（ツール一覧のカードと同じ）

スタッフがツールを選ぶときの条件。値はツール一覧（`apps/index.html`）のカードの札・`data-scenes`・`data-speech`・`data-self` と同じにする。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 1人〜（1台の画面なら CPU と対戦できる。ルームの対戦は2人） |
| 目安時間 | 10〜20分 |
| 利用シーン | ボドゲクラブ・ひろば・作戦会議 |
| 話す量 | 選ぶだけ・話さなくてよい |
| 自分の話 | 外の題材で遊べる |

## ルール

| 項目 | 内容 |
|---|---|
| 盤 | 15×15。碁盤のように線の交わる所に置く（星は D4・L4・H8・D12・L12）。はじめは何も置いていない。黒が先に置く |
| 置ける場所 | 空いている所ならどこでも。置いた石は動かさない |
| 勝ち | たて・よこ・ななめのどれかに、自分の石が5つ以上ならんだら勝ち（6つ以上でも勝ち。**禁じ手なし**: 三三・四四・長連も黒白どちらも打てる） |
| 引き分け | 盤がうまっても5つならばなかったら |
| 結果 | 盤の上に「黒（○○）の勝ち！　5つならんだよ」、勝った人の札に「勝ち」、5つのならびの石を光らせる |
| 場所の言い方 | 横は左から A〜O、たては上から 1〜15（盤のふちに出す）。「H8」のように言う |

- 先手（黒）が有利なのは知られているが、オーナーの判断で禁じ手を入れていない（いちばん知られた遊び方で、ルールの説明を増やさないため）。「もう一回」で黒と白を入れかえる
- 盤のルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/gomoku/engine.test.cjs`

## 補助（はじめての人向け）

| 項目 | 中身 | はじめの値 |
|---|---|---|
| 補助を使う人 | ふたりとも／黒の人だけ／白の人だけ／使わない。その色の番のときだけ補助が出る（ハンデにも使える） | ふたりとも |
| あと1つで5つのしるし | 番の人が置くと5つならぶ空きに、番の色の輪。相手が置くと5つならぶ空きに、赤い輪。盤の上の一行にも「輪の場所に置くと5つならぶよ」「相手があと1つで5つ。赤い輪の場所を見てね」 | オン |
| おすすめの手 | CPU（「つよい」と同じ考え方）が選んだ1手に、番の色の星。同じ局面なら同じ場所（くじを使わない） | オン |
| 直前の手のしるし | 最後に置いた石に赤い点 | オン |
| 置く前にたしかめる | 1回押すと、置く石が薄く出る。「ここに置く」か、同じ場所をもう1回押すと置く | オフ |

- 補助はホストが待合室で決め、遊んでいる間も「補助の設定」で変えられる（1台の画面も同じ）。観戦・みんなにみせる画面にも、その番の補助が出る
- 対局がおわったら、補助を使わない設定でも直前の手のしるし（決まった1手）を出す。ほかの補助の印は消す
- 「置く前にたしかめる」は、オーナーが選んだ3つに加えてリバーシから引き継いだ（15×15 はスマホでマスが小さく、押しまちがえやすいため）。はじめはオフ
- オーナーの選んだ「直前の手のしるし」は補助の1つにした（リバーシでは補助と関係なくいつも出していた）。ほかの補助と同じく「補助を使う人」に従う

## 1手の制限時間と CPU

リバーシと同じ（`apps/reversi/AGENTS.md`「1手の制限時間と CPU」）。

| 項目 | 内容 |
|---|---|
| 選べる時間 | なし・15秒・30秒・60秒（はじめは「なし」）。対局を始めた時点で固定 |
| 残り時間 | 番の人の札に「のこり 12秒」。5秒からは色を変える（音は鳴らさない） |
| 時間切れ | CPU がその人の代わりに1手置き、全員に「時間切れ。CPU が白の代わりに H8 に置いたよ。」と出す |
| CPU の置き方 | 5つにできればそこ、相手が5つにできればふさぐ。あとは点の高い場所（いちばんの点の8割以上）からくじ（`engine.js` の `autoMove`） |

- ルームの締め切り・時間切れの手を置く端末・ホストが切れている間は時計を止める、などはリバーシと同じ作り

### 点のつけ方（CPU・おすすめの手）

5マスの窓（たて・よこ・ななめ）ごとに、相手の石がなければ、自分の石の数で点をつける（1:1・2:12・3:150・4:2500・5:1000000）。ある場所の点 ＝ そこに置いたときの自分の窓の点（攻め）＋ 相手がそこに置いたときの相手の窓の点（守り）。候補は石から2マス以内の空き（石がなければ真ん中）。

## 端末なしの参加者・接続・切断・再接続・終了とデータ削除・みんなにみせる画面

リバーシと同じ（`apps/reversi/AGENTS.md` の各節）。RTDB パスと保存キーだけ違う。

- 端末なしの参加者: 待合室でホストが名前を足す（4人まで）。その人の番はホストが代わりに置く。「端末なし」の印はホストの画面にだけ出す
- ホスト切断中はゲストと見る画面に共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- 公認バリアント「ふりかえり画面滞在中は削除しない」（対局がおわっても自動削除しない）。削除経路はホストの「ルームを閉じる」・ホスト切断＋2分・次回アクセス時の期限切れ掃除
- みんなにみせる画面（`?watch=CODE`）はルームへの書き込みゼロ

## 技術スタック

```
apps/gomoku/
├── AGENTS.md    # この仕様書
├── index.html   # 画面の骨組み・howto.js の設定
├── app.js       # 進行・描画（ES module。リバーシの app.js をもとにした）
├── engine.js    # 盤のルールと CPU（window.GomokuEngine。node では module.exports）
└── style.css    # 固有スタイル
```

- 分割型。index.html・app.js・engine.js・style.css を変えたら `?v=` をそろえて上げる
- Firebase compat SDK **13.3.0**（app / auth / database）+ 匿名認証
- `../shared/js/rtdb-utils.js?v=20261005`・`../shared/js/room-qr.js?v=20261022`
- CSS 接頭辞: **`gm-`**（BEM）。画面切替は `.gm-screen` / `.active`
- 描画はすべて DOM API（textContent）。innerHTML は使わない
- アイコン: Material Symbols Rounded（ポータルは `grid_on`）
- RTDB パス: `gomoku_rooms/{roomCode}`、sessionStorage キー: `gomoku_session`（`{role, nickname, roomCode, uid, joinedAt}` だけ）・`gomoku_local`（1台の画面の対局。読み込み直しで続きから）
- 盤は 225 個のボタン（`role="grid"`）。線はボタンの背景と `::before` で引き、ふちのマスは外へ出さない。マスは作りなおさず使いまわす（キーボードの位置が消えない）。Tab で入るのは1マスだけで、矢印キー・Home/End で動く（roving tabindex）。押せないときは `aria-disabled="true"`（観戦でも盤を読めるよう disabled にしない。押したときは `onCell` で確かめる）
- 幅の狭い画面（600px 以下）は盤の大きさを対局の欄の実際の幅（`cqw`）から決める（375px でマスが約 22px）

## 画面構成・フロー

リバーシと同じ（`apps/reversi/AGENTS.md`「画面構成・フロー」）。対局の画面の札には石の数を出さない（五目並べでは意味がないため）。

## status 遷移

```
waiting ─はじめる→ play ─（5つならぶ・盤がうまる）→ play（game.over）
play ─もう一回（ホスト・終わったあと）→ play（新しい対局。黒と白を入れかえる）
play ─対戦する人を選びなおす／この対局をやめる（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
gomoku_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── aid:                { who: 'both'|'b'|'w'|'none', threat, hint, last, confirm }   # 補助（いつでも変えられる）
  ├── moveTime:           0 | 15 | 30 | 60   # 1手の制限時間（秒。0 はなし。待合室で変更）
  ├── seats:              { b: 名前, w: 名前 }   # 待合室で選んだ席
  ├── players/{name}:     { isHost, uid, joinedAt }
  ├── proxies/{name}:     { joinedAt }                # 端末なしの参加者
  └── game/                          # 「はじめる」で作り、待合室にもどると消す
       ├── id, seats: {b, w}, uids: {b?, w?}, proxy: {b?: true, w?: true}
       ├── board: 225文字（'.' 'b' 'w'。左上 A1 から行ごと）, turn: 'b'|'w', ply: 何手目
       ├── last: 直前に置いた場所（-1 はまだ）
       ├── over: true（おわり）。勝った色と5つのならびは保存せず、盤と last から求める（`E.result`）
       ├── hist: [置いた場所の番号...]   # 1手もどす用。盤を丸ごと持たないので、225手でも小さい
       ├── moveTime, turnAt（ServerValue.TIMESTAMP）, auto: 直前の手を CPU が代わりに置いた色
       ├── rev: 局面が変わるたびに増える番号（置く・時間切れの手・1手もどす）
       └── ended: 一度でもおわった（finish を1対局に1回だけ数える）
```

- 1手もどすは `hist` の最後の場所の石を取り、その石の色の番にもどす（`undoOnce`）
- 読み込むときは壊れた値を読み飛ばす（`gameOf`。`hist` のうち石のない場所は捨てる）

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る。engine.js は DOM に触らない
- **ホスト以外も進行の一部を行う**: 席の人が置く・最後の手を置いた端末が `finish` を数える・時間切れの手は番の人の端末も置く
- **観戦は参加者として players に入る**（席に入らない人）。見るだけの画面（書き込みゼロ）は別にある
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **端末なしの参加者は在室を持たない**（`proxies`）
- **勝ち負けを出す**（定番の対戦ゲームの結果。勝ち数の記録や順位はしない）

## 入れない機能

- 禁じ手（三三・四四・長連）・連珠の開局ルール（2026-11-18 オーナー判断）
- 音（石を置く音・時間切れの音もなし）
- こうさん・待ったのやりとり（「1手もどす」はホストと1台の画面だけ）
- ルームで CPU と対戦するモード（CPU と対戦できるのは1台の画面だけ。リバーシと同じ）
- 勝ち数・対戦成績の記録、順位
- 対局中の新しい対戦者（途中から入った人は観戦）

## 既知の制約（v1）

- リバーシの「既知の制約」と同じ（同じ名前のタブが2つ・時間切れの手が進む条件・裏に回ったタブのタイマー・待合室の席の名前・切断予約の順序・数え漏れ・残り時間のずれ）
- スマホ（幅 375px）ではマスが約 22px で、指では押しまちがえやすい。「置く前にたしかめる」で補う
- おすすめの手は「つよい」CPU の考え（3手先まで）なので、いつも最善とは限らない

## メンター向けの心得（画面には出さない）

- 1台の画面で遊ぶときは、子どもに「H8」のように場所を言ってもらう（盤のふちに A〜O・1〜15 が出ている）。言いにくい子には、指で示してもらう・チャットで送ってもらうでもよい
- はじめての子には補助をオンのまま。慣れてきたら「黒の人だけ」などにしてハンデにする。先手（黒）が有利なので、慣れている人が白を持つのもよい
- 赤い輪（相手のあと1つ）が出たら、まずそこを見るよう声をかける。ふさげたらほめる
- 1手の制限時間は、考えこんで止まってしまう子がいるとき・観戦の子が待ちくたびれるときに。CPU が置いても責めない
- 勝ち負けで落ち込む子には、ふさげた場面・4つまでならべた場面をほめる。観戦の子に「次はどこに置くと思う？」と聞くと、見ているだけの時間も楽しくなる
