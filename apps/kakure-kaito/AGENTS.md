# かくれ怪盗 仕様書

## 目的・使用シーン

美術館の警備員の中に、警備員に変装した怪盗がまざっている。主任が見回りのメンバーを選び、みんなで投票し、見回りに行った人がこっそり「異常なし」か「すり替える」を出す。宝石を3回守れば警備員チーム、3回すり替えられたら怪盗チームの勝ち。

- **core value**: 正体かくしの話し合いを、だれも途中でぬけずに最後まで遊べる（人狼のように脱落しない）。役は自分の画面にだけ出る
- 対象: 小学校中学年〜中学生。ボドゲクラブ・サークルタイム（`data-scenes="bodoge circle"`）
- 遊ぶのは4〜10人（ホストは遊ぶか、進行だけかを選ぶ）。ほかに見ているだけの人も入れる
- 所要時間 1回20〜30分

> 経緯: 2026-10-30 オーナーの依頼で『レジスタンス：アヴァロン』から着想して `drafts/kakure-kaito/` に試作（同じブラウザのウィンドウ間だけでつながるモック）。テーマ「美術館と怪盗」と名前「かくれ怪盗」はオーナー決定。同日「ワクワクしそうな画面に」の依頼で見た目を刷新。仮置きをオーナーが決定（下の「オーナーが決めたこと」）。2026-10-30 オーナーが「本体に移す」と承認し、Realtime Database で本体化した。
> 着想元の名前はアプリ名・画面・検索のキーワードに使わない。早見表と更新情報で「『レジスタンス：アヴァロン』から着想」と紹介する。

## ルール

| 項目 | 内容 |
|---|---|
| 人数 | 4〜10人。怪盗は 4人:1・5〜6人:2・7〜9人:3・10人:4 |
| 見回りの人数 | 4人 2-2-2-3-3／5人 2-3-2-3-3／6人 2-3-4-3-4／7人 2-3-3-4-4／8〜10人 3-4-4-5-5 |
| 1回の見回り | 主任がメンバーを選ぶ（選んでいる途中もみんなに見える）→ 全員が賛成・反対 → 賛成が半分より多ければ出発 → メンバーがこっそり出す → 結果 |
| 選びなおし | 反対が多いと、となりの人が主任になって選びなおす。**5回目は投票なしで出発**（待合室で外すと、5回続けて反対が多ければ怪盗チームの勝ち） |
| 出す札 | 警備員チームは「異常なし」だけ（「すり替える」は押せない）。怪盗チームはどちらでも出せる |
| 結果 | 「すり替え」が1枚でもあれば、すり替えられた（7人以上の4回目だけは2枚いる）。枚数だけ出し、だれが出したかは出さない |
| 投票 | だれが賛成・反対したかは、開いたあとに出す |
| 最後の見やぶり | 名探偵がいるとき、警備員チームが3回守ったら、怪盗チームの正体を明かし、名探偵だと思う人を選ぶ。当たれば怪盗チームの逆転勝ち。怪盗みんなで相談し、決めるのは**かしら**（かしらの通信が切れたら、端末のあるほかの怪盗が決められる。そういう怪盗もいない・かしらが端末のない人なら、ホストが代わりに選ぶ） |
| しらべのルーペ | 待合室で選ぶ（はじめはオフ）。**7人から**（選んでいても6人以下なら使わず、待合室にそう出す）。はじめに持つのは最初の主任のひとつ前の人。2・3・4回目の見回りのあと、持っている人が1人のチームをこっそり確かめる（結果はその人にだけ出る・「自分の役を見る」にも残る）。確かめられた人にルーペが渡る。一度持った人は確かめられない。だれがだれを確かめたかはみんなに出る |
| 話し合いの時間 | 待合室で「制限なし・1分・2分・3分」（はじめは制限なし）。メンバー選びと見やぶりのときに残り時間を出す。時間になっても自動では進めない。音は鳴らさない |
| おしまい | 勝ったチーム・全員の役・かしら。ホストは「もう一回（役を配りなおす）」「待合室にもどる」 |

### 役（待合室でホストが選ぶ）

| 役 | チーム | 知っていること・特徴 | はじめの値 |
|---|---|---|---|
| 警備員 | 警備員 | 何も知らない | （残りの全員） |
| 名探偵 | 警備員 | 怪盗がだれか（変装名人は見えない）。最後の見やぶりもこの役とセット | オン |
| 助手 | 警備員 | 名探偵がだれか（にせ探偵がいると、2人のどちらか） | オフ |
| 怪盗 | 怪盗 | 仲間の怪盗（ひとり怪盗は見えない）と、かしらがだれか | （残りの全員） |
| にせ探偵 | 怪盗 | 助手からは名探偵に見える | オフ |
| 変装名人 | 怪盗 | 名探偵にも見やぶられない | オフ |
| ひとり怪盗 | 怪盗 | 仲間を知らないし、仲間からも知られていない（名探偵からは見える） | オフ |

- 名探偵を外すと、助手・にせ探偵・変装名人も選べなくなる。助手を外すと、にせ探偵も選べなくなる
- 怪盗チームの役が怪盗の人数より多いと、はじめられない（理由を出す）
- かしら: 名探偵がいるとき、怪盗の1人（ほかに怪盗がいれば、ひとり怪盗以外）。ひとり怪盗のほかの怪盗には、役のカードに「最後の見やぶりは、かしらの○○が決める」と出る
- ルーペを持っている人が「だれを確かめるか」選んでいる途中は、みんなに出る（着想元と同じく、確かめる相手は公開。結果だけが持っていた人に出る。意図した扱い）

ルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/kakure-kaito/engine.test.cjs`（配る3000回で役の数・知っていることを照合、ルーペ・時間など）。

## 端末のない参加者（ホストが代わりに押す）

- ホストが「自分（ホスト）も遊ぶ」を外しているときだけ、待合室の「端末のない人を足す」で名前を足せる（待合室でだけ。参加者・ホストと同じ名前は不可。「外す」で外せる）。足しているあいだは「自分も遊ぶ」にできない（ホストは端末のない人の役を見るため）
- `proxies/{name}` に置き、在室（`players`）には入れない（切断しない扱い）
- ゲーム中、ホストの画面に「端末のない人の代わりに押す」欄が出る: 「役を見る」「チャット用にコピー」（チャットの個別メッセージで送る文。役・知っていること・ルーペの結果。絵文字なし）・「役を伝えた」・「賛成／反対」・「異常なし／すり替える」（警備員チームは「すり替える」を押せない）
- その人が主任・ルーペを持つ人・かしらになったときは、ホストの画面に選ぶボタンが出る
- 「端末なし」の印は、ホストの画面にだけ出す（子どもどうしの画面で区別しない）

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（ゲーム中なら見ているだけ）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
ルーム（screen-room）
  待合室: 参加している人・自分（ホスト）も遊ぶ・端末のない人を足す・役の設定・話し合いの時間・「役を配ってはじめる」
  ゲーム: 展示室（守った／すり替えの印・5回の展示ケース）・いまの段階・メンバー選びの回数・大きな案内・段階ごとの中身・遊んでいる人・「自分の役を見る」・ホストの操作
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）
- 役を配ると、伏せたカードを自分でタップしてめくる（めくるまで「たしかめた」は出ない。「カードをふせる」でもどせる）。そのあとは「自分の役を見る」を押したときだけ出る
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「役を配ってはじめる」、各段階のホストの「次へ」系、主任の「このメンバーで投票する」など）
- 演出（展示ケースの宝石・票と札が1枚ずつめくれる・見やぶりのスポットライト・おしまいにはじける宝石か星）は、その結果をはじめて出すときだけ動く。動きを減らす設定の端末では動かさない。音は鳴らさない

## status 遷移

```
waiting ─役を配ってはじめる→ play（game.phase: reveal）
reveal ─見回りをはじめる（ホスト）→ propose ─このメンバーで投票する（主任）→ vote ─全員の票→ voteResult
  voteResult ─見回りに出発（ホスト）→ mission ─メンバー全員の札→ missionResult
  voteResult ─次の主任へ（ホスト）→ propose（5回続けて反対で end。5回目はそのまま出発のときは vote をとばして mission）
  missionResult ─次の見回りへ→ propose ／ しらべのルーペへ→ lens ─確かめる→ lensResult ─次の見回りへ→ propose
  missionResult ─3回すり替え→ end ／ 3回守った→ guess（名探偵あり）または end
guess ─かしらが決める→ end
end ─もう一回（ホスト）→ reveal（新しい game.gid）
play ─待合室にもどる（ホスト）→ waiting（game を消す）
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
kakure_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── hostPlays:          ホストも遊ぶか
  ├── opts:               { detective, assistant, fake, disguise, lone, lens, fifthGo, talk }
  ├── lastGameId:         number
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}:     { joinedAt }                # 端末のない参加者
  └── game/                                            # 「役を配ってはじめる」で作り、待合室にもどると消す
       ├── gid, step（段階が進むたびに1増える。古い操作の照合に使う）, phase
       ├── players: [名前...]（主任の順）, uids: {名前: 匿名ID}（端末のない人はなし）
       ├── roles: {名前: 役}, knows: {名前: [{kind, ids}]}, boss: かしらの名前
       ├── seen: {名前: true}, round, results: [true|false...], missions: [見回りの結果...]
       ├── leaderIdx, proposal（メンバー選びの何回目か）, team: [名前...]
       ├── votes: {名前: true|false}（開くまで）, lastVote: { round, proposal, team, votes, approved, auto? }
       ├── submitted: {名前: true}（出したかどうかだけ）, safeN, swapN（出た札の枚数）, lastMission: { round, team, need, swaps, safe, ok }
       ├── guessPick, guess, winner: 'guard'|'thief', how: 'missions'|'guess'|'guessMiss'|'rejects'
       ├── talkEnd: 話し合いの締め切り（ミリ秒。進めた端末の RoomkRTDB.now() から）
       └── lensHolder, lensUsed: [名前...], lensLog: [{round, from, to}], lensSeen: {名前: [{id, side, round}]}, lensPick
```

- 読み込むときは欠けた値を補う（`normGame`。RTDB は空の配列・null を残さない）
- 役・知っていること・ルーペの結果・開く前の票はルームに置き、画面には自分の分だけ出す（DevTools で見えるのは、ルート AGENTS.md の性善説で許容）。見回りの札は、だれが出したかを残さず `safeN`・`swapN` で数える

## transaction 設計

すべてルーム全体への `transaction()`。中で「押した人の在室の匿名ID」「押した時点の `game.step`」「その段階でその人が押せるか」を確かめる（`applyMsg`）。ホストの操作は `hostUid` を確かめる（`hostAct`）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | 名前が空いている（ホスト・端末なしの人・ゲームで遊んでいるほかの匿名IDの人と同じ名前は不可）・参加者14人未満（ゲームで遊んでいる人が戻るときは上限を見ない）→ `players/{name}`（`transactRetry`。自分の在室が残っていれば入りなおし） |
| 設定（役・時間・ホストも遊ぶ） | ホスト | `waiting`。続けて変えても取りこぼさないよう、ロックを使わず差分だけ送る（中で今の値に重ねる） |
| 端末のない人を足す・外す | ホスト | `waiting`・ホストは進行だけ・名前が空いている |
| 役を配る／もう一回 | ホスト | `waiting` か `end`・`checkOpts` が通る → `game` を作る（`gid` を1増やす） |
| たしかめた・選ぶ・投票・札・見やぶり・ルーペ | 遊んでいる人（端末のない人の分はホストが `as` で） | `play`・`step` が一致・段階と人が合う → 進める。最後の票で開き、最後の札で結果を出す |
| 主任の代わり・ルーペの代わり・見やぶりの代わり | ホスト | 主任・持っている人の通信が切れている／端末がない。見やぶりは、かしらが端末のない人か、かしらの通信が切れて端末のあるほかの怪盗もいないとき |
| 見やぶりを決める | かしら（など） | 押した人が画面で見ていた候補（`id`）が、いまの `guessPick` と同じときだけ（直前にほかの怪盗が選びなおしていたら決めない） |
| 次へ・見回りをはじめる・票を開く・選びなおす | ホスト | `step` が一致（二度押しで2段進まない）。票を開くのは、まだの人がいて全員の通信が切れているときだけ（だれも投票していなくても開ける。賛成0なので選びなおし）。選びなおすのは、出していないメンバーに通信が切れた人がいるときだけ（どちらも transaction の中で確かめなおす） |
| 待合室へ | ホスト | `play`・押した画面のゲームの `gid` が一致（古いタブから新しいゲームを消さない）→ `waiting`、`game` を消す |
| 退出 | ゲスト | 自分の在室を消す（ゲームの中の名前は残す。主任・ルーペはホストが代わりに進められる） |

## 接続・切断・再接続

リバーシ・しるしでヒントと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- 遊んでいる人が切れると、全員の札に「通信が切れた」。主任ならホストが代わりに選べる。投票でまだの人がみな切れているときは「通信が切れた人を待たずに開く」。見回りのメンバーが切れたら「この見回りをやめて、メンバーを選びなおす」（同じ主任・選びなおしの回数は増えない）。かしらが切れたら、ほかの怪盗が見やぶりを決められる
- 戻ると（同じタブの読み込み直し・同じ名前と同じ匿名ID）同じ役で続きから。ゲームで遊んでいる人の名前は、ほかの人（別の匿名ID）は使えない
- ゲーム中に入った人は見ているだけ（役は配られない）
- ホスト切断中、ゲストと見る画面には共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おしまいでも自動削除しない（「もう一回」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 待合室にもどると `game` を消す（設定・端末のない人は残る）

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: players に入らない・切断予約をしない・期限切れのルームも消さない
- **役は出さない**（役のカード・「自分の役を見る」・端末のない人の欄は出ない）。見やぶりで怪盗チームの正体、おしまいで全員の役が出る
- 待合室では「参加のしかた」とルームコードを大きく出す

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る。engine.js は DOM に触らない
- **ホスト以外も進行の一部を行う**: 主任の選ぶ・全員の投票・メンバーの札・かしらの見やぶり・ルーペは、その人の端末が transaction で進める（最後の票・札を出した端末が結果に進める）。ホストは段階の「次へ」と代わりの操作
- **秘密の情報をルームに置く**（役・投票の中身・ルーペの結果）。画面は自分の分だけ。性善説（ルート AGENTS.md「セキュリティ方針」）
- **端末のない参加者は在室を持たない**（`proxies`。切断しない。ホストが代わりに押す）
- **終了後の自動削除なし**（公認バリアント）
- **勝ち負けを出す**（チームの勝ち負けだけ。点数・順位・成績の記録はしない）

## 入れない機能

- 音（演出も音なし）
- 脱落（全員が最後まで遊ぶ）
- 勝ち数・成績の記録、順位、だれが何回怪盗だったかの記録
- チャット（話し合いは Zoom / Meet の声とチャットで）

## 既知の制約（v1）

- 名前に数字だけは使えない（RTDB は数字のキーだけのオブジェクトを配列で返すため。読むときも配列を番号のキーにもどす `asObj`）
- 切断予約（onDisconnect）は在室を書き戻す transaction の前に張る（リバーシ・しるしでヒントと同じ作り）。同じ名前を別の人が使っていると分かったら、その画面はルームから外れて予約を取り消す。そのすきまに切れると、別の人の在室を消すことがありうる（2026-10-31 レビューの指摘。頻度が低く、ほかのアプリと同じ扱い）
- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- 話し合いの残り時間は、段階を進めた端末の時刻（`RoomkRTDB.now()`）から数える。端末どうしの時刻の見積もりのずれぶん、表示が少しずれることがある
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（共通方針どおり、少なめに出る側の誤差として扱う）
- サムネイルはまだない

## メンター向けの心得（画面には出さない）

- はじめての回は、特別な役は名探偵だけ（はじめの設定のまま）で。慣れてきたら助手・にせ探偵を足すと、名探偵を守る・見やぶる駆け引きが増える
- 役を配ったら「まわりに見えないようにめくってね」と声をかける。画面共有しているホストは「みんなにみせる画面」を共有すると、役が映らない
- 怪盗になった子が責められないように。「うまくだませたね」「よく見ぬいたね」と、どちらのチームのがんばりも言葉にする
- 話し合いで止まってしまうときは、話し合いの時間（1〜3分）を使う。時間になっても自動では進まないので、主任に「そろそろ決めようか」と声をかける
- 端末のない子の役は、チャットの個別メッセージで送る（「チャット用にコピー」）。ほかの子に見えないところで送る
