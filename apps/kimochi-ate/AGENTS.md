# 気持ち当てゲーム 仕様書

## 目的・使用シーン

場面カードを見て、主役の気持ちがどの系かを、ほかの人が予想し合うルーム参加型のゲーム。
「同じ場面でも、気持ちは人それぞれ」を遊びながら知る。気持ちのことば（6系×72語）にふれる機会にもなる。
『フィーリンクス』（アークライト、2019）から着想した（名称・場面・進め方・得点は変えている）。

| 項目 | 内容 |
|------|------|
| 人数 | 遊ぶ人2人以上（ホストが遊ぶなら1対1も可）。ゲストは8人まで |
| 所要時間 | 1場面2〜4分・全体10〜20分 |
| 使う場面 | サークルタイム・作戦会議（1対1）・ボドゲクラブ |

### 経緯（2026-09-25 作り変え）

旧「きもちのことばマップ」（`apps/kimochi-map/`。オフライン・1対1で今日の気持ちに近いことばをさがす内省ツール）を、
オーナー判断でこのゲームに一本化した。今日の気持ちをさがす使い方と、72語を一覧する「マップ全体」の画面は廃止した。
旧フォルダは転送スタブだけを残している。6系×72語の語彙と系の色は、表記を変えずに引き継いだ。

## 技術と保存

- Realtime Database と匿名認証。パスは `kimochiate_rooms/{roomCode}`、再接続用の sessionStorage キーは `kimochiate_session`
- 構成は `index.html` + `app.js`（ES module）+ `style.css`。CSS 接頭辞は `.ka-`（BEM）。index.html・app.js・style.css を変えたら `?v=` をそろえて上げる
- 描画はすべて DOM API（textContent）。innerHTML は使わない
- 保存するのは進行用の一時状態だけ。選んだ内容（picks）はそのラウンドの間だけルームに置き、次のラウンドへ進むときとルームを閉じたときに消える。ホストが「ルームを閉じる」を押さずにタブを閉じた場合は、最後の場面の選択がルームの削除（TTL 後の次回アクセス時の掃除）まで残る（rtdb.md の全体共通の制約）。sessionStorage には再接続用の `{role, nickname, roomCode, uid, joinedAt}` だけを置き、選んだ内容は入れない
- 利用回数は stats.js の `open` だけを数える。選ばれた系やことばは数えない
- 開発・静的監査から本番 Firebase に書き込まない

## 役割と人数

- ホストはルームを作る人（メンター）。作成画面のチェック「ホストも遊ぶ」は**既定で ON**。ON のときホストも主役・予想に入る（1対1で遊べるようにするため）。OFF のときは進行だけ
- 開始は「遊ぶ人」が2人以上（ホストが遊ぶならゲスト1人から）。ゲストは8人まで
- 途中参加はどのフェーズでもできる。参加順の最後に並び、予想の途中なら今の場面から予想に加われる
- 切断から戻る人は、人数の上限を超えていても戻れる（参加したときの順番のまま）

## 進行

1. ホストが「ルームを作る」。参加する人は「ルームに参加する」で名前 → ルームコード → 「参加する」の順に入れる
2. 待機画面で、ホストが「はじめる」を押す
3. **場面（casting）**: 全員に場面カードが出る。ホストが主役を決めて「この人で始める」を押す
   - 主役の既定は参加順の順番回し（前の主役の次の人）。最初はいちばん先に参加した人（ホストが遊ぶならホスト）
   - 立候補は声かチャットで受け、ホストが名前を選ぶ（アプリ内の立候補ボタンは作らない）
   - 「別の場面にする」で引き直せる。場面は使い切るまで重ならない
4. **選ぶ（answering）**
   - 主役は「この場面なら、どんな気持ちになりそう？」に、①〜⑥の系を選び、続けてその系の①〜⑫のことばを選んで「きめた」。「ことばは選ばない（系だけ）」「この場面はパス」もできる
   - ほかの遊ぶ人は「〇〇さんは、どの系の気持ちになりそう？」に①〜⑥で答えて「きめた」。「今回は予想しない」もできる
   - 選んだ後は、本人の画面にも中身を出さず「えらんだよ」とだけ出す。公開までは「えらびなおす」で取り消せる（取り消した後も、前の選択を強調しない）
   - ホストには、名前と「えらんだよ／まだ／パス／接続が切れています」だけを出す。誰が何を選んだかは出さない
   - ホストは主役が選び終えたら「公開する」を押せる（予想していない人はそのまま）。主役がパスしたら「場面をかえる」になる。「主役をえらびなおす」はいつでも押せる
5. **公開（reveal）**: 主役のことば（系だけのときは系名）を系の色で大きく出す。予想した人を参加順に並べて、それぞれの系を出し、主役と同じ系の人に小さく「同じ」と付ける。ホストの「つぎの場面へ」で3へ戻る
6. 終わるときは、ホストが「ルームを閉じる」（確認あり）。ルームを消して全員トップへ戻る。まとめの画面・終了のフェーズは作らない

## ルーム状態

```
waiting ─はじめる→ casting ─この人で始める→ answering ─公開する→ reveal
                     ↑  └別の場面にする（場面だけ変える）   │           │
                     ├───────── 場面をかえる（主役のパス時）─┘           │
                     ├───────── 主役をえらびなおす（同じ場面）           │
                     └───────────────────── つぎの場面へ ────────────────┘
どの状態でも: ホストの「ルームを閉じる」→ ルーム削除 → 全員トップへ
```

| キー | 内容 | 書く人 |
|------|------|--------|
| `status` | `waiting` / `casting` / `answering` / `reveal` | ホストの transaction だけ |
| `host` / `hostUid` / `hostPlays` / `createdAt` | 作成時に確定 | ホスト（作成時） |
| `hostConnected` / `hostDisconnectedAt` | ホストの接続状態 | ホストの onDisconnect と在室復帰 |
| `round` | answering に入るたびに +1（画面には出さない） | ホスト |
| `scene` / `usedScenes` | 場面の番号と、使った番号（本文は書かない） | ホスト |
| `star` / `starUid` / `lastStar{name, joinedAt}` | 主役と、順番回しの基準 | ホスト |
| `players/{name}` | `{isHost, uid, joinedAt}`。ゲストは切断で消え、戻ると同じ joinedAt で復帰 | 本人・ホスト（作成時） |
| `picks/r{round}/{name}` | 主役 `{uid, group, word?}` か `{uid, pass:true}`、予想 `{uid, group}` か `{uid, skip:true}`。常に1ラウンド分だけ | 本人（answering 中だけ） |
| `members/{name}` | このラウンドの参加者 `{uid, joinedAt}`。主役を決めたときに遊ぶ人を固定し、途中参加・選んだ人を加え、明示退出で外す。casting に戻ると消す。切断中の人も進み具合に「接続が切れています」と出し、公開の並びを参加順にそろえるため | ホスト（固定）・本人（参加・選択・退出） |

- transaction はすべてルーム全体に対して行い、中で `hostUid`（ホストの操作）・`status`・`round`・主役の `starUid` を確かめる
- 選択の書き込みは `picks` を今のラウンドの分だけにして書く（前のラウンドの分は残らない）。遷移後に届いた古い書き込みは round の照合で弾く
- **名前の予約**: `starUid`・`members`・今のラウンドの picks の uid が自分と違う名前では参加・復帰できない。切断中の人の名前を別の人が使って、その人の主役や選択を引き継がないため（次の場面へ進むと予約は外れる）
- 参加・再接続は `warmRoomCache`（先に値を購読）してから transaction を実行する（空のキャッシュで中止されないため）
- 秘密の選択は UI でだけ隠す。DevTools で見えることはルート AGENTS.md の性善説の方針で許容する

## みんなにみせる画面（画面共有用・見るだけ）

ホストも遊ぶと、ホストの画面には自分の選択が出る。そこでホストは別のタブで「みんなにみせる画面」を開き、
それを Zoom / Meet / Metalife で共有する。チャットだけで参加する子は、この画面を見て予想する。
見ている全員（主役本人を含む）が見てよい情報だけを出す（かぶらずヒントの観戦ビューと同じ原則）。

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけに出る。クリックの中で同期的に `window.open(url, '_blank', 'noopener')`）②トップの「みんなにみせる画面をひらく」→ ルームコード → 「画面をひらく」③アドレスの `?watch=CODE`（最優先。起動時に再接続の記録を消してから入る。無効なら通知してトップへ）
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。`kimochiate_rooms` の値を読むリスナーだけで、players に入らない・切断予約をしない・期限切れのルームも消さない・`cancelRoomOnDisconnect` も呼ばない。描画は `handleSpectator()` に分けて、ホスト・参加者の処理（在室、transaction）に入らない。利用回数（stats.js の `open`）は全ページ共通の計測で、ルームのデータではないので別扱い
- **再接続と排他**: 開く処理は再接続・ルーム作成・参加と同じ `state.busy` で排他し、読み込みを待ったあとにも他の接続がないか確かめる。再接続の間はトップの3つのボタンを押せなくする
- **出すもの**: 待機（参加者・ルームコード・チャットでも予想できる案内）／場面（「主役を決めています。」だけ。チャットだけの子は主役にならないので立候補は呼びかけない）／選ぶ（場面・主役・番号つきの系の一覧（押せない）・チャットの案内・名前と「えらんだよ／まだ」）／公開（参加者の公開画面と同じ内容＋「チャットで予想した人は、自分の番号と見くらべてね」）。主役のパスは参加者の画面と同じく全員に知らせる（系の一覧を隠して「パスになったよ」、進み具合も「パス」）
- **出さないもの**: 公開までの主役と予想の中身、ホストの主役候補。ルームの操作ボタン
- **終わり**: ホストがルームを閉じたら「このルームは閉じられました」、期限切れ（ホスト切断から2分。ローカルのタイマーでも確かめる）なら「このルームは終わりました」を出し、購読とタイマーを止める。「トップへ戻る」は購読を止めてアドレスから watch を外すだけで、ルームには触らない
- **見分けやすさ**: 開いている間はタブの題名を「みんなにみせる画面 | …」にし、見出しの下に「みんなにみせる画面」の札を出す（共有するタブ・ウィンドウを選ぶときに間違えないため）
- **描画関数の共用と約束**: 待機・場面・公開の描画（renderWaiting・renderCasting・renderReveal と renderPeople・progressLabel・updateStarAway・appendGroupContent）は参加者の画面と共用している。共用の約束: ①主役候補の選択はホストの画面にだけ出す ②公開前に主役・予想の中身を DOM に書かない ③spectator の nickname は null（「あなた」の札も出ない）。選ぶ画面だけは renderWatchAnswering に分けている。これらの関数を変えるときは、みんなにみせる画面でも確かめる

## チャットで参加する（ルームに入らない人向け）

- 自分の端末を開けない子は、みんなにみせる画面を見て、**予想だけ**チャットで参加できる。主役が選び終わってから、系の番号（①〜⑥）をチャットで送る
- **チャットの予想はアプリに記録しない**（かぶらずヒント・クイズのチャット参加と同じ扱い）。公開の画面に主役の系と番号が出る（ことばを選ばなかったときも「⑥ すっきり系」のように番号を出す）ので、自分で見くらべる。メンターが読み上げて受け止めてもよい
- チャットだけの子は主役にならない（主役の選択は公開まで秘密にする必要があるため）

## 切断・再接続・削除

- ホスト: `onDisconnect().update({hostConnected:false, hostDisconnectedAt})`。ゲストには「ホストの戻りを待っています」を出す。接続が戻ると `.info/connected` で在室を戻す
- ゲスト: `players/{name}` を `onDisconnect().remove()`。選択は players の外にあるので残り、選んだ後に切断しても公開に含める。戻ると在室を戻す
- 主役が選ぶ前に切断したら、全員に「接続が切れています」の案内を出す。自動では進めず、ホストが待つか「主役をえらびなおす」
- ゲストの明示退出は、自分の在室と公開前の自分の選択だけを消す（進行は書き換えない）
- 削除は公認バリアント「ふりかえり中は削除しない」（docs/development/rtdb.md）を採用: ①ホストの明示的な「ルームを閉じる」（`cancelRoomOnDisconnect` を await してから remove）②ホスト切断から2分の TTL（`ORPHAN_TTL_MS = 2 * 60 * 1000`、`isRoomExpired`・`RoomkRTDB.now()`）③次回アクセス時の期限切れ掃除（status の無いゴーストも対象、applyLocally:false）
- 自分で退出・ルームを閉じる途中は `state.leaving` でルームの変化を無視する（「ルームが閉じられたよ」を自分に出さない）

## 心理的安全

- **「正解」「当たり」「はずれ」「おしい」を使わない**。点数・人数の集計・並べ替え・順位は作らない。気持ちに正しい答えはないため（kotoba-theme の監査判断: 場面から“正しい気持ち”を当てさせる形は内面の断定にあたる。apps/kotoba-theme/waza.js:27, 73-78）
- 「同じ」の印は、主役と同じ系を選んだことを示すだけで、採点ではない。数えない・残さない
- 当てる対象は、主役が**架空の場面**について自分で選んだ気持ち。今日の気持ちは扱わない。問いかけを「今の気持ちは？」にしない
- 主役を強制しない（立候補か本人の確認）。主役の「この場面はパス」、予想の「今回は予想しない」、主役の「ことばは選ばない」を用意し、責めたり目立たせたりしない
- 公開まで誰にも（本人にも）選んだ中身を見せない。ホストの進み具合にも中身を出さない
- 系に優劣をつけない（同じトーンの色。ネガティブな系を暗い色・警告色にしない）

## 語彙リスト方針（編集時に必ず守る。旧 きもちのことばマップ から引き継ぎ）

1. **60〜80語**を維持する（現在72語、6系×12語）
2. 小学校中学年でも読める**ひらがな中心**の表記（漢字を使う場合はやさしい漢字のみ）。
   ※これは**語彙72語と系の名前**の規定。語彙は表記トーン方針（ルート AGENTS.md）の対象外で変えない。
   **UI文言（見出し・ボタン・案内）と場面カードは通常表記（漢字まじり）**（読めない子にはメンターが読み上げる）
3. 各系の中は**「近い言葉」が隣り合う順**に並べる
4. ネガティブ語彙は必ず入れるが、**深刻度の上限は「つらい」「しんどい」まで**。絶望・消えたい・死・自傷を連想させる語は入れない
5. 学校・勉強・成績・登校関連の文脈、恋愛に関わる語は入れない
6. 系の名前は医学・心理用語（抑うつ・不安障害等）にしない

- 系ボタンに出す代表4語（`GROUPS[].sample`）は、その系の12語から選ぶだけで表記は変えない。系の幅（例: いらいら・びっくりがざわざわ系、わくわくがにこにこ系）が伝わる語を選ぶ

## 場面カードの方針（`SCENES`）

- 日常の軽い場面で、**人によって気持ちが分かれそう**なもの（2つ以上の系がありうる）にする
- 学校・勉強・登校・恋愛・暴力・ホラー・死・いじめ・仲間はずれ・家族のもめごと・叱られる・体調・お金・生活リズムを連想させるものは入れない。商品名は出さない
- 遊んでいるこの場（オンラインで、初めての人や一緒に遊ぶ人とゲームをすること）そのものを描かない。主役の答えが「この場の人への気持ち」に見えて、架空の場面でなくなるため
- 系のかたよりに気をつける。出来事の場面（うれしい・びっくり・ざんねん）だけでなく、余韻の場面（〜したあと・〜している間）を入れて、ぐったり系・ぽかぽか系・すっきり系も出るようにする
- 通常表記（漢字まじり・ふりがななし）。一文で、スマホでも3行以内に収まる長さ
- ルームでは番号だけを共有するので、**並べ替え・途中の削除はしない。追加は末尾だけ**
- 新しい場面を本体に入れるのはオーナーが決める（ルート AGENTS.md「新規コンテンツの本体投入は人間専任」）

## 意図的な逸脱

- **番号の色**: 系ボタン・ことばボタンの番号は accent ではなく系の文字色（`--ka-c-text`）。系に優劣をつけない色設計を番号にも通すため（ui.md の番号規約からの逸脱。旧 きもちのことばマップ から継続）
- **特別な選択肢**（パス・ことばは選ばない・予想しない）には番号を付けない（ui.md の標準どおり。各自が自分の端末で押すので、チャットの番号回答は不要）
- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は index.html しか見ないので、app.js の `ORPHAN_TTL_MS` と `clearInterval`・`clearTimeout` は rtdb-audit で手確認する
- **hostPlays の既定 ON**: pittari-meter（既定 OFF。ホスト画面の画面共有で秘密が映るため）と逆。1対1で遊べることを優先し、共有はみんなにみせる画面で行う。ホストの画面でも、選んだ後は中身を出さない・進み具合に中身を出さない
- **どのフェーズでも途中参加できる**（minna-ranking は待機中だけ）
- **公開画面の場面カードは小さめ**（本文 22px・余白 20/28px。600px 以下は 20px）。公開では主役の気持ち（ことばと系）を主役にし、場面は確認用に添えるため。場面・選ぶ画面の場面カードは ui.md のお題表示の定石どおり

## 入れない機能

- まとめ画面・点数・ランキング・履歴・コピー・書き出し
- 今日の気持ちをさがすモード・72語を一覧するマップ画面（2026-09-25 廃止）
- アプリ内の立候補ボタン（立候補は声かチャット、決めるのはホスト）
- チャットの予想の記録・チャットだけの子の主役（チャットで参加する節を参照）
- 時間制限・自動で進む処理（全員そろっても、公開はホストが押す）

## 既存ガイドラインからの例外

共通コンテンツガイドラインは「暗い内容を使わない」「ポジティブな軸を推奨」としているが、このゲームは気持ちのことばとして
**ネガティブな気持ちのことば（もやもや／いらいら／つらい／しんどい 等）を意図的に収録する**（旧 きもちのことばマップ から継続）。

- 理由: いやな気持ちにも「ことば」があり、人によって感じ方がちがうことを知るのがねらいの半分のため。ポジティブ語だけでは「いやな気持ちは言ってはいけない」というメッセージになる
- 歯止め: 深刻度の上限は「つらい」「しんどい」まで（語彙リスト方針 4）。場面カードは軽い日常の場面に限る
- 系の見た目でネガティブを特別扱いしない

## メンター向けの心得（画面には出さない）

- **画面共有は「みんなにみせる画面」で行う**（ルームバーの「みんなにみせる画面」で別タブを開いて、そのタブを共有する）。ホストのタブを共有すると、ホストが主役・予想で選ぶ中身が映る
- **ウィンドウ単位で共有する（Zoom の「ウィンドウ」共有など）ときは、みんなにみせる画面のタブを別のウィンドウに切り離してから共有する**。同じウィンドウのままホストのタブへ切り替えると、選ぶ中身が映る
- 終わるときは必ず「ルームを閉じる」を押す（押さずにタブを閉じると、最後の場面の選択がしばらくルームに残る）
- 主役は立候補か、本人に確かめてから決める。1対1では、最初にメンターが見本の主役をする
- パス・予想しない・ことばを選ばないを責めない。理由は聞き出さない（言いたい人だけ）
- 公開のあとは「そう感じるんだね」「いろんな気持ちがあるね」と受け止める。当たり外れで盛り上げない
- チャットだけで参加する子には、「主役が選び終わったら、系の番号をチャットで送ってね」と声をかける。先に送ると主役やほかの人に見えるので、主役が選んでからにする。公開のあとは、チャットの番号も「同じだね」「そう思ったんだね」と受け止める
