# こっそりワード 仕様書

## 目的・使用シーン

話し手の2人が、通話での雑談の中に「お題」の言葉を3回以上こっそりまぎれこませ、聞いていたみんなが「お題はどの言葉だったか」を書いて当てる会話ゲーム。
メンターと子どもが Zoom / Meet などで通話しながら遊ぶ（ボドゲクラブ・サークルタイム）。
アプリは「お題をくばる・答えを集める・発表する」だけを受け持ち、雑談そのものは通話の声で行う。
ルームに入るのは話し手の2人だけでもよい。ルームに入っていない人は、画面共有された「みんなにみせる画面」を見ながら、声やチャットで当てる。

2026-10-07 オーナーの発案。同日 `drafts/kossori-word/`（1台用のモック）で流れを確かめ、ルーム対応にして本体化した。

## オーナーの決定（2026-10-07）

| 項目 | 決定 |
|---|---|
| お題の言い方 | 話し手は言葉そのものを口に出す（言い換えで伝える遊びではない） |
| 話し手の決め方 | ホストが2人を指名する、またはおまかせ（ランダム）で選ぶ |
| 話し手のねらい | かくす（気づかれないように自然にまぎれこませる） |
| 回数の数え方 | アプリでは数えない。話し手が「3回以上言えた」と思ったら終える（話しながらボタンを押すのは負担のため） |
| 聞き手のヒント | なし。候補は出さず、聞いた言葉を自分で書く |
| 名前 | こっそりワード |
| 雑談の時間 | 何分間の雑談かを選べるようにする（1分・2分・3分・5分・決めない）。初期値は3分 |
| 準備の間 | お題が決まってすぐ時間が動くと余白がない（公開直後の実機の声）→ お題が決まったあと「雑談をはじめる」を押してから時間をスタートする |
| お題の決め方 | 話し手が3つくらいの候補から選ぶ、または自分で決める。お題の数も増やす（48語→144語） |
| ルームの外の人 | ルームに入っていない人も当てる側として楽しめるようにする（→「みんなにみせる画面」と、聞き手がルームにいなくても始められる人数条件） |

## 画面フロー

```
TOP
 ├── ホスト → 名前 → 待合室（ルームコード・「自分もプレイヤーとして参加する」・話し手を2人えらぶ）
 ├── ゲスト → 名前＋ルームコード → 待合室
 ├── 参加用のリンク ?room=CODE → 参加画面（コード入力済み・名前だけ入れる）→ 待合室
 └── みんなにみせる画面 → コード入力 → 共有画面（?watch=CODE。読み取りだけ）
                ↓ ホスト「お題をくばる」
        お題えらび（話し手: 3つの候補から1つ、または「自分で決める」→「この言葉にする」／聞き手: えらんでいるよ）
                ↓ 話し手のどちらかがえらぶ（ホストは「話し手をえらび直す」で待合室にもどせる）
        じゅんび（話し手: お題と「雑談をはじめる」／聞き手: 準備しているよ。時間はまだ動かない）
                ↓ 話し手のどちらか、またはホストの「雑談をはじめる」
        雑談タイム（話し手: お題と「話しおわった」／聞き手: よく聞いてね。のこり時間を全員に表示）
                ↓ 話し手のどちらかの「話しおわった」／時間切れ（ホストは「雑談を終わりにして、答える時間にすすむ」）
        答える時間（聞き手: 言葉を書いて「これで答える」。発表までは書き直せる）
                ↓ ホスト「お題を発表する」
        発表（お題・話し手・何人が見抜いたか・見抜いた人）
                ↓ ホスト「つぎのお題へ」→ 同じメンバーで待合室へ
```

## status 遷移

`waiting → choosing → talking → answering → result → waiting …`

- どの遷移もルーム全体の `transaction()` で、いまの `status` を確かめてから進める
- `waiting → choosing`: ホストだけ。話し手・候補3つ（`options`）・`round` を確定し、全員の `answer` を消す
- `choosing → talking`: 話し手だけ（先にえらんだほうで決まる）。`topic` を入れる。**この時点では時間を動かさない**（`talkStarted`・`talkEndsAt` は無し＝準備の間）
- 雑談の開始（`talking` のまま）: 話し手かホストの「雑談をはじめる」で `talkStarted=true` と `talkEndsAt`（雑談の時間が「決めない」なら無し）を入れる。画面の見出しは、開始前「じゅんび」・開始後「雑談タイム」
- `choosing → waiting`: ホストだけ（「話し手をえらび直す」。`round` を1つもどす）
- `talking → answering`: 話し手（`speakers` に名前があり、在籍している人）かホスト。`talkEndsAt` を過ぎたら、ホストと話し手の端末が同じ transaction を自動で送る（その回の `talkEndsAt` と一致するときだけ進める）
- `answering → result`・`result → waiting`: ホストだけ
- 途中参加は断る（`waiting` のときだけ参加できる。「いまお題の途中だよ。発表が終わってから…」）

## Firebase データ構造（Realtime Database）

```
kossoriword_rooms/{roomCode}/
  ├── host:               string    # ホストの名前
  ├── hostConnected:      boolean
  ├── hostDisconnectedAt: number    # 切断時のサーバー時刻（TTL 判定用）
  ├── status:             string    # waiting | choosing | talking | answering | result
  ├── round:              number    # くばった回数（0 から。くばるたびに +1）
  ├── options:            number[]  # 話し手に出す候補3つ（TOPICS の添字）。choosing の間だけ
  ├── topic:              string    # いまのお題（候補の言葉、または話し手が自分で決めた言葉。waiting にもどすと消す）
  ├── talkStarted:        boolean   # 「雑談をはじめる」が押されたか（お題が決まった直後は無し）
  ├── talkEndsAt:         number    # 雑談が終わる時刻（ms）。「雑談をはじめる」で入る。雑談の時間が「決めない」なら無し
  ├── used:               number[]  # 話したお題の番号（TOPICS の添字）。候補が3つ出せなくなったら最初から。自分で決めた言葉は入れない
  ├── speakers/{名前}:    true      # いまの話し手2人
  ├── spoken/{名前}:      true      # 話し手になった人（おまかせで、まだの人を先に選ぶ）。全員が話したら消す
  ├── manualHits/{名前}:  true      # ホストが「当たりにする」を押した聞き手
  ├── settings/hostPlays: boolean   # ホストも遊ぶか（作成時 true・キーなしは true 扱い・待合室でだけ変更）
  ├── settings/talkSecs:  number    # 雑談の時間（秒）。60 / 120 / 180 / 300 / 0（決めない）。作成時 180・待合室でだけ変更
  └── players/{名前}/
       ├── isHost:          boolean
       ├── answer:          string   # 聞き手が書いた言葉（次のお題をくばるとき・待合室にもどるときに消す）
       ├── presenceVersion: 1        # ゲストの接続情報の方式
       └── connections/{id}: true    # 接続ごとの生存記録（ゲストのみ）
```

- 待合室での話し手の選択（指名・おまかせ）はホストの端末の中だけに持ち、「お題をくばる」の transaction で確定する。ホストが再読み込みすると選択は消える
- `answer` はゲームの進行用の一時データ。ルームと一緒に消え、ほかの場所には保存しない。`stats.js` には回数（`round`）だけを送る

## ホストの参加

- 待合室のホスト用の欄に「自分もプレイヤーとして参加する」（初期値: 参加）。変えられるのは待合室だけ
- 外すと進行役になる。話し手に選べず、答えもしない。参加者一覧に「進行役」タグ
- **遊ぶ人** = ホストが参加するなら全員、しないならホスト以外
- 始められるのは、遊ぶ人のうち接続している人が2人以上（話し手の2人）のとき。聞き手はルームの外（通話・みんなにみせる画面）にいてもよい
- **ホストの画面は共有されることが多いので、ホストの画面に出るひみつは折りたたむ**（koedake-theater などと同じ扱い）
  - ホストが話し手のとき: 候補は「お題をえらぶ（タップでひらく）」、お題は「あなたのお題（タップで見る）」の折りたたみの中
  - 発表画面の「ほかの答え（タップで見る）」: 外れた答えの一覧（ホストだけ）
  - ホストが聞き手のときに書く答えは折りたためない（入力欄なので）。ホストが遊ぶときは「みんなにみせる画面」を共有する

## 当たりの判定

- 自動: 答えとお題（と `ALIASES` の別の書き方）を、`NFKC`・空白除去・小文字化・カタカナ→ひらがなでそろえて一致を見る
- 手動: 漢字など書き方がちがうだけの答えは、発表画面でホストが「当たりにする」を押す（`manualHits`。取り消せる）
- 外れた答えを見られるのはホストだけ。ほかの人には「見抜いた人」の名前と、自分の答えだけを出す
- **得点・順位・回数の記録はつけない**。発表は「N人のうちM人が見抜いた」と見抜いた人の名前だけ。だれにも見抜かれなければ話し手をほめる
- 聞き手の数は、遊ぶ人のうち話し手でない人。接続が切れたまま答えていない人は数えない。ルームの外（声やチャット）で当てた人は数えない
- ルームの中に聞き手がいないときの発表は「当たっていたかな？」だけ

## みんなにみせる画面（画面共有用）

ルームに入っていない人も当てる側として楽しめるようにする、読み取り専用の画面（`#screen-spectator`）。作りは kakure-number などの同名の画面にそろえている。

- 入口は3つ: (1) アドレスの `?watch=CODE`（最優先。先に保存した記録を消してから検査し、無効・ルームなし・期限切れはトースト＋トップ） (2) トップの「みんなにみせる画面をひらく」→ コード →「画面をひらく」（成功したらアドレスを `?watch=CODE` にそろえる） (3) ホストの待合室の「みんなにみせる画面をひらく」（クリックの中で同期的に `window.open(url, '_blank', 'noopener')`）
- `state.role = 'spectator'`。ルーム監視の入口で `handleSpectator(room)` へ分岐し、ホスト・ゲストの処理（切断オーバーレイ・期限切れの削除・onDisconnect・players への読み書き）に入らない
- **RTDB には一切書き込まない**（匿名認証だけ行う）。sessionStorage の記録も持たない（再読み込みはアドレスの `?watch=` から入り直す）
- **お題を DOM に入れるのは発表（`result`）だけ**。待合室にもどったら消す。候補（`options`）と、聞き手が書いた答えは出さない（答えた人数だけ）
- 表示: 待合室「話し手を決めているよ」／お題えらび「○○さんと○○さんが、お題をえらんでいるよ」／じゅんび「○○さんと○○さんが準備しているよ」／雑談「○○さんと○○さんの話をよく聞いてね」＋のこり時間／答える時間「お題はなんだった？…入っていない人は、声やチャットで答えてね」＋ルームの聞き手の答えた人数／発表はお題・話し手・結果の1行・見抜いた人
- ホスト切断中は注意書きを出す。期限切れ・ルーム削除では購読を止めて「このルームは終わったよ」を残す（ルームは消さない）
- 「トップへ戻る」は購読を外し、`?watch` をアドレスから除いてトップへ。ルームには触らない

## 切断時の挙動・再接続

word-wolf と同じ方式（ゲスト保持の共通規約例外）。

- ホストの接続は `.info/connected` を監視し、つなぐたび（作成・再読み込み・通信が切れたあとの自動再接続）に、切断時の予約（`onDisconnect().update`）を張り直して `hostConnected=true`・`hostDisconnectedAt=null` にもどす（`startHostPresence`）。もどさないと、一時的な通信切れのあともゲストに切断の表示が残り、2分後にルームが消される（2026-10-07 独立レビューの指摘で追加。word-wolf にはない）
- ルームが消えた通知を受けたときは、予約済みの onDisconnect を取り消し終えてから状態を捨てる（取り消しの前に切断するとゴースト room になる。同レビューの指摘）

- ホスト切断: `hostConnected=false`・`hostDisconnectedAt` を保存。ゲストにオーバーレイを出し、2分（`ORPHAN_TTL_MS`）を過ぎたらゲスト側が期限切れとして削除を試みる
- ゲストの一時切断: 接続ごとの `connections/{id}` だけを `onDisconnect().remove()` し、player 本体（名前・答え）は残す。待合室では「接続を待っているよ」と出し、話し手に選べない・人数に数えない
- 明示的な「退出する」: ゲストは自分の `players/{名前}` を消す。ホストはルームを消す
- 再読み込み: sessionStorage（`kossoriword_session`）から同じルーム・同じ役割に戻る。答えた言葉は入力欄にもどす。ホストは `hostConnected=true` にもどす
- 話し手が雑談中に落ちても、もう1人の話し手かホストが先へ進められる

## セッション削除の例外

ルート規約ではゲーム終了後30秒でルームを削除するのが基本だが、このアプリは発表（`result`）のあと自動削除しない（公認バリアント「ふりかえり画面滞在中は削除しない」）。

- 理由: 発表から「つぎのお題へ」で、同じメンバーのまま話し手を変えて続けるため
- 削除の経路: (1) ホストの「退出する」で即時削除 (2) ホスト切断の2分 TTL (3) 次回アクセス時の期限切れ掃除（`status` のないゴースト room も期限切れ扱い）

## お題

- `TOPIC_GROUPS`（12の仲間 × 12語 = 144語。2026-10-07 オーナーが一覧を確認して公開を指示）。くばるときは、まだ話していない言葉からランダムに3つを候補に出し、話し手が1つえらぶ（えらばれなかった候補は、あとでまた出ることがある）
- 話し手は候補のかわりに、話したい言葉を自分で決められる（12文字まで）。自分で決めた言葉は検査しない（発表で全員に出るので、気になる言葉はその場でメンターが声をかける）。自動判定はひらがな・カタカナのちがいだけなので、漢字の書き方ちがいはホストが「当たりにする」
- 同じ読みで別の言葉になるお題は入れない（例: 「雨」と「あめ（おかし）」。声で聞き分けられず、判定も重なる）。1文字で聞き取りにくい言葉（絵・木など）も避ける
- 雑談に自然にまぎれこませやすい、身近な名詞にする。学校・勉強、恋愛、暴力・ホラーを連想させる言葉は入れない
- 漢字のお題にはひらがな、ひらがなのお題には漢字の書き方を `ALIASES` に足す（自動判定のため）
- お題を足す・変えるときは `node scripts/content-audit.mjs` で重複を確かめる

## 特有のルール・制約

- ルームコードは6桁英数字（紛らわしい文字除外）。名前は1〜8文字・同ルーム内重複NG・`. # $ [ ] /` は使えない
- ルームに入れるのは12人まで（ホストをふくむ）。みんなにみせる画面はこの人数に入らない
- 答えは20文字まで。答えの欄も、自分で決めるお題の欄も、日本語入力の変換を確定する Enter では送らない
- 雑談の時間の初期値は3分（2026-10-07 オーナー決定）。時間が動くのは「雑談をはじめる」から。`talkEndsAt` だけがあって `talkStarted` のない部屋（公開直後の版でお題を決めたもの）は、開始済みとして扱う（`talkStartedOf`）。のこり時間は `RoomkRTDB.now()`（サーバー時刻寄り）で計算する
- 表記は通常表記（漢字まじり）、文体は「〜だよ・〜してね」

## メンター向けの心得

- 話し手は、やりたくない子に無理にさせない。指名する前に声をかけるか、「話し手をおまかせでえらぶ」のあとで変えてよいと伝える
- 回数はきびしく数えない。「3回くらい言えたかな」で十分。時間切れで3回言えなくても、そのまま答える時間に進んでよい
- 話し手がお題えらびで止まったら、「話し手をえらび直す」で待合室にもどせる
- 外れた答えを読み上げて比べない。発表は「だれが見抜いたか」と、話し手のかくし方のうまさに目を向ける
- 画面共有するのは「みんなにみせる画面」。ホストが進行役のときはホストの画面を共有してもよいが、ホストが話し手・聞き手として遊ぶときはホストのタブを共有しない（お題や自分の答えが映るため）
- ルームに入っていない人の答えは、声やチャットで受ける。アプリは数えないので、発表のあとに「当たった人いる？」と聞く

## 検証と独立レビュー（2026-10-07）

- 隔離エミュレーターの E2E（本番には接続しない・計156項目）: 作成・参加・話し手えらび・お題えらび（候補・自分で決める・えらび直す）・雑談の時間（表示・決めない・時間切れで自動で進む）・3ラウンド・ホスト参加の切り替え、再読み込み・退出・切断・期限切れ・入口の例外、みんなにみせる画面（書き込みゼロ・お題は発表まで出ない）・ルームの外の聞き手・ホストの一時切断からの復帰
- 別系統モデル（Codex）の読み取りだけの独立レビュー: 指摘2件（ホストの自動再接続で `hostConnected` がもどらない／ルーム消失時に onDisconnect の取り消しを待たない）を修正
