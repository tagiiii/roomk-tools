# みんなでランキング 仕様書

## 目的・使用シーン

ホストが選んだ同じお題で、遊ぶ人がそれぞれランキングを作る。ほかの人の1位を予想してから結果を公開し、順位の違いを会話のきっかけにする。ホストは待合室で「自分もランキングを作って参加する」を選べる。**初期値は進行だけ**（ランキングと予想に参加しない）。参加を選ぶとホストもランキングを作り、ほかの人の1位を予想し、ほかの人からも1位を予想される。

人数は**遊ぶ人が2人以上**。ゲストの上限は4人のまま（ホストが遊ぶと遊ぶ人は最大5人、進行だけならゲスト2〜4人）。

ランキングは好みの表現であり、内容を採点しない。予想が当たった人にだけ、このお題の間の一時的な1ポイントを付ける。ポイントはルーム内の進行状態としてのみ保持し、次のお題でリセットする。

## 技術と保存

- Realtime Database と匿名認証。パスは minnaranking_rooms/{roomCode}。
- ルームコードは共通関数の6文字。ニックネームは8文字以内、同一ルームで重複不可。
- お題は既存の45問を利用。ホストはガチャ、一覧、自分たちで作るから選べる。新しいプリセットのお題はこの変更では追加しない。
- 入力中の並びは各端末だけで扱い、再読み込み復帰用に sessionStorage に一時保存する。提出時だけ RTDB に書く。
- ルームを閉じるまで結果はルーム内に残す。ホストの明示的な退出でルームを削除する。ホスト切断後2分の期限切れ判定と次回アクセス時の掃除も行う。ふりかえり中の明示退出・TTL・次回アクセス時掃除のバリアントを採用する。
- 開発・静的監査から本番 Firebase に書き込まない。

## 進行

1. ホストがルームを作る。参加者は名前、ルームコードの順に入れて参加する。
2. 待機中、ホストがお題を選び、自分も参加するかを選ぶ。遊ぶ人が2人以上になれば開始できる。開始時に遊ぶ人の順（roundOrder）、お題、進行状態を transaction で確定する。
3. 各参加者が個人のランキングを作り、提出する。ドラッグと上下ボタン、上とタイ、ランク外を使える。予想の選択肢を全員で共通にするため、個別のアイテム追加は行わない。最低1個は順位に残す。
4. 目安3分を表示するが、自動で次に進まない。ホストはいつでも提出済みの人だけで予想へ進める。未提出の作りかけは公開しない。提出者が0人ならそのお題の結果画面へ進む。
5. 提出した遊ぶ人を一人ずつ対象に、ほかの遊ぶ人がその人の1位を予想する。対象者と進行だけのホストは予想しない。自分のランキングを提出しなかった人も予想には参加できる。
6. ホストは予想の提出を待たずに結果を公開できる。未予想はパス。公開時に対象者の全ランキングと各自の予想を示す。対象者の1位がタイなら、そのどれを選んでも当たり。正しい予想に1ポイントを付ける。
7. ホストが次の人へ進め、全員の公開後にこのお題のポイントを表示する。次のお題へ戻るとポイントと回答を消す。

## メンターの心得

- ホストが遊ぶときは、自分のランキングを開く前に画面共有を止める（開いた並べ替え欄はそのまま共有画面に映る）。画面上には注意書きを出さない

## 心理的安全

- 順位の対象はものごとだけ。人物・成果・行動を並べるプリセットのお題は入れない。
- ランキングに正解・優劣・評価はない。点数は1位の予想にだけ付く。
- 提出・予想には強制的な締め切りを設けない。離席した参加者がいてもホストが段階を進められる。
- 未提出はパス扱い。初期の並びや作成途中の並びを本人の答えとして表示しない。
- 未提出者や未予想者を責める演出・敗者扱いはしない。

## ホストの参加（2026-10-01 追加）

- 待合室の「参加者」欄に、ホストだけに見えるチェックボックス「自分もランキングを作って参加する」（`#set-host-plays`）。保存先は `settings/hostPlays`（boolean）。作成時は `false`。**キーがない旧ルームも進行だけ**（`hostPlaysOf()` = `settings.hostPlays === true`）
- 書けるのはホストだけ・`status === 'waiting'` の間だけ（transaction で確認）。結果画面・次のお題の前では変えず、待合室に戻ったときに変えられる。値は次のお題へ引き継ぐ
- 遊ぶ人 = `playerNames()`（ゲスト全員＋参加を選んだホスト、参加順）。開始時の `roundOrder`・最少人数（2人）・提出状況・予想状況はこれで数える。参加の満員判定（`MAX_GUESTS = 4`）はゲストだけで数える
- 最少2人の根拠: 予想は対象者以外の遊ぶ人が出すため、遊ぶ人が2人いれば各対象者に予想する人が1人以上いる。ホスト＋ゲスト1人でも成り立つ
- 待合室の一覧にホストの行を出し、進行だけなら「進行役」、参加なら「ホスト・参加中」
- 案内: 足りないときは「あと N人で始められます。（自分を入れて2人から／ホストのほかに2人から）」
- 遊ぶホストの画面: ランキングを作る段階では、自分の並べ替え欄を `<details>` の折りたたみ（`#hostRankSecret`「自分のランキング（タップで開いて並べる）」）に入れ、普段は閉じておく。提出すると閉じ、見出しが「提出しました」になる。ランキングを作る段階を出たら必ず閉じ直す。提出状況・予想へ進むボタンなどの進行操作は折りたたみの外。予想の段階では、ほかの人の1位を予想する選択肢と進行操作（予想の提出状況・結果を公開）を両方出す。自分が対象のときは選択肢を出さない
- ホスト自身のランキングは、結果発表（reveal）で公開されるまで画面に開いた状態で出さない。他人のランキングは従来どおり公開まで誰にも見せない（ホストにも）
- 進行だけのホストの画面は従来どおり（提出状況・予想の提出状況・公開・次へだけ）
- 再接続: ホストは `host`・`hostUid` で戻る（hostPlays に関係なく戻れる）。遊ぶホストの作りかけの並びもゲストと同じく sessionStorage から戻る
- 自動で書き込む処理（watchdog など）はないため、遊ぶ人が全員抜けて進行役だけ残っても書き込みは繰り返されない。ホストが段階を進めるか次のお題へ戻す

## ルーム状態

status は waiting → ranking → guess → reveal → guess… → done → waiting と進む。ルーム作成・参加・開始・提出・進行・予想・公開は transaction でフェーズを確認する。提出者の一覧は ranking から guess へ進むときに確定する。ホストのみがフェーズを進める。

ホスト切断時は接続待ちの画面を出し、2分を過ぎたルームは期限切れとする。ゲスト切断時は players の該当者のみ onDisconnect で消す。提出済みの結果と予想は再接続・公開のために残し、提出後に切断しても公開対象に含める。明示退出では自分の提出と予想を削除し、現在の公開対象なら次の人へ進める。再読み込みでは sessionStorage のルーム情報から復帰する。

## お題作成の制約

自由入力のお題30文字、アイテム15文字・2〜8個。重複は不可。プリセットは既存の45問。人物・成果・行動、学校や成績、恋愛、怖い話、対立を生みやすい話題は扱わない。
