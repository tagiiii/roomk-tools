# ことばひろい 仕様書

## 目的・使用シーン

5〜7つのひらがなが並ぶ。決められた文字数になるように文字をえらんで、言葉をつくるルーム型のゲーム。
みんなでボードの言葉をうめる「協力」と、早く見つけた人の言葉になる「個人戦」を、ホストが待合室で選ぶ。

2026-11-25 にオーナーが、テレビで見た「5文字くらいの中から、決められた文字数の言葉を見つける」ゲームから相談し、同日に構想 → 問題の候補 → 本体化まで進めた。番組名は分かっていないので、着想元は書かない（早見表は系統ラベル「文字えらび・言葉づくり系」）。
構想の記録は [docs/moji-erabi-design-v1.md](../../docs/moji-erabi-design-v1.md)、問題を選んだ記録は [docs/content-candidates/moji-erabi-puzzles-2026-11-25.md](../../docs/content-candidates/moji-erabi-puzzles-2026-11-25.md)。仕様の正本はこのファイル。

- ことばシャッフル（`kotoba-shuffle`）は出た文字を**全部**使って答え1つを当てる。こちらは**一部だけ選び**、答えがいくつもある
- もじそろえゲーム（`moji-soroe`）は手番制の麻雀型。こちらは手番なしで、同じ文字をみんなで探す

## 技術スタック

Firebase Realtime Database + 匿名認証。分割ファイル（`index.html`・`app.js`（module）・`style.css`・`data.js`）。接続・作成・参加・再接続・退出・ホスト切断の扱いは `kotoba-dash` と同じ形。`RoomkRTDB.initFirebase()`・`RoomkRTDB.now()`・`copyRoomCode` / `copyRoomLink`・`RoomkQR`・howto・stats を使う。名前空間は `kotobahiroi_rooms`。

## 遊び方（ルール）

### 1問の流れ

- 問題がはじまると、文字（並びはホストが問題ごとにまぜて `q.tiles` に書く）と、ボード（答えの数だけ「○」のマス）が出る
- 文字を順に押して、決められた文字数の言葉をつくり、「これにする」で出す。1つの言葉の中で同じ文字は1回だけ（押した文字は薄くなって押せない）。言葉ごとに全部の文字を使える
- 「1文字もどす」「ぜんぶ消す」「文字をまぜる」（自分の画面の並びだけ変える）
- 出した言葉は、自分の画面にだけ返事が出る（「見つけた！「さくら」」「もう見つかっている言葉だよ」など）

### 出した言葉の扱い

| 言葉 | 扱い |
|---|---|
| 答えの一覧（`answers`）にある・まだ見つかっていない | `found/{問題}/{言葉}` に transaction で書く。先に書けた人のもの（個人戦はここで取り合いになる） |
| もう見つかっている（ボードか、OK になったほかの言葉） | 送らない。協力「もう見つかっている言葉だよ」、個人戦「もう見つけた言葉だよ」／「もうだれかが見つけた言葉だよ」 |
| 外す言葉（`ng`） | 送らない。「ほかの言葉をさがしてみよう」 |
| それ以外（グレー `gray` も、一覧にない言葉も） | `pending/{問題}/{言葉}` に書く。みんなの画面に「たしかめ中の言葉」として出す（**だれの言葉かは出さない**） |

- ホストの画面に「一覧にない言葉（みんなでたしかめてね）」と「OK」「ちがうみたい」。OK なら `extra/{問題}/{言葉}` に入れ、ボードの下の「ボードのほかに見つけた言葉」に出す。ちがうときは、だれの言葉かも出さずに消す（ルート AGENTS.md「却下した答えは、だれの答えかも文も出さない」に近い形。文は「たしかめ中」のあいだ出ているが、出した人の名前は出ない）
- たしかめないまま次の問題へ進んだ言葉は、そのまま消す
- グレーを一覧と分けて持つのは、問題を選ぶときの記録として残すため。画面ではほかの一覧にない言葉と同じ扱い

### 問題のおしまい（`q.ended`・`q.endedBy`）

- ボードの言葉が全部見つかった（`all`）: 協力は「全部うまった！ クリア！」、個人戦は「全部見つかったよ！」
- 制限時間になった（`time`）・ホストが「のこりのこたえを出す」（`host`）: 見つかっていない言葉を薄い色で開く
- おしまいの判定はホストの画面だけが行う。ホストが切断している間は、時間になっても進まない
- おしまいのあとはホストの「つぎの問題へ」（最後は「結果を見る」）

### ヒント

ホストの「ヒントを出す」で、まだのマスを1つ選んで最初の文字を出す（`hints/{問題}/{言葉}`。みんなの画面に出る）。

### ボード

- 答えはあいうえお順に並べる
- 協力: 見つかった言葉はマスに入る。だれが見つけたかは出さない（見つけられなかった子が目立たないように）
- 個人戦: 自分が見つけた言葉だけ色を変える。遊んでいるあいだはほかの人の名前を出さない。上の行に「あなた ◯こ」

### 結果

- 問題ごとに、文字の組と言葉（見つかった言葉・見つからなかった言葉（薄く）・ボードのほかに見つけた言葉）
- 協力: 「みんなで ◯こ 見つけたよ」（0このときは出さない）
- 個人戦: 「あなたは ◯こ 見つけたよ」（0このときは出さない）と「見つけた数」に一人ずつの数を**多い順**に並べる。**順位の数字はつけない。0この人は並べない**。数えるのはボードの言葉と OK になったほかの言葉。退出した人・端末なしの参加者の数も残す

### 設定（待合室）

| 項目 | 選べるもの | はじめ |
|---|---|---|
| 遊び方 `mode` | 協力 `coop`／個人戦 `race` | 協力 |
| むずかしさ `level` | やさしい（5枚・2文字）／ふつう（6枚・3文字）／むずかしい（7枚・3か4文字）／まぜる | ふつう |
| 問題の数 `count` | 3問／5問（その段階の問題が少ないときは全部。むずかしいは2問） | 3問 |
| 制限時間 `limit` | 決めない／1分／2分／3分（1問ごと） | 決めない |

問題は「はじめる」のときに、選んだ段階の中からまぜて選ぶ（`order`）。同じ回の中で同じ問題は出ない。

### 画面と文字の大きさ

大きくするのは遊ぶ画面（ボード・文字・つくる場所）だけ。待合室・名前の入力・結果はほかのツールと同じ大きさ（ui.md「画面の幅と文字の大きさ」）。囲みは 760px（遊ぶ画面だけ 860px）。ボタンの高さは 56（「これにする」「はじめる」「つぎの問題へ」）・48（そのほか）・36（ルームのバー・端末なしの「外す」）。音は鳴らさない。

## 画面構成・status 遷移

`waiting`（待合室）→ `play`（問題。`q.idx` で何問め）→ `result`（結果）→ ホストの「もう一回（待合室へ）」で `waiting`。

## Firebase データ構造

```
kotobahiroi_rooms/{code}
  status: 'waiting' | 'play' | 'result'
  host, hostUid, hostConnected, hostDisconnectedAt
  settings: { hostPlays, mode, level, count, limit }
  game: はじめた回数
  order: [問題の id]
  q: { idx, tiles: [並べる文字], startAt, endAt (0 は決めない), ended, endedBy?: 'all' | 'time' | 'host' }
  found:   { 問題番号: { 言葉: { by, at } } }   … ボードの言葉
  pending: { 問題番号: { 言葉: { by, at } } }   … たしかめ中（by は画面に出さない）
  extra:   { 問題番号: { 言葉: { by } } }       … OK になったほかの言葉
  hints:   { 問題番号: { 言葉: true } }
  players: { 名前: { isHost, uid, joinedAt } }
  proxies: { 名前: { joinedAt } }              … 端末なしの参加者
```

- 言葉を出すのは `found/…/{言葉}`・`pending/…/{言葉}` への子の transaction（あれば書かない）。個人戦の取り合いはここで決まる
- ホストの操作（設定・端末なしの参加者・はじめる・ヒント・たしかめる・おしまい・つぎへ・待合室へ）は、どれも `hostUid` を確かめるルームの transaction
- 答えの一覧は参加する人の端末にも届く（`data.js`。性善説。画面には見つかるまで出さない）

## ホストも遊ぶか・途中参加・端末のない参加者

- **ホストも遊ぶ（`settings.hostPlays`）: 初期値は「遊ぶ」**。ホストの画面にも答えは見つかるまで出ないので、同じ条件で遊べる。進行だけのときは待合室で「進行役」の印
- 遊ぶ人が1人以上いれば始められる（ホストひとりでも遊べる）
- **途中参加**: どの status でも参加でき、問題の途中でもすぐ言葉を出せる
- **端末のない参加者を作る**（rtdb.md「端末のない参加者」）: ホストが待合室の「端末なしの参加者を足す」で名前を足す（4人まで。ほかの人と同じ名前は不可。「外す」で外せる）。在室を持たず、いつも遊べる人として数える。遊んでいるあいだ、ホストの画面に「だれの言葉？」（自分が遊ぶときの自分と、端末なしの参加者）を出し、選んだ人の言葉として出す。印と「外す」はホストの画面にだけ出す。秘密の情報はないので、ホストが遊ぶかは変えない
- 声を使わないゲームなので「ひとこと」は持たない（言葉は画面の文字で出す。たしかめるときの話し合いはチャットでも加われる）

## 切断時の挙動・削除

- ホスト切断: `hostConnected=false`・`hostDisconnectedAt`。ゲストには「ホストの戻りを待っています」を出し、TTL（`ORPHAN_TTL_MS` = 2分）を過ぎたら期限切れとして消す
- ゲスト切断: `players/{名前}` の `onDisconnect().remove()`。戻ったときは同じ名前で在室を足し直す（見つけた言葉は名前で持っているのでそのまま）
- 再接続: sessionStorage（`kotobahiroi_session`）で同じルームに戻る
- **自動削除は rtdb.md「公認バリアント: ふりかえり画面滞在中は削除しない」を採用**: 結果のあとも続けて遊ぶ（「もう一回」）ことが多いので、終了30秒後の自動削除はしない。(1) ホストの「ルームを閉じる」 (2) ホスト切断の TTL (3) 次回アクセス時の期限切れ掃除 の3経路で消す

## 問題（`data.js`）

- `window.KOTOBA_HIROI_PUZZLES` に12問（やさしい4・ふつう6・むずかしい2）。1問は `{ id, level, tiles, len, answers, gray, ng }`
- 答えは1問8〜10個を目安にする（協力のボードで、早く終わりすぎず、最後で止まりすぎない数）
- 足すときは、文字の組から作れる並びを**すべて書き出して**言葉を拾い、悪い言葉・学校やこわい言葉が作れないかも見る（作れたら `ng` に入れるか、文字の組を変える）。動詞は辞書の形だけ・人名や地名や国名は入れない
- `node scripts/content-audit.mjs` が、言葉が文字の組から作れるか・文字数・重なり・同じ文字の組の重複を確かめる（構造エラーは fail-fast）
- 「い・か・た・ら」を含む問題が多く、答えが一部重なる（からい・こたつ・いくら など）。問題を足すときは字がかたよらないようにする
