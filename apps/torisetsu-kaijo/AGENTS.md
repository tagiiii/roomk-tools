# とりせつ解除班 仕様書

## 目的・使用シーン

1人だけが爆弾を見て、ほかの人は説明書を読む協力ゲーム（2〜6人）。解除する人はしかけの様子を声で伝え、読む人は説明書から止め方をさがして伝える。時間のうちに、しかけをぜんぶ解除する。

- **core value**: 見えている人と、知っている人が別。見たものを言葉にする・聞いて確かめる・急いでいるときに落ち着いて伝える、がそのまま遊びになる
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの2人でも遊べる）。種類は「当てっこ・協力ゲーム」（`data-genre="atekko"`）
- 着想元: 『完全爆弾解除マニュアル：Keep Talking and Nobody Explodes』。紹介は**段階1（既定）**: 早見表と `updates.json` に「『Keep Talking and Nobody Explodes』から着想」。アプリ名・画面・検索のキーワードには入れない
- **借りたのは遊びのしくみだけ**（1人が爆弾を見て、ほかの人が説明書を読む・時間・まちがいの数・割り込むしかけ）。しかけの種類と決まり・説明書の文・記号・爆弾の見た目・名前は、すべてこのツールのために作った。着想元のモジュール・マニュアルの表・記号・見た目・音は写さない（ルートの app-registration.md「着想元に寄せるとき」）。しかけを足すときも同じ

> 経緯: 2026-11-26、オーナーが「完全爆弾解除マニュアルに似たツール」を相談。はじめは爆発を使わない案（機械の修理・ロケットの点検）を出したが、オーナーが「スリル感を出して遊びたい」「爆発でもOK」「本家に作りを寄せて臨場感を出したい」「1人だけが見る。いろんな箇所を見て3D風に動かせる」と決め、同日「本番で作っていって」で本体として作った。名前「とりせつ解除班」はオーナーが3案から選んだ（商標は未確認）。

## 既存ガイドラインからの例外（オーナー判断 2026-11-26）

- **爆弾・爆発を題材にする**（ルート AGENTS.md「暴力・ホラー・死・怖い話などダークな内容」を使わない、の例外）。オーナー「爆発でもOK」。そのうえで、爆発は**マンガ調**（ギザギザの絵と「ドカーン！」の文字）だけにし、人・けがの絵は出さない。強い点滅は使わない。音は鳴らさない（オーナーへの案では「音ははじめ切で、ホストが入れられる」としたが、まだ作っていない。足すときは、はじめは切にする）
- **時間に追われる**（スリルが目的。オーナー「スリル感を出して遊びたい」）。時間がつらい回のために、待合室の「ゆっくり（時間をはからない）」を残す
- **失敗を人に結びつけない**: 爆発の画面・結果の文には、だれの名前も出さない（「まちがいが3回になった」「時間が0になった」だけ）。まちがいの知らせ（「まちがい！」）にも名前を出さない。解除する人は1回ごとに交代する

## ルール

| 項目 | 内容 |
|---|---|
| 役 | 1回ごとに、遊ぶ人のうち1人が**解除する人**、ほかは**説明書を読む人**。解除する人は参加した順に交代（`turn`）。待合室で「解除する人にならない（説明書を読むだけ）」を本人が選べる（ホストも付け外しできる。`players/{名前}/ro`） |
| 爆弾 | 箱の形。表と裏にしかけが3つずつ入る場所（6か所）。手がかりが4つ: 左の側面のシール（赤・青・黄・緑）・右の側面の4けたの番号（最後の数字を使う）・上のねじ（2〜5本）・底のふたの中の印（ほし・つき・たいよう。ふたを開けると見える） |
| むずかしさ | やさしい: しかけ3つ・5分・導火線なし／ふつう（はじめ）: 4つ・5分・導火線あり／むずかしい: 5つ・4分・導火線あり |
| まちがい | 3回で爆発。1回ごとに時間のへりかたが速くなる（1倍 → 1.25倍 → 1.5倍） |
| 時間 | 0で爆発。「ゆっくり」のときは時間をはからず、導火線も出ない（まちがい3回で爆発は同じ） |
| 導火線 | はじめてから30秒で火がつき、そのあと45秒ごと。20秒のうちに正しいつまみ（△○□）を押す。まにあわないと、まちがい1回。まちがったつまみを押しても、まちがい1回（火はついたまま） |
| 成功 | 導火線のほかのしかけを、ぜんぶ解除する |
| 説明書 | 「本体の手がかり」は読む人みんなが持つ。しかけのページは、「説明書を分けて配る」（はじめはオン）で読む人が2人以上のとき、1ページずつ順に配る（だれも0ページにならない。読む人のほうが多いときは、同じページを2人が持つ）。その回の爆弾にないしかけのページは配らない |

### しかけ（すべて自作。決まりは `engine.js` の表が正本で、説明書の文も同じ表から作る）

| しかけ | 見えるもの | 止め方 |
|---|---|---|
| コード | 上の①〜⑤から下のア〜オへ、交差しながらつながる5色（赤・青・黄・白・黒）のコード | シールの色 × 番号の最後の数字（0・2・4・6・8／1・3・5・7・9）で決まる行き先（ア〜オ）につながるコードを1本切る。それが黒なら切らずに①（①が黒なら⑤）。ちがうコードを切ると、まちがい1回（切れたまま） |
| 記号スイッチ | 名前のない記号4つ（12種類から）と、それぞれのスイッチ | 記号ごとに決まった条件（手がかり）で上か下にして「たしかめる」 |
| ダイヤル | 色のランプ3つと、1〜8のダイヤル | いちばん左のランプの色 × 同じ色のランプがあるか（3つともちがう・2つが同じ・3つとも同じ）で決まる数字に合わせて「たしかめる」。印が「つき」なら反対がわの数字 |
| やじるし | 色のついた形（まる・さんかく・しかく・ひしがた × 赤青黄緑） | 形で決まる4回の順を、色で決まる読み方（そのまま・うしろから・上下を入れかえ・左右を入れかえ）で押す。まちがえると、まちがい1回ではじめから |
| 導火線（割り込み） | 火の色と、つまみ3つ | 火の色 × ふたの中の印で決まるつまみを押す |

- 色は、近くで見る欄では名前（「赤」など）も文字で出す（色だけに頼らない）。色を言い当てることは遊びの中心ではない
- 記号12種類は `art.js` の線画。名前は付けない（どう言い表すかが遊び）
- しかけ・説明書の表・手がかりを足す・変えるときは、オーナーが決める。変えたら `tests/torisetsu-kaijo/engine.test.cjs`（正しい操作で必ず解除できる・説明書の行数・記号の決まりが重ならない・やじるし16通りが重ならない）を流す

## 画面構成

| 見る人 | 出るもの |
|---|---|
| 解除する人 | 回せる爆弾（暗い作業台の地）。しかけ・手がかりを押すと「近くで見る欄」がひらき、そこで操作する。説明書は出ない。この間は右下の「？」とフィードバックの丸ボタンを出さない（`html.tk-playing`） |
| 説明書を読む人 | 説明書（上の札でページを切りかえる）。爆弾は出ない（DOM にも作らない） |
| 進行だけのホスト・みんなにみせる画面（`?watch=`）・この回は見る番の人 | のこり時間・まちがいのランプ・解除できた数・解除する人と読む人の名前だけ。**画面共有にはこれを出す** |

- **爆弾の回し方**: 6つの面を CSS の 3D 変形で箱に組み、箱ごと回す（外部ライブラリなし）。向きは四元数で持つ（`cube.q`）。ドラッグ（7px 動いたら回す。はなしたあと少し惰性）と、やじるしのボタン（90度ずつ。いまの向きをまっすぐにしてから回す）。面を押すと、その面を正面に向ける。見えていない面（奥を向いた面）は `inert` で、キーボードでも選べない。`prefers-reduced-motion` のときは、回す動き・惰性・ゆれ・寄る動きをなくす
- 説明書の行の右の丸いボタン（48px）と、記号スイッチ（幅44px以上・縦長）は、ボタンの高さの3段（36・48・56px）の外（アイコンだけのボタンと、しかけの部品のため）
- **近くで見る欄**: 箱の面の上のしかけは絵だけ（押すとひらく）。操作は近くで見る欄で行う（スマホでも 44px 以上で押せる・回すドラッグと押すのを取りちがえない）。「もどる」か Esc で閉じ、もとのボタンへフォーカスをもどす。解除できたら約1秒で自動で閉じる
- **しかけの大きさ**: `.tk-mod` を em で組み、箱の面では 8px、近くで見る欄では最大 17px（画面の幅に合わせる）
- 遊ぶ画面は、ほかのツールと同じ幅（760px）。みんなにみせる画面だけ 1040px まで

## マイクを使わない子の加わり方（ui.md「マイクを使わない子が参加できる手段」）

- **ひとこと**: 決まった言葉をボタンで送る（`SAYS`。もう一回言って・ちょっと待って・わかった・そのページ持ってるよ・持ってないよ・見つけた・見つからない・ちがうかも・ナイス！）。ひとり5秒に1回・遊んでいる人だけ・10秒出して消える・最新の3つまで。**この9つの言葉は、まだオーナーの承認を受けていない**（承認が要る。ui.md）
- **説明書の1行を見せる**: 読む人が、行の右のボタンで、その行をみんなの画面（解除する人・ホスト・みんなにみせる画面）に出す。声で読み上げなくても止め方を伝えられる。「本体の手がかり」のページには付けない。データは「ページの名前と行の番号」だけ（文は各端末が `engine.js` から作る。自由な文は送れない）
- **解除する人にならない**を本人が選べる（上の「役」）。解除する人は、見たものを言葉で伝える役なので、声が要る
- 進行だけのホスト・みんなにみせる画面には、ひとことの欄を出さない

## 端末のない参加者・ホストも遊ぶか

- **端末のない参加者は作らない**: どちらの役も、自分だけの画面（爆弾か説明書）が要る。ホストが代わりに持つと、ホストの画面を共有できなくなる。端末のない子は、共有画面ののこり時間を見て、声で加わる
- **ホストも遊ぶか**（`set/hostPlays`）: はじめは**進行だけ**（ホストの画面を共有するため）。待合室でだけ切りかえる。メンターと子どもの2人で遊ぶときは「ホストも遊ぶ」をオンにする（このときホストの画面には爆弾か説明書が出るので、共有するなら「みんなにみせる画面」）

## Firebase データ構造

```
torisetsukaijo_rooms/{code}
  status: 'waiting' | 'play'        // 結果は play のまま game/out で出す
  host, hostUid, hostConnected, hostDisconnectedAt, createdAt
  lastGameId, turn                  // turn: つぎに解除する人を決める番号（1回ごとに +1）
  set: { hostPlays, level: 'easy'|'normal'|'hard', slow, split }
  players/{名前}: { isHost, uid, joinedAt, ro? }     // ro: 読むだけ
  game: {
    id, seed, level, slow, split,   // seed から、どの端末でも同じ爆弾を作る（engine.makeBomb）
    seats: [名前], uids: [匿名ID], def: 解除する人の席,
    startAt,                        // 導火線の時刻のもと
    t: { left, at, rate } | なし,    // のこり時間 = left − (いま − at) × rate。ゆっくりのときはなし
    x,                              // まちがいの数
    ok: { s0..s5: true },           // 解除したしかけ
    m: { s0..s5: { c | b | p } },   // 途中の様子（c: 切ったコード "0,3"・b: スイッチのビット・p: ダイヤルの位置／やじるしの進み）
    fz,                             // 済んだ導火線の回数
    out: 'safe' | 'boom', why: 'time' | 'strike', endAt
  }
  say/{pushId}: { f: 名前, g: 回の番号, at, k: ひとことの番号 } | { …, c: ページ, l: 行の番号 }
```

- **爆弾の中身（正解）は、どの端末でも seed から作れる**。読む人・ホストの画面には描かないが、DevTools で見れば分かる（ルートの「性善説」）
- しかけの場所のキーは `s0`〜`s5`（数字だけのキーにすると、RTDB が配列に変えて返すため）

## 書き込みの設計

- **待合室**（ルーム全体の transaction。だれも遊んでいない間だけ）: 設定・はじめる。「読むだけ」は `players/{名前}` への transaction（いない人の所に印だけを作らない）
- **あそんでいる間**: しかけの操作は、解除する人が `game` への transaction で書く（`commitGame`。同じ回・まだ終わっていないときだけ。`engine.act` の結果をそのまま置く）。続けて押しても順番どおりに書くよう、1本の列（`state.queue`）に並べる
- **時間で起きること**（導火線がまにあわない・時間が0）: 解除する人の端末が `engine.tick` で見つけて書く。ホストは、解除する人がいるかどうかを見ずに、いつも3秒おくれで控える（解除する人が退出・切断したとき、タブが裏に回ったときも拾える）
- **自分の通信が切れている間は書かない**（`state.isConnected`）。切れている間の操作や時間切れが、戻ったときにまとめて届かないようにする
- **まちがいになった操作を、0.8秒のうちにもう一度押しても受けない**（`STRIKE_GUARD_MS`。「たしかめる」やつまみの二度押しで、まちがいが2回つかないように。ほかの操作は受ける）
- **参加・在室の戻し**（rtdb.md「参加は status 判定と players 追加を同じ transaction に」からの例外。あれください商店と同じ形）: 名前・人数・status は先に読んだ値で確かめ、書くのは `players/{名前}` への transaction だけ（ルーム全体の transaction は、解除する人が `game` に書いている間は通りにくい）。同時に入ると7人めが在室しうるが、遊ぶ人（`seatList`）は6人で切る。ホストの在室の戻しは、手元の値で確かめて要る欄だけ `update`
- **のこり時間は書かない**: 各端末が `game/t` から出す。まちがえたときだけ、その時刻ののこりと新しい速さを書く
- **ホストが切れている間は時間を止める**（`roomNow`。切れた時刻で止め、だれも書かない）。戻ったとき、ホストが切れていた分だけ `game/startAt` と `game/t/at` をずらす
- **もう一回・待合室へ**: ホストが要る欄だけを `update` で書く（`game`・`turn`・`say` など）
- ひとことは `say` に `push`。新しい回・待合室へもどるときに消す
- **途中でいなくなった人**: みんなの画面と上の帯で、名前に「（いまいない）」を付ける。読む人がいなくなったら、その人の持っていたページは、いる読む人みんなが読めるようになる（その人だけが持っていたページを、だれも読めなくならないように。戻ってくれば元にもどる。2026-11-26 に実装側で決めた。オーナーは未確認）

## status 遷移

```
waiting ──はじめる──▶ play（game.out なし: あそんでいる）
                       │ しかけをぜんぶ解除 → game.out = 'safe'
                       │ まちがい3回・時間が0 → game.out = 'boom'
                       ├─もう一回──▶ play（新しい game。解除する人を交代）
                       └─待合室へ──▶ waiting
```

## 切断時の挙動・再接続・削除

- ホスト切断: `hostConnected=false`・`hostDisconnectedAt`。ゲストに「ホストの戻りを待っています」（`data-roomk-blocking`）。2分（`ORPHAN_TTL_MS`）で期限切れ。期限のタイマーは、切れた時刻が変わったら仕掛けなおす（`orphanAt`）
- ゲスト切断: `players/{名前}` を `onDisconnect().remove()`。あそんでいる間の席（`game/seats`）は残るので、読み込み直すと同じ役にもどる（同じ匿名IDだけ）。「読むだけ」の印は、在室を書きなおすときに付けなおす（`state.ro`。再読み込みでも残るよう sessionStorage にも入れる）
- 再接続: sessionStorage（`torisetsukaijo_session`）。解除する人は、同じ爆弾・同じ進み具合にもどる（爆弾の向き・近くで見る欄・ふたを開けたかは、端末の中だけなので、はじめにもどる）
- 作成・参加の「送信後の切断」は、やり直して自分の書き込みが届いていれば成功として扱う（rtdb.md）
- **削除**: 公認バリアント「ふりかえり画面滞在中は削除しない」。結果のあとも「もう一回」ができるよう、30秒後の自動削除はしない。消えるのは、(1) ホストの「ルームを閉じる」 (2) ホスト切断の TTL (3) 次に開いたときの期限切れの掃除

## 利用回数

- 「1回」は1つの爆弾（はじめてから、解除か爆発まで）
- `room-create`・`start`・`players-{N}`・`level-{easy|normal|hard}`・`slow`・`finish`・`safe`・`boom-time`・`boom-strike`・`again`
- `finish` と結果は、その回を終わらせた書き込みを確定させた端末だけが数える（解除する人。時間切れをホストが代わりに書いたときはホスト）。「この回をやめて待合室へ」は `finish` を数えない

## メンター向けの心得

- 画面共有には、ホストの画面（進行だけ）か「みんなにみせる画面」を出す。爆弾・説明書は共有しない
- はじめての回は「やさしい」か「ゆっくり」で、しかけの見方と説明書の引き方を一度通すと入りやすい
- 爆発したあとに、だれのまちがいだったかを探す流れにしない。「次はどう伝える？」に話を向ける
- 解除する人になりたくない子は、待合室の「読むだけ」を使う。声を出さない子には、ひとことと「行を見せる」ボタンがあることを伝える
