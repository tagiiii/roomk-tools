# よく見て漢字 — 仕様

共通の運用・品質基準はルートの [AGENTS.md](../../AGENTS.md)。ここにはこのアプリだけの仕様と、共通規約からの意図的な例外を書く。

## 目的・使用シーン

社会・理科の用語の漢字を、にせものの混ざった部品から組み立てるパズル。組み立てるうちに、字の形が頭に入ることをねらう。
作戦会議（週1回30分の面談）で本人が決めたことを、会議の外で一人で進めるための道具。メンターは、子どもの画面の動きを「見る画面」で見られる。

- きっかけ: 中学1年生が国語以外の教科のテストで、漢字のまちがいで減点された。計画支援コーディネーターから「進度に合った単元の漢字を学習すれば減らせるのでは」と提案があった。字形を覚えていない様子で、本人は PC を使う。オーナーの心配は「書き問題にすると、書けないことで自信をなくさないか」
- **ツール一覧（ポータル）・早見表・更新情報には載せない**（特定の子どもとの作戦会議で使うため。作戦会議チャットと同じ扱い）。URL を直接ひらいて使う。検索エンジンに載せない（`noindex`）

経緯（2026-10-13。同じ外し方をくり返さないために残す）:

| 版 | 内容 | オーナーの評価 |
|---|---|---|
| 第1版 | 見る → 似た字さがし → 見ながら紙に書く → かくして書く | 「全然面白くありません」。つまらない所は「ゲームが単調」「押すだけで受け身」 |
| 第2版 | 組み立てパズル。レベル3つ（部品＝見本あり／にせものあり／一画ずつ） | 「にせものありは面白い。部品と一画ずつは不要」 |
| 第3版 | にせものありだけ。メンターの見る画面を足した（`drafts/` の試作。通信なし） | 「本体化を進めてください」 |

第1版の原因は、自信をなくさないようにと点数・時間・失敗を全部外し、手ごたえまで外したこと。練習の手順にゲームの名前を付けただけだった。
第2版から、**遊ぶこと自体が字の形を覚えることになる**形にした。時間制限と記録（前回より速い・多い）は入れない（オーナー決定）。
置き場所は、はじめ `~/dev/roomk-programs` に作り、見る画面に別の端末との同期が要るため、公開先と Firebase のそろったこのリポジトリへ移した（オーナー決定）。

## 既存ガイドラインからの例外

- **勉強・テスト由来の題材を扱う**（共通のコンテンツガイドラインでは不可）。作戦会議で本人が「テストの減点を減らしたい」と決めたことを支える道具のため（2026-10-13 オーナー承認）。ただし次は守る:
  - 点数・正解率・×印・「まだ」の数を出さない。時間制限・ランキング・ほかの子との比較を付けない
  - 音を鳴らさない
  - 「できない」「まちがい」を強調する文言・演出をしない
- **アプリ名に漢字表記を使う**（漢字そのものが題材のため）
- 子ども向けの文言は**です・ます調**（「〜してね」「〜だよ」は使わない）
- 画面は、共通規約の `showScreen()`・`.screen.active`・`const state` の形ではなく、JS で画面ごとに組み立てて入れかえる（`show()`）。つなぎの状態は `share` と `link.js` の中に持つ
- トップは単元の一覧（「はじめる」1つのパネルではない）。選ぶこと自体が最初の操作のため

## 技術スタック

- `index.html` + `app.js`（画面とパズル）+ `link.js`（見る画面とのつなぎ）+ `data.js`（語）+ `kvg-data.js`（字の画）+ `style.css`（クラスの接頭辞は `yk-`）
- Realtime Database（`yokumitekanji_rooms/{ルームコード}`）＋匿名認証。共通モジュール: `rtdb-utils.js`・`stats.js`・`howto.js`・`utils.js`（`shuffle`）
- **Firebase につなぐのは、ルームを作る・入るときだけ**（`link.js` の `init()`）。一人で遊ぶだけなら、ゲーム側の接続は張らない
- `app.js` は `data.js`・`kvg-data.js`・`link.js` を `?v=` 付きで読み込む。**どれかを変えたら、`index.html` の `?v=` と `app.js` の import の `?v=` をそろえて上げる**

## あそびかた

1. 単元を選ぶ（進度はアプリには分からないので、本人かメンターが選ぶ）
2. 語を選ぶ。語の中の「よく見る1字」がバラバラになる
3. 部品をドラッグして、わくの中の正しい場所で放すと、はまって黒くなる。正しくない場所でははまらず、置いた所に残るだけ（×は出さない）
4. 全部はまると、書き順どおりに字が書き直され、語と「見るポイント」が出る
5. 「紙にも書いた」は任意のチェック。押さなくても先へ進める

- 部品は、へん・つくりなどのかたまり3〜4個と、にせものの部品2〜3個。見本は出さない
- **にせもの**は、似た字（`data.js` の `sim`）の「ちがう所」を先に使う（「遣」に「遺」の「貝」、「墾」に「懇」の「心」）。まちがえやすい所そのものを、自分で選ぶ形にするため。足りないときは、ほかの字の部品から借りる
- **見本を見る**は、押すと2.5秒だけ見本が出る。回数の制限も減点もない
- **同じ形の部品はどの場所にもはまる**（「晶」の3つの「日」）。見分けられないものを「ちがう」と返さないため。完成時に正しい形へ書き直す
- 画面に字を書かせない（マウスの字はだれでも崩れる）。紙に書くかどうかは本人が決める
- キーボード: 部品にフォーカスして矢印で動かし、Enter かスペースで放す

### 記録

- 端末の localStorage（`yokumite-kanji:v2`）だけに残す。残すのは、語ごとの「組み立てた」と「紙にも書いた」だけ。回数・時間・失敗は残さない
- 組み立てた語には星が付く。トップの「記録を消す」で消せる

## 見る画面（メンターが、子どもの操作を見る）

オーナーの希望: 「子どもの操作をメンターが観られると、より楽しい」。

1. メンターがトップの「見る画面をつくる（メンター用）」を押すと、ルームができる。「リンクをコピー」で `?room=コード` の付いたリンクを子どもに送る
2. 子どもがリンクをひらくと、「メンターの画面にも出る」ことの説明が出て、「見せてはじめる」「見せずに一人でやる」を選ぶ。**見せるかどうかは本人が決める**（見られていると緊張する子もいるため、断れる入口を置いた）
3. 見せている間は、子どもの画面の上に「メンターに見せています」の帯と「見せるのをやめる」が出る
4. 見る画面には、子どもの今の画面（単元を選んでいる／語を選んでいる／パズル）が出る。パズルでは、部品の動き・はまった部品・「見本を見る」・完成が映る。見る側からは操作できない
5. メンターが「とじる」を押すと、ルームごと消える

- 送るのは、どの語か・にせものの部品（どの字の何番目の部品か）・部品の位置・はまったかどうかだけ。名前は送らない。会話や入力はない
- 見る側は、受け取った中身を確かめてから盤面を組む（単元は手元のデータにあるもの、語の番号は整数で範囲内、にせものは手元の字のデータにある部品だけ、部品は12個まで、位置は盤面の範囲に丸める、盤面の形は決めてある名前だけ）。組み立てに失敗したら「相手の画面を読みこめませんでした」を出す
- 役: メンター＝ホスト（`viewer`）、子ども＝ゲスト（`player`）

### 共通規約からの例外

- **名前とルームコードの手入力がない**（共通規約は「名前 → ルームコード → 参加する」「コードをコピー」）。1対1でリンクから入るため。ルームコード（6文字）は見る画面に出すが、参加はリンクだけ。「リンクをコピー」（`id="btnCopyLink"`）は共通の `RoomkRTDB.copyRoomLink()`
- **見せる人は1人で、あとから入った側に切りかわる**（共通規約の「重なったら弾く」ではない）。同じ子がリンクをひらき直しても詰まらないようにするため。前の画面は、切りかわったのを知って見せるのをやめる（トーストで知らせる）
- **席と中身を人（`pid`）ごとに分けている**（`meta/seats/{pid}`・`live/{pid}`）。前の画面の切断時の予約や、遅れて届いた書き込みが、あとから入った人の席・盤面を消したり書きかえたりしないようにするため。見る側は、`meta.player` の指す人の `live` だけを見る
- **`meta` を分けている**（作戦会議チャットと同じ理由）。transaction は対象の値をまるごと送り直す。部品を動かしている間は `live` が1秒に何度も変わるので、ルーム全体に transaction を使うと、やり直しが続いて終わらない。status・在室の確認と席の取得は `meta` の transaction で行う。ルーム全体の transaction は、空のルームを作る1回だけ
- ゲームの回・得点・進行はない（`status` は `open` だけ）

## Firebase データ構造

```
yokumitekanji_rooms/{コード}/
  meta/                         小さい情報だけ。transaction はここにしか使わない
    status: 'open'
    createdAt, hostUid, hostToken
    hostConnected, hostDisconnectedAt
    player: pid                 いま見せている人（あとから入った人に切りかわる。切断では消えない）
    seats/{pid}: { uid, joinedAt }      在室。自分の pid の下だけを、切断時に消す
  live/{pid}/                   その人だけが書く。切断で消える
    view: { name: 'top'|'unit'|'puzzle', unit }
    puzzle:
      unit, w                   単元の id・その単元の語の番号
      layout: 'wide'|'tall'     見せる側の盤面の形（PC は横長、幅 700px 以下はたて長）
      decoys: [{ c, i }]        にせもの（字 c の i 番目の部品）
      pieces: [{ x, y, l }]     部品ごとの、わくからのずれと「はまった」。順番は「正しい部品（データの順）→ にせもの」
      peek, done
```

- 相手がいる（見る画面に出す）のは、`meta.player` の指す pid に席（`meta/seats/{pid}`）があるとき
- **人の id（`pid`）はタブごと**（sessionStorage `yokumitekanji_pid`。英小文字と数字の12文字。パスに使うので形を確かめる）。同じブラウザの別タブは匿名認証の uid が同じなので、自分の席かどうかは uid ではなく `pid` で見る（メンターが同じブラウザの別ウィンドウで子どもの側を試せる）
- `hostToken` は、ルームを作る transaction のやり直しで「前の送信がもう届いていた」ことを見分けるしるし
- 部品を動かしている間は、その部品（`live/{pid}/puzzle/pieces/{番号}`）だけを 0.08 秒おきに書く。放したとき・はまったときは必ず書く
- 見る側は `meta` と、いま見せている人の `live/{pid}` を購読する（相手が変わったら付けかえて、前の盤面をすぐに下ろす）。見せる側は `meta` だけを購読する

## 切断時の挙動

| 役割 | 挙動 |
|---|---|
| メンター（ホスト）切断 | `meta.hostConnected=false`・`hostDisconnectedAt`。子どもの帯は「メンターの画面がひらくのを待っています」になる。子どもはそのまま遊べる |
| 子ども（ゲスト）切断 | 自分の `meta/seats/{pid}` と `live/{pid}` を `onDisconnect().remove()`。見る画面は「相手の画面がとじました」になる |
| つながり直したとき | 接続のたびに切断時の予約を張り直し、自分の在室を確かめる（`ensurePresence`。同時には1本だけ走らせ、退出・終了と重なったら何もしない）。子どもの側は、席がなくなっていたら取り直して、今の画面をまとめて送り直す。切れている間の変更は送らず、手元にだけ持つ。送れなかったときは、つぎの確認（5秒おき）でもう一度送る |

- **期限切れは2分**（`ORPHAN_TTL_MS`。共通どおり）。メンターが2分もどらないと、開いている子どもの端末がルームごと消し、見せるのをおわる（子どもはそのまま一人で遊べる）
- 作成・席の取得は、送信後の切断（`Error('disconnect')`）でやり直す。自分の書き込みがもう届いていれば成功として扱う
- ルームを作るときは「切断中」として作り、つないだあとの在室確認で接続中にする（切断時の予約がないルームを残さない）
- 席と中身の切断時の予約は、席を取る transaction の前に張る（どちらも自分の `pid` の下なので、ほかの人の分は消えない。先に張っておけば、席を取った直後に閉じても席が残らない）。入れなかったときは取り消す
- つないだ直後に相手がいた・終わっていた、という変化も取りこぼさない（`onPeer`・`onEnd` は、登録より前に起きていた分をその場で知らせる）

## 削除

1. メンターの「とじる」: 走っている在室の確認を待ち、切断時の予約を取り消してから、ルームごと `remove()`。取り消しに失敗したら消さずにやめる。接続が切れている間は押せない（知らせる）
2. ルームがなくなったのを知った端末は、切断時の予約を取り消してから、もう一度ルームごと `remove()` を送る（とじる直前に送った書き込みが削除よりあとに届いても、残りかすにならない）。あとから入った人に切りかわった端末は、自分の `live/{pid}` だけを消す
3. メンターが「とじる」を押さずに閉じた: 子どもの端末が開いていれば2分後に消す。そうでなければ、つぎにそのルームのリンクをひらいた端末が消す
4. `status` のない `meta`（削除後に切断時の予約が発火してできたかけら）は、期限切れとして消す

**残る限界**（サーバー側で時間で消すしくみは Spark プランでは持てない）:

- メンターが「とじる」を押さずに閉じ、そのあとだれもそのリンクをひらかなければ、`meta` が残る（中身は語の番号と部品の位置だけ。名前や入力はない）
- 再読み込みした見る画面は、同じブラウザでなければ元のルームにもどれない（ホストかどうかを匿名認証の uid で見るため）
- 「タブを複製」した子どもの画面は、`pid` も写るので、2つのタブが同じ席として両方から書く（表示がちらつく。片方を閉じると席が一度消え、残った側が5秒以内に取り直す）
- 「見せるのをやめる」のすぐあとに同じタブで入り直すと、前の接続の切断時の予約が遅れて発火して、席が一度消えることがある（気づいた時点ですぐ取り直して送り直す）

## 再接続（sessionStorage）

- `yokumitekanji_session` に `{ code, role }` を置く。再読み込みで、見る側は見る画面へ、見せる側は見せている状態へもどる。ルームがもうなければ記録を消して知らせる。通信の失敗でつなげなかったときは、記録も `?room=` も残す（読み直せば、もう一度つなぎに行く）
- 入口の順番: `?room=`（リンク）→ 保存した記録 → トップ。`?room=` は `normalize('NFKC')`・空白除去・大文字化してから `/^[A-Z2-9]{6}$/` で検査する。正しくなければトーストで知らせてアドレスから外す
- 同じコードの記録があれば、つなぎ直しを優先する。別のコードの記録は捨てて、リンクのルームを優先する
- `?room=` は、つないだあとにアドレスから外す。入れなかった間は残す

## 利用回数

ゲームの回がないので、共通の `start`・`finish`・`players-{N}`・`again` は数えない。

| 項目 | 数えるとき |
|---|---|
| `room-create` | 見る画面のルームができた（作成を確定した1台だけ） |
| `show` | 子どもが「見せてはじめる」で入れた（再読み込みのつなぎ直しでは数えない） |
| `puzzle-done` | 字を1つ組み立て終えた（一人で遊んだ分もふくむ） |

数えるのは回数だけ。どの語か・だれかは記録しない。

## 語のデータ（`data.js`）

- 語は学習指導要領の単元から制作者個人が選ぶ。**教科書の一覧を写さない**。教科書会社は不明
- 「まちがえやすい」は見立てで、誤答の統計にもとづくものではない
- 見るポイントは1語に1つ。字の形についての事実だけを書き、書く前に字を調べて確かめる（例: 「徳」は14画で、「罒」と「心」の間に横線は入らない）
- 似た字（`sim`）は、へんやつくりの一部だけがちがう常用漢字を選ぶ
- 単元の `id` は記録のキーと、見る画面へ送る値に使う。公開後は変えない。**語は末尾に足すだけ**（見る画面へは語の番号を送るので、途中に入れたり並べかえたりすると、古い版のタブとずれる）
- 教科書によって表記がちがう語（例: 「は虫類」と「爬虫類」）は、学校で求められる書き方を優先する
- 入っている単元: 理科「身のまわりの物質」12語、社会「古代までの日本」13語（2026-10-13 時点。**オーナーの内容確認はまだ**）
- `scripts/content-audit.mjs` は `COVERED_APPS`（語を重複検査に載せる。`k` が語にふくまれるか等の構造検査つき）

## 字のデータ（`kvg-data.js`）

- KanjiVG（https://kanjivg.tagaini.net/ 、© Ulrich Apel、CC BY-SA 3.0）の筆順データから作った二次的なデータ。**このファイルも CC BY-SA 3.0**。画面下のクレジット（出典・ライセンスへのリンク・変更したこと）を消さない
- 手で直さない。**字のデータを作り直す**ときは:
  1. `tools/build.py` の `TARGETS`（よく見る字）と `SIMS`（似た字）に字を足す
  2. `https://raw.githubusercontent.com/KanjiVG/kanjivg/master/kanji/{5けたの16進}.svg` を、空のフォルダに取得する（取得はオーナーの許可を得てから。2026-10-13 に56字分を取得）
  3. `python3 -I tools/build.py <取得したフォルダ> kvg-data.js`
- 部品の分け方は KanjiVG の入れ子に従い、「3つ以上になるまで」「8画以上の部品がなくなるまで」大きい部品から分ける
- `data.js` の `k` に字のデータがない語は、一覧に出ない
- **部品の順番も、見る画面へ送る値に使う**（にせものは「字と部品の番号」、位置は部品の順）。作り直して部品の分け方が変わると、古い版のタブとずれる

## 入れない機能（意図的に未実装）

- 点数・正解率・時間制限・自分の記録（前回より速い・多い）・ランキング
- 音（効果音・通知音）
- 画面に字を書かせること、書いた字の自動採点
- 見る側からの操作（お題を出す・部品を動かす・コメントを書く）
- 「なんで？」と理由を書かせる欄

## 検証

2026-10-13 隔離エミュレーター（本番には接続しない）＋ Playwright で確認。テスト一式と手順は [tests/yokumite-kanji/](../../tests/yokumite-kanji/README.md)。

- その1（93項目）: 一人で遊ぶ（Firebase につながない）・見る画面の作成・リンクから入る／見せずに一人でやる・部品の動き／はまる／見本／完成が映る・せまい画面・見せるのをやめる／入り直す・見せる人の切りかえ・おかしな値が届いたとき・とじる・正しくないリンク
