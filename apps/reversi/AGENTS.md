# リバーシ 仕様書

## 目的・使用シーン

黒と白の石を交互に置き、はさんだ相手の石をひっくり返す、定番の盤ゲーム。最後に自分の色の石が多いほうの勝ち。

- **core value**: ルールがすぐ分かり、1手ずつ考えて置ける。はじめての子は「補助」で置ける場所やひっくり返る数を見ながら遊べる。対戦しない子も、自分の画面や「みんなにみせる画面」で勝負を見られる
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの1対1でも遊べる）
- 対戦は2人。観戦はゲスト20人まで（＋端末なしの参加者4人まで）
- 所要時間 1回10〜20分

> 経緯: 2026-10-25 オーナーの依頼（メンターが操作する版・プレイヤーがそれぞれ操作して対戦する版・観戦・初心者用の補助）で `drafts/reversi/` に試作 → 同日オーナーが「この内容で本体化」と承認。本体化の途中で、オーナーから「1手に制限時間を設け、過ぎたら CPU が自動で置く」の追加依頼があり、本体で入れた（試作にはない）。
> 名前「リバーシ」は伝統ゲームの一般名称なので、命名の例外（人狼・ブラックジャックと同じ。`docs/development/app-registration.md`「アプリ名のつけかた」）に当たる。「オセロ」は商品名なので、画面・検索のキーワード・早見表のどこにも使わない。早見表では系統ラベル「定番の盤ゲーム」で紹介する。

## ルール

| 項目 | 内容 |
|---|---|
| はじめの並び | D4 白・E4 黒・D5 黒・E5 白。黒が先に置く |
| 置ける場所 | 相手の石を、自分の石ではさめる場所だけ（たて・よこ・ななめ）。はさんだ石はすべて自分の色になる |
| パス | 置ける場所がない人の番は自動でとばし、「白（○○）は置ける場所がないので、パス。」と出す（パスのボタンは置かない） |
| おわり | どちらも置けなくなったら。石の多いほうの勝ち。同じ数なら引き分け |
| 結果 | 盤の上に「白（○○）の勝ち！　黒 23 ー 白 41」、勝った人の札に「勝ち」 |
| 場所の言い方 | 横は左から A〜H、たては上から 1〜8（盤のふちに出す）。「D3」のように言う |

盤のルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/reversi/engine.test.cjs`（はじめの局面からの手の数を既知の値と照合・でたらめ対局・CPU の手）。

## 補助（はじめての人向け）

| 項目 | 中身 | はじめの値 |
|---|---|---|
| 補助を使う人 | ふたりとも／黒の人だけ／白の人だけ／使わない。その色の番のときだけ補助が出る（ハンデにも使える） | ふたりとも |
| 置ける場所を見せる | 置ける場所に、番の色の点が出る | オン |
| ひっくり返る数も見せる | 点のかわりに、そこに置くとひっくり返る石の数が出る（置ける場所を見せるときだけ） | オフ |
| 置く前にたしかめる | 1回押すと、置く石が薄く出て、ひっくり返る石が光る。「ここに置く」か、同じ場所をもう1回押すと置く | オフ |

- 補助がなくても、直前に置いた石の印（赤い点）・石の数・だれの番かは、いつも出す
- 補助はホストが待合室で決め、遊んでいる間も「補助の設定」で変えられる（1台の画面も同じ）。観戦・みんなにみせる画面にも、その番の補助（置ける場所・数）が出る
- 試作から本体まで、補助のはじめの値はオーナー確認待ちの仮置き（2026-10-25）

## 1手の制限時間と CPU

2026-10-25 オーナー依頼。「それぞれ1手に制限時間を設けたい。過ぎたら CPU が自動操作みたいな感じ」。

| 項目 | 内容 |
|---|---|
| 選べる時間 | なし・15秒・30秒・60秒（はじめは「なし」）。ルームはホストが待合室で、1台の画面は準備の画面で選ぶ。対局を始めた時点で固定 |
| 残り時間 | 番の人の札に「のこり 12秒」。5秒からは色を変える（音は鳴らさない）。観戦・みんなにみせる画面にも出す |
| 時間切れ | CPU がその人の代わりに1手置き、全員に「時間切れ。CPU が白の代わりに D3 に置いたよ。」と出す。次の番の時間は最初から |
| CPU の置き方 | 角が取れれば角。取れなければ、まだ空いている角のとなり（相手に角を渡しやすい場所）を避けて、残りからくじで選ぶ（`engine.js` の `autoMove`）。強すぎず、でたらめすぎない手 |
| 1手もどす | もどした番の時間は最初から |

- 「時間」と「CPU が置く」は、オーナーの依頼の言葉どおりの仮置き（時間の選択肢・CPU の強さ・はじめは「なし」は 2026-10-25 に AI が決めた。オーナー確認待ち）
- ルームの締め切りの起点はサーバーの時刻（`game.turnAt` に `ServerValue.TIMESTAMP`）。残り時間の表示と締め切りの判定は各端末の `RoomkRTDB.now()`
- 時間切れの手を置くのは、**ホストの端末か、その番に置ける端末**（番の人・端末なしの人の番ならホスト）。どちらも締め切りの0.5秒あとに1回だけ送り、transaction の中で「同じ対局・同じ局面（`rev`）・締め切りを過ぎている・ホストが在室」を確かめる。局面の照合で、同時に送っても1つしか通らない。時刻の差で締め切り前と判定されたら、1秒後に送りなおす（ホストのタブが裏に回ってタイマーが遅れても、番の人の端末が進める）
- **ホストが切れている間は時計を止める**（残り時間を出さず、CPU も置かない）。参加者の画面は「ホストの戻りを待っています」で押せないので、CPU どうしで対局が進まないようにするため（2026-10-25 レビューの指摘）。ホストが戻ると、その番の時間を最初から数えなおす（ホストの在室を戻す transaction で `turnAt` を書き直す）
- 締め切りのあと、CPU の手が届く前（0.5秒の余裕の間や、タイマーが遅れている間）に人が置いた手は、そのまま通す（止まるより続くほうがよいため。意図した扱い）
- 1台の画面は端末の時計（`Date.now()`）で数える。読み込み直したら、その番の時間は最初から

## 端末なしの参加者（ホストが代わりに置く）

- 待合室でホストが「端末なしの参加者を足す」で名前を足す（はじめる前だけ。4人まで。ほかの人・ホストと同じ名前は不可。「外す」で外せる）。`proxies/{name}` に置き、在室（`players`）には入れない（切断しない扱い）
- 席に選べる。その人の番は、ホストの画面に「黒（○○）の番。代わりに置いてね」が出て、ホストが置く
- 「端末なし」の印は、ホストの画面にだけ出す（子どもどうしの画面で区別しない）

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（対局中なら観戦で対局の画面）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 ├── 「1台の画面であそぶ」 → 名前・制限時間・補助（screen-local） → 対局（通信しない）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting）: 対戦する人（黒・白）・参加している人・1手の制限時間・補助。ホストは席を選ぶ・入れかえる・端末なしの参加者を足す・「はじめる」
  ↓「はじめる」（席の2人がそろっている）
対局（screen-game）: 2人の札（石の数・番・残り時間）・番の表示・盤・（たしかめる）・結果のあとのボタン・そのほかの操作
  ↓ どちらも置けなくなる
結果（同じ画面）: ホストは「もう一回（黒と白を入れかえる）」「対戦する人を選びなおす」（→ 待合室）
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）。1台の画面では出さない
- 席: 待合室では、入った順に空いている席（黒→白）へ入る。ホストは自分で選んだときだけ席に入る。3人目からは観戦。ホストは席を選びなおせる（反対の席の人を選ぶと入れかわる）
- そのほかの操作（ホスト・1台の画面）: 「1手もどす」（ホストは確認あり）・「補助の設定」・「この対局をやめる」（ホスト。確認あり。待合室へ）／「最初からやりなおす」「トップへ戻る」（1台の画面）
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「はじめる」、結果「もう一回」、たしかめる「ここに置く」）。そのほかの操作は弱いボタン
- 広い画面（900px 以上）では、対戦する2人の札を盤の左右に置く（画面共有で見やすいように）。盤は画面の高さに収める

## status 遷移

```
waiting ─はじめる→ play ─（どちらも置けない）→ play（game.over）
play ─もう一回（ホスト・終わったあと）→ play（新しい対局。黒と白を入れかえる）
play ─対戦する人を選びなおす／この対局をやめる（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
reversi_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── aid:                { who: 'both'|'b'|'w'|'none', spots, count, confirm }   # 補助（いつでも変えられる）
  ├── moveTime:           0 | 15 | 30 | 60   # 1手の制限時間（秒。0 はなし。待合室で変更）
  ├── seats:              { b: 名前, w: 名前 }   # 待合室で選んだ席
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}:     { joinedAt }                # 端末なしの参加者
  └── game/                          # 「はじめる」で作り、待合室にもどると消す
       ├── id, seats: {b, w}, uids: {b?, w?}（端末なしの人はなし）, proxy: {b?: true, w?: true}
       ├── board: 64文字（'.' 'b' 'w'。左上 A1 から行ごと）, turn: 'b'|'w', ply: 何手目
       ├── last: 直前に置いた場所（-1 はまだ）, flipped: [ひっくり返った場所], passed: パスになった色
       ├── over: true（おわり）
       ├── hist: [{ board, turn, last, passed, ply }...]   # 1手もどす用
       ├── moveTime: 開始時の moveTime, turnAt: いまの番が始まった時刻（ServerValue.TIMESTAMP）
       ├── auto: 直前の手を CPU が代わりに置いた色（なければなし）
       ├── rev: 局面が変わるたびに増える番号（置く・時間切れの手・1手もどす）。手数（ply）はもどすと減るので、古い操作の照合はこちらで行う
       └── ended: 一度でもおわった（もどしても消さない。finish を1対局に1回だけ数える）
```

- 読み込むときは壊れた値を読み飛ばす（`gameOf`）

## transaction 設計

すべてルーム全体への `transaction()`。ホストの操作は `hostUid` を確かめる（`hostTransaction`）。
席・制限時間・補助の変更は、続けて変えても取りこぼさないよう二度押しよけのロックを使わない（中で今の値から作りなおす）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | 名前が空いている（ホスト・端末なしの子と同じ名前は不可）・ゲスト20人未満（対局の席の人が戻るときは上限を見ない）・対局の席の名前は同じ匿名IDの人だけ → `players/{name}`。待合室なら空いている席にも入れる（`transactRetry`。自分の在室が残っていれば入りなおし） |
| 席・入れかえ・端末なしの参加者・制限時間 | ホスト | `waiting` |
| 補助 | ホスト | いつでも |
| はじめる | ホスト | `waiting`・席の2人がそろっている（在室か端末なし・別の人）→ `game` を作る |
| 置く | 席の人（端末なしの人・通信が切れた人の番はホスト） | `play`・押した時点の game.id と局面の番号（`rev`）が一致・おわっていない・その番に置ける人・置ける場所 → 盤・番・手数・`turnAt` を進め、`rev` を1増やし、`hist` に前の局面を足す。おわったら `ended` |
| 時間切れの代わりの手 | ホストか、その番に置ける端末 | 上と同じ照合＋ホストが在室・制限時間あり・締め切り（`turnAt + moveTime`、0.5秒の余裕）を過ぎている → `autoMove` の手で進め、`auto` に色を書く |
| 1手もどす | ホスト | `play`・押した時点の game.id と `rev` が一致（確認の間に置かれた手を取り消さない）・`hist` がある → 前の局面にもどし、`turnAt` を新しくし、`rev` を1増やす。合わなければ「盤が進んだので、もどさなかったよ」 |
| もう一回 | ホスト | おわった対局・game.id 一致・2人がまだいる → 黒と白を入れかえて新しい対局 |
| 待合室へ | ホスト | game.id 一致 → `waiting`。席は直前の対局のまま |
| 退出 | ゲスト | 自分の在室を消す。待合室なら自分の席を空ける（対局中の席は残し、ホストが代わりに置ける） |

## 接続・切断・再接続

しるしでヒント・スタンプあてゲームと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- 席の人が切れると、全員の札に「通信が切れた」、ホストに「黒（○○）の番。代わりに置いてね」。ホストが代わりに置ける。戻ると（同じタブの読み込み直し・同じ名前と同じ匿名ID）続きから
- 対局の席の名前は、ほかの人（別の匿名ID）は使えない（「その名前は使われているよ」）
- 対局中に入った人は観戦（席には入らない）
- ホスト切断中、ゲストと見る画面には共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。対局がおわっても自動削除しない（「もう一回」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 待合室にもどると `game` を消す（席・補助・制限時間・端末なしの参加者は残る）

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。players に入らない・切断予約をしない・期限切れのルームも消さない・時間切れの手も置かない
- 待合室では「参加のしかた」とルームコードを大きく出す。対局では、2人の札を盤の左右に置き、盤を大きく出す
- リバーシは秘密の情報がないので、ホストの画面をそのまま共有してもよい。みんなにみせる画面は、ホスト自身が対戦するときや、ルームバー・操作を映したくないとき用

## 1台の画面（メンターが操作する）

- 通信しない（Firebase に書き込まない）。名前（なくてもよい）・1手の制限時間・補助を選んで「はじめる」
- 対局は sessionStorage（`reversi_local`）に置き、読み込み直すと続きから。「トップへ戻る」で消す
- 結果のあと「もう一回」で黒と白の名前を入れかえる（名前がないときは「もう一回あそぶ」）。「名前と補助を変える」で準備の画面へ

## 利用回数（stats.js）

「1回」は1対局。

| 項目 | 数えるとき・端末 |
|---|---|
| `room-create` | ルームができた（ホスト） |
| `start`・`players-2` | 対局が始まった（「はじめる」「もう一回」。ホスト） |
| `finish` | 対局がおわった（最後の1手を確定させた端末。時間切れの手も）。おわったあとに1手もどして、もう一度おわらせても数えない（`ended`） |
| `again` | おわったあと「もう一回」「対戦する人を選びなおす」（ホスト）。途中でやめたときは数えない |
| `local-start` | 1台の画面で対局を始めた（「はじめる」「最初からやりなおす」「もう一回」） |
| `local-finish` | 1台の画面の対局がおわった（もどしておわらせなおしても1回） |

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る。engine.js は DOM に触らない
- **ホスト以外も進行の一部を行う**: 席の人が置く・最後の手を置いた端末が `finish` を数える・時間切れの手は番の人の端末も置く（ホストのタブが裏に回ってタイマーが遅れても止まらないように。ホストが切れている間は置かない）
- **観戦は参加者として players に入る**（席に入らない人）。見るだけの画面（書き込みゼロ）は別にある
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **端末なしの参加者は在室を持たない**（`proxies`。切断しない。ホストが代わりに置く）
- **勝ち負けを出す**（定番の対戦ゲームの結果。点数の比較や順位の記録はしない）

## 入れない機能

- 音（石を置く音・時間切れの音もなし）
- こうさん・待ったのやりとり（「1手もどす」はホストと1台の画面だけ）
- CPU と対戦するモード（CPU は時間切れの代わりの1手だけ）
- 勝ち数・対戦成績の記録、順位
- 対局中の新しい対戦者（途中から入った人は観戦）

## 既知の制約（v1）

- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- 時間切れの手は、ホストが在室していて、ホストか番の人の端末が開いているときだけ進む
- ブラウザは裏に回ったタブのタイマーをゆっくりにする（Chrome は長く裏にあるタブを1分に1回まで落とす）。ホストと番の人のタブがどちらも長く裏にあると、時間切れの手が遅れることがある
- 待合室で席の人が一時的に切れている間（`players` から消え、`seats` に名前だけ残っている）は、同じ名前で別の匿名IDの人が参加すると、その席に入ったことになる（待合室の席は名前で持つため。ホストが席を選びなおせる）。端末なしの参加者は、席に残っている名前と同じ名前では足せない
- 切断予約（onDisconnect）は在室を書き戻す transaction の前に張る（しるしでヒントと同じ作り）。同じ名前を別の人が使っていると分かったら、その画面はルームから外れて予約を取り消す
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（共通方針どおり、少なめに出る側の誤差として扱う）
- 残り時間の表示は各端末の `RoomkRTDB.now()`（サーバー時刻の見積もり）なので、つながった直後は少しずれることがある。置いた直後は、サーバーの時刻が届くまで（一瞬）残り時間を最初の値で出す

## メンター向けの心得（画面には出さない）

- 1台の画面で遊ぶときは、子どもに「D3」のように場所を言ってもらう（盤のふちに A〜H・1〜8 が出ている）。言いにくい子には、点のある場所を指で示してもらう・チャットで送ってもらうでもよい
- はじめての子には「置ける場所を見せる」をオンに。慣れてきたら「黒の人だけ」などにして、ハンデとして使う
- 「置く前にたしかめる」は、うっかり置いてしまう子・タブレットで押しまちがえやすい子に
- 1手の制限時間は、考えこんで止まってしまう子がいるとき・観戦の子が待ちくたびれるときに。CPU が置いても責めない（「時間切れでも、CPU が続けてくれるよ」）
- 勝ち負けで落ち込む子には、角を取れた・たくさん返せた場面をほめる。観戦の子に「次はどこに置くと思う？」と聞くと、見ているだけの時間も楽しくなる

## 確かめたこと

`tests/reversi/`（隔離した Firebase エミュレーター＋Playwright。本番に接続しない）。手順は `tests/reversi/README.md`。
2026-10-25（レビュー前）: ルールのテスト（91,602 項目）・その1 79項目（3回続けて合格）・その2 40項目・その3 34項目、すべて合格。
テストで見つけて直したもの: ホストが席を続けて2回変えると2回目が無視されて元にもどる（席・制限時間・補助はロックを使わない形に）／「はじめる」の処理中に盤を押すと無視される（置く操作の二度押しよけを分けた）。
二重レビュー（2026-10-25）: Codex（CLI・読み取り専用）と Claude のレビュー役（サブエージェント）。直したもの: ホストが切れている間、参加者は押せないのに CPU どうしで対局が進む（時計を止め、戻ったら数えなおす）／1手もどしたあとに届いた古い手が通る・確認の間に置かれた手を「1手もどす」が取り消す（局面の番号 `rev` で照合）／おわったあとに1手もどして終えなおすと `finish` を二重に数える（`ended`）／最後の1手を CPU が置いたとき「時間切れ」が出ない／ルームを出たあとの1台の画面にバーの表示が残る／待合室の「端末なし」の印が全員に出る／切れている席の人と同じ名前の端末なしの参加者を足せる／在室が消えている間の退出で席が空かない。直さなかったもの（既知の制約に書いた）: 締め切り後の余裕の間の人の手・待合室の席の名前・切断予約の順序・応答が届かないときの数え漏れ。
直したあとの結果: ルール 91,433・その1 81項目（3回続けて）・その2 43項目（2回）・その3 34項目、すべて合格。
