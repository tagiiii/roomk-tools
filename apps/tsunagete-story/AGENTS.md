# つなげてストーリー

## 目的・使用シーン

昔からある「いつ・どこで・だれが・何をした」の遊びを、ルームで遊ぶ形にしたことばのゲーム。お題を3つから選び、1人ずつ「いつ」「どこで」などをうけもって書く。そろったら1片ずつ順に出して文にし、できた文に「そのあと…」を足して小さなお話にする。点数・勝ち負け・投票はない。

参加する人は**それぞれの端末の画面で書く**。読む画面はホストの画面共有でも見られる。

2026-11-10 にオーナーの依頼で `drafts/itsudoko/`（BroadcastChannel の試作。仮の名前「いつどこ文づくり」）を作り、同日オーナーの「改善点がなければ本体に移して」で本体化した。試作で決めたことの経緯は、この AGENTS.md を正本にする（drafts はリポジトリに入れていない）。

## セッション条件（ツール一覧のカードと同じ）

値はツール一覧（`apps/index.html`）のカードと同じにする。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 2〜13人（ホスト＋参加12人まで） |
| 目安時間 | 10〜20分 |
| 利用シーン | コトバであそぼ！・ひろば・サークルタイム |
| 種類 | ことばのゲーム（`kotoba`） |

## 技術スタック

Firebase Realtime Database + 匿名認証。分割ファイル（`index.html`・`app.js`（module）・`style.css`・`data.js`）。作成・参加・再接続・切断・退出・ルームのバーは `apps/kotoba-dash/` と同じ作り。`RoomkRTDB.initFirebase()`・`RoomkRTDB.now()`（サーバー時刻補正）・`copyRoomCode` / `copyRoomLink`・`RoomkQR`・howto・stats を使う。名前空間は `tsunagetestory_rooms`（`database.rules.json` に 2026-11-10 オーナー承認で追加）。

## 遊び方（ルール）とオーナーが決めたこと（2026-11-10）

| 項目 | 内容 |
|---|---|
| 流れ | 待合室 → お題を決める（3択）→ 書く → 読む（1片ずつ）→「そのあと…」を足す → つぎの文／もう1回書く → おしまい（その日にできたお話の一覧） |
| 言葉の出し方 | **はじめは自分で書く**（入力欄が先）。思いつかない子は「候補から選ぶ」で候補カード3枚に切りかえる（「ほかの候補」で入れかえ）。入力欄の例（プレースホルダー）はお題の言葉。「基本的には自分で書くのをデフォルトに」 |
| 文ができたあと | お話をつなげる。だれでも「そのあと…」を1つの文に3つまで足せる（入力欄が先・候補は「候補から選ぶ」）。点数も投票もない |
| お題 | 回のはじめに「きょうのお題は？」で3つのカードを出し、ホストが選んで「このお題で書きはじめる」を押す（選ぶまでは押せない）。「ほかの3つにする」で入れかえ（いま出ている3つは出さない）。参加する人の画面にも同じ3つが出て、選ばれたカードに色がつく（押せない）。書いているあいだはかえられない。「お題を増やして3択から選ぶような感じで」「お題は決めてから記入に移る」 |
| お題の数 | 16（`data.js` の `themes`。各「いつ・どこで・だれが・何をした」10語）。書きはじめたお題は、16を出しきるまで候補に出さない（`usedThemes`）。待合室の「お題: なし」なら、お題の画面をとばしてすぐ書く（候補は `when` などのふつうの言葉） |
| 文の項目 | 待合室の「文の項目」で「だれと」「なぜ」「どのように」を足せる（いくつでも。はじめは「どのように」だけ）。「どのようになど増やすと面白くなるもの」 |
| 見直し画面 | 置かない（本体化のときオーナーが外すと決めた）。「送る」ですぐ送る。読む前なら「書きなおす」で直せる。合わない文はホストの「この文をとばす」で止める |
| やめたこと | 「ひとり1文をまぜる」（一人が4つとも書いた文をバラバラにしてまぜる）を試作で作ったが、「1人で文を考えるのは長いし面白みが無くなりそう」でやめた |

### 文の項目と、文の中のつけ方

文の中の順番は次の表のとおり（`ALL_SLOTS`）。例:「満月の夜、雲の上で、ねこが、カメと、ひまだったから、こっそり、おどりだした。」

| 項目 | つけ方 | 候補 |
|---|---|---|
| いつ | 「〜、」 | お題の言葉／ふつうの候補（`when`） |
| どこで | 「〜で、」 | 同上（`where`） |
| だれが | 「〜が、」 | 同上（`who`） |
| だれと（足せる） | 「〜と、」 | 「だれが」と同じ言葉から |
| なぜ（足せる） | 「〜、」（「〜から」で書く） | お題によらず共通（`why`）。いやなこと・こわいことを理由にしない |
| どのように（足せる） | 「〜、」 | お題によらず共通（`how`） |
| 何をした | 「〜。」 | お題の言葉／ふつうの候補（`what`） |

- 助詞と句読点は画面でつける。自分で書いた言葉の最後に同じ助詞（「雲の上で」の「で」など）があれば取ってからつける（`strip`）。書く子は名詞だけ考えればいい
- 1片は16文字まで、「そのあと…」は24文字まで

### うけもちの割り当て（人数ごとの遊び方）

| 人数（書く人） | うけもち |
|---|---|
| 項目の数より少ない | 1人がいくつかずつうけもって、1つの文を作る（5項目で2人なら3つと2つ） |
| 項目の数と同じ | 1人1つずつ |
| 項目の数より多い | 文を増やす（5項目なら6〜10人で2つ、11人から3つ）。足りない片はおまかせ（お題の言葉）で入る |

- 回ごとに、うけもつ項目をずらす（`round` で回す）
- 書く画面の上に文の形（いつ・どこで…）を出し、自分のうけもちに色をつける

### 読む

- みんなが送ったら、ホストの画面が自動で読む画面にする（`maybeRead`）。ホストは「待たずに読む」でも進められる。まだの所・退出した人の所は候補からおまかせで埋める
- 1片ずつ 1.3秒ごとに出る。出す時刻（`read.at`）はサーバー時刻で、各画面が `RoomkRTDB.now()` とくらべて自分で出す。ホストは「もう一度出す」で出しなおせる
- 「そのあと…」は、文が出そろってから足せる。だれが足したかは出さない

## 画面構成・status 遷移

`waiting`（待合室）→ `theme`（お題を決める。お題なしならとばす）→ `write`（書く）→ `read`（読む。`read.idx` で何文め）→ ホストの「もう1回書く」で `theme` / `write`、「おしまい」で `result` → ホストの「もう一回（待合室へ）」で `waiting`。

- はじめの画面: 入口の型 `.app-entry`（絵・説明・「ルームをつくる」「ルームに参加する」）
- 作成・参加・ルームのバー（コードをコピー・リンクをコピー・QRコードを出す・退出する／ルームを閉じる）は rtdb.md の共通どおり
- 待合室: 参加する人・「自分も書く」（ホストだけ）・ルール（文の項目・お題）・「はじめる」。参加する人の画面には「いまのルール」の要約

## Firebase データ構造

```
tsunagetestory_rooms/{code}
  status: 'waiting' | 'theme' | 'write' | 'read' | 'result'
  host, hostUid, hostConnected, hostDisconnectedAt
  settings: { hostPlays, themeMode: 'on' | 'none', extra: ['with' | 'why' | 'how'] }
  game: はじめた回数, round: その中の何回め
  themeChoices: [お題のid ×3], theme: お題のid | null, usedThemes: [お題のid]
  slots: ['when', 'where', 'who', 'how', 'what']   … この回の項目（書きはじめに決まる）
  tasks: { 名前: [[何文め, 何番めの項目], ...] }   … うけもち
  nSent: この回の文の数
  sub: { 名前: { '何文め-何番め': 書いた言葉 } }
  sents: [ { parts: [言葉...], hidden, lines: [そのあと...] } ]
  read: { idx, at }
  book: [ { parts, slots, lines, theme: お題の名前 } ]   … おしまいの一覧（とばした文は入れない）
  players: { 名前: { isHost, uid, joinedAt } }
```

- ホストの操作（設定・はじめる・お題・書きはじめる・読む・もう一度出す・とばす・つぎへ・おしまい・待合室へ）は、どれも `hostUid` を確かめるルームの transaction
- 書いた言葉（`sub/{名前}`）と「そのあと…」（`sents/{idx}/lines`）は、参加する人がルームの transaction で書く（status・回・うけもち・文が出そろったかを確かめる）
- だれが何を書いたか（`sub`）は参加する人の端末にも届く（性善説。画面には出さない）

## ホストも書くか・途中参加・端末のない参加者

- **ホストも書く（`settings.hostPlays`）: 初期値は「書く」**。ホストの画面にもほかの人のうけもちは出ない（読むまで分からない）ので、同じ条件で遊べる。進行だけのときは待合室で「進行役」の印、うけもちを持たない
- 2人から始められる（書く人が1人以上）
- **途中参加**: どの status でも参加できる。書いている途中で入った人はその回は見るだけで、つぎの回からうけもちがつく。「そのあと…」は足せる
- **端末のない参加者は作らない**（作るかは本体化のときオーナーに確かめていない。いまは作っていない）。声で参加する子は、読む画面の「そのあと…」を声で言ってもらい、だれかが書き足せばよい
- マイクを使わない子は、書く・選ぶだけで最後まで遊べる（声は要らない）

## 切断時の挙動・削除

- ホスト切断: `hostConnected=false`・`hostDisconnectedAt`。ゲストには「ホストの戻りを待っています」を出し、TTL（`ORPHAN_TTL_MS` = 2分）を過ぎたら期限切れとして消す
- ゲスト切断: `players/{名前}` の `onDisconnect().remove()`。戻ったときは同じ名前で在室を足し直す（うけもち・書いた言葉は名前で持っているのでそのまま続く）。書いている途中で切れた人は待たない（読むときにおまかせで埋める）
- 再接続: sessionStorage（`tsunagetestory_session`）で同じルームに戻る
- **自動削除は rtdb.md「公認バリアント: ふりかえり画面滞在中は削除しない」を採用**: おしまいのあとも続けて遊ぶ（「もう一回」）ことが多いので、終了30秒後の自動削除はしない。(1) ホストの「ルームを閉じる」 (2) ホスト切断の TTL (3) 次回アクセス時の期限切れ掃除 の3経路で消す

## 特有のルール・制約

- 言葉は `data.js`（ふつうの候補 `when` 36・`where` 38・`who` 35・`what` 37、`why` 28・`how` 30、「そのあと…」`next` 20、お題 `themes` 16×40）。学校・勉強・家族・恋愛・こわい話・けんか・かけごとにつながる言葉は入れない。家族（お父さん・おばあちゃん）は家庭の事情にふれうるので入れていない
- 同じ言葉が、ふつうの候補とお題の候補、別のお題どうしに入っているのは意図どおり（欄ごとに引くため）。同じ欄の中の重複と空の言葉は `node scripts/content-audit.mjs` が止める
- 子どもが自由に書くので、合わない言葉が入ることはある。ホストの「この文をとばす」でその場で止め、とばした文はおしまいの一覧にも入れない
- 配慮の理由は画面・あそびかた・更新情報に書かない
- 音は鳴らさない
- 未確認（2026-11-10 公開時点）: 実際の日本語入力（Mac・iPad のフリック）での入力、Safari
