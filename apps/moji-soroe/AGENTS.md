# もじそろえゲーム 仕様書

## 目的・使用シーン

ひらがなの文字タイルを「1枚引いて1枚捨てる」を順番にくり返し、手もとの8枚を
「2文字・3文字・3文字」の3つの言葉にそろえたら「あがり」のワードゲーム。
市販の『ひらがじゃん（ひらがな麻雀）』カード版から着想（オーナー依頼・2026-09-02）。
名称は商品名を使わずオリジナル（ルート AGENTS.md「アプリ名のつけかた」）。着想元は
`updates.json` の紹介文と `apps/guide/` にのみ記述的に書く。

- **core value**: 「言葉が見つかった！」の瞬間と、あがった言葉を**みんなで確かめる会話**。
  正誤を機械判定せず、言葉になっているか・意味や由来を話す時間がゲームの一部。
- 対象: 小学校中学年〜中学生。コトバであそぼ・ボドゲクラブ（`data-scenes="kotoba bodoge"`）。
- **2〜5人**。手番制なので人数が多いと待ち時間が伸びる（5人上限は意図的）。
  **ホストもプレイヤーとして参加する**。
- 音声なしでチャット参加する子も遊べる（全アクションはボタン操作。言葉の確認だけは
  チャット／口頭で会話する前提）。

## ゲームルール

### 文字タイル（120枚）

| 種類 | 構成 | 枚数 |
|------|------|------|
| 清音 | あ〜ん 45音（「を」は含めない） | 各2枚 = 90 |
| 濁音・半濁音 | が〜ぽ 25音 | 各1枚 = 25 |
| 小さい文字・のばし棒 | ゃ ゅ ょ っ ー | 各1枚 = 5 |

タイルID 0〜119。`TILE_CHARS[id]` が文字（清音は 0〜44 と 45〜89 に同じ並びで2周）。

### ラウンドの流れ（回数無制限・ホストが終わるまで）

1. 全員に7枚配る。席順でラウンドごとに先手をずらす（ラウンド r の先手 = 席順の (r−1) % 人数 番目）。
2. 手番の人が「1枚引く」→ 8枚になる。
3. 8枚から1枚を選んで「◯を捨てる」→ 確認「捨てて、次の人へ」→ 次の人の番
   （確認をはさむのは「捨てたら勝手に番が終わった」というオーナー実機FBへの対応・2026-09-02）。**捨てた文字は全員に見える**（共通の捨て札列）。
   または、8枚が「2文字・3文字・3文字」の言葉になっていれば「あがる」で宣言。
4. あがり宣言（`check`）: 3つの言葉を全員に表示し、みんなで言葉になっているか確かめる。
   ホストが「OK！あがり」で確定（そのラウンドの勝ち）、または「ちがうみたい（つづける）」で
   宣言した人の「捨てる」に戻す。
5. 山（120 − 7×人数）がなくなったら、そのラウンドは引き分け。
6. ホストが「次のラウンド」か「ここで終わる」を選ぶ。

- **ポン・カン・ロンはない**（カード版相当のシンプルルール。オーナー選択）。
- **言葉の判定は自己申告＋みんなで確認**。辞書・語彙リストは持たない。固有名詞や方言、
  活用形なども場の会話で決めてよい（メンター裁量）。
- 手もとの並べかえは手番に関係なくいつでもできる（ドラッグで好きな位置へ移動。タップで選んで
  移動先をタップしてもよい。入れかえではなく「挿入」で、間のタイルは詰まる）。
  並びは「2文字・3文字・3文字」の枠で常に可視化し、あがりはこの並び順で切る。
- 引き分けや途中終了に罰則はない。

### まとめ

- 「ここで終わる」時点の「あがった回数」一覧と、各ラウンドでできた言葉の履歴を表示。
  いちばん多くあがった人をやわらかく祝う（同数は全員・全員0回なら「おつかれさま」）。
  順位表・煽りは出さない。

共通規約どおり最大8文字・同ルーム内重複NG・空文字NG。RTDB パスキーに使うため
`.` `#` `$` `[` `]` `/` を含む名前は参加時に拒否。前後の空白は trim。

## 画面構成・フロー

```
TOP（screen-top）
 ├── ルームを作る → ニックネーム入力 → ロビー（screen-lobby）
 └── 入る → ニックネーム + コード入力 → ロビー or ゲーム（ラウンドの合間の途中参加）
                      ↓（ホストが「始める」/ 2〜5人）
            ゲーム画面（screen-game）
              turn（draw→discard を手番ごとに）→ check（あがり宣言）→ settled
              を1画面内で繰り返す（画面遷移はしない）
                      ↓（ホストが「ここで終わる」/「途中で終わる」）
            まとめ（screen-result）
              ホスト: 「もう一度」（接続中メンバーで仕切り直し）「トップへ戻る」（ルーム削除）
              ゲスト: 「トップへ戻る」（自分の退出のみ）
```

- ゲーム画面は上から「盤面（ラウンド・手番・山の残り・捨てられた文字）」「あなたの手もと」「みんな」。
- 観戦（みるだけ）モードは**置かない**。手もとは各自の端末にだけ表示され、他の人の手札は
  枚数のみ。メンターが画面共有するときは自分の手もとが見えてよい前提（ホストも1プレイヤー）。

## status 遷移

```
waiting → playing → result（ここで終わる／途中で終わる）
result →（もう一度）→ playing
```

| status | 説明 |
|--------|------|
| `waiting` | ロビー。2〜5人 |
| `playing` | ゲーム中。`match/phase` が turn / check / settled を持つ |
| `result` | まとめ。ホストは「もう一度」「トップへ戻る」 |

- `waiting → playing`・`result → playing`・`playing → result`・あがり確定／差し戻し・次のラウンドは
  **ホストのみ**。引く・捨てる・あがり宣言・並べかえは各メンバー本人の transaction。

### 途中参加

- `playing` かつ `phase === 'settled'`（ラウンドの合間）: `players` と `match/members` に追加され、
  次のラウンドから参加（`wins` は 0）。
- ラウンド中（turn / check）: 参加は拒否し「いまのラウンドが終わったら入れるよ」と案内。
- `result`: `players` にだけ追加され、「もう一度」で参加。

## Firebase データ構造（Realtime Database）

パス: `mojisoroe_rooms/{roomCode}/`（共通命名規則。セキュリティルール変更不要）

```
mojisoroe_rooms/{roomCode}/
  ├── host / hostConnected / hostDisconnectedAt / status / createdAt   # 共通
  ├── players/                          # presence: 「いま接続している人」のみ（ノードの有無が接続状態）
  │    └── {nickname}/ { isHost, seat }
  └── match/                            # 開始・「もう一度」で丸ごと上書き
       ├── matchId: number              # ゲーム世代（開始=1、もう一度で+1）
       ├── members/ {nickname}: { seat } # 対戦者集合（settled 中の途中参加でのみ増える）
       ├── wins/    {nickname}: number  # あがった回数
       ├── history: [{ round, nick, words: [str×3] }]   # あがりの履歴（まとめ表示用）
       ├── round:   number              # 1始まり・上限なし
       ├── phase:   'turn' | 'check' | 'settled'
       ├── turn:    nickname            # 手番の人（turn のとき）
       ├── step:    'draw' | 'discard'  # 手番の中の段階
       ├── deck:    [number × 120]      # タイルID。ラウンド開始時にシャッフル済みで固定
       ├── pos:     number              # deck の次に引く位置（配り・引きで単調増加）
       ├── hands/   {nickname}: [tileId, ...]   # 手もと（並び順そのものがあがりの区切り）
       ├── discards: [tileId, ...]      # 捨てられた文字（全員共通・時系列）
       ├── drawnId: tileId | null       # いま引いた1枚（手番の人の画面で new 表示）
       ├── claim:   { nick, words: [str×3], tiles: [tileId×8] } | null   # あがり宣言中
       └── winner:  { nick, words: [str×3] } | null   # settled のとき。null なら山切れの引き分け
```

- `hands` / `discards` / `history` などは空だと RTDB に保存されないため、読み取りは必ず `|| []` / `|| {}` で補う。
- 手もとは RTDB 上は平文（**性善説**・共通方針どおり）。他人の手札は UI で枚数だけ表示する。

### transaction 設計

進行の書き込みはすべてルームルートへの `transaction()`。deck はラウンド開始時（開始・次のラウンド・
もう一度）にホストが transaction の**外**でシャッフルして渡し、配り（`dealRound` 純関数）と引きは
`deck[pos]` からの順次消費＝決定的。

| 操作 | 実行者 | transaction 内の検証 → 書き込み |
|------|--------|--------------------------------|
| 作成 | ホスト | `room == null` → 初期ルーム一式 |
| 参加 | ゲスト | 上記「途中参加」参照（waiting / settled / result で可） |
| 開始 | ホスト | `status==='waiting'`・host 本人・2〜5人 → `status:'playing'` + `dealRound` |
| 引く | 手番の人 | `phase==='turn'`・`turn===自分`・`step==='draw'` → `deck[pos]` を手もとに追加・pos+1・`step:'discard'`・`drawnId`。**山切れなら `phase:'settled'`・`winner:null`** |
| 捨てる | 手番の人 | `phase==='turn'`・`turn===自分`・`step==='discard'`・そのタイルを持っている → 手もとから除去・`discards` 末尾に追加・`turn` を席順の次へ・`step:'draw'` |
| あがる | 手番の人 | `phase==='turn'`・`turn===自分`・`step==='discard'`・手もとが8枚 → `phase:'check'`・`claim`（words は並び順を 2/3/3 で切った文字列） |
| 並べかえ | 各メンバー | `phase==='turn'`・手もとの**多重集合が前後で一致** → `hands/{自分}` を並び替え後で上書き（手番でなくても可） |
| OK！あがり | ホスト | `phase==='check'` → `phase:'settled'`・`winner`・`wins[nick]+1`・`history` 追記・`claim:null` |
| ちがうみたい | ホスト | `phase==='check'` → `phase:'turn'`・宣言者の `step:'discard'` に戻す（宣言者が抜けていたら次の人の draw） |
| 次のラウンド | ホスト | `phase==='settled'`・メンバー2人以上 → round+1・新 deck で `dealRound` |
| ここで終わる | ホスト | `status==='playing'` → `status:'result'`（match は残す） |
| もう一度 | ホスト | `status==='result'`・接続中2人以上 → 接続中 players で members/wins を作り直し・matchId+1 |
| ゲスト退出 | 各自 | players と match（members/wins/hands）から自分を削除。自分の手番・自分の宣言中なら次の人の draw に進める |

- クライアントは操作時点の `matchId` / `round` / `phase` を捕捉し transaction 内で再検証（ABA 対策）。
- 引く・捨てる・あがるは `state.actionBusy` で連打をガード。
- タイルの選択（`state.selectedIndex`）と捨てる確認中（`state.confirmDiscard`）はローカルのみ。
  手番・フェーズが変わったら捨てる。タイルを触る・並べかえると確認はやり直し。
- ドラッグは Pointer Events（`touch-action: none`）。8px 動くまではタップ扱いで click に任せ、
  動いたらゴースト表示→最も近いタイルの位置へ挿入。ドラッグ中は `renderMyArea` を保留し、
  ドロップ後に描き直す。並べかえはローカル表示を先に更新してから RTDB へ書く（体感優先）。

## 接続・切断・再接続

blackjack と同一（presence「ノードの有無方式」）:

| 役割 | onDisconnect 予約 |
|------|------|
| ホスト | `roomRef.onDisconnect().update({ hostConnected:false, hostDisconnectedAt:TIMESTAMP, 'players/{host}': null })` |
| ゲスト | `players/{nick}` への `onDisconnect().remove()`（全フェーズ共通） |

- ゲームデータ（hands / wins など）はすべて `match/` 側にあるため、presence ノードが消えても失われない。
  切断表示は「members に居て players に居ない人」。
- `.info/connected` を購読し、復帰のたびに `writeBackPresence` transaction で presence を再作成 →
  成功後に onDisconnect 予約を張り直す。epoch ガードで「書き戻し中に退出」を無効化。
- sessionStorage キー **`mojisoroe_session`**（roomCode / nickname / isHost / matchId）。
  リロード時 `tryReconnect()` で復帰。RTDB の値から画面を完全再構築できる。
- ホスト切断: ゲストにオーバーレイ + 2分カウントダウン（`ORPHAN_TTL_MS = 2 * 60 * 1000`）。

### 切断中の進行

- 切断中の人の手番は**待つ**（進行が止まる）。軽い通信切れは `.info/connected` 復帰で解消。
  長い離脱は本人の明示退出（手番が次へ進む）か、ホストの「途中で終わる」→「もう一度」で解消する。

## 終了とデータ削除

- `result` 画面ではルームを**自動削除しない**（公認バリアント「ふりかえり画面滞在中は削除しない」。
  先行事例: blackjack, esadori, tatoe-narabe）。
- クリーンアップ経路は3つ: ①ホストの「トップへ戻る」で即時 `remove()` ②ホスト切断
  onDisconnect + 2分 TTL ③次回アクセス時（join / tryReconnect / ルーム監視）の期限切れ判定。
- すべての退出・削除経路で `remove()` の前に必ず `cancelRoomOnDisconnect()` を await する。

## 文言・UX ガイド

- 通常表記（漢字まじり。ルート AGENTS.md「表記トーン」参照）。
- 麻雀用語（ツモ・リーチ・流局など）は使わない。「引く」「捨てる」「あがる」「山」だけ。
- あがり宣言の確認は「3つとも言葉になっているかな？ 意味や由来も聞いてみよう」と会話に誘導する。
  「不正解」「失敗」とは言わず、差し戻しは「ちがうみたい（つづける）」。
- 引き分けは淡々と（「山がなくなったよ」）。まとめの祝いはやわらかく。

## 共通規約からの逸脱の明文化

- **競争要素（あがった回数・いちばん）を意図的に残す**: 「比較を促さない」の例外案件
  （先行事例: ピタハメ、エサドリ、ブラックジャック）。ただし1ラウンドの勝者は1人で、
  負けは「山切れ」か「他の人があがった」だけ。順位表は出さない。
- **手番制（同時進行ではない）**: 既存の同時出し系（esadori / blackjack）と異なり順番待ちがある。
  待ち時間に手もとを並べかえられるようにして退屈を減らす。
- **正誤の判定を機械で行わない**: 辞書を持たず、ホストの「OK！あがり」だけで確定する。
  自動判定より会話を優先する意図的な設計（オーナー選択）。
- **途中参加あり**: settled / result で参加可（blackjack と同じ）。
- **明示退出で match からも自分を抜く**: 手番制のため退出者を待ち続けると止まる（blackjack と同じ）。
- **result 後の自動削除なし**: 公認バリアント採用。
- **観戦モードなし**: 上記「画面構成」参照。

## メンター向け進行のコツ

- あがり宣言が出たら、確定を急がず「どういう意味？」「どこで知ったの？」と聞く時間が本体。
  言葉として微妙なときは「みんなはどう思う？」と場に振り、OK でも差し戻しでも明るく。
- 固有名詞（キャラ名・地名）や擬音語を認めるかは最初に一言決めておくと揉めない
  （おすすめ: 「みんなが知っていればOK」）。
- 手番が回ってこない時間は「並べかえて言葉を探す時間」と伝える。「あと1文字で◯◯なんだけど」と
  つぶやく子が出てきたら盛り上がっている合図。
- 1ラウンドは人数×2〜3周で決着することが多い。長引いたら「あと1周で山切れにしよう」ではなく
  ホストの「途中で終わる」→「もう一度」で仕切り直してよい。
- 通信が切れたまま戻らない子がいたら、本人の「退出する」で手番が次に進む。
