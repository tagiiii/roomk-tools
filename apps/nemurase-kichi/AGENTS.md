# ねむらせ基地 仕様書

## 目的・使用シーン

ひみつ基地の中をそれぞれの端末で歩きまわり、仕事のミニゲームを片づける正体かくしゲーム。仲間のふりをした「ねむらせ屋」がまぎれていて、近くの隊員をこっそりねむらせる。ねむっている人を見つけたら会議をひらき、話し合って投票する。

- **core value**: 体を動かす（歩く・ミニゲーム）ことと、会議の話し合いの両方で参加できる。ねむらされても・投票で選ばれても、仕事をつづけられるので、途中で何もできなくなる子が出ない
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・サークルタイム（`data-scenes="bodoge hiroba circle"`）
- 4〜10人（練習用のロボットを含む）。**ひとり1台の端末**。1回は10〜15分（15分で時間切れ）

> 経緯: 2026-10-25 オーナー依頼「インポスターゲーム的なもの」→「Among Us 的なもの」→「リアルタイムで動く・倒すでなく『ねむらせる』・ねむった人も仕事を続けられる」で `drafts/nemurase-kichi/` に試作。2026-10-26 にオーナーと仮置きをすべて見直して確定し、同日「本体化をお願いします」で本体化した。試作の README（`drafts/nemurase-kichi/README.md`）に、見直しの経緯と試作の作りが残っている。
> 名前・キャラ・宇宙船のテーマは着想元から借りず、ひみつ基地にした。着想元は早見表と更新情報でだけ「『Among Us』から着想」と書く（検索のキーワードには入れない）。
> 暴力・死はコンテンツ規約で使えないので、倒すかわりに「ねむらせる」。ねむっている姿は横になって「Zzz」。

## ルール

| | 隊員 | ねむらせ屋 |
|---|---|---|
| 勝ち | みんなの仕事がぜんぶおわる／ねむらせ屋を全員見つける | おきている隊員が、ねむらせ屋と同じ数になる |
| 引き分け | 15分たつ（時間切れ） | 同じ |
| できること | 仕事（ミニゲーム）・ふたりの仕事・停電をなおす（ミニゲーム）・空気のパネルをなおす（ミニゲーム）・はしご・監視カメラ・地図・「見つけた！」・会議ボタン・ひとこと（ささやき） | 近くの隊員をねむらせる（待ち時間あり）・しかけ（停電・空気を止める・ドアをしめる）・近道・はしご・監視カメラ・地図・「見つけた！」・会議ボタン・ひとこと。仕事の場所に立って、仕事のふりができる（本当の仕事はできない）。ふたりの仕事のスイッチはおせる（手伝い・アリバイ） |
| ねむったあと | 仕事をつづけられる（ふたりの仕事も）。おきている人からは見えない。かべ・家具・ドアを通りぬけて歩ける。投票はしない。だれにねむらされたかは自分の画面にだけ出る | 見ているだけ（かべを通りぬけて歩ける） |
| 負け | ねむらせ屋に「空気を止め」られて、60秒のうちに2つのパネルを両方なおせなかった（2026-10-28。「停電で負けることはない」はそのまま。負けるのは空気だけ） | — |

- 歩く: 矢印キー / WASD、タッチの端末は左下のスティック。つかう: スペース（E）、地図: M、ひとこと: T、見つけた: R、ねむらせる: Q、しかけ: F、役職のわざ: G（下の「役職」）
- 仕事のミニゲームは3種類（線を5本つなぐ／1〜8を順に押す／メーターを目印に合わせる（±2、合ったまま1秒）。`minigames.js`）。どれもまちがえてもやりなおしにならない
- 見える広さは隊員5.5マス（2026-10-29 子どもの要望「視野が広くなるとよい」→ オーナー決定で 4.5 → 5.5）・停電中2.4マス・ねむらせ屋7.5マス。**この広さの中でも、自分と相手の間にかべがあれば見えない**（2026-10-27。`E.canSee`。v1 の「かべで隠す計算はしない」をやめた）。暗がりも丸でなく、自分から見える範囲の多角形で抜く（`E.viewPolygon`。全方向に540本の光線を飛ばし、かべに当たった所で止める。かべの面が見えるよう0.3マスだけのばす）。「見つけた！」「ねむらせる」も、かべの向こうの相手には押せない（ねむらせる距離1.5マスは、かべ1枚（1マス）をへだてると届かないので、実際に効くのは「見つけた！」2.2マスの方）。ねむった人はぜんぶ見える（かべも関係ない）。ロボットも同じ（かべの向こうのねむっている姿は見つけない・かべの向こうの隊員は「見ている人」に数えない・ねむらせない）
- 近道（`E.VENTS`）: ねむらせ屋（と役職の整備係）だけが使える。8か所（台所・電気室・畑・倉庫・洗たく室・ポンプ室・監視室・ゲーム室。どれもちがう部屋）。床のまるいふた（だれにでも見える）の上で「近道に入る」（スペース）を押すと、**近道の中に入って姿が消え**、画面に「どこに出る？」の一覧（ほかの7か所の部屋の名前＋「ここから出る」）が出る。選ぶとその近道から出る（2026-10-29 子どもの要望「ベントで飛ぶ場所を選べるように」→ オーナー決定: 8か所のどこへでも・中では見えない・部屋の名前のボタン。それまでは2か所ずつの組で、決まった1か所へ一瞬で移っていた）。中にいられるのは `E.VENT_STAY_S`（10秒）までで、過ぎたら入った近道から出る（Escape でも、そこから出る）。中にいる間は歩けず、ほかの操作もできない。会議になったら出る。続けて使えるのは出てから1.2秒あと（整備係は30秒あと）。おきているねむらせ屋と整備係だけ。ロボットのねむらせ屋は使わない
  - 中にいることは、位置の文字列の3つ目を `2` にして知らせる（`"x,y,2"`。`E.encodePos(x, y, f, hidden)`。書き込みは増えない。ルールの「16文字までの文字列」のまま）。受け取った側は、その人を描かない・ねむらせる相手にしない・カメラに映さない（`drawPos` が null を返す）。ロボットのねむらせ屋も見えない人として扱う（`knownPos`）。自分の画面では、自分をうすく描く
  - 読み込み直すと近道の外（入った近道の上）に出る
- **ねむらせ屋を有利にする調整（2026-10-26 オーナー「インポスターが不利な感じがする」→ 4つとも入れる）**: 隊員の見える広さ 6→4.5マス／ねむらせてから次まで はじめ30秒（20・30・45）→ はじめ20秒（15・20・30）／ミニゲームを少し長く（線4→5本・番号1〜6→1〜8・メーター±3→±2、0.6→1秒）／近道を追加。実際に遊んで、まだ偏りがあれば数を見直す
- **行き止まり**（2026-10-27 子どもの意見「マップに行き止まりがほしい」「壁越しで見えない仕様にしてほしい」。どちらもねむらせ屋が有利になる向きの変更）: 入口が1つの小部屋を2つ足した。**道具室**（台所↔電気室の通路の右手。通路2×3マス＋部屋4×3マス）と**温室**（畑↔倉庫の通路の左手。同じ形）。奥に仕事の場所を1つずつ置き（`SPOTS` の id 11・12。わざわざ入る理由）、ひとりの仕事（3〜5）はこの13か所（2026-10-29 から17か所）からくじで選ぶ。マップは `engine.js` の `ROOMS`・`HALLS` の数字だけで決まり、ぶつかる判定・ロボットの道さがし・進行役の地図はグリッドから自動で合う。行き止まりの数と場所・かべごしの見えなさで隊員がさらに不利になるので、見える広さ・待ち時間の数字は実際に遊んで見直す前提。**2026-10-27 オーナー決定: 行き止まり2つ（道具室・温室）・暗がりも多角形で切る段階2あり・見える広さと待ち時間の数字はそのまま、で確定**
- 停電: はじめは20秒たってから、なおしてから40秒は起こせない（この待ち時間 `darkReadyAt` は空気と共通。停電と空気は同時には起こせない）。電気室のスイッチで、おきている人ならだれでもなおせる。会議でもなおる。停電で負けることはない
  - **なおすのはミニゲーム**（2026-10-28 子どもの意見「電気を直しにくく」。ねむらせ屋が有利になる向き）: スイッチの前で「電気をなおす」を押すと、仕事と同じ型のミニゲーム（1〜8を順に押す。題は「電気室：スイッチを順に入れなおす」）がひらき、おえると直る（`openFix`。`state.taskSpot = FIX_TASK（-2）`）。途中でほかの人が直したら「電気はついたよ」でとじる。ねむらされたらとじる。ロボットも同じくらいの時間（`BOT_FIX_MS` 5.5秒）をかけてから直す（その間に直っていれば何もしない）。2か所同時になおす形は入れていない（4人の回では重いため）
- **はしご**（2026-10-28 子どもの意見「マップにギミック（はしご）」）: 通信室（画面の上）と見はり台（画面の下）をつなぐ。`E.LADDERS`（2つ・対）。上に立って「はしごをおりる／のぼる」（スペース）を押すと、`E.CLIMB_MS`（2.5秒）のあいだその場に立ったまま（ボタンは「おりている…／のぼっている…」で押せない・歩けない・ほかの人から見える・ねむらせられる）、つながったはしごへ移る。**だれでも使える**（隊員・ねむらせ屋・ねむった人）。近道とちがって書き込みはなく、位置の送り方は歩くときと同じ。会議がひらいたら途中でも取り消す（テーブルのまわりへもどる）。ロボットは使わない（道さがしは歩きだけ）。隊員の移動が速くなる＝隊員が有利になる向きなので、見える広さ・待ち時間の数字は実際に遊んで見直す前提
- **監視カメラ**（2026-10-28 子どもの意見。2026-10-29 子どもの要望「カメラルーム（監視室）がほしい」で、台を通信室から新しい監視室へ移し、カメラを4つ→6つにした）: 監視室のカメラの台（`E.CAM_STAND`）に立って「カメラを見る」（スペース）を押すと、通路に置いた6つのカメラ（`E.CAMS`。台所と通信室の間・通信室と監視室の間・監視室とひろばの間・ひろばと倉庫の間・ひろばと見はり台の間・ポンプ室と見はり台の間）のまわり `E.CAM_R`（2.5マス）の**通路の部分だけ**が小窓（はばが420px以上なら3列×2行、せまければ2列×3行）に映る（部屋の中は映らない。おきている人・ねむっている姿が名前つきで映る。ねむった人は映らない）。隊員が有利になる向きなので、対にする制約を3つ入れた: ①見ている間はその場から動けない（ねむらせられる。会議がひらく・ねむらされると自動でとじる）②だれかが見ている間は、通路のカメラの赤いランプが点滅する（ねむらせ屋が避けられる。見える範囲にあるカメラだけ）③停電中は映らない（「停電中は映らない」）。おきている人だけ（ねむらせ屋も使える）。見ていることは `game/cam/{id}: true` に書き、とじたら消す（切れたら `onDisconnect` で消える。会議で空にする）。位置はおきている人がもともと全員分受け取っているので、カメラで通信は増えない。進行役の画面にはランプを出さない
- 会議: 「見つけた！」（ねむっている人の近く）か、ひろばのテーブルの会議ボタン（ひとり1回・設定で2回）。全員テーブルのまわりにもどる。ねむっている姿・空気の妨害・ドア・おしているスイッチは片づく
  - **会議ボタンの待ち時間**（2026-10-28 子どもの要望「ボタンにクールダウン」）: はじめと会議の結果のあと `E.BUTTON_WAIT_S`（20秒）は押せない（`game/buttonReadyAt`。ラベル「会議ボタン（あとN秒で押せる）」）。空気が止まっている間も押せない（「会議ボタン（空気をなおしてから）」）。「見つけた！」には待ち時間がない（本当にねむった人がいるなら、すぐ会議でよい）。はじまった直後の会議・会議の連続・追われたときにボタンで逃げることをふせぐ
  - **会議の時間**は 60・90・120・150・180秒から。残り時間は会議の画面に大きく出し、30秒を切るとオレンジ、10秒を切ると赤く点滅（`is-near`/`is-soon`。音は鳴らさない。`prefers-reduced-motion` では点滅しない）。下に減っていくバー（`#meetingBar`）
- 投票はおきている人だけ。いちばん多い1人がねむる（同じ数・スキップがいちばん多いときは、だれもねむらない）。**しめきり（時間切れ・ホストの「投票をしめきる」）で終わった会議では、まだ入れていない人（通信が切れた人を含む）をスキップとして数える**（2026-10-28 子どもの要望「時間切れは投票スキップ」。`endMeeting(g, now, timeout)`。みんな入れて終わったときは何も足さない）。結果で「ねむらせ屋だった／じゃなかった」を出す。**票は人ごとの数だけ出し、だれがだれに入れたかは出さない**（入れられた子が気まずくならないように）
- 時間切れ: 15分（`E.GAME_LIMIT_S`）。遊んでいる途中ならすぐ、会議・結果の途中なら結果を見せおわってから「時間切れ！ 引き分け」。ただし、会議の結果で勝ち負けが決まったときは、15分を過ぎていてもそちらを優先する（会議で見つけたのに引き分けにしない）
- **途中で抜けた人**（2026-10-26 オーナー決定。2026-10-28 待つ時間を30秒→1分・戻れるように変更）: ゲームの途中で「退出する」を押した人はすぐ、タブを閉じた人・通信が切れたままの人は在室が消えたまま1分たったら（`LEFT_GRACE_MS`。読み込み直し・アプリの切り替え・短い切断は抜けたことにしない）、抜けた人になる（`game/left/{id}`）
  - 勝ち負けの判定から外す（おきている人に数えない）。ねむらせ屋が全員抜けたら隊員の勝ち（理由「ねむらせ屋がいなくなった」）。隊員が抜けて、おきている隊員がねむらせ屋と同じ数になったら、ねむらせ屋の勝ち
  - 仕事の数からも外す。**おわらせた仕事はそのまま数え、のこりの仕事だけを全体の数から外す**（みんなの仕事のバーが下がらないように）
  - 投票しない・投票の相手に選べない（会議の一覧に「抜けた」）。おしまいの一覧に「途中で抜けた」
  - **同じ人が戻ってきたら、続きから遊べる**（2026-10-28 オーナー決定「途中で落ちる子がいた」）: 勝ち負けが決まる前に、同じブラウザ（同じ匿名ID）・同じ名前で入りなおすか、同じタブのままつながりなおすと、ホストの端末（`watchLeavers`）が在室を見て抜けた人の印を外す（`mut.back`）。同じ役・同じ状態（おきている／ねむっている）で続きから。**のこりの仕事も全体の数にもどる**（みんなの仕事のバーは少し下がる）。本人の画面には役のお知らせを出し、その文の頭に「もどってきたね。つづきから遊べるよ。」（ねむったまま戻ったときは「ねむったまま、つづきから遊べるよ」。ねむったお知らせのバナーの代わり。バナーだと役のお知らせの下に隠れるため、お知らせの中に書く）。会議・結果の間に戻ったときは、遊ぶ時間になってから一度だけ出す（`backNote`）。位置は、同じタブ（つながりなおし・読み込み直し）なら元の場所から、新しいタブならテーブルのまわりから（位置はタブごとの保存のため）
  - おしまいのあと（勝ち負けが決まったあと）は戻さない。別の端末（別の匿名ID）からは、これまでどおり同じ名前で入れない
  - 遊んでいる間に勝ち負けが決まればすぐおしまい（15分を過ぎていたら時間切れが先）。会議の間に抜けたときは会議の結果で、結果の間に抜けたときは結果のあとで、勝ち負けを確かめなおす（結果のときに決まっていた勝ち負けも変わりうる。たとえば、ねむらせ屋の勝ちが決まった結果の間に、そのねむらせ屋が抜けたら隊員の勝ち）
  - 理由は、ねむらせ屋を全員（投票・ねむらせで）見つけたときだけ「ねむらせ屋を全員見つけた」。ひとりでも抜けていれば「ねむらせ屋がいなくなった」
  - **ホストは抜けた人にならない**（ホストがタブを閉じると、参加者の画面は「ホストの戻りを待っています」で止まり、2分で期限切れ。戻ればそのまま続ける）

- **だれにねむらされたか**（2026-10-28 子どもの要望。オーナー「入れる」）: `mut.sleep` が `game/sleptBy/{相手}` にねむらせた人の id を書く。**ねむらされた本人の画面にだけ**出す（お知らせの帯「〇〇さんにねむらされた… だれにねむらされたかは、ないしょだよ」と、やることの注意書き「（〇〇さんにねむらされた。ないしょだよ）」）。ほかの人の画面・会議・おしまいには出さない。DB は全員が読めるので DevTools では見える（性善説）。ねむった子が声でばらすと推理がこわれるので、スライドと心得で「ないしょ」を約束にしている（本家は幽霊が声を出せないが、ここは Zoom の声がある）
- **ねむった人はかべを通りぬける**（2026-10-28 子どもの要望「幽霊状態で壁を通り抜けられない」）: `E.stepFree`。かべ・家具・ドア・テーブルを無視して歩き、マップの外（`RADIUS` の内側）には出ない。ロボットの幽霊は道さがしのまま（通りぬけない）。ねむった人は位置を `g` に送るので、おきている人の画面には出ない
- **読み込み直しても元の場所**（2026-10-28 キル回避の対策）: 以前は読み込み直すと `spawnPoint`（テーブルのまわり）に戻ったため、追われたときに F5 で瞬間移動して逃げられた。自分の位置を `sessionStorage` の `nemurase_pos`（`{g: ゲームの番号, s: spawnKey, x, y, f}`）に送るたびに残し、同じ回・同じ `spawnSeq` の読み込み直しなら元の場所から続ける（立てない場所なら spawnPoint）。会議のあと（spawnSeq が増える）は使わない。ルームを出ると消す
- **ひとこと＝ささやき**（2026-10-28 子どもの要望「近づいたらコメントを送信」。オーナー「ささやきにしてください」）: 遊んでいる間のひとことは、**送った人が自分の見える広さの中にいて、間にかべがない人にだけ**届く（`sayReaches`。送る側が `game/say/{id}` に位置 `x, y` を足し、受け取る側が自分の `viewRadius` と `canSee` で決める）。自分のは届く。ねむった人（ぜんぶ見える）にはぜんぶ届く。進行役・見学には遊んでいる間のひとことは届かない（位置の話なので、画面共有で流れないように）。会議中のひとことはこれまでどおりみんなに届く。語は変えていない（「ひろばに集まろう」なども近くの人にだけ届く）
- **声の約束の帯**（2026-10-28 子どもの要望「会議の時間以外はミュート」。アプリは Zoom / Meet のマイクを操れないので、帯と心得で約束にする）: 画面の上に「いまはミュートの時間。ひとことで知らせよう」（遊んでいる間）／「会議の時間。ミュートを外して話そう」（会議・結果）を出す（`#hudMute`。おしまいでは出さない）。進行役・見学の画面（画面共有）にも出す。会議の画面にも「会議の時間。ミュートを外して話そう」

- 表示: 遊んでいる間は、ゲームの画面を見ている全員（進行役・見学を含む）の画面の上に「名前: 言葉」を6秒（新しい順に3つまで）。会議中は、投票の一覧の名前の下にその人の最新の1件、言葉のボタンの下にこの会議の流れ（新しい8件）。会議の流れは会議の番号で分ける（遊んでいる間の言葉は会議に出ない）
- 書き方: `game/say/{id}` に **ひとり1枠**で `{k: 言葉のキー, t: 相手の id か '', r: 部屋のキーか '', n: 通し番号, at: 時刻, m: 会議の番号（遊んでいる間は 0）, x, y: 送った位置, a: 見た目のだれか（へんしん中ならなっている人。2026-10-29）}` を set（位置と同じ考え方で、流れは端末の中だけに持つ。読み込み直すと、それまでの流れは消え、いま入っている分は見たことにする）。`gameOf` が確かめて `g.say` に取りこむので、`r` 全体の transaction でもそのまま書き戻る。はじめると前の回の分は消える
- 音は鳴らさない。ホスト（進行だけ）の言葉は持たせていない（声で話せるため。要るなら足す）
- 「〔名前〕さんがあやしいと思う」は責める言葉に寄るが、投票そのものが同じ意味を持つので残した（2026-10-27 オーナー承認）。「ねむっている人がいた！」は「見つけた！」（会議をひらく）とは別で、会議をひらかずに知らせたいとき用

## 設定（待合室でホストが決める）

| 項目 | 選べる値 | はじめの値 |
|---|---|---|
| ホスト（あなた） | いっしょに遊ぶ／進行だけ | いっしょに遊ぶ |
| ねむらせ屋の数 | 1人／2人（7人以上のときだけ。少ないときは1人になる） | 1人 |
| ねむらせ屋の決め方 | ランダム／ホストが選ぶ | ランダム |
| ひとりの仕事の数 | 3・4・5つ（隊員はこれに「ふたりの仕事」1つが足される） | 4つ |
| ふたりの仕事 | あり（隊員はひとり1つ）／なし | あり |
| ねむらせてから次まで | 15・20・30秒（はじめの1回は15秒） | 20秒 |
| 会議の時間 | 60・90・120・150・180秒 | 90秒 |
| 会議ボタン（ひとり） | 1・2回 | 1回 |
| みんなの仕事のバー | 出す／進行役の画面だけ／出さない | 出す |
| 整備係・見守り係・まもり星・へんしん屋（役職。ひとつずつ） | 入れる／入れない | 入れない（2026-10-29） |

2026-10-26 にオーナーと見直して、すべて確定（試作 README の「決まったこと」）。

- **ねむらせ屋の決め方（2026-10-27 追加）**: 子どもから「同じルームで続けて遊ぶと、ねむらせ屋が登録順の最後の人に続けてなった。ランダムにしてほしい」と意見が出た。ランダム（`E.shuffled` の Fisher–Yates）はもとから偏りがなく、連続は偶然だが、オーナー指示で「ランダム／ホストが選ぶ」を設定にした
  - 「ホストが選ぶ」にすると、ホストの待合室の「あそぶ人」に「ねむらせ屋にする」ボタンが出る（進行だけのホスト自身には出ない）。選んだ人には「ねむらせ屋」のタグ。必要な人数（1人、または7人以上で2人）とちがう間は「はじめる」を押せず、注意書きで足りない・多い人数を出す
  - 選んだ人は **ホストの端末だけが持つ（`state.picks`。DB には書かない）**。参加者の画面には設定の値「ホストが選ぶ」だけが見え、だれを選んだかは見えない。はじめると空にする（次の回は選び直す）。ホストが読み込み直すと消える（選び直す）
  - `E.newGame(ids, settings, rnd, picks)`: 選んだ人のうち遊ぶ人にいる分を人数ぶんだけねむらせ屋にし、足りなければ残りはシャッフルで決める（画面の側で人数を合わせているので、通常は選んだ人がそのままなる）
  - ホストが「いっしょに遊ぶ」で選ぶと、ホストはだれがねむらせ屋か知ったまま遊ぶことになる。選ぶのは、ホストが進行だけのとき・ホストが知っていてもよいと決めたときに使う（心得）

## 進行役の画面・端末のない子

- ホストが「進行だけ」を選ぶと、ゲームの人数に入らず、役のお知らせも出ない。会議では投票しないが「投票をしめきる」は押せる
- **進行役・見学の人の画面には、だれがどこにいるかを出さない**（地図・みんなの仕事のバー・停電・のこり時間・会議と結果・おしまいだけ）。画面共有しても、ねむらせ屋の動きが見えないようにするため
- **端末のない子は、画面共有された進行役の画面を見て、会議の話し合いに声やチャットで加わる**（投票はしない）。ホストが代わりに動かす形は作らない（役が見えてしまうため）
- ゲームの途中から入った人も、進行役と同じ画面（「見学（次の回から）」）

## 練習用のロボット

- 待合室でホストが「練習用のロボットを入れる」で足す（`ロボ1`〜`ロボ9`。遊ぶ人は合わせて10人まで）。人数が足りないとき・メンターがひとりで遊び方を確かめるとき用
- **ホストの端末が動かす**（`setInterval` で50msごと。裏のタブでもタイマーは1秒おきに動くので止まらない。ホストが切れている間は止まる）
- 仕事の場所へ歩いて仕事をする／ねむっている人の近くで「見つけた！」／投票は半分スキップ／隊員のロボットのうち1つが停電をなおしに行く。ねむらせ屋のときは、ほかに見ている人がいないときだけねむらせる
- ロボットの名前（`ロボ` ＋数字1つ）は人の名前に使えない

## 別の Firebase プロジェクト（`roomk-nemurase`）

2026-10-26 オーナー決定。位置を絶えず送り合うので、ほかのアプリよりずっと通信が多い。無料枠（Spark）を超えるとその期間アプリが止められるため、room-K 本体のプロジェクト（`roomk-tools`）から分けて、止まってもねむらせ基地だけで済むようにした。同時接続100も本体と別。

- プロジェクトはオーナーが作った（Spark・請求先なし・Realtime Database はシンガポール・匿名ログインだけ・承認済みドメイン `tagiiii.github.io`・使用量のメールのお知らせはオン）。経緯は試作 README の「本体の通信の作り」
- **接続の設定は `firebase-config.js` だけに持つ**。共通の `RoomkRTDB.initFirebase` は本体のプロジェクトにつなぐので使わず、同じ形（初期化・匿名ログイン・`RoomkRTDB.initServerTime`）をここでそろえる。ほかの共通部品はそのまま使う
- ルールはコンソールで直接設定している（リポジトリの `database.rules.json` は本体用で、このプロジェクトには入らない）。**正本は `tests/nemurase-kichi/rules.json`**（テストはこのルールを入れたエミュレーターで動く）。ルールを変えるときは、この JSON を直してテストを流し、同じ中身をコンソールに貼る
- **軽い決まり（2026-10-26 オーナー決定）**: 匿名ログインした人が `nemurase_rooms/{ルームコード}` を読み書きできる。そのうえで、①ルームコードの形（6文字・`A-HJ-NP-Z2-9`）の場所だけ ②部屋の中は `r`・`p`・`g` だけ ③位置（`p`・`g`）は id が16文字まで・値が16文字までの文字列だけ。`r` の中（ゲームの中身）は決めない（アプリを直してもルールを変えずに済むように）。ルームの一覧（`nemurase_rooms` 全体）は読めない
  - ねらい: 関係のない場所への書き込み・大きな書き込みを防ぐ。正しい形の書き込みをくり返されると無料枠は使い切られうる（そこまでは防がない。防ぐなら App Check などが要る）
  - **データの形を変えるとき**: `r` の中なら変えなくてよい。部屋の中に `r`・`p`・`g` 以外を足す・位置の形を変えるときは、先にルールを変える（古い画面が新しいルールで断られないよう、ルールはゆるめる方向を先に、アプリをあとに）
- **利用回数（stats.js）は本体のプロジェクトに数える**（stats.js は名前付きの別アプリとして初期化するので、ぶつからない。回数だけなので通信はわずか）

## Firebase データ構造（roomk-nemurase の Realtime Database）

```
nemurase_rooms/{roomCode}/
  ├── r/                               # ゲームの状態（全員が value で購読する）
  │    ├── status:          'waiting' | 'play'
  │    ├── host / hostUid:  ホストの名前と匿名ID
  │    ├── hostConnected / hostDisconnectedAt / createdAt
  │    ├── lastGameId:      number
  │    ├── settings:        { hostPlays: 1|0, sleepers, tasks, cooldown, meeting, buttons }
  │    ├── players/{name}:  { isHost, uid, joinedAt, color }   # 在室。ゲストは切断で消える
  │    ├── bots/{*1〜*9}:   { name: 'ロボN', color }            # 練習用のロボット（待合室で足す）
  │    └── game/                       # 「はじめる」で作り、待合室にもどると消す
  │         ├── id, players: [id...], uids: {id: 匿名ID}（人だけ）, names: {id: 表示名}, colors: {id: 色}
  │         ├── roles: {id: 'crew'|'sleeper'}, tasks: {id: [{spot, done}...]}, buttons: {id: 残り回数}
  │         ├── done/{id}/{場所}: ゲームの番号     # 仕事の完了の印（ゲーム全体を書き直さないため。番号がちがう回の印は使わない）
  │         ├── asleep: {id: 'slept'|'voted'}, sleptBy: {id: ねむらせた人の id}, left: {id: true}（途中で抜けた人）, bodies: {id: {x, y}}, cooldown: {id: 時刻}
  │         ├── air: 期限の時刻（0＝止まっていない）, airFixed: {a: true, b: true}, doors: {部屋のキー: この時刻までとじる}, doorReadyAt, buttonReadyAt
  │         ├── pair/{p0|p1}/{a|b}: {id, at}       # ふたりの仕事のスイッチをおしている人（2秒おきに at を書き直す。はなれたら消す。会議で空にする）
  │         ├── cam/{id}: true                   # 監視カメラを見ている人（とじたら消す。切れたら onDisconnect で消える。会議で空にする）
  │         ├── jobs: {id: 'engineer'|'watcher'|'shifter'|'angel'}, angelReadyAt   # 役職（2026-10-29）
  │         ├── shield: {id: この時刻までバリア}, shape: {id: {as, until}}（へんしん中）, shiftReadyAt: {id: 時刻}   # 会議で shield・shape は空にする
  │         ├── blocked: {by, t, at}              # さいごにバリアで ねむらせられなかったとき（本人とまもり星に一度だけ知らせる）
  │         ├── dark, darkReadyAt, spawnSeq（増えたら全員テーブルのまわりへ）, endsAt（15分の時刻）
  │         ├── stage: 'play'|'meeting'|'result'|'end'
  │         ├── meetingSeq: これまでの会議の数
  │         ├── meeting: { seq（何回目の会議か）, why: 'body'|'button', caller, found, endsAt, votes: {id: 相手の id | '*skip'} }
  │         ├── ballots/{会議の番号}/{id}: 相手の id | '*skip'   # 投票（1つずつ書く。番号がちがう会議の票・ねむっている人の票・ねむっている人への票は使わない）
  │         ├── result: { counts, target, tie, wasSleeper, until }
  │         ├── winner: 'crew'|'sleeper'|'draw', winReason: 'tasks'|'found'|'outnumber'|'left'|'timeup'|'air'
  │         ├── settings（はじめた時点の写し）, ended（finish を1回だけ数える）
  ├── p/{id}: "x,y,f"                  # おきている人の位置（座標×10の整数・向き。f は 1＝右・0＝左・2＝近道の中で見えない（2026-10-29））
  └── g/{id}: "x,y,f"                  # ねむった人の位置
```

- id は人なら名前、ロボットは `*1`〜`*9`（名前に `*` は使えない）。投票のスキップは `*skip`
- 読み込むときは壊れた値を読み飛ばす（`gameOf`）。位置は `E.decodePos` で検査する

## 通信を抑える作り

試作で見積もった量（10人で1時間約100MB）では無料枠（1日の目安約360MB）にすぐ届くため、次のようにした（2026-10-26）。

| やること | 中身 |
|---|---|
| 位置はゲームの状態と別の場所 | `p`・`g` は `r` の購読に入らない。位置が動くたびにルーム全体の処理・転送が起きない |
| 位置は1秒に3回まで | 動いている間だけ送る（`POS_MS = 333`）。止まったら最後の位置を1回だけ。届いた位置の間は補間でつなぐ |
| 会議・結果・おしまいの間は送らない | 0回（ひとことは別。ひとり1枠の小さな set で、5秒に1回まで） |
| ねむった人の位置は `g` | おきている人は `g` を購読しない（見えないので受け取らない）。ねむった人だけが購読する |
| 見学・進行役は位置を受け取らない | ただし、ロボットのいるホストは、ロボットのねむらせ屋が隊員の位置を知るために `p` を受け取る（画面には出さない） |
| 位置は短い文字列1つ | `"123,456,1"` |
| よく起きる操作は小さく書く | 仕事の完了は `game/done/{id}/{場所}` に、投票は `game/ballots/{会議の番号}/{id}` に、1つだけ書く。`r` 全体の transaction は全員に `r` 全体が配られるため、ねむらせる・見つけた・会議・停電・進行など、たまにしか起きない操作だけにする |
| 人数と時間の上限 | 10人まで（ロボットを含む）。1回15分まで |

- 測った量（2026-10-26、エミュレーター、ホスト＋参加者1人＋ロボット6つの8人で40秒。参加者はずっと歩き、ロボットは仕事をしながら歩く）: 位置の知らせ1件 約78バイト、参加者の受信 1時間あたり約4MB → **8人の部屋で1時間あたり約30〜35MB**（2回測って 29.7MB・34.5MB）。8人全員がずっと歩きつづけたときの位置の分だけの上限は約47MB。手順は `tests/nemurase-kichi/traffic.cjs`
- 本番は暗号化と通信のつなぎの分が足されるので、これより少し多くなる。Firebase コンソールの使用量で、実際の量を見て確かめる（オーナー）
- **1日の上限（その日に遊んだ時間を数えて止める仕組み）は入れない**（2026-10-26 オーナー決定。別のプロジェクトと通信の節約だけにする）。無料枠を超えたら、その期間ねむらせ基地だけが止まる。上限に近づくとメールが届く

## 操作と書き込み

| 操作 | 実行者 | 書き方 |
|---|---|---|
| 作成 | ホスト | `r` に transaction（`transactRetry`。やり直しで自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | `r` に transaction。名前が空いている（ホスト・ロボット・別の匿名IDの人・ゲーム中の名前の持ち主と同じは不可）・待合室で遊ぶ人10人未満・在室20人未満（ゲームの人は上限を見ない）→ `players/{name}`（色は空いている色。ゲーム中の人はゲームの色） |
| 設定・ロボット | ホスト | `waiting` の `r` に transaction |
| はじめる | ホスト | 前の回の `p`・`g` を消してから、`waiting`・遊ぶ人4〜10人（「ホストが選ぶ」なら選んだ人数が合っている）→ `game` を作る |
| 仕事の完了 | その人（ロボットはホスト） | 端末で確かめて `game/done/{id}/{場所}` にゲームの番号を set。ぜんぶおわったら、ホストが進行の transaction |
| 投票 | その人（ロボットはホスト） | 端末で確かめて `game/ballots/{会議の番号}/{id}` に transaction（まだ入れていないときだけ）。みんな入れたら、ホストが進行の transaction（ホスト以外は下の「進行」で代わる） |
| 近道 | ねむらせ屋 | 書き込みなし（自分の位置が移るだけ。位置の送り方は歩くときと同じ） |
| はしご | 遊んでいる人（ねむった人も） | 書き込みなし（2.5秒その場に立ってから位置が移る。位置の送り方は歩くときと同じ） |
| 監視カメラ | おきている人 | `game/cam/{id}` に true を set（`onDisconnect().remove()` を張る）。とじたら cancel して remove |
| 停電をなおす | おきている人（ロボットはホスト） | スイッチの前でミニゲームをおえてから、`r` に transaction（`mut.fix`） |
| ひとこと | その人（おきている人だけ） | `game/say/{id}` に1件を set（ひとり1枠・5秒に1回まで・位置つき。上の「ひとこと」） |
| ふたりの仕事のスイッチ | 遊んでいる人（ロボットはホスト） | `game/pair/{仕事}/{a|b}` に `{id, at}` を set（おしている間2秒おき）。はなれたら transaction で自分の分だけ消す。そろったら、この仕事を持つ人が `game/done` に書く |
| 空気のパネルをなおす | おきている人（ロボットはホスト） | パネルの前でミニゲームをおえてから、`r` に transaction（`mut.airFix`） |
| 空気を止める・ドアをしめる | ねむらせ屋 | `r` に transaction（`mut.air`・`mut.door`） |
| まもる・へんしん（役職） | まもり星・へんしん屋 | `r` に transaction（`mut.protect`・`mut.shift`）。中で役職・おきているか・待ち時間・相手を確かめる。距離は押した端末が確かめる |
| 近道（整備係）・チェッカー（見守り係） | 整備係・見守り係 | 書き込みなし（待ち時間と電池は端末の中） |
| ねむらせる・見つけた・会議ボタン・停電・なおす | その人（ロボットはホスト） | `r` に transaction（`gameAct`）。中で役・おきているか・待ち時間・回数を確かめる。**距離は押した端末が確かめる**（性善説） |
| 進行（会議のしめきり・みんな投票した・結果のあと・仕事がぜんぶおわった・15分） | ホスト。ホスト以外は、進められる状態を最初に見てから3秒たっても進んでいないときだけ代わる（ホストが切れている間は代わらない） | `r` に transaction（`mut.advance`）。同時に送っても条件を中で確かめるので1回しか進まない |
| 投票をしめきる | ホスト | `r` に transaction |
| 待合室へ（おしまいから／途中でやめる） | ホスト | `r` に transaction → `p`・`g` を消す |
| 退出 | ゲスト | `r` に transaction で自分の在室を消す。ゲームの途中なら同じ transaction で抜けた人の印をつけ、勝ち負けが決まればおしまいにする（`finish` もこの端末が数える）。そのあと自分の位置を消す |
| タブを閉じた人を抜けた人にする | ホスト（`watchLeavers`） | ゲームの人の在室が消えた時刻をホストの端末が覚え、1分たっても戻らなければ `r` に transaction（`mut.left`）。ホストが読み込み直すと数えなおし（1分から）。ホストが切れている間は止まる |
| 抜けた人を戻す | ホスト（`watchLeavers`） | 抜けた人の印があるのに在室がある人を見つけたら `r` に transaction（`mut.back`。transaction の中でも在室を確かめる。おしまいのあとは何もしない） |

## 接続・切断・再接続

リバーシと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | `r` に `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `r/players/{name}` を `remove()` |
| 全員 | 自分の `p/{name}`・`g/{name}` を `remove()`（切れた人が、おきている人の画面に止まったまま残らないように） |

- `.info/connected` が true になるたびに予約を張り直し、在室を書き戻す（3秒に1回まで。つながった時点でルームの値がまだなければ、最初の値が届いたときに張る）。同じ名前の在室が別の匿名IDのものだったら、張った予約を取り消してルームから外れる
- つながりなおしたら、止まったままでも自分の位置を送り直す（切れていた間に、予約で位置が消されているため）。切れている間は位置を送らない（SDK が書き込みをためて、ルームが消えたあとに位置だけを作りなおさないように）
- ゲーム中に切れた人は、その場から消える（位置の予約）。会議ではその人の票を待たず、一覧に「通信が切れた」。同じタブで読み込み直すと、同じ役で続きから（位置は元の場所から）
- **切れている間は本人の画面に出す**（2026-10-28）: `.info/connected` が false のまま2秒（`OFFLINE_SHOW_MS`）たつと、上のバーに「通信が切れています。つながりなおしています…」（`#hudOffline`。赤）。つながったら消す。一瞬の切れでは出さない。**切れている間は歩けない・はしごを終えない・近道などの「つかう」は効かない**（つながりなおしたときに、ほかの人が見ていない間に動いた場所へ現れないように。2026-10-28 Codex レビュー）
- **遊んでいる間は画面を消さない**（2026-10-28）: 遊ぶ人の画面で、おしまいまで Screen Wake Lock（`navigator.wakeLock`）を取る。タブが裏にまわると外れるので、表にもどったら取りなおす（`visibilitychange`。表のまま外れたときは `release` で取りなおす）。取りに行っている間は重ねて取らない（`wakePending`）。対応していない端末・断られたときは何もしない。見学・進行役の画面では取らない
- ゲームの人の名前は、ほかの人（別の匿名ID）は使えない
- ホスト切断中、ゲストには共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`。ロボットと進行はホストの端末が動かすので、その間は止まる

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おしまいの画面のあとも自動削除しない（ホストが「待合室にもどる」で次の回へ）
- 削除経路: ①ホストの「ルームを閉じる」（ロボットと位置の送信を先に止め、`cancelRoomOnDisconnect()` をルートに await → ルートを `remove()`。`r`・`p`・`g` がまとめて消える。そのあと `r` のない `p`・`g` が残っていれば消す。ルームが消えたのを受け取った参加者も、同じ確かめをする） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、ルートへの transaction・`applyLocally: false`）
- 待合室にもどると `game` と `p`・`g` を消す

## 利用回数（stats.js）

「1回」は1ゲーム（はじめる〜おしまい）。数えるのは本体のプロジェクト。

| 項目 | 数えるとき・端末 |
|---|---|
| `room-create` | ルームができた（ホスト） |
| `start`・`players-{N}` | 「はじめる」（ホスト）。N は遊ぶ人（ロボットを含む・進行だけのホストは含めない） |
| `finish` | おしまいに進めた transaction を確定させた端末（`ended` で1ゲーム1回） |
| `again` | おしまいから「待合室にもどる」（ホスト）。途中でやめたときは数えない |

## 意図的な逸脱

- **別の Firebase プロジェクト**（上の節）。`RoomkRTDB.initFirebase` を使わない
- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る
- **ルームの下を `r`（状態）・`p`・`g`（位置）に分ける**。ルームの有無・期限切れは `r` で判断し、削除はルートで行う
- **ホスト以外もゲームを進める**: 自分の操作は自分の端末が transaction で書く。進行はホストが遅れたら、ほかの端末が代わる。`finish` は確定させた端末が数える
- **よく起きる操作は transaction でなく小さな場所への書き込み**（仕事の完了・投票）
- **みんなにみせる画面（`?watch=`）はない**。役と位置を隠すゲームなので、画面共有には進行役の画面を使う
- **端末なしの参加者は作らない**（役が見えてしまうため。進行役の画面を見て話し合いに加わる）
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **勝ち負けを出す**（隊員／ねむらせ屋のチームの勝ち負けだけ。点数・順位・成績は記録しない）
- **投票で選ばれた人に「ねむらせ屋だった／じゃなかった」を出す**（推理につなげるため。2026-10-26 オーナー確認）

## 既知の制約（v1）

- 距離（ねむらせる・見つけた・仕事・スイッチ・テーブル）は押した端末の見え方で確かめる（DevTools で書きかえれば遠くからもできる。共通方針の性善説）。役も DevTools では見える
- 位置は1秒に3回までなので、ほかの人の動きは少しなめらかさに欠けることがある（補間でつないでいる）
- かべごしに見えるかは相手の中心1点で決める（体の半分だけかべから出ているときも、中心がかべの向こうなら描かない。かべの角で急に出たり消えたりする）。暗がりの多角形は光線540本なので、かべの角のふちが少しギザつくことがある。ねむった人（見える広さなし）だけは、かべの向こうもぜんぶ見える
- ホストが切れている間は、ロボットと進行（会議のしめきり・結果のあと・時間切れ）が止まる。ホストのタブが裏にあると、ブラウザがタイマーを遅らせる（1秒おき。Chrome は長く裏にあるタブを1分おきまで遅らせることがある）ので、ロボットの動きと票が遅れる。進行は、ほかの端末が3秒あとに代わる
- ホストが読み込み直すと、ロボットはテーブルのまわりから動きなおす（進めかけの仕事は最初から）
- タブを閉じた人が抜けた人になるまでの1分の間は、その人はおきている人として数えたまま（会議の票だけは待たない）
- 抜けた人が戻ると、その子ののこりの仕事が全体の数にもどるので、みんなの仕事のバーが少し下がる（オーナー決定）
- 戻った子には、ホストの端末が印を外すまで（1秒ほど）見学の画面が見える。ホストが切れている間は戻せない（ホストが戻ってから）
- iPad など、ビデオ通話のアプリに切り替えている間にブラウザのタブが止められ、戻ったときに読み込み直しになることがある。1分以内なら同じ役で続き、1分を過ぎても入りなおせば戻れる
- 仕事の完了は小さな書き込みなので、ミニゲームをおえた瞬間にほかの人が会議をひらくと、会議の最中に完了が入ることがある（進み具合が会議中に1つ増えるだけ。勝ちの判定は遊んでいる間にだけ行う）
- 仕事の完了の印を書いた直後に、ホストが待合室にもどしたり次の回を始めたりした場合、印は番号のちがう回として読み飛ばされる（数え漏れはその回だけ）
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（共通方針どおり、少なめに出る側の誤差）
- はしごを使っている2.5秒の間、ほかの人の画面ではその場に立って見えるだけ（のぼっている様子は描かない）。ロボットははしごを使わない
- 監視カメラの映像は、ほかの人の位置が1秒に3回届く分だけなめらかさに欠ける。カメラを見ている人が通信を切ったままになると、`onDisconnect` が届くまで（最大で在室が消えるまで）ランプが光りつづけることがある
- ふたりの仕事の「おしている」は2秒おきの書き込みで、受け取る側は6秒で切れたとみなす。通信が遅いと、そろっているのに切れたことになり、おし直しになることがある。同じ組の仕事を2人が持っていて、その2人が両はしをおすと、2人ともおわる
- 空気のパネルをなおすミニゲームの途中で時間がくると、ミニゲームはとじる（`mut.airFix` は期限を過ぎていれば なおさずに おしまいにする）
- ドアをしめた瞬間にドアのマスにいた人は出られるが、その人がドアの上にとどまっている間は、ほかの人はそのマスに入れない。ロボットがドアの前で止まっているときは、1.5秒ごとに道を考えなおす
- 整備係の近道の待ち時間と、見守り係の電池は端末の中だけで持つ（読み込み直すと、待ち時間は消え、電池は満タン。書き込みを増やさないため）
- へんしん中のねむらせ屋のひとことは、送った時点のすがたの名前で出る（`game/say/{id}` の `a`。会議ではもとの名前）。へんしんの見た目は位置と同じく1秒に3回の知らせの間で切りかわる
- ふたりの仕事は、そろったあと1.5秒（`PAIR_LINGER_MS`）おしたままにしてから はなす（2026-10-29 E2E で、手伝う側がそろった瞬間にはなすと、仕事を持つ側の画面が「そろった」を見ないまま おわらないことがあると分かって直した）
- 読み込み直しの位置は端末（sessionStorage）の値なので、別の端末・別のタブからは元の場所に戻れない（テーブルから）
- 実機のスマホ・タブレットでのスティックの操作感、本番のプロジェクトでの通信量は未確認（2026-10-26 時点。2026-10-28 のふたりの仕事・空気・ドアの書き込みも本番では未確認）

## メンター向けの心得（画面には出さない）

- 端末のない子がいる回は、ホストを「進行だけ」にして、進行役の画面を画面共有する。進行役の画面には人の位置が出ないので、ねむらせ屋の動きはばれない。会議のときは、端末のない子にも「だれがあやしいと思う？」と聞いて話し合いに入ってもらう
- 投票で選ばれてねむった子には、「ねむっても仕事はつづけられるよ」と声をかける。ねむらせ屋だったことがばれた子も責めない（「うまくまぎれていたね」）
- はじめての回は、ロボットを入れてホストがひとりで1回遊んでみると、画面の流れが分かる
- 15分で時間切れになるので、長引いたら「あと何分」と声をかけて会議ボタンをうながすとよい
- 「ねむらせ屋の決め方」を「ホストが選ぶ」にすると、だれを選んだかは待合室のホストの画面に出る。画面共有している間は選ばない（共有を止めるか、選んでから共有する）。ホストが「いっしょに遊ぶ」で選ぶと、ホストはねむらせ屋を知ったまま遊ぶことになるので、進行だけのときに使うのが向いている
- **声の約束（2026-10-28）**: 声を出すのは会議の時間だけ。歩いている間は全員ミュートにしてもらい、「ひとこと」（近くの人にだけ届く）で知らせる。画面の上の帯が「いまはミュートの時間／会議の時間」を示すので、はじめの回は帯を指さして約束を確かめる。アプリは Zoom / Meet のマイクを操れないので、ミュートの切りかえは声かけで
- **ねむらされた子は、だれにねむらされたかを言わない約束**。本人の画面にだけ出る（「ないしょだよ」と書いてある）。声で言ってしまったら「それはないしょだったね」とやわらかく止め、その会議は続ける（ゲームがこわれるほどではない）
- 「空気が止まった！」が出たら、ひとりで2つのパネルは間に合いにくい。「台所はだれ？ 倉庫はだれ？」と手分けをうながす。負けたときは「60秒は短いね。次は分かれて動いてみよう」
- 「ふたりの仕事」は、ひとりで待っていてもおわらない。光っているスイッチを見つけたら、もう一方へ行ってあげるよう声をかける。少人数の回で相手が見つからないときは、設定で「ふたりの仕事: なし」にしてもよい
- **途中で落ちた子には、同じリンクから同じ名前で入りなおしてもらう**（同じブラウザで。別の端末からは同じ名前で入れない）。勝ち負けが決まる前なら、同じ役で続きから遊べる。Zoom・Meet と同じタブレットで遊ぶ子は、遊んでいる間はなるべくアプリを切り替えないようにする（切り替えるとブラウザが止められ、落ちたように見えることがある）
- 「どこに行けばいいか分からない」には、右上の小さな地図（押すと大きくなる）と、部屋の目印（台所はコンロ、通信室はアンテナ、倉庫は荷物、電気室は発電機、見はり台はライト、畑は水タンク、監視室はモニター、洗たく室は洗たく機、ポンプ室はポンプ、ゲーム室はゲーム機）と部屋の形（十字のひろば・L字の台所と倉庫・T字の畑）を教える
- **役職（2026-10-29）**: はじめての回は入れず、ゲームになれてから1つずつ足す。へんしん屋を入れた回は、「〇〇さんを見た」が当たらないことがあるので、すがたを使われた子が責められないように「へんしん屋かもしれないね」と声をかける。まもり星の子には「ねむらされても、みんなをまもれるよ」と伝える
