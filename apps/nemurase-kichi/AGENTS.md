# ねむらせ基地 仕様書

## 目的・使用シーン

ひみつ基地の中をそれぞれの端末で歩きまわり、仕事のミニゲームを片づける正体かくしゲーム。仲間のふりをした「ねむらせ屋」がまぎれていて、近くの隊員をこっそりねむらせる。ねむっている人を見つけたら会議をひらき、話し合って投票する。

- **core value**: 体を動かす（歩く・ミニゲーム）ことと、会議の話し合いの両方で参加できる。ねむらされても・投票で選ばれても、仕事をつづけられるので、途中で何もできなくなる子が出ない
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・サークルタイム（`data-scenes="bodoge hiroba circle"`）
- 4〜10人（練習用のロボットを含む）。**ひとり1台の端末**。1回は10〜15分（15分で時間切れ）

> 経緯: 2026-10-25 オーナー依頼「インポスターゲーム的なもの」→「Among Us 的なもの」→「リアルタイムで動く・倒すでなく『ねむらせる』・ねむった人も仕事を続けられる」で `drafts/nemurase-kichi/` に試作。2026-10-26 にオーナーと仮置きをすべて見直して確定し、同日「本体化をお願いします」で本体化した。試作の README（`drafts/nemurase-kichi/README.md`）に、見直しの経緯と試作の作りが残っている。
> 名前・キャラ・宇宙船のテーマは着想元から借りず、ひみつ基地にした。着想元は早見表と更新情報でだけ「『Among Us』から着想」と書く（検索のキーワードには入れない）。
> 暴力・死はコンテンツ規約で使えないので、倒すかわりに「ねむらせる」。ねむっている姿は横になって「Zzz」。

## ルール

| | 隊員 | ねむらせ屋 |
|---|---|---|
| 勝ち | みんなの仕事がぜんぶおわる／ねむらせ屋を全員見つける | おきている隊員が、ねむらせ屋と同じ数になる |
| 引き分け | 15分たつ（時間切れ） | 同じ |
| できること | 仕事（ミニゲーム）・停電をなおす・「見つけた！」・会議ボタン | 近くの隊員をねむらせる（待ち時間あり）・停電・「見つけた！」・会議ボタン。仕事の場所に立って、仕事のふりができる（本当の仕事はできない） |
| ねむったあと | 仕事をつづけられる。おきている人からは見えない。投票はしない | 見ているだけ |

- 歩く: 矢印キー / WASD、タッチの端末は左下のスティック。つかう: スペース（E）、見つけた: R、ねむらせる: Q、停電: F
- 仕事のミニゲームは3種類（線をつなぐ／1〜6を順に押す／メーターを目印に合わせる。`minigames.js`）。どれもまちがえてもやりなおしにならない
- 見える広さは丸だけ（隊員6マス・停電中2.4マス・ねむらせ屋7.5マス。かべで隠す計算はしない）。ねむった人はぜんぶ見える
- 停電: はじめは20秒たってから、なおしてから40秒は起こせない。電気室のスイッチで、おきている人ならだれでもなおせる。会議でもなおる。停電で負けることはない
- 会議: 「見つけた！」（ねむっている人の近く）か、ひろばのテーブルの会議ボタン（ひとり1回・設定で2回）。全員テーブルのまわりにもどる。ねむっている姿は片づく
- 投票はおきている人だけ。いちばん多い1人がねむる（同じ数・スキップがいちばん多いときは、だれもねむらない）。結果で「ねむらせ屋だった／じゃなかった」を出す。**票は人ごとの数だけ出し、だれがだれに入れたかは出さない**（入れられた子が気まずくならないように）
- 時間切れ: 15分（`E.GAME_LIMIT_S`）。遊んでいる途中ならすぐ、会議・結果の途中なら結果を見せおわってから「時間切れ！ 引き分け」。ただし、会議の結果で勝ち負けが決まったときは、15分を過ぎていてもそちらを優先する（会議で見つけたのに引き分けにしない）
- **途中で抜けた人**（2026-10-26 オーナー決定）: ゲームの途中で「退出する」を押した人はすぐ、タブを閉じた人は在室が消えたまま30秒たったら（`LEFT_GRACE_MS`。読み込み直し・短い切断は抜けたことにしない）、抜けた人になる（`game/left/{id}`）
  - 勝ち負けの判定から外す（おきている人に数えない）。ねむらせ屋が全員抜けたら隊員の勝ち（理由「ねむらせ屋がいなくなった」）。隊員が抜けて、おきている隊員がねむらせ屋と同じ数になったら、ねむらせ屋の勝ち
  - 仕事の数からも外す。**おわらせた仕事はそのまま数え、のこりの仕事だけを全体の数から外す**（みんなの仕事のバーが下がらないように）
  - 投票しない・投票の相手に選べない（会議の一覧に「抜けた」）。おしまいの一覧に「途中で抜けた」
  - 同じ人が戻ってきても、その回は見学（「見学（次の回から）」。位置は送らない・受け取らない）。次の回からまた遊べる
  - 遊んでいる間に勝ち負けが決まればすぐおしまい（15分を過ぎていたら時間切れが先）。会議の間に抜けたときは会議の結果で、結果の間に抜けたときは結果のあとで、勝ち負けを確かめなおす（結果のときに決まっていた勝ち負けも変わりうる。たとえば、ねむらせ屋の勝ちが決まった結果の間に、そのねむらせ屋が抜けたら隊員の勝ち）
  - 理由は、ねむらせ屋を全員（投票・ねむらせで）見つけたときだけ「ねむらせ屋を全員見つけた」。ひとりでも抜けていれば「ねむらせ屋がいなくなった」
  - **ホストは抜けた人にならない**（ホストがタブを閉じると、参加者の画面は「ホストの戻りを待っています」で止まり、2分で期限切れ。戻ればそのまま続ける）

マップとルールは `engine.js`（画面と通信に触らない。node でも読める）。

## 設定（待合室でホストが決める）

| 項目 | 選べる値 | はじめの値 |
|---|---|---|
| ホスト（あなた） | いっしょに遊ぶ／進行だけ | いっしょに遊ぶ |
| ねむらせ屋の数 | 1人／2人（7人以上のときだけ。少ないときは1人になる） | 1人 |
| ひとりの仕事の数 | 3・4・5つ | 4つ |
| ねむらせてから次まで | 20・30・45秒（はじめの1回は15秒） | 30秒 |
| 会議の時間 | 60・90・120秒 | 90秒 |
| 会議ボタン（ひとり） | 1・2回 | 1回 |

2026-10-26 にオーナーと見直して、すべて確定（試作 README の「決まったこと」）。

## 進行役の画面・端末のない子

- ホストが「進行だけ」を選ぶと、ゲームの人数に入らず、役のお知らせも出ない。会議では投票しないが「投票をしめきる」は押せる
- **進行役・見学の人の画面には、だれがどこにいるかを出さない**（地図・みんなの仕事のバー・停電・のこり時間・会議と結果・おしまいだけ）。画面共有しても、ねむらせ屋の動きが見えないようにするため
- **端末のない子は、画面共有された進行役の画面を見て、会議の話し合いに声やチャットで加わる**（投票はしない）。ホストが代わりに動かす形は作らない（役が見えてしまうため）
- ゲームの途中から入った人も、進行役と同じ画面（「見学（次の回から）」）

## 練習用のロボット

- 待合室でホストが「練習用のロボットを入れる」で足す（`ロボ1`〜`ロボ9`。遊ぶ人は合わせて10人まで）。人数が足りないとき・メンターがひとりで遊び方を確かめるとき用
- **ホストの端末が動かす**（`setInterval` で50msごと。裏のタブでもタイマーは1秒おきに動くので止まらない。ホストが切れている間は止まる）
- 仕事の場所へ歩いて仕事をする／ねむっている人の近くで「見つけた！」／投票は半分スキップ／隊員のロボットのうち1つが停電をなおしに行く。ねむらせ屋のときは、ほかに見ている人がいないときだけねむらせる
- ロボットの名前（`ロボ` ＋数字1つ）は人の名前に使えない

## 別の Firebase プロジェクト（`roomk-nemurase`）

2026-10-26 オーナー決定。位置を絶えず送り合うので、ほかのアプリよりずっと通信が多い。無料枠（Spark）を超えるとその期間アプリが止められるため、room-K 本体のプロジェクト（`roomk-tools`）から分けて、止まってもねむらせ基地だけで済むようにした。同時接続100も本体と別。

- プロジェクトはオーナーが作った（Spark・請求先なし・Realtime Database はシンガポール・匿名ログインだけ・承認済みドメイン `tagiiii.github.io`・使用量のメールのお知らせはオン）。経緯は試作 README の「本体の通信の作り」
- **接続の設定は `firebase-config.js` だけに持つ**。共通の `RoomkRTDB.initFirebase` は本体のプロジェクトにつなぐので使わず、同じ形（初期化・匿名ログイン・`RoomkRTDB.initServerTime`）をここでそろえる。ほかの共通部品はそのまま使う
- ルールはコンソールで直接設定している（リポジトリの `database.rules.json` は本体用で、この プロジェクトには入らない）。中身は `nemurase_rooms/$roomId` だけ、匿名ログインした人が読み書きできる（`tests/nemurase-kichi/rules.json` と同じ）。ルールを変えるときはコンソールで変え、テストの `rules.json` もそろえる
- **利用回数（stats.js）は本体のプロジェクトに数える**（stats.js は名前付きの別アプリとして初期化するので、ぶつからない。回数だけなので通信はわずか）

## Firebase データ構造（roomk-nemurase の Realtime Database）

```
nemurase_rooms/{roomCode}/
  ├── r/                               # ゲームの状態（全員が value で購読する）
  │    ├── status:          'waiting' | 'play'
  │    ├── host / hostUid:  ホストの名前と匿名ID
  │    ├── hostConnected / hostDisconnectedAt / createdAt
  │    ├── lastGameId:      number
  │    ├── settings:        { hostPlays: 1|0, sleepers, tasks, cooldown, meeting, buttons }
  │    ├── players/{name}:  { isHost, uid, joinedAt, color }   # 在室。ゲストは切断で消える
  │    ├── bots/{*1〜*9}:   { name: 'ロボN', color }            # 練習用のロボット（待合室で足す）
  │    └── game/                       # 「はじめる」で作り、待合室にもどると消す
  │         ├── id, players: [id...], uids: {id: 匿名ID}（人だけ）, names: {id: 表示名}, colors: {id: 色}
  │         ├── roles: {id: 'crew'|'sleeper'}, tasks: {id: [{spot, done}...]}, buttons: {id: 残り回数}
  │         ├── done/{id}/{場所}: ゲームの番号     # 仕事の完了の印（ゲーム全体を書き直さないため。番号がちがう回の印は使わない）
  │         ├── asleep: {id: 'slept'|'voted'}, left: {id: true}（途中で抜けた人）, bodies: {id: {x, y}}, cooldown: {id: 時刻}
  │         ├── dark, darkReadyAt, spawnSeq（増えたら全員テーブルのまわりへ）, endsAt（15分の時刻）
  │         ├── stage: 'play'|'meeting'|'result'|'end'
  │         ├── meetingSeq: これまでの会議の数
  │         ├── meeting: { seq（何回目の会議か）, why: 'body'|'button', caller, found, endsAt, votes: {id: 相手の id | '*skip'} }
  │         ├── ballots/{会議の番号}/{id}: 相手の id | '*skip'   # 投票（1つずつ書く。番号がちがう会議の票・ねむっている人の票・ねむっている人への票は使わない）
  │         ├── result: { counts, target, tie, wasSleeper, until }
  │         ├── winner: 'crew'|'sleeper'|'draw', winReason: 'tasks'|'found'|'outnumber'|'timeup'
  │         ├── settings（はじめた時点の写し）, ended（finish を1回だけ数える）
  ├── p/{id}: "x,y,f"                  # おきている人の位置（座標×10の整数・向き）
  └── g/{id}: "x,y,f"                  # ねむった人の位置
```

- id は人なら名前、ロボットは `*1`〜`*9`（名前に `*` は使えない）。投票のスキップは `*skip`
- 読み込むときは壊れた値を読み飛ばす（`gameOf`）。位置は `E.decodePos` で検査する

## 通信を抑える作り

試作で見積もった量（10人で1時間約100MB）では無料枠（1日の目安約360MB）にすぐ届くため、次のようにした（2026-10-26）。

| やること | 中身 |
|---|---|
| 位置はゲームの状態と別の場所 | `p`・`g` は `r` の購読に入らない。位置が動くたびにルーム全体の処理・転送が起きない |
| 位置は1秒に3回まで | 動いている間だけ送る（`POS_MS = 333`）。止まったら最後の位置を1回だけ。届いた位置の間は補間でつなぐ |
| 会議・結果・おしまいの間は送らない | 0回 |
| ねむった人の位置は `g` | おきている人は `g` を購読しない（見えないので受け取らない）。ねむった人だけが購読する |
| 見学・進行役は位置を受け取らない | ただし、ロボットのいるホストは、ロボットのねむらせ屋が隊員の位置を知るために `p` を受け取る（画面には出さない） |
| 位置は短い文字列1つ | `"123,456,1"` |
| よく起きる操作は小さく書く | 仕事の完了は `game/done/{id}/{場所}` に、投票は `game/ballots/{会議の番号}/{id}` に、1つだけ書く。`r` 全体の transaction は全員に `r` 全体が配られるため、ねむらせる・見つけた・会議・停電・進行など、たまにしか起きない操作だけにする |
| 人数と時間の上限 | 10人まで（ロボットを含む）。1回15分まで |

- 測った量（2026-10-26、エミュレーター、ホスト＋参加者1人＋ロボット6つの8人で40秒。参加者はずっと歩き、ロボットは仕事をしながら歩く）: 位置の知らせ1件 約78バイト、参加者の受信 1時間あたり約4MB → **8人の部屋で1時間あたり約30〜35MB**（2回測って 29.7MB・34.5MB）。8人全員がずっと歩きつづけたときの位置の分だけの上限は約47MB。手順は `tests/nemurase-kichi/traffic.cjs`
- 本番は暗号化と通信のつなぎの分が足されるので、これより少し多くなる。Firebase コンソールの使用量で、実際の量を見て確かめる（オーナー）
- **1日の上限（その日に遊んだ時間を数えて止める仕組み）は入れない**（2026-10-26 オーナー決定。別のプロジェクトと通信の節約だけにする）。無料枠を超えたら、その期間ねむらせ基地だけが止まる。上限に近づくとメールが届く

## 操作と書き込み

| 操作 | 実行者 | 書き方 |
|---|---|---|
| 作成 | ホスト | `r` に transaction（`transactRetry`。やり直しで自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | `r` に transaction。名前が空いている（ホスト・ロボット・別の匿名IDの人・ゲーム中の名前の持ち主と同じは不可）・待合室で遊ぶ人10人未満・在室20人未満（ゲームの人は上限を見ない）→ `players/{name}`（色は空いている色。ゲーム中の人はゲームの色） |
| 設定・ロボット | ホスト | `waiting` の `r` に transaction |
| はじめる | ホスト | 前の回の `p`・`g` を消してから、`waiting`・遊ぶ人4〜10人 → `game` を作る |
| 仕事の完了 | その人（ロボットはホスト） | 端末で確かめて `game/done/{id}/{場所}` にゲームの番号を set。ぜんぶおわったら、ホストが進行の transaction |
| 投票 | その人（ロボットはホスト） | 端末で確かめて `game/ballots/{会議の番号}/{id}` に transaction（まだ入れていないときだけ）。みんな入れたら、ホストが進行の transaction（ホスト以外は下の「進行」で代わる） |
| ねむらせる・見つけた・会議ボタン・停電・なおす | その人（ロボットはホスト） | `r` に transaction（`gameAct`）。中で役・おきているか・待ち時間・回数を確かめる。**距離は押した端末が確かめる**（性善説） |
| 進行（会議のしめきり・みんな投票した・結果のあと・仕事がぜんぶおわった・15分） | ホスト。ホスト以外は、進められる状態を最初に見てから3秒たっても進んでいないときだけ代わる（ホストが切れている間は代わらない） | `r` に transaction（`mut.advance`）。同時に送っても条件を中で確かめるので1回しか進まない |
| 投票をしめきる | ホスト | `r` に transaction |
| 待合室へ（おしまいから／途中でやめる） | ホスト | `r` に transaction → `p`・`g` を消す |
| 退出 | ゲスト | `r` に transaction で自分の在室を消す。ゲームの途中なら同じ transaction で抜けた人の印をつけ、勝ち負けが決まればおしまいにする（`finish` もこの端末が数える）。そのあと自分の位置を消す |
| タブを閉じた人を抜けた人にする | ホスト（`watchLeavers`） | ゲームの人の在室が消えた時刻をホストの端末が覚え、30秒たっても戻らなければ `r` に transaction（`mut.left`）。ホストが読み込み直すと数えなおし（30秒から）。ホストが切れている間は止まる |

## 接続・切断・再接続

リバーシと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | `r` に `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `r/players/{name}` を `remove()` |
| 全員 | 自分の `p/{name}`・`g/{name}` を `remove()`（切れた人が、おきている人の画面に止まったまま残らないように） |

- `.info/connected` が true になるたびに予約を張り直し、在室を書き戻す（3秒に1回まで。つながった時点でルームの値がまだなければ、最初の値が届いたときに張る）。同じ名前の在室が別の匿名IDのものだったら、張った予約を取り消してルームから外れる
- つながりなおしたら、止まったままでも自分の位置を送り直す（切れていた間に、予約で位置が消されているため）。切れている間は位置を送らない（SDK が書き込みをためて、ルームが消えたあとに位置だけを作りなおさないように）
- ゲーム中に切れた人は、その場から消える（位置の予約）。会議ではその人の票を待たず、一覧に「通信が切れた」。同じタブで読み込み直すと、同じ役で続きから（位置はテーブルのまわりから）
- ゲームの人の名前は、ほかの人（別の匿名ID）は使えない
- ホスト切断中、ゲストには共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`。ロボットと進行はホストの端末が動かすので、その間は止まる

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おしまいの画面のあとも自動削除しない（ホストが「待合室にもどる」で次の回へ）
- 削除経路: ①ホストの「ルームを閉じる」（ロボットと位置の送信を先に止め、`cancelRoomOnDisconnect()` をルートに await → ルートを `remove()`。`r`・`p`・`g` がまとめて消える。そのあと `r` のない `p`・`g` が残っていれば消す。ルームが消えたのを受け取った参加者も、同じ確かめをする） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、ルートへの transaction・`applyLocally: false`）
- 待合室にもどると `game` と `p`・`g` を消す

## 利用回数（stats.js）

「1回」は1ゲーム（はじめる〜おしまい）。数えるのは本体のプロジェクト。

| 項目 | 数えるとき・端末 |
|---|---|
| `room-create` | ルームができた（ホスト） |
| `start`・`players-{N}` | 「はじめる」（ホスト）。N は遊ぶ人（ロボットを含む・進行だけのホストは含めない） |
| `finish` | おしまいに進めた transaction を確定させた端末（`ended` で1ゲーム1回） |
| `again` | おしまいから「待合室にもどる」（ホスト）。途中でやめたときは数えない |

## 意図的な逸脱

- **別の Firebase プロジェクト**（上の節）。`RoomkRTDB.initFirebase` を使わない
- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る
- **ルームの下を `r`（状態）・`p`・`g`（位置）に分ける**。ルームの有無・期限切れは `r` で判断し、削除はルートで行う
- **ホスト以外もゲームを進める**: 自分の操作は自分の端末が transaction で書く。進行はホストが遅れたら、ほかの端末が代わる。`finish` は確定させた端末が数える
- **よく起きる操作は transaction でなく小さな場所への書き込み**（仕事の完了・投票）
- **みんなにみせる画面（`?watch=`）はない**。役と位置を隠すゲームなので、画面共有には進行役の画面を使う
- **端末なしの参加者は作らない**（役が見えてしまうため。進行役の画面を見て話し合いに加わる）
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **勝ち負けを出す**（隊員／ねむらせ屋のチームの勝ち負けだけ。点数・順位・成績は記録しない）
- **投票で選ばれた人に「ねむらせ屋だった／じゃなかった」を出す**（推理につなげるため。2026-10-26 オーナー確認）

## 入れない機能

- 音（通知音・効果音なし）
- チャット（話し合いは Zoom / Meet の声か、Metalife のチャット）

## 既知の制約（v1）

- 距離（ねむらせる・見つけた・仕事・スイッチ・テーブル）は押した端末の見え方で確かめる（DevTools で書きかえれば遠くからもできる。共通方針の性善説）。役も DevTools では見える
- 位置は1秒に3回までなので、ほかの人の動きは少しなめらかさに欠けることがある（補間でつないでいる）
- ホストが切れている間は、ロボットと進行（会議のしめきり・結果のあと・時間切れ）が止まる。ホストのタブが裏にあると、ブラウザがタイマーを遅らせる（1秒おき。Chrome は長く裏にあるタブを1分おきまで遅らせることがある）ので、ロボットの動きと票が遅れる。進行は、ほかの端末が3秒あとに代わる
- ホストが読み込み直すと、ロボットはテーブルのまわりから動きなおす（進めかけの仕事は最初から）
- タブを閉じた人が抜けた人になるまでの30秒の間は、その人はおきている人として数えたまま（会議の票だけは待たない）
- 仕事の完了は小さな書き込みなので、ミニゲームをおえた瞬間にほかの人が会議をひらくと、会議の最中に完了が入ることがある（進み具合が会議中に1つ増えるだけ。勝ちの判定は遊んでいる間にだけ行う）
- 仕事の完了の印を書いた直後に、ホストが待合室にもどしたり次の回を始めたりした場合、印は番号のちがう回として読み飛ばされる（数え漏れはその回だけ）
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（共通方針どおり、少なめに出る側の誤差）
- 実機のスマホ・タブレットでのスティックの操作感、本番のプロジェクトでの通信量は未確認（2026-10-26 時点）

## メンター向けの心得（画面には出さない）

- 端末のない子がいる回は、ホストを「進行だけ」にして、進行役の画面を画面共有する。進行役の画面には人の位置が出ないので、ねむらせ屋の動きはばれない。会議のときは、端末のない子にも「だれがあやしいと思う？」と聞いて話し合いに入ってもらう
- 投票で選ばれてねむった子には、「ねむっても仕事はつづけられるよ」と声をかける。ねむらせ屋だったことがばれた子も責めない（「うまくまぎれていたね」）
- はじめての回は、ロボットを入れてホストがひとりで1回遊んでみると、画面の流れが分かる
- 15分で時間切れになるので、長引いたら「あと何分」と声をかけて会議ボタンをうながすとよい
