# 好きなものマップ

## 目的・使用シーン

選ぶだけで「好き」を深掘りして、自分のマップを作るルーム型のツール。好きなジャンル（動物・ゲーム・食べもの など）を選び、その中の好きなもの（犬・猫／育成・パズル など）も選ぶと、名前を真ん中にしたマップが広がる。できたら1人ずつマップを出して見せあい、「きいてみよう」の質問をきっかけに話す。点数・順位・勝ち負け・投票はない。

参加する人は**それぞれの端末の画面で作る**。見せあいはホストの画面共有でも見られる。

2026-11-11 にオーナーの依頼（「選択式で好きなものを深掘りできるマップを作りたい。好きな動物は？と聞き、犬や猫など、ゲームでは育成系やFPSなど」）で `drafts/suki-mono-map/`（BroadcastChannel の試作）を作り、同日オーナーの「本体化してください」で本体化した。試作で決めたことの経緯は、この AGENTS.md を正本にする（drafts はリポジトリに入れていない）。

もとの「すきなことマップ」（`apps/sukina-map/`。自由入力のカードマップ。2026-07-30 に「すきタイプチェック」へ作り変え、いまはリダイレクトスタブ）とは別のツール。

## セッション条件（ツール一覧のカードと同じ）

値はツール一覧（`apps/index.html`）のカードと同じにする。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 2〜13人（ホスト＋参加12人まで。ほかに端末なしの参加者4人まで） |
| 目安時間 | 10〜20分 |
| 利用シーン | ひろば・サークルタイム・作戦会議 |
| 種類 | 話す・自分を知る（`talk`） |
| 話す量（`data-speech`） | `pick talk silent`（選ぶだけで作れる／見せあいで話す／選ぶだけで進み、ホストが代わりに作れるので声を出さずに参加できる） |
| 自分の話（`data-self`） | `center`（自分の好きなものを見せて話すのが中心） |

作戦会議（`sakusen`）の札は 2026-11-11 にオーナーの「作戦会議でも使えるようにして」で足した。話す量・自分の話の値は、画面と上の遊び方から読める事実で決めた（すきタイプチェック・バリューカードと同じ `center`）。

### 作戦会議（1対1）での使い方

アプリの作りは変えていない。次のどちらでも遊べる。

- **2人ともルームに入る**: メンターがルームをつくり、子どもがリンクで入る。2人ともマップを作って見せあう（ホストの「自分も作る」は入れたまま）
- **メンターの画面共有だけで遊ぶ**: 子どもが端末を使わないときは、メンターが「くわしい設定」の「端末なしの参加者を足す」で子どもの名前を足し、声やチャットで聞きながら代わりに作る。メンターがマップを作らないなら「自分も作る」を外す（1人でも「はじめる」を押せる）

## 技術スタック

Firebase Realtime Database + 匿名認証。分割ファイル（`index.html`・`app.js`（module）・`style.css`・`data.js`）。作成・参加・再接続・切断・退出・ルームのバーは `apps/tsunagete-story/` と同じ作り。`RoomkRTDB.initFirebase()`・`RoomkRTDB.now()`（サーバー時刻補正）・`copyRoomCode` / `copyRoomLink`・`RoomkQR`・howto・stats を使う。名前空間は `sukimonomap_rooms`（`database.rules.json` に 2026-11-11 オーナー承認で追加）。

| 項目 | 内容 |

| 深さ | 2段（ジャンル → その中の好きなもの） |

| 作る画面 | **マップだけの画面**。マップの「＋」を押すとポップアップで選ぶ（下の「画面の作り」）。3回作り直してこの形になった |
| 「FPS・シューティング」 | ゲームの選択肢に入れる（オーナーの例にあった。本体化のとき「そのまま残す」と決めた。ルートの「暴力・ホラー」の題材はふくらませない: 質問の文は「どんなところが好き？」などで、中身を聞きこまない） |

### 画面の作り（作る画面）

オーナーの声で3回作り直した（1回め「ボタンの押す順番がわからない」→ 3ステップの形／2回め「やり直したいときに消しにくい。マップから直接編集したい」→ マップ＋横のパネル／3回め「マップにプラスボタンをつけてポップアップ式がいい。右の選択ボタンもなくせる」→ いまの形）。

- 画面はマップと、その下の「マップを完成する」だけ（塗りの主ボタンはこれ1つ。せまい画面では下にとめる）
- 真ん中の名前から出ている **「＋ ジャンルを足す」** を押すと、ポップアップにジャンルの一覧が出る。選ぶとマップに足され、ポップアップはそのままそのジャンルの中身に変わる
- ジャンルごとに付く **丸い「＋」** を押すと、そのジャンルの中身を選ぶポップアップが出る（ジャンルそのものを押しても同じ）。札はもう一度押すと外れる
- 選択肢にないものは、札の並びのさいごの「自分で書く」（1ジャンル3つまで・12文字まで）
- マップの **好きなもの（× つき）を押す** と、その場で消える
- ジャンルごと消すのは、ポップアップの下の「『動物』をマップから消す」。中身を選んでいるときだけ「消す？」と確かめる
- ポップアップ（`<dialog>`）は「マップにもどる」・外側を押す・Esc で閉じる。せまい画面では下から出る
- 「マップを完成する」のあとも「選びなおす」でもどれる。できあがりの画面に「見せあいのときにみんなに出す」（はじめはオン）
- マップの点は `role="button"`・Tab で移れる・Enter／スペースで押せる。押すと図を描きなおすので、キーボードの位置は外れる（既知の制約）

### 見せあう

- ホストが「見せあいをはじめる」を押すと、1人ずつマップが大きく出る。順番は参加した順（端末なしの参加者はそのあと）。「みんなに出す」を外した人・何も選んでいない人は出ない
- マップの下の「きいてみよう」に、出ている人のマップから1つを選んで入れた質問が出る（`data.js` の `asks` 6種類。くわしく選んでいないときは「『ゲーム』だと、どんなのが好き？」）。ホストは「ほかの質問にする」で変えられる
- ホストの操作: 「つぎの人」（主）・「まえの人」・名前のボタン。さいごの人では主ボタンを置かず「はじめの人へ」。「もう一度作る時間にする」「おしまいにして待合室へ」は「そのほかの操作」にたたむ
- 「見せあいをはじめる」は、まだの人がいても押せる（そこまで選んだ分が出る）。ホストの分ができて全員そろったときだけ塗りの主ボタンになる

### 比べっこを出さない

「同じものを選んだ人」「人気のもの」「選んだ数」は出さない。重ならない子・少ない子だけが目立たないようにするため（ルート AGENTS.md「否定的な判定を、出した人・出された人と結びつけて目立たせない」）。この理由は画面・あそびかた・更新情報に書かない。

## 画面構成・status 遷移

`waiting`（待合室）→ `pick`（作る）→ `show`（見せあう。`show.idx` で何人め）→ ホストの「もう一度作る時間にする」で `pick`（マップは残し、`done` だけ外す。`seq` を1つ進める）／「おしまいにして待合室へ」で `waiting`（マップを消す）。

- はじめの画面: 入口の型 `.app-entry`（説明・「ルームをつくる」「ルームに参加する」）。絵は `apps/assets/illustrations/suki-mono-map.webp`（2026-11-11。真ん中のハートから、足あと・アイス・音符・星の丸がのびる絵）
- 作成・参加・ルームのバー（コードをコピー・リンクをコピー・QRコードを出す・退出する／ルームを閉じる）は rtdb.md の共通どおり
- 待合室: 参加する人・ルール（選べるジャンルの数）・「くわしい設定」（自分も作る・端末なしの参加者を足す）・「はじめる」。参加する人の画面には「いまのルール」の要約

## Firebase データ構造

```
sukimonomap_rooms/{code}
  status: 'waiting' | 'pick' | 'show'
  host, hostUid, hostConnected, hostDisconnectedAt
  settings: { hostPlays, maxGenres: 3 | 5 | 0（いくつでも） }
  round: はじめた回数, seq: その回で「作る」にもどった回数
  shown: その回で見せあいまで進んだか（finish を二重に数えないため）
  players: { 名前: { isHost, uid, joinedAt } }
  proxies: { 名前: { addedAt } }                 … 端末なしの参加者
  maps: { 名前: { r: 回, genres: [ジャンルのid], items: { ジャンルのid: [好きなもの] }, done, share } }
  show: { order: [名前], idx, ask: 質問の文 }
```

- ホストの操作（設定・端末なしの参加者・はじめる・見せあい・つぎの人・質問・作るへもどす・待合室へ）は、どれも `hostUid` を確かめるルームの transaction
- 自分のマップ（`maps/{名前}`）は、参加する人がルームの transaction で書く（status・回・`seq`・自分の在室の uid を確かめる。端末なしの参加者の分はホストだけ）。選ぶたびに送ると多いので 350ms まとめて送り、「マップを完成する」「選びなおす」「みんなに出す」はすぐ送る
- 作っている途中のマップは各端末が持ち（`state.picks`）、ルームの分は読み込み直し・再接続・「もう一度作る時間」のときだけ読みなおす
- ほかの人の作りかけのマップは参加する人の端末にも届く（性善説。作る画面には出さない）
- RTDB は空の配列を持てないので、中身を選んでいないジャンルの `items` は無い。読むときは `cleanMap` で空として読む

## ホストも作るか・途中参加・端末なしの参加者

- **ホストも作る（`settings.hostPlays`）: 初期値は「作る」**。秘密の情報がないので、ホストも同じ条件で作れる。進行だけのときは待合室で「進行役」の印、マップを持たない
- 作る人が1人いれば始められる（ホスト1人＋端末なしの参加者だけでもよい）
- **途中参加**: どの status でも参加できる。作っている途中で入った人はそのまま作れる。見せあいの途中で入った人は見るだけ（順番は見せあいをはじめたときに決まる）
- **端末なしの参加者を作る**: ホストが待合室の「くわしい設定」→「端末なしの参加者を足す」で名前を足す（4人まで。ニックネームの規則どおり・ほかの人と同じ名前は不可）。作る画面の上の「だれの分を作る？」で切りかえて、ホストが代わりに作る。印（「端末なし」）と「外す」はホストの画面にだけ出す。在室（onDisconnect）を持たず、いつも作る人に数える
- マイクを使わない子は、選ぶだけで作れる。見せあいで出したくない子は「見せあいのときにみんなに出す」を外せる

## メンター向けの心得（画面には出さない）

- 「きいてみよう」は話のきっかけ。答えたくなさそうなら「ほかの質問にする」か「つぎの人」で進める。理由を聞きこまない
- マップの大きさ（選んだ数）を比べる声かけをしない
- 見せあいに出さなかった子に、その場で理由をたずねない

## 切断時の挙動・削除

- ホスト切断: `hostConnected=false`・`hostDisconnectedAt`。ゲストには「ホストの戻りを待っています」を出し、TTL（`ORPHAN_TTL_MS` = 2分）を過ぎたら期限切れとして消す
- ゲスト切断: `players/{名前}` の `onDisconnect().remove()`。戻ったときは同じ名前で在室を足し直す（マップは名前で持っているのでそのまま続く）。切れた人・退出した人のマップは残り、見せあいの順番を決めるときは在室の人と端末なしの参加者だけを並べる
- 再接続: sessionStorage（`sukimonomap_session`）で同じルームに戻る
- 通信が切れているあいだも、作る画面は止まらずに選べる（各端末が作りかけを持っている）。つながりなおしたら、在室をもどしたあとで、いまのマップをルームに送りなおす（`resendDrafts`。切れているあいだの書き込みは、もどったときの処理の順番しだいで届かないことがあるため。2026-11-11）
- ポップアップをひらいているあいだにホストが切れたら、ポップアップを閉じて「ホストの戻りを待っています」を出す（`<dialog>` はいちばん手前に出るので、ひらいたままだと待つ画面が後ろに隠れる。2026-11-11 修正。選んだものは残る）
- メッセージ（「うまく送れなかったよ」など）は、ひらいているポップアップがあればその中へ移して出す（`app.js` の `toast`。2026-11-12）。共通の `showToast` は body の末尾に出すので、スマホの幅で画面の下まで広がるポップアップ（`showModal`）に隠れていた。ポップアップの出るときの動きは `backwards`（`both` だと動きのあとも位置の基準がポップアップになり、PC の幅でメッセージがポップアップの中の下端に出る）
- **自動削除は rtdb.md「公認バリアント: ふりかえり画面滞在中は削除しない」を採用**: 見せあいのあとも続けて作る・待合室へもどることが多いので、終了30秒後の自動削除はしない。(1) ホストの「ルームを閉じる」 (2) ホスト切断の TTL (3) 次回アクセス時の期限切れ掃除 の3経路で消す

## 利用回数

「1回」は、待合室で「はじめる」を押してから見せあいまで。

| 項目 | 数えるとき |
|---|---|
| `room-create` | ルームができた |
| `start`・`players-{N}` | ホストの「はじめる」が確定した（N は作る人の人数。端末なしの参加者を含め、進行だけのホストは含めない） |
| `finish` | その回ではじめて「見せあいをはじめる」が確定した（「もう一度作る時間」のあとの2回めは数えない） |
| `again` | 「おしまいにして待合室へ」が確定した（次の `start` は、はじめたときに数える） |

## 特有のルール・制約

- 中身は `data.js`（ジャンル12・各10〜13こ、質問6）。作品名・商品名は入れず、種類だけにする。学校・勉強・恋愛・こわい話につながる言葉は入れない
- 同じ言葉が別のジャンルに入っているのは意図どおり（「ダンス」が音楽・スポーツ・動画、「料理」が動画・つくる など。`scripts/content-audit.mjs` の `CROSS_VARIANT_EXPECTED_TOOLS`）。同じジャンルの中の重複と空の言葉は `node scripts/content-audit.mjs` が止める
- マップの枝・札の色はジャンルを見分けるための色（`data.js` の `color`・`pale`・`ink`）で、ボタンには使わない。選んだ印と主ボタンは共通のアクセント色
- 子どもが自由に書ける欄（「自分で書く」）がある。合わない言葉が入ったときは、その子の番を「つぎの人」で進める（1つだけ隠す操作はない）
- 選んだものは保存しない。待合室にもどる・ルームを閉じると消える
- 配慮の理由は画面・あそびかた・更新情報に書かない
- 音は鳴らさない
- 説明スライド（`slides.html`・14枚）は `apps/kotoba-tantei/slides.html` の型。あそびかたの「説明スライドを見る」とツール一覧のカードから開ける。画面の作りやボタン名を変えたら、スライドの文も合わせる
- 検証: `tests/suki-mono-map/`（エミュレーター＋Playwright の E2E。`e2e1` 75項目: ホスト・参加者2人・端末なしの参加者・途中参加の通し／`e2e2` 38項目: ホストと参加する人の切断・復帰・2分の期限切れ／`e2e3` 27項目: 通信だけ落とす形の切断と、実時間で2分待つ期限切れ／`e2e4` 40項目: 接続が閉じられないまま通信だけ止まる形と、作成・参加の送信したあとの切断／`slides` 27項目: 説明スライドと発表者ウィンドウ。2026-11-11）
- **スマホの幅（マップの場所が 520px 未満）では、マップを上から下へ枝をのばす形で描く**（2026-11-11 オーナー「スマホでマップの文字を大きく」。放射に広げると、ジャンル5つで文字が9〜10pxになった）。名前を左上に置いて幹を1本おろし、ジャンルは幹から右へ、好きなものはジャンルの下に折り返して並べる。1目盛り＝1px で描くので文字は実寸（ジャンル18px・好きなもの16px）、高さは中身のぶんだけのびる。作る画面・できあがり・見せあいのどれも同じ。PC の幅は放射のまま。幅が変わったら描きなおす（`drawMap` の `tree`）
- 未確認（2026-11-11 公開時点）: 本番のサーバーが止まった接続に気づくまでの時間、 実際の日本語入力（Mac・iPad のフリック）での「自分で書く」、Safari、実機のスマホでの見え方
