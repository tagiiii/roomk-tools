# ピッタリメーター 仕様書

## 目的・使用シーン

Wavelength 風の「感覚のものさし」得点ゲーム。出題者が出すヒントを頼りに、各自が自分のメーター（0〜100）でターゲットの位置をぴったり当てる。ターゲットに近いほど高得点で、個人得点のランキングを表示する。

**core value: ヒントはアプリ内のテキスト入力なので、マイクで話す子もチャット参加の子も対等に出題者になれる。**

- 対象: 小学校中学年〜中学生
- メンター（ホスト）が Zoom / Meet で画面共有しながら進行する
- **個人得点制・順位表示あり**（2026-08-18 ユーザー指示でチーム得点制から変更。ピタハメと同じく、競争を意図的に残す例外案件）

> 原作「Wavelength」にインスパイアされた派生ルールのオンライン版。
> 名称・演出・ルール細部をオリジナルに変更している。

## 画面構成・フロー

```
TOP（screen-top）
 ├── ホスト → ニックネーム入力＋「自分も回答者として遊ぶ」チェック（hostPlays・既定オフ）
 │            → ルーム作成・待機（screen-host-setup）
 └── ゲスト → ニックネーム＋コード入力 → 待機（screen-waiting）
                     ↓（ホストが「ゲームを始める」/ ゲスト2〜8人）
           ヒント入力（screen-hinting）
             全員: ものさし（軸ペア）表示
             出題者: ターゲット位置つきメーター + ヒント入力（1〜20文字）
             それ以外（進行専任ホスト含む）: 「〇〇さんが考え中…」
                     ↓（出題者が「ヒントを送る」）
           メーター合わせ（screen-guessing）
             全員: ヒント表示
             出題者以外のプレイヤー: スライダーを動かして「決めた」（「選び直す」も可）
             出題者: 自分のターゲットを見ながら待機
             ホスト: 進行状況 + 「結果発表」（1人でも決定していれば押せる。
                     hostPlays 時は自分のスライダー/出題UIも重ねて表示、案内文はたたむ）
                     ↓
           結果発表（screen-reveal）
             ターゲット + 得点ゾーン + 全員の予想位置（名前つき）を1本のメーターに表示
             個人得点ランキング（このラウンドの +◯ / 出題 / — つき）
             ホスト: 「次のラウンドへ」（次の出題者・新しい軸）/ 「終わる」
                     ↓
           きょうのきろく（screen-done）
             1位の発表・最終ランキング・ラウンド数 → 30秒後にルーム自動削除
```

- ホスト＝メンター。**既定では回答に参加しない**（players に isHost:true で存在するが turnOrder に含めない）
- **hostPlays: true のとき（2026-08-18追加）**: ホストも回答・出題ローテーション・得点に入る。回答だけの参加だと出題番のぶんホストの得点機会が多くなり不公平なため、turnOrder にも必ず入れる。進行ボタン（結果発表・次のラウンドへ・終わる）は引き続きホストのみ。開始条件はゲスト2人以上のまま変えない
- 出題者は turnOrder（既定はゲストのみ、hostPlays 時はホスト込み）で毎ラウンド順番にローテーション（ゲーム開始時にシャッフル確定）
- **ホスト画面は画面共有されうるため、既定ではターゲットをホストに見せない**（出題者にのみ表示）。**hostPlays でホストが出題者の回はホスト画面にターゲットが出る**ので、画面共有しながら進行するメンターはチェックを入れないこと（既定オフはこのため）

## status 遷移

```
waiting → hinting → guessing → reveal ─┬→ hinting（次ラウンド）
                                       └→ done（30秒後にルーム削除）
```

| status | 説明 |
|--------|------|
| `waiting` | ロビー。このフェーズのみ新規入室可 |
| `hinting` | 出題者がターゲットを見てヒントをテキスト入力 |
| `guessing` | 出題者以外のゲストがメーターを動かして「決めた」 |
| `reveal` | ターゲットと全員の予想を公開。各回答者の個人得点を加算 |
| `done` | きょうのきろく表示。30秒後にルーム削除 |

## Firebase データ構造

```
pittari_rooms/{roomCode}/
  ├── host:                string          # ホストのニックネーム
  ├── hostConnected:       boolean
  ├── hostDisconnectedAt:  number | null
  ├── hostPlays:           boolean         # ホストも回答者として遊ぶか（作成時に確定・以後不変）
  ├── status:              string          # 上記 status 参照
  ├── scores/                              # 個人累計得点（ゲーム開始時に turnOrder 全員を 0 で初期化）
  │    └── {nickname}:     number          # players と別に room 直下へ持つ（ゲスト切断で消えないように）
  ├── roundsDone:          number          # 発表まで終えたラウンド数
  ├── usedAxes:            number[]        # 使用済み軸インデックス（使い切ったらリセット）
  ├── turnOrder:           string[]        # ゲスト名の出題順（開始時にシャッフル確定・以後不変）
  ├── turnIndex:           number          # turnOrder 上の現出題者位置
  ├── players/
  │    └── {nickname}/
  │         ├── isHost:   boolean
  │         ├── guess:    number | null    # 0〜100
  │         └── decided:  boolean
  └── round/
       ├── number:     number              # 1始まり
       ├── axisIndex:  number              # AXES 配列のインデックス
       ├── target:     number              # 0〜100 のランダム値（UIレベルで出題者のみに表示）
       ├── speaker:    string              # 出題者ニックネーム
       ├── hint:       string | null       # 1〜20文字
       ├── results:    { [nickname]: number } | null   # 発表時に確定した予想スナップショット
       └── points:     { [nickname]: number } | null   # 発表時に確定した各回答者の獲得点スナップショット
```

### データ操作の注意点

- **ルーム作成・参加・ゲーム開始**: `transaction()` で原子的に確定（コード衝突・status 判定・重複ニックネーム・満員判定を同一 transaction 内で行う）
- **ヒント提出**: 出題者が `round/hint` と `status: 'guessing'` を同時 `update()`
- **きめた**: 各ゲストが自分の `players/{nick}` に `guess` / `decided` を書くだけ（競合なし）
- **けっか発表**: ホストが最新スナップショットを `get()` → 決定済みの予想を `round/results`、各自の獲得点を `round/points` に固定し、`scores/{nickname}` へ加算（プレイヤー切断後も表示が崩れないようスナップショットする）。scores を書くのはホストだけなので transaction は不要（単一ライター）
- **target の秘匿は UI レベル**（共通規約の性善説方針どおり。DevTools での確認は許容）

## 切断時の挙動

| 役割 | 挙動 |
|------|------|
| ホスト切断 | `hostConnected=false` + `hostDisconnectedAt=ServerValue.TIMESTAMP`。ゲストにオーバーレイ + カウントダウン表示。ORPHAN_TTL_MS（2分）超過で期限切れ扱い・削除 |
| ゲスト切断 | `onDisconnect().remove()` でそのプレイヤーデータのみ削除。**累計得点は room 直下の `scores/` にあるため消えない**（再接続すれば継続） |
| **出題者切断（hinting 中）** | ホスト画面に「出題者を変える」ボタンが自動表示される。押すと **新しい軸・新しいターゲット** で次のプレイヤーに出題者を交代する（ラウンド番号は据え置き）。切断した子のターゲットが漏れる心配をなくすため、軸ごと引き直す。hostPlays でホスト自身が出題者のときの切断は、ホスト切断フロー（オーバーレイ + TTL）がそのまま適用されるため個別対応不要 |
| 出題者切断（guessing 以降） | ヒントは提出済みのため、そのままラウンドを続行できる（対応不要） |

- 再接続: sessionStorage `pittari_session` から復元。ゲストはプレイヤーデータが消えていれば `{ isHost:false, guess:null, decided:false }` で再追加（turnOrder は不変なので出題順は保たれる）
- ゲーム中の同名再参加（別タブ・別端末）も再接続として扱う。ただし**ゲストの名前だけ**で、ホストと同じ名前での入室は `waiting` 中と同じく「そのニックネームはすでに使われています」で拒否する（`hostPlays` が true でも同じ）
- TTL 判定は `RoomkRTDB.now()` / `RoomkRTDB.isRoomExpired()` でサーバー時刻補正
- 未決定のゲストがいてもホストは「結果発表」で進行できる（1人以上決定が条件）

## 得点ルール（個人得点制）

各回答者（出題者・ホスト除く）について、ターゲットとのずれで点を出し、**個人の累計得点** に加算する。

| ずれ | 点 |
|------|----|
| 5以内 | 3点 |
| 12以内 | 2点 |
| 25以内 | 1点 |
| それ以上 | 0点 |

- 結果画面ではメーター（全員の予想位置・名前つき）の下に**個人得点ランキング**を表示する。行ごとに「◯位・名前・このラウンドの増分・累計点」
- ランキングのタイは **同順位・次をとばす 1,1,3方式**（minna-ranking と同じ）。1位の行は金色ハイライト
- ラウンド増分の表示: 得点した回答者は `+◯`（0点も `+0`）／出題者は `出題`／未決定は `—`
- **出題者はそのラウンドは加点なし**。出題は turnOrder で全員に順番に回るため、周回すれば公平（ヒントの「うまさ」は採点しない）
- **hostPlays 時はホストも同じルールで加点・ランキングに載る**（出題番も回ってくる）。進行専任（既定）のときはランキングに載らない
- 未決定のまま発表になった子は 0点扱いではなく **集計外**（メーターにも表示しない。累計はそのまま）
- きょうのきろく（done）では「1位は ◯◯さん！」と最終ランキングを表示する。全員同点なら「みんな同点！」
- 2026-08-18 まではチーム得点制（合計のみ・個人得点/順位の表示なし）だった。個人得点制＋順位表示への変更はユーザー判断（チーム得点は廃止）

## 共通規約からの逸脱の明文化

- **個人得点・順位を表示する**: room-K の多くのアプリは個人の優劣を出さない設計だが、本アプリは 2026-08-18 のユーザー判断で競争を意図的に採用（ピタハメと同系の例外）。安全側へ勝手に戻さないこと
- **status 更新をホスト以外が1箇所行う**: 出題者のヒント提出時に `hinting → guessing` を出題者クライアントが書く（ホスト操作を挟むと進行が1テンポ遅れるため。他の遷移はすべてホストのみ）
- **ホストは既定で回答に参加しない**: players に isHost:true で含まれるが、turnOrder・回答・得点集計から除外（メンター＝ファシリテーター専任のため）。作成時の「自分も回答者として遊ぶ」チェック（hostPlays）でのみ参加に切り替わる（2026-08-18 実機フィードバック「ルームを作った人がメーターを動かせない」対応）
- **最小人数はゲスト2人**（ホストを含めた総人数ではない）。最大ゲスト8人（join transaction で拒否）
- **scripts/lint.sh の RTDB_HTML_FILES に未登録**: 実装時の指示で scripts/lint.sh 編集が禁止されていたため。次回 lint.sh を触る機会に `apps/pittari-meter/index.html` を追加すること（XSS / CSS 系チェックは全アプリ対象なので適用済み。viewport / TTL 規約は実装済み）
- **apps/index.html（ポータル）に未登録**: 同じく実装時の指示による。公開時にカード追加が必要

## メンター向け進行のコツ

（画面には出さない。ここにだけ書く）

- 最初のラウンドは「ものさし」の読み方を口頭で補足するとよい。「左が0、右が100。ヒントの言葉がどのへんか、みんなで合わせるゲームだよ」
- 比喩の説明は最初の一度だけでよい。以降はボタンの文言（決めた・次へ）どおりに進む
- ヒントが思いつかず止まっている子には「食べもの・場所・キャラ、なんでもOK」と選択肢を広げる声かけを。急かさない
- 「結果発表」は全員決定を待つのが基本だが、迷って動けない子がいたら「今の位置でいったん出してみようか」と促してから締め切る（未決定でも進められる）
- 結果発表では 1位や +3 のぴったり賞を明るく拾いつつ、順位が下の子を話題にしない。ヒントの面白さも拾う。「にくまん、いいヒントだったね」
- 順位で空気が重くなったら「出題の回は点が入らないから、まだ逆転できるよ」とラウンド数の残りに目を向けさせる
- チャット参加の子が出題者のときこそこのツールの本領。ヒント入力をゆっくり待つ
- 軸が抽象的で難しそうなら、次のラウンドで「さっきより簡単な軸が来るかも」と気楽さを保つ（軸はランダム）
- 全員が1回ずつ出題者を経験したあたり（ゲスト人数＝ラウンド数）が「終わる」の目安
