# ことばダッシュ！

## 目的・使用シーン

言葉が1つ、画面を一瞬で走りぬける。なんて書いてあったかを入力して当てるルーム型の個人戦。1〜13人、1回5〜10分。ひろば・コトバであそぼ！・サークルタイム。

参加する人は**それぞれの端末の画面で遊ぶ**。動きはそれぞれの画面で作るので、画面共有越しに見るとカクついて読めない。

2026-11-09 にオーナーの依頼で `drafts/kotoba-dash/`（BroadcastChannel の試作）を作り、同日オーナーの「本番に移して」で本体化した。試作で決めたことの経緯は、試作の README（drafts はリポジトリに入れていない）ではなく、この AGENTS.md を正本にする。

## セッション条件（ツール一覧のカードと同じ）

値はツール一覧（`apps/index.html`）のカードと同じにする。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 1〜13人（ホスト＋参加12人まで） |
| 目安時間 | 5〜10分 |
| 利用シーン | ひろば・コトバであそぼ！・サークルタイム（2026-11-09 オーナー） |
| 種類 | ことばのゲーム（`kotoba`） |

## 技術スタック

Firebase Realtime Database + 匿名認証。分割ファイル（`index.html`・`app.js`（module）・`style.css`・`data.js`）。`RoomkRTDB.initFirebase()`・`RoomkRTDB.now()`（サーバー時刻補正）・`copyRoomCode` / `copyRoomLink`・`RoomkQR`・howto・stats を使う。名前空間は `kotobadash_rooms`（`database.rules.json` に 2026-11-09 オーナー承認で追加）。

## 遊び方（ルール）

### 1問の流れ

1問めは 3・2・1（3.5秒）、2問めからと「もう一回流す」は「よーい…」（1.5秒）→ 言葉が1回走りぬける → こたえる欄が出る（走っているあいだは入力できない。見ながら写せないように）→ みんながこたえる・こたえる時間になる・ホストが「待たずにこたえを出す」のどれかで、さっきの言葉がゆっくり（3倍・最低2秒）もう一度流れて、こたえが出る。

- 流す時刻（`q.showAt`）と、こたえが出た時刻（`q.revealAt`）はサーバー時刻。各画面は `RoomkRTDB.now()` とくらべて、自分で言葉を動かす（動きは通信しない）
- 画面が裏に回ってタイマーが遅れても、走りおわる時刻を過ぎていれば終わったことにする（`catchUpFlow`。こたえが送れなくなる不具合を試作で見つけて直した）

### はやさ（`travel` = 言葉が画面を走りぬける時間）

| はやさ | 言葉 | travel |
|---|---|---|
| ゆっくり | 4〜5文字（`data.js` の `middle`） | 1.4秒 |
| ふつう（初期値） | `middle` と6文字以上（`long`） | 0.9秒 |
| はやい | `long` | 0.55秒 |

2026-11-09 オーナー「スピードが遅すぎる」でおよそ半分に、「もう少し長くていい」で言葉を4文字以上に（2〜3文字の言葉はやめた）。言葉はたくさんの中からランダム（ホストが言葉を決める機能は、入力に時間がかかるので同日オーナー判断でやめた）。

### 問題の種類（2026-11-09 オーナーが4つとも入れると決めた）

| 種類 | 流れ方 | こたえ方 |
|---|---|---|
| ことば（`plain`） | 右から左へ | 入力 |
| 逆走・ななめ（`dir`） | 左から右・下から上・右下から左上のどれか | 入力 |
| どっちが先？（`order`） | 同じなかまの言葉が2つ、続けて | 2つから選ぶ |
| どのなかま？（`cat`） | 1つ | なかまを3つから選ぶ |
| にせもの入り（`fake`） | ★のついた言葉1つと、形の似たほかの言葉2つが、3つの高さで少しずつずれて | ★の言葉を3つから選ぶ |
| かくれ文字（`pieces`） | 3文字以上の言葉が1文字ずつバラバラの高さで | 入力 |

- ホストは待合室の「くわしい設定」で、出す種類をいくつでも選べる（初期値は全部。1つは残す）。「ことば」を選んでいれば1問めは必ず「ことば」、そのあとは同じ種類が続かない
- **選択肢とにせもの入りの言葉は、本当にある言葉だけ**から選ぶ（同じ文字の種類・長さの近い言葉から、同じ位置に同じ文字・形の似た文字があるほど似ているとみなす）。2026-11-09 オーナー「選択肢がなんとなく言葉になっている文字で予想ができる」。1文字変えた言葉でない文字列は混ぜない
- にせもの入りの本物は、色に加えて★と太い枠でも見分けられるようにする（色だけに頼らない）

### こたえる

- 入力はひらがな・カタカナ・全角半角のちがいを同じとみなす（NFKC → カタカナをひらがなに）。それ以外はぴったり同じで正解
- 日本語の変換中の Enter は確定だけにする（`compositionstart/end`）
- **ヒント**（入力の問題だけ・自分の画面だけ）: 「ヒントを見る」を押すたびに、1段め 何文字か（□□□□）、2段め 最初の文字、3段め 最後の文字。ヒントを見ても当たりの数は同じで、見たかどうかはどこにも送らない。もう一回流しても消えない。2026-11-09 オーナー「基本的には入力で答える。選んで答えるではなくヒントを見れるようにする」（その前の「入力／選んでこたえる」の切りかえはやめた）
- 「パス」はだれでも押せる
- こたえは `answers/{問題番号}/{名前}` に `{ ok, pass }` だけを書く（入力した文字は送らない）。同じ問題に二度は書かない（transaction）
- こたえるあいだは流れる場所を低くたたんで、入力欄とヒントを上に寄せる（スマホのキーボードで隠れないように）
- こたえた人には「こたえたよ。あと◯人を待っているよ」。だれがまだかは出さない

### こたえる時間・つぎの問題へ（ホストの「くわしい設定」）

- こたえる時間: 決めない／10秒／20秒（初期値）／30秒。言葉が流れおわってから数え（`q.deadline`）、みんなの画面に「のこり◯秒」とバー。時間になるとホストの画面がこたえを出す。こたえていない人はそのまま。もう一回流すと数えなおす
- つぎの問題へ: 自動で進む（初期値。ゆっくり流しおえて3秒後、`q.nextAt`）／ホストが押す。自動のときもホストは「とめる」で止められ、そのあとは「つぎの問題へ」で進む
- 時間で進む処理はホストの画面だけが行う。ホストが切断している間は進まない

### 結果（個人戦）

2026-11-09 オーナー「個人戦でいい」（試作は「みんなで◯こ」の協力だった）。

- 遊んでいるあいだは、自分の画面に「あなた ◯こ あたり」だけを出す
- おしまいに「あなたは◯こ当てたよ」（0このときは出さない）と、「当てた数」に一人ずつの数を**多い順**に並べる。**順位の数字はつけない**（2026-11-09 オーナー決定）。**1こも当たらなかった人は並べない**（ルート AGENTS.md「0点の人を並べない」）。だれも当たらなかったときは「こんどは、もう少しゆっくりにしてみよう」
- 1問ごとに何人当てたかは出さない。結果の言葉の一覧は、自分が当てた言葉だけ色を変える
- 当てた数（`hits/{名前}`）は、こたえを出す transaction でホストが数える。退出した人の数も結果に残す

### 画面と文字の大きさ・ボタン

- 2026-11-09 オーナー「なるべく画面や文字は大きく」: 流れる場所 360px（スマホ 260px）、流れる言葉 4rem（スマホ 2.6rem）、入力欄 2rem など
- 2026-11-09 オーナー「重要度がわからないのでジャンプ率でわかりやすく」: いちばん押すもの（こたえる・はじめる・つぎの問題へ・もう一回）は大きく（`kd-btn-main`）、「待たずにこたえを出す」は中くらい（`kd-btn-mid`）、補助（ヒントを見る・もう一回流す・とめる）は小さく（`kd-btn-sub`）、パスは文字だけ（`kd-btn-text`）
- 音は鳴らさない

## 画面構成・status 遷移

`waiting`（待合室）→ `q`（問題。`q.idx` で何問め）→ `result`（結果）→ ホストの「もう一回（待合室へ）」で `waiting`。

- はじめの画面: 入口の型 `.app-entry`（絵・説明・「ルームをつくる」「ルームに参加する」）
- 作成・参加・ルームのバー（コードをコピー・リンクをコピー・QRコードを出す・退出する／ルームを閉じる）は rtdb.md の共通どおり
- 待合室: 参加する人・「自分も遊ぶ」（ホストだけ）・ルール（はやさ・問題の数を上に、問題の種類・こたえる時間・つぎの問題へは「くわしい設定」にたたむ）・「はじめる」。参加する人の画面には「いまのルール」の要約

## Firebase データ構造

```
kotobadash_rooms/{code}
  status: 'waiting' | 'q' | 'result'
  host, hostUid, hostConnected, hostDisconnectedAt
  settings: { hostPlays, speed, count, kinds: [...], limit, auto }
  game: はじめた回数
  qs: [ { kind, input, answer, reveal, hint, prompt, options?, sprites: [ { text, path, lane, t0, dur, small?, real? } ] } ]
  q: { idx, lead: 'count' | 'ready', showAt, deadline, revealed, revealAt?, nextAt?, hold? }
  inRound: { 名前: true }          … いまの問題にこたえる人
  answers: { 問題番号: { 名前: { ok, pass } } }
  hits: { 名前: 当てた数 }
  players: { 名前: { isHost, uid, joinedAt } }
```

- 問題は「はじめる」の transaction でホストが全部作って書く。言葉・こたえは参加する人の端末にも届く（性善説。画面には流れおわるまで出さない）
- ホストの操作（設定・はじめる・もう一回流す・こたえを出す・とめる・つぎへ・待合室へ）は、どれも `hostUid` を確かめるルームの transaction

## ホストも遊ぶか・途中参加・端末のない参加者

- **ホストも遊ぶ（`settings.hostPlays`）: 初期値は「遊ぶ」**。ホストの画面にこたえは出ない（流れおわるまで出さない）ので、ホストも同じ条件で遊べる。進行だけのときは待合室で「進行役」の印、人数・こたえる人・当てた数の対象にしない
- 遊ぶ人が1人以上いれば始められる（ホストひとりでも遊べる）
- **途中参加**: どの status でも参加できる。問題の途中で入った人はその問題は見るだけで、ホストが「つぎの問題へ」進めたときに `inRound` に入る（2026-11-09 オーナー承認の改善）
- **端末のない参加者は作らない**（2026-11-09 オーナー判断）。一瞬で走りぬける言葉を自分の画面で見て打つゲームで、画面共有越しでは動きがカクついて読めないため
- 声を使わないゲームなので「ひとこと」は持たない

## 切断時の挙動・削除

- ホスト切断: `hostConnected=false`・`hostDisconnectedAt`。ゲストには「ホストの戻りを待っています」を出し、TTL（`ORPHAN_TTL_MS` = 2分）を過ぎたら期限切れとして消す
- ゲスト切断: `players/{名前}` の `onDisconnect().remove()`。戻ったときは同じ名前で在室を足し直す（遊んでいる途中でも。`inRound`・`answers`・`hits` は名前で持っているのでそのまま続く）
- 再接続: sessionStorage（`kotobadash_session`）で同じルームに戻る
- **自動削除は rtdb.md「公認バリアント: ふりかえり画面滞在中は削除しない」を採用**: 結果のあとも続けて遊ぶ（「もう一回」）ことが多いので、終了30秒後の自動削除はしない。(1) ホストの「ルームを閉じる」 (2) ホスト切断の TTL (3) 次回アクセス時の期限切れ掃除 の3経路で消す

## 特有のルール・制約

- 言葉は `data.js`（`middle` 130語・`long` 80語・`cats` 5なかま×14語・`similar` 形の似た文字の組）。学校・こわい・恋愛につながる語は入れない。足すときは `node scripts/content-audit.mjs` で同じアプリ内の重複（ひらがなとカタカナの同じ言葉も）がないことを確かめる
- 配慮の理由は画面・あそびかた・更新情報に書かない
- 未確認（2026-11-09 公開時点）: 実際の日本語入力（Mac・iPad のフリック）での入力、Safari
