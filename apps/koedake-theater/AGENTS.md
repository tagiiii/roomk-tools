# こえだけシアター 仕様書

## 目的・使用シーン

「はぁって言うゲーム」風の、声だけ演技ゲームのオンライン版。
短いセリフ（「えー」「まじで」など）を、秘密のシチュエーション通りの気持ちで**声だけで**演技し、
他の参加者が「どのシチュエーションか」を丸数字①〜⑥から当てる。

- ホスト＝メンター（ファシリテーター）。**初期値は進行だけ**（演技・投票に参加しない）。待合室の「自分もプレイヤーとして参加する」にチェックすると、ホストも演じる人の候補・当てる側に入る（後述「ホストの参加」）
- 遊ぶ人2〜8人（ホストが進行だけならゲスト2〜8人）。メンターが Zoom / Meet / Metalife で画面共有しながら進行する
- **演者は立候補制**。声を出したい子が主役になり、聞き専・チャット参加の子は「当てる側」で対等に活躍できる
- 当てた人にも演者にも点が入る協力寄りの設計（伝わるほど演者も嬉しい）

> 原作「はぁって言うゲーム」にインスパイアされた派生ルールのオンライン版。
> 名称・お題・演出・得点ルールをオリジナルに変更している。

## 画面構成・フロー

```
TOP（screen-top）
 ├── ホスト → ニックネーム入力 → ルーム作成・待機（screen-waiting）
 └── ゲスト → ニックネーム＋コード入力 → 待機（screen-waiting）
                     ↓（ホストが「ゲームスタート」/ 遊ぶ人2〜8人）
           えんじる人えらび（screen-casting）
             全員: お題カード（セリフ1つ＋シチュエーション①〜⑥）を表示
             ホスト: 遊ぶ人の一覧から演者を選択（「ランダムに選ぶ」あり）→「きめた」
                     ホストも遊ぶならホスト自身も候補に入る
             ゲスト: 「やってみたい人は、声かチャットで教えてね」
                     ↓
           えんぎ中（screen-acting）
             演者だけ: 「きみのシチュエーションは ③ ○○○」（ランダム割り当て）
                     ホストが演者のときは折りたたみ（タップで表示）で、ふだんは見せない
             全員: セリフ＋シチュエーション一覧
             ホスト: 「投票へ」/「演じる人を選び直す」
                     ↓
           とうひょう（screen-voting）
             演者以外の遊ぶ人: ①〜⑥から選んで「きめた」（ホストも遊ぶならホストも投票する）
             演者: 自分のシチュエーションを見ながら待機（ホストが演者なら折りたたみ）
             ホスト: 投票状況を見て「結果を見る」（未投票がいても進められる）
                     ↓
           けっか（screen-reveal）
             正解のシチュエーション・各自の投票・当たった人・累計ポイントを表示
             ホスト: 「次のラウンドへ」（別カード・演者選び直し）/「終わる」
                     ↓
           おしまい（screen-done）
             ポイント一覧を控えめに表示。30秒後にルーム自動削除
```

## status 遷移

```
waiting → casting → acting → voting → reveal ─┬→ casting（次のラウンド）
                      ↑ ↓（えらびなおし）        └→ done（30秒後にルーム削除）
                    casting
```

| status | 説明 |
|--------|------|
| `waiting` | ロビー。このフェーズのみ入室可 |
| `casting` | お題カードを全員に表示し、ホストが演者を選ぶ |
| `acting` | 演者がマイクでセリフを演技。演者にだけ正解シチュエーションを表示 |
| `voting` | 演者以外の遊ぶ人が①〜⑥に投票 |
| `reveal` | 開票結果・得点を表示 |
| `done` | 終了画面。ホスト端末が30秒後に `roomRef.remove()` |

status の更新はすべてホスト操作起点で、`transaction()` で前状態を検証してから遷移する。

## Firebase データ構造

```
koedake_rooms/{roomCode}/
  ├── host:                string          # ホストのニックネーム
  ├── hostConnected:       boolean         # 切断検知用
  ├── hostDisconnectedAt:  number | null   # 切断時のタイムスタンプ（ms）
  ├── status:              string          # 上記 status 参照
  ├── settings/
  │    └── hostPlays:      boolean         # ホストもプレイヤーとして遊ぶか（作成時 false。キーなしの旧ルームも false 扱い）。
  │                                        # 待合室（status 'waiting'）の transaction でだけ変える
  ├── players/
  │    └── {nickname}/                  # 進行だけのホストも players に残る（再接続・表示のため）。演者・投票・得点の対象外
  │         ├── isHost:  boolean
  │         ├── score:   number            # 累計ポイント
  │         └── vote:    number | null     # 今ラウンドの投票（0〜5）。次ラウンド開始時に null へリセット
  ├── usedCards:           number[]        # 使用済みカードインデックス（12枚使い切ったら再利用）
  └── round/
       ├── number:       number            # 現在のラウンド（1始まり）
       ├── cardIndex:    number            # CARDS 配列のインデックス（カード本文は同梱データから引く）
       ├── actor:        string | null     # 演者のニックネーム（casting 中は null）
       ├── answerIndex:  number | null     # 正解シチュエーション（0〜5）。演者確定時にランダム割り当て
       ├── votes:        { [nick]: number }  # 開票時のスナップショット（表示の安定用）
       ├── correctNicks: string[]          # 当てた人（開票時に確定）
       └── correctCount: number            # 当てた人数
```

### データ操作の注意点

- **ルーム作成・参加・開始**: すべて `transaction()`。参加は `status === 'waiting'` 判定・ニックネーム重複・満員（遊ぶ人8人）チェックを同一 transaction 内で行う
- **演者確定（casting → acting）**: transaction 内で演者の在室を確認し、`answerIndex` をランダム割り当て
- **開票（voting → reveal）**: ホストの transaction で votes スナップショット・correctNicks・スコア加算を一括確定（多重加算防止）
- **カード本文は書き込まない**: 全端末が同じ `CARDS` 配列を同梱しているため `cardIndex` のみ共有する
- **秘密情報（answerIndex）**: UI レベルで演者以外に非表示。DevTools での確認は性善説で許容（共通規約どおり）。ホストが演者のときは、ホストの画面では `<details>` の折りたたみ（「きみのシチュエーション（タップで見る）」）に入れ、acting / voting に入るたびにとじ直す（画面共有対策。画面に注意書きは出さない）

## 切断時の挙動

| 役割 | 挙動 |
|------|------|
| ホスト切断 | `hostConnected=false` + `hostDisconnectedAt=ServerValue.TIMESTAMP`。ゲストにオーバーレイ表示。TTL（`ORPHAN_TTL_MS = 2分`）超過でルーム削除 |
| ゲスト切断 | `onDisconnect().remove()` で自分の players データのみ削除 |
| **演者が切断** | acting 画面のホスト用「演じる人を選び直す」で casting に戻し、別の演者を選べる（answerIndex も引き直し） |

### 再接続

- sessionStorage `koedake_session` に `{ nickname, roomCode, role, score, vote }` を保存
- ゲストはスナップショット受信のたびに score / vote をセッションへ反映し、リロードで players から消えていても同じスコアで復元する（tatoe-gp と同方式）
- ホスト再接続時は `hostConnected=true` / `hostDisconnectedAt=null` を戻す
- TTL 判定は `RoomkRTDB.now()` / `RoomkRTDB.isRoomExpired()` を使用

## 得点ルール

| 立場 | 得点 |
|------|------|
| 当てた人 | +1pt |
| 演者 | **当てた人の人数**がそのまま加点（伝わるほど演者も嬉しい協力型） |
| ホスト | 進行だけなら得点なし（スコア表示にも出さない）。遊ぶときはゲストと同じ（当てたら+1pt・演じたら当てた人数ぶん） |

- 累計スコアは「これまでのポイント」としてチップ表示のみ。**順位付け・並べ替え・1位の強調はしない**
- 未投票者は「投票なし」として表示し、減点などのペナルティはない

## お題カード

- 12カードを `index.html` 内の `CARDS` 配列に同梱: `{ serifu: 'セリフ', situations: [6つ] }`
- セリフは「えー」「まじで」「やった」など短く言いやすいもの
- シチュエーションは声の演技で違いを出せる軽い日常場面のみ（びっくり・ねむい・うれしい・てれる・わくわく・あきれる 等）
- **入れないもの**: 恋愛・学校・勉強・テスト・ホラー・死。怒られた・こわい等のネガティブすぎる状況も不可
- 12枚使い切ったら `usedCards` の候補が尽きるので、全カードから再抽選する（重複解禁）

## 共通規約からの逸脱の明文化

- **`scripts/lint.sh` の `RTDB_HTML_FILES` に未登録**: ポータル（apps/index.html）と lint.sh を変更しない制約下で追加したため。viewport `maximum-scale=1`・`ORPHAN_TTL_MS = 2 * 60 * 1000` は規約どおり実装済み。lint.sh を触れるタイミングで配列に追加すること
- **ポータル未登録**: 同上の理由で `apps/index.html` にカード未追加。公開時に追加すること
- **done 後のルーム削除でゲストをトップに戻さない**: ルーム削除を検知してもおしまい画面はそのまま表示を続ける（結果の余韻を消さないため）。他アプリの「ホストがルームを終了しました」即時トースト方式とは異なる
- 最小人数は「遊ぶ人2人」（演じる人1人＋当てる人1人で成り立つ）。ホストが進行だけ（初期値）なら「ゲスト2人」、ホストも遊ぶなら「ホスト＋ゲスト1人」から始められる。最大も遊ぶ人8人（ホストも遊ぶならゲスト7人まで）。待合室でホストを遊ぶ側にして9人になった場合は開始ボタンを無効にし「遊ぶ人は8人までです」と出す

## ホストの参加（2026-10-01）

- 待合室のホストだけに見える「設定」に「自分もプレイヤーとして参加する」チェック（初期値: 外れている＝進行だけ。従来どおり）。開始後は変えない（このゲームは待合室に戻る作りがないので、ゲームの最後まで同じ値）
- 判定は `hostPlaysOf(room)`（`settings.hostPlays === true`）と `playingNames(room, players)` / `isPlaying(room, nick)`。遊ぶ人は「ホストが遊ぶなら全員、遊ばないならゲストだけ」
- 遊ぶ人だけで数えるもの: 開始の最少2人・最大8人（ボタンの無効化・案内文「あと N 人必要です」）、参加時の満員、演じる人の候補、当てる側（投票）、開票の集計・得点、結果の投票一覧、ポイント表示
- 待合室の一覧で、進行だけのホストの行に「進行役」タグ。人数表示は進行だけのとき「遊ぶ人 N人」
- ホストが演じる人のとき、ホストは当てる側にならない（従来の演じる人と同じ）。場面はホストの画面では折りたたみ（タップで表示）にする
- 自動の書き込み（タイマーでの進行・手番送りなど）はないので、遊ぶ人が全員抜けて進行役だけ残っても書き込みは続かない（演者えらびの候補が空になり、「きめた」が押せないだけ）
- 経緯: 2026-10-01 オーナー決定: 待合室でホストの参加を選べる（初期値は従来どおり＝進行だけ）

## メンター向け進行のコツ

- **演者は立候補制**。「やってみたい人？」と声かけし、こえ・チャットどちらの手挙げも拾う。誰も手を挙げないときは「ランダムに選ぶ」を使ってもよいが、**演技を強要しない**こと。声を出したくない子は当てる側で十分活躍できる（当てる側にも1ptずつ入る設計）
- 演技は**何回言ってもOK**。1回で決めさせず、「もう1回聞きたい人？」で場を温めると当てやすくなる
- 演者の得点は「当てた人の人数」なので、伝わらなくても演者を責める空気にならないよう「むずかしいお題だったね」でフォローする
- 未投票の子がいても「結果を見る」で進められる。投票を待ちすぎて場が冷めるより、テンポを優先してよい
- 演者が回線落ちしたときは acting 画面の「演じる人を選び直す」で選び直す（同じカードのまま、正解だけ引き直しになる）
- 同じ子ばかりが演者にならないよう、ラウンドごとに別の子へ声をかける
- ホストも遊ぶ設定で**ホストが演じる番では、場面（折りたたみ）を開く前に画面共有を止める**。演じ終わって投票に進んだら、共有を戻してよい（ホストの画面には投票状況だけが出る。折りたたみは開かない）
