# カンペ放送局 仕様書

## 目的・使用シーン

読む人の原稿には空らんがある。ほかの人は「食べ物」「音」のような**ヒントだけ**を見て言葉を書く（文の中身は知らない）。
読む人は「つぎへ」を押しながら原稿を声に出して読み、言葉はそのとき初めて出る。読む人は笑わずに読みきれるか。読み終わったら、読む人のほかのみんなで「笑わずに読めた」か「笑った」かを判定する。

- **core value**: 思いがけない言葉の組み合わせで、読む人を笑わせる・笑わずに読みきる。マイクを使わない子も、書く・判定するで参加できる
- 対象: 小学校中学年〜中学生。コトバ・ボドゲクラブ・サークルタイム（`data-scenes="kotoba bodoge circle"`）
- 遊ぶのは3〜8人（ホストは遊ぶか、進行だけかを選ぶ）。ほかに見ているだけの人も入れる
- 所要時間 1回15〜30分

> 経緯: 2026-11-02 オーナーの依頼で『ニュースの時間です』（A.I.Lab.遊＆ささみ企画×ClaGla）から着想して `drafts/kanpe-housou/` に試作（同じブラウザのウィンドウ間だけでつながるモック）。オーナーが試しに遊んだうえで、マイクOFFの人のための「書くだけ」を足した。同日、番組を10本足して20本に。同日オーナーが「本体に移す」「原稿20本とヒントの言葉はこのまま」「名前はカンペ放送局」と承認し、Realtime Database で本体化・公開した（cb1d374）。
> **「笑った」の意味の取りちがえ（2026-11-02）**: オーナーの「笑ったときの判断もみんなでできるといい」を、AI は「聞いている人がおもしろかった言葉に『笑った！』を押す」と取りちがえて作り、そのまま公開した。オーナーの意図は「読む人が笑ったかどうかのチェック」。同日、オーナーが「読み終わってから、みんなで判定」「結果は読む人の成功／失敗だけ」「点は読みきった人と笑わせた人」と決め、作りなおした。
> 着想元の名前はアプリ名・画面・検索のキーワードに使わない。早見表と更新情報で「『ニュースの時間です』から着想」と紹介する。着想元の原稿は使っていない（原稿はすべて独自）。
> 着想元との違い: 番組はニュースだけでなく、いろいろな放送。書く人に文を見せない（ヒントだけ）。判定は着想元と同じく、読み終わってからみんなで（過半数で読みきり）。

## ルール

| 項目 | 内容 |
|---|---|
| 人数 | 3〜8人 |
| 読む順番 | 入った順。待合室で「みんな1回ずつ」か「2回ずつ」を選ぶ（はじめは1回ずつ）。「読まない（書くだけ）」の人には読む番が来ない |
| 書くだけ | マイクを使わない人向け。待合室で本人が自分の行の「読まない（書くだけ）」にチェックする（ホストはだれの分も切りかえられる）。書く番と判定はある。みんな書くだけだと、はじめられない（理由を出す） |
| 空らんの数 | 書く人が2人なら2つずつ（4つ）。3人からは1人1つ（書く人の数と同じ・7つまで）。割りあては書く人の順をまぜてから順に |
| 番組 | 30本から、まだ使っていないものを選ぶ（使いきったら、また全部から）。空らんが少ないときは、原稿の頭の行から使う |
| 書く | ヒント（例つき）を見て12文字まで。「おまかせ」で、ヒントに合う言葉が入る。みんなが出すと、読む段階（番組のはじまり）へ。読む人が「読みはじめる」を押すまでは「書きなおす」ができる（番組のはじまりからは書く段階にもどる）。ホストがおまかせに替えた言葉がある人は書きなおせない |
| 読む | 読む人だけ「読みはじめる → つぎへ → 読みおわった」を押す。みんなの画面に、読んだ行まで出る。番組のはじまりから読みおわるまで、読む人のほかの画面（みんなにみせる画面も）に「読む人のほかのみんなは、マイクをOFFにしてね」を出す（2026-11-04 フィードバック「読み上げのときはみんなマイクOFFにしてほしい」） |
| 判定 | 「読みおわった」で判定の段階へ。読む人のほかのみんな（書くだけ・端末のない人も）が「笑わずに読めた」か「笑った」を1回だけ出す。みんな出したら開く。**だれが何を出したかは画面に出さない**（出したかどうかだけ） |
| 結果 | 「笑わずに読めた」が出た判定の半分より多ければ「○○ は、笑わずに読みきった！」、そうでなければ「○○ は、笑っちゃった！」（同じ数は読みきりにしない。着想元と同じ過半数）。原稿の中に、だれが書いたかも出す。判定の数は出さない |
| おしまい | 1本ごとに番組名・読んだ人・読みきったか・書かれた言葉（おまかせはのぞく）を並べる。待合室で「おしまいに順位を出す」をオンにしたときだけ点数の順位も出す（**はじめはオフ**。読みきった読む人に1点、読む人が笑った回は言葉を書いた人に1点ずつ（おまかせの言葉しかない人は入らない）。**点のある人だけ並べ、0点の人は出さない**） |

ルールは `engine.js`（画面と通信に触らない。node でも読める）。原稿とヒントは `data.js`。テストは `tests/kanpe-housou/engine.test.cjs`（空らんの数・割りあて・原稿の形・判定（過半数）・点・読む順番）。

### 原稿（data.js）

- 番組30本 × 空らんのある行7つ ＋ 書き出し・締め。1行に空らんは1つ（`{food}` など）。頭の行から使うので、頭のほうに笑いやすい行を置く
- ヒント9種類（食べ物・生きもの・音・動き・もの・のりもの・数・色・場所）。それぞれに例と「おまかせ」の言葉
- 行の文は、ヒントのどの言葉を入れても読めるように書く（動きは「〜る」の形なので「{move}のが」「{move}ように」など）
- 原稿・ヒントの言葉を変えるときは、オーナーの確認がいる（新規コンテンツの本体投入は人間専任）。ルームでは番組の id と行の番号で共有するので、**行の順番を入れかえたり、途中に足したりしない**（遊んでいる途中のタブとずれる）。番組を足すときは末尾に
- 重複監査（`scripts/content-audit.mjs`）は、原稿の行とおまかせの言葉を抽出する。番組の id の重複・空らんが1つでない行は失敗にする
- **ふりがな**: 原稿（書き出し・行・締め）のすべての漢字に、いつもふりがなを付ける。原稿の文字は変えず、`data.js` の `RUBY`（漢字のつながり → 読み）から画面に出すときに付ける（`engine.js` の `rubyParts`）。送りがなで読みが変わる字は、うしろのかなまで入れたキーを置く（`入れ` → い・`入っ` → はい など）。書かれた言葉は、おまかせの言葉と同じときだけ付ける（ほかは読みが分からないので付けない）。原稿やおまかせの言葉に漢字を足したら `RUBY` にも足す（`tests/kanpe-housou/engine.test.cjs` が付け漏れを見つける）

### オーナーが決めたこと（2026-11-02）

- 判定は、読み終わってから読む人のほかのみんなで「笑わずに読めた」「笑った」を出し、過半数で決める。結果は読む人の成功（読みきった）／失敗（笑っちゃった）だけを出す
- 点（順位をオンにしたとき）は、読みきった読む人と、読む人を笑わせた回の書く人に入れる
- 番組は、ニュースだけにせず、いろいろな放送
- 言葉は各自の端末で書き、端末のない人の分はホストが代わりに入れる
- マイクOFFの人は「書くだけ」。本人が待合室で選ぶ
- 原稿20本・ヒントの言葉・名前「カンペ放送局」
- 2026-11-13 フィードバックから、番組を10本（バスの車内放送・テレビショッピング・きょうの占い・誕生日パーティーの司会・新しいロボットの発表会・宝島への船旅・生きもの観察・スキー場・海水浴場・カフェのメニュー紹介）末尾に足して30本に。原稿は AI の案で、PR でオーナーが読んで確かめてからマージする（新規コンテンツの本体投入は人間専任）。ヒントの種類とおまかせの言葉は変えていない

### AI が決めて、オーナーが遊んで確かめたこと

- 判定の数は出さない・だれが何を出したかも出さない。順位ははじめオフ・0点の人は出さない
- 失敗の言い方は「笑っちゃった！」（「失敗」とは書かない）
- 書く人に文を見せない

## 端末のない参加者（ホストが代わりに押す）

- 待合室の「端末のない人を足す」で名前を足せる（待合室でだけ。参加者・ホストと同じ名前は不可。「外す」で外せる）。ホストが遊んでいても足せる（秘密の役がないため。かくれ怪盗と違う）
- `proxies/{name}` に置き、在室（`players`）には入れない（切断しない扱い）
- 書く番: ホストの画面に「○○ の代わりに書く」欄が出る（「ヒントをチャット用にコピー」でヒントを個別メッセージに送れる。絵文字なし）
- 読む番: みんなにみせる画面の原稿を読んでもらい、ホストが「代わりに：つぎへ」を押す
- 判定: ホストの画面に「○○ の代わりに出す」が出る
- 「端末なし」の印は、ホストの画面にだけ出す（子どもどうしの画面で区別しない）

## ホストの道具（ホストの画面の「ホストだけ」）

- 書く段階: 「まだの人を待たずに読みはじめる」（まだの人の空らんには、おまかせの言葉が入る）
- 読みはじめる前（書く段階と、番組のはじまり）: 「届いた言葉をたしかめる」→「おまかせに替える」
- 判定: 端末のない人・通信が切れた人の分を「○○ の代わりに出す」。「まだの人を待たずに判定を開く」（1人以上が出しているとき。出た分だけで過半数を見る）
- 読んでいるあいだ: 「代わりに：つぎへ」。読む人が端末のない人・通信が切れたときは大きく出す。読む人がつながっているときも、押さずに止まったときのために小さく出す（押す前に確かめる）
- 読む人の通信が切れているとき（書く段階と読む段階）: 「読む人の ○○ を待っています（通信が切れたみたい）」と「○○ の番をとばす」（副ボタン・確かめてから）。押すと、その番をとばして次の番組（最後の番ならおしまい）へ進む（2026-11-07。P4 監査「抜けた子を待ち続けて進めない」）
  - 自動ではとばさない。ホストが押したときだけ。つながっている読む人・端末のない読む人には出さない（端末のない人は「代わりに：つぎへ」で読む）
  - とばした番は、おしまいの「きょうの放送」にも点にも入れない（読んでいないため）。書かれていた言葉は使わない
  - ゲームの中の名前・読む順番は変えない（外さない）。とばした人がもどれば、次の番からそのまま遊べる。2回ずつなら2周目の番もまた来て、切れたままならまたとばせる
  - ほかの子の画面には「とばした」と出さない（次の番組に変わるだけ）
  - 読む人がみんなとばされたときは、おしまいの画面に「きょうは、読んだ番組がなかったよ」。順位オンでも、このときは点数のカード（「みんなで放送できたね」）を出さない
- 書く段階で、通信が切れたまま出していない人がいるときは「○○ を待っています（通信が切れたみたい）」（「まだの人を待たずに読みはじめる」の上。2026-11-07）
- ゲーム中いつでも: 「放送をやめて待合室にもどる」（確かめてから。ここまでの名場面は消える）。結果の画面の「ここでおしまいにする」とともに、ホストの枠の「そのほかの操作」（はじめは閉じる・作りなおしても開いたまま）にたたむ（2026-11-06）

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（ゲーム中なら見ているだけ）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
ルーム（screen-room）
  待合室: 参加している人（自分の「読まない（書くだけ）」）・自分（ホスト）も遊ぶ・端末のない人を足す・読む回数・おしまいに順位を出す・「放送をはじめる」
  ゲーム: 番組の帯（ON AIR のランプ・番組名・何本目・読む人）・大きな案内・段階ごとの中身・ホストだけの道具・遊んでいる人
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「放送をはじめる」、書く「出す」、読む人の「つぎへ」、結果のホストの「つぎの番組へ」、おしまいの「もう一回」）
- 書く欄は、自分の空らんと出したかどうかが変わらないうちは作りなおさない（作りなおすと iPhone のキーボードが閉じる）。作りなおすときも、入れている言葉と入力の位置は残す。日本語の変換中は画面を描きなおさない（確定してから描く）
- 「つぎへ」・判定のボタンは、キーボードで押したあとも同じボタンにフォーカスを戻す
- 「今の行」が動くのは新しく出たときだけ（ほかの人の変化で描きなおしても動かさない）。動きを減らす設定の端末では動かさない。音は鳴らさない

## status 遷移

```
waiting ─放送をはじめる→ play（game.phase: write）
write ─みんなが出す／まだの人を待たずに読みはじめる（ホスト）→ read（pos -1 から）
read ─つぎへ（読む人・ホストの代わり）で pos が 0（書き出し）〜 k+1（締め）→ 読みおわった → judge
judge ─みんなが出す／まだの人を待たずに判定を開く（ホスト）→ result
result ─つぎの番組へ（ホスト）→ write（次の読む人）／最後なら end
result ─ここでおしまいにする（ホスト）→ end
write / read ─○○ の番をとばす（ホスト・読む人の通信が切れているときだけ）→ write（次の読む人）／最後なら end
end ─もう一回（ホスト）→ write（新しい game.gid。そのとき在室している人で）
play ─待合室にもどる（ホスト）→ waiting（game を消す）
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
kanpe_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── hostPlays:          ホストも遊ぶか
  ├── opts:               { laps: 1|2, score: bool }
  ├── noRead/{name}:      true（読まない（書くだけ））
  ├── lastGameId:         number
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}:     { joinedAt }                # 端末のない参加者
  └── game/                                            # 「放送をはじめる」で作り、待合室にもどると消す
       ├── gid, step（段階が進むたびに1増える。古い操作の照合に使う）, phase
       ├── players: [名前...], uids: {名前: 匿名ID}（端末のない人はなし）, order: [読む人の名前...]
       ├── round（何本目。0から）, used: [使った番組の id...], points: {名前: 点}
       ├── reader, prog（番組の id）, k（空らんの数）
       ├── blanks: [{ hint, writer, word, auto }]（auto はおまかせで入った言葉）
       ├── submitted: {名前: true}, rev: {名前: 数}（出す・書きなおす・おまかせに替えるのたびに1増える）, pos（読んだ行。-1 は番組のはじまり）
       ├── judges: [判定する人...], verdicts: {名前: 'ok'|'laugh'}, success: 読みきったか（結果から）
       └── history: [{ reader, prog, k, blanks, success }]（おしまいのふりかえり）
```

- 読み込むときは欠けた値を補う（`normGame`。RTDB は空の配列・null を残さない。数字のキーだけのオブジェクトは配列で返るので `asObj` でもどす）
- まだ読んでいない言葉・だれが書いたかはルームに置き、画面には読んだ行の言葉だけ出す（DevTools で見えるのは、ルート AGENTS.md の性善説で許容）

## transaction 設計

すべてルーム全体への `transaction()`。中で「押した人の在室の匿名ID」「押した時点の `game.gid` と `game.step`」「その段階でその人が押せるか」を確かめる（`applyMsg`。前のゲームの操作が遅れて届いても通さない）。ホストの操作は `hostUid` と、押した画面の `gid`・`step` を確かめる（`hostAct`）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | 名前が空いている（ホスト・端末なしの人・ゲームで遊んでいるほかの匿名IDの人と同じ名前は不可）・参加者12人未満（ゲームで遊んでいる人が戻るときは上限を見ない）→ `players/{name}`（`transactRetry`。自分の在室が残っていれば入りなおし） |
| 読まない（書くだけ） | 本人（待合室） | `waiting` → `noRead/{自分}` |
| 設定・ホストも遊ぶ・だれかの書くだけ | ホスト | `waiting`。続けて変えても取りこぼさないよう、ロックを使わず差分だけ送る |
| 端末のない人を足す・外す | ホスト | `waiting`・名前が空いている |
| はじめる／もう一回 | ホスト | 待合室からは `waiting`、「もう一回」は `end` で押した画面の `gid` が一致・人数（3〜8人）と読む人がいる → `game` を作る（`gid` を1増やす） |
| 出す | 書く人（端末のない人の分はホストが `as` で） | `write`・`gid`/`step` が一致・まだ出していない・押した画面の `rev` が一致 → 言葉を入れる。最後の人が出すと読む段階へ |
| 書きなおす | 書く人（同上） | 読みはじめる前・出している・`rev` が一致・おまかせに替えられた言葉がない → 取り消す（番組のはじまりからは書く段階にもどる） |
| つぎへ | 読む人／ホスト（いつでも。画面では、読む人がつながっているときは確かめてから） | `read`・`gid`/`step` と `pos` が一致（二度押しで2行進まない）→ 1行進める。締めのあとは結果を出す |
| 判定を出す | 判定する人（端末のない人・通信が切れた人の分はホストが `as` で） | `judge`・`gid`/`step` が一致・まだ出していない・`ok` か `laugh` → 入れる。最後の人が出すと開く（過半数・点を入れる・history に残す） |
| 判定を開く | ホスト | `judge`・`gid`/`step` が一致・まだの人がいて、1人以上が出している → 出た分で開く |
| 待たずに読みはじめる | ホスト | `write`・`gid`/`step` が一致 → まだの人の空らんにおまかせ |
| おまかせに替える | ホスト | 読みはじめる前・`gid`/`step` が一致・ホストが画面で見ていた言葉と同じ → おまかせ（書いた人の `rev` を1増やす） |
| つぎの番組へ・ここでおしまい | ホスト | `result`・`step` が一致 |
| ○○ の番をとばす（`skipTurn`） | ホスト | `write` か `read`・`gid`/`step` と読む人が押した画面と一致・読む人が端末のない人でなく、いまも通信が切れている（`players` にない）→ `round` を1進めて次の番組（最後なら `end`）。もどっていたら断って「○○ がもどってきたので、このまま続けるよ」 |
| 待合室へ | ホスト | `play`・押した画面のゲームの `gid` が一致（古いタブから新しいゲームを消さない）→ `waiting`、`game` を消す |
| 退出 | ゲスト | 自分の在室と「書くだけ」を消す（ゲームの中の名前は残す。空らんはホストが待たずに進められる） |

- 新しく入る人（入りなおし・ゲーム中の戻りでない人）は、前に同じ名前の人が残した「書くだけ」を引きつがない。端末のない人を足すときも同じ

## 接続・切断・再接続

かくれ怪盗・リバーシ・しるしでヒントと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- 遊んでいる人が切れると、札に「通信が切れた」。書く番なら、ホストが「まだの人を待たずに読みはじめる」。読む人ならホストが「代わりに：つぎへ」か「○○ の番をとばす」（2026-11-07）
- 人数の数え方（ゲームの遊ぶ人・判定する人に、一時的に切れた人も入れる）は変えない。とばす・待たずに進むは、ホストが押したときだけ働く
- 戻ると（同じタブの読み込み直し・同じ名前と同じ匿名ID）続きから。ゲームで遊んでいる人の名前は、ほかの人（別の匿名ID）は使えない
- ゲーム中に入った人は見ているだけ（「もう一回」から入る）
- ホスト切断中、ゲストと見る画面には共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おしまいでも自動削除しない（「もう一回」と名場面のふりかえりのため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 待合室にもどると `game` を消す（設定・書くだけ・端末のない人は残る）

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: players に入らない・切断予約をしない・期限切れのルームも消さない
- まだ読んでいない言葉は出さない。読んだ行の言葉は出す（端末のない子が読む番のとき、この画面の原稿を読む）。判定のボタンは出さない
- 待合室では「参加のしかた」とルームコードを大きく出す。原稿の文字を大きくする

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る。engine.js・data.js は DOM に触らない
- **ホスト以外も進行の一部を行う**: 書く人の「出す」（最後の人で読む段階へ）、読む人の「つぎへ」（締めのあとで結果へ）は、その人の端末が transaction で進める。ホストは番組の切りかえと代わりの操作
- **まだ読んでいない言葉をルームに置く**。画面は読んだ行の分だけ。性善説（ルート AGENTS.md「セキュリティ方針」）
- **端末のない参加者は在室を持たない**（`proxies`。切断しない。ホストが代わりに入れる）
- **終了後の自動削除なし**（公認バリアント）
- **原稿にふりがなを付ける**（ルート AGENTS.md「表記トーン」の「ふりがなは付けない」の例外）。ふつうは読めない字をメンターが読み上げて補うが、このゲームは読む人が自分で原稿を声に出して読むので、補いにくい。2026-11-04 フィードバック「カンペにフリガナがあるとより参加しやすそう」を受けて、オーナーが「いつも付ける・すべての漢字」と決めた
- **判定の中身（だれが何を出したか・数）は画面に出さない**。順位は待合室でオンにしたときだけ（はじめはオフ）。成績の記録はしない

## 入れない機能

- 音（演出も音なし）
- だれが「笑った」を出したかの表示（読む人と判定した人の間に気まずさが出ないように）
- 0点の表示、判定の数の表示
- 勝ち数・成績の記録
- チャット（話し合いは Zoom / Meet の声とチャットで）

## 既知の制約（v1）

- 名前に数字だけは使えない（RTDB は数字のキーだけのオブジェクトを配列で返すため）
- 切断予約（onDisconnect）は在室を書き戻す transaction の前に張る（かくれ怪盗と同じ作り）。同じ名前を別の人が使っていると分かったら、その画面はルームから外れて予約を取り消す。そのすきまに切れると、別の人の在室を消すことがありうる（ほかのアプリと同じ扱い）
- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- ホストが遊ぶ人で、端末のない人の代わりに書くと、ホストが読む番の回でもその人の言葉が先に見える（代わりに入れるため）
- 判定を同時にたくさん出すと、ルーム全体の transaction がやり直しになって少し遅れることがある（8人まで）
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（共通方針どおり、少なめに出る側の誤差として扱う）

## メンター向けの心得（画面には出さない）

- 読む番を嫌がる子は、待合室で「読まない（書くだけ）」にしてよい。マイクを使う子にも、無理に読ませない
- 読む人が笑ってしまっても、責めない。「笑っちゃうよね」「あの言葉はずるいね」と一緒に笑い、書いた子の言葉もほめる。読み間違いを直さない
- 書いた言葉がからかいや、ほかの子の名前になっていないか、ホストは「届いた言葉をたしかめる」で読む前に見られる。気になる言葉は「おまかせに替える」
- 判定は笑いを取った言葉の勝負でもある。読みきった子には「よく読みきったね」、笑わせた側には「いい言葉だったね」と、どちらのがんばりも言葉にする
- 画面共有するときは「みんなにみせる画面」を共有すると、まだ読んでいない言葉が映らない
