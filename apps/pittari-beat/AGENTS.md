# ぴったりビート 仕様書

## 目的・使用シーン

上から落ちてくるしるし（まる・ひしがた）が線に来たときにボタンをたたいて点を集める、リズムあそび。音楽系のプログラムで使う。
**子どもは自分のパソコンやスマホでアドレスを開いて、各自の端末で遊ぶ。** 画面共有では音と映像が遅れて届き、見ている側はリズムに合わせられないため（2026-10-21 オーナー決定）。
進行役は画面共有で、お手本とランキングを見せる。ポータルのシーンは ひろば・サークル。

- 元にしたゲームの名前・キャラクター・見た目・「どん」「かっ」などの言葉は使わない。遊び方だけを取り入れ、名前（ぴったりビート）と見た目（上から落ちる2列・フラットな丸とひし形）はオリジナル。早見表の「近い遊び」も名前を出さず「リズムゲーム系」とした
- 既存の曲（はやりの曲・アニメの歌など）は使わない。曲は ElevenLabs で作ったオリジナル3曲（歌なし）
- キャラクターは使わない（10-21 オーナー決定）

## ルール

- コースは3段階。しるしの並びは同じ曲・同じコースなら毎回同じ（4小節ひとまとまりで A A B A のくり返し）
  - やさしい: しるしは1種類（まる）。どのボタン・どのキーでも当たる。毎拍＋8分音符の「タタ」
  - ふつう: まる（左）と ひしがた（右）。8分音符のこまかいリズム
  - むずかしい: 16分音符も入る。16分音符はとなりの列とだけ（同じ列のしるしは8分音符より近づけない）
- **マークの数**（ふつう・むずかしいで選ぶ。10-21 オーナー判断で追加）: 2つ（まる・ひしがた。はじめの形）か 3つ（左＝まる・まんなか＝さんかく・右＝ひしがた）。やさしいはいつも1つで、欄を隠す。3つの並びは `engine.js` の `PATTERNS3`（2つとは別の譜面）。さんかくは紫（ほかの2つと形と色で見分ける）
  - 落ちる速さ（上から線まで）: やさしい 1.3秒・ふつう 1.15秒・むずかしい 1.0秒（`engine.js` の `TRAVEL`）
- 点数: ぴったり100点・いいね50点（判定のはばは `engine.js` の `JUDGE`。コースごと）。つづけて当てた回数は遊んでいる間とおわりの画面に出すだけで、点には足さない
- **はずれは、だまって流す。** 外れたしるしは薄くなって消えるだけで、文字も音も出さない。いいねのはばより早いタップはそのしるしを流す（でたらめにたたき続けても当たり続けないように）。何もないところをたたいても何も起きない
- **たたく音**（10-21 意見を受けてオーナー判断で追加）: 当たったとき（ぴったり・いいね）だけ短くやわらかい音が鳴る。はずれ・空振りでは鳴らさない（はずれが目立たないように）。**はじめは「切」**（聴覚過敏の子がいるかもしれないため）で、「ひとりで遊ぶ」と参加者の画面の「たたく音」で各自が「入」にする。音の大きさは曲とは別のつまみ。マークごとに高さを少し変える（まる 660Hz・さんかく 784Hz・ひしがた 880Hz）。「入」にした瞬間に1回だけ聞かせる。設定は端末に残す（localStorage）
- 曲の大きさは「音の大きさ」で選べる。たたいたときは光る（たたく音が切でも）
- おわりの画面: 点数・ぴったり◯回・いいね◯回・つづけて当てた回数（いちばん長く）。責める言葉は出さない

### ルームとランキング（10-21 オーナー判断で入れた）

はじめの指示書は「ランキングは入れない」だったが、試作を見たオーナーの判断でルームのランキングを入れた。

- 進行役が「ルームを作る」でコース・マークの数・曲を1つに決める。みんな同じ設定で遊ぶ
- 参加する人はリンク（`?room=`）かルームコードで入り、「はじめる」で何回でも遊べる。ランキングには**ひとりひとりのいちばんよい点数**がのる。同じ点数は同じ順位（1, 1, 3）。まだ遊んでいない人は「まだ」で後ろ
- 進行役は名前を持たない（ランキングに入らない）。「お手本を見せる」で遊んで見せられる（点数は送らない）
- 「コースと曲を変える」（マークの数もここで変える）と、みんなの点数は消える（変える前に注意書きを出す）。遊んでいる途中で変わった回はランキングにのらず、おわりの画面で知らせる
- 判定は各自の端末の中だけで行い、ルームに送るのは「いちばんよい点数」と「遊んでいる」の印だけ。通信のおくれで点数は変わらない
- ひとりで遊ぶとき（「ひとりで遊ぶ」）は、これまでどおり点数を出すだけで、どこにも送らない

## 技術スタック

- 分割ファイル: `index.html`（画面）・`app.js`（画面・音・操作・ルーム。type="module"）・`engine.js`（譜面・判定・点数・順位・タイミング合わせの計算。音や画面に関係しない）・`style.css`（接頭辞 `pb-`）
- Realtime Database（compat 10.14.1）。`RoomkRTDB.initFirebase()`・`now()`・`isRoomExpired()`・`cancelRoomOnDisconnect()`・`copyRoomCode()`・`copyRoomLink()`・`showToast()` を使う
- 音: Web Audio。**時間は音の時計（AudioContext）を基準にする。** `getOutputTimestamp()` で「いま耳に届いている音の位置」と画面の時計を対応させ、しるしの位置も判定もそこから出す（使えないブラウザは `currentTime − outputLatency`）。たたいた時刻はイベントの `timeStamp`
- 曲は `music/*.mp3` を `fetch` → `decodeAudioData` し、`AudioBufferSourceNode` で鳴らす。止めて再開するときは `start(when, offset)` で2秒前から
- iPhone のマナーモードでも鳴るよう `navigator.audioSession.type = 'playback'`（対応しているブラウザだけ）
- 端末の設定として localStorage に残すもの: 音のおくれ（タイミング合わせ）・音の大きさ・選んだコースと曲。点数は残さない

## 画面構成・フロー

| 画面 | 内容 |
|---|---|
| `pb-top` | パネル1枚。「ルームを作る」（主）・「ルームに参加する」（副）・「ひとりで遊ぶ」「タイミング合わせ」（弱） |
| `pb-solo` | ひとりで遊ぶ: コース・マークの数・曲・音の大きさ・「はじめる」 |
| `pb-create` | ルームを作る: コース・マークの数・曲・「ルームを作る」 |
| `pb-host` | 進行役（画面共有で見せる）: ルームコード・「コードをコピー」「リンクをコピー」「QRコードを出す」（`#btnShowQr`。別の端末で入る人向けに参加用のリンクを QR コードで大きく出す。共通の `RoomkQR.show(code)`、`apps/shared/js/room-qr.js`。2026-10-22）・ランキング・「お手本を見せる」・「コースと曲を変える」・「ルームを閉じる」 |
| `pb-join` | ニックネーム（8文字）→ ルームコード（6文字）→「参加する」。リンクから開くとコードが入っていてヒントが出る |
| `pb-guest` | 参加者: きょうのコース・あなたのいちばん・いまの順位・「はじめる」・音の大きさ・ランキング・「タイミング合わせ」・「退出する」 |
| `pb-play` | 遊ぶ: 点数・つづけて・とめる・しるしの落ちる場所（canvas）・ボタン（まる・ひしがた／マーク3つは まる・さんかく・ひしがた／やさしいは「たたく」1つ）。止めると「ひとやすみ中」（つづける／やめる） |
| `pb-result` | おわり: 点数・回数。参加者は「ランキングに送ったよ」など |
| `pb-calib` | タイミング合わせ: 手拍子（70 BPM・16拍）に合わせてたたき、ずれのまん中の値を差し引く。＋／− で 0.01 秒ずつ直せる（−0.1〜0.4 秒） |

- キーボード: まる＝F（D・S・←も）、ひしがた＝J（K・L・→も）、さんかく（マーク3つ）＝スペース（↑・↓も）。やさしいは F・J・スペースのどれでも。Esc で止める／つづける
- 画面のしるしの落ちる場所を押したときは、押した位置の列（2つなら左右半分、3つなら3等分）
- ほかの画面に切りかえる（タブを隠す）と止まる
- 遊んでいる間は「？」ボタンを隠す（右のボタンと重なるため）

## Firebase データ構造（Realtime Database）

`pittari_beat_rooms/{6文字コード}`（ルールの変更は不要。最上位の `$app_rooms` で書ける）

```
status: 'open'                 // ゴースト判定にも使う（status がない room は削除後に再生成されたもの）
hostUid, createKey             // createKey は作成のやり直しで自分のルームか確かめる印
hostConnected, hostDisconnectedAt, createdAt
course: 'easy' | 'normal' | 'hard'
track: 'slow' | 'mid' | 'fast'
marks: 2 | 3                   // マークの数（やさしいのときは使わない）
version: 1, 2, …               // コース・マークの数・曲を変えるたびに 1 上げる
players/{名前}: { uid, joinedAt, best, v }   // いちばんよい点数と、その点を出したときの version。切断しても消さない
online/{名前}:  { uid, playing }             // いまつながっているか・遊んでいるか。切断したら消える
```

- ランキングに出すのは `players/{名前}/v === version` の `best` だけ。コースを変えたときは version を上げるだけで、点数を書き消さない
- 点数は `players/{名前}` だけの transaction で送る（uid が自分のもの・同じ版で今より高いときだけ書く）。参加者はいまの版の自分のいちばんを覚えていて、ルームの点が低ければ送りなおす（読み込みなおしや通信の切れで届かなかったとき）

## transaction 設計

- 作成: ルートの transaction。やり直しのとき `hostUid` と `createKey` が自分のものなら、そのまま使う（rtdb.md「作成・参加の送信後の切断」）
- 参加: 先に購読してから（`warmRoomCache`）ルートの transaction。同じ名前が別の uid なら断る。同じ uid なら入りなおし（点数はそのまま）。30人まで
- 在室の確認（`ensurePresence`）: 接続のたびと、1秒ごとの確認で、ルームの上の自分の状態（進行役は `hostConnected`、参加者は `online/{名前}` と `playing`）が違っていたら直す
- `transactRetry` は `'disconnect'`（送信後の切断）と `'set'`（同じ端末の配下の書き込みで中止）でやり直す（3回まで）

## 接続・切断・再接続（意図的な逸脱あり）

| 役割 | 切断したとき |
|---|---|
| 進行役 | `hostConnected: false` と `hostDisconnectedAt`（共通の決まりどおり）。参加者の画面に「進行役の画面とつながっていないよ。遊ぶことはできるよ」と出す。2分（`ORPHAN_TTL_MS`）たつと期限切れ |
| 参加者 | **`online/{名前}` だけを消す（`players/{名前}` は消さない）**。ランキングでは薄く「はなれている」と出し、点数と順位はそのまま |

- **意図的な逸脱: はなれている人の点数は消さない**（10-21 オーナー決定）。共通の決まり（ゲスト切断で players を `onDisconnect().remove()`）は使わず、つながりの印 `online` を別に持つ。ランキングから消えるのは「退出する」を押したときだけ
- 再接続: sessionStorage（`pittari_beat_session`）に役割・名前・コード・uid・自分のいちばんを残し、読み込みなおしたら同じルームへ戻る。同じ端末なら、ブラウザを閉じたあとでも同じ名前で「参加する」から入りなおせる（点数はそのまま）
- 参加用のリンク（`?room=`）は rtdb.md「参加用のリンク」のとおり（つないだらアドレスから外す・形が正しくなければトースト）

## 終了とデータ削除（公認バリアント）

ランキングを見せている間は消さない。rtdb.md「公認バリアント: ふりかえり画面滞在中は削除しない」と同じく、次の3つで消す。

1. 進行役の「ルームを閉じる」（確認のうえ `cancelRoomOnDisconnect` → `remove`）。参加者の画面ははじめにもどり「ルームは閉じられたよ」
2. 進行役の切断から2分（期限切れ）
3. 次に開いた人が期限切れを見つけたとき（`removeExpired`、`applyLocally: false`）

## 入れない機能

- 点数・結果の保存（ひとりで遊ぶとき）、ルームを閉じたあとのランキングの記録、ルームをまたいだ比較・自動の推薦
- ミスの表示・ミスの音（たたく音は当たったときだけ）
- 画面共有で全員が同じ画面を見て遊ぶ形（音が遅れるため）

## 既知の制約

- 音としるしのずれは、自動の確かめ（Chrome）では音の時計と判定の対応までしか見られない。耳で聞いたずれはオーナーが実際の端末とイヤホンで確かめた（10-21「いい感じ」）。Safari・iPhone は未確認
- ワイヤレスのイヤホンは、おくれをブラウザが知らせないことがある。そのときは「タイミング合わせ」で差し引く
- 匿名の uid は同じブラウザの別タブと共通。同じブラウザの2つのタブで同じ名前を使うと、同じ参加者として扱う

## メンター向けの心得（画面には出さない）

- 遊ぶ前に、各自の端末で音が出るか（音の大きさ・マナーモード）を確かめてもらう。ワイヤレスのイヤホンの子には「タイミング合わせ」をすすめる
- 画面共有はランキングとお手本を見せるためのもの。共有画面に合わせてたたいても合わないことを伝える
- 点数が低い子がいても、ランキングを読み上げて比べることはしない。「いちばんよい点が更新できたね」など、その子の中の伸びを拾う
