# わたし、ぼくってどんな人？ 仕様書

## 目的・使用シーン

作戦会議（週1回30分の1対1）で使う自己理解ワーク。スタッフが作ったスライド資料
「わたし、ぼくってどんな人？」（両はしの言葉のどちらに近いかを1〜4で選ぶ9つの軸）をもとにした。
問いを1つずつ出し、両はしの言葉のどちらに近いかを 1〜4（またはパス）で答える。
答え終わったら答えたところを1つずつふりかえって話し、最後に全部の答えを一覧で見る。
所要時間 10〜15分（会話込み）。

| ロール | 説明 |
|--------|------|
| 操作者 | メンター（画面共有して読み上げ、子どもの答えを聞いて押す） |
| 閲覧者 | 子ども（Zoom/Meet等の画面共有で閲覧） |

**経緯**: 2026-11-05 に `drafts/donna-hito/` で試作（695526d）→ 同日オーナーの指示で本体に移した。
試作中のオーナー判断:
- 一覧をいきなり見せると、目の前の問いより他の問いに気が向いて話に集中しにくい → **1つずつ出す**（答える・ふりかえるとも）
- まとめは一覧でよい
- まとめの行を押すと、その問いだけを大きく出す（「ふりかえりにもどる」は分かりにくいのでやめた）
- 「つづきを答える」は行を押すのと同じ役割なので置かない
- メンターの答えを入れる機能は置かない（メンターによって言ったり言わなかったりするため）
- 選んだ数字の輪は、選ぶ前は出さない（真ん中の点線の丸はやめた）

## 画面構成・フロー

```
TOP → 問い（答える: 1つずつ）→ 問い（ふりかえり: 答えたところを1つずつ）→ 一覧
                                                        一覧の行 → 問い（1つだけ大きく）→ 一覧
```

画面は `#screen-top` / `#screen-question` / `#screen-summary` の3つ。問いの画面は `state.mode` で3つの使い方をする。

| mode | 上の表示 | 主ボタン | 控えめなボタン |
|------|----------|----------|----------------|
| `answer`（答える） | 9つの点（いま・出した問い） | 「つぎへ」／最後は「ふりかえりへ」（選ぶまで押せない） | 1〜4のすぐ下に「パス」（枠線のボタン）。下の段に「ひとつ前にもどる」「今日はここまで」 |
| `review`（ふりかえり） | 「ふりかえり」＋ふりかえる数の点 | 「つぎへ」／最後は「全部の答えを見る」 | 「まえへ」 |
| `detail`（一覧から） | 「一覧から」 | 「一覧にもどる」 | なし |

- TOP: パネル1枚構成（ui.md「トップ画面の定石」）。タイトル＋説明＋注意3点（正解はない／どちらもいいところがある／パスでOK）＋「はじめる」（主ボタン1つ）
- 答える: 両はしの言葉（アイコン＋言葉）と 1〜4 の4つのボタン（1・4 は「とても」、2・3 は「少し」）。
  選んだ数字に輪が出る。同じ数字をもう一度押すと選ぶ前にもどる。「つぎへ」で答えが決まる
- 「パス」は答えを空にして次へ。「パス」と「まだ答えていない」は `seen` で分けて表示する
- 「今日はここまで」は、そこまでに答えた問いだけをふりかえりに進める（とがめる文言は出さない）
- ふりかえり: 答える画面で出した問い（パスを含む）を順に出す。その場で選び直せる（すぐ `answers` に入る）。
  空の問いには「パスした。いま選んでもOK」／「まだ答えていない。いま選んでもOK」を出す
- 一覧: 9つの問いを全部並べる。行は押せるボタンで、両はしの言葉と小さな 1〜4 の点（選んだ数字だけ塗る）。
  近いほうの言葉を太字に、アイコンをアクセント色にする。押すとその問いを detail で出し、「一覧にもどる」でその行にフォーカスを戻す
- 一覧のボタンは「結果をコピー」（btn-primary）＋「最初にもどる」（控えめなテキストボタン）

## 問いのデータ

`app.js` の `QUESTIONS` 配列（`title` / `left` / `leftIcon` / `right` / `rightIcon`）を直接編集する。9つ・固定順（シャッフルしない）。
1 = 左にとても近い、2 = 左に少し近い、3 = 右に少し近い、4 = 右にとても近い。

元資料の言葉を 2026-11-05 の修正案（オーナー承認）で直した:
- 両はしがどちらも「いいな」と思える言葉にする（片方が欠点に聞こえる言葉にしない）
- 左右を同じ形の言葉にそろえる
- 同じ軸を2回聞かない（元の「考え 慎重派／楽観的」は1つ目・3つ目と重なるので「好きなことは？」に入れかえた）

言葉の書きかえはコンテンツの判断（人間専任）。重複監査（`scripts/content-audit.mjs`）は title を `question`、両はしを `end` として抽出する。

## 心理的安全設計

- **正解・よい答えを作らない**。両はしは同格で、色・大きさに差をつけない
- **点数・タイプ分け・診断・比較・おすすめをしない**。一覧は答えを並べるだけで、まとめの文や傾向を出さない
- **パスは正式な答え**。パスの問いを責める文言・数え上げを出さない。パスは1〜4のすぐ下に選択肢として置き、「もどる」「今日はここまで」と同じ段に混ぜない（2026-11-08 P5 監査。前は控えめな文字ボタンで、4つから選ぶものに見えた）
- **全部答えることを目標にしない**。「今日はここまで」は常設
- 話してみて変わったら選び直せる（ふりかえり・一覧から）。最初の答えとの比較は出さない

## 結果コピー

Metalifeチャット貼り付け用のプレーンテキスト（絵文字なし）。選んだ数字を [ ] で囲む。

```text
わたし、ぼくってどんな人？
・動くときは？ 考えてから動く 1 [2] 3 4 まず動いてみる
・予定は？ パス
```

答えていない問いは「まだ」。コピー失敗時は無反応にせずエラートーストを出す。

## キーボード

問いの画面で 1〜4 キーがその数字のボタンを押す。Enter は「つぎへ」（数字のボタンにフォーカスがあるときも「つぎへ」。選び直しにしない）。
修飾キーつき・日本語変換中・モーダル表示中は反応しない。

## stats（回数のみ・内容は送らない）

- `open`: stats.js の自動計上
- `start`: 「はじめる」押下
- `finish`: 一覧の初回表示（1回の通しで1回。`state.counted` でガード。一覧から開いてもどっても数えない）

## CSS命名規則

接頭辞: `.dh-`（donna-hito）

| クラス | 用途 |
|--------|------|
| `.dh-panel` / `.dh-note-list` | TOP のパネル |
| `.dh-header` / `.dh-progress` / `.dh-dots` | 問いの見出し・進み具合の点 |
| `.dh-end` / `.dh-end__icon` / `.dh-end__label` | 両はしの言葉（言葉は `word-break: auto-phrase` で文節で折り返す） |
| `.dh-scale` / `.dh-scale__btn` / `.dh-ring` | 1〜4 のボタンと、選んだ数字を囲む輪 |
| `.dh-quiet-btn` | 控えめなテキストボタン |
| `.dh-row` / `.dh-mini` | 一覧の行と小さな 1〜4 の点 |

角丸は押せるものを `--radius-btn`、入れものを `--radius-box` / `--radius-card` にそろえる。

## アクセシビリティ

- 問いを出したら見出し（`tabindex="-1"`）にフォーカスを移す
- 1〜4 のボタンは `aria-pressed` と、どちらの言葉に「とても／少し」近いかの `aria-label` を持つ
- 一覧の行は `aria-label` に問い・答え・「押すと大きく出す」を入れる
- タップターゲットは最小 44×44px。`prefers-reduced-motion` で輪の動きを止める

## メンター向けの心得（画面には出さない）

- 問いと言葉はメンターが読み上げる。読めない漢字は読み上げで補う
- 子どもが言った答えをメンターが押す
- メンター自身の答えを話すかどうかはその場で決める（ツールには入れない）

## 入れない機能（意図的に未実装）

- 点数・タイプ分け・診断・傾向のまとめ文・おすすめ
- 一覧を最初から見せる（1つずつ出す。2026-11-05 オーナー判断）
- 「つづきを答える」ボタン（一覧の行を押すのと同じ役割）
- メンターの答えを入れる欄（2026-11-05 オーナー判断）
- 「なんで？」を書かせる欄
- 自動で次へ進む（答えを聞いてから「つぎへ」で進める）
- 永続化（localStorage 含む）・履歴・`beforeunload` 警告
- 問いのシャッフル・問数の可変
