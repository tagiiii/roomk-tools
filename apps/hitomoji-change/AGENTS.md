# ひともじチェンジ 仕様書

## 目的・使用シーン

はじめのことばを1文字ずつ変えて、ゴールのことばまでつなぐことば遊び（例: いぬ→いか→たか→たこ→ねこ）。
遊び方は2つ。
- **ルーム**（2026-11-25 追加）: ひとりひとりの端末で、順番に（または、だれでも）1文字ずつ変える。参考動画のホワイトボードを順に回す形に近い
- **1台の画面**: メンターが画面共有して操作し、参加者が「ここを『か』にしたら？」と声やチャットで案を出す
1対1でも、サークルタイムの10人程度でも遊べる。

- 2026-11-25 オーナーの依頼で作成。参考にしたのは、YouTube のショート動画「さかなを変換しておにくにするゲーム」（3人がホワイトボードで順番に1文字ずつ書き換える）。遊びそのものは、ルイス・キャロルの「ダブレット」に始まる昔からのことば遊び（英語では word ladder）で、だれかの商品名ではない
- 名前は動きをそのまま表す「ひともじチェンジ」。参考の動画やチャンネルの名前は、画面・更新情報・検索のことばに入れない
- **商標の確認（2026-11-25、J-PlatPat の商標検索・出願／登録情報）**: 商標（検索用）「ひともじチェンジ」0件、称呼の類似検索「ヒトモジチェンジ」0件、称呼の部分一致「モジチェンジ」0件。称呼の部分一致「ヒトモジ」は16件で、どれも「一文字」「人文字」などを含む別の名前（食品・酒・種苗・アプリの「１文字日記」など）。遊び・教育に近い41類では「ＨＩＴＯＭＯＪＩ」（16・41類、登録6297042）と「一文字セラピー」（41・44類）があるが、名前全体の「ひともじチェンジ」とは読みも見た目もちがう。同じ名前・「ヒトモジチェンジ」に似た読みの商標は見つからなかった（法律上の判断ではなく、検索の結果）

| 項目 | 値 |
|---|---|
| 人数 | 人数制限なし（ルームは遊ぶ人12人まで） |

## 技術スタック

- 1台の画面は通信しない。ルームは Realtime Database（名前空間 `hitomojichange_rooms`。ルームを作る・参加する・ルームにもどるときだけつなぐ）
- `index.html` + `app.js`（画面・通信。ES モジュール）+ `logic.js`（ことばとルームの決まり。`window.HMC_LOGIC`、Node のテストからも読む）+ `words.js` + `style.css`。変えたら `?v=` をそろえて上げる
- 共通: design-system.css、`utils.js` の `shuffle` / `popIn`、rtdb-utils.js、room-qr.js、overlay-a11y.js、focus-keep.js、howto.js、stats.js
- テスト: `tests/hitomoji-change/`（決まりの単体テスト・隔離エミュレーターの E2E 2本・サムネイルの撮り方）

## 画面構成・フロー

```
はじめの画面（ルームを作る / ルームに参加する / 1台の画面であそぶ）
  1台: お題の選び方（2文字 / 3文字 / 自分で決める → スタート）→ 遊ぶ画面 → ゴール（次のお題 / はじめの画面へ）
  ルーム: 作る・参加する → 待合室（ホスト: 変える人・お題・端末のない人・ホストも遊ぶか → はじめる）
          → 遊ぶ画面（番の帯 → ここまでのことば → いまのことば → 文字の表）→ ゴール（ホスト: 次のお題 / 待合室にもどる）
```

- いまのことばの文字を押す → 文字の表（50音・濁音・半濁音・小さい字・「ー」）から選ぶ → 1文字だけ変わったことばが「ここまでのことば」に足される
- **文字は打ち込まず、場所と文字を押して選ぶ**。こうすると「1回に1文字だけ・文字の数は変わらない」を必ず守れて、日本語入力の変換中の不具合も起きない
- 濁点・半濁点（か→が）も1回の変更。小さい字と「ー」も1文字として数える
- 「1つ戻す」でいくらでも戻れる。ゴールと同じ文字には、タイルの下に緑の小さな印が出る
- 「ヒント」: 1回目は変える場所を光らせ、あと何回くらいでゴールできそうかを出す。2回目は次のことばの例を出す。ことばを変えると最初からになる
- 「お題を変える」で、そのお題をやめて次のお題へ（ルームはホストだけ）。1台の画面は家のボタンで、はじめの画面へ
- 2文字・3文字のお題は、全部を出し切るまで同じお題を出さない（出し切ったら混ぜ直す）

## ルーム（2026-11-25 追加。オーナーが「順番＋だれでもを選べる」を選んだ）

| 決めたこと | 中身 |
|---|---|
| 変える人 | ホストが待合室で「順番に」（はじめの値）か「だれでも」を選ぶ。順番は入った順（ホスト→参加した順→端末なしの参加者は足した時刻の順） |
| 順番のとき | 番の人だけが文字を押せる。番の人とホストは「パス」で、つぎの人へ。変えたら、つぎの人の番 |
| だれでものとき | 遊ぶ人とホストのだれが押してもよい。同時に押したときは、先に入った1つだけを残し、遅れた人には「ほかの人が先に変えたよ」と出す（transaction の中で、押す前のことばの数と同じかを見る） |
| 1つ戻す | ホストと、最後に変えた人（つぎの手がまだのとき）。順番のときは、戻したことばを変えた人の番にもどす |
| ヒント | ホストだけが押す。みんなの画面に同じヒントが出る（段はルームに `game/hint: { n: ことばの数, stage }` で持ち、ことばが変わったら消える） |
| お題 | ホストが待合室で選ぶ。2文字・3文字は、そのルームでまだ出していないお題から（`seen/c2`・`seen/c3` に番号を残し、出しきったら空にする）。自分で決めるお題は、ホストが待合室で書く（ホストの画面にだけ持つ） |
| ゴールのあと | ホストが「次のお題」（自分で決めるお題のときは「お題を決めなおす」＝待合室へ）か「待合室にもどる」。つぎのお題は、前のお題で最後に変えた人のつぎの人からはじめる |
| 途中参加 | できる（協力なので、遊んでいる途中に入っても困らない）。入った人は順番の最後に入る |
| 人数 | 遊ぶ人は12人まで（端末なしの参加者をふくむ）。端末なしの参加者は4人まで |
| ホストも遊ぶか | はじめは「遊ぶ」（メンターもいっしょに考える協力のあそびで、ホストだけが知る答えがないため）。外すと「進行役」の印を出し、順番に入れない。進行だけのホストは、端末なしの参加者の番に代わりに押す・パス・ヒント・お題を変えるができる |
| 端末のない参加者 | 作る。待合室でだけ足す・外す（`proxies/{名前}: { addedAt }`。在室を持たない）。その子の番はホストの画面に「○○の番。代わりに入れてね」と出し、ホストが押す。手は番の子の手として残す。印「端末なし」はホストの画面にだけ出す |
| マイクを使わない子 | ひとことのボタンは置かない。自分の端末で、自分の番に文字を押せば加われるため（声で相談しなくても進められる）。必要になったら ui.md の形で足す（言葉はオーナーの承認が要る） |
| 名前を出さない | ここまでのことばに、だれが変えたかは出さない（だれが多く変えたかを比べる形にしない）。出すのは、いまの番の人の名前だけ |

### データ（`hitomojichange_rooms/{コード}`）

```
status: 'waiting' | 'playing'
host, hostUid, hostConnected, hostDisconnectedAt, createdAt
settings: { hostPlays: true, order: 'turn' | 'free', level: 'two' | 'three' | 'custom' }   # キーがないときは、この値として読む
players/{名前}: { isHost, uid, joinedAt }
proxies/{名前}: { addedAt }
seen: { c2: [お題の番号…], c3: [...] }
game: { id, puzzle: { chars, start, goal }, ladder: [{ w: ことば, by: 変えた人 }], cleared, hint: { n, stage } | null, turn: 名前 | null, turnAt }
```

- 操作はすべて、ルーム全体への transaction の中で `logic.js` の決まり（`move`・`undo`・`pass`・`hint`・`newGame`・`backToWaiting`・`addPlayer`・`leave`）を呼ぶ
- **番の人がいなくなったとき**（タブを閉じた・通信が切れた）は書きかえない。`turnOf()` が「記録した番の人がいなければ、その人のあと（`turnAt` より後）に入った人、いなければ先頭」として読む。だれかが手を進めたときに、その形で書きなおされる
- **番の途中でいなくなった人が戻ったとき**は、すでにつぎの人へ移っていた番を戻さない（`addPlayer`。戻った人は順番の最後に入る）。再読み込みの一瞬でも同じ
- 自分で抜けた（「退出する」）ときは、番だったらつぎの人へ書きかえる（`leave`）

### 切断・削除・再接続（共通の形）

- ホストの切断は `hostConnected: false`・`hostDisconnectedAt`。ゲストには「ホストの戻りを待っています」を出し、期限（2分）を過ぎたら消す。切れた時刻が変わったら期限のタイマーを仕掛けなおす（`orphanAt`）
- ゲストの切断は在室（`players/{名前}`）だけを消す。遊んでいる途中でも同じ名前で入りなおせる
- **終わったあとの自動削除はしない**（rtdb.md の公認バリアント「ふりかえり画面滞在中は削除しない」。ゴールのあとも続けて次のお題で遊ぶため）。消えるのは、ホストの「ルームを閉じる」・ホストの切断の期限・次に開いたときの期限切れの掃除
- 作成・参加は送信後の切断でやり直す（`transactRetry`。自分のルーム・自分の在室が届いていたら成功として扱う）
- 再読み込みは sessionStorage（`hitomojichange_session`）で同じルームへ戻る。参加用のリンク（`?room=`）・QRコードも共通の形

## 判定のしかた（意図的な設計）

- **途中のことばがあるかどうかを機械で判定しない**。みんなで「あり」と決めれば進む（もじそろえゲームと同じ考え）。辞書を持つと、方言や子どもが知っていることばが弾かれて、言い合いの種になるため
- ゴールは、いまのことばがゴールのことばと同じになったときだけ自動で出す
- `VOCAB` は、ヒントと「ほかのつなぎ方の例」を探すためだけに使う（幅優先探索のいちばん短い道）。リストにないことばを出しても止めない。リストにないことばからでも、1文字ちがいでリストのことばにつながればヒントは出る

## 比べない・点をつけない

- 点数・順位・時間制限はない。ゴールの画面は「N回の変更でつながった」だけを出す
- 「ほかのつなぎ方の例」は、自分たちの道と同じときは出さない。例の回数と自分たちの回数を並べて比べる言い方はしない

## お題データ（`words.js`）

| 名前 | 中身 |
|---|---|
| `PUZZLES` | `{ chars, start, goal }`。2文字31題・3文字15題 |
| `VOCAB` | ヒントに使うことばのリスト（約380語。2文字と3文字） |

### お題の確かめかた

- どのお題も、`VOCAB` のことばだけでつながることを確かめてから入れる（2026-11-25 時点で、2文字は2〜5回、3文字は3〜6回でつながる）。ブラウザでヒントを2回ずつ押してゴールまで行けることでも確かめられる
- `VOCAB` のことばは、ルートの AGENTS.md「使用しない表現・トピック」に当たらないものだけにする（学校・こわい・恋愛のほか、見た目をからかうのに使われうることばも入れない。例: おかめ を外した）。ヒントの例として画面に出るため
- お題を足したら `node scripts/content-audit.mjs` で重複と禁止題材を確かめる（台帳は `COVERED_APPS`。`はじめ→ゴール` の形で登録している）

## 自分で決めるお題

- ひらがな（カタカナは自動でひらがなにする）・同じ文字の数・2〜5文字・ちがうことば、のときだけ始められる
- つながるかどうかは確かめない（つながらないお題でも遊べる。ヒントが見つからないときは、そう出す）

## メンター向けの心得

- 声を出さない子は、チャットで「1文字目を『か』」のように送ってもらい、メンターが押す
- 出たことばが「ある」かどうかで迷ったら、言った子に意味を聞いてみんなで決める。迷ったら「あり」寄りでよい
- 詰まったら、まず1回目のヒント（変える場所）だけを出す

## 共通モジュールの使用箇所

- `howto.js`: あそびかたモーダル（説明スライドの入口つき）
- `rtdb-utils.js`・`room-qr.js`: ルームの接続・コード・リンク・QR。`overlay-a11y.js`: ホストの戻りを待つ画面。`focus-keep.js`: 描きなおしでキーボードの位置を残す
- `stats.js`: 開いた回数。1台の画面はお題を始めるたびに `chars2` / `chars3` / `custom`、ルームは `room-create`・`room-chars2` / `room-chars3` / `room-custom`・`players-{N}`・`room-clear` を数える
