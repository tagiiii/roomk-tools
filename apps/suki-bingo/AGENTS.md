# 好きなものビンゴ 仕様書

## 目的・使用シーン

テーマにそって好きなものを9個選んでビンゴカードを作り、ホストがひくのを見る、運まかせのルーム参加型ゲーム。
調子が低い日や初参加の子でも入れるように、考えることを最初の1回（カード作り）だけにした。
ひかれるたびに「だれが選んでいたか」が名前で出るので、知り合うきっかけになる。
ビンゴは遊びの一般名称として使っている（特定の商品から着想したものではない）。

| 項目 | 内容 |
|------|------|
| 人数 | カード2枚から（ホストが遊ぶなら1対1も可）。ゲストは9人まで、カードは10枚まで |
| 所要時間 | 1ゲーム5〜10分 |
| 使う場面 | サークルタイム・ひろば・ボドゲクラブ |

### 経緯（2026-10-12）

「いまのツール群に足りないもの」の検討で、ボドゲクラブ向けのゲームのほとんどが推理・ブラフ・言語化を求めることから、
頭を使わなくても参加できる運まかせのゲームとしてオーナーが採用した。同日、1台で動く試作（`drafts/suki-bingo/`）を作り、
オーナーの承認を受けてルーム型の本体にした。

オーナーが決めたこと:

| 点 | 決めた内容 |
|---|---|
| カードの作り方 | 候補から選ぶだけ（文字は打たない）。全員が同じ候補から選ぶので、ビンゴが成り立ち、重なりが見える |
| ひき方 | アプリがランダムにひく（手番も発言もない） |
| 選んだ人の見せ方 | 名前で出す |
| 終わり方 | 決まった回数で終了。ビンゴの本数は出すが、順位は出さない |
| ルームに入れない子 | ホストが代わりにカードを作る |

## 技術と保存

- Realtime Database と匿名認証。パスは `sukibingo_rooms/{roomCode}`、再接続用の sessionStorage キーは `sukibingo_session`
- 構成は `index.html` + `app.js`（ES module）+ `style.css`。CSS 接頭辞は `.sb-`（BEM）。index.html・app.js・style.css を変えたら `?v=` をそろえて上げる
- 描画はすべて DOM API（textContent）。innerHTML は使わない
- 保存するのは進行用の一時状態だけ。カード（cards）はそのゲームの間だけルームに置き、つぎのゲームへ進むとき（テーマを選ぶ画面に戻るとき）とルームを閉じたときに消える。ホストが「ルームを閉じる」を押さずにタブを閉じた場合は、最後のゲームのカードがルームの削除（TTL 後の次回アクセス時の掃除）まで残る（rtdb.md の全体共通の制約）。sessionStorage には再接続用の `{role, nickname, roomCode, uid, joinedAt}` だけを置き、カードの中身は入れない
- 利用回数は stats.js の `open` と、ホストが選んだテーマ（`theme-{id}`）だけを数える。だれが何を選んだかは数えない
- 開発・静的監査から本番 Firebase に書き込まない

## 役割と人数

- ホストはルームを作る人（メンター）。待機画面のチェック「自分もプレイヤーとして参加する」は**既定で ON**（1対1で遊べるようにするため。ビンゴには隠す情報がないので、ホストの画面をそのまま共有してよい）。OFF のときは進行だけ。切り替えは待機画面だけ
- ビンゴを始められるのは、カードが2枚以上あるとき（ホストが代わりに作ったカードも数える。全員がチャット参加でも、ホストが全員分を作れば遊べる）
- 途中参加はどの画面でもできる。カードを作る間に入ればそのゲームから、ひいている途中・結果の画面ならつぎのゲームから遊べる（それまでは見ているだけ）
- 切断から戻る人は、人数の上限を超えていても戻れる（参加したときの順番のまま）

## 進行

1. ホストが「ルームを作る」。参加する人は「ルームに参加する」で名前 → ルームコード → 「参加する」の順に入れる
   - 参加用のリンク `?room=CODE` と「リンクをコピー」。共通仕様は docs/development/rtdb.md「参加用のリンク」（作りは気持ち当てゲーム・カギあわせと同じ）。入口は app.js 末尾の起動時の処理（`?watch=` → `?room=` → 保存した記録の順）、参加画面は `screen-join`（ヒント `#joinLinkHint`・`openJoinFromLink`）。`?room=` は `connectToRoom` でアドレスから外す
2. **待機（waiting）**: ホストがテーマ（①〜⑥）とひく回数（8回・10回・12回。初期値10回）を選び、「このテーマでカードを作る」を押す。テーマとひく回数は、押すまでホストの端末の中だけで持つ
3. **カードを作る（picking）**: 遊ぶ人は、16個の候補から9個を選んで「このカードで決める」。選んだ順に 3×3 にならぶ
   - 「おまかせで選ぶ」は、残りのマスをランダムに埋める（1つも選ばずに押せば全部おまかせ）
   - 決めたあとも、ビンゴが始まるまでは「カードを作りなおす」で、前に選んだものを入れた状態から選びなおせる
   - ホストには「ルームに入れない人のカードを足す」が出る。名前を入れ、チャットで教えてもらった番号を押すか「おまかせで選ぶ」で作る。「このカードを取り消す」で消せる
   - カードを作った人がいなくなったとき（タブを閉じた・接続が切れた）は、一覧に「できた（接続が切れています）」と出て、ホストがそのカードも「このカードを取り消す」で消せる（別の端末・別の名前で入りなおして、前のカードが残ったときのため）。在室している人のカードは、本人しか作りなおせない
   - ホストは、カードが2枚以上あれば「ビンゴをはじめる」を押せる。まだ作っている人がいるときは確認を出す（始めると、その人は今回は見ているだけ）
   - 「テーマを選びなおす」で待機へ戻る（作ったカードは消える。カードがあるときは確認を出す）
4. **ビンゴ（playing）**: ホストが「ひく」「つぎをひく」を押すたびに、まだひいていない候補から1つをランダムにひく
   - ひいたものを大きく出し、その下に「選んでいた人」を名前で出す。新しくビンゴ・リーチになった人も知らせる
   - 各自の画面に「あなたのカード」と、ほかの人のカード（小さな目印とビンゴの本数。「カードを見る」で開く）を出す
   - 自分のカードがない画面（みんなにみせる画面・進行だけのホスト・途中から入った人）は、全員のカードを開いて出す
   - ひく演出（候補がぱらぱら切り替わる。約1秒）は端末ごとに再生する。途中から入った・読み込みなおした・タブを隠していた・動きをへらす設定の端末は、演出なしで今の状態を出す。演出の途中でタブが隠れたら、その場で打ち切って今の状態を出す（`visibilitychange`）
   - 決まった回数をひいたら、ボタンが「結果を見る」になる。途中でも「ここで終わりにする」（確認あり）で結果へ進める
5. **結果（result）**: 「選んだ人が多かったもの」（2人以上が選んだものを多い順に3つ。3つ目と同じ人数のものは切らずに全部出す）、「ひとりだけが選んだもの」、「みんなのカード」を出す。ホストの「ちがうテーマでもう一度」で2へ戻る
6. 終わるときは、ホストが「ルームを閉じる」（確認あり）。ルームを消して全員トップへ戻る

## ルーム状態

```
waiting ─このテーマでカードを作る→ picking ─ビンゴをはじめる→ playing ─結果を見る／ここで終わりにする→ result
   ↑            └テーマを選びなおす┘                                                              │
   └────────────────────────────── ちがうテーマでもう一度 ─────────────────────────────────────────┘
どの状態でも: ホストの「ルームを閉じる」→ ルーム削除 → 全員トップへ
```

| キー | 内容 | 書く人 |
|------|------|--------|
| `status` | `waiting` / `picking` / `playing` / `result` | ホストの transaction だけ |
| `host` / `hostUid` / `createdAt` | 作成時に確定 | ホスト（作成時） |
| `hostPlays` | ホストが遊ぶか（待機中だけ変えられる） | ホスト |
| `hostConnected` / `hostDisconnectedAt` | ホストの接続状態 | ホストの onDisconnect と在室復帰 |
| `round` | カードを作る画面に入るたびに +1（画面には出さない） | ホスト |
| `theme` / `drawTotal` | テーマの id と、ひく回数 | ホスト |
| `drawn` | ひいた候補の番号（ひいた順の配列） | ホスト |
| `players/{name}` | `{isHost, uid, joinedAt}`。ゲストは切断で消え、戻ると同じ joinedAt で復帰 | 本人・ホスト（作成時） |
| `cards/r{round}/{name}` | `{uid, joinedAt, cells[9]}`。ホストが代わりに作ったカードは `proxy: true` で uid はホスト。常に1ゲーム分だけ | 本人（picking 中だけ）・ホスト（代わりのカード） |

- transaction はすべてルーム全体に対して行い、中で `hostUid`（ホストの操作）・`status`・`round` を確かめる。ひく操作は「いまのひいた数」も照合する（連打・再実行で2つ進まない）
- カードの書き込みは `cards` を今のゲームの分だけにして書く（前のゲームの分は残らない）。遷移後に届いた古い書き込みは `status`・`round` の照合で弾く
- **名前の予約**: 今のゲームのカードの uid が自分と違う名前、またはホストが代わりに作ったカードの名前では、参加・復帰できない。切断中の人や代わりのカードの名前を別の人が使って、そのカードを引き継がないため（つぎのゲームへ進むと予約は外れる）
- **接続が切れている間に、ホストがその人の名前でカードを作ったとき**: その人の端末は、接続が戻っても在室に戻れない（名前をホストのカードが予約しているため）。かわりに、そのカードを「あなたのカード」として見せ、カードを作る画面には「ホストが、あなたのカードを作ってくれたよ」と出す（作りなおしはできない。ホストが取り消せば、自分で作れる）。在室には、つぎのゲームで戻る。読み込みなおすとトップへ戻り、同じ名前では入れない
- ひく候補は transaction の外で1回だけ決め、中では「ひいた数が同じ・まだひいていない」ことだけを確かめる（transaction が再実行されても、ホストの画面に先に出した候補が入れかわらないため）
- ゲストの明示退出は、自分の在室と、カードを作る間（picking）の自分のカードだけを消す。ひいている途中・結果の画面で退出したときは、表示が途中で変わらないようにカードを残す
- 参加・再接続は `warmRoomCache`（先に値を購読）してから transaction を実行する（空のキャッシュで中止されないため）
- 画面の各部分は `renderKeyed`（中身を表す key が同じなら作り直さない）で描く。ほかの人の操作で再描画されても、フォーカス・開いた「カードを見る」・マスが開く演出を保つため。表示に使う値を増やしたら、key にも入れる

## みんなにみせる画面（画面共有用・見るだけ）

ルームに入れない子が、候補の番号と自分のカードを見るための画面。ホストは別のタブで開いて、それを共有する。
（ビンゴには隠す情報がないので、ホストの画面をそのまま共有してもよい。みんなにみせる画面は、全員のカードが最初から開いている点がちがう）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけに出る。クリックの中で同期的に `window.open(url, '_blank', 'noopener')`）②トップの「みんなにみせる画面をひらく」→ ルームコード → 「画面をひらく」③アドレスの `?watch=CODE`（最優先。起動時に再接続の記録を消してから入る。無効なら通知してトップへ）
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。値を読むリスナーだけで、players に入らない・切断予約をしない・期限切れのルームも消さない・`cancelRoomOnDisconnect` も呼ばない
- **出すもの**: 待機（参加者・ルームコード）／カードを作る（番号つきの候補の一覧（押せない）・番号を9個ホストに伝える案内・だれができたか）／ビンゴ（ひいたもの・選んでいた人・全員のカード）／結果（参加者の画面と同じ）
- **終わり**: ホストがルームを閉じたら「このルームは閉じられました」、期限切れなら「このルームは終わりました」を出し、購読とタイマーを止める。「トップへ戻る」は購読を止めてアドレスから watch を外すだけで、ルームには触らない
- **見分けやすさ**: 開いている間はタブの題名を「みんなにみせる画面 | …」にし、見出しの下に「みんなにみせる画面」の札を出す
- 描画関数は参加者の画面と共用している（spectator の nickname は null なので「あなた」の札・自分のカードは出ない）。描画を変えるときは、みんなにみせる画面でも確かめる

## 切断・再接続・削除

- ホスト: `onDisconnect().update({hostConnected:false, hostDisconnectedAt})`。ゲストには「ホストの戻りを待っています」を出す。接続が戻ると `.info/connected` で在室を戻す
- ゲスト: `players/{name}` を `onDisconnect().remove()`。カードは players の外にあるので残り、切断中もビンゴは進む。戻ると在室を戻す
- 削除は公認バリアント「ふりかえり画面滞在中は削除しない」（docs/development/rtdb.md）を採用: ①ホストの明示的な「ルームを閉じる」（`cancelRoomOnDisconnect` を await してから remove）②ホスト切断から2分の TTL（`ORPHAN_TTL_MS = 2 * 60 * 1000`、`isRoomExpired`・`RoomkRTDB.now()`）③次回アクセス時の期限切れ掃除（status の無いゴーストも対象、applyLocally:false）
- 自分で退出・ルームを閉じる途中は `state.leaving` でルームの変化を無視する（「ルームが閉じられたよ」を自分に出さない）

## 心理的安全

- **順位を作らない**。人の並びは、どの画面でも参加した順のまま。ビンゴの本数で並べ替えない・「1位」「勝ち」「負け」を使わない
- ビンゴの本数とリーチは出す（ビンゴの楽しさそのもの）。ビンゴが0本の人には何も出さない（「0本」「ビンゴなし」と書かない）。リーチは、ひく回数が残っている間だけ出す
- 結果の画面で数えるのは「候補ごとに、だれが選んでいたか」だけ。人ごとの集計（いちばん重なった人など）は作らない
- 好きなものは、深く考えずに選んでよい。「おまかせで選ぶ」を主な操作のすぐ下に置き、おまかせで作ったカードとそうでないカードを区別して見せない
- 選んだ理由を聞く欄は作らない
- ひく回数は初期値10回（試算で、約84%の人が1本以上ビンゴになり、ならなかった人もほぼ全員リーチで終わる）。8回は約56%、12回は約98%（本数の差が1本〜4本と大きくなる）

## テーマと候補の方針（`THEMES`）

- 1テーマ16語。だれでも知っていて、好き・きらいが分かれても軽い話題で済むものにする
- 学校・勉強・登校・恋愛・暴力・ホラー・死・お金・家族のもめごとを連想させる語は入れない。商品名・作品名・実在の人物名は入れない
- 通常表記（漢字まじり・ふりがななし）。3×3 のマスに入る長さ（8文字くらいまで）にする
- ルームではテーマの `id` と候補の番号だけを共有するので、**`id` は変えない・候補の並べ替えや途中の削除はしない**（遊んでいる途中のタブと食い違う）。テーマを足すときは末尾に足し、足した直後は古い画面のタブが「画面が古いみたい」の案内になる
- 色のテーマだけ、語のとなりに見本の色（`c`）を出す
- `scripts/content-audit.mjs` が、1テーマ16語・空の語なし・同じテーマ内の重複なしを確かめる（ほかのアプリのお題と同じ語があるのは、ありふれた名詞を使うため問題にしない）
- テーマと候補を本体に足す・変えるのはオーナーが決める（ルート AGENTS.md「新規コンテンツの本体投入は人間専任」）

## 意図的な逸脱

- **分割構成の RTDB アプリ**: 気持ち当てゲーム・カギあわせと同じ。lint の REF-4（TTL 定数）と REF-5（タイマー解放）は、`RTDB_HTML_FILES` のとなりの app.js も見る
- **hostPlays の既定 ON**: 1対1で遊べることを優先（気持ち当てゲームと同じ）。隠す情報がないので、ホストの画面を共有しても困らない
- **どの画面でも途中参加できる**（ひいている途中に入った人は、つぎのゲームまで見ているだけ）
- **「ルームに入れない人のカードを足す」は控えめなボタン（`btn-ghost`）**: ホストが自分のカードを選んでいる間、「おまかせで選ぶ」「ビンゴをはじめる」と合わせて枠線ボタンが3つ並ばないようにするため
- **ポータル・早見表の人数「2〜10人」はカードの枚数**（遊ぶ人数。ホストが進行だけのときは、ホストを数えない）
- **候補ボタンが9個そろったあとの残り**: `disabled` ではなく `aria-disabled` と見た目で押せないことを伝える（`disabled` にすると、押した直後にフォーカスが外れることがあるため）

## 入れない機能

- 順位・ランキング・点数・履歴・書き出し
- 自由入力の候補（自分で書いた好きなもの）。全員が同じ候補から選ばないとビンゴが成り立たないため。入れるなら「16個のうち何個かを参加者が出し合う」形になるが、準備の時間と入力の手間が増える
- 手番（順番に自分の好きなものを言う）・時間制限・自動で進む処理
- ひいている途中のカード作り（途中参加の人がひかれたものを見てから選べてしまうため）
- 選んだ理由を書く欄

## メンター向けの心得（画面には出さない）

- ルームに入れない子がいるときは、「みんなにみせる画面」を共有して、カードを作る画面の候補の番号を見せる。番号を9個チャットで送ってもらい、「ルームに入れない人のカードを足す」で作る。選ぶのが重そうなら「おまかせ」でよい
- ホストの画面をそのまま共有するときは、ビンゴの画面で、代わりに作ったカードの「カードを見る」が最初から開いている（その子が自分のカードを見られるように）
- 「選んでいた人」が出たら、「〇〇さんもカレーが好きなんだね」のように、同じものを選んだ人どうしをつなぐ。理由は聞き出さない（言いたい人だけ）
- ビンゴの本数で盛り上げすぎない。ビンゴにならなかった人がいても、取り上げない
- 終わるときは必ず「ルームを閉じる」を押す（押さずにタブを閉じると、最後のゲームのカードがしばらくルームに残る）
