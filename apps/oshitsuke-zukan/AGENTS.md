# おしつけずかん 仕様書

## 目的・使用シーン

ごきぶりポーカー（Kakerlakenpoker）に着想を得たブラフカードゲームのオンライン版。
イヤ〜な生き物のカードを「これは ムカデ です」のような宣言つきで押しつけ合い、
受け取った人は「ホントかウソかを当てる」か「こっそり見て別の人に回す」かを選ぶ。
同じ生き物を4枚引き取ってしまった人のひとり負け。

- **core value**: 「裏向きカードの受け渡し」というオンラインでは実物で再現できない部分だけをアプリが担い、宣言まわりの駆け引き・演技（ゲームの本体）は Metalife の声とチャットで行う。
- 対象: 小学校中学年〜中学生。ボドゲクラブ（`data-scenes="bodoge"`）。
- 3〜6人。**ホストもプレイヤーとして参加する**（かくれナンバーと異なりファシリテーター専任ではない）。
- **音声なしでチャット参加する子も完全に遊べること**が必須条件。ゲームの全アクション（宣言含む）はアプリ内のボタン操作で完結し、声はあくまで追加の演出とする。

> 原典「ごきぶりポーカー」の名称・8種の生き物構成・アートは商標/著作権リスクがあるため使わない。
> ルール構造のみ参照し、名称・生き物ラインナップ・見た目はすべてオリジナル（ピタハメの改名と同じ判断）。

## ゲームルール

### カード

8種 × 各8枚 = 64枚。種別は固定順（丸数字採番・UI 表示順もこの順）:

| # | id | 表示名 | カード色（白文字が乗る濃色） |
|---|----|--------|------------------------------|
| ① | `namekuji` | ナメクジ | `#8D6E63` |
| ② | `mukade` | ムカデ | `#C62828` |
| ③ | `ka` | カ | `#6A1B9A` |
| ④ | `mimizu` | ミミズ | `#AD1457` |
| ⑤ | `hebi` | ヘビ | `#2E7D32` |
| ⑥ | `gejigeji` | ゲジゲジ | `#EF6C00` |
| ⑦ | `hiru` | ヒル | `#37474F` |
| ⑧ | `karasu` | カラス | `#1565C0` |

- 絵文字・イラストは使わない（リポジトリ共通ルール）。カードは**種別色 + カタカナ名**で表現する。
- トーンはユーモラスに。怖がらせる演出（ホラー的表現・効果音）は入れない。

### 配り方

- シャッフルした64枚から **floor(64 ÷ 人数) 枚ずつ**配る（3人=21枚、4人=16枚、5人=12枚、6人=10枚）。
- 余りは使わない。**余りカードは RTDB に書かず、内訳も公開しない**（「何がぬけているか分からない」も駆け引きのうち）。
- 最初の手番はカード配布 transaction 内でランダムに決める。

### 手番の流れ

1. **手番の人（choosing）**: 手札から1枚 + 相手1人 + 宣言（8種から1つ）を選んで裏向きで差し出す。宣言はウソでもホントでもよい。
2. **受け取った人（deciding）**: 2択。
   - **当てる**: 「ホント」か「ウソ」を選んでカードを公開。当たれば**直前に出した人**が、外れれば**自分**がカードを表向きで引き取る。引き取った人が次の手番。
   - **こっそり見る**: 自分だけカードの中身を確認し、**まだ見ていない人**へ新しい宣言（変更可・同じでも可）をつけて回す（passing → 受け取った人がまた deciding）。
3. 「見た人」には**最初に出した人も含む**。回せる相手 = ゲーム中の接続中プレイヤー − 見た人 − 自分。
4. 回せる相手がいない場合（全員見た/切断中）は「当てる」しか選べない（UI 無効化 + transaction でも拒否）。
5. **「こっそり見る」は不可逆**。見たら「当てる」には戻れない。選択前に確認ダイアログを1回挟む（「カードを見ると、『ホント』『ウソ』はえらべなくなるよ。見てまわす？」）。

### 敗北判定（引き取り確定 transaction 内で判定）

1. 引き取った人の同種カードが**4枚**になったら、その人のひとり負けで即終了（`reason: 'four'`）。
2. そうでなければ、引き取った人（=次の手番）の**手札が0枚**なら、その人のひとり負けで終了（`reason: 'empty'`）。
3. 同時成立時は `'four'` を優先して表示する。

負けは1人だけ決まり、残りの人の順位づけ・ランキングはしない。

## 画面構成・フロー

```
TOP（screen-top）
 ├── ルームをつくる → ニックネーム入力 → ロビー（screen-lobby）
 ├── はいる → ニックネーム + コード入力 → ロビー（screen-lobby）
 └── みるだけ → コード入力のみ → 共有ボード（screen-board）
                      ↓（ホストが「はじめる」/ 3人以上）
            ゲーム画面（screen-game）
              フェーズに応じて中身が切り替わる（画面遷移はしない）
                      ↓（敗北確定 / ホストが「とちゅうでおわる」）
            けっか（screen-result）
              ホスト: 「もういちど」（同メンバーで配り直し → screen-game）
                      「トップへもどる」（ルーム削除）
```

### ゲーム画面の構成（全フェーズ共通レイアウト）

- **中央の宣言バナー**: 「◯◯さん → △△さん 『これは ムカデ です』」を大きく表示。声が聞こえない子はここと進行ログで完全に追える。
- **プレイヤー一覧**: 各プレイヤーの「ずかん」（引き取ったカードを種別ごとに表向きで表示。同種3枚は視覚的に強調）+ 手札の**枚数のみ**（種類は非公開）+ 接続状態。
- **自分の手札**: 種別ごとにまとめたタイル表示（種別色 + 名前 + 枚数）。最大21枚を1枚ずつ並べない。
- **進行ログ**: 画面下部に直近8件。「Aさんが Bさんに カードをわたした『ムカデ です』」「Bさんが カードを見た」「Bさんが Cさんに まわした『ヒル です』」「Cさんは『ウソ』をえらんだ → あたり！」の形式。
- **待機表示**: 自分の操作でないときは「いま △△さんが えらんでいます」を表示。
- **のぞき/出したカードの再確認**: 流れているカードを見たことがある人（seenBy に入っている人。最初に出した人を含む）にだけ「あなたが見たカード: ムカデ」を小さく表示し続ける（記憶負荷を下げる）。

### フェーズごとの操作 UI

| phase | 操作できる人 | UI |
|-------|--------------|-----|
| `choosing` | 手番の人 | ①手札の種別タイルから1枚選ぶ → ②宣言を8種から選ぶ（丸数字①〜⑧） → ③相手を選ぶ → 「わたす」 |
| `deciding` | 受け取った人 | 「ホント」「ウソ」の2大ボタン + 「こっそり見る」（確認ダイアログ付き。回せる相手がいなければ無効化） |
| `passing` | 見た人 | カードの中身を確認 → 宣言を選ぶ → 相手を選ぶ（見た人はグレーアウトではなく**非表示**）→ 「まわす」 |
| `resolved` | 引き取った人 | 結果パネル（下記）+ 「つぎへ」。他の人はパネルを見るだけ |

- 結果パネルは自動で消さない。「カードは ムカデ でした！」「△△さんの『ホント』は あたり！／はずれ…」「カードは ◯◯さんの ずかんへ」を、次の手番の人が「つぎへ」を押すまで全員に表示する。
- ボタンの文言は素直な動詞（わたす・見る・まわす・ホント・ウソ・つぎへ）。「ずかん」の比喩の説明は howto とロビーの説明文で一度だけ行う。

## status 遷移

```
waiting → playing → result（敗北確定）
             └────→ aborted（ホストが「とちゅうでおわる」）
result →（もういちど）→ playing
```

| status | 説明 |
|--------|------|
| `waiting` | ロビー。このフェーズのみ新規入室可。3〜6人 |
| `playing` | ゲーム中。`match/turn/phase` が細かい状態を持つ |
| `result` | ひとり負け確定。ホストは「もういちど」「トップへもどる」 |
| | 「もういちど」は**接続中のプレイヤーだけ**で配り直す（切断中・退出済みの人は players から外し、seat を振り直す）。接続中が3人未満なら不可。外された人の画面は「メンバーから はずれたよ」の文言でトップへ戻す |
| `aborted` | 途中終了。**まけなし**（「とちゅうで おわったよ。まけは なし！」）。ホストは「トップへもどる」 |

- `waiting → playing`（開始・配布）、`result → playing`（もういちど）、`→ aborted` は**ホストのみ**。
- `playing → result` は敗北を確定させた judge の transaction 内で行う（ホスト以外も status を書く。逸脱として下記に明文化）。

## turn 状態機械

```
choosing → deciding → resolved → choosing（次の手番）
              ↕
           passing
```

`match/turn` は毎手番書き換える。`resolved` の内容は次の「つぎへ」まで保持する。

## Firebase データ構造（Realtime Database）

パス: `oshitsuke_rooms/{roomCode}/`（共通命名規則。セキュリティルール変更不要）

```
oshitsuke_rooms/{roomCode}/
  ├── host:                string          # ホストのニックネーム
  ├── hostConnected:       boolean
  ├── hostDisconnectedAt:  number | null
  ├── status:              'waiting' | 'playing' | 'result' | 'aborted'
  ├── createdAt:           number          # ServerValue.TIMESTAMP
  ├── players/
  │    └── {nickname}/
  │         ├── isHost:    boolean
  │         ├── seat:      number          # 参加順。表示順の固定に使う
  │         ├── connected: boolean         # ゲーム中の切断検知（jinro 方式）
  │         └── disconnectedAt: number | null
  └── match/                               # 「もういちど」で丸ごと上書き
       ├── round:   number                 # 1始まり
       ├── cards/
       │    └── {cardId}/                  # 配られたカードのみ書く（余りは書かない）
       │         ├── kind:  string         # 8種の id
       │         ├── zone:  'hand' | 'inFlight' | 'taken'
       │         └── owner: string | null  # hand=持ち主 / taken=引き取った人 / inFlight=null
       ├── turn/
       │    ├── phase:      'choosing' | 'deciding' | 'passing' | 'resolved'
       │    ├── actor:      string         # いま操作すべき人
       │    ├── fromPlayer: string | null  # 直前にカードを送った人（判定負け時の引き取り先）
       │    ├── cardId:     string | null
       │    ├── claimKind:  string | null
       │    ├── seenBy:     { [nickname]: true } | null   # 最初に出した人を含む
       │    └── resolved:   { guess, correct, judge, takenBy, cardKind } | null
       ├── log/
       │    └── {pushId}: { t: 'start'|'pass'|'peek'|'forward'|'judge'|'rematch',
       │                    from?, to?, claim?, guess?, correct?, at }
       └── result: { loser: string, reason: 'four' | 'empty', kind?: string } | null
```

### 秘匿情報の扱い（性善説）

- 手札の種別・流れているカードの中身は cards ノードに平文で入り、全端末に届く。表示は**クライアント側フィルタのみ**:
  - `zone === 'hand'` のカードの kind は `owner === 自分` のときだけ描画する。他人の手札は枚数のみ。
  - `inFlight` カードの kind は `turn/seenBy` に自分が入っているときだけ描画する。
- DevTools での閲覧は共通のセキュリティ方針（性善説・スタッフ監視下）どおり許容する。jinro・かくれナンバーと同じパターン。

### データ操作の注意点

- ルーム作成・参加・開始（配布）・turn の全操作・「もういちど」は、すべて**ルームルートへの `transaction()`**。
- turn 操作の transaction では毎回、`status === 'playing'`・`turn.phase`・`turn.actor === 自分`・カードの所在（zone/owner）・相手の適格性（在室・接続中・seenBy 非含・自分以外）を再検証し、不一致なら abort（`return` せず `undefined` を返す）。
- カードの所在は `cards/{cardId}/zone` の**一元管理**。「手札から減らす + inFlight にする」「公開 + taken にする + 敗北判定」はそれぞれ同一 transaction 内で確定する。引き取り枚数・手札枚数は別フィールドに重複保存せず、cards から都度集計する。
- 判定（judge）の transaction 内で敗北条件を評価し、成立時は同じ transaction で `status: 'result'` と `match/result` を書く。
- ログは各 turn / 開始系 transaction の**内側**で連番キー（`l0000`…）により書く。transaction 外の `push()` は、ルーム削除と競合したとき log だけの回収不能ルームを再生成しうるため使わない。ログ時刻は `RoomkRTDB.now()`。

## 切断時の挙動

| 役割 | 挙動 |
|------|------|
| ホスト切断 | 共通規約どおり `onDisconnect().update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })`。他プレイヤーにはカウントダウン付きオーバーレイ。TTL（`ORPHAN_TTL_MS = 2分`）超過で期限切れ扱い → 削除を試みて退出 |
| ゲスト切断（waiting 中） | `onDisconnect().remove()` で `players/{nickname}` のみ削除（共通規約どおり） |
| ゲスト切断（playing 以降） | `onDisconnect().update({ connected: false, disconnectedAt: TIMESTAMP })`。**手札・ずかんは保持**（jinro 方式）。status 変化時に onDisconnect の予約を張り替える |

- 切断中プレイヤーには「◯◯さんの つうしんが きれています」を全員に表示。
- 切断中の人へはカードを**渡せない・回せない**（transaction でも拒否）。
- 切断中の人が手番当事者（actor）のときは進行が止まる。「こっそり見る」のあとに回せる相手が全員切断した場合も同様に止まる。ホストはいつでも「とちゅうでおわる」（確認ダイアログ付き）で `aborted` にできる。自動での途中終了はしない（v1 はホスト判断に一本化）。
- 再接続: sessionStorage キー **`oshitsuke_session`**（roomCode / nickname / isHost）。リロード時 `tryReconnect()` で復帰し、`connected: true` / `disconnectedAt: null` を書き戻す。ホストは `hostConnected: true` / `hostDisconnectedAt: null` も戻す。
- TTL 判定は `RoomkRTDB.now()` / `isRoomExpired()`（サーバー時刻補正）。`joinRoom` / `tryReconnect` / ルーム監視で期限切れルームを検知したら `remove()` を試みる（`cancelRoomOnDisconnect` を await してから）。

## 終了とデータ削除

- `result` / `aborted` 画面ではルームを**自動削除しない**（振り返り・「もういちど」のため。jinro 方式）。
- クリーンアップは ①ホストの「トップへもどる」で即時 `remove()`、②ホスト切断 onDisconnect + 2分 TTL、③次回アクセス時の `isRoomExpired()` 判定、の3経路に一本化する。
- 期限切れルームの削除は、`remove()` 直前にもう一度取得して期限切れを再確認してから行う（判定と削除の間にホストが復帰した場合、生きているルームを消さないため）。削除経路では必ず `cancelRoomOnDisconnect()` を await してから `remove()` する。
- ゲスト側の「トップへもどる」は自分の退出のみ（waiting 中は players から削除、それ以外は connected: false のまま離脱）。

## 共有ボード（screen-board）= 観戦モード

- TOP の「みるだけ」からコード入力のみで入る。ニックネーム不要・`players` に**書き込まない**・上限なし・読み取り専用。
- 表示: 宣言バナー / 全プレイヤーのずかんと手札枚数 / 進行ログ / 結果パネル。**秘匿情報（手札の中身・のぞいたカード）は一切描画しない**。
- 用途: ①メンターが画面共有するとき（自分の参加画面には手札が映るため、共有はこの画面で行う）、②観戦したい子。
- sessionStorage 復帰は不要（コードで入り直せばよい）。

## 文言・UX ガイド

- ひらがな多め・子ども向け。「ずかん」比喩の説明は howto とロビーで一度だけ（「ひきとったカードは じぶんの ずかんに たまっていくよ。おなじ生きものが 4まい そろったら まけ！」）。以降のボタンは素直な動詞のみ。
- 負けの表示はやわらかく、ただし負け自体は消さない: 「◯◯さんの ずかんが ムカデで いっぱいに なっちゃった！こんかいは ◯◯さんの まけ！」。責める演出・順位表示はしない。
- 宣言の8種選択には丸数字 `①〜⑧` を付ける（共通ルール。チャットの子が「③かも！」と反応できる）。
- タイマー・制限時間は置かない（時間圧をかけない方針）。
- 効果音なし。

## 共通規約からの逸脱の明文化

- **turn の更新はホスト以外も行う**: `status` の開始/再戦/中断はホストのみだが、`match/turn` は手番の当事者（actor）が transaction で書く。敗北確定時のみ、judge の transaction が `status: 'result'` も書く（ホスト専任にすると全操作がホスト経由になり遅延・複雑化するため）。
- **ゲスト切断で remove しない（playing 以降）**: 手札・ずかんを保持して再接続に備えるため `connected: false` 方式（先行事例: jinro）。waiting 中は共通規約どおり remove。
- **result 後の自動削除なし**: 「もういちど」（再戦）と振り返りのため（先行事例: jinro, word-wolf, ito）。
- **観戦（共有ボード）モード**: players に入らない読み取り専用ロール。画面共有時の秘匿漏れ対策（本リポジトリ初のパターン）。
- **競争要素（ひとり負け）を意図的に残す**: 「比較を促さない」ガイドラインの例外案件（先行事例: ピタハメ）。ブラフの緊張感がこのゲームの核であるため。ただし順位づけ・ランキング・敗者を責める演出は置かない。
- **カード種別色の固定値**: 8種の識別に design-system 変数以外の固定色8つを使う（種別色はゲームの情報そのものsince 色=種別。変数化より可読性を優先）。

## メンター向け進行のコツ

- このゲームの本体は**宣言まわりの演技と読み合い**。「ウソをついていい」ことがルールで公認されている遊びなので、最初に「ウソ、どんどん ついていいからね」と言っておくと動き出しやすい。
- 画面共有は**必ず「みるだけ」（共有ボード）で行う**。自分の参加画面を共有すると手札が映る。
- 声の子とチャットの子が混ざっていても、宣言・進行はすべて画面に出るので置いていかれない。チャットの子には「あやしいと思ったらチャットで『あやしい！』って書いてね」と促すと参加しやすい。
- 「こっそり見る」を知らない子が多いので、最初の1〜2周は「当てるだけじゃなくて、見てまわすのもできるよ」と声をかける。
- 1ゲームは10〜20分程度。同種3枚たまっている人が出ると終盤。
- 途中で抜けたい子・接続が戻らない子が出たら「とちゅうでおわる」で仕切り直してよい（まけなし表示になる）。
