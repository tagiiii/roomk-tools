# そろってゴール 仕様書

## 目的・使用シーン

みんなでコマを1マスずつ動かして、全員がゴールに入るとクリアの協力パズル（2〜12人）。スイッチに乗っている間だけ開くとびら・2人で押す重い箱・カギ・番号の人だけ渡れる橋など、1人では進めないしかけを、声をかけ合ってこえていく。

- **core value**: 「そこに乗ってて」「いま通るよ」と声をかけ合うことが、そのまま遊びになる。勝ち負けがなく、全員でクリアする
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・サークルタイム・作戦会議（`data-scenes="bodoge hiroba circle sakusen"`。メンターと子どもの2人でも遊べる）。種類は「当てっこ・協力ゲーム」（`data-genre="atekko"`）
- 時間制限なし・やりなおし自由。順位・点数の比較は出さない（星の数と歩数は、そのステージのクリアのときにだけ出す。記録しない）
- 着想元の紹介は**段階3**（早見表は系統ラベル「協力パズル系」だけ・更新情報には書かない。2026-11-12 オーナー）。きっかけはスタッフの要望（市販の協力アクションゲームのような「協力型ミッションゲームがほしい」）だが、遊びの中身は別物（マス目を1歩ずつ進む協力パズル）で、名前・キャラクター・絵・ステージは写していない

> 経緯: 2026-11-12 にスタッフから「協力型ミッションゲームもあったら嬉しい」と届き、案を3つ出してオーナーが「マス目を1歩ずつ進む協力ステージ」を選んだ。同日 `drafts/sorotte-goal/` で試作（PR #208。試作のフォルダは、本体にしたあと 2026-11-13 に消した。中身は git の履歴に残っている）→ オーナーの要望で、絵と動き・難易度・人数（12人まで）・たくさんのステージ・くり返し遊べる仕組み（星）を足し、UI/UX の所見（高・中・低）を直した（PR #210・#213・#214）→ オーナーが本体にすると決め、名前「そろってゴール」・DB ルールへの名前空間の追加・イラストの作成を承認した（2026-11-12）。
> リアルタイムに動かすアクションにしなかった理由: 位置を送り続けると Firebase の無料枠と遅延の両方で厳しい。1歩ずつにして、書くのは押したときだけにした。

## セッション条件（ツール一覧のカードと同じ）

スタッフがツールを選ぶときの条件。値はツール一覧（`apps/index.html`）のカードの札・`data-scenes`・`data-speech`・`data-self` と同じにする。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 2〜12人 |
| 目安時間 | 5〜15分 |
| 利用シーン | ボドゲクラブ・ひろば・サークルタイム・作戦会議 |
| 話す量 | ひとことで・話さなくてよい（「ひとこと」で、決まった言葉をえらんで送れる） |
| 自分の話 | 外の題材で遊べる |

## ルール

| 項目 | 内容 |
|---|---|
| 動かす | 自分のコマを、矢印キー（W A S D でも）か画面の矢印のボタンで、上下左右へ1マス。かべ・ほかの人のいるマスには入れない |
| クリア | 全員がゴール（旗のマス。人数ぶんある）に入るとクリア |
| スイッチととびら | 同じしるし（まる・さんかく・しかく・ほし・ひしがた・プラス・ろっかく・つき）のスイッチに、人か箱が乗っている間だけ、とびらが開く。数字の付いたスイッチは、その数だけ同時におさえる（4人から出る） |
| 重い箱 | 1人では動かない。箱の札の数字の人数が、たてにならんで押すと、箱とならんだ人がそろって1マス進む。ふつうは「2」（押す人のうしろにもう1人）。3人からは、もっと重い箱も出る |
| カギ | カギのマスに入ると持つ（1人1本）。持った人がかぎつきのとびらに入ると、開いたままになり、カギはなくなる |
| 橋 | 番号の付いた橋は、同じ番号のコマだけ渡れる |
| 星 | 1ステージに3つ。とってもとらなくてもいい。とった数は、クリアのときに歩数といっしょに出す |
| すみのカギ・星 | 部屋のすみにあり、入口がとびらか、番号の橋になっている。とびらのときは、1人がスイッチをおさえている間に、もう1人がとりに行く |
| むずかしさ | やさしい（部屋3つ・関門2つ）／ふつう（部屋4つ・関門3つ）／むずかしい（部屋5〜6つ・関門5つ。カギや星が、とびらの先）／げきむず（部屋6つ・関門5つ。どの関門も2人以上で力を合わせる） |
| ステージ番号 | 1〜9,999。むずかしさ・人数・番号から、その場でステージを作る。同じなら、どの端末でも同じステージ |
| 人数 | 2〜12人。人数に合わせて部屋が広がる（4人まで 5×5・8人まで 7×7・12人まで 9×9） |

- ルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/sorotte-goal/engine.test.cjs`
- **ステージの作り方**: 部屋を一列につなぎ（ならび方はくじ）、部屋と部屋のあいだに「関門」を1つずつ置く。関門は、作り方から必ず通れる8種類: とびらのリレー（手前と先にスイッチ）・橋の先のスイッチ・カギ・橋の先のカギ・とびらの先のカギ・重い箱をスイッチへ・みんなで押す箱をスイッチへ（3人から）・同時におさえるスイッチ（4人から）。くわしくは `engine.js` の `generate` の頭の説明
- **むずかしさを上げ、協力を増やした**（2026-11-13 オーナー「難易度を上げて、より協力プレイできるように」）: 番号の橋は「その人の出番」にはなるが、1人でとりに行ける。とびらの先のカギ・星（1人がスイッチをおさえ、もう1人がとる）を足し、「むずかしい」の星はとびらの先に、いちばん上の「げきむず」は関門をすべて協力の要るもの（重い箱・とびらの先のカギ・2つ同時のスイッチ。3人までは橋の先のスイッチが1つ入る）にした。しるしは5つから8つに増やした（使いきったら、橋の先か、ゆかに置く）
- **人数に合わせた協力**（2026-11-13 オーナー「人数が増えたときに、3人以上や4人以上など人数に合わせた協力もほしい」）。数は `engine.js` の `teamFor`・`needFor`

  | 遊ぶ人 | みんなで押す箱（たてにならぶ人数） | 同時におさえるスイッチ |
  |---|---|---|
  | 2人 | 出ない（ふつうの箱の2人だけ） | 出ない |
  | 3人 | 3人 | 出ない |
  | 4人 | 3人 | 2つ |
  | 5人 | 4人 | 2つ |
  | 6人 | 4人 | 3つ |
  | 7人 | 5人 | 3つ |
  | 8人 | 5人 | 4つ |
  | 9・10人 | 6人 | 4つ |
  | 11・12人 | 7人 | 4つ |

  - 箱の人数は、部屋の通り道に収まる数まで。スイッチの数は、おさえた人も先へ行けるように、通る人がおさえる人より少なくならない数まで（手前と先に、同じ数ずつ置く）
  - 「ふつう」ではくじで出ることがあり、「むずかしい」「げきむず」ではよく出る。「げきむず」は、3人なら3人で押す箱が2つ、4人からは、みんなで押す箱と同時のスイッチが必ず入る
  - 全員がそろわないと進めないしかけは作っていない（1人が席を外しても止まらないように、いちばん多くても12人のうち7人）
- **解けることの確かめ**: 2人は、4つのむずかしさすべてで、テストで総当たりして解ける（やさしい40個・ふつう20個・むずかしい12個・げきむず12個。いちばん少ない歩数は、やさしい45歩まで・げきむず117歩まで）。1人だけでは解けないことも確かめている。3人は、やさしい4個と、3人で押す箱の入った「ふつう」1個。**4人以上は総当たりでは確かめていない**（組み合わせが多すぎる。関門の作り方で通れる形にしている）。解けないステージが見つかったら、ホストが「ほかのステージにする」で飛ばせる
- **詰み**: 重い箱を押しすぎると、スイッチまで運べなくなることがある。`E.stuck` が「箱が、箱で開けるとびらのスイッチ（ステージを作るときに `boxSw` に入れてある）にもう届かない」ときに気づき、やりなおしを案内する。判定は箱だけを見た目安（「とびらの中からなら押せる」場面は詰みと出ることがあるので、文は「〜みたい」）
- 手で作った2人用の3ステージ（`engine.js` の `FIXED`）は、ルールのテストで使う。画面からは選べない

## 画面で気をつけたこと

- **盤は1画面に収める**: 盤の大きさを、はばと画面の高さの両方に収まるように決める。操作・遊ぶ人の一覧・説明は盤の横（900px 以下は下）
- **番号が読める**: コマの左上に番号の札。橋の番号の札も大きく。色だけに頼らない（12色には近い色がある。番号と、頭のかざり4種類 × 体の形2種類でも見分ける）
- **自分のコマが見つかる**: 自分のコマの上に「あなた」の印。マスが小さいとき（人数が多い・画面がせまい）は盤を大きくして、動かすコマのまわりを映す（「全体を見る／近くを見る」）。みんなにみせる画面・進行だけのホスト・見る番の人は、いつも全体
- **進めない理由をその場で出す**: 進めなかったとき、自分の画面にだけ一言（「重い箱は、うしろからもう1人が押すと動く。」など）。ほかの人の画面には出さない
- **動きの量**: 5人からは、体と頭のかざりがゆれるのを自分のコマだけにし、ゴールの台の動きを止める。端末の「動きを減らす」設定では、くり返す動き・はねる動き・紙ふぶきを止める
- **音は鳴らさない**
- **スマホ**: 盤のわくの高さを、下に矢印のボタンが入り、右下の固定のボタン（？など）にかからない高さにする（`camera`）。マスが小さいので、はじめから近くを映す
- 歩数は、あそんでいる間は出さない（少ないほどよい、と受け取られやすいため）。クリアのときに「ぜんぶで○歩」とだけ出し、目安や評価は付けない
- だれがスイッチからおりた・だれが箱を押しすぎた、のような「だれのせいか」は画面に出さない

## くらやみ・砂時計（ホストが選ぶ設定。はじめは、どちらも「なし」）

2026-11-13、オーナーの「制限時間などあったら面白い機能は？」に案を5つ出し、オーナーがこの2つを選んだ。待合室の「くわしい設定」（たたんである）で選ぶ。

**くらやみ**
- 自分のコマ（ホストは、代わりに動かしているコマも）のまわり2マス（たて・よこ・ななめ。5×5）だけが見える。前に見たマスは、うす暗く残る（かべやしかけの場所はおぼえている）。人・箱・カギ・星は、いま見えている所だけ出す
- **みんなにみせる画面・進行だけのホスト・見る番の人は、みんなの明かりを合わせた範囲が見える**（だれも行っていない所は見えない）。画面共有していても、行っていない所は分からないので、「行って見てくる」「見えた所を伝える」が要る
- クリアしたら、ぜんぶ見せる
- 見える範囲は端末の側で決めるだけ。ルームには何も書かない（通信は増えない）。見えていない所のデータも端末には届いている（性善説。ルートの AGENTS.md「セキュリティ方針」）

**砂時計**
- 3分・5分・10分から選ぶ。ステージごとに、残り時間を星のとなりに出す（のこり30秒からは色が変わる。音・点滅はなし）
- **0になっても終わりではない**。「時間だよ」と出して、ホストが「このままつづける」（そのステージの砂時計を止める）か「ほかのステージにする」をえらぶ。えらぶまでは、コマを動かせない。失敗の表示にしないのは、だれのせいかという空気にしないため
- 時間内にクリアすると、クリアの札に「時間内にクリア！（のこり 1:23）」と出る
- 残り時間は、それぞれの端末が `game.startAt`（ステージをはじめた時刻）と `game.limit`（分）から出す。**時間のための書き込みはしない**（書くのは、クリアした時刻 `play/{id}/doneAt` を1回と、「このままつづける」の1回だけ）
- ホストが切れている間は、切れた時刻で止める。戻ったときに、切れていた分だけ `game.startAt` をずらす

## ひとこと（決まった言葉をえらんで送る）

マイクを使わない子も伝えられるように、声のほかの手段を用意した（2026-11-13 オーナー「マイクOFFの子ども用に、選択肢で会話できるチャット機能がほしい」。形は `docs/development/ui.md`「マイクを使わない子が参加できる手段」）。

- 横の「ひとこと」を押すと言葉の一覧がひらき、1つえらぶと、**自分のコマの上の吹き出し**と、横の遊ぶ人の一覧に6秒出る（みんなにみせる画面にも出る）。場所で伝わるので、「だれに」はえらばない
- **自由に打つ欄は置かない**。言葉は `app.js` の `SAYS` にまとめてある。足す・変えるときはオーナーが決める

  | 言葉（14こ） |
  |---|
  | スイッチに乗るよ／スイッチに乗って |
  | そこで待ってて／いま通って |
  | 箱を押そう／うしろから押して |
  | カギをとるよ／こっちに来て |
  | ちょっと待って／どうする？ |
  | OK／ありがとう |
  | ナイス！／たすけて |

  この14この言葉は、2026-11-13 にオーナーが一覧を見て承認した。人の名前をえらぶ言葉（吹き出しがコマの上に出るので、場所で伝わる）と、相手の動きを否定する言葉（「ちがうよ」など）は入れていない。
- **ひとり5秒に1回まで**（端末で止め、早いときは「あと○秒」と出す）。送れるのは、コマを動かせる人だけ（自分のコマ。ホストは、代わりに動かしているコマの分も送れる）。進行だけのホスト・見る番の人・みんなにみせる画面は送らない。音は鳴らさない
- データ: `play/{game.id}/say/{席の番号}` に `"言葉の番号.何回目"`（同じ言葉を続けて送っても、変わったと分かるように回数を付ける）。吹き出しは、届いてから6秒（ステージの画面を開いた時点でもう置いてあった言葉は出さない）
- 配慮の理由は画面・あそびかた・更新情報に書かない

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（ステージの途中なら、見る番でステージの画面）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting）: 遊ぶ人（参加した順に番号）・ホストは「ホストも遊ぶ」・むずかしさ・ステージ番号・「はじめる」。端末なしの参加者を足す欄は、たたんだ「そのほかの操作」の中
  ↓「はじめる」（遊ぶ人が2人以上）
ステージ（screen-game）: 盤・星・しかけの名前／横に、自分の表示・矢印のボタン・遊ぶ人の一覧・説明・ホストの「そのほかの操作」
  ↓ 全員がゴール
クリア（同じ画面）: ホストに「次のステージへ」「もう一回」。参加者には「ホストが次のステージをえらぶよ」
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「はじめる」、クリア「次のステージへ」）
- ホストの「そのほかの操作」（ステージの画面）: 「このステージをやりなおす」「ほかのステージにする」「待合室へ」。1歩でも進んでいたら確認を出す
- **やりなおし・次のステージ・ほかのステージは、ホストだけ**（1人の押しまちがいで全員の進みが消えないように）
- **遊ぶ人**: ルームに参加している人みんなと端末なしの参加者。参加した順にコマの番号が決まる。ホストは「ホストも遊ぶ」（はじめはオン。メンターと子どもの2人で遊べるように）を外すと進行だけ。12人まで（13人目は「このルームはいっぱいだよ」で、みんなにみせる画面を案内する）
- **途中から入った人**は、そのステージは見る番。ステージを作りなおすとき（次のステージ・やりなおす・ほかのステージ）に、いま参加している人で遊ぶ人を決めなおすので、そこから入る。いなくなった人は外れる
- **端末なしの参加者**（4人まで）: 待合室でホストが名前を足す。その人のコマは、ホストが動かす（ホストの画面に、動かすコマをえらぶ一覧が出る。盤のコマを押してもえらべる）。「端末なし」の印はホストの画面にだけ出す
- **通信が切れた人・退出した人のコマ**も、ホストが動かせる（全員がゴールに入らないとクリアできないため）。戻ると、自分で動かせるようになる

## status 遷移

```
waiting ─はじめる→ play（game と play/{id} を作る。クリアは、全員がゴールにいるかで各端末が決める）
play ─次のステージへ／もう一回／ほかのステージにする（ホスト）→ play（新しい game。id が1増える）
play ─待合室へ（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

```
sorottegoal_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── set:                { level: 'easy'|'normal'|'hard'|'expert', stage: 1〜9999, hostPlays, dark: true/false, time: 0|3|5|10 }
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}:     { joinedAt }                # 端末なしの参加者
  ├── game/                          # 「はじめる」で作り、待合室にもどると消す。ステージの決まり
  │    ├── id, seats: [名前, …], uids: [匿名ID または ''（端末なしの人）, …], proxy: [true/false, …]
  │    ├── spec: { level, n, seed }  # ステージの形は、ここから各端末で作りなおす（ルームには置かない）
  │    └── dark, limit（分。0 はなし）, startAt   # くらやみ・砂時計・ステージをはじめた時刻
  └── play/{game.id}/                # そのステージの動く部分（engine.js の toRoom / fromRoom / patch）
       ├── p: ["x.y.k.n", …]         # 人ごと。k はカギを持っていれば 1、n はその人の歩数
       ├── b: ["x.y", …]             # 箱ごと
       ├── k / st: { 番号: 1 }        # まだ置いてあるカギ・星（とったら消す）
       ├── o: { 番号: 1 }             # 開けた、かぎつきのとびら
       ├── say: { 席の番号: "言葉の番号.何回目" }   # ひとこと
       └── doneAt                    # クリアした時刻（砂時計があるときだけ）
```

- **動く部分は、人ごと・箱ごとに分けて置く**。1歩で書くのは、ふつう自分の `p/番号` の1か所だけ（テストで、1歩の9割以上が1か所）。箱を押したときは箱とうしろの人、カギ・星をとったときはそのカギ・星も、1回の `update` でまとめて書く
- 全員ぶんを1つの値にまとめて transaction で書く形にはしない。ほかの人の1歩が先に届くたびに書きなおしになり、通信の往復に 0.1〜0.2 秒かかる本番で12人が動くと、書きなおしが続いて進めなくなるおそれがあるため（2026-11-13。はじめは1本の文字列で作り、同日に作りかえた。本番で測ったわけではない）
- `play` の下を対決の番号で分けているのは、ステージを作りなおしたあとに遅れて届いた1歩を、いまのステージに当てないため。ステージを作りなおすときに、`play` を新しい番号のものだけにする
- こわれた値・ステージと合わない値は、その所だけはじめの値で読む（1つこわれても、全体を読めなくしない）。`game` がこわれているときは `gameOf` が null を返し、待合室の画面になる（ホストは「はじめる」で作りなおせる）
- 歩数は、人ごとの `n` の合計。クリアは、全員がゴールのマスにいるかどうかで各端末が決める（ルームには書かない）

## 書き込みの設計

| 操作 | 実行者 | 書き方 | 検証 → 書き込み |
|---|---|---|---|
| 作成 | ホスト | ルームへ transaction | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | `players/{名前}` へ transaction | 先に読んだ値で、名前が空いている・ステージの途中の名前は同じ匿名IDの人だけ・遊ぶ人が12人未満（自分のコマがある人が戻るときは見ない）を確かめる → 自分の在室だけを書く（同じ名前を同時に書いた人がいたら、先の人のもの）。書いたあと、ルームが閉じられていたら在室を消してやめる |
| 在室を戻す（再接続） | ゲスト | `players/{名前}` へ transaction | 参加と同じ確かめ → 在室がなければ書く |
| 在室を戻す（再接続） | ホスト | `update` | 手元の値で、自分がホスト・期限切れでない → `hostConnected`・`hostDisconnectedAt` だけを書く |
| 端末なしの参加者・設定・ホストも遊ぶ | ホスト | ルームへ transaction | `waiting`（端末なしは4人まで・遊ぶ人は12人まで） |
| はじめる | ホスト | ルームへ transaction | `waiting`・遊ぶ人が2〜12人 → `game` と `play/{id}` を作る |
| 次のステージへ・もう一回・ほかのステージにする | ホスト | `update` | 手元の値で、自分がホスト・`play`（次のステージへは、クリアしている）・遊ぶ人が2人以上 → `game`・`play`（新しい番号だけ）・`lastGameId`・`set/stage` をまとめて書く |
| 待合室へ | ホスト | `update` | `status: waiting`・`game` と `play` を消す |
| **1歩** | その席の人（端末なしの人・いない人のコマはホスト） | `play/{id}` へ `update` | 手元の値で `E.move` が動ける → さわった所だけ（`E.patch`）。動けない1歩は書かない |
| 時間だよ → このままつづける | ホスト | `game/limit` へ `set` | 0 を書く（そのステージの砂時計を止める） |
| ひとこと | コマを動かせる人 | `play/{id}/say/{席}` へ `set` | 手元で、5秒に1回まで・ホストが在室 → 言葉の番号と回数 |
| 退出 | ゲスト | `players/{名前}` へ transaction | 自分の匿名IDの在室なら消す（コマは残る） |

- **あそんでいる間に起きる書き込みは、ルーム全体の transaction を使わない**（参加・再接続・退出・ステージの作りなおし・1歩）。ルーム全体の transaction は、下のどこかが書かれるたびに書きなおしになり、みんなが動いている間は通りにくいため。ルーム全体の transaction を使うのは、だれも動いていない待合室の操作と作成だけ
- **1歩は、確かめずに書く**（`update`）。そのため、次のことが起きうる（どれもルールの上で困らない形にしてある）
  - 2人が同じマスへ同時に入ると、重なる。次の1歩で出られる
  - 同じカギを同時にとると、2人ともカギを持つ（カギが1本多くなるだけ）
  - 同じ箱を2組が同時に別の向きへ押すと、あとに届いたほうの場所になる
  - 相手の1歩がまだ届いていないと、手元では「まだ進めない」と出て書かれない（とびらが開いた直後など。もう一度押せば進む）
- **1歩・ステージの作りなおしの権限は、端末の側で確かめる**（`movableSeats`・ホストかどうか）。ほかの人のコマを動かす操作は画面にないが、防いではいない（性善説。ルートの AGENTS.md「セキュリティ方針」）
- **通信量**（2026-11-13 にエミュレーターで測った。`tests/sorotte-goal/e2e3.cjs`。WebSocket の中身のバイト数で、暗号化などの上乗せは入っていない。本番で測ったわけではない）

  | 1歩で流れる量 | バイト |
  |---|---|
  | 動かした人が送る | 約 98 |
  | 動かした人が受ける（書けたという返事） | 約 137 |
  | 見ているほかの端末が受ける（1台あたり） | 約 90 |

  - 12人＋ホスト＋みんなにみせる画面（14台）なら、1歩で受ける量の合計は 137＋90×13 ≒ 1.3KB。1ステージで合わせて1,000歩動いても 1.3MB ほど
  - Realtime Database の無料枠は、ダウンロードが月10GB。上の数字なら、12人のステージを月に数千回遊べる計算
  - **先に当たるのは、同時接続の数**（無料枠は、ツール全体で同時に100本）。12人のルームは、1つで14本使う。大人数のルームを同じ時間にいくつも立てると、ほかのツールもつながりにくくなる
  - くらやみ・砂時計は、通信を増やさない（上の「くらやみ・砂時計」）

## 接続・切断・再接続

ちゃりんバトン・リバーシと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- 遊ぶ人が切れると、その人のコマはうすくなり、横の一覧に「通信が切れた」。ホストが代わりに動かせる。戻ると（同じタブの読み込み直し・同じ名前と同じ匿名ID）自分のコマに戻る
- ホストが切れている間は、参加者の画面は共通のオーバーレイ「ホストの戻りを待っています」で押せない（1歩も書かない）。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- ステージの途中の名前は、ほかの人（別の匿名ID）は使えない

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。クリアしても自動削除しない（次のステージへ続けて遊ぶため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 待合室にもどると `game` を消す（遊ぶ人・設定・端末なしの参加者は残る）

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。players に入らない・切断予約をしない・期限切れのルームも消さない・1歩も書かない
- 待合室では「参加のしかた」とルームコードを大きく出す。ステージでは、矢印のボタン・ホストの操作を出さず、盤をいつも全体で出す

## メンター向けのメモ（画面には出さない）

- マイクを使わない子がいる回は、はじめに「ひとこと」の場所を一度見せる。吹き出しが出たら、声でひろう（「スイッチに乗ってくれるんだね」）と、声の人と同じように加われる
- くらやみは、言葉で伝える量が増える。はじめての回や、話すのが負担な子が多い回では「なし」のままにする
- 砂時計は、急がされるのが合わない子もいる。「時間だよ」は終わりではないことを、はじめに一言そえる
- はじめての回は「やさしい」のステージ1から。しかけの説明は盤の横と、進めなかったときの一言に出るので、先に全部を説明しなくてよい
- 12人のような大人数は、同時に話すと聞き取れなくなりやすい。部屋ごとに「いまはこの部屋のしかけ」と場面を区切ると進めやすい
- 箱を押しすぎて詰んだときは、だれが押したかを話題にせず、「やりなおす」で戻す
- 番号の人だけ渡れる橋は、その人に出番を作るしかけ。ほかの人が先に答えを言いすぎないよう、少し待つ
