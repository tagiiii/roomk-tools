# 麻雀 仕様書

## 目的・使用シーン

牌を1枚引いて1枚捨て、3枚の組を4つと同じ2枚（あたま）を1組そろえたら「あがり」。役・点数のない、かんたんなルールの麻雀。
それぞれの端末で自分の手牌だけを見て打つ。あいている席・抜けた人の代わりは CPU が打つ。

- **core value**: 「麻雀をやりたい」に、はじめての子でも遊べる形で応える。人数が足りない・途中で抜けた・放置した、でも止まらない
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば（`data-scenes="bodoge hiroba"`）
- あそぶ人 **1〜4人**（席はいつも4つ。足りない分は CPU）。在室はホストのほかに12人まで（5人目から・はじめたあとに入った人は見る人）
- 所要時間 1局10分ほど

> 経緯: 2026-11-14「麻雀がほしい」という意見を受けて、`drafts/mahjong/` で試作（PR #238）→ 同日オーナーが「マージして本体化」。
> 試作の前にオーナーが決めたこと: ルールは「かんたん」と「役あり」を選べる形にし、まずかんたんだけ作る（役ありはあとで足す）／点数は出さず、あがった回数だけ／1〜4人で足りない席は CPU。
> 同日、オーナー依頼で「役あり」のルールを足した（点数は出さず役の名前と翻数だけ・リーチあり・フリテン／ドラ／カンは本家どおり）。かんたんはそのまま残し、ホストが待合室で選ぶ。
> 名前「麻雀」は伝統ゲームの一般名称なので、命名の例外（人狼・大富豪と同じ）。

## ルール

ルールの本体は `engine.js`（画面・通信に触らない。node でも読める。テストは `tests/mahjong/engine.test.cjs`）。

| 項目 | 内容 |
|---|---|
| 牌 | 136枚（萬子・筒子・索子の1〜9、字牌7種 × 4枚）。赤ドラ・ドラ・王牌なし |
| 配り方 | 13枚ずつ。はじめの人（親）が14枚目を引いて、はじめに捨てる。親は局ごとに席の順で1つずつ回る |
| あがり | 3枚の組（同じ牌3枚・同じ種類で続いた数3枚）× 4 ＋ 同じ2枚。設定で同じ2枚 × 7組（七対子）もあがり |
| ないもの | 役・点数・リーチ・フリテン・カン（4枚目は持っておくか捨てる）・食い替えの制限 |
| ツモ | 引いた牌でそろったら |
| ロン | だれかが捨てた牌でそろったら（いつでも。フリテンなし） |
| ポン・チー | ポンはだれの捨て牌でも、チーは左の人（自分の前の番）の捨て牌だけ。設定で切れる。山が0枚のときはできない。鳴いたら引かずに1枚捨てる |
| 答えの順 | ロン → ポン → チー。同じ答えが2人なら、捨てた人の次に近い人（頭ハネ） |
| 引き分け | 山がなくなったら |
| 結果 | あがった人と、あがりの形（組に分けて、あがった牌に印）。席の「あがり N」に数える（待合室からはじめるたびに0から） |

### 役ありのルール（`settings.rule === 'yaku'`。2026-11-14 オーナー決定）

役の判定は `yaku.js`（局の流れに触らない純粋な関数 `evaluate`）、局の流れは `engine.js`（`opts.rule === 'yaku'` のときだけ動く分岐。かんたんの動きは変えていない）。

| 項目 | 内容 |
|---|---|
| あがり | 役が1つ以上要る（ドラは役に数えない）。形は4面子1雀頭・七対子・国士無双 |
| 点数 | **出さない**。あがったときに役の名前と翻数（ドラ込みの合計。役満は「役満」）だけ。数えるのはこれまでどおりあがった回数 |
| 王牌 | 14枚（嶺上牌4・ドラ表示牌5・裏ドラ表示牌5）。カンで嶺上牌を引くたびに、山のいちばん奥の1枚を王牌へ回す（海底がひとつ手前になる） |
| ドラ | 表示牌の次（9→1、北→東、中→白）。カンドラは暗槓ならすぐ、明槓・加槓は次に捨てたときにめくる。裏ドラはリーチであがったときだけ |
| リーチ | 門前（暗槓はよい）・まだリーチしていない・山が4枚以上・捨てたあとテンパイ。宣言牌は捨て牌にオレンジの枠と帯。リーチ後は引いた牌だけ捨てられ、待ちが変わらない暗槓だけできる。一発（1巡の間に鳴きが入ると消える）・ダブル立直（最初の一巡） |
| フリテン | 自分の待ちの牌を捨てている／待ちの牌を見逃した（次に自分が引くまで）／リーチのあとに見逃した（局の終わりまで）。ロンだけできない |
| カン | 暗槓・加槓（自分の番）、明槓（捨て牌。ポンと同じ順位）。加槓の牌は槍槓でロンできる（暗槓の国士無双の槍槓はない）。4回まで |
| 喰い替え | できない（鳴いた牌と同じ種類、チーでは筋の反対側も、すぐには捨てられない。捨てられる牌が残らない鳴きは出さない） |
| 役 | 1翻: 立直・一発・門前清自摸和・平和・断么九（喰いタンあり）・一盃口・役牌（三元牌・場風・自風。ダブ東は2つ）・嶺上開花・槍槓・海底摸月・河底撈魚／2翻: ダブル立直・七対子・三色同順・一気通貫・混全帯么九（この3つは鳴くと1翻）・対々和・三暗刻・三色同刻・三槓子・小三元・混老頭／3翻: 二盃口・混一色・純全帯么九（鳴くと2翻）／6翻: 清一色（鳴くと5翻）／役満: 国士無双・四暗刻・大三元・字一色・緑一色・清老頭・小四喜・大四喜・四槓子・九蓮宝燈・天和・地和 |
| 待ちの形 | 同じ手にいくつかの分け方・待ちの取り方があるときは、翻数がいちばん多いもの（役満が先）。平和は両面待ちだけ。ロンで完成した刻子は暗刻に数えない |
| 途中流局 | 九種九牌（最初のツモで么九牌9種類以上。「流す（九種九牌）」で宣言・CPU はしない）・四風連打・四家立直・四槓散了（2人以上で4回カン） |
| 局の進み方 | 東1局から（`game.kyoku` 0〜7。東場4局→南場4局→また東1局）。場風は東場が東・南場が南、自風は親が東。親があがる・流局で親がテンパイ・途中流局なら同じ親で同じ局、ほかは次の人が親で次の局。本場はない |
| 2人がロン | 頭ハネ（捨てた人の次に近い人だけ。かんたんと同じ） |

### ホストが選べるルール（待合室）

| 設定 | 内容 | はじめ |
|---|---|---|
| ルール | かんたん／役あり（上の表） | かんたん |
| CPUの強さ | やさしい（ポンをしない・あと何枚が増えない牌の中から、種と手番で決まるくじで捨てる）／ふつう（受け入れの多い牌を捨て、あと何枚が減るならポンする） | やさしい |
| ポン・チーをする | 切ると、ロンとツモだけ（役ありでは「ポン・チー・カンをする」。切っても暗槓・加槓はできる） | オン |
| 七対子 | 同じ2枚 × 7組でもあがり（かんたんだけ。役ありではいつもあがりの形） | オン |
| 1回に考える時間 | なし・30秒・60秒・90秒 | 60秒 |

**役ありの CPU**: テンパイして門前ならリーチする（どちらの強さでも。役がなくてもリーチで役がつくため）。ふつうは、役牌だけポンし（ほかを鳴くと役がなくなりやすい）、手が悪くならない暗槓・加槓をする。やさしいは鳴かず、カンもしない。コンピューター4人の120局で、やさしいは流局が多め（42局）、ふつうはほとんど流局しない（2局）。

**CPU はチーをしない**（どちらの強さでも）: 試作でチーまですると、コンピューター4人の150局で鳴きが279回、流局0回で、局がすぐ終わったため。

### 各自が選ぶ見え方（待合室の「見え方（この端末だけ）」とゲームの画面。localStorage `mahjong:view`。ルームには書かない）

**ヒントなどを出すか・枠で囲むかは、プレーヤーがひとりずつ選ぶ**（2026-11-14 オーナー指示）。ホストの設定にはしない（わかる子は切り、はじめての子はつける、を同じ卓で選べるように）。待合室とゲームの画面の切りかえは同じ設定で、片方を変えるともう片方もそろう。みんなにみせる画面には出さない。

| 設定 | 内容 | はじめ |
|---|---|---|
| ヒントを出す | 自分の番: おすすめの捨て牌にオレンジの点・「あがりまであと○枚」／ほかの人の番: テンパイなら待ちの牌、そうでなければ「あと○枚」 | オン |
| そろった組を枠で囲む | 手牌の中でもうそろっている組を囲む。3枚の組は白い線、同じ2枚は点線。組と組に入らない牌を種類の順に並べる（引いた牌は右に離したまま組に入れない） | オン |
| 牌の下に名前を出す | 「三萬」「5筒」「東」など | オフ |

- おすすめは「捨てたあとのあと何枚が少なく、見えていない分で受け入れの枚数が多い牌」（`discardAdvice`）。「あと○枚」は向聴数＋1
- 組の見つけ方は `groupHand`: 3枚の組を3点・同じ2枚を2点として、点がいちばん多い分け方（同じ点なら3枚の組が多いほう）。あがりへの近さ（向聴数）とは別の物差しなので、おすすめの捨て牌が組の中の牌になることもある
- 枠は「ルールを知らなくても、組を作っていることが目で分かる」ために足した（2026-11-14。点を押すだけになりやすい、という見立てから）

## CPU・時間切れ・抜けた人

| 場面 | 動き |
|---|---|
| CPU の席 | はじめるとき、あそぶ人が4人に足りない分（「CPU 1」〜「CPU 3」）。待合室で足す・外す操作はない |
| 通信が切れた人の番 | 在室（`players/{名前}`）が消えてから3秒待って、CPU が代わりに打つ。席に「通信が切れた・CPUが代わり」 |
| 「退出する」で抜けた人 | 同じ（席と手牌は局が終わるまで残る） |
| もどってきた人 | 同じ名前で入りなおすと席にもどり、また自分で打てる（別の端末からでも、その席の人が在室していなければ入れる。性善説） |
| 時間切れ | 捨てる番は、引いた牌をそのまま捨てる（鳴いたあとは CPU の選び方）。聞かれている間（ロン・ポン・チー）はパス |
| 捨てる番で時間切れが2回続いた人 | CPU にまかせる。その人の画面に「いまはCPUが代わりに打っているよ」と「自分でやる」。聞かれている間の時間切れは数えない |

CPU の席・抜けた人・まかせた人の番と時間切れは、**ホストの画面が進める**（250ミリ秒ごと。捨てる番の CPU は0.9秒待ってから。聞かれている間の CPU の答えは待たずにまとめて）。時計は Web Worker（大富豪と同じ理由: ホストがみんなにみせる画面を開くと、ホストのタブが裏に回ってタイマーが間引かれる）。

## status 遷移

```
waiting（待合室）→「はじめる」→ playing（打っている・結果）
playing →「次の局へ」→ playing（同じ席で配りなおす。親が1つ回る）
playing →「待合室にもどる」「この局をやめて待合室へ」→ waiting
```

結果は `playing` のまま `game` の中の `s.phase === 'end'` で出す（ふりかえり画面滞在中は削除しない公認バリアント）。

## Firebase データ構造（Realtime Database）

```
mahjong_rooms/{CODE}
  status: 'waiting' | 'playing'
  host, hostUid, hostPlays, hostConnected, hostDisconnectedAt, createdAt
  round: 何局目か
  settings: { rule: 'simple' | 'yaku', calls, chiitoi, level: 'easy' | 'normal', time: 0 | 30 | 60 | 90 }
  players/{名前}: { isHost, uid, joinedAt }   // 在室（ゲストは onDisconnect で消える）
  wins: '{"p:そら":2,"c:1":1}'                // あがった回数（席の id の JSON 文字列）
  game: '{...}'                               // ゲームの状態の JSON 文字列（下）
```

`game` の中身: `kyoku`（役ありの局の番号 0〜7）・`seats`（4席。`{ id: 'p:名前' | 'c:1〜3', name, cpu }`）・`s`（`engine.js` の状態。山・手牌・鳴き・捨て牌・番・聞いている答え・結果・`rev`・`disc`）・`log`（できごと6件まで）・`deadline`（締め切り）・`auto`（CPU にまかせた人）・`timeouts`（捨てる番で続けて時間切れになった回数）。

- **JSON の文字列にしている理由**: RTDB は空の配列を消すので（空の手牌・捨て牌・鳴き）、そのまま置くと読み戻せない。読むときは形を確かめ、壊れていたら読まない
- 手牌は全員分が同じ文字列に入っている。画面では自分の分だけ出す（DevTools で見えるのは性善説で許容）
- `wins` を JSON 文字列にしているのは、席の id の `:` と名前をそのままキーにしないため

## transaction 設計

- 捨てる・ツモ: ルーム全体の transaction で `game` を読み直し、**何局目か（`round`）と何手目か（`s.rev`）が押した時点と同じ**・自分の席か（名前と匿名IDの持ち主）を確かめてからルールに当てはめる
- ロン・ポン・チー・カン・パス: 答えられる人は同時に押すので、`rev` は見ず、**同じ捨て牌（または加槓の牌）への答えか（`s.disc`・`s.claim` と `phase === 'claim'`）**だけ確かめる。答えた人の分は `engine.act` がはじく
- 聞かれている間の答えでは締め切りを動かさない（ほかの人が答えるたびに時間がのびないように）。捨てる・鳴く・引く、で番が動いたら決めなおす
- ホストの進行（CPU・時間切れ・在室のできごと）も同じ transaction。CPU は「同じ `rev` で、その席がまだ CPU で動く」、時間切れは「同じ `rev` で、同じ締め切り」を確かめる
- 待合室の操作（設定・ホストもあそぶ）は前の保存が終わる前に押しても捨てない（大富豪と同じ `concurrent`）。はじめる・次の局は二度押しを捨てる

## 接続・切断・再接続

- ホスト: `onDisconnect().update({ hostConnected: false, hostDisconnectedAt })`。参加する人にはオーバーレイ。2分（`ORPHAN_TTL_MS`）で期限切れ
- ゲスト: `players/{名前}` を `onDisconnect().remove()`。接続のたびに在室を確かめて張り直す（`ensurePresence`）
- 再読み込み: sessionStorage（`mahjong_session`）から同じルーム・同じ名前で戻る（手牌は保存しない）
- 参加用のリンク `?room=`、QR コード、みんなにみせる画面 `?watch=` は共通の形

## 終了とデータ削除

公認バリアント「ふりかえり画面滞在中は削除しない」（`docs/development/rtdb.md`）。結果のあと「次の局へ」「待合室にもどる」で続けるため、終了30秒後の自動削除はしない。削除は (1) ホストの「ルームを閉じる」 (2) ホスト切断の TTL (3) 次に開いたときの期限切れの掃除、の3つ。

ホストのルームバーの「みんなにみせる画面」、またはトップの「みんなにみせる画面をひらく」。ルームに入らず、書き込まない。手牌は出さない。

## 利用回数（stats.js）

`room-create`（ルームを作った）・`start`（はじめた）・`again`（次の局）・`players-N`（あそぶ人の数。CPU は数えない）・`rule-simple`／`rule-yaku`（はじめた・次の局のルール）・`finish`（局が最後まで終わった。終わらせた transaction の画面で1回）。

## ホストも遊ぶ・端末のない参加者

- **ホストも遊ぶ（`hostPlays`）: はじめは「遊ぶ」**。外すと進行役（待合室の印は「進行役」）。あそぶ人が0人のときは「はじめる」を押せない
- **端末のない参加者は作らない**: 手牌がホストに見えてしまうため（大富豪と同じ）。代わりに CPU の席が入る

## 意図的な逸脱

- **ゲームの状態を JSON 文字列で持つ**（上の理由）
- **別の端末からでも、同じ名前で空いている席にもどれる**（大富豪と同じ。性善説）
- **「CPU」ではじまる名前は使えない**（CPU の席と見分けるため）
- **競争要素（あがった回数）を残す**: オーナーが「あがり回数だけ」を選んだ（2026-11-14）。点数・順位の一覧は出さない。回数は席の小さな文字だけで、0回の人を並べて見せる画面はない
- **麻雀の言葉（ツモ・ロン・ポン・チー・テンパイ・七対子・萬子など）を使う**: 麻雀そのものを遊びたい子のためのツールなので（もじそろえゲームは逆に麻雀の言葉を使わない。混ぜない）。「テンパイ」はヒントの中で「あと1枚であがれる形」と並べて出す

## 入れない機能

- 点数・本場・供託（役ありでも、役の名前と翻数だけ。オーナー決定）
- 流し満貫・三家和・ダブロン（2人のロンは頭ハネ）・暗槓への国士無双の槍槓・赤ドラ
- 三人麻雀
- CPU がチーをすること（上の理由）
- 端末なしの参加者（上の理由）
- 効果音

## 既知の制約

- 急な切断（電源・Wi-Fi）は、在室が消えるまで数十秒〜1分かかる。その間は CPU が代わりに打たない（考える時間があれば時間切れで進む。「なし」だと止まる）
- ホストの通信が切れている間は、CPU と時間切れが進まない
- 4枚目を持っている種類は、待ちに出さない（その牌はもう来ないため）。ほかの人が使っている枚数までは見ないので、待ちに出ても山に残っていないことがある

## メンター向けの心得（画面には出さない）

- はじめての子が多いときは、CPU は「やさしい」、ヒントはオンのまま。ポン・チーで迷う子がいたら、ホストが「ポン・チーをする」を切ってもよい
- 「あと○枚」は、あがりまでに必要な牌の数の目安。数字が減っていくのを一緒に見ると、何を捨てればいいかの手がかりになる
- 待ちの牌がなかなか来ないことはよくある。「来なかったね」と軽く流す
- あがり回数が0のまま続く子がいたら、次の局から CPU を「やさしい」にする・自分（メンター）が入るなどで、卓の雰囲気を見る
