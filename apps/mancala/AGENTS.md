# マンカラ 仕様書

## 目的・使用シーン

自分の穴の石をすくって、となりの穴から1つずつ入れていき、最後に自分のゴールの石が多いほうが勝つ、定番の盤ゲーム。

- **core value**: 1手ごとに「どこに入るか」を数えて考えられる。運の要素がなく、ルールは短い。はじめての子は「補助」で石が入る穴を見てから選べる。1台の画面なら CPU とも対戦できる。対戦しない子も、自分の画面や「みんなにみせる画面」で勝負を見られる
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの1対1でも、子どもひとりと CPU でも遊べる）
- 対戦は2人。観戦はゲスト20人まで（＋端末なしの参加者4人まで）
- 所要時間 1回10分くらい

> 経緯: 2026-11-14 オーナー「マンカラがほしいという意見がありました」。遊び方は「CPU とも対戦できる形」（リバーシと同じ形＋CPU）、ルールは「よくあるルール」をオーナーが選んだ。`drafts/mancala/` に試作（1台・CPU・2つのウィンドウ）→ 同日オーナーが「本体化する」と承認。
> 作りは [リバーシ](../reversi/AGENTS.md) をそのまま土台にした（ルーム・席・観戦・みんなにみせる画面・端末なしの参加者・1手の制限時間・CPU と対戦・切断と再接続）。ちがうのは盤・ルール・補助・石を1つずつ入れる動きだけ。ここに書いていないルームまわりの決まりは、リバーシの仕様書と同じ。
> 名前「マンカラ」は伝統ゲームの一般名称（いくつもの国で遊ばれてきた種まき型の盤ゲームの総称）なので、命名の例外（リバーシ・人狼と同じ。`docs/development/app-registration.md`「アプリ名のつけかた」）に当たる。商品名（「カラハ」の名で売られた製品など）は画面・キーワード・早見表に使わない。早見表では系統ラベル「定番の盤ゲーム」で紹介する。

| 項目 | 値 |
|---|---|

## ルール（よくあるルール）

| 項目 | 内容 |
|---|---|
| 盤 | 1人6つの穴と、右はしの自分のゴール。はじめは各穴に石4つ（合計48） |
| まき方 | 自分の穴を1つ選び、中の石を全部取って、右どなりから反時計まわりに1つずつ入れる。自分のゴールには入れ、相手のゴールはとばす |
| もう1回 | 最後の1つが自分のゴールに入ったら、同じ人がもう1回まく |
| よこどり | 最後の1つが自分の空の穴に入り、向かいの相手の穴に石があれば、その1つと向かいの石を全部自分のゴールへ。向かいが空なら何もしない |
| おわり | どちらかの側の穴が全部空になったら。残った石は、その穴の側の人のゴールへ |
| 結果 | ゴールの石が多いほうの勝ち。同じなら引き分け。「後（○○）の勝ち！　先 21 ー 後 27」、勝った人の札に「勝ち」 |
| 先と後 | 色ではなく「先」「後」で呼ぶ（先＝青・後＝赤の札）。内部の名前は `b`（先）・`w`（後）でリバーシと同じ |
| 穴の言い方 | その人から見て左から「3番めの穴」。メッセージ（「CPU は 3番めの穴からまいたよ。」）で使う |

盤のルールは `engine.js`（画面と通信に触らない。node でも読める）。盤の番号は 0〜5 が先の穴、6 が先のゴール、7〜12 が後の穴、13 が後のゴール。テストは `tests/mancala/engine.test.cjs`（でたらめ対局3000局で石が48のまま・必ず終わる、よこどり・おわり・相手のゴールをとばす、CPU の強さ）。

## 盤の見せ方

- 横長の盤。左右のはしがゴール、下の段が下の側の穴（左から右）、上の段が上の側の穴（右から左）。石は反時計まわりに入る
- **自分の側を下にする**: 対戦する人は自分の側、1台の画面は先（CPU と対戦するときは自分）、観戦・みんなにみせる画面は先が下
- 穴の中に色つきの石（16こまで描く）と、穴の下に数。ゴールは40こまで描く
- 直前にまいた穴に小さな赤い点。札（盤の上と下）にゴールの数と「いまの番」
- **石を1つずつ入れる動き**: 1手ごとに、すくった穴を空にしてから1つずつ（0.23秒ずつ。13こ以上なら0.15秒）入れ、よこどりは0.9秒光らせてからゴールへ、おわりは「のこりの石は、それぞれのゴールへ」と出してから移す。動きの間は盤を押せず、「先（○○）が 3番めの穴からまいているよ」と出す。ルームでは全員の画面で同じ動きを見る（`game.path`・`capture`・`sweep` から作る）。1手もどす・新しい対局・読み込み直し・端末の「動きを減らす」では動かさない
- 動きの間に同じ局面のまま描きなおす（補助の変更・在室の変化）ときは、動きを続ける。次の手が届いたら、動きをやめて最新の盤を出す

## 補助（はじめての人向け）

| 項目 | 中身 | はじめの値 |
|---|---|---|
| 補助を使う人 | ふたりとも／先の人だけ／後の人だけ／使わない。その側の番のときだけ補助が出る | ふたりとも |
| まく前にたしかめる | 1回押すと、石が入る穴に点線の印、最後の穴に太い印が出て、「最後の石がゴールに入って、もう1回できるよ」などの文が出る。「ここからまく」か、同じ穴をもう1回押すとまく。「やめる」で取り消す | オン |
| いい手に印を出す | 「もう1回」になる穴に回る矢印、「よこどり」できる穴に手の印 | オフ |

- 数える手間が遊びの中心なので、印は「どこに入るか」と「もう1回・よこどり」だけにした（どの手が強いかは出さない）
- 「たしかめる」をはじめオンにしたのは、押しまちがえで1手が進むのを防ぐため（試作でオーナーが確かめた形）。はじめの値は AI の仮置き
- 補助はホストが待合室で決め、遊んでいる間も「補助の設定」で変えられる（1台の画面も同じ）

## 1手の制限時間と CPU

リバーシと同じ（なし・15秒・30秒・60秒。はじめは「なし」。過ぎたら CPU がその人の代わりに1手まき、「時間切れ。CPU が後の代わりに 3番めの穴からまいたよ。」と出す）。時間切れの手を送る端末・照合（`rev`）・ホストが切れている間は時計を止める、もリバーシと同じ。

- 石を入れる動きの間は、時間切れの手を送らない（動きがおわってから送る）。残り時間の表示は、動きの間も進む（置いた直後の番の時間は、動きの分だけ短く見える。15秒でも十分に残るので、そのままにした）

### CPU と対戦する（1台の画面）

| 項目 | 内容 |
|---|---|
| 相手 | 準備の画面の「対戦の相手」（人どうし（はじめの値）・CPU（自分が先）・CPU（自分が後）） |
| 強さ | よわい＝まける穴からくじ／ふつう（はじめの値）＝もう1回になる穴 → よこどりが多い穴 → くじ（時間切れの手もこれ）／つよい＝ゴールの差で5手先まで読む（もう1回の手は深さを減らさない）。同じ値の手はくじ |
| 強さの差 | `tests/mancala/engine.test.cjs` で、ふつうがよわいに60局中40局以上、つよいがふつうに30局中22局以上勝つことを確かめる。つよいの1手は0.25秒未満 |
| CPU の番 | 石を入れる動きがおわってから0.9秒待ってまく。「CPU は 3番めの穴からまいたよ。」と出す。CPU の番は時間を数えない |
| 1手もどす | CPU の手と、その前の自分の手をいっしょにもどして、自分の番にする |
| もう一回 | 先と後を入れかえる（CPU の側も入れかわる） |

## 端末なしの参加者

リバーシと同じ（待合室でホストが足す。その人の番はホストの画面に「先（○○）の番。代わりにまいてね」。「端末なし」の印はホストの画面にだけ）。

## 画面構成・フロー・status 遷移

リバーシと同じ（トップ → ルームを作る／参加する／1台の画面であそぶ／みんなにみせる画面をひらく → 待合室 → 対局 → 結果（同じ画面）→ もう一回（先と後を入れかえる）／対戦する人を選びなおす）。対局の画面は、上から「番の表示」「上の側の札」「盤」「下の側の札」「たしかめる」「結果のあとのボタン」「そのほかの操作」。

## Firebase データ構造（Realtime Database）

リバーシと同じ形。`game` の中だけちがう。

```
mancala_rooms/{roomCode}/
  ├── status / host / hostUid / hostConnected / hostDisconnectedAt / createdAt / lastGameId
  ├── aid:                { who: 'both'|'b'|'w'|'none', confirm, hint }
  ├── moveTime:           0 | 15 | 30 | 60
  ├── seats:              { b: 名前（先）, w: 名前（後） }
  ├── players/{name}:     { isHost, uid, joinedAt }
  ├── proxies/{name}:     { joinedAt }
  └── game/
       ├── id, seats, uids, proxy
       ├── board: [14この数]（0〜5 先の穴・6 先のゴール・7〜12 後の穴・13 後のゴール。合計48）
       ├── turn: 'b'|'w', ply: 何手目, last: 直前にまいた穴（-1 はまだ）
       ├── path: [直前の手で石を入れた穴の並び], extra: もう1回か, capture: { from, opp, count }（よこどり）, sweep: おわりに残りを移したか
       ├── over, hist: [{ board, turn, last, ply, extra }...], moveTime, turnAt, auto, rev, ended
```

- 読み込むときは壊れた値を読み飛ばす（`gameOf`。盤は14この0以上の整数で合計48のときだけ読む）
- transaction の設計・接続と切断・終了とデータ削除・みんなにみせる画面（書き込みゼロ）は、リバーシの仕様書の同じ節と同じ

## 利用回数（stats.js）

リバーシと同じ項目（`room-create`・`start`・`players-2`・`finish`・`again`・`local-start`・`local-finish`）。

## 意図的な逸脱

リバーシと同じ（分割構成の RTDB アプリ・ホスト以外も進行の一部を行う・観戦は players に入る・終了後の自動削除なし（公認バリアント「ふりかえり画面滞在中は削除しない」）・端末なしの参加者は在室を持たない・勝ち負けを出す（点数の比較や順位の記録はしない））。

## 入れない機能

- 音
- ほかのルール（石の数・よこどりの有無・時計まわり など）の切りかえ。オーナーが「よくあるルール」を選んだ
- どの手が強いかの印（「いい手に印」は もう1回・よこどり だけ）
- 勝ち数・対戦成績の記録、順位

## 既知の制約（v1）

リバーシと同じもの（同じ名前のタブが2つ・時間切れの手はホストか番の人の端末が開いているときだけ・裏に回ったタブのタイマー・待合室の席は名前で持つ・応答が届かないときの数え漏れ・残り時間の表示のずれ）に加えて:

- 石を入れる動きは各端末で見るので、動きの間に次の手が届く（もう1回の手を続けて早くまいた）と、その端末は動きをやめて最新の盤を出す
- 長い手（石が多い穴）の動きは数秒かかる。その間に残り時間が進む

## メンター向けの心得（画面には出さない）

- はじめての子には「まく前にたしかめる」のまま遊ぶ。どこに入るかを見てから決められるので、数えるのが苦手でも置いていかれにくい
- 1台の画面で遊ぶときは、子どもに「3番めの穴」のように言ってもらう（その子から見て左から数える）。言いにくい子には指で示してもらう・チャットで送ってもらうでもよい
- 「もう1回」が続くと楽しい。最後の石がゴールにぴったり入る穴を一緒に探すと、数える遊びになる
- CPU と遊ぶときは、はじめは「よわい」か「ふつう」。負けが続く子には強さを下げる。「つよい」はメンターでも負けることがある
