# 作戦会議 — 固有仕様

週1回30分の作戦会議の流れ（もとは Google スライド）を、ひとつのルームで進めるスタッフ向けのツール。
メンターが「みんなにみせる画面」を画面共有し、子どもは自分の端末のボタン・声・チャットのどれでも答えられる。
2026-11-12 に `drafts/` で試作し、同じ日にオーナーの依頼で本体化した（試作はリポジトリに入れていない。決めたことと理由は、このファイルにまとめた）。

**サークルタイムと同じく、スタッフ向け。ツール一覧には出さない・更新情報にも書かない**（2026-11-12 オーナー）。
入口は `apps/guide/`（ゲームえらび早見表）の上のリンク。子どもは、ルームの中で出る参加用のリンク・QR・ルームコードから入る。
`<body data-genre="talk">` は書式のために残しているだけで、一覧の種類には使わない。

## 流れと画面

表紙 → チェックイン（お題）→ もくじ → ジブンチェック（心の1〜5）→ 今日は何する？（6つ）→ 予定の確認（1週間の表）→ お知らせ（単発実施プログラム・次回の日）。
文言はもとのスライドのまま（ふりがなは外した）。4つのコーナー（ジブンチェック〜お知らせ）には表紙があり、進行役が「コーナーの表紙を出す」を外すと飛ばせる。

画面は3つ。別々の作りにしている。

- **みんなにみせる画面**（`?watch=コード`）: 1280×720 の舞台を、窓の幅に合わせて縮める（スライドと同じ見え方）。画面共有するのはこの窓
- **進行役の画面**: 左に流れ、中央に舞台のプレビュー・「前の画面／次の画面」・その画面で使う操作だけ、右に参加する人。共有しない。
  上の帯にいまの時刻と「はじめて ○分」（みんなにみせる画面には出さない）。幅 721〜1100px は、流れを上に横並び
- **子どもの画面**（`?room=コード`）: 自分の端末で押すための、縦に並んだ大きいボタン。上に進みぐあいの帯

## 主導権は進行役

- 画面を進める・戻す・飛ばす、「今日は何する？」を決める、使うツールを決める・開く、は進行役だけ
- **子どもが押しても、みんなの画面は切りかわらない**（2026-11-12 オーナー「子どもが自分の端末で押すと全体の画面が急に変わって戸惑う」）。
  「今日は何する？」の6つや候補のカードを子どもが押すと、「これがいい」が進行役に伝わり、みんなの画面ではそのカードに名前の札がつくだけ。
  進行役の6つのボタンに名前が出て、候補のほうは「子どもがえらんだもの」の列が出る。押して決めるのは進行役
- ジブンチェックは、子どもが押すとすぐその段に名前が出る（「送る」ボタンは置かない。オーナー判断）。別のものを押せば選びなおせる
- 子どもが入れられるのは、いま出ている画面の自分の分だけ。進行役は「参加する人」の名前の横の数字で、だれの分でも代わりに入れられる
- 予定の表は、進行役（プレビューのマス）と子ども（自分の端末）が同時に入れられる。ふせんは、つかんで別のマスへ動かせる

## 予定の表の範囲

きょうから7日ぶん（2026-11-12 オーナー「今日の日付を基準に1週間の表示がいい」。はじめは、あしたから7日ぶんだった）。
きょうの列には色をつける。次回の作戦会議の日がこの7日に入るときだけ、その日に「作戦会議」のふせんを入れておく
（次回がちょうど1週間後のときは、表の外になるので入らない。次回の日は「お知らせ」に出る）。

## 端末のない参加者

作る。進行役が「参加する人」で名前を足す（`persons/{id}` に `proxy: true`。在室を持たない）。ジブンチェックは名前の横の数字、
予定はプレビューのマスで進行役が代わりに入れる。「端末なし」の印は進行役の画面にだけ出す。子ども（端末あり・なしを合わせて）は6人まで。
ホスト参加の切りかえ（`hostPlays`）はない（進行役はいつも進行だけ。答える側に入らない）。

## 学校の予定の選択肢（2026-11-12 オーナー判断）

登校している子は学校やテストの予定を入れるが、登校していない子の目にその選択肢が入ってよいか、がオーナーの考えどころだった。

- はじめに出す選択肢に、学校に関するものを入れない（room-K・おうち・おでかけ・習いごと・病院・あそぶ・趣味・ゆっくりする）
- 「学校・テスト・行事・部活」（「やること」の行は「宿題・提出物」）は、進行役が「予定の確認」の操作で、その子の
  「選択肢に、学校の予定も出す」をオンにしたときだけ、その子の表の選択肢に出る。はじめはオフ
- 選択肢の窓は、マスを押した人の画面にだけ出る。みんなにみせる画面には出ない
- 「自分で書く」（12字まで）はいつでも使える。切り替えは進行役の画面にだけあり、画面に理由は書かない

## 今日は何する？ とツール

- 6つ（ゲーム・おしゃべり・学習する・自分について知る・おまかせ・したいことがある）はスライドのまま
- 決めたあとの候補は、ツール一覧と同じイラストと名前のカード。みんなの画面は4枚ずつ（進行役の「前の4枚」「次の4枚」で送る）。
  候補の組（`data.js` の `menu`）は仮。おまかせは、ツール一覧の利用シーンに「作戦会議」があるものから3つ
- 「ほかのゲームも見せる／ほかのツールも見せる」で、ツール一覧の同じ種類のものを全部足す。子どもの「ほかも見る」は、その子の画面の中だけで広がる
- 進行役の「ツールの一覧から選ぶ」: 種類のボタン（作戦会議向け・ことば・パズル・推理・当てっこ・ボード・トーク・ぜんぶ）と
  イラストの格子（オーナー「名前がわからない場合がある。選択式で」）。名前で探す欄は、その下に小さく置いた
- 全ツールの一覧は、ツール一覧のページ（`apps/index.html`）のカードを読んで作る。読めなければ `data.js` の `all`（写し）
- **ツールは進行役が開く**（オーナー「基本的にホストが開き、参加者にリンクを共有する流れ」）。進行役が「○○を開く」を押すと
  新しいタブ（名前 `roomk-sakusen-tool`）でツールが開く。そのタブでルームを作ると、1秒ごとにそのタブの sessionStorage
  （同じサイトなので読める）からルームのコード（6文字）を拾い、`apps/{フォルダ}/?room={コード}` を子どもの画面に「○○に入る」として出す。
  **開いた時点でもう入っているコードは送らない**（前に作ったルームの記録が、進行役のタブから写ったり、使い回したタブに残ったりする。
  送ると、ルームを作る前に子どもが入れてしまう）。開いたあとに新しく増えたコードだけを送る。
  「リンクが出ないときは、貼って送る」はたたんである（進行役の画面を読みこみなおすと、開いたタブを見失うため）
- 「学習する」には e-board（`www.eboard.jp/list/`）をはじめから入れた（外部サイトはこれだけ。オーナー判断）。
  ほかの学習サイトは、進行役が名前とリンク（https だけ）を入れて使える。外部サイトは「このリンクをみんなに送る」で子どもに届く

## データ

`sakusenkaigi_rooms/{code}`（`database.rules.json` への追加は 2026-11-12 にオーナーが承認）。

- つなぎの型はサークルタイムと同じ: `status`（`live` → `finished`）、`host`・`hostUid`・`hostConnected`・`hostDisconnectedAt`、
  在室は `players/{id}/connections/{pushId}`（進行役と、端末のある子）
- 中身: `cur`・`view`（`cover`／`body`）・`covers`・`skip`、`topic`、`persons/{id}`（`name`・`proxy`・`school`）と `order`、
  `heart/{id}`、`wants/{id}`・`twant/{id}`（子どもの希望）、`decided`・`tool`（`name`・`href`・`join`・`code`）・`page`・`wide`・`omakase`、
  `sched/{id}/{日-行}`（ふせんの配列）、`sel`（予定の表を出している子）、`next`（次回の日と時刻）、`notices`
- **直し方**: 進行役も子どもも、ルームの根っこへの transaction（`tx`）で直す。配下への `set` はしない
  （親の transaction と同じ端末の配下 set がぶつかると 'set' で中止されるため）。RTDB は空の入れものを保存しないので、読んだあと `norm()` で足す
- **残さない**: 「ルームを閉じる」で消す。進行役が切れたまま2分たつと期限切れ（`ORPHAN_TTL_MS`）。心の答え・予定は、日をまたいで残さない・集計しない・くらべない
  （内省の回答に保存・採点・比較を足さない方針）。端末に残すのは、再接続用の sessionStorage だけ
- ふりかえり画面はないので、終了30秒後の自動削除はなく、「ルームを閉じる」・進行役の切断の TTL・次のアクセスのときの期限切れ掃除の3つで消す

## 見た目

フラット。色はあたたかい3色（こげ茶よりの文字 `#3D3833`・オレンジのさし色 `#C2571F`・黄色の札 `#FBEBA6`）と生成りの地（`#F6F1E8`）。
共通の色の変数を、このツールの `body` の中だけ置きかえている。影・傾き・模様（方眼・しま・点線）は使わない。

- オーナーの判断の順（2026-11-12）: サークルタイムの切り紙とかぶるので変える → 3案から「作戦ノート」→ 目がチカチカするので方眼・しま・点線をやめる →
  色をおさえ文字を落ち着かせる → シンプルなフラットに → 背景の青みがイラストにかぶって不気味なので、あたたかい色合いに
- 表紙とコーナーの表紙は真ん中ぞろえ。見出しは Zen Maru Gothic の 700 まで（900 は使わない）
- しるし（ハート・さいころ・カレンダーなど）は手で組んだ SVG。人・顔・手は描かない。ツールの候補は、ツール一覧のイラスト
- 音は鳴らさない。配慮の理由・保存の有無は画面に書かない

## 確かめ方

`tests/sakusen-kaigi/`（README.md）。隔離したエミュレーターと Playwright で、進行役・子ども2人・みんなにみせる画面を別々のブラウザとして動かす。
本物のクイズパックでルームを作り、参加用のリンクが子どもに届くところまで見る。

確かめるときの落とし穴:

- 画面を描きなおすたびに中身を書きかえると、押している途中のボタンが消えて「押した」が届かない。`setHTML` は中身が同じなら書きかえない
- ふせんを動かし終えた「その動きの押した」だけを捨てる（`dropJust`）。時間で区切ると、動かした直後に別のボタンを押した分まで捨てる
- 進行役の通信が切れて戻ったとき、古い接続の切断の予約が遅れて動き、つながっているのに `hostConnected: false` になることがある。進行役は、自分がつながっているのに切断になっていたら在室を入れなおす（`onRoomChange`。kotoba-meter と同じ考え方）。サークルタイムにも同じ日に入れた
- 押している間は描きなおさない（`pressing`）。押してから離すまでの間に描きなおすと、押していたボタンが作り直されて「押した」が届かない。中身が同じなら書きかえない（`setHTML`）だけでは、中身が変わる所（参加する人の一覧など）を守れない。サークルタイムで再現（押している間に更新が届くと、6回中6回とも選べなかった）
- 進行役の画面だけを描きなおす道（一覧を開く・種類を切りかえる）でも、プレビューを縮めなおす（`renderHost` の最後の `fit()`）
