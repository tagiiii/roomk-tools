# 興味スゴロク 仕様書

## 目的・使用シーン
不登校支援のオンラインメンタリングセッションで、子どもとの対話のきっかけをつくるスゴロクツール。
マスに止まった人が、出てきた質問について話す。

| ロール | 説明 |
|--------|------|
| 操作者 | 1台の画面: メンター。ルーム: 番の人（自分の端末）とホスト（メンター） |
| 参加者 | 1〜10人 |

**利用シーン**
- セッション開始後のアイスブレイク
- 自己紹介や興味の探索
- 話題に困ったときの対話のきっかけづくり（作戦会議など）

## セッション条件（ツール一覧のカードと同じ。2026-11-08）

スタッフがツールを選ぶときの条件。値はツール一覧（`apps/index.html`）のカードの札・`data-scenes`・`data-speech`・`data-self` と同じにする（話す量・自分の話は P-33・P-34 で承認。決めた根拠は [sakusen-conditions-draft-2026-11-08.md](../../docs/reports/sakusen-conditions-draft-2026-11-08.md)）。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 1〜10人 |
| 目安時間 | 10〜20分 |
| 利用シーン | ひろば・作戦会議 |
| 話す量 | 選ぶだけ・話す・説明する |
| 自分の話 | 自分のことを話すのが中心 |

## 遊び方は2つ（2026-11-04 オーナー決定）

- **ルーム（各自の端末）**: ホストが「ルームを作る」、ほかの人は「ルームに参加する」（名前 → ルームコードの順）。自分の番は自分の端末で「サイコロを振る」。ホストはだれの番でも代わりに押せる
- **1台の画面であそぶ**: これまでの遊び方。1台の画面をみんなで見て、メンターが押す。ゲームの通信はしない（利用回数カウンタだけ）
- 経緯: 2026-11-04 フィードバック（「名前を入れたい」「みんなが自分でサイコロを振れたら」）。名前は1台の画面の任意の欄で対応し、ルームは同日オーナーが次を決めて追加した:
  1. 1台の画面であそぶは残す
  2. 「サイコロを振る」「別の質問」「話せた！次の人へ」・選択肢は、番の人とホストが押せる
  3. 選択肢で選んだものは、みんなの画面に出す（その番の間だけ。次の人へ進むと消える）→ 同日改訂（下の 5）
  5. （2026-11-04 夕 改訂）選択肢は、選ぶと次の人の番になる（「選ぶ → 話せた！次の人へ」の2回押しをやめる）。選んだものは盤の上に小さく残し、次の人がサイコロを振ると消える。1台の画面・ルームとも同じ。ルームで質問のカードを盤の横に並べるのは見づらいのでやめ、どの幅でも盤の上に出す
  4. 人数は6人まで（1台の画面も6人まで。コマの色を2色足した）→ 2026-11-18 オーナー「10人くらいまで参加できるといい」で、どちらの遊び方も10人まで（コマの色を4色足した。`L.MAX_PLAYERS`）

## 技術スタック・ファイル

```
apps/kyoumi-sugoroku/
├── AGENTS.md   # この仕様書
├── index.html  # 画面の骨組み・howto.js の設定
├── app.js      # 質問データ（THEMES・QUESTIONS）・1台の画面・ルームの通信と画面（ES module）
├── logic.js    # ルームの決まり（DOM も Firebase も使わない。transaction の中から呼ぶ）
├── art.js      # 盤の景色（SVG）とマスの位置。決まった文字列と数だけで作る（ES module）
└── style.css   # 固有スタイル（prefix: .ks-）
```

- index.html・app.js・logic.js・art.js・style.css はセットで変わるので、変えたら `?v=` をそろえて上げる（app.js の `import ... from './logic.js?v=…'`・`'./art.js?v=…'` も）
- `QUESTIONS` は app.js に置く（`scripts/content-audit.mjs` が app.js から読む）
- Firebase compat SDK **13.3.0**（app / auth / database）+ 匿名認証、`../shared/js/rtdb-utils.js?v=20261005`、`../shared/js/room-qr.js?v=20261022`
- ゲームの通信は、ルームを作る・参加する・再読み込みでルームにもどるときだけ準備する（`firebaseReady`）。1台の画面では Firebase を初期化せず、接続もしない
- 共通の `shared/js/utils.js` の `shuffle`（1台の画面の質問の山）・`popIn`（質問・ゴールのカード）
- 描画は DOM API（textContent）。名前は innerHTML に入れない
- テストは `tests/kyoumi-sugoroku/`（ルームの決まりの単体テストと、隔離エミュレーターの E2E。使い方は同じフォルダの README）

## 画面構成・フロー

```
TOP（screen-top）: 「ルームを作る」（主）・「ルームに参加する」・「1台の画面であそぶ」
 ├── 1台の画面であそぶ → 設定（screen-settings） → ゲーム（screen-game）。質問・ゴールはモーダル
 ├── ルームを作る → 名前（screen-create） → 待合室
 ├── ルームに参加する → 名前＋ルームコード（screen-join） → 待合室
 └── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み） → 待合室
待合室（screen-waiting）: 参加者。ホストは「自分もプレイヤーとして参加する」・マス数・テーマ・「端末のない人を足す」・「はじめる」
  ↓「はじめる」（遊ぶ人 1〜10人）
ゲーム（screen-game）: 名前とコマ・番の案内・質問のカード（画面の中）・前の人が選んだもの・盤・サイコロ。ホストは「待合室に戻る」
  ↓ だれかがゴール
ゴールのカード（画面の中）: ホストは「もう一度あそぶ」（→ 待合室）。1台の画面では「もう一度あそぶ」（同じ設定ですぐはじめる）と「設定に戻る」
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「退出する」（ホストは「ルームを閉じる」）
- ルームでは、質問とゴールのカードをモーダルにせず画面の中（`#roomStage`）に出す（ルームバーや「待合室に戻る」がかくれないように）。1台の画面と同じカードの要素を `placeCards` で置きかえる
- 画面の見た目（2026-11-04 見直し）:
  - ヘッダーの説明の1行はトップだけに出す（ほかの画面では盤や質問を上に寄せる）
  - ルームでは、質問・ゴールのカードはどの幅でも盤の上に出す（2026-11-04 夕。盤の横に並べるのは見づらいとオーナー判断。カードが出ている間はサイコロの欄をかくす）
  - 前の人が選んだもの（`#lastPick`）: だれが・どの質問で・何を選んだか（「自由に話す」もふくむ）を盤の上に出す。次の人がサイコロを振ると消える（1台の画面・ルーム共通。`renderPick`）
  - 選択肢のある質問では、番の人に「選ぶと、次の人の番になるよ」、ほかの人に「○○さんが選ぶと、次の人の番になるよ」と出す
  - テーマの選択は、選んでいるものに右上のチェック印、選んでいないものはアイコンを淡く（画面共有でも見分けやすく）。自分の番でない人の画面の選択肢は、押せない見た目（淡い背景）
  - 質問のカードは幅 480px まで（「別の質問」「話せた！次の人へ」を折り返さずに並べる）。質問文は文節で折り返す（`word-break: auto-phrase`・`text-wrap: pretty`）
  - 「トップへ戻る」などの文字だけのボタン（`.ks-quiet-btn`）も高さ 44px
  - カードがある間はサイコロの欄をかくし、出た目はカードの上（テーマのとなり）に出す
  - 質問の宛先「○○ さんへ」には、その人のコマの色の番号を添える（1台の画面も同じ）
  - ルームバーは 860px より狭いと2段（ルームコードと退出／コピー・QR を3つ同じ幅）
  - 1台の画面の人数（1〜10人）は同じ幅で5つずつ2段。質問のボタンは同じ幅
  - 盤のマスはいつも同じ幅（`minmax(0, 1fr)`）。マスの中のコマと番号はマスの幅に合わせて小さくし（コンテナクエリの `cqi`）、6人が同じマスにいても3つずつ2段で正方形に収める（2026-11-04。せまい画面で5〜6人だと盤が画面からはみ出していたため）
- サイコロとコマのアニメーションは、各端末がルームの変化（`game.rollNo` が1増えた）を見て行う（サイコロ 0.6秒・1マス 0.25秒）。開いた直後・再読み込みのあとはアニメーションせずにいまの形を出す。カードはアニメーションが終わってから出す
- 番の案内（1台の画面: 「○○さんの番だよ」・サイコロのあと「○○さんがサイコロを振ったよ」）。ルーム: 自分の番「あなたの番だよ。「サイコロを振る」を押してね」、ホストが代わりに押せるとき「○○さんの番だよ（ホストは代わりに押せます）」、ほかの人「○○さんがサイコロを振る番だよ」、話す番「○○さんが話す番だよ」
- 「端末なし」の印は、ホストの画面にだけ出す（子どもどうしの画面で区別しない）。つながっていない人には「つながっていない」

## 遊ぶ画面の見た目（2026-11-18 オーナー依頼「見た目を楽しくリッチに」。1台の画面・ルーム共通）

ルール・同期・質問は変えず、遊ぶ画面の絵と動きだけを作り直した。

- **盤**: 景色（`art.js` の SVG。空 → 草原 → 森 → 水辺 → 夕方の丘。5段目からくり返す）の中を道が蛇行し、マスは道の上の丸い石（4色のくり返し・スタートは白・ゴールは金色で旗つき）。景色は同じマス数ならいつも同じ（決まった並びの乱数）。景色の色は場面の色なので直書き
- マスの位置は `art.js` の `squarePoints`（景色の座標）を、盤の幅と高さに対する割合で置く。盤の縦横比は `--ks-ratio`
- **マスとコマの要素は作りなおさない**（`renderBoard` は動いたコマだけを移す）。ルームではアニメーション中に60ミリ秒ごとに描くので、作りなおすと跳ねる動きがとちゅうで切れる。`#board .ks-square`・`.ks-square__num`・マスの中の `.ks-pawn` という形は E2E が見ているので変えない
- **コマ**: 色ごとのキャラクター（丸い耳・三角の耳・長い耳 × 6色。番号は中に書く）。CSS だけで描く。進むとき1マスずつ跳ね、いまの番の人のコマは白いふちでゆっくり上下する。同じマスに3人以上いるときは小さくして3つずつ2段
- **サイコロ**: 白いサイコロに目。数字は読み上げ用に文字で持ち（`#dice` の textContent。E2E も読む）、見た目は `data-n` で目を出す（`setDice`）。振っている間はゆれる（`is-rolling`）
- **質問のカード**: テーマごとの色（上の帯・テーマの札の丸いアイコン。`#questionCard` の `data-theme`）。文字の色は今までどおり
- **ゴール**: トロフィーのまわりの光と紙ふぶき（`celebrate`。5秒で消す・押せるものをじゃましない）
- 動きを減らす設定（`prefers-reduced-motion`）のときは、跳ねる・ゆれる・紙ふぶきを出さない。音は入れない
- 着想元の商品の見た目（ルーレット盤・車のコマ）は使わない

## 「人生の道」モード（2026-11-18 試作。1台の画面・ルーム）

オーナーの「人生をたどるすごろくを作りたい（20分くらい・マスでお題・選択式・だれかに聞きたいこと）」から。新しいツールにせず、興味スゴロクの今の遊び方を残したままモードを選べるようにする（2026-11-18 オーナー方針）。

- **選び方**: 「あそびかた」で「テーマで話す」（今までの遊び方・初期値）か「人生の道」。1台の画面は設定、ルームはホストが待合室で選ぶ。「人生の道」ではマス数とテーマの欄をかくし、「長さ」（みじかい・ふつう・ながい）を出す
- **盤**: 4段で、1段が1つの場面（小さいころ → いま → もうすぐ → おとなになったら）。マス数は 12・16・20・24・28（列は 3〜7）。人数からの初期値は 1〜2人 28・3人 24・4人 20・5〜6人 16・7〜10人 12（`L.lifeDefaultSize`）で、「長さ」で1段階ずらす。ルームは「はじめる」の時点の遊ぶ人数で決まる
- **マスの種類**（`L.LIFE_PATTERN` の順にくり返す。マスの色とアイコンで見分け、盤の下に見本を出す）。質問はどれも3択（＋「自由に話す」）にした（2026-11-18 オーナー「チャットで参加する人もいるので、選択式をなるべく」。声を使わなくても押すだけで答えられる。独立レビューの「声を使わない答え方がない」もこれで解消）:
  - えらぶ: 番の人が3択から選ぶ。選ぶと次の人の番で、選んだものは次のサイコロまで盤の上に出る
  - きく: ①番の人が聞く相手（いまいる人・「みんなに聞く」）を選ぶ → ②質問カード3枚から1枚を選ぶ（「別の質問」で3枚を引きなおす）→ ③**聞かれた人**が自分の端末で3択から選んで答える（「別の質問」に変えられる）。答えは「○○さんの答え（△△さんの質問）」として次のサイコロまで盤の上に出る。「みんなに聞く」と、1人で遊ぶとき（そばにいる人に聞く）は、選択肢は見るだけで、声やチャットで答えて番の人が「話せた！次の人へ」を押す
  - できごと: 先へ進む・みんな1マス進む・もう一度サイコロ・ひと息（何も起きない）。もどる・休みはない。できごとで進んだ先のマスでは何も起きない
  - いっしょ・よそう（**みんなが同時に選ぶマス**。2026-11-18 オーナーが選んだ案。ルームで遊ぶ人が2人以上のときだけ盤に出る。`game.votes`）:
    - いっしょ: みんなが自分の端末で、自分の答えを3択から選ぶ。番の人と同じだった人が1マス進む。みんな同じなら、選んだ人みんな（番の人も）もう1マス
    - よそう: 番の人は自分の答えを、ほかの人は「番の人はどれを選ぶか」を選ぶ。当てた人が1マス進み、当ててもらえたら番の人も1マス
    - 選んだものは、開くまで自分の画面にだけ出る（ほかの人には「選んだ人 2／3人」と、まだの人の名前だけ）。いまいる人がみんな選んだら自動で開く。番の人とホストは「開く」で先に開ける（選んでいない人は進まない）。開いたら、番の人の答えと、同じだった人（当てた人）を出し、番の人かホストが「進む」
    - 選べるのは自分のぶん。ホストは、自分・端末のない人・つながっていない人のぶん（`L.canVote`。つながっている人のぶんは本人が押す）。ホストが複数人のぶんを入れるときは「だれのぶんを選ぶ？」で切りかえる
    - 外れても何も失わない（進まないだけ）。順位は出さない。選んだものは、次の番で消える（残さない）
    - **結果の出し方**（独立レビューの指摘から。ルート AGENTS.md「判定・投票は、だれが何を出したかと細かい数を画面に出さない」）: どちらのマスも、**番の人の答えと、同じだった人（当てた人）だけを出す**。ちがう答え・外れた予想は、だれのものかも人数も出さない。進む人がいないときは「今回は、だれも進まないよ」。「いっしょ」は自分の好みを答えるマスだが、「同じだったら進む」という判定が付くので、「よそう」と同じ扱いにした（はじめは全員ぶんを出していた。独立レビューの2回目で、出さないほうが規約に沿うという意見。**全員ぶんを出す形に変えるかは、オーナーが決める**）
    - まだ選んでいない参加者（番の人でない人）が切断・退出して、いる人がみんな選んだ形になったら、ホストの見はりが4秒後に開く（`L.votesComplete`・`L.openIfComplete`）。番の人が退出したときは、ほかのカードと同じく、開かずにカードを捨てて次の人へ（`L.dropTalk`）
    - 既知の制約: ホストが切断している間は、ホストは在室のまま数え（`players` から消えない）、見はりも動かないので、自動では開かない・進まない。ホストがもどるのを待つ（ほかのマスと同じ。2分もどらなければルームは閉じる）
    - **1台の画面には出さない**（1つの画面で順に入れると、選んだものがみんなに見えてしまうため。`startLocalLife` が `offline: true` を渡す）
    - ホストの画面を画面共有しているときに、ホストが端末のない人のぶんを入れると、その人の選んだものは見えてしまう（既知の制約。みんなにみせる画面は作っていない）
- **サイコロは2つ**（2026-11-18 オーナーが選んだ案）: 振ると目が2つ出て、番の人が進む目を選ぶ（止まるマスの種類を見て選べる）。同じ目のときはそのまま進む
- **おうえん**（同上）: ゴールした人にも番が回り、サイコロのかわりに、まだゴールしていない人（いまいる人）を1人選んで1マス進める。先に着いた人が待つだけにならないように
- 「はなす」のマス（選択肢のない質問）は、全部3択にしたのでなくした
- **おわり**: みんながゴールしたらおわり。順位は出さず、ルームにも `winner` を持たない。ゴールした人がいても遊ぶ人が戻らないときは、ホストが「待合室に戻る」で終える
- **中身**: `app.js` の `LIFE_QUESTIONS`（「えらぶ」。場面ごとに12問）・`LIFE_ASK`（「きく」。場面ごとに5問）・`LIFE_EVENTS`（「できごと」9種類）。質問はどれも `{ q, choices }`。ルームでは場面のキーと一覧の中の番号で共有するので、**どれも並べ替え・途中の削除をしない（足すのは末尾だけ）**。`scripts/content-audit.mjs` が `LIFE_QUESTIONS`・`LIFE_ASK` を読む
- **ルームのデータ**（`kyoumisugoroku_rooms/{code}`。今までの形に足したもの。キーがなければ今までの遊び方）:
  - `mode: 'life'`・`lifeLen: -1 | 0 | 1`（待合室の設定）
  - `game.mode: 'life'`・`game.squares: 16〜28`・`game.done: [ゴールした人…]`・`game.arrived: { who: [番号…], rollNo }`（着いた人を次のサイコロまで知らせる）
  - `game.votes: true`（みんなが同時に選ぶマスのある盤。マスの並びは `L.LIFE_PATTERN_VOTES`）
  - `game.step: 'life3-roll' | 'life3-pick'（進む目を選んでいる）| 'life3-talk'`・`game.dice: [目, 目]`（選んでいる間だけ。ちがう 1〜6 の数が2つ）
  - `game.q: { kind, scene, idx, n }`（`kind` は erabu / kiku / dekigoto / issho / yosou）。いっしょ・よそうは `votes: { 順番の番号: 選択肢の番号 }`・`open: true`（開いたあと）を持つ。「きく」は `{ kind, scene, n, target, opts: [質問の番号3つ], phase: 'answer', idx }`（`target` は順番の番号・`-1` みんな・`-2` そばにいる人。段階は中身から決める: 相手なし→相手を選ぶ／相手と opts→質問を選ぶ／`phase: 'answer'` と idx→答える）
  - `game.last` に `quick: true`（サイコロはもう見せたので、コマの動きだけ）・`cheerBy`（おうえんした人）
  - `game.picked: { life: true, turn, scene, idx, choice }`（「きく」の答えは `kiku: true`・`turn` は答えた人・`by` は聞いた人）、`game.used` のキーは `life_{種類}_{場面}`・`life_event`
- **押せる人**: ふだんは番の人とホスト。「きく」で答える段階だけ、聞かれた人とホスト（`L.actingIndex`。`L.canAct` もこれで見る）。聞かれた人がいなくなったら番の人にもどり、相手を選びなおす
- **1台の画面**は、通信しないルーム（`net.offline`）として、ルームと同じ決まり（logic.js）・同じ画面（`renderRoomGame`）で動かす（`startLocalLife`）。遊ぶ人はみんな「端末のない人」の扱いで、押すのはいつもその画面。決まりを2か所に書かないため
- **ルームの決まり**（`logic.js`。今までの `roll`・`reask`・`choose`・`nextPlayer`・`skipAbsent` が、`game.mode` を見て「人生の道」の決まりへ分かれる。目を選ぶのは `pickDie`、おうえんは `cheer`）: 中身の形は `L.setLifeContent`（番号の一覧と、できごとの効き目）で渡す。「きく」の相手選びは `choose`（自分は選べない・選ぶと `n` が1増える）。できごとの効き目は `nextPlayer` で確定する。進む目を選んでいる途中で番の人がいなくなったら、`skipAbsent` がその目を捨てて次の人へ進める
- **独立レビュー（Codex・2026-11-18）で直したこと**:
  - 段階の名前を分けた（`game.step` は `life-roll`／`life-talk`。今までの遊び方は `roll`／`talk`）。モードを知らない古い版の画面が同じルームにいても、その画面からの操作は通らない（古い版は `roll`／`talk` のときだけ動く）。段階は `L.isRollStep`・`L.isTalkStep` で見る
  - 番の人が退出したときは `L.dropTalk`（カードの中身を確定させずに次の人へ）。できごとの効き目を退出で確定させない
  - カードが出ている段階なのに読めるカードがない（壊れた値）ときは、ホストの見はり（`hostWatchAbsent`）が4秒後に `L.dropTalk` で次の人へ進める（今までの遊び方も同じ）
  - `game.done` は「人生の道」のときだけ見る（今までの遊び方に余分なキーがあっても番をとばさない）。添字の欠けた形でも人がずれないように読む
  - 「きく」の相手は、いまルームにいる人だけ。選んだ相手がいなくなったら選びなおせる（`L.targetGone`）
  - 見送り（オーナー判断待ち）: 「はなす」「きく」に声を使わない答え方がない、という指摘。選択式を増やす方向で別に直す
  - 確かめ直し（同日）: 上の5件は解消。残るのは、カードが出ている間に番の人がいなくなったとき（切断・古い版の画面からの退出）に自動では進まないこと。今までの遊び方と同じで、ホストが代わりに「話せた！次の人へ」を押す（下の「既知の制約」。再読み込みの一瞬でカードを捨てないため、自動にはしていない）。段階の名前を分ける前の版は公開していないので、古い名前のままの人生の道のルームは本番にない
- **独立レビュー2回目（Codex・2026-11-18。3択・サイコロ2つ・質問カード・おうえん・10人の分）で直したこと**:
  - 段階の名前をもう一度分けた（`life2-roll`／`life2-pick`／`life2-talk`）。公開済みの前の版（`life-roll`／`life-talk`。サイコロ1つ・「はなす」あり）とは進み方がちがうので、同じルームに混ざっても、ちがう版の画面からの操作が通らないようにするため。**決まりを変えて、前の版の画面と混ざると困るときは、段階の名前を変える**
  - 前の版が作った人生の道のゲームを開いたら（`L.isOldLife`）、ホストの画面が待合室にもどして知らせる（この版では進められないため）。参加者には「ホストの画面が待合室にもどすのを待ってね」
  - 進む目が読めない（壊れた値）ときは、ホストの見はりが4秒後に、同じ人が振りなおすところにもどす（`L.pickBroken`・`L.dropPick`）
  - いちばん新しいサイコロの記録（`game.last`）が盤の中の正しい動きでないときは、アニメーションしない（`validLast`。大きすぎる値で画面が止まらないように）
  - おうえんの相手は、まだゴールしていない、いまいる人だけ（`L.cheerTargets`）。いない人を進めて、いる人だけでゲームを終わらせない。相手がいないときは「ほかの人がもどるのを待ってね」
  - 1台の画面で同じ名前を分けるとき、分けたあとの名前がほかの人と重ならないようにした
  - あそびかたの「おわりかた」を、遊び方ごとに書いた
- 段階の名前は、いっしょ・よそうを足したときに `life3-*` にした（マスの並びが変わり、公開中の前の版 `life2-*` の画面と混ざると、前の版が知らない種類のカードを捨ててしまうため）
- **決まっていないこと（試作の値。実装モデルが仮に決めた。オーナーの一言で差し替える）**: モードの名前「人生の道」・順位を出さないこと・できごとに学校や恋愛やお金や仕事を入れず想像の質問だけにしたこと・質問と3択と できごとの文・マスの種類の割合・マス数
- **試作で測った手番数**（1台の画面を自動で最後まで動かした値。サイコロ2つ・おうえん入り）: 1人 28マスで7回、2人 28マスで13回、4人 20マスで19回、6人 16マスで23回（サイコロを振った回数。ほかに、おうえんの番がある）。「きく」は3段階あるので、1回の番は前より長い。20分に収まるかは人の試遊で見る
- **まだ入れていないもの**（オーナーが選んだ案のうち）: おたすけカード・みんなで1つずつ選ぶマス。ほかに、書いて答える形（オーナーの案・未決）
- 利用回数: 「人生の道」ではじめたら `mode-life`（1台の画面の `start-local`、ルームの `start`・`players-{N}` も今までどおり数える）

## 設計方針：入力を最小化

セッション開始時に使うため、**設定操作は「トグルを数回押してスタート」で済む**ように絞り込んである。

- **1台の画面の名前は任意**（8文字まで）。空欄なら `プレイヤー1` 〜 `プレイヤー6` を自動付与し、入れたときはターン表示・質問の宛先・ゴールにその名前を使う。人数を変えても入れた名前は残す
  - 経緯: 当初は名前入力を廃止していたが、2026-11-04 フィードバックを受けて任意の欄として戻した
- ルームは名前が必須（room-K 共通のニックネーム制約: 8文字・同じルームで重複なし）
- 人数・マス数は select ではなくトグルボタン（1クリック選択）
- テーマは折りたたまず常時表示（メンターが子どもの反応に応じて即調整できるように）。最低 2 テーマ必須

※ 1台の画面で名前を必須にしないのは room-K 共通の「ニックネーム必須」ルールの例外にあたる。理由は「対面（オンライン通話）前提・共有端末・対話のきっかけツール」という性質上、参加者識別は通話側で済んでいるため。

## ルール（1台の画面・ルーム共通）

- **質問の重複回避**: テーマごとに出した質問を覚え、出しきったら最初から（ルームはいま出ている質問をすぐには出さない）
- **テーマの連続回避**: 直前と同じテーマが他にあれば避ける
- **ゴール**: サイコロの出目は最終マスで止まる（オーバーしない）。最初にゴールした人で終わり
- **ボード**: 5列の蛇行（偶数段は左→右、奇数段は右→左）。景色の中を通る道の上に、丸いマスを置く（下の「遊ぶ画面の見た目」）
- **コマ色**: 10色固定（`.ks-pawn--0` 〜 `--9`。7人目からは 2026-11-18 に足した）。同じマスに7人以上いるときは、4つずつ3段に小さく並べる
- **最低人数**: 1人から遊べる（自分だけの対話用途を想定）
- **選択肢**: 選ぶと次の人の番になる（「話せた！次の人へ」は出さない）。選んだものは盤の上に出て、次の人がサイコロを振ると消える。選ぶ前なら「別の質問」で変えられる

## ルーム（Realtime Database）

### データ構造

`kyoumisugoroku_rooms/{roomCode}`（ルールはワイルドカードのため変更なし）

```
  ├── status:        'waiting' | 'playing' | 'goal'
  ├── host / hostUid:ホストの名前と匿名ID
  ├── hostPlays:     boolean   # 自分もプレイヤーとして参加する（初期値 true。1対1で使うことが多いため）
  ├── squares:       10 | 15 | 20（初期値 15）
  ├── themes:        [テーマのキー...]（2つ以上。初期値は全部）
  ├── hostConnected / hostDisconnectedAt / createdAt / lastGameId
  ├── players/{name}: { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}: { joinedAt }                # 端末のない人（待合室でホストが足す）
  └── game/                                       # 「はじめる」で作り、待合室に戻ると消える
       ├── id, order: [name...], uids: {name: uid}, joined: {name: joinedAt}, proxy: {name: true}
       ├── squares, themes                        # 「はじめる」の時点の設定で固定
       ├── pos: [マスの番号...]                   # order と同じ並び
       ├── turn: 番の人の位置, step: 'roll' | 'talk'
       ├── rollNo: 振った回数（アニメーションと古い操作の見分けに使う）
       ├── last: { dice, from, to, turn }         # いちばん新しいサイコロ
       ├── q: { theme, idx, n }                   # いまの質問（step が talk のときだけ）
       ├── picked: { turn, theme, idx, choice }   # 前の人が選んだもの。choice は選択肢の番号、-1 は「自由に話す」。次のサイコロで消す
       ├── used: { theme: [idx...] }, lastTheme   # 出した質問・直前のテーマ
       └── winner: ゴールした人の位置（status が goal のとき）
```

- 質問はテーマのキーと `QUESTIONS` の中の番号で置く。**QUESTIONS は並べ替え・途中の削除をしない（足すのは末尾だけ）**
- 選んだ選択肢は `game.picked` に次の人がサイコロを振るまでだけ置き、振ると消える（内省の回答を残さない方針と両立させるため、記録・集計はしない）
- 読み込むときは壊れた値を読み飛ばす（`questionOf`・`squaresOf`・`themesOf`）

### status 遷移

```
waiting ─はじめる（ホスト）→ playing ─だれかがゴール→ goal ─もう一度あそぶ（ホスト）→ waiting
playing ─待合室に戻る（ホスト・確認あり）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

### transaction 設計

すべてルーム全体への `transaction()`。乱数（出目・質問）は transaction の外で作った種から決める（`seededRandom`）。
番の操作は押した時点の `game.id`・`rollNo`（選ぶは質問の `n` も）を捕まえて、中で一致を確かめる（古い画面・二度押しで次の番を変えない）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | `waiting`・名前が空いている（ホスト・端末のない人と同じ名前は不可）・遊ぶ人10人未満 → `players/{name}`。遊んでいる途中は `game.uids` の持ち主だけ入りなおせる（`transactRetry`） |
| 設定（遊ぶ・マス数・テーマ）・端末のない人を足す／外す | ホスト | `waiting`。遊ぶ人は10人まで（ホストが遊ぶにする・足すときも見る） |
| はじめる | ホスト | `waiting`・遊ぶ人1〜10人 → `game` |
| サイコロを振る | 番の人・ホスト（`canAct`） | `playing`・`step: roll`・id/rollNo 一致 → `picked` を消す。進んでゴールなら `goal`、でなければ質問を出して `talk` |
| 別の質問 | 同上 | `talk`・id/rollNo/n 一致 → 同じテーマの別の質問 |
| 選ぶ | 同上 | `talk`・id/rollNo/n 一致・選択肢の番号か -1 → `picked` に置き、`q` を消して次にいる人の `roll` |
| 話せた！次の人へ | 同上 | `talk`・id/rollNo 一致 → `q` を消し、次にいる人の `roll` |
| 退出 | ゲスト | 自分の在室を消す。自分の番だったら同じ transaction で次の人へ（`talk` なら次の人へ、`roll` ならとばす） |
| いない人をとばす | ホスト | 振る番の人がいない状態が4秒続いたら（`ABSENT_GRACE_MS`。再読み込みの一瞬は待つ）、次にいる人へ（`hostWatchAbsent` → `skipAbsent`） |
| 待合室に戻る・もう一度あそぶ | ホスト | `playing`／`goal`・id 一致 → `waiting`・`game` を消す |

- 順番は「はじめる」の時点の遊ぶ人を参加した順に固定（ホストが遊ぶときはホストが最初）。次の番は順番どおりに回し、いない人はとばす（端末のない人はいつもいる）
- 話す番の人が切断した（退出ではない）ときは、ホストが代わりに「話せた！次の人へ」を押す

## 接続・切断・再接続

しるしでヒントと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- コマと名前の予約はゲームにあるので、在室が消えても残る。戻ると続きから
- ホスト切断中、ゲストには共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`。ホストが戻ると消え、続きから遊べる
- 遊んでいる途中に新しい名前では参加できない（「もうゲームが始まっているよ」）
- 再読み込み: `sessionStorage['kyoumisugoroku_session'] = { role, nickname, roomCode, uid, joinedAt }` で同じ席にもどる

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。ゴールのカードでは自動削除しない（「もう一度あそぶ」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）

## 利用回数（stats.js）

「1回」は1ゲーム（はじめてからゴールまで）。

| 項目 | 数えるとき・端末 |
|---|---|
| `start-local` | 1台の画面で「ゲームスタート」・ゴールのあと「もう一度あそぶ」 |
| `room-create` | ルームができた（ホスト） |
| `start`・`players-{N}` | ルームで「はじめる」（ホスト。N は遊ぶ人の数。進行だけのホストは含めない） |

| `again` | ゴールのあと「もう一度あそぶ」（ホスト） |

## テーマ & 質問データ
`app.js` 内の `QUESTIONS` を直接編集する（**末尾に足すだけ**。上の「データ構造」）。テーマは6種類:

| キー | ラベル | アイコン |
|------|--------|---------|
| suki | 好きなもの | favorite |
| yatte | やってみたい | rocket_launch |
| moshimo | もしも… | auto_awesome |
| jibun | 自分のこと | person |
| saikin | 最近のこと | today |
| tokui | 得意・チャレンジ | star |

質問データは `string | { q, choices }` のハイブリッド。選択肢ありの場合、「自由に話す」ボタンが自動で追加される。

### 質問作成ガイドライン（AGENTS.md コンテンツガイドラインに準拠）
- 学校・勉強・宿題・テスト・成績を連想させる表現を使わない
- 恋愛・暴力・ダークな話題を避ける
- 正解のない開かれた質問にする
- 「答えたくない」と感じにくい軽いトーン

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は index.html と app.js を見る。logic.js にタイマーはない
- **進行の一部をホスト以外も行う**: 番の人がサイコロ・質問のボタンを押す（スゴロクの手番のため）
- **ホストの初期値は遊ぶ**（`hostPlays: true`）。1対1（メンターと子ども）で使うことが多く、質問に秘密はないため
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **選んだ選択肢をみんなに出す**（オーナー判断 2026-11-04、同日夕に「選ぶと次の人の番・次のサイコロまで盤の上に出す」へ改訂）。残さない
  - 「今週のコンディションは？」「話すのは？」のような自分の状態を答える問いも同じに出し、番を回すボタンは「話せた！次の人へ」のまま（2026-11-08 P6 監査・オーナー判断「今のまま」。答えにくいときは「別の質問」で替えられるため）。次の監査で同じ理由だけでは出さない
- **みんなにみせる画面はない**: 秘密の情報がないので、ホストの画面をそのまま共有してよい

## 入れない機能

- 音（サイコロ・ゴールも音なし）
- 答えの記録・集計・ふりかえりの一覧（選んだ選択肢は次の人がサイコロを振ると消える）
- 遊んでいる途中の新しい参加者・端末のない人の途中追加

## 既知の制約

- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- ホストが切断している間は、いない人をとばす見はり（`hostWatchAbsent`）が進まない（番の人が戻るか、ホストが戻れば進む）
- 話す番の人が切断したときは自動では進まない（ホストが代わりに「話せた！次の人へ」を押す）
