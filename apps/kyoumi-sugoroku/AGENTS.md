# 興味スゴロク 仕様書

## 目的・使用シーン
不登校支援のオンラインメンタリングセッションで、子どもとの対話のきっかけをつくるスゴロクツール。
マスに止まった人が、出てきた質問について話す。

| ロール | 説明 |
|--------|------|
| 操作者 | 1台の画面: メンター。ルーム: 番の人（自分の端末）とホスト（メンター） |
| 参加者 | 1〜6人 |

**利用シーン**
- セッション開始後のアイスブレイク
- 自己紹介や興味の探索
- 話題に困ったときの対話のきっかけづくり（作戦会議など）

## 遊び方は2つ（2026-11-04 オーナー決定）

- **ルーム（各自の端末）**: ホストが「ルームを作る」、ほかの人は「ルームに参加する」（名前 → ルームコードの順）。自分の番は自分の端末で「サイコロを振る」。ホストはだれの番でも代わりに押せる
- **1台の画面であそぶ**: これまでの遊び方。1台の画面をみんなで見て、メンターが押す。ゲームの通信はしない（利用回数カウンタだけ）
- 経緯: 2026-11-04 フィードバック（「名前を入れたい」「みんなが自分でサイコロを振れたら」）。名前は1台の画面の任意の欄で対応し、ルームは同日オーナーが次を決めて追加した:
  1. 1台の画面であそぶは残す
  2. 「サイコロを振る」「別の質問」「話せた！次の人へ」・選択肢は、番の人とホストが押せる
  3. 選択肢で選んだものは、みんなの画面に出す（その番の間だけ。次の人へ進むと消える）→ 同日改訂（下の 5）
  5. （2026-11-04 夕 改訂）選択肢は、選ぶと次の人の番になる（「選ぶ → 話せた！次の人へ」の2回押しをやめる）。選んだものは盤の上に小さく残し、次の人がサイコロを振ると消える。1台の画面・ルームとも同じ。ルームで質問のカードを盤の横に並べるのは見づらいのでやめ、どの幅でも盤の上に出す
  4. 人数は6人まで（1台の画面も6人まで。コマの色を2色足した）

## 技術スタック・ファイル

```
apps/kyoumi-sugoroku/
├── AGENTS.md   # この仕様書
├── index.html  # 画面の骨組み・howto.js の設定
├── app.js      # 質問データ（THEMES・QUESTIONS）・1台の画面・ルームの通信と画面（ES module）
├── logic.js    # ルームの決まり（DOM も Firebase も使わない。transaction の中から呼ぶ）
└── style.css   # 固有スタイル（prefix: .ks-）
```

- index.html・app.js・logic.js・style.css はセットで変わるので、変えたら `?v=` をそろえて上げる（app.js の `import ... from './logic.js?v=…'` も）
- `QUESTIONS` は app.js に置く（`scripts/content-audit.mjs` が app.js から読む）
- Firebase compat SDK **10.14.1**（app / auth / database）+ 匿名認証、`../shared/js/rtdb-utils.js?v=20261005`、`../shared/js/room-qr.js?v=20261022`
- ゲームの通信は、ルームを作る・参加する・再読み込みでルームにもどるときだけ準備する（`firebaseReady`）。1台の画面では Firebase を初期化せず、接続もしない
- 共通の `shared/js/utils.js` の `shuffle`（1台の画面の質問の山）・`popIn`（質問・ゴールのカード）
- 描画は DOM API（textContent）。名前は innerHTML に入れない
- テストは `tests/kyoumi-sugoroku/`（ルームの決まりの単体テストと、隔離エミュレーターの E2E。使い方は同じフォルダの README）

## 画面構成・フロー

```
TOP（screen-top）: 「ルームを作る」（主）・「ルームに参加する」・「1台の画面であそぶ」
 ├── 1台の画面であそぶ → 設定（screen-settings） → ゲーム（screen-game）。質問・ゴールはモーダル
 ├── ルームを作る → 名前（screen-create） → 待合室
 ├── ルームに参加する → 名前＋ルームコード（screen-join） → 待合室
 └── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み） → 待合室
待合室（screen-waiting）: 参加者。ホストは「自分もプレイヤーとして参加する」・マス数・テーマ・「端末のない人を足す」・「はじめる」
  ↓「はじめる」（遊ぶ人 1〜6人）
ゲーム（screen-game）: 名前とコマ・番の案内・質問のカード（画面の中）・前の人が選んだもの・盤・サイコロ。ホストは「待合室に戻る」
  ↓ だれかがゴール
ゴールのカード（画面の中）: ホストは「もう一度あそぶ」（→ 待合室）。1台の画面では「もう一度あそぶ」（同じ設定ですぐはじめる）と「設定に戻る」
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「退出する」（ホストは「ルームを閉じる」）
- ルームでは、質問とゴールのカードをモーダルにせず画面の中（`#roomStage`）に出す（ルームバーや「待合室に戻る」がかくれないように）。1台の画面と同じカードの要素を `placeCards` で置きかえる
- 画面の見た目（2026-11-04 見直し）:
  - ヘッダーの説明の1行はトップだけに出す（ほかの画面では盤や質問を上に寄せる）
  - ルームでは、質問・ゴールのカードはどの幅でも盤の上に出す（2026-11-04 夕。盤の横に並べるのは見づらいとオーナー判断。カードが出ている間はサイコロの欄をかくす）
  - 前の人が選んだもの（`#lastPick`）: だれが・どの質問で・何を選んだか（「自由に話す」もふくむ）を盤の上に出す。次の人がサイコロを振ると消える（1台の画面・ルーム共通。`renderPick`）
  - 選択肢のある質問では、番の人に「選ぶと、次の人の番になるよ」、ほかの人に「○○さんが選ぶと、次の人の番になるよ」と出す
  - テーマの選択は、選んでいるものに右上のチェック印、選んでいないものはアイコンを淡く（画面共有でも見分けやすく）。自分の番でない人の画面の選択肢は、押せない見た目（淡い背景）
  - 質問のカードは幅 480px まで（「別の質問」「話せた！次の人へ」を折り返さずに並べる）。質問文は文節で折り返す（`word-break: auto-phrase`・`text-wrap: pretty`）
  - 「トップへ戻る」などの文字だけのボタン（`.ks-quiet-btn`）も高さ 44px
  - カードがある間はサイコロの欄をかくし、出た目はカードの上（テーマのとなり）に出す
  - 質問の宛先「○○ さんへ」には、その人のコマの色の番号を添える（1台の画面も同じ）
  - ルームバーは 860px より狭いと2段（ルームコードと退出／コピー・QR を3つ同じ幅）
  - 1台の画面の人数（1〜6人）は同じ幅で1列、480px 以下は3つずつ2段。質問のボタンは同じ幅
  - 盤のマスはいつも同じ幅（`minmax(0, 1fr)`）。マスの中のコマと番号はマスの幅に合わせて小さくし（コンテナクエリの `cqi`）、6人が同じマスにいても3つずつ2段で正方形に収める（2026-11-04。せまい画面で5〜6人だと盤が画面からはみ出していたため）
- サイコロとコマのアニメーションは、各端末がルームの変化（`game.rollNo` が1増えた）を見て行う（サイコロ 0.6秒・1マス 0.25秒）。開いた直後・再読み込みのあとはアニメーションせずにいまの形を出す。カードはアニメーションが終わってから出す
- 番の案内（1台の画面: 「○○さんの番だよ」・サイコロのあと「○○さんがサイコロを振ったよ」）。ルーム: 自分の番「あなたの番だよ。「サイコロを振る」を押してね」、ホストが代わりに押せるとき「○○さんの番だよ（ホストは代わりに押せます）」、ほかの人「○○さんがサイコロを振る番だよ」、話す番「○○さんが話す番だよ」
- 「端末なし」の印は、ホストの画面にだけ出す（子どもどうしの画面で区別しない）。つながっていない人には「つながっていない」

## 設計方針：入力を最小化

セッション開始時に使うため、**設定操作は「トグルを数回押してスタート」で済む**ように絞り込んである。

- **1台の画面の名前は任意**（8文字まで）。空欄なら `プレイヤー1` 〜 `プレイヤー6` を自動付与し、入れたときはターン表示・質問の宛先・ゴールにその名前を使う。人数を変えても入れた名前は残す
  - 経緯: 当初は名前入力を廃止していたが、2026-11-04 フィードバックを受けて任意の欄として戻した
- ルームは名前が必須（room-K 共通のニックネーム制約: 8文字・同じルームで重複なし）
- 人数・マス数は select ではなくトグルボタン（1クリック選択）
- テーマは折りたたまず常時表示（メンターが子どもの反応に応じて即調整できるように）。最低 2 テーマ必須

※ 1台の画面で名前を必須にしないのは room-K 共通の「ニックネーム必須」ルールの例外にあたる。理由は「対面（オンライン通話）前提・共有端末・対話のきっかけツール」という性質上、参加者識別は通話側で済んでいるため。

## ルール（1台の画面・ルーム共通）

- **質問の重複回避**: テーマごとに出した質問を覚え、出しきったら最初から（ルームはいま出ている質問をすぐには出さない）
- **テーマの連続回避**: 直前と同じテーマが他にあれば避ける
- **ゴール**: サイコロの出目は最終マスで止まる（オーバーしない）。最初にゴールした人で終わり
- **ボード**: 5列グリッドの蛇行（偶数段は左→右、奇数段は右→左）
- **コマ色**: 6色固定（`.ks-pawn--0` 〜 `--5`）
- **最低人数**: 1人から遊べる（自分だけの対話用途を想定）
- **選択肢**: 選ぶと次の人の番になる（「話せた！次の人へ」は出さない）。選んだものは盤の上に出て、次の人がサイコロを振ると消える。選ぶ前なら「別の質問」で変えられる

## ルーム（Realtime Database）

### データ構造

`kyoumisugoroku_rooms/{roomCode}`（ルールはワイルドカードのため変更なし）

```
  ├── status:        'waiting' | 'playing' | 'goal'
  ├── host / hostUid:ホストの名前と匿名ID
  ├── hostPlays:     boolean   # 自分もプレイヤーとして参加する（初期値 true。1対1で使うことが多いため）
  ├── squares:       10 | 15 | 20（初期値 15）
  ├── themes:        [テーマのキー...]（2つ以上。初期値は全部）
  ├── hostConnected / hostDisconnectedAt / createdAt / lastGameId
  ├── players/{name}: { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}: { joinedAt }                # 端末のない人（待合室でホストが足す）
  └── game/                                       # 「はじめる」で作り、待合室に戻ると消える
       ├── id, order: [name...], uids: {name: uid}, joined: {name: joinedAt}, proxy: {name: true}
       ├── squares, themes                        # 「はじめる」の時点の設定で固定
       ├── pos: [マスの番号...]                   # order と同じ並び
       ├── turn: 番の人の位置, step: 'roll' | 'talk'
       ├── rollNo: 振った回数（アニメーションと古い操作の見分けに使う）
       ├── last: { dice, from, to, turn }         # いちばん新しいサイコロ
       ├── q: { theme, idx, n }                   # いまの質問（step が talk のときだけ）
       ├── picked: { turn, theme, idx, choice }   # 前の人が選んだもの。choice は選択肢の番号、-1 は「自由に話す」。次のサイコロで消す
       ├── used: { theme: [idx...] }, lastTheme   # 出した質問・直前のテーマ
       └── winner: ゴールした人の位置（status が goal のとき）
```

- 質問はテーマのキーと `QUESTIONS` の中の番号で置く。**QUESTIONS は並べ替え・途中の削除をしない（足すのは末尾だけ）**
- 選んだ選択肢は `game.picked` に次の人がサイコロを振るまでだけ置き、振ると消える（内省の回答を残さない方針と両立させるため、記録・集計はしない）
- 読み込むときは壊れた値を読み飛ばす（`questionOf`・`squaresOf`・`themesOf`）

### status 遷移

```
waiting ─はじめる（ホスト）→ playing ─だれかがゴール→ goal ─もう一度あそぶ（ホスト）→ waiting
playing ─待合室に戻る（ホスト・確認あり）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

### transaction 設計

すべてルーム全体への `transaction()`。乱数（出目・質問）は transaction の外で作った種から決める（`seededRandom`）。
番の操作は押した時点の `game.id`・`rollNo`（選ぶは質問の `n` も）を捕まえて、中で一致を確かめる（古い画面・二度押しで次の番を変えない）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | `waiting`・名前が空いている（ホスト・端末のない人と同じ名前は不可）・遊ぶ人6人未満 → `players/{name}`。遊んでいる途中は `game.uids` の持ち主だけ入りなおせる（`transactRetry`） |
| 設定（遊ぶ・マス数・テーマ）・端末のない人を足す／外す | ホスト | `waiting`。遊ぶ人は6人まで（ホストが遊ぶにする・足すときも見る） |
| はじめる | ホスト | `waiting`・遊ぶ人1〜6人 → `game` |
| サイコロを振る | 番の人・ホスト（`canAct`） | `playing`・`step: roll`・id/rollNo 一致 → `picked` を消す。進んでゴールなら `goal`、でなければ質問を出して `talk` |
| 別の質問 | 同上 | `talk`・id/rollNo/n 一致 → 同じテーマの別の質問 |
| 選ぶ | 同上 | `talk`・id/rollNo/n 一致・選択肢の番号か -1 → `picked` に置き、`q` を消して次にいる人の `roll` |
| 話せた！次の人へ | 同上 | `talk`・id/rollNo 一致 → `q` を消し、次にいる人の `roll` |
| 退出 | ゲスト | 自分の在室を消す。自分の番だったら同じ transaction で次の人へ（`talk` なら次の人へ、`roll` ならとばす） |
| いない人をとばす | ホスト | 振る番の人がいない状態が4秒続いたら（`ABSENT_GRACE_MS`。再読み込みの一瞬は待つ）、次にいる人へ（`hostWatchAbsent` → `skipAbsent`） |
| 待合室に戻る・もう一度あそぶ | ホスト | `playing`／`goal`・id 一致 → `waiting`・`game` を消す |

- 順番は「はじめる」の時点の遊ぶ人を参加した順に固定（ホストが遊ぶときはホストが最初）。次の番は順番どおりに回し、いない人はとばす（端末のない人はいつもいる）
- 話す番の人が切断した（退出ではない）ときは、ホストが代わりに「話せた！次の人へ」を押す

## 接続・切断・再接続

しるしでヒントと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- コマと名前の予約はゲームにあるので、在室が消えても残る。戻ると続きから
- ホスト切断中、ゲストには共通のオーバーレイ（2分）。`ORPHAN_TTL_MS = 2 * 60 * 1000`。ホストが戻ると消え、続きから遊べる
- 遊んでいる途中に新しい名前では参加できない（「もうゲームが始まっているよ」）
- 再読み込み: `sessionStorage['kyoumisugoroku_session'] = { role, nickname, roomCode, uid, joinedAt }` で同じ席にもどる

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。ゴールのカードでは自動削除しない（「もう一度あそぶ」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）

## 利用回数（stats.js）

「1回」は1ゲーム（はじめてからゴールまで）。

| 項目 | 数えるとき・端末 |
|---|---|
| `start-local` | 1台の画面で「ゲームスタート」・ゴールのあと「もう一度あそぶ」 |
| `room-create` | ルームができた（ホスト） |
| `start`・`players-{N}` | ルームで「はじめる」（ホスト。N は遊ぶ人の数。進行だけのホストは含めない） |
| `finish` | ゴールした（ゴールになるサイコロを確定させた端末） |
| `again` | ゴールのあと「もう一度あそぶ」（ホスト） |

## テーマ & 質問データ
`app.js` 内の `QUESTIONS` を直接編集する（**末尾に足すだけ**。上の「データ構造」）。テーマは6種類:

| キー | ラベル | アイコン |
|------|--------|---------|
| suki | 好きなもの | favorite |
| yatte | やってみたい | rocket_launch |
| moshimo | もしも… | auto_awesome |
| jibun | 自分のこと | person |
| saikin | 最近のこと | today |
| tokui | 得意・チャレンジ | star |

質問データは `string | { q, choices }` のハイブリッド。選択肢ありの場合、「自由に話す」ボタンが自動で追加される。

### 質問作成ガイドライン（AGENTS.md コンテンツガイドラインに準拠）
- 学校・勉強・宿題・テスト・成績を連想させる表現を使わない
- 恋愛・暴力・ダークな話題を避ける
- 正解のない開かれた質問にする
- 「答えたくない」と感じにくい軽いトーン

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は index.html と app.js を見る。logic.js にタイマーはない
- **進行の一部をホスト以外も行う**: 番の人がサイコロ・質問のボタンを押す（スゴロクの手番のため）
- **ホストの初期値は遊ぶ**（`hostPlays: true`）。1対1（メンターと子ども）で使うことが多く、質問に秘密はないため
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **選んだ選択肢をみんなに出す**（オーナー判断 2026-11-04、同日夕に「選ぶと次の人の番・次のサイコロまで盤の上に出す」へ改訂）。残さない
  - 「今週のコンディションは？」「話すのは？」のような自分の状態を答える問いも同じに出し、番を回すボタンは「話せた！次の人へ」のまま（2026-11-08 P6 監査・オーナー判断「今のまま」。答えにくいときは「別の質問」で替えられるため）。次の監査で同じ理由だけでは出さない
- **みんなにみせる画面はない**: 秘密の情報がないので、ホストの画面をそのまま共有してよい

## 入れない機能

- 音（サイコロ・ゴールも音なし）
- 答えの記録・集計・ふりかえりの一覧（選んだ選択肢は次の人がサイコロを振ると消える）
- 遊んでいる途中の新しい参加者・端末のない人の途中追加

## 既知の制約

- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- ホストが切断している間は、いない人をとばす見はり（`hostWatchAbsent`）が進まない（番の人が戻るか、ホストが戻れば進む）
- 話す番の人が切断したときは自動では進まない（ホストが代わりに「話せた！次の人へ」を押す）
