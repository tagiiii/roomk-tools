# のりあいロード 仕様書

## 目的・使用シーン

みんなで右へ進む、横スクロールの協力アクション（2〜10人）。友だちの頭に乗って高い所へ上がる・重い箱をみんなで押す・人数で動くリフトなど、1人では進めないしかけを、力を合わせてこえていく。全員がゴールのとびらに入るとクリア。

- **core value**: 「乗って」「押して」と声をかけ合いながら、手を動かして力を合わせること。勝ち負け・順位・点数はない（タイムアタックは、みんなでクリアするまでの時間だけ。下の「タイムアタック」）
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの2人でも遊べる）。種類は「当てっこ・協力ゲーム」（`data-genre="atekko"`）
- 着想元の紹介は**段階3**（早見表は系統ラベル「協力アクション系」だけ・更新情報には書かない。2026-11-16 オーナー）。ジャンルの定番の仕組み（人の上に乗る・人数で押す箱など）を使っているが、名前・キャラクター・見た目・ステージは独自で、特定の作品を写していない

> 経緯: 2026-11-16 にオーナーが「協力必須の横スクロールアクションパズル」を相談し、人の上に乗る階段など、ジャンルによくある仕組みを全部入れて `drafts/noriai-road/` で試作した（PR #304。ウィンドウの間だけでつなぎ、遅れをまねて確かめた）。同日、オーナーが本体にすると決め、名前「のりあいロード」・DB ルールへの名前空間 `noriairoad_rooms` の追加・イラストの作成・着想元は系統名だけ、を決めた。試作のフォルダは本体にしたときに消した（中身は git の履歴に残っている）。
> 同日、「ステージを増やしてほしい」のフィードバックで、オーナーが「今のしかけの組み合わせ・手分けするしかけ・ジャンプ台など新しい動き」を選び、ステージ6〜10を足した（ばね・同時のスイッチ・番号のスイッチ・人の塔・箱の足場）。どれもこのジャンルによくある仕組みで、特定の作品のステージは写していない。
> 2026-11-16 に「10人ほどで遊びたい」というフィードバックがあり、同日オーナーが「10人まで作り直す」と決めた（4人前提だった「みんな」の数字・ひも・はじめの場所・色・書く間かくを直した。下の各節）。
> 2026-11-18、フィードバックボードの「タイムアタックがしたい」（オーナーが「直す」にした）で、タイムアタックを足した（下の「タイムアタック」）。
> 2026-11-18、フィードバックボードの「もう少し難しいマップを」（オーナーが「直す」にした）で、ステージ11「ひもでつながる長い道」・12「いちばん長い道」を足した。新しいしかけは足さず、これまでの区間を長く続けてつないで、むずかしくした。
> 2026-11-18、オーナーが「使わなくてもクリアできるブロックがある。出てきたものを使わないとクリアできない仕組みがいい」と言い、(1) シーソーの箱と箱の足場を、最後の1人は箱を使わないと進めない形にし、(2) しかけブロック（みんなで乗ると持ち運べるばねが出る）と、そのばねがないとわたれない穴のステージ13を足した。このゲームは人が重さにも足場にもなるので、ものを必ず使わせるには「最後の1人の下にはだれもいない」ことを使う。
> 前に「そろってゴール」をリアルタイムのアクションにしなかったのは、位置を送り続けると Firebase の無料枠と遅延の両方で厳しいためだった。このツールでは、送るのを「変わったときだけ・1秒に10回まで」にし、遅れても困らない作り（下の「同期の作り」）にした。

## セッション条件（ツール一覧のカードと同じ）

| 項目 | 値 |
|---|---|
| 人数 | 2〜10人（1台のパソコンで遊ぶのは2〜4人） |
| 目安時間 | 5〜15分 |
| 利用シーン | ボドゲクラブ・ひろば・作戦会議 |
| 話す量 | ひとことで・話さなくてよい（「ひとこと」で、決まった言葉をえらんで送れる） |

## ルール

ルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/noriai-road/engine.test.cjs`。

| 項目 | 内容 |
|---|---|
| 動かす | 左右で歩く・ジャンプ・持っているものを投げる。ひとりで跳べる高さは 1.7マス（2マスの段は、ひとりでは上がれない） |
| 人の上に乗る | ほかの人の頭は、上から乗れる床。乗ったまま、下の人が歩く・運ばれると、いっしょに動く。横からはすりぬける（押し合いにしない。遅れがあると、押し合いはずれやすいため） |
| スイッチととびら | 同じしるし（色と形）のスイッチに、人か箱が乗っている間だけ開く。閉じかけのとびらに人・箱が重なっていたら、出るまで閉じない |
| 番号のかべ | その番号の人だけ通れる。向こうのスイッチをその人がおさえると、みんな通れる。番号のブロックは、その番号の人だけ入れる（中のカギをとる） |
| 重い箱 | 箱の数字の人数が、同じ向きへ押すと動く（「みんな」は遊ぶ人数。ただし5まで＝`ALL_CAP`）。箱はとびらで止まる（スイッチの上から押し出さないため） |
| リフト・動く床 | 数字の人数が乗る（人の上に乗っている人も数える）と動く。人数がへっても1.5秒待ってから戻る（おりる間に下がらないため）。動くのに要る人数は、数字と「まだ向こうへ行っていない人（通信が切れた人をのぞく）」の少ないほう（`platNeed`）。6人以上で「みんな」が5のとき、何回かに分かれて運び、最後の組が5人より少なくても動けるように。床の下の数は、この人数を出す |
| シーソー | 重いほうが下がる（人は重さ1。箱の重さは押すのに要る人数で、シーソーの箱は2）。傾きは1.5マスまで（下がった側からも、床へ跳んで出られる高さ）。右のシーソーのすぐとなりに3マスの段（上にカギかボール。下に床はない）があり、上がった右のシーソーから上がる。人は人の頭からも上がれるが、**最後の1人は、左に箱を乗せないと上がれない**（最後の人の下にはだれもいないため。2026-11-18）。上がった右のシーソーへは、左の床から走って跳び移れる（左の板 1.8マス・右の板 2.8マス・あいだ 0.4マス。2026-11-19。前は左の板が 2.8マスで遠く、箱を押した2人のうち最後の1人が左側に残って進めなかった。`engine.test.cjs` で、押して乗せる・床から跳び移るを確かめる） |
| ボール | 持つとジャンプできない。投げてわたす。高いかごに、ふちより上から落ちると入り、とびらが開いたままになる。地面から投げても届かず、友だちの頭の上から投げると届く |
| カギとゴール | カギを持ってゴールのとびらにふれると開く。開いたとびらに入った人は消え、下（投げる）で、とびらの左どなりへ出られる（入っている間は、「投げる」のボタンが「出る」になり、キーの案内も出かたを言う）。いる人がみんな入るとクリア |
| 人の塔（ステージ6・9・10） | 3マスの台。上のスイッチをおさえている間だけ、下のとびらが開く。ひとりの頭の上からでは届かず、2人重なった上から跳ぶと上がれる。**2人で遊ぶときは2マス**（3マスには3人要るため）。スイッチは、とびらのすぐ上（ひもでつながっていても、下の人がとびらを通れる近さ） |
| 箱の足場（ステージ6・9・11・13） | 2マスのかべ（下の通り道はない）。押す人数1の箱を、かべの前まで押す（箱はかべで止まる）。人は人の頭から上がれるが、**最後の1人は、箱に乗らないと上がれない**（2026-11-18。前は3マスの台とスイッチで、3人以上だと人の塔で上がれて、箱を使わなくてもよかった）。ひものステージ（9・11）では、上の人にひもで引き上げてもらうこともできる |
| しかけブロック・持ち運べるばね（ステージ13） | 2マス幅・1マスの高さのブロック。数字の人数（人の上に乗っている人も数える）がブロックに乗ると開いて、上に持ち運べるばねが出る（`springBlock`。数字は2と「みんな」）。ばねは歩いてもひろわず、「ひろう」（下・投げる）で持ち、「置く」（もう一度）で目の前の足もとに置く。持ったままジャンプできる。置いてあるばねに乗ると、床のばねと同じに跳ぶ。その先の穴は5マスで、ふつうのジャンプでも、人の頭からでも（2〜4人重なっても）わたれない。穴の手前に置いたばねからならわたれる。**最後の1人も、ばねがないとわたれない**。穴に落ちたばねは、ブロックの上に戻る（2026-11-18 オーナー。「出てきたものを使わないとクリアできない仕組み」） |
| ばね（ステージ7・10） | 床のばねに立つと、4.6マスの高さまで跳ぶ（`SPRING_H`。ジャンプのキーをはなしても低くならない）。ふつうのジャンプでとどかない4マス幅の穴と、4マスのかべ（上にカギ）をこえる。ボールを持っていても跳ぶ |
| 同時のスイッチ（ステージ8・10） | とびらに `all`（同じしるしのスイッチが全部おさえられたとき）と `latch`（一度開いたら、ずっと開いたまま）。とびらに「おさえている数/全部の数」を出す。下のスイッチと、2マスの高さの足場の上のスイッチの組（2人なら、1人が頭を貸してから下のスイッチへ戻る）。ホストの読み込み直しでも開いたまま（`applySnapshot` で `latched` を戻す） |
| 番号のスイッチ（ステージ8・10） | 1番と、いちばん大きい番号の人（`seat: 'last'`）だけがおさえられる。箱ではおさえられない。2つとも同時で、とびらがずっと開く。片方は2マスの足場の上 |
| ひも（ステージ4・9） | となりの番号の人から 3.5マスより遠くへは行けない。ぶら下がったら、ジャンプで上がれる。4人までは1本につながる。5人からは、4人までの組に分ける（5→3・2、8→4・4、10→4・3・3。`ropeGroups`）。10人を1本にすると約31マスになり、横22マスの画面に収まらないため。引かれて動くときも、かべ・床に止まる（1回に動かすのは半マスまで＝`MOVE_STEP`。2026-11-19 フィードバック「ロープのコースで道にめりこんで抜け出せない」。前は穴に落ちた人に1こまで2マス以上引かれると、行き先の列だけを見て、かべの内側で止めていた）。かべ・床の中に入ってしまった人は、つぎのこまで近くの空いている所へ出る（`unstick`。上を先に、なければ区間のはじめ） |
| 画面 | 全員の真ん中を映す。映っている所（横22マス）から外へは行けない（ひとりだけ先へ行かない） |
| 落ちたとき | 落ちた所のすぐ手前の区間のはじめに戻る。残機・落ちた回数はない（だれがミスしたかを残さない） |
| ステージ | 13こ: 1 のりあいの練習／2 重い箱と動く床／3 シーソーとボール／4 ひもでつながる／5 ぜんぶ／6 高い台／7 ばねでとぶ／8 手分けの道／9 ひもと高い台（ひもあり）／10 さいごの道／11 ひもでつながる長い道（ひもあり）／12 いちばん長い道／13 しかけブロック。11・12 は「むずかしい道」で、これまでのステージで使った区間だけを長くつなぐ（ひものステージは、ひものステージで使った区間だけ。`engine.test.cjs` で確かめる）。区間（段・穴・台・番号のかべ・箱・リフト・動く床・シーソー・かご・人の塔・箱の足場・手分け・番号のスイッチ・ばね・ゴール）を左からつないで作る（`engine.js` の `SEG` と `STAGES`。`SEG.名前(b, 引数, 遊ぶ人数)`）。どの区間も、人数の数字は遊ぶ人数で頭打ち。はじめの区間は、人数が多いと全員が並べるように広くなる（`start` に人数を渡す） |

## タイムアタック（2026-11-18）

- 待合室でホストが「タイムアタック」をオンにすると、ステージの上に「タイム 1:05」を出し、クリアの札に「クリアまでのタイム 1:05.3」を出す。**はじめはオフ**（いつもの遊び方は時間を気にせず進めるため）。1台のパソコンで遊ぶときも、人数・ステージの下でえらべる
- はかるのは**みんなでクリアするまでの時間だけ**。人ごとの時間・順位・だれが速かったかは出さない・残さない
- 同じステージの「いちばん速いタイム」を、ルームの中だけで覚える（`best/{ステージ}`。ルームを閉じると消える）。速くなったら「このステージで、いちばん速いタイム！（前は …）」、遅かったら「このステージのいちばん速いタイム …」。1台のパソコンのときは、画面を開いている間だけ（保存しない）
- 時計: はじめた時刻を `game/startedAt`（サーバーの時刻）に書き、各端末が `RoomkRTDB.now()` との差で出す。クリアしたら、ホストが1回だけ `game/clearMs` と `best/{ステージ}` を `update` で書く（ステージを作りなおすと `game` ごと新しくなる）。ホストが切れている間も時計は進む（止めない）

## 同期の作り（遅れに強くする）

- **自分のキャラは、自分の端末で動かす**（`stepPlayer`）。位置を `live/{対決の番号}/p/{番号}` に、1つの文字列（`"x,y,向き,乗っているもの,押している向き,とびらに入った[,横の位置]"`）で書く。書くのは**変わったときだけ**で、間かくは人数で変える（4人まで 0.1秒＝1秒に10回・7人まで 0.15秒・10人まで 0.2秒。`app.js` の `sendMsFor`）。止まっている間は書かない。はじめの1回は止まっていても書く
- 間かくを人数で変えるのは、受けとる量が「人数×書く人数」でふえるため。ほかの人は、間かくの1.4倍前の時刻に合わせて描く（4人まで 0.14秒・10人で 0.28秒）
- **箱・動く床・とびら・スイッチ・カギ・ボールは、ホストの端末だけが動かす**（`stepObjects`）。`live/{対決の番号}/w` に、変わったときだけ・人の位置と同じ間かくで書く。ホストは「進行だけ」でも動かす
- ほかの人とホストの書いたものは、**届いた時刻から少し前（上の描く時刻）に合わせて、なめらかにつないで描く**。しばらく止まっていた人が動きだしたときは、止まっていた位置から動く
- **人・動く床・箱の上に乗っている人は、「なにの上の、横のどこか」を書く**（乗っているもの `s{番号}`・`p{番号}`・`b{番号}` と横の位置）。受けた側は、下の人・床・箱の描く位置に乗せて描く → 遅れても、乗っているものとずれない（床・箱は 2026-11-16 の10人対応で足した。描く時刻を遅らせても、リフトの上の人がリフトの下に見えないように）
- 前の版が書いた配列の位置も読める（`decodePlayer`）
- **動いている箱は、少し後ろ（2マスまで）にいて押している人も、押している人に数える**（ほかの端末の人は、遅れたぶん後ろに見えるため。止まっている箱を押しはじめるのは、となりにいるときだけ）
- **投げる**は `live/{対決の番号}/ev` に push し、ホストが投げて、受けとった印を消す。持ち運べるばねの「ひろう」も同じ所に `k: 'p'` を付けて push し、ホストがひろわせる（2026-11-18）。ひろう・かごに入る・カギでとびらが開くは、ホストが決める
- 自分の端末では、ほかの人の頭・箱・床・とびらは「描いている位置」で当たる（ホストと少しずれることがあるが、次の書き込みでそろう）
- ステージを作りなおすときは `live` を消し、新しい対決の番号で書く（遅れて届いた前のステージの位置を、いまのステージに当てない）

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（ステージの途中なら、見る番でステージの画面）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 └── 「1台のパソコンで遊ぶ」 → 人数・ステージ（screen-local） → ステージ（通信しない）
待合室（screen-waiting）: 遊ぶ人（参加した順に番号）・ホストは「ホストも遊ぶ」・ステージ（13こ）・「タイムアタック」・「はじめる」
  ↓「はじめる」（遊ぶ人が2〜10人）
ステージ（screen-game）: 名前・「しかけの説明」・canvas／下に、画面のボタン・キーの案内・ひとこと・遊ぶ人の一覧・ホストの「そのほかの操作」
  ↓ いる人がみんなゴールのとびらに入る
クリア（同じ画面）: ホストに「次のステージへ」「もう一回」。参加者には「ホストが次のステージをえらぶよ」
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「退出する」（ホストは「ルームを閉じる」）
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「はじめる」、クリア「次のステージへ」）
- ホストの「そのほかの操作」: 「このステージをやりなおす」「次のステージにする」「待合室へ」。クリアしていなければ確かめる
- **やりなおし・次のステージ・待合室へは、ホストだけ**（1人の押しまちがいで全員の進みが消えないように）
- **ホストも遊ぶ**（はじめはオン。メンターと子どもの2人で遊べるように）。外すと進行だけ（キャラを持たず、みんなの様子を見る。箱などは、進行だけでもホストの端末が動かす）
- **途中から入った人**は、そのステージは見る番（「この回は見る番。次のステージから入れるよ」）。ステージを作りなおすときに、いま参加している人で遊ぶ人を決めなおす。いなくなった人は外れる
- **通信が切れた人・退出した人**: 一覧に「（通信が切れた）」。キャラは出さず、クリアの数に入れない（いる人がみんな入ればクリア）。リフトなどの人数は、はじめた人数のまま。足りなくなったら、ホストが「このステージをやりなおす」で、いまの人数からはじめる。戻ると（同じタブの読み込み直し・同じ名前と匿名ID）同じ番号で、自分の書いた位置から続ける
- 遊ぶ人は10人まで（11人目は「このルームはいっぱいだよ」）
- 1台のパソコンで遊ぶ: キーは 1番 矢印・2番 W A S D・3番 I J K L・4番 T F G H（上でジャンプ・下で投げる）。画面のボタンは、選んだ人を動かす。ひとことは出さない
- **端末なしの参加者は作らない**（本人がその場で動かし続けるゲームのため。rtdb.md「端末のない参加者」の「作らないゲーム」）。1台のパソコンを囲んで遊ぶときは「1台のパソコンで遊ぶ」を使う
- **みんなにみせる画面は作らない**（答え・秘密がない。ホストが遊ぶ画面をそのまま共有できる）

## 画面で気をつけたこと

- 自分のキャラは、頭の上の三角の印と「あなたはN番」で見分ける。キャラの色は番号ごとにちがい（10色）、体に番号を書く（色だけに頼らない）
- 番号のかべ・ブロックは、その番号の人の色と番号。とびらとスイッチは、色と形（まる・さんかく・しかく・ひしがた・ほし）の両方でそろえる
- PC には「キーボード: 左右で動く・上かスペースでジャンプ・下で投げる」を出す。スマホ・タブレットは画面のボタン（長押しで歩き続ける）
- ステージの枠は、画面の高さに合わせて縮める（ボタンまで見えるように）。スマホは幅いっぱい
- 音は鳴らさない

## ひとこと（決まった言葉をえらんで送る）

- 言葉: 「待って」「行くよ」「乗って」「押して」「ありがとう」「いいね」（`app.js` の `SAYS`。2026-11-16 オーナー承認。言葉を足す・変えるときはオーナーが決める）
- 送れるのは遊んでいる人だけ（進行だけのホスト・見る番の人は送らない）。ひとり5秒に1回まで（早いときは「ひとことは、5秒に1回まで送れるよ」）。キャラの上に吹き出しで4秒出す
- `live/{対決の番号}/say/{番号}` に「言葉の番号.回数」を書く。読み込み直したときは、前から出ていたひとことを出しなおさない

## status 遷移

```
waiting ─はじめる→ play（game を作る。live は空から）
play ─次のステージへ／もう一回／次のステージにする（ホスト）→ play（新しい game。id が1増え、live を消す）
play ─待合室へ（ホスト）→ waiting（game と live を消す）
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
noriairoad_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── set:                { stage: 0〜12, hostPlays: true/false, timer: true/false }
  ├── best/{stage}:       タイムアタックの、このルームでいちばん速いタイム（ms）
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── game/               # 「はじめる」で作り、待合室にもどると消す
  │    └── id, seats: [名前, …], uids: [匿名ID, …], stage, n, timer?, startedAt?, clearMs?   # timer 以下はタイムアタックのときだけ
  └── live/{game.id}/     # そのステージの動く部分
       ├── p/{番号}: "x,y,向き,乗っているもの,押している向き,とびらに入った[,乗っているものからの横の位置]"   # 自分だけが書く（1つの文字列）
       ├── w: { b: 箱, p: 床と乗っている重さ, i: カギとボールとばね（位置・持ち主・かご・なくなった・まだ出ていない）, k: しかけブロック（開いたら o、開く前は乗っている人数）, g/s/h: とびら・スイッチ・かごの印, d: ゴールのカギ, c: クリア }   # ホストだけが書く
       ├── ev/{push}: { s, f, x, y }   # 投げる（ホストが受けとって消す）
       └── say/{番号}: "言葉の番号.回数"
```

- こわれた値は、その所だけ読み飛ばす（`decodePlayer` は null、`applySnapshot` はその欄を飛ばす）。`game` がこわれているときは待合室の画面になる（ホストは「はじめる」で作りなおせる）
- 座標は 0.01 マスにまるめて書く

## 書き込みの設計

| 操作 | 実行者 | 書き方 |
|---|---|---|
| 作成 | ホスト | ルームへ transaction（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加・在室を戻す | ゲスト | 先に読んだ値で、名前が空いている・ステージの途中の名前は同じ匿名IDの人だけ・遊ぶ人が4人未満（自分の番号がある人が戻るときは見ない）を確かめ、`players/{名前}` へ transaction（自分の在室だけ） |
| 在室を戻す | ホスト | `update`（`hostConnected`・`hostDisconnectedAt` だけ） |
| 設定・ホストも遊ぶ | ホスト | ルームへ transaction（`waiting` のときだけ） |
| はじめる | ホスト | ルームへ transaction（`waiting`・遊ぶ人が2〜10人 → `game` を作り `live` を消す） |
| 次・もう一回・次のステージにする | ホスト | `update`（`lastGameId`・`set/stage`・`game`・`live: null`） |
| 待合室へ | ホスト | `update`（`status: waiting`・`game`・`live` を消す） |
| 自分の位置 | 遊ぶ人 | `live/{id}/p/{番号}` へ `set`（変わったときだけ・人数に合わせた間かく） |
| ワールド | ホスト | `live/{id}/w` へ `set`（変わったときだけ・人数に合わせた間かく） |
| クリアのタイム | ホスト | `update`（`game/clearMs`・速ければ `best/{ステージ}`。1回だけ） |
| 投げる | 遊ぶ人（ホスト以外） | `live/{id}/ev` へ `push`。ホストが投げて `remove` |
| ひとこと | 遊ぶ人 | `live/{id}/say/{番号}` へ `set`（5秒に1回まで） |
| 退出 | ゲスト | `players/{名前}` へ transaction（自分の匿名IDの在室なら消す） |

- **あそんでいる間の書き込みに、ルーム全体の transaction を使わない**（位置が1秒に何十回も書かれるので、書きなおしがぶつかって通らない）
- ルームの購読は1つ（ルーム全体の `value`）。位置が変わるたびに届くので、画面の文字やボタンは、`live` をのぞいた所が変わったときだけ作りなおす（`handleRoom` の `metaSig`）
- ホストが切れている間は、参加者は動かさず・書かない（「ホストの戻りを待っています」で押せない）
- 自分の位置・ワールドの書き込みに失敗したら、5秒に1回まで「うまく送れなかったよ。通信を確かめてね」
- **通信量**（2026-11-16 にエミュレーターで測った。`tests/noriai-road/e2e1.cjs`。WebSocket の中身のバイト数で、暗号化などの上乗せは入っていない。本番で測ったわけではない）
  - 3人のうち2人が歩き続けている5秒の平均で、1台が受ける量は 1秒に約 4.2〜4.9KB（ホストは送る量が約 3.1KB/秒、歩いている参加者は約 1.2KB/秒）
  - 10分ずっと全員が動き続けると、1台あたり受ける量は 3MB 前後、4人のルームで 12MB 前後。Realtime Database の無料枠（ダウンロード月10GB）なら、そういうルームを月に数百回。止まっている間は書かないので、実際はもっと少ない
  - **10人対応のあと**（2026-11-16、`tests/noriai-road/e2e2.cjs`。全員が左右に歩き続ける約5.7秒の平均）: 10人で1台が受ける量 約4.8KB/秒・ルーム全体で約48KB/秒（10分で約29MB）。4人で約3.9KB/秒（10分で約9MB）。同じ測り方で前の版の4人は約4.9KB/秒（10分で約12MB）。位置を1つの文字列にして約2割へり、10人では書く間かくを0.2秒にして、1台が受ける量を前の4人と同じくらいにした（前の作りのまま10人なら、10分で80MB前後の見こみだった）
  - 無料枠（月10GB）なら、10人が10分ずっと動き続けるルームで月300回あまり。ほかのツールと分け合う
  - 同時接続は1人1本（無料枠はツール全体で同時に100本。10人のルームは10本）
- **ホストのタブは前に出しておく**: ブラウザは、うしろに回したタブの描く処理を止める。ホストのタブがうしろに回ると、箱・床などが止まる（ホストは画面を共有して遊ぶ想定）

## 接続・切断・再接続

そろってゴールと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- ホストが切れている間は、参加者の画面は共通のオーバーレイ「ホストの戻りを待っています」で押せない。`ORPHAN_TTL_MS = 2 * 60 * 1000`。切れた時刻が変わったら、期限のタイマーを仕掛けなおす（`orphanAt`）
- ホストが読み込み直したときは、`live/{id}/w` からワールドの続きを読む（箱・床・カギとボール・とびら）。遊ぶ人が読み込み直したときは、自分の書いた位置から続ける
- ステージの途中の名前は、ほかの人（別の匿名ID）は使えない

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。クリアしても自動削除しない（次のステージへ続けて遊ぶため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 待合室にもどると `game` と `live` を消す

## テスト

`tests/noriai-road/`（ルールのテストと、隔離した Firebase エミュレーター＋Playwright の E2E。本番には接続しない。手順は同じフォルダの README.md）

- **通しプレイ** `playthrough.cjs`（2026-11-19）: 13ステージ × 2〜10人を、人の操作だけでゴールまで進める。ルールのテストは人やものを置いて確かめるので、前の場面から動かすと進めない形を見落としうる（シーソーの最後の1人。PR #369）。ステージ・区間・人数の決まりを変えたら流す。新しい区間を足したら越え方も足す
- 通しプレイで分かったこと: ステージ5は、前はカギ（シーソーの先）のあとにボールとかごがあり、2人だと2人とも手がふさがって、カギをいったん投げないとボールを頭の上で受けとれなかった。2026-11-19 にかごをシーソーの前へ移した（カギを持つ前にボールを使い終わる）。通しプレイは、ボールを受けとる人の手があいていないと失敗にする（ほかのステージで同じ形を作らないため）。3マスの高い台は、2人目と3人目が同じ人の頭に乗り、3人目が2人目の頭へ乗りなおして跳ぶ（床から2人重なった頭へは届かない）。ひものステージは、穴や足場のはしまで寄ってから跳ぶ

## メンター向けのメモ（画面には出さない）

- はじめは「1. のりあいの練習」から。「友だちの頭に乗る」が、このゲームのいちばんの約束
- うまく動かせない子がいても、落ちてもすぐ戻れるので、急がせなくてよい。だれのせいで進めない、という話にならないよう、「次はどうする？」と全員に聞く
- 進めなくなったら「このステージをやりなおす」。人が抜けて、リフトなどの人数が足りなくなったときも、やりなおすと今の人数になる
- 人数が多いとき（6人以上）は、リフトと動く床は5人ずつに分かれて乗る。ひもは組に分かれる。だれから乗るかで待たされる子が出ないよう、「先に乗った組が、上で待っていよう」などと声をかける
- スマホ・タブレットでも遊べるが、パソコンのキーボードのほうが動かしやすい
