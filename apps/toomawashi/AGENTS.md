# とおまわしクイズ 仕様書

## 目的・使用シーン

秘密の「お題」を、そのことば＋「言っちゃダメことば」を**使わずに**説明して、みんなに当ててもらう協力ゲーム。
説明役は遠回しな言い方を発明し、聞き手は推理する。「冷蔵庫」を「冷たい」も「食べ物」も使わずに
伝えるもどかしさと、伝わった瞬間の「それ！」が面白さの核。

- **説明は Metalife の声が基本**。アプリが担うのは「秘密の配布・回答受付・判定・記録」の4つだけ
- 対象: 小学校中学年〜中学生。コトバであそぼ！（`data-scenes="kotoba"`）のメイン枠を張れる1本
- **2〜10人**（説明役1＋聞き手1以上）。支援者が説明役を務めれば2人で成立する
- 1お題2〜3分・1ゲーム15〜25分
- 声が出せずチャットだけで参加する子も、答えの候補①②③と自由回答欄で完全に遊べる
- 仕様の上位文書は [docs/requirements.md](../../docs/requirements.md) 第9.4章・第17.3章・第21〜23章

> 「禁止語つき説明」という一般的なゲームメカニクスのみを参照している。実在ボードゲームの名称・
> カード構成・固有用語・説明文は使わない（AGENTS.md「アプリ名のつけかた」準拠）。
> 「Web版」「オンライン版」等の表現も使わない。

### 独自性（市販の禁止語ゲームとの差別化）

1. **観点チップ**による「説明の骨組みの可視化」。無言でもチップを押すだけで手がかりが出せる
2. **答えの候補を全員に出す**協力設計（早押し個人戦にしない）
3. NG判定を人間（ホスト）の裁量に置き、違反をペナルティでなく笑いに変える運用

## 画面構成・フロー

```
TOP（screen-top / パネル1枚）
 ├── 「ルームを作る」→ screen-create
 │      ニックネーム → パック選択（丸数字・レベルバッジはこの画面のみ）
 │      → 「答えの候補を見せる」トグル（既定ON）→ 作成
 └── 「ルームに入る」→ screen-join（ニックネーム＋6桁コード）
                  ↓
        screen-waiting（コード大表示・タップでコピー・「コードをコピー」ボタン）
                  ↓（ホストが「始める」/ 2人以上）
        screen-round（status: explain）
          説明役: お題大表示＋言っちゃダメことば＋観点チップ＋お題変更＋パス
          聞き手: 答えの候補①②③＋自由回答欄＋自分の回答表示
          ホスト: 進行用のぞき見＋操作帯
                  ↓（ホストが「正解発表」）
        screen-reveal（status: reveal・全員共通）
          お題・言っちゃダメことば・みんなの回答一覧
          ホスト: 「つたわった！」/「次へ」→ 次ラウンドへ
          1周終わり: 「もう1周」/「終わる」
                  ↓
        screen-final（status: finished）
          「みんなで ○個 つたわった！」＋全ラウンドふりかえり＋「TOPに戻る」

screen-pending … 想定外の status のときの安全な待機画面（default-deny）
```

### 画面ごとの要点

- **screen-top**: パネル1枚構成（タイトル・説明・注意3点・主ボタン1つ・副ボタン1つ・保存されない旨）
- **screen-waiting**: 主ボタンは「始める」1つだけ。ルームコードのコピーは
  **コード単体のみ**（`copyCode()`）で、コード表示部のタップと弱いボタン「コードをコピー」の
  2経路。URL＋コードの案内文をまとめてコピーするボタンは持たない
  （2026-08-10 オーナー指示「コードをコピーはコードだけでOK」）
- **screen-create**: レベルバッジ（`レベル1`〜`3`）を出すのは**この画面だけ**。子どもの画面には出さない
- **screen-round**: レイアウトの骨格は役割共通（上=ラウンド情報、中=主情報、下=自分の操作）。
  「言っちゃダメことば」は赤枠＋`block` アイコン＋ラベルで区別する（色だけに意味を持たせない）
- **screen-reveal**: 「できなかったこと」を並べない。×印・ブザー等の失敗演出は置かない。
  伝わらなかった場合の文言は「つたわらなくても大丈夫。また今度つたわるかも。」
- **screen-final**: 個人別の集計は出さない。数えるのはチームの「つたわった数 / お題数」だけ

### 「相談OK」

`screen-round` と `screen-reveal` の下部に常時小さく表示し、声・チャットでの相談を公式ルールにする。

## ゲームの進行

### ラウンドの流れ

1. `turnOrder` のローテーションで説明役が決まる。**初回はホスト**（`turnOrder` の先頭がホスト）
2. 説明役の画面にだけ「お題」と「言っちゃダメことば」が出る。ホストは進行用に小さく見える
3. 説明役が声で説明する。観点チップを押すと全員の画面に「いま『ばしょ』の話」が出る
4. 聞き手は候補①②③をタップするか、自由回答欄に書いて送る（**何度でも上書き可・無回答OK**）
5. ホストが「正解発表」→ 全員にお題・NG語・みんなの回答が見える
6. ホストが「つたわった！」（`clear`）か「次へ」（`nope`）→ history に記録して次ラウンドへ
7. 全員1巡したら、ホストが「もう1周」か「終わる」を選ぶ → `finished`

### 説明役の支援

| 機能 | 誰が | 内容 |
|---|---|---|
| 観点チップ | 説明役 | 固定5種「ばしょ」「かたち」「つかいかた」「いつ・どこで」「なかま」。押すと `round/aspect` に入り全員の画面に出る。もう一度押すと解除。`item.aspects` があればチップの**並び順**だけそれに合わせる（機能はどれも同じ） |
| お題を変える | 説明役 | **1ラウンド1回まで**（`round/changed`）。知らないもの・説明しにくいものを引いたときの救済。失敗扱いにしない文言にする |
| 説明役をパスする | 説明役 | 役ごと次の人へ。**お題も引き直す**（パスした本人は答えを見てしまっているため） |

### ホストの操作

| ボタン | 画面 | 動作 |
|---|---|---|
| 正解発表 | explain | `status: 'reveal'` |
| お題をスキップ | explain | `result:'skip'` で history に記録し、**reveal を経ずに**次ラウンドへ。`score` には数えない |
| 説明役を次の人に | explain | 説明役のパスと同じ処理（切断・不在時の救済） |
| ここまでにする | explain / reveal | `status: 'finished'` |
| つたわった！ / 次へ | reveal | `clear` / `nope` を記録して次ラウンドへ |
| もう1周 / 終わる | reveal（1周終わり） | `turnOrder` を組み直して継続 / `finished` |

- **ホストは進行役であり、回答には参加しない**（お題が常に見えているため）。
  ホストが説明役になることは可能。説明役でないときは `進行用: お題は「〇〇」` と
  言っちゃダメことばが小さく出る（NG語を耳で判定するために必要）
- 未提出者を子ども画面で名指ししない。ホストはいつでも先に進められる

### 人数・参加制御

- 開始は **2人以上**（`MIN_PLAYERS`）。上限 **10人**（`MAX_PLAYERS`）
- ニックネームは最大8文字・同ルーム内重複NG・空NG・`. # $ [ ] /` を含む名前は拒否（RTDB のパスキーに使うため）
- **途中参加**: `waiting` / `explain` / `reveal` / `finished` のどの状態でも入室できる。
  `explain` / `reveal` で入った人は `turnOrder` **末尾に追加**され、その周の最後（周回が終わっていれば次周）に説明役が回る。
  入った瞬間から聞き手として回答できる。`finished` で入った人はふりかえり画面を見るだけ（`turnOrder` には入らない）
- **途中退出**: 聞き手の切断は `onDisconnect().remove()` のみで進行に影響しない。
  説明役が切断したらホスト画面に案内が出るので、「説明役を次の人に」か「お題をスキップ」で進める（自動化しない）

## status 遷移

```
waiting → explain → reveal → explain（次の説明役へ）
                       ↓
                    reveal に留まる（1周終わり: round.result が入った状態）
                       ↓
                    explain（もう1周） / finished（終わる）

explain →（お題スキップ）→ explain     ※ reveal を経由しない
explain / reveal →（ここまでにする）→ finished
```

| status | 説明 |
|---|---|
| `waiting` | ロビー。参加待ち |
| `explain` | 説明中。説明役だけにお題が見える。聞き手はいつでも回答できる |
| `reveal` | 正解発表。全員にお題・NG語・回答一覧が見える |
| `finished` | 終了。ふりかえり一覧とチームスコア |

**`reveal` の2つのサブ状態**（`status` を増やさずに `round/result` で表現している）:

| 条件 | 意味 | ホストのボタン |
|---|---|---|
| `round.result == null` | 発表中・判定前 | 「つたわった！」「次へ」「ここまでにする」 |
| `round.result != null` | **1周終わり**（判定済みだが次の説明役がいない） | 「もう1周」「終わる」 |

`status` を進めるのはホストだけ（UI制御＋transaction 内の条件チェック）。

## Firebase データ構造（Realtime Database）

パス: `toomawashi_rooms/{roomCode}/`（共通命名規則。**セキュリティルールの変更は不要**）

```
toomawashi_rooms/{roomCode}/
  ├── host:               string           # ホストのニックネーム
  ├── hostConnected:      boolean
  ├── hostDisconnectedAt: number | null    # 切断時刻（ms）
  ├── status:             'waiting' | 'explain' | 'reveal' | 'finished'
  ├── packId:             string           # packs.js の pack.id
  ├── showChoices:        boolean          # 答えの候補を出すか（ルーム作成時に決める・既定 true）
  ├── usedItems:          number[]         # 使用済みお題の index（重複出題しない）
  ├── turnOrder:          string[]         # 説明役の順番。先頭はホスト。途中参加は末尾追加
  ├── turnIndex:          number           # turnOrder 上の現在位置（0始まり）
  ├── score/              { clear: number, total: number }   # チーム記録。個人は数えない
  ├── players/
  │    └── {nickname}/    { isHost: boolean, joinedAt: number }
  ├── round/
  │    ├── number:        number           # 通し番号（1始まり）。history のキーになる
  │    ├── explainer:     string           # 説明役ニックネーム
  │    ├── itemIndex:     number           # packs.js 内の index（answer / ng / choices は引かない）
  │    ├── aspect:        string | null    # 現在の観点チップ（"ばしょ" 等）
  │    ├── choiceOrder:   number[]         # ★ 答えの候補の表示順（下記「追加フィールド」）
  │    ├── changed:       boolean          # ★ このラウンドで「お題を変える」を使ったか
  │    ├── answers/
  │    │    └── {nickname}/ { text: string, at: number }
  │    └── result:        null | 'clear' | 'nope' | 'skip'
  └── history/
       └── {round.number}/ { itemIndex, explainer, answers, result }
```

### 追加フィールド（要件定義書 17.3 からの差分）

| フィールド | なぜ必要か |
|---|---|
| `round/choiceOrder` | 答えの候補を**全員同じ順番**でシャッフルするため。丸数字①②③で「2ばん！」と口頭・チャットで答える運用が成立しなくなるので、クライアントごとのランダム並べ替えにはできない。ホストがラウンド開始時に生成して RTDB に置く |
| `round/changed` | 「お題を変える」を1ラウンド1回に制限するため |
| `players/{nick}/joinedAt` | `turnOrder` を参加順に組むため（`RoomkRTDB.now()` の数値。transaction 内で `ServerValue.TIMESTAMP` を使わない） |

### 秘密情報の置き場所（重要）

**`answer` / `ng` / `choices` は packs.js（静的データ）にしかない。ルームには `itemIndex` だけを置く。**
答えのテキストを RTDB に二重保持しない。DevTools での覗き見は共通の性善説方針どおり許容する
（AGENTS.md「セキュリティ方針（性善説）」。スタッフ監視下・小集団での利用が前提）。

### 秘密情報の出し分け原則（変更禁止）

`explain` 中、**お題と言っちゃダメことばを DOM に書いてよいのは「説明役本人」と「ホスト」だけ**。
かぶらずヒントの「回答者セーフ原則」と同じ厳密さで守る。

- `handleExplain()` は毎スナップショットで **必ず両方向に代入する**。
  該当者には値を入れ、非該当者には `''` を入れて**消す**（`hidden` にするだけでは不十分。
  説明役がパスして聞き手に変わった瞬間に、前のラウンドのお題が DOM に残るため）
- 非該当者の画面には `title` / `aria-label` / HTML コメントにもお題を書かない
- 対象要素: `#explain-topic` / `#explain-ng` / `#hostpeek-topic` / `#hostpeek-ng`
- **答えの候補（`choices`）は answer を含むが、これは全員に出す公開情報**（このゲームの普通の遊び方。
  「Lv.1 の子向けの救済」として一部の子にだけ出す設計にはしない）

### 回答の可視範囲

| フェーズ | 説明役 | ホスト | ほかの聞き手 |
|---|---|---|---|
| `explain` | 全文（ニックネーム付き） | 全文（ニックネーム付き） | **「n人が答えた」の人数だけ** |
| `reveal` | 全文 | 全文 | **全文** |

`explain` 中に説明役へ全文を見せるのは、「ちがうちがう、もっと大きい」と説明を調整できるようにするため。
ほかの聞き手に人数しか出さないのは、**珍回答が並ぶ発表の楽しみを reveal まで取っておくため**。

### transaction 設計

ルーム作成・参加・開始・ラウンド送り・判定・スキップ・説明役交代・お題変更・復帰の書き戻しは、
すべて**ルームルートへの `transaction()`**。回答送信だけは自分のパス `round/answers/{自分}` への `set()`（競合なし）。

- **乱数は transaction コールバックの外で作る**（コールバックは複数回呼ばれうるため純粋に保つ）。
  お題抽選用の `Math.random()` と候補順の `shuffledIndices()` は呼び出し前に1回だけ生成し、
  コールバックには値として渡す
- **ローカルキャッシュ null 対策**: リスナー未接続の状態から実行する transaction（参加・復帰・期限切れ削除）は、
  コールバックが `null` で始まると abort だけしてサーバー照会せずに終わるため、事前に `get()` した
  スナップショットを `const r = room || preRoom` で代用してサーバー照会を強制する（esadori / oshitsuke-zukan の確立パターン）
- **世代ガード**: ホストの「正解発表」「判定」「説明役交代」は、押した時点の `round.number` /
  `turnIndex` を捕捉して transaction 内で再検証する。連打・遅延クリックで2ラウンド飛ぶのを防ぐ
- 二重押し防御: 判定は `status === 'reveal' && round.result == null`、発表は `status === 'explain'`、
  もう1周は `status === 'reveal' && round.result != null` を条件にしている

## 切断・再接続

| 役割 | 挙動 |
|---|---|
| ホスト切断 | `roomRef.onDisconnect().update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })`。ゲストにはオーバーレイ「ホストの戻りを待っています」 |
| ゲスト切断 | `players/{nick}` への `onDisconnect().remove()` |

- `ORPHAN_TTL_MS = 2 * 60 * 1000`（共通規約どおり2分）。TTL 超過でゲストが `remove()` を試みる
- 時刻判定は `RoomkRTDB.now()` / `isRoomExpired()`（サーバー時刻補正）。`status` を持たないルームは
  ゴースト（削除後に onDisconnect が発火して部分再生成されたもの）として TTL を待たず期限切れ扱いにする
- ホスト再接続時は `hostConnected: true` / `hostDisconnectedAt: null` に戻し、onDisconnect を張り直す
- **リロード復帰**: sessionStorage キー `toomawashi_session`（`{ nickname, roomCode, role }`）。
  ゲストはリロードで `onDisconnect().remove()` が発火して `players` から消えるため、
  `tryReconnect()` は**自分を players に戻す**（`turnOrder` に既にいれば追加しない）。
  復帰後の画面は `round.explainer` から導出されるので、自分が説明役なら説明役画面に戻る
- すべての退出・削除経路で、`remove()` の**前に** `cancelRoomOnDisconnect()` を await する

## 共通規約からの意図的な逸脱

| 逸脱 | 理由 |
|---|---|
| **`packs.js` を外部ファイルに分離**（RTDB アプリの「単一ファイル」規約からの逸脱） | お題は件数が伸びる前提のデータで、コンテンツ追加のたびに本体を触るのを避けたい。既存実績（quiz `questions.js`・ことば探偵 `words.js`）と同じ形。docs/requirements.md 11.1 で明示的に決めた方針 |
| **`finished` 画面滞在中はルームを自動削除しない** | ふりかえり一覧を読む時間を保証するため（共通規約の「終了30秒後に自動削除」からの逸脱。先行事例: jinro / word-wolf / tatoe-narabe / esadori）。削除は ①「TOPに戻る」（ホストは `remove()`）②ホスト切断＋TTL 2分 ③次回アクセス時の期限切れ判定 の3経路 |
| **`finished` 中はゲストにホスト切断オーバーレイ・TTL 削除を出さない** | 上と同じ理由。ホストが先に抜けてもふりかえりを読み終えられるようにする |
| **ホストはプレイヤーだが回答しない** | お題が常に見えているため。ホストが説明役になることは可能（初回はホスト既定） |
| **`shuffledIndices()` をローカルに実装** | utils.js の `shuffle(arr)` とは用途が違う「0..n-1 の並べ替え」専用。通常スクリプトのままにしたい（module import は defer になり読み込み順の race を持ち込むため） |

## パックの追加方法

`packs.js` の `window.ToomawashiPacks` 配列に1エントリ追加する。**追加のみで本体の変更は不要。**

```js
{
  id: 'tabemono-1',        // 英数字とハイフン。stats の pack-{id} に使う。既存 id と重複させない
  title: '食べ物・生き物',    // 子どもに見える名前（レベルは見せない）
  theme: 'setsumei',       // goi | joshi | bun | setsumei | kimochi（支援者向け分類）
  level: 1,                // 1〜3。バッジはホストのルーム作成画面にだけ出る
  items: [
    {
      answer: '冷蔵庫',
      ng: ['冷蔵庫', '冷たい', '食べ物'],           // 3〜5語。answer 自身を必ず含める
      choices: ['冷蔵庫', '戸棚', 'クローゼット'],   // 3つ。answer を必ず含める
      aspects: ['ばしょ', 'つかいかた', 'かたち'],   // 任意。観点チップの並び順だけに影響する
    },
    // ... 1パック 15お題以上が目安
  ],
}
```

### 執筆ガイドライン

- **`ng` の選定がゲームの生命線**。answer の言い換えと最頻連想語を封じる。緩すぎると一言で終わり、
  厳しすぎると手がかりが消える。3〜5語に収める
- `choices` は answer ＋ **同カテゴリの2つ**（明らかに違うものを混ぜると考える余地がなくなる）。
  表示順はアプリ側でシャッフルするので、書く順番は気にしなくてよい
- 共通の[コンテンツガイドライン](../../AGENTS.md#コンテンツガイドライン)に従う。
  学校・勉強・宿題・テスト・成績、出席・登校、恋愛、暴力・ホラー・死を連想させる素材は使わない
- お題は小学校中学年〜中学生が知っている具体名詞を中心に。**表記は日常で見慣れた通常表記**
  （冷蔵庫・洗濯機・自動販売機、生き物はカタカナ）。1件の中で `answer` と `choices` の
  表記の粒度をそろえる。下の「文言・UX ガイド」を参照
- 追加後は `bash scripts/lint.sh` と `node scripts/content-audit.mjs` を実行し、
  `apps/updates.json` に1行追記する

## 文言・UX ガイド

- **通常表記（漢字まじり・分かち書きなし）**。読みはファシリテーターが読みながら補完する
  （2026-08-10 オーナー実機フィードバックによる変更。「漢字がなさすぎで文章を読みづらい」。
  root [AGENTS.md](../../AGENTS.md) 表記トーンの「ことば系はひらがな中心」からの**意図的逸脱**）
  - 漢字は小中学生が読める常用範囲。やわらかいトーン（〜だよ・〜してね）は維持する
  - `packs.js` の `answer` / `ng` / `choices` も日常で見慣れた表記（冷蔵庫・洗濯機・自動販売機、
    生き物はカタカナ）。**語そのもの・お題構成・ng の効きは変えない。表記だけ**
  - 1件の中で `answer` と `choices` の表記の粒度をそろえる（3択のうち1つだけ漢字／ひらがなで浮かせない）
  - **観点チップの5語（ばしょ / かたち / つかいかた / いつ・どこで / なかま）は表記変更の対象外**。
    `scripts/content-audit.mjs` の `TW_ASPECTS` と `packs.js` の `aspects` と本体の `ASPECTS` が
    突き合う統制語彙のため、3か所同時に変えないと壊れる
  - **「つたわった」だけは ひらがな のまま**（このゲームの signature 語。判定ボタン・結果画面・
    ふりかえりで一貫させる）
- 「問題」「不正解」を子ども向け画面で使わない。「お題」「つたわった」「また今度」を使う
  （ホストの進行ボタン「正解発表」は、発表フェーズの合図として例外的に使う）
- 出題文体（「次の問いに答えよ」「説明問題」等）を使わない
- ボタンは素直な動詞（作る・入る・始める・送る・変える・パスする）
- 絵文字は使わない。アイコンは Material Symbols Rounded のみ
- タイマー・効果音なし。NG語の自動判定なし（判定は人間）
- エラー文言は原因を子どものせいにせず、次にやることを1つだけ示す
  （例: 「ルームが見つからないよ。コードを確かめてね」）

## アクセシビリティ

- タップターゲット 44px 以上（チップ・候補ボタン・ルームコード・弱いボタンすべて）
- お題は 44px（600px 以下で 34px）。要件の「32px 以上」を満たす
- 色だけに意味を持たせない: 言っちゃダメことば=赤枠＋`block` アイコン＋ラベル、
  選択中のチップ・候補=枠色＋`check` アイコン、結果=アイコン＋テキスト
- `prefers-reduced-motion: reduce` でドットアニメを止め、スピナーを減速し、トランジションを切る
- 観点チップの共有表示と回答人数は `role="status"` / `aria-live="polite"`
- `maximum-scale=1` は RTDB アプリ共通の意図的例外（画面共有中の進行安定を優先）

## メンター向けの心得

**（このセクションの内容を子ども向け画面や `howto.js` に書かないこと）**

- **NG語を言ってしまっても裁かない。** 「いまのはナシで」と軽く流して続ける。
  アプリに自動判定を入れていないのは、違反をペナルティではなく笑いに変えるため。
  厳密にジャッジし始めると、説明役になるのが怖くなる子が出る
- **説明役は立候補と指名を、その日の子どもの様子で使い分ける。**
  「やる？」と聞くと断りづらい子がいるので、初回は「今日はホストからやるね」で始められるようにしてある
  （`turnOrder` の先頭はホスト）。難しそうなら「説明役を次の人に」でそっと回してよい
- **説明が苦手な子の番では、レベルの低いお題に差し替える。**
  「お題をスキップ」を使えば画面上は「次のお題」にしか見えない。子どもに理由を見せない調整ができる
- **「あと1語で伝わりそう」の焦れ感が面白さの本体。** 早く正解を出させようとせず、
  「いまの説明、もう1回言ってみて？」と間を作ると盛り上がる
- 珍回答は reveal で全員に並ぶ。**そこを笑って面白がる**のが設計意図で、×をつける画面はどこにもない。
  「そのことば使わずによく伝えたね」の空気を作る
- 画面共有するときはホスト画面にお題が映る。**画面共有をするなら子どもたちには各自の端末で入ってもらう**
  （観戦ビューは MVP では未実装。要件定義書では Should 扱い）
- **記録は参考情報であり、テスト結果ではない。** 「つたわった数」はチームの記録で、
  個人の正答数は数えていない。ゲーム内の行動から子どもの能力を断定しない
- 結果画面には回答がニックネーム付きで並ぶ。支援の記録として外部共有する場合はニックネームに配慮する
- 途中参加はいつでも受け入れられる。遅れて来た子はコードを入れればその場で聞き手になれる
- 1ゲーム15〜25分。時間が押したら「ここまでにする」でいつでも結果画面へ進める
