# キャパグラフ 仕様書

## 目的・使用シーン

登校を頑張りすぎているなど「予定を詰めすぎている」子どもが、自分のがんばり量(負荷量)を**数値とグラフで客観把握**するためのメンター＋本人 共同ツール。1週間の項目別の負荷を入力し、自分でドラッグして引いた「キャパライン」と見比べることで、容量を超えていそうな日にメンターと一緒に気づく。

| ロール | 説明 |
|--------|------|
| 操作者 | メンター（または本人）|
| 閲覧者 | 本人（Zoom/Meet 画面共有で共同編集）|

**利用シーン**
- 面談での「今週どれくらい頑張った？」の振り返り
- 登校頑張りすぎの子の「キャパ超え」の言語化
- 予定を詰めすぎている自覚を、本人のラインで見える化する

## 設計思想（重要：他の内省ツールと哲学が異なる）

このツールは roomk-tools の他の内省ツール（`nurie-week`, `mienai-ganbari`）とは**意図的に逆方向**の設計をしている。

| ツール | 哲学 |
|--------|------|
| nurie-week | 「眺めて気づく」。**数値化しない**。評価・比較・最適化に寄せない |
| mienai-ganbari | 個数表示なし。証拠化しない |
| **kyapa-graph（本ツール）** | **数値化して客観把握する**。ただし「達成スコア」ではなく「負荷量」として表現する |

**意図的に哲学を変えた理由**: 「眺めて気づく」では本人がピンとこない子もいる。「数字で見ないと自分でブレーキを掛けられない」という登校頑張りすぎの子のニーズに応えるため、評価軸を「達成」ではなく「**負荷の累積**」に置き換える形で数値化を採用した。

### 設計原則

- **数値は『負荷量』であり『達成スコア』ではない**: グラフが伸びる=「危ない、休もう」のサイン
- **キャパラインは本人が引く**: メンターや大人が「これが限界」と決めない
- **判定の言葉は使わない**: 「キャパオーバー」「やりすぎ」などの警告テキストを出さず、線とグラフの位置関係だけで気づきを促す
- **項目はフラット**: 「学校・授業」と「自分の時間」を上下や良し悪しで色分けしない

## 入れない機能（意図的に未実装）

| 入れない機能 | 入れない理由 |
|------------|------------|
| 連続記録日数・累計日数バッジ | 入力すること自体を頑張る動機になり、過剰適応の入れ子になる |
| 「先週より◯%多い」のような比較表示 | 比較が「改善／悪化」の文脈を立ち上げる |
| 「キャパ超え」警告文・赤色警告 | 言葉や色で本人を断罪しない。線とグラフの位置だけで示す |
| 達成バッジ・スコアランキング | 「もっと頑張ろう」の動機を作らない |
| PDF・画像エクスポート | 証拠化につながる。保護者・先生への提出材料にしない |
| カレンダー連携・予定取り込み | 「あるべき姿」の押し付けになる |
| 入力リマインド通知 | 入力ノルマ化を避ける |

## 既存ガイドラインからの例外

roomk-tools プロジェクト全体の [AGENTS.md](../../AGENTS.md) のコンテンツガイドラインでは「学校・勉強・授業を連想させる内容は使わない」と定めているが、本ツールは**意図的にこれを例外として扱う**。

- **理由**: 「学校・授業」を抽象化した表現では、登校を頑張りすぎている子が「これは自分のことだ」と認識しにくく、自分でブレーキを掛ける目的が機能しなくなる
- **適用範囲**: 本ツール内の初期タグおよびUI文言に限る。他のアプリへは波及させない
- **対象ユーザー**: 不登校の子どもには別ツール（`nurie-week`, `mienai-ganbari`）を使う。本ツールは「登校はしているが頑張りすぎている子」専用

## 技術スタック

- 単一HTMLファイル（CSS・JS インライン）
- オフライン動作（Firebase 不要）
- localStorage で状態保存
- pointer events でキャパラインのドラッグを mouse/touch/pen 共通処理

## 画面構成・フロー

```
[1画面で完結]
  ├─ ヘッダー（タイトル + サブ）
  ├─ グラフエリア（スタック棒 + キャパライン）
  │     - 横軸: 月〜日(7日)
  │     - 縦軸: 負荷の累積（0〜上限）
  │     - 各タグの色でスタック表示
  │     - キャパラインは pointer ドラッグで上下に動く
  │     - 「↑↓ ドラッグできる」サインを線の右端に出す
  ├─ 週送り（← 先週 ・ 今週 ・ 次の週 →）
  │     - 「先週との差」のような比較表示は出さない
  ├─ 入力エリア
  │     - 日付タブ（月〜日）
  │     - 選んだ日のタグごとに 0〜5 のボタン
  ├─ タグ編集（折りたたみ）
  │     - 初期タグの編集・削除
  │     - 自由追加
  └─ リセット（その週の入力だけ消す）
```

## データ構造

```js
// localStorage key: 'kyapa-graph:v1'
{
  // 各日のスコア: { 'YYYY-MM-DD': { tagId: score } }
  // score: 0-5 の整数
  days: {
    '2026-05-25': { 'school': 4, 'class': 5, 'homework': 3 }
  },
  // タグ定義（初期8項目 + ユーザー追加）
  tags: [
    { id: 'school',   label: '学校',         color: '#5B8FB9', removable: false },
    { id: 'class',    label: '授業',         color: '#9B89B3', removable: false },
    { id: 'homework', label: '宿題',         color: '#E07A5F', removable: false },
    { id: 'lesson',   label: '習い事',       color: '#81B29A', removable: false },
    { id: 'test',     label: 'テスト',       color: '#C9676A', removable: false },
    { id: 'friends',  label: '人といる時間', color: '#F2CC8F', removable: false },
    { id: 'home',     label: '家のお手伝い', color: '#B5C28C', removable: false },
    { id: 'mytime',   label: '自分の時間',   color: '#D4A5A5', removable: false }
  ],
  // キャパライン（負荷の累積で何点を「これ以上はしんどい」と本人が決めたか）
  capacity: 15
}
```

- 読み込み時は score を 0-5 に clamp する
- 週送りは「今日を含む週(月始まり)」を基準に ±週単位でオフセット

## CSS 命名規則

接頭辞 `kg-` + BEM。例: `.kg-chart__bar`, `.kg-input__btn--active`, `.kg-tag-edit__row`。

## 共通モジュールの使用箇所

| モジュール | 使用箇所 |
|-----------|----------|
| design-system.css | カラートークン、ボタン (.btn / .btn-ghost / .btn-sm) |
| Material Symbols Rounded | ヘッダーアイコン、週送り矢印、タグ編集の追加・削除 |

utils.js / firebase-config.js は不使用（オフライン単一ファイルのため）。

## 特有のルール・制約

- キャパラインのドラッグは pointer events で統合（mouse / touch / pen 区別なし）
- 保存は 150ms デバウンス
- 0-5 の入力ボタンは丸数字ではなく数字そのまま（量を直感的に表すため）
- タグの色は **学校系・学校外で色相を分けない**（フラットな配色）
- スコア入力時に「お疲れさま」「すごい」などの励まし文言を出さない（達成感を演出しない）
- 週送りで前週・前々週へ遡れるが、「先週は ◯ 点だった」のような比較サマリは表示しない
