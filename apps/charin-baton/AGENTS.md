# ちゃりんバトン 仕様書

## 目的・使用シーン

ならんだ小銭がぜんぶでいくらかを答えて、正解したら次の人にバトンを渡す対決（2〜6人の勝ち残り）。自分の番の間だけ自分の時計が減り、0になった人から「ここまで」で、最後まで残った人の勝ち。2人なら1対1の対決（時計が0になった人の負け）。

- **core value**: 小銭を数えることが、そのまま遊びになる。番が行ったり来たりするテンポで盛り上がり、終わったあと「50円玉2枚と100円玉1枚は同じだね」とお金の話につなげやすい
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの1対1でも遊べる）。種類は「クイズ・パズル」（`data-genre="puzzle"`）
- ひとりでも遊べる（2026-11-05。フィードバックボードの要望「ひとりだけでどんどん数えるモード（ホストは見守るだけ）」に、オーナーが「対戦する人が1人でも始められる」「時計が0でおしまい・点数があれば面白い」「正解の数はその回だけ出す」と決めた）。ホストが「ホストも対戦する」を外し、参加する人が1人ならその子がひとりで数え、ホストとみんなにみせる画面は見るだけ。1台の画面でも対戦する人を1人にすると遊べる
- 対戦は、ルームに参加している人みんな（2〜6人。2026-11-04 オーナー「複数人で遊べるといい」→ 勝ち残りに決定。同日「対戦する人は参加者全員でOK（観戦者はみんなにみせる画面で見る）」「持ち時間と小銭の種類は全員一緒でいい」）。端末なしの参加者（4人まで）も入る。見るだけの人はみんなにみせる画面で見る。1回3〜10分
- 着想: テレビ番組『THE FLOOR』（日本テレビ系）のジャンル「小銭」。番組名・ジャンル名は画面・名前に使わず、早見表（`apps/guide/` の「近い遊び」）でだけ紹介する。`updates.json` の紹介文には着想元を書かない（2026-11-04 オーナー）

> 経緯: 2026-11-04 にスタッフからの DM（子どもと番組を見ていて面白かった。お金の話もできて生活にも役立つ）を受けて、オーナーが仕様検討を依頼。設計書 [docs/coin-game-design-v1.md](../../docs/coin-game-design-v1.md)。同日 `drafts/coin-baton/` で試作（1台の画面の対決・いっしょに数える・ウィンドウ間のルームのモック）→ オーナーの実機確認で数字キー入力・PC で画面の数字ボタンをかくす・UI の見直しを入れた → 同日オーナーが「本体に移って」と承認し、名前を「ちゃりんバトン」に決めた。
> 出題の中身は、DM の説明と、オーナーが放送を見て確かめたこと（**小銭だけ・2枚から始まり4〜5枚くらいまで増える**）を正本にした（公開情報には出題の中身が見つからなかった）。

## セッション条件（ツール一覧のカードと同じ。2026-11-08）

スタッフがツールを選ぶときの条件。値はツール一覧（`apps/index.html`）のカードの札・`data-scenes`・`data-speech`・`data-self` と同じにする（話す量・自分の話は P-33・P-34 で承認。決めた根拠は [sakusen-conditions-draft-2026-11-08.md](../../docs/reports/sakusen-conditions-draft-2026-11-08.md)）。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 1〜6人 |
| 目安時間 | 3〜10分 |
| 利用シーン | ボドゲクラブ・ひろば・作戦会議 |
| 話す量 | ひとことで・話さなくてよい |
| 自分の話 | 外の題材で遊べる |

## ルール

| 項目 | 内容 | はじめの値 |
|---|---|---|
| 持ち時間 | 30・45・60・90・120・180秒から、ホストが選ぶ（みんな同じ。120・180秒は 2026-11-05 にフィードバックボードの要望「90秒より長く」で足した） | 45秒（番組と同じ） |
| 小銭の種類 | 「ぜんぶ（6種類）」か「1・10・100円だけ」を、ホストが選ぶ（みんな同じ） | ぜんぶ |
| 小銭の枚数 | 2枚から。その人が2問正解するごとに1枚増える。上限は4・5・6・8枚から選ぶ | 5枚まで |
| ならべ方 | ばらばら（重ならない・少し回す）／そろえる（金額の大きい順） | ばらばら |
| 答える順 | 席の順（待合室・準備の画面の上から）。先に答える人は、くじか、いちばん上の人 | くじ |
| はじまる前 | 3・2・1。小銭はかくし、時計は止める | 3秒 |
| 答える | 番の人が金額を数字で入れて「こたえる」 | — |
| 正解 | 小銭を見せたまま、トレーの下に「正解！ ○○円」と内訳（500円玉 1枚・50円玉 1枚）を出す。その間はみんなの時計を止める。そのあと、まだ残っている次の人の番 | 1.5秒 |
| まちがい | 「ちがうみたい。もう一回数えてみよう」。何回でも答えなおせる。時計は止めない | — |
| パス | 小銭をかくして待つ（自分の時計は減る）。同じ人に次の小銭。パスでは枚数は増えない | 3秒 |
| ここまで | 番の人の時計が0になったら「ここまで」。そのとき出ていた小銭を見せたまま、「この小銭は ○○円」と「○○はここまで・内訳」を出す。その間はみんなの時計を止める。そのあと、残っている次の人の番。「ここまで」の人の札はうすくなり、番はとばす | 1.5秒 |
| 決着 | 残りが1人になったら、その人の勝ち（2人なら、時計が0になった人の負け）。2位・3位のような順位は出さない | — |
| ひとり | 対戦する人が1人なら、その人がひとりで数えつづける（番は回らない。正解すると1.5秒の帯のあと同じ人に次の小銭）。時計が0になったら「おしまい！ ○○は ○点」。勝ち負けはなく、**正解した数がその回の点数**（札にも、その回の間だけ出す。記録・前の回との比較はしない） | — |
| 結果 | 勝った人と、出た小銭の一覧（合計つき。押すと大きく出て内訳も見られる）。だれが解いたかは出さない | — |

- 問題はその場でくじで作る（問題集は持たない）。同じ硬貨は3枚まで・直前と同じ組み合わせは出さない
- 番組との違い: 正解のあとの1.5秒（答えの金額をみんなが目で確かめられるように）と、はじまる前の 3・2・1（「はじめる」を押した瞬間に時計が動かないように）は番組にない
- ルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/charin-baton/engine.test.cjs`

## 硬貨の絵

| 硬貨 | 色 | 穴 | 大きさ（実物の直径の比） |
|---|---|---|---|
| 1円 | 白っぽい銀 | なし | 20.0mm |
| 5円 | 金 | あり | 22.0mm |
| 10円 | 銅 | なし | 23.5mm |
| 50円 | 銀 | あり | 21.0mm |
| 100円 | 銀 | なし | 22.6mm |
| 500円 | 金（ふちだけ色を変える） | なし | 26.5mm |

- **本物の図柄（桜・稲穂・平等院など）は描かない**。色・穴・大きさ・金額の数字だけの、ひと目で絵とわかる硬貨にする（通貨及証券模造取締法。財務省 FAQ「貨幣と紛らわしい外観のもの」）
- 金額の数字を大きく書く（色だけに頼らない）。SVG で描く（画像ファイルを持たない）。お札は出さない

## 答え方

- 金額の欄は入力欄に見えるように、アクセント色の枠・点滅するカーソル・空のときの案内を出す。本物の入力欄にはしない（日本語入力の変換で数字がずれるのを避けるため。`docs/development/ui.md`「文字入力欄と日本語入力」）
- キーボードの数字キー・テンキー（全角の数字も）で入れ、Enter で答え、Backspace・Delete で1つ消す
- **PC（マウスのある端末）では画面の数字ボタンを出さない**（2026-11-04 オーナー「テンキーの表示がややこしい」）。「画面の数字ボタンを出す」で出せて、そのタブの間はおぼえる（`charinbaton_pad`）。スマホ・タブレットはいつも出す
- 画面が切りかわるとき、かくれる画面の入力欄からカーソルを外す（名前欄で Enter を押して始めると、数字キーが名前欄に入っていた。2026-11-04）
- 1台の画面では、子どもが声で言った金額をメンターが入れる。ルームの端末なしの参加者・通信が切れた席の人の番は、ホストの画面に「○○の番。代わりに入れてね」と入力欄が出る

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（対決中なら観戦で対決の画面）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 ├── 「1台の画面であそぶ」 → 名前・持ち時間・小銭の種類・枚数・ならべ方・先に答える人（screen-local） → 対決（通信しない）
 ├── 「いっしょに数える（時間なし）」 → screen-count（通信しない）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting）: 対戦する人（参加している人みんな・参加した順）・持ち時間と小銭の出し方。ホストは「ホストも対戦する」・「はじめる」。端末なしの参加者を足す欄は、たたんだ「そのほかの操作」（`<details id="proxyMenu">`・`.cb-hostmenu`。ホストだけ・開くと出る。2026-11-06 docs/development/ui.md「たまに使う操作をたたむ」）の中
  ↓「はじめる」（対戦する人が1人以上いる。1人ならひとりで数える）
対決（screen-game）: 対戦する人の札（残り時間・バー・ここまで）・番の表示・トレー（3・2・1／パス／正解・時間切れの帯）・金額の欄・「パス」「こたえる」
  ↓ 残りが1人
結果（同じ画面）: 「もう一回（先に答える人をかえる）」「待合室へ（対戦する人を選びなおす）」（ホスト）・出た小銭の一覧
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）。1台の画面では出さない
- 対戦する人: ルームに参加している人みんなと端末なしの参加者。参加した順に答える（`seatList`。席を選ぶ・順番を変える操作はない）。ホストは「ホストも対戦する」（はじめはオン）を外すと進行だけ。参加できるのは対戦する人が6人になるまで（7人目は「このルームはいっぱいだよ」で、みんなにみせる画面を案内する）。対決の途中に入った人は、その回は観戦で、次の回から対戦する
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「はじめる」、対決「こたえる」、結果「もう一回」、いっしょに数える「答えを見る」）
- 札はトレーの上にならべる。2人のときだけ、広い画面（900px 以上）でトレーの左右に置く（画面共有で見やすいように）
- いっしょに数える: 枚数（2〜8枚）・種類・ならべ方をその場で変えられる。「答えを見る」で合計と内訳、「次の小銭」。PC では Enter・スペースでも進む

## status 遷移

```
waiting ─はじめる→ play（game.duel.phase: ready → play ⇄ reveal / pass … → over）
play ─もう一回（ホスト・終わったあと）→ play（新しい対決。先に答える人を入れかえる）
play ─待合室へ／この対決をやめる（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
charinbaton_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── set:                { time, kinds, maxCoins, arrange, first: 'random'|'top', hostPlays }   # 待合室で決める（持ち時間と小銭の種類はみんな同じ）

  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}:     { joinedAt }                # 端末なしの参加者
  └── game/                          # 「はじめる」で作り、待合室にもどると消す
       ├── id, seats: [名前, …], uids: [匿名ID または ''（端末なしの人）, …], proxy: [true/false, …]
       ├── duel: engine.js の対決の状態（settings・phase・turn・rem・at・phaseEnd・correct・out・problem・history・last・lastOut・winner・rev・startedAt）
       └── ended: 一度でもおわった（finish を1回の対決に1回だけ数える）
```

- 時刻（`at`・`phaseEnd`・`startedAt`）は、書いた端末の `RoomkRTDB.now()`（サーバー時刻の見積もり）
- Realtime Database は空の配列と null を消すので、読むときに `normDuel` で埋めなおす。合計（`total`）と組み合わせ（`key`）は小銭から計算しなおす。壊れた値は読み飛ばす（`gameOf`）
- **答えの金額もルームに入る**。番でない人の画面には出さない（性善説。ルートの AGENTS.md「セキュリティ方針」）

## transaction 設計

すべてルーム全体への `transaction()`。ホストの操作は `hostUid` を確かめる（`hostTransaction`）。
席・設定の変更は、続けて変えても取りこぼさないよう二度押しよけのロックを使わない（中で今の値から作りなおす）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | リバーシと同じ（名前が空いている・対決の席の名前は同じ匿名IDの人だけ）。対戦する人（ゲスト＋端末なし＋対戦するホスト）が6人に達していたら断る（対決の席の人が戻るときは見ない） |
| 端末なしの参加者・設定・ホストも対戦する | ホスト | `waiting`（端末なしは4人まで・対戦する人は6人まで） |
| はじめる | ホスト | `waiting`・対戦する人（`seatList`）が1〜6人 → `game` を作る（`createDuel`）。答える順は参加した順 |
| 正解 | 番の席の人（端末なしの人・通信が切れた人の番はホスト） | `play`・ホストが在室・押した時点の game.id と場面の番号（`duel.rev`）が一致・`duel.phase === 'play'`・その番に答えられる人 → `E.answer`。時間が残っていなければ「ここまで」（残り1人なら決着）として書く |
| まちがい | — | **書かない**。押した端末で「ちがうみたい」を出すだけ |
| パス | 正解と同じ | 正解と同じ照合 → `E.pass` |
| 時間で進める（3・2・1 のおわり・正解の帯のおわり・「ここまで」のおわり・パスのおわり・時間切れ） | ホストか、対戦する人の端末（「ここまで」の人も） | ホストが在室・game.id と `rev` が一致・この端末の時刻で `E.due` → `E.tick`。同じ場面へ同時に送っても `rev` の照合で1つだけ通る。まだと判定されたら0.7秒後にためしなおす |
| もう一回 | ホスト | おわった対決・game.id 一致・いま参加している人が1人以上 → いま参加している人みんなで、先に答える人を次の人にかえて新しい対決 |
| 待合室へ | ホスト | game.id 一致 → `waiting`。席は直前の対決のまま |
| 退出 | ゲスト | 自分の在室を消す。待合室なら自分の席を空ける（対決中の席は残し、ホストが代わりに入れられる） |

## 接続・切断・再接続

リバーシと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- 席の人が切れると、全員の札に「通信が切れた」、ホストの画面に「○○の番。代わりに入れてね」。ホストが代わりに入れられる。時計は止めない。戻ると（同じタブの読み込み直し・同じ名前と同じ匿名ID）続きから
- **ホストが切れている間は時計を止める**（各端末の時計は `hostDisconnectedAt` で止めて出す。だれも書かない）。参加者の画面は共通のオーバーレイ「ホストの戻りを待っています」で押せない。ホストが戻ると、在室を戻す transaction の中で `E.resume`（止めた時刻の残りを残して 3・2・1 から。正解の帯・「ここまで」の途中なら次の人の番から、パスの途中なら新しい小銭から。止めた時点で時間が残っていなければ「ここまで」）。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- 対決の席の名前は、ほかの人（別の匿名ID）は使えない。対決中に入った人は観戦

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。対決がおわっても自動削除しない（「もう一回」と出た小銭のふりかえりのため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 待合室にもどると `game` を消す（席・設定・端末なしの参加者は残る）

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。players に入らない・切断予約をしない・期限切れのルームも消さない・時間で進める書き込みもしない
- 待合室では「参加のしかた」とルームコードを大きく出す。対決では、金額の欄を出さず、トレーをいちばん大きく出す
- 秘密の情報がない（答えは正解したときにみんなに出る）ので、ホストの画面をそのまま共有してもよい。みんなにみせる画面は、ホスト自身が対戦するときや、ルームバー・操作を映したくないとき用

## 1台の画面・いっしょに数える

- 1台の画面: 通信しない。対戦する人（1〜6人。はじめは2人分の欄。「対戦する人を足す」「この人を外す」）の名前（なくてもよい。なければ「1人目」「2人目」…）・持ち時間・小銭の種類と、枚数・ならべ方・先に答える人を選んで「はじめる」。対決は sessionStorage（`charinbaton_local`）に1秒ごとにおぼえ、読み込み直すと閉じていた間は数えずに 3・2・1 から続く。「この対決をやめる」「トップへ戻る」で消す。結果のあと「もう一回」で先に答える人を次の人にかえる。「名前や設定を変える」で準備の画面へ
- いっしょに数える: 通信しない・時間なし・勝ち負けなし・記録なし

## 利用回数（stats.js）

「1回」は1回の対決。

| 項目 | 数えるとき・端末 |
|---|---|
| `room-create` | ルームができた（ホスト） |
| `start`・`players-{N}` | 対決が始まった（「はじめる」「もう一回」。ホスト。N は対戦する人数） |
| `finish` | 対決がおわった（時間切れを確定させた端末。ホストが戻ったときに時間切れとして確定したときはホスト） |
| `again` | おわったあと「もう一回」「待合室へ」（ホスト）。途中でやめたときは数えない |
| `local-start` | 1台の画面で対決を始めた（「はじめる」「もう一回」） |
| `local-finish` | 1台の画面の対決がおわった |
| `count-start` | 「いっしょに数える」をひらいた |

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る。engine.js は DOM に触らない
- **ホスト以外も進行の一部を行う**: 席の人が正解・パスを書く・時間で進める書き込みは対戦する人の端末も行う（ホストのタブが裏に回ってタイマーが遅れても止まらないように。ホストが切れている間は書かない）・時間切れを確定させた端末が `finish` を数える
- **観戦は参加者として players に入る**（席に入らない人）。見るだけの画面（書き込みゼロ）は別にある
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **1人で遊ぶときは、その回の点数（正解した数）を出す**（2026-11-05 オーナー判断）。札と「おしまい！」の行にだけ出し、記録・通算・前の回との比較はしない。2人以上のときは正答数を出さないまま
- **端末なしの参加者は在室を持たない**（`proxies`。切断しない。ホストが代わりに入れる）
- **勝ち負けを出す**（最後まで残った人だけ。2位・3位のような順位・正答数・通算成績は記録も表示もしない）。勝ち残りなので早く「ここまで」になった子は待つ時間が長い（2026-11-04 オーナーがチーム戦でなく勝ち残りを選んだ）。「ここまで」の子にも同じ小銭が見え、自分の画面で続きを見られる。計算の得意・不得意が勝ち負けに出やすいので、持ち時間と小銭の種類をホストが決められるようにし、勝ち負けのない「いっしょに数える」を用意した（人ごとのハンデは、2026-11-04 オーナー判断でみんな同じにした）

## 入れない機能

- 音（正解・まちがい・時間切れの音もなし）
- 正答数・正答率・通算成績・順位の表示や記録。結果の一覧でも、だれがどの小銭を解いたかは出さない（例外: 1人で遊ぶときの、その回の点数＝正解した数だけは出す。記録・比較はしない）
- お札、「おつり」「これで何が買える？」の問題（お金の話はメンターがその場でふる。画面で促さない）
- 画面・名前・説明に「計算」「算数」「練習問題」「ドリル」ということばを使わない（勉強に見せない）
- 対決中の新しい対戦者（途中から入った人は観戦）

## 既知の制約（v1）

- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- 時間で進める書き込みは、ホストが在室していて、ホストか対戦する人のどれかの端末が開いているときだけ進む。ブラウザは裏に回ったタブのタイマーをゆっくりにするので、それらのタブがどれも長く裏にあると、番の切りかわり・時間切れが遅れることがある
- 残り時間の表示と時間切れの判定は、各端末の `RoomkRTDB.now()`（サーバー時刻の見積もり）なので、つながった直後は少しずれることがある
- 待合室で席の人が一時的に切れている間は、同じ名前で別の匿名IDの人が参加すると、その席に入ったことになる（リバーシと同じ。ホストが席を選びなおせる）
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（共通方針どおり、少なめに出る側の誤差として扱う）

- 2026-11-05 の公開前から開いていた古い版のタブ（1人の対決・120・180秒を知らない）は、1人の対決を壊れたデータとして読み飛ばす（その子は答えられず、時計が0になるまで止まって見える）。また古い版のタブが時間で進める書き込みをすると、持ち時間の設定が45秒に戻って書かれ、時計のバーの長さがずれる（残り時間と時間切れは対決の状態どおり）。版をそろえる仕組みは入れず、更新情報で読み込み直しを案内している（二重レビューの指摘。2026-11-05 オーナー判断「案内だけ」。起きるのは公開直後だけで、読み込み直せば直るため）

## メンター向けの心得（画面には出さない）

- 1台の画面で遊ぶときは、子どもに金額を声で言ってもらい、メンターが入れる。チャットで送ってもらってもよい
- 3人以上のときは、早く「ここまで」になった子が待つことになる。苦手な子は持ち時間を長くしておく。「ここまで」の子には、ほかの人の小銭をいっしょに数えてもらうと、待つ時間も楽しくなる
- 計算が苦手な子がいるときは、持ち時間を長く・小銭の種類を「1・10・100円だけ」にする（みんな同じになる）。勝ち負けがつらそうな子とは「いっしょに数える」で、数え方を話しながら遊ぶ
- 結果の一覧は、お金の話のきっかけに使える（「これは何円玉が何枚？」「500円玉1枚と100円玉5枚は同じだね」）。何が買えるか・おこづかいの話は、子どもが話したそうなときだけ。家のお金の事情に踏みこまない
- まちがえても責めない。「もう一回数えてみよう」で十分
