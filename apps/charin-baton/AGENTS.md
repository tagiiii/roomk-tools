# ちゃりんバトン 仕様書

## 目的・使用シーン

ならんだ小銭がぜんぶでいくらかを答えて、正解したら相手にバトンを渡す2人の対決。自分の番の間だけ自分の時計が減り、先に時間がなくなった人の負け。

- **core value**: 小銭を数えることが、そのまま遊びになる。番が行ったり来たりするテンポで盛り上がり、終わったあと「50円玉2枚と100円玉1枚は同じだね」とお金の話につなげやすい
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの1対1でも遊べる）。種類は「クイズ・パズル」（`data-genre="puzzle"`）
- 対戦は2人。観戦はゲスト20人まで（＋端末なしの参加者4人まで）。1回3〜5分
- 着想: テレビ番組『THE FLOOR』（日本テレビ系）のジャンル「小銭」。番組名・ジャンル名は画面・名前に使わず、早見表（`apps/guide/` の「近い遊び」）でだけ紹介する。`updates.json` の紹介文には着想元を書かない（2026-11-04 オーナー）

> 経緯: 2026-11-04 にスタッフからの DM（子どもと番組を見ていて面白かった。お金の話もできて生活にも役立つ）を受けて、オーナーが仕様検討を依頼。設計書 [docs/coin-game-design-v1.md](../../docs/coin-game-design-v1.md)。同日 `drafts/coin-baton/` で試作（1台の画面の対決・いっしょに数える・ウィンドウ間のルームのモック）→ オーナーの実機確認で数字キー入力・PC で画面の数字ボタンをかくす・UI の見直しを入れた → 同日オーナーが「本体に移って」と承認し、名前を「ちゃりんバトン」に決めた。
> 出題の中身は、DM の説明と、オーナーが放送を見て確かめたこと（**小銭だけ・2枚から始まり4〜5枚くらいまで増える**）を正本にした（公開情報には出題の中身が見つからなかった）。

## ルール

| 項目 | 内容 | はじめの値 |
|---|---|---|
| 持ち時間 | 30・45・60・90秒から、人ごとに選ぶ（ハンデ） | 45秒（番組と同じ） |
| 小銭の種類 | 「ぜんぶ（6種類）」か「1・10・100円だけ」を人ごとに選ぶ（ハンデ） | ぜんぶ |
| 小銭の枚数 | 2枚から。その人が2問正解するごとに1枚増える。上限は4・5・6・8枚から選ぶ | 5枚まで |
| ならべ方 | ばらばら（重ならない・少し回す）／そろえる（金額の大きい順） | ばらばら |
| 先に答える人 | くじ・1人目・2人目 | くじ |
| はじまる前 | 3・2・1。小銭はかくし、時計は止める | 3秒 |
| 答える | 番の人が金額を数字で入れて「こたえる」 | — |
| 正解 | 小銭を見せたまま、トレーの下に「正解！ ○○円」と内訳（500円玉 1枚・50円玉 1枚）を出す。その間はふたりとも時計を止める。そのあと相手の番 | 1.5秒 |
| まちがい | 「ちがうみたい。もう一回数えてみよう」。何回でも答えなおせる。時計は止めない | — |
| パス | 小銭をかくして待つ（自分の時計は減る）。同じ人に次の小銭。パスでは枚数は増えない | 3秒 |
| 決着 | 番の人の時計が0で負け。そのとき出ていた小銭を見せたまま、合計と内訳を出す | — |
| 結果 | 勝った人と、出た小銭の一覧（合計つき。押すと大きく出て内訳も見られる）。だれが解いたかは出さない | — |

- 問題はその場でくじで作る（問題集は持たない）。同じ硬貨は3枚まで・直前と同じ組み合わせは出さない
- 番組との違い: 正解のあとの1.5秒（答えの金額をみんなが目で確かめられるように）と、はじまる前の 3・2・1（「はじめる」を押した瞬間に時計が動かないように）は番組にない
- ルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/charin-baton/engine.test.cjs`

## 硬貨の絵

| 硬貨 | 色 | 穴 | 大きさ（実物の直径の比） |
|---|---|---|---|
| 1円 | 白っぽい銀 | なし | 20.0mm |
| 5円 | 金 | あり | 22.0mm |
| 10円 | 銅 | なし | 23.5mm |
| 50円 | 銀 | あり | 21.0mm |
| 100円 | 銀 | なし | 22.6mm |
| 500円 | 金（ふちだけ色を変える） | なし | 26.5mm |

- **本物の図柄（桜・稲穂・平等院など）は描かない**。色・穴・大きさ・金額の数字だけの、ひと目で絵とわかる硬貨にする（通貨及証券模造取締法。財務省 FAQ「貨幣と紛らわしい外観のもの」）
- 金額の数字を大きく書く（色だけに頼らない）。SVG で描く（画像ファイルを持たない）。お札は出さない

## 答え方

- 金額の欄は入力欄に見えるように、ティールの枠・点滅するカーソル・空のときの案内を出す。本物の入力欄にはしない（日本語入力の変換で数字がずれるのを避けるため。`docs/development/ui.md`「文字入力欄と日本語入力」）
- キーボードの数字キー・テンキー（全角の数字も）で入れ、Enter で答え、Backspace・Delete で1つ消す
- **PC（マウスのある端末）では画面の数字ボタンを出さない**（2026-11-04 オーナー「テンキーの表示がややこしい」）。「画面の数字ボタンを出す」で出せて、そのタブの間はおぼえる（`charinbaton_pad`）。スマホ・タブレットはいつも出す
- 画面が切りかわるとき、かくれる画面の入力欄からカーソルを外す（名前欄で Enter を押して始めると、数字キーが名前欄に入っていた。2026-11-04）
- 1台の画面では、子どもが声で言った金額をメンターが入れる。ルームの端末なしの参加者・通信が切れた席の人の番は、ホストの画面に「○○の番。代わりに入れてね」と入力欄が出る

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（対決中なら観戦で対決の画面）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 ├── 「1台の画面であそぶ」 → 名前・持ち時間・小銭の種類・枚数・ならべ方・先に答える人（screen-local） → 対決（通信しない）
 ├── 「いっしょに数える（時間なし）」 → screen-count（通信しない）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting）: 対戦する人（1人目・2人目。持ち時間・小銭の種類）・参加している人・小銭の出し方。ホストは席を選ぶ・入れかえる・端末なしの参加者を足す・「はじめる」
  ↓「はじめる」（席の2人がそろっている）
対決（screen-game）: 2人の札（残り時間・バー）・番の表示・トレー（3・2・1／パス／正解・時間切れの帯）・金額の欄・「パス」「こたえる」
  ↓ 番の人の時計が0
結果（同じ画面）: 「もう一回（先に答える人を入れかえる）」「待合室へ（対戦する人を選びなおす）」（ホスト）・出た小銭の一覧
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）。1台の画面では出さない
- 席: 待合室では、入った順に空いている席（1人目→2人目）へ入る。ホストは自分で選んだときだけ席に入る（ホストも対戦できる）。3人目からは観戦
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「はじめる」、対決「こたえる」、結果「もう一回」、いっしょに数える「答えを見る」）
- 広い画面（900px 以上）では、2人の札をトレーの左右に置く（画面共有で見やすいように）
- いっしょに数える: 枚数（2〜8枚）・種類・ならべ方をその場で変えられる。「答えを見る」で合計と内訳、「次の小銭」。PC では Enter・スペースでも進む

## status 遷移

```
waiting ─はじめる→ play（game.duel.phase: ready → play ⇄ reveal / pass … → over）
play ─もう一回（ホスト・終わったあと）→ play（新しい対決。先に答える人を入れかえる）
play ─待合室へ／この対決をやめる（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

## Firebase データ構造（Realtime Database）

```
charinbaton_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── set:                { time: {a, b}, kinds: {a, b}, maxCoins, arrange, first }   # 待合室で決める
  ├── seats:              { a: 名前, b: 名前 }   # 待合室で選んだ席（a＝1人目、b＝2人目）
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── proxies/{name}:     { joinedAt }                # 端末なしの参加者
  └── game/                          # 「はじめる」で作り、待合室にもどると消す
       ├── id, seats: {a, b}, uids: {a?, b?}（端末なしの人はなし）, proxy: {a?: true, b?: true}
       ├── duel: engine.js の対決の状態（settings・phase・turn・rem・at・phaseEnd・correct・problem・history・last・winner・rev・startedAt）
       └── ended: 一度でもおわった（finish を1回の対決に1回だけ数える）
```

- 時刻（`at`・`phaseEnd`・`startedAt`）は、書いた端末の `RoomkRTDB.now()`（サーバー時刻の見積もり）
- Realtime Database は空の配列と null を消すので、読むときに `normDuel` で埋めなおす。合計（`total`）と組み合わせ（`key`）は小銭から計算しなおす。壊れた値は読み飛ばす（`gameOf`）
- **答えの金額もルームに入る**。番でない人の画面には出さない（性善説。ルートの AGENTS.md「セキュリティ方針」）

## transaction 設計

すべてルーム全体への `transaction()`。ホストの操作は `hostUid` を確かめる（`hostTransaction`）。
席・設定の変更は、続けて変えても取りこぼさないよう二度押しよけのロックを使わない（中で今の値から作りなおす）。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | リバーシと同じ（名前が空いている・ゲスト20人未満・対決の席の名前は同じ匿名IDの人だけ。待合室なら空いている席に入る） |
| 席・入れかえ・端末なしの参加者・設定 | ホスト | `waiting` |
| はじめる | ホスト | `waiting`・席の2人がそろっている → `game` を作る（`createDuel`） |
| 正解 | 番の席の人（端末なしの人・通信が切れた人の番はホスト） | `play`・ホストが在室・押した時点の game.id と場面の番号（`duel.rev`）が一致・`duel.phase === 'play'`・その番に答えられる人 → `E.answer`。時間が残っていなければ負けとして書く |
| まちがい | — | **書かない**。押した端末で「ちがうみたい」を出すだけ |
| パス | 正解と同じ | 正解と同じ照合 → `E.pass` |
| 時間で進める（3・2・1 のおわり・正解の帯のおわり・パスのおわり・時間切れ） | ホストか、対戦する2人の端末 | ホストが在室・game.id と `rev` が一致・この端末の時刻で `E.due` → `E.tick`。同じ場面へ同時に送っても `rev` の照合で1つだけ通る。まだと判定されたら0.7秒後にためしなおす |
| もう一回 | ホスト | おわった対決・game.id 一致・2人がまだいる → 先に答える人を入れかえて新しい対決 |
| 待合室へ | ホスト | game.id 一致 → `waiting`。席は直前の対決のまま |
| 退出 | ゲスト | 自分の在室を消す。待合室なら自分の席を空ける（対決中の席は残し、ホストが代わりに入れられる） |

## 接続・切断・再接続

リバーシと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- 席の人が切れると、全員の札に「通信が切れた」、ホストの画面に「○○の番。代わりに入れてね」。ホストが代わりに入れられる。時計は止めない。戻ると（同じタブの読み込み直し・同じ名前と同じ匿名ID）続きから
- **ホストが切れている間は時計を止める**（各端末の時計は `hostDisconnectedAt` で止めて出す。だれも書かない）。参加者の画面は共通のオーバーレイ「ホストの戻りを待っています」で押せない。ホストが戻ると、在室を戻す transaction の中で `E.resume`（止めた時刻の残りを残して 3・2・1 から。正解の帯の途中なら相手の番から、パスの途中なら新しい小銭から）。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- 対決の席の名前は、ほかの人（別の匿名ID）は使えない。対決中に入った人は観戦

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。対決がおわっても自動削除しない（「もう一回」と出た小銭のふりかえりのため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 待合室にもどると `game` を消す（席・設定・端末なしの参加者は残る）

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。players に入らない・切断予約をしない・期限切れのルームも消さない・時間で進める書き込みもしない
- 待合室では「参加のしかた」とルームコードを大きく出す。対決では、金額の欄を出さず、トレーをいちばん大きく出す
- 秘密の情報がない（答えは正解したときにみんなに出る）ので、ホストの画面をそのまま共有してもよい。みんなにみせる画面は、ホスト自身が対戦するときや、ルームバー・操作を映したくないとき用

## 1台の画面・いっしょに数える

- 1台の画面: 通信しない。名前（なくてもよい。なければ「1人目」「2人目」）・持ち時間・小銭の種類・枚数・ならべ方・先に答える人を選んで「はじめる」。対決は sessionStorage（`charinbaton_local`）に1秒ごとにおぼえ、読み込み直すと閉じていた間は数えずに 3・2・1 から続く。「この対決をやめる」「トップへ戻る」で消す。結果のあと「もう一回」で先に答える人を入れかえる。「名前や設定を変える」で準備の画面へ
- いっしょに数える: 通信しない・時間なし・勝ち負けなし・記録なし

## 利用回数（stats.js）

「1回」は1回の対決。

| 項目 | 数えるとき・端末 |
|---|---|
| `room-create` | ルームができた（ホスト） |
| `start`・`players-2` | 対決が始まった（「はじめる」「もう一回」。ホスト） |
| `finish` | 対決がおわった（時間切れを確定させた端末。ホストが戻ったときに時間切れとして確定したときはホスト） |
| `again` | おわったあと「もう一回」「待合室へ」（ホスト）。途中でやめたときは数えない |
| `local-start` | 1台の画面で対決を始めた（「はじめる」「もう一回」） |
| `local-finish` | 1台の画面の対決がおわった |
| `count-start` | 「いっしょに数える」をひらいた |

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は RTDB_HTML_FILES のとなりの app.js も見る。engine.js は DOM に触らない
- **ホスト以外も進行の一部を行う**: 席の人が正解・パスを書く・時間で進める書き込みは対戦する2人の端末も行う（ホストのタブが裏に回ってタイマーが遅れても止まらないように。ホストが切れている間は書かない）・時間切れを確定させた端末が `finish` を数える
- **観戦は参加者として players に入る**（席に入らない人）。見るだけの画面（書き込みゼロ）は別にある
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **端末なしの参加者は在室を持たない**（`proxies`。切断しない。ホストが代わりに入れる）
- **勝ち負けを出す**（対決の結果だけ。正答数・通算成績・順位は記録も表示もしない）。計算の得意・不得意が勝ち負けに出やすいので、持ち時間と小銭の種類を人ごとに変えられるハンデと、勝ち負けのない「いっしょに数える」を用意した

## 入れない機能

- 音（正解・まちがい・時間切れの音もなし）
- 正答数・正答率・通算成績・順位の表示や記録。結果の一覧でも、だれがどの小銭を解いたかは出さない
- お札、「おつり」「これで何が買える？」の問題（お金の話はメンターがその場でふる。画面で促さない）
- 画面・名前・説明に「計算」「算数」「練習問題」「ドリル」ということばを使わない（勉強に見せない）
- 対決中の新しい対戦者（途中から入った人は観戦）

## あとで考えること

- **複数人での対戦**（2026-11-04 オーナー「複数人でも対戦できたら利用の幅が広がる」）。AI のおすすめはチーム戦（2チームでチームに1つの持ち時間、チームの中で順番に答える。1対1は1人ずつのチームとして今までどおり）。ほかの案は勝ち残り（3人以上で順番に、時計がなくなった人から抜ける。早く抜けた子の待ち時間が長い）。同日、まず2人対戦で公開すると決めた
- 硬貨の数字をかくす上級（色・穴・大きさだけで見分ける）

## 既知の制約（v1）

- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- 時間で進める書き込みは、ホストが在室していて、ホストか対戦する2人のどれかの端末が開いているときだけ進む。ブラウザは裏に回ったタブのタイマーをゆっくりにするので、3人のタブがどれも長く裏にあると、番の切りかわり・時間切れが遅れることがある
- 残り時間の表示と時間切れの判定は、各端末の `RoomkRTDB.now()`（サーバー時刻の見積もり）なので、つながった直後は少しずれることがある
- 待合室で席の人が一時的に切れている間は、同じ名前で別の匿名IDの人が参加すると、その席に入ったことになる（リバーシと同じ。ホストが席を選びなおせる）
- 確定の応答が届く前に通信が切れると、`start`・`finish` などを数え漏れることがある（共通方針どおり、少なめに出る側の誤差として扱う）
- 待合室の席と人ごとの設定のプルダウンは、ルームが変わるたびに作りなおすので、ホストが開いている途中にだれかが入る・抜けると閉じる（リバーシと同じ）

## メンター向けの心得（画面には出さない）

- 1台の画面で遊ぶときは、子どもに金額を声で言ってもらい、メンターが入れる。チャットで送ってもらってもよい
- 計算が苦手な子には、持ち時間を長く・小銭の種類を「1・10・100円だけ」にしてハンデにする。勝ち負けがつらそうな子とは「いっしょに数える」で、数え方を話しながら遊ぶ
- 結果の一覧は、お金の話のきっかけに使える（「これは何円玉が何枚？」「500円玉1枚と100円玉5枚は同じだね」）。何が買えるか・おこづかいの話は、子どもが話したそうなときだけ。家のお金の事情に踏みこまない
- まちがえても責めない。「もう一回数えてみよう」で十分

テストで見つけて直したもの:
- 正解・時間切れの帯が小銭にかぶり、小さいトレーで小銭が隠れる（帯をトレーの下、金額の欄の場所に移した）
- 時間切れの帯の文字が長く折れる
- スマホで数字ボタンの最後の段が画面からはみ出す（札・欄・ボタンを詰めた）

二重レビュー（2026-11-04）: Codex（CLI・読み取り専用）と Claude のレビュー役（サブエージェント）。どちらも、同期の取りあい（正解・パス・時間で進める書き込み）とホストが戻ったときの続きに問題はないとした。直したもの:
- パスの3秒の間に時間切れになると、最後の小銭の合計と内訳が出ない（パスした小銭を時間切れとして一覧に残す）
- 壊れた対決のデータを補って続けてしまう（進行に要る値が壊れていたら読み飛ばす。正解の帯の金額は小銭から計算しなおす）
- 匿名IDのない壊れた在室の人で対決を作ると、書き込みが失敗する
- 入れている途中の数字が、番や場面が変わっても残る（場面の番号が変わったら消す）
- パスを送れなかったとき、画面の数字と内部の値が食い違う
- 1台の画面の「はじめる」「もう一回」の二度押しで、対決を作りなおす
- 結果の小銭を大きく見ている途中に「もう一回」になると、窓が開いたままトレーと数字キーをふさぐ
- 相手のパス・正解の帯の間も「○○が数えているよ」と出る
- 1台の画面で「この対決をやめる」の確認を出している間も時計が減る（やめなかったときは 3・2・1 から続ける）
- 待合室で2か所を続けてすばやく変えると、先に変えた値がもどる（変えた項目だけを今の設定に重ねる）
- 対決のデータが壊れて play のまま残ると、始めなおせない

直さなかったもの: 待合室のプルダウンが、ホストが開いている途中にだれかが入ると閉じる（下の「既知の制約」）。
