# 大富豪 仕様書

## 目的・使用シーン

トランプの大富豪。場のカードより強いカードを出していき、手札を早くなくした人からあがる。
それぞれの端末で自分の手札だけを見て出す。8切り・階段・革命などのローカルルールはホストが選ぶ。

- **core value**: みんなが知っている定番を、知っているルールのまま遊べる。人数が足りない・途中で抜けた・放置した、でも止まらない（CPU が代わりに出す）
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば（`data-scenes="bodoge hiroba"`）
- あそぶ人 **3〜6人**（CPU をふくむ）。在室はホストのほかに12人まで（7人目から・はじめたあとに入った人は見る人）
- 所要時間 1回10〜15分

> 経緯: 2026-07-26 に検討して見送り（実装規模と、階級・カード交換で負けが固定される懸念）。2026-10-25 オーナーが「大富豪をつくりたい」と依頼（ルールを設定で選べる・抜けたら CPU・もどれば自分で・制限時間）。
> 同日 `drafts/daifugo/` で試作（BroadcastChannel のモック）→ オーナーが試して、見出しを「ジョーカー・2・8ではあがれない」に、呼び名は結果にいつも出す・カード交換だけ選べる（はじめはオフ）に決めて、本体化を承認。試作の README に仮置きの一覧がある。
> 名前「大富豪」はトランプの一般名称なので、命名の例外（人狼・ブラックジャックと同じ）。
> 2026-11-08 フィードバックで「3連しばり」（設定・はじめはオフ）を追加し、階段では8切りなど1枚の効果を起こさないように変えた。
> 2026-10-27 子どもの意見「必要なルール: 階段革命・都落ち・ジョーカーに同じ効果（10捨てなど）」を受けて3つを追加。同日、「追加できそうなルール」（7渡し・Qボンバー・数しばり・激しばり・5飛び・4止め）もオーナー指示で追加（すべて設定・はじめはオフ）。激しばりは設定ではなく、しばりと数しばりが同時にかかった状態。

## ルール

ルールの本体は `engine.js`（画面・通信に触らない。node でも読める）。

| 項目 | 内容 |
|---|---|
| カード | 52枚＋ジョーカー（0〜2枚。はじめは1枚）。全部を順に配る（人数で割り切れない分は前の席から1枚多い） |
| 強さ | 3 < 4 < … < 10 < J < Q < K < A < 2。ジョーカーはいつもいちばん強い（1枚出し） |
| 出し方 | 1枚・同じ数の2〜4枚（ジョーカーはどの数にもなる）・階段（同じマークで続いた3枚以上。ジョーカーで穴や端をうめられる。2より上には続かない）。1枚＋ジョーカー2枚は、場が空なら同じ数3枚、場が階段なら階段として読む |
| 返し方 | 場と同じ形・同じ枚数で、場より強いもの。階段はいちばん弱い数どうしで比べる |
| パス | 場が空いていなければいつでも。パスした人は場が流れるまで出せない |
| 流れる | 最後に出した人以外がみんなパス（またはあがり）したら場が流れ、最後に出した人から（あがっていたらその次の人から） |
| はじめ | ♦3を持っている人から（カード交換がある回は大貧民から） |
| おわり | のこりが1人になったらおしまい。あがった順が結果 |

### ホストが選べるルール（待合室）

| 設定 | 内容 | はじめ |
|---|---|---|
| 階段 | 上のとおり | オン |
| 革命 | 同じ数を4枚以上で強さが逆に（もう一度で元に） | オン |
| 階段革命 | 4枚以上の階段でも革命になる（革命と階段がオンのとき）。3枚の階段ではならない | オン |
| 8切り | 8を出すと場が流れ、出した人からもう一度。階段に8が入っていても起きない（下の「階段では1枚の効果は起きない」） | オン |
| イレブンバック | J を出すと、場が流れるまで強さが逆。重ねても逆のまま。革命中は元の強さになる | オフ |
| 10捨て | 10を出すと、出した10の枚数まで手札を捨てられる（捨てなくてもいい。捨てたカードはほかの人に見せない） | オフ |
| しばり | ジョーカーなしで、同じマークの組が2回続くと、場が流れるまでそのマークだけ | オフ |
| 3連しばり | ジョーカーなしで、同じマークの組が3回続くと、場が流れるまでそのマークだけ。しばりもオンなら2回でかかる（数え方は `s.lockRun`。ジョーカー入りの手で0、マークが変わると1、場が流れると0） | オフ |
| 数しばり | 続きの数（5の次に6。革命中なら下へ）が出ると、場が流れるまで続きの数だけ。1枚・同じ数の組だけで、階段ではかからない。ジョーカーだけの手は出せて、続きの数とみなす。2の上（革命中は3の下）は続きがないので、ジョーカーしか出せない。しばりと同時にかかると「激しばり」（表示とできごとだけ。設定はない） | オフ |
| 7渡し | 7を出すと、出した枚数まで手札を次の番の人（あがった人はとばす）にわたせる（わたさなくてもいい）。もらった人にだけ「○○から ○○ をもらったよ」と印。10捨てと同じ手なら、捨てる→わたす の順。わたして手札がなくなったらあがり（反則あがりの札なら反則） | オフ |
| Qボンバー | Qを出すと場が流れ、出した人からもう一度（8切りと同じ） | オフ |
| 5飛び | 5を出すと、出した枚数だけ次の人をとばす（あがった人・パスした人は数に入らない）。みんなとばしたら場が流れて出した人から。とばされた人は次に順番が来たら出せる | オフ |
| 4止め | 4を出すと場が流れ、出した人からもう一度（8切りと同じ） | オフ |
| スペ3返し | ジョーカー1枚には♠3で勝てる（勝つと場が流れる。しばり中でも） | オフ |
| ジョーカー・2・8ではあがれない | 最後の1手にジョーカー・いちばん強い数（革命中は3）・8（8切りがオンのとき）を入れられない。場が空いていて、のこり1枚がそのカードのときだけ出せて、順番は最後（結果に「反則あがり」）。10捨てでそのカードを捨てて手札がなくなったときも反則あがり | オフ |
| ジョーカー | なし・1枚・2枚 | 1枚 |
| カード交換 | 下の「呼び名とカード交換」 | オフ |
| 都落ち | 下の「呼び名とカード交換」 | オフ |
| 1回に考える時間 | なし・15秒・30秒・60秒 | 30秒 |
| 時間切れのとき | パスする／CPUが代わりに出す | パスする |
| 出せるカードを目立たせる | 自分の番に、出せないカードを薄くする | オン |

**待合室の見せ方（2026-11-06。docs/development/ui.md「たまに使う操作をたたむ」）**: ホストの「ルール」の欄の上には、まず決めること「ジョーカー」「1回に考える時間」だけを出す（どちらも1回押せば決まり、遊び心地がすぐ変わるため）。ほかの「使うルール」（15項目）・「2回目からのルール」・「時間切れのとき」・「補助」は、たたんだ「くわしい設定」（`<details id="lobbyMore">`・はじめは閉じる）の中に、まとまりごとに見出しと「何が変わるか」の1行（`.df-more__desc`）を付けて置く。見出しの横に、いま使うルールの要約（「使う: 階段・革命・階段革命・8切り」など）。設定を変えると中身（`#lobbyRulesTop`・`#lobbyRulesMore`）だけを作りなおすので、開閉はそのまま。「配ってはじめる」は下に固定（`.df-startbar`。せまい画面は右下の「？」などより上に来るよう下をあける）。参加する人・みんなにみせる画面は、これまでどおり設定の一覧（`#lobbyRulesView`）だけ。設定の値・初期値は変えていない

見出し「ジョーカー・2・8ではあがれない」は、ルール名の「反則あがり」だけだと「反則でもあがれる」と読めるため（2026-10-25 オーナー指示）。

**ジョーカーは、いっしょに出した数として効果も数える**（2026-10-27）: 10＋ジョーカーなら10が2枚で2枚捨てられる、8＋ジョーカーは8切り、J＋ジョーカーはイレブンバック。

**階段では1枚の効果は起きない**（2026-11-08 フィードバックから・オーナー承認）: 8切り・イレブンバック・10捨て・7渡し・Qボンバー・5飛び・4止めは、1枚か同じ数の組で出したときだけ。階段に8や J が入っていても（ジョーカーがその位置でも）起きない。階段革命は階段そのものの効果なので起きる。それまでは階段に入っている数としても数えていた（6・7・ジョーカーで8切りなど）。

**ジョーカーだけで出すときは「何として出すか」を選ぶ**（2026-10-27 オーナー選択）: ジョーカーだけを選ぶと「出す」のかわりに「そのまま」「7として（わたせる）」「8として（8切り）」「10として（捨てられる）」「Jとして（イレブンバック）」のボタンが出る（オンのルールの分だけ。手札がなくなるなら7・10は出さない、イレブンバック中ならJは出さない。Qボンバー・4止めは8切りと同じ、5飛びはみんなパスするので意味がなく、出さない）。強さはいちばん強いままで、効果だけつく（`play(s, p, cards, as)`・手の `as`。できごとと場の説明に「（10として）」）。CPU・時間切れの代わりの手は選ばない（そのまま）。

**「何として出すか」のボタンは、せまい画面（幅600px以下）では幅いっぱいにして縦に積む**（2026-11-07）: ほかのボタンの列と同じく横に分け合うと、幅375で1つが約99px（5つなら約55px）になり、「10として（捨てられる）」などが1行に2〜3文字ずつ折れた縦長のボタンになって読めなかった（P4 監査）。縦に積むと375でも1行で読める。広い画面はこれまでどおり横に並べて折り返す。ボタンの見た目（ぜんぶ同じ枠線のボタン）と数は変えていない。

### 呼び名とカード交換

- **呼び名はいつも出す（設定なし）**: 結果の「あがった順」に、大富豪・富豪・平民・貧民・大貧民（3人なら大富豪・平民・大貧民。6人は平民が2人）
- **カード交換はホストが選ぶ（はじめはオフ）**: 2回目から、配ったあとに前回の大貧民のいちばん強い2枚（いつもの強さ。ジョーカーがいちばん）が自動で大富豪へ、大富豪は好きな2枚を選んで「返す」。4人以上なら富豪と貧民も1枚ずつ。返す人がみんな返すまでだれも出せない。交換がある回は大貧民から出す
- **都落ちはホストが選ぶ（はじめはオフ。2026-10-27 子どもの意見）**: 2回目から、1番にあがった人が前回の大富豪でなければ、前回の大富豪はその場で手札を捨てて抜け（`s.fallen`・札に「都落ち」・できごとに「都落ち！ 前回の大富豪の○○は抜けて、最後になる」）、結果ではいちばん最後（反則あがりの人よりも後ろ）＝大貧民。前回の大富豪が1番なら何も起きない。反則あがりは「1番」に数えない（そのあとの本当の1番で起きる）。10捨てで手札がなくなってあがったときも同じ。3人なら都落ちの時点でのこり1人になるので、そこでおしまい
- 次の回の名前の横に前回の呼び名を出すのは、**カード交換か都落ちがオンのとき**（だれとだれがとりかえるか・だれが前回の大富豪かを示すため。どちらもオフなら次の回に関係しないので出さない。2026-10-25 オーナー指示、2026-10-27 都落ちを追加）
- 前回のあがり順を使うのは、前回と同じ人たち（席の顔ぶれ）のときだけ。待合室にもどってルールを変えても使う。人がかわると交換なしで♦3から
- 交換したカードは、とりかえた2人にだけ見せる（「○○ をわたして、○○ をもらったよ」と、もらったカードの印）

## CPU・時間切れ・抜けた人

| 場面 | 動き |
|---|---|
| CPU の席 | 待合室の「CPUを足す」（「CPU 1」「CPU 2」…）。待合室で外せる。あそぶ人が6人だと足せない |
| 通信が切れた人の番 | 在室（`players/{名前}`）が消えてから3秒待って、CPU が代わりに出す（読み込み直しならその間にもどれる）。札に「通信が切れた・CPUが代わり」、できごとに「○○の通信が切れた…」 |
| 「退出する」で抜けた人 | 同じ（席と手札はゲームが終わるまで残る） |
| もどってきた人 | 同じ名前で入りなおすと席にもどり、また自分で出せる。別の端末（ちがう匿名ID）からでも、その席の人が在室していなければ入れる（性善説。下の「意図的な逸脱」）。自分の番なら考える時間をはじめから（カード交換中は、みんなの締め切りをその人の分までのばす） |
| 時間切れ | 「パスする」ならパス。場が空いているとき（パスできない）・カード交換は CPU が決め、10捨ては捨てない。「CPUが代わりに出す」なら CPU が決める |
| 時間切れが2回続いた人 | CPU にまかせる。その人の画面に「いまはCPUが代わりに出しているよ」と「自分でやる」。自分で出すと回数は0にもどる |
| CPU の考え方 | 1種類。弱いカードから手放し、ペアはなるべくくずさない。ジョーカーといちばん強い数は、手札が多いうちは場を取りにいかない（パス）。返すカードは弱い順（ジョーカーは返さない） |

CPU の席・抜けた人・まかせた人の番と、時間切れは、**ホストの画面が進める**（250ミリ秒ごとに確かめ、CPU は1.1秒待ってから出す）。ホストの通信が切れている間は止まる（参加する人の操作はできる）。

- 時計は Web Worker で回す。ホストが「みんなにみせる画面」を別のタブで開いて共有すると、ホストのタブは裏に回り、ふつうのタイマーは間引かれて（長く裏にあると1分に1回）CPU が止まるため
- ホストの画面では、ホスト自身の席は在室とみなす（再読み込みの直後に `hostConnected` が戻る前に、ホストの番を CPU が出さないように）
- 新しい回（`round`）になったら、在室の記録と CPU の待ちを決めなおす

## status 遷移

```
waiting（待合室）→「配ってはじめる」→ playing（あそんでいる・結果）
playing →「もう一回（配りなおす）」→ playing（同じ席で配りなおす）
playing →「待合室にもどる」「この回をやめて待合室へ」→ waiting
```

結果は `playing` のまま `game` の中の `over` で出す（ふりかえり画面滞在中は削除しない公認バリアント。下の「終了とデータ削除」）。

## Firebase データ構造（Realtime Database）

```
daifugo_rooms/{CODE}
  status: 'waiting' | 'playing'
  host, hostUid, hostPlays, hostConnected, hostDisconnectedAt, createdAt
  round: 何回目か
  settings: { rules: {...engine の設定}, time: { limit, onTimeout }, hint }
  players/{名前}: { isHost, uid, joinedAt }   // 在室（ゲストは onDisconnect で消える）
  cpus/{c1}: { name: 'CPU 1', joinedAt }
  cpuN: CPU の名前の番号
  lastOrder: '["p:そら","c:c1",...]'          // 前回のあがり順（席の id の JSON 文字列）
  game: '{...}'                               // ゲームの状態の JSON 文字列（下）
```

`game` の中身: `seats`（席の並び。`{ id: 'p:名前' | 'c:CPUのキー', name, cpu }`）・`s`（`engine.js` の状態。手札・場・パス・あがり・交換など）・`log`（できごと6件まで）・`deadline`（締め切り。サーバー時刻寄り）・`auto`（CPU にまかせた人）・`timeouts`（続けて時間切れになった回数）。

- **JSON の文字列にしている理由**: RTDB は空の配列を消すので、ルールの状態（空の手札・空の場・あがった順など）をそのまま置くと読み戻せない。読むときは形を確かめ、壊れていたら読まない
- 手札は全員分が同じ文字列に入っている。画面では自分の分だけ出す（DevTools で見えるのは性善説で許容。ルート AGENTS.md「セキュリティ方針」）

## transaction 設計

- 作成・参加・再接続は共通の形（作成・参加は送信後の切断のやり直し `transactRetry` つき。`warmRoomCache` で先に購読）
- 出す・パス・捨てる: ルーム全体の transaction で `game` を読み直し、**何回目か（`round`）と何手目か（`s.seq`）が押した時点と同じ**・自分の席か（名前と匿名IDの持ち主）・いまの段階（10捨て待ちか）を確かめてからルールに当てはめる。先に時間切れなどが入って書けなかったときは「そのあいだに場が変わったよ」と出す
- 返す（カード交換）: 返す人は同時に押すので、何手目かは見ず、何回目かと自分がまだ返していないかだけ確かめる
- ホストの進行（CPU・時間切れ・在室のできごと）も同じ transaction。CPU は「同じ何手目で、その席がまだ CPU で動く」、時間切れは「同じ何手目で、同じ締め切り」を確かめる
- 待合室の操作（設定・CPU・ホストもあそぶ・配る）はホストの transaction（`hostUid` を確かめる）
- 設定・「ホストもあそぶ」は、前の保存が終わる前に押しても捨てない（`hostTransaction` の `concurrent`。どれもルームを読み直して1項目だけ変えるので、続けて走っても重ならない）。CPU・配るは二度押しを捨てる（`state.busy`）。2026-11-08 まで設定も捨てていて、続けてすばやく押すと、ボタンの見た目だけ変わり設定は前のまま残っていた（E2E の「設定はルームに入る」が落ちて見つかった）

## 接続・切断・再接続

- ホスト: `onDisconnect().update({ hostConnected: false, hostDisconnectedAt })`。参加する人にはオーバーレイ。2分（`ORPHAN_TTL_MS`）で期限切れ
- ゲスト: `players/{名前}` を `onDisconnect().remove()`。接続のたびに在室を確かめて張り直す（`ensurePresence`）
- 再読み込み: sessionStorage（`daifugo_session`）から同じルーム・同じ名前で戻る（手札は保存しない）
- 参加用のリンク `?room=`、QR コード、みんなにみせる画面 `?watch=` は共通の形

## 終了とデータ削除

公認バリアント「ふりかえり画面滞在中は削除しない」（`docs/development/rtdb.md`）。結果の画面のあと「もう一回」「待合室にもどる」で続けるため、終了30秒後の自動削除はしない。削除は (1) ホストの「ルームを閉じる」 (2) ホスト切断の TTL (3) 次に開いたときの期限切れの掃除、の3つ。

## みんなにみせる画面（画面共有用・見るだけ）

ホストのルームバーの「みんなにみせる画面」、またはトップの「みんなにみせる画面をひらく」。ルームに入らず、書き込まない。あそぶ人の札・場・できごと・結果を出し、**手札は出さない**（場のカードは大きく）。

## 利用回数（stats.js）

`room-create`（ルームを作った）・`start`（配ってはじめた）・`again`（もう一回）・`players-N`（あそぶ人の数）・`finish`（最後まで終わった。終わらせた transaction の画面で1回）。

## 意図的な逸脱

- **ゲームの状態を JSON 文字列で持つ**（上の理由）
- **別の端末からでも、同じ名前で空いている席にもどれる**: 抜けた子が端末をかえて入りなおすことがあるため。ほかの子が名前をまねて入る心配は、スタッフの見ている場の性善説で許容（在室している人の名前は使えない）
- **「CPU」ではじまる名前は使えない**（CPU の席と見分けるため）
- **ニックネームは8文字**（試作の10文字から共通の8文字へ）
- **場の札の色**: ふつうは黄、革命は赤、しばりはティール（`#E6F2F4` の面に `#286F7C` の文字）で固定。アクセント色が茶オレンジになり、変数にするとふつうの札と見分けにくくなるため（2026-11-06 オーナー判断）

## 入れない機能

- 9リバース・11バック以外の「○○返し」など、上の表にないローカルルール
- 激しばりの独立した設定（しばりと数しばりの両方をオンにすれば起きる）
- CPU がジョーカーの「何として出すか」を選ぶこと（いつも「そのまま」）
- 都落ちの大きな表示（スプラッシュ）。抜ける子の画面にも大きく出るので、できごとと札だけにしている
- 端末なしの参加者（ホストが代わりに出す）: 手札がホストに見えてしまう。代わりに CPU を足す
- カードを配る演出・音（音は鳴らさない）
- CPU の強さを選ぶ設定

## 既知の制約

- 電源が落ちた・Wi-Fi が切れたなどの急な切断は、サーバーが気づいて在室が消えるまで数十秒〜1分ほどかかる。その間は「通信が切れた」にならず、CPU も代わりに出さない（考える時間があれば時間切れで進む。「なし」だと止まる）。別の端末から同じ名前で入ろうとしても「その名前は使われているよ」になる。少し待ってから入りなおす
- ホストの通信が切れている間は、CPU と時間切れが進まない
- 古い端末が再接続した瞬間に切れると、同じ名前で入りなおした新しい端末の在室が一瞬消えることがある（在室の確かめなおしで数秒でもどる）

## メンター向けの心得（画面には出さない）

- カード交換は「負けた子ほど不利になる」仕組み。はじめはオフ。オンにするのは、遊び慣れた子が「いつものルールでやりたい」と言ったときくらいにする
- 都落ちは逆に「勝ち続ける子を引きずり下ろす」仕組みで、負けが固定される心配はない。ただし抜けた子はその回の残りを見ているだけになるので、回が長いときは気にかける
- 大貧民の呼び名が気になりそうな子がいるときは、結果の画面を長く映さず、すぐ「もう一回」へ
- 時間切れが続く子は、操作がわからないのかもしれない。「自分でやる」を一緒に押す
- CPU はそこそこ強い（でたらめに出す3人相手なら7割ほど1番）。初めての子ばかりのときは、メンターも入って人数を CPU に頼りすぎない
