# ひらめき大喜利 仕様書

## 目的・使用シーン

お題に、思いついた答えを何回でも出す大喜利。出た答えは1つずつ、だれのか伏せてみんなの画面に出る。
「おもしろい！」を押した人が、投票する人の何割か（ホストが選ぶ）に届いたら「一本！」。順位も点もない。

- **core value**: 思いついた順に何回でも出せて、1回の答えが外れても目立たない。押した数は見せず、一本になったときだけ名前が出るので、「票が入らなかった」が見えない。答えを書かずに「投票だけ」でも参加できる
- 対象: 小学校中学年〜中学生。コトバであそぼ・ボドゲクラブ・サークルタイム（`data-scenes="kotoba bodoge circle"`）
- 投票する人 **2人から**（ゲスト15人まで＋端末のない参加者4人まで）。1つのお題は数分
- たとえグランプリ（1人1回答える→匿名で1票→点数と順位）とは別の遊び

> 経緯: 2026-10-29 の要望「IPPONグランプリのような大喜利ができるツール」から、オーナーと相談して `drafts/oogiri/` で試作（同じブラウザのウィンドウの間だけでつながるモック）。同日〜10-30 にオーナーが触って直した点（「押すだけ」→「投票だけ」・ホストの確認・お題の区切り・見る時間・人ごとの一本の数・端末のない参加者・ホストのすること）を反映し、2026-10-30 にオーナーが本体化を決めた。表示名「ひらめき大喜利」・お題104個もオーナー決定（同日）。
> 名前に番組名（IPPON）は使わない。早見表では系統ラベル（大喜利・発想系）で紹介する。
> 試作の README（決めたことの経緯）は、本体化のコミットの前の `drafts/oogiri/README.md`（git の履歴）にある。

## ルール

| 項目 | 内容 |
|---|---|
| 答え方 | 思いついたら何回でも出せる（40文字まで）。答えるのは出したい人だけでいい |
| ホストの確認 | 参加者の答えは、ホストが「みんなに出す」を押すか、**届いてから10秒たつと**順番に入る（2026-10-30 オーナー判断。ホストが押し忘れて、書いた答えが出ないまま終わる子がいないように）。ホストの画面の届いた答えに「あと7秒で出るよ」。ホストは「かくす」も選べる（順番待ち・出ている間もかくせる）。ホスト自身の答えと、ホストが代わりに書いた答えは確認しない。確認待ちと順番待ちを合わせて1人2つまで |
| 出し方 | 答えは1つずつ出し、押せる時間（ホストが10・15・20秒から選ぶ。はじめは15秒）をとる。必要な数に届いたら、その場で一本 |
| 一本 | 投票する人の何割かが押したら一本。ホストが待合室で「半分・3分の2・全員」から選ぶ（はじめは半分。切り上げ・1人以上） |
| 投票する人 | 答えを出した本人をのぞいた、いる人全員（「投票だけ」の人・遊ぶホスト・端末のない参加者をふくむ）。進行だけのホストとみんなにみせる画面は入らない。答えが出ている間に抜けた人・参加のしかたを変えた人がいたら、その場で数えなおす |
| 押した数 | 見せない。一本になったら大きく出し（3.5秒・音なし）、ならなかった答えは数を出さずに「これまでに出た答え」へ静かに移す |
| 名前 | 押している間は、だれの答えか出さない。一本になったときだけ「○○さん」。一本にならなかった答えは名前を出さない（自分の答えには、自分の画面でだけ「あなた」） |
| 参加のしかた | 参加するときに「答えも出す」か「投票だけ」を選ぶ（はじめは「答えも出す」）。途中でもいつでも切りかえられる。どちらかは、ほかの人の画面に出さない。ホストは「進行だけ」も選べる（はじめは「答えも出す」。2026-10-30 オーナー判断） |
| お題 | ホストが3つの候補から選ぶ（「ほかの候補」で入れかえ。このルームで出していないお題を先に出す） |
| お題の区切り | ホストが待合室で「一本が出たら」（はじめ）か「時間で」（2・3・5分。はじめは3分）を選ぶ。どちらでも、ホストはいつでも「答えを締め切る」で区切れる |
| 一本が出たら | 一本が出たら**新しい答えの受付だけ**を締め切る。順番待ち・確認待ちの答えは最後まで1つずつ出してから結果へ（投票もでき、1つのお題で一本が2つ以上出てもよい。2026-10-30 オーナー判断。はじめは順番待ちを出さずに結果へ並べていたが、書いた答えが出ないまま終わる子が出るため変えた） |
| 時間で | お題の下に「のこり 2:34」。時間になったら答えを締め切り、順番待ちの答えが出終わったら結果へ。時間内は何回でも一本 |
| 結果へ進む条件 | 締め切っていて、いま出ている答え・順番待ち・確認待ちがないとき（確認待ちも10秒で順番待ちへ入るので、止まらない） |
| ここでおしまい | 遊ぶ画面で、まだ出ていない答え（確認待ち・順番待ち）があると、確認の文に「まだ出ていない答えが3つあるよ」と出す |
| 結果 | このお題の一本（名前つき）と、ほかに出た答え（名前なし）。ホストは「次のお題へ」「ここでおしまい」 |
| おしまい | 「一本の数」（人ごと・1本以上の人だけ・参加した順。順位はつけない）と「お題ごとの一本」。ホストは「もう一回あそぶ」 |
| 途中参加 | 遊んでいる途中からも入れる |
| 確認の手間 | 1つずつ「みんなに出す」。押し忘れても10秒で出る（2026-10-30 オーナー判断。「全部出す」・確認する／しないの選択は足さない） |

## 端末のない参加者（ホストが代わりに書く・押す）

- ホストが「端末のない参加者を足す」（参加する人のカードの中にたたんである）で名前を足す。4人まで。ほかの人と同じ名前は不可。足せるのは**待合室と結果の画面**（お題の間）、**外せるのは待合室だけ**（おしまいの画面の一本の数が消えないように）。ルームの `proxies/{name}` に置く。在室（`players`）には入れず、切断しない扱い
- 参加者の一覧にほかの人と同じく出る。「端末なし」の印はホストの画面にだけ
- 投票する人に数える。はじめられる条件の「投票する人2人以上」にも入る
- 遊ぶ画面のホストの枠のいちばん上に「端末のない参加者のぶん」: 子ごとの「おもしろい！」（その子の答えには押せない＝「本人の答え」）と「代わりに答えを書く」（名前を選んで「代わりに出す」。確認なしで順番待ちへ。1人2つまで）
- 一本になったら、その子の名前で出し、一本の数にも入る
- 押さないままの子も投票する人に数えるので、一本が出にくくなる。気になるなら待合室で外す（仮置き）

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード＋参加のしかた（screen-join） → 待合室（遊んでいる途中ならその画面）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（waiting）: 参加する人（ホストは「端末のない参加者を足す」）・ホストのすること（ホストだけ）・ルール（ホストだけ）・あなたの参加のしかた・「はじめる」（ホストだけ）・あそびかた
  ↓「はじめる」（投票する人 2人以上）
お題を選ぶ（pick）: ホストに3つの候補（①②③）・「ほかの候補」。画面の下に「ここでおしまい」。ほかの人は待つ
  ↓ お題を選ぶ
遊ぶ（play）: お題・いま出ている答え（押せる時間の帯・「おもしろい！」）・あなたの答え・参加のしかた・ホストの枠（端末のない参加者のぶん・届いた答え・このあと出る答え・答えを締め切る・ここでおしまい）・これまでに出た答え
  ↓ 締め切って、出る答えがなくなったら
結果（result）: 一本・ほかに出た答え。ホストは「次のお題へ」「ここでおしまい」（ホストは端末のない参加者も足せる）
  ↓
おしまい（end）: 一本の数・お題ごとの一本。ホストは「もう一回あそぶ」（→ 待合室）
```

- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）
- 2026-10-30「はじめてホストをする人でもわかりやすいか」を受けて、待合室にホストにだけ「ホストのすること」（画面共有は「みんなにみせる画面」で・お題を選ぶ・「みんなに出す」・「次のお題へ」）と「みんなにみせる画面をひらく」。遊ぶ画面のホストの枠の見出しにも「この画面は共有しないでね」
- ボタン階層: 塗りつぶしの主ボタンは待合室「はじめる」、遊ぶ画面「出す」、結果「次のお題へ」、おしまい「もう一回あそぶ」。ホストの枠の「みんなに出す」（小）・「代わりに出す」は、ホストにだけ出る小さな操作
- 「おもしろい！」は黄色の大きなボタン（押すと「押したよ」で押せなくなる。取り消せない）

## status 遷移

```
waiting ─はじめる→ pick ─お題を選ぶ→ play ─締め切り＋出る答えなし→ result ─次のお題へ→ pick
pick / play / result ─ここでおしまい（ホスト）→ end ─もう一回あそぶ→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

- `play → result` は、時間の進み（`stepTick`）か、操作（出す・みんなに出す・かくす・締め切る）の transaction の中の `stepGame` が行う

## Firebase データ構造（Realtime Database）

```
oogiri_rooms/{roomCode}/
  ├── status:             'waiting' | 'pick' | 'play' | 'result' | 'end'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── rule:               { ratio: 'half'|'two3'|'all', showSec: 10|15|20, cut: 'ippon'|'time', minutes: 2|3|5 }
  ├── usedTopics:         [番号...]  # このルームで出したお題（使い切ったら、出したものからも出す）
  ├── players/{name}:     { isHost, uid, joinedAt, mode: 'both'|'press'|'none' }   # 在室。ゲストは切断で消え、戻ると書き戻す
  ├── roster/{name}:      { uid, joinedAt }   # 参加した人（いまいない人もふくむ）。名前の予約と、一本の数の並び。待合室で退出すると消え、「もう一回あそぶ」でいない人の分を消す
  ├── proxies/{name}:     { joinedAt }        # 端末のない参加者
  └── game/                          # 「はじめる」で作り、「もう一回あそぶ」で消す
       ├── id, round（お題の通し番号）, topic（番号）, cands: [番号×3]（お題を選ぶ間）
       ├── closing, endBy: 'ippon'|'time'|'host', roundEndsAt（時間で区切るとき）, gapUntil
       ├── cur: { a: 答え, at, endsAt, presses: {name: true}, state: 'open'|'ippon', holdUntil }   # いま出ている答え
       ├── pending: [答え]（確認待ち） queue: [答え]（順番待ち） shown: [答え＋ippon]（出た。新しい順）
       ├── hidden: [答え]（かくした）
       └── history: [{ topic, ippons: [答え] }]   # お題ごとの一本（おしまいの画面）
  答え = { id, by: 名前, text, at: 届いた時刻（確認待ちを10秒で順番待ちへ入れるのに使う） }
```

- お題は番号で置く（`data.js` のお題の並べ替え・途中の削除をしない理由）
- 読み込むときは壊れた値を読み飛ばす（`gameOf`。ないものは null か空の配列にして、そのまま transaction で書き戻せるようにする）
- 時刻（`at`・`endsAt`・`holdUntil`・`gapUntil`・`roundEndsAt`）は、書きこむ端末の `RoomkRTDB.now()`（サーバー時刻に合わせた見積もり）

## transaction 設計

すべてルーム全体への `transaction()`。

| 操作 | 実行者 | 検証 → 書き込み |
|---|---|---|
| 作成 | ホスト | 空のコード → 初期ルーム（`transactRetry`。やり直しで自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | 名前が空いている（ホスト・端末のない参加者・ほかの人の在室・ほかの人の roster と同じ名前は不可）・ゲスト15人未満（roster にある人は上限を見ない）→ `players`・`roster`。どの status でも入れる（`transactRetry`） |
| 参加のしかた | 本人（進行だけはホストだけ） | `players/{name}/mode`。投票する人が変わるので、その場で一本を確かめる |
| 設定 | ホスト | `waiting` |
| 端末のない参加者を足す／外す | ホスト | 足す: `waiting`・`result`。外す: `waiting` |
| はじめる | ホスト | `waiting`・投票する人2人以上 → `pick`・`game` を作る。候補は transaction の外でくじを引く |
| ほかの候補・お題を選ぶ | ホスト | `pick`・game.id 一致（選ぶは候補にあるお題）→ `play`。お題ごとの欄を空にして、`history` に足す |
| 答えを出す | 本人（ホストは端末のない参加者の代わりにも） | `play`・round 一致・締め切っていない・「答えも出す」・1人2つまで → 参加者は `pending`、ホスト自身と代わりの答えは `queue` |
| おもしろい！ | 本人（ホストは端末のない参加者の代わりにも） | **`game/cur` だけへの transaction**（一斉に押してもルーム全体を送り直さない）。いま出ている答えの id 一致・一本でない・本人の答えでない・まだ押していない・押せる時間を0.3秒より過ぎていない → `presses`。進行だけでないことは押す前に手元で確かめる（数えるのは投票する人だけなので、ずれても数に入らない）。押した端末がすぐに `stepTick(true)` で一本かどうかを見る |
| みんなに出す・かくす・締め切る | ホスト | `play`。かくすは確認待ち・順番待ち・いま出ている答え（一本を出している途中もふくむ。その一本はお題ごとの一本に入れない）。確かめている間に出し終わっていたら「もう出し終わった答えなので、かくせなかったよ」 |
| ここでおしまい | ホスト | 押した時点の status とお題の番号が一致（確認の間にほかのタブで進んでいたら何もしない）。一本を大きく出している途中なら、その一本をお題ごとの一本に入れてから `end` |
| 答えを締め切る | ホスト | 押した時点のお題の番号が一致 |
| 時間の進み | ホストと参加者（`stepTick`。200ms ごとに手元で `stepGame` を試し、変わるときだけ書く。参加者の端末は0.8秒遅れていたときだけ） | 届いて10秒たった確認待ちを順番待ちへ・一本（数えなおし）・押せる時間の終わり・一本の表示の終わり・時間で締め切る・次の答えを出す・結果へ。中で同じ進みを確かめるので、だれが進めても結果は同じ |
| 次のお題へ・おしまい・もう一回あそぶ | ホスト | それぞれの status・game.id（次のお題へは round も）一致 |
| 退出 | ゲスト | 自分の在室を消す（待合室なら roster も）。投票する人が変わるので、その場で一本を確かめる |

## 接続・切断・再接続

しるしでヒントと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで。参加のしかたは sessionStorage から戻す）。切断の予約を先に張るのは、名前が自分に予約されている（`roster` が自分）ときだけ。「もう一回あそぶ」で名前が空いたあとに戻るときは、在室を書いてから張る（同じ名前で入った人の在室を消さないため。rtdb.md の注意）
- 名前は `roster` に残るので、抜けた人は同じ名前で戻れる（同じ匿名ID のときだけ）。答え・一本はゲームにあるので残る
- ゲストが抜けると投票する人が減る。いま出ている答えは、その場で数えなおして一本を確かめる
- **時間の進みは、ふだんはホストの端末、遅れたら参加者の端末**。ホストが「みんなにみせる画面」のタブを前に出して共有すると、ホストのタブは裏に回り、タイマーが1秒に1回（5分をこえると1分に1回）まで落ちる。そのため参加者の端末が、0.8秒遅れていたら代わりに進める（2026-10-30 レビューの指摘）
- ホストが切断している間は、ゲストと見る画面に共通のオーバーレイ（2分。`ORPHAN_TTL_MS = 2 * 60 * 1000`）。順番待ちの答えは参加者の端末が出しつづけるが、確認待ちの答えは出ない（ホストが「みんなに出す」を押せないため）

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おしまいの画面では自動削除しない（「もう一回あそぶ」のため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）
- 「もう一回あそぶ」で `game`（答え・一本）を消す。端末のない参加者（`proxies`）は待合室に残る

## みんなにみせる画面（画面共有用・見るだけ）

ホストの画面には、届いた答え・このあと出る答えが**名前つき**で出る。画面共有は、ホストが別のタブで「みんなにみせる画面」を開き、それを共有する。

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②待合室の「ホストのすること」のボタン ③トップの「みんなにみせる画面をひらく」④アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。players に入らない・切断予約をしない・期限切れのルームも消さない
- **出さないもの**: 届いた答え・このあと出る答え・名前（一本のときをのぞく）・お題の候補・操作のボタン・参加のしかた
- お題と答えを大きめに出す（`.is-watch`）。「いま出ている答え」の下は「おもしろかったら、自分の画面で「おもしろい！」を押してね」

### 秘匿情報の扱い（性善説）

- だれの答えか・だれが押したか・参加のしかたはルームにあり、画面に出さないだけ。DevTools でルームを見れば分かることは、共通のセキュリティ方針どおり許容する

## 利用回数（stats.js）

「1回」はお題1つ。ホストが好きなところで終える型。

| 項目 | 数えるとき・端末 |
|---|---|
| `room-create` | ルームができた（ホスト） |
| `start`・`players-{N}` | お題を選んだ（ホスト。N はそのときの投票する人の数） |
| `finish` | お題の結果に進んだ（ホストの端末が play → result を見たとき） |
| `again` | 「次のお題へ」・「もう一回あそぶ」（ホスト） |

## お題の方針（`data.js`）

- 2026-10-30 の104個はオーナーが確定。新しいお題を本体に入れるのはオーナーが決める（ルート AGENTS.md「新規コンテンツの本体投入は人間専任」）
- ルームではお題を番号で共有するので、**並べ替え・途中の削除はしない。追加は末尾だけ**。重複は content-audit で弾く
- 学校・勉強・恋愛・こわい話・死・暴力・人や家族をからかう方向に行きにくいものを選ぶ
- 「無人島に1つだけ持っていくなら？（ちょっと変わったもの）」は talk-card の質問と似ている（content-audit の similarQuestions）。大喜利のお題と会話のお題で遊び方がちがうので残している

## 意図的な逸脱

- **分割構成の RTDB アプリ**: lint の REF-4（TTL 定数）と REF-5（タイマー解放）は index.html しか見ないので、app.js の `ORPHAN_TTL_MS` と `clearInterval`・`clearTimeout`・`cancelAnimationFrame` は rtdb-audit で手確認する
- **進行の一部をホスト以外も行う**: 「おもしろい！」の transaction が、そのまま一本にする（押した瞬間に一本を出すため）。退出・参加のしかたの切りかえも、その場で一本を確かめる
- **時間で進むことは、ホストの端末と、遅れたときの参加者の端末が行う**（`stepTick`。ホストのタブが裏に回っても止まらないように）。みんなにみせる画面は進めない（書き込みゼロ）
- **「おもしろい！」は `game/cur` だけへの transaction**（ほかの操作はルーム全体）
- **ホストの初期値は「答えも出す」**（2026-10-30 オーナー判断。ほかのアプリのように進行だけにはしない）
- **遊んでいる途中からも入れる**（何回でも答える遊びなので、途中の人が困らない）
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **おしまいに人ごとの一本の数を出す**（オーナー判断。順位はつけず、1本以上の人だけ、参加した順）。ゲームの得点であり、内省の評価ではない
- **ニックネームは8文字**（試作は10文字だった）

## 入れない機能

- 音（一本も画面の表示だけ）
- 押した数の表示・順位・点
- 「全部出す」・確認する／しないの選択（2026-10-30 オーナー判断。かわりに、押し忘れても10秒で出る）
- 参加者がお題を選ぶ・自分でお題を書く
- 押した「おもしろい！」の取り消し
- 絵のお題（写真で一言のような形）

## 既知の制約（v1）

- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）
- ホストが切断している間は、確認待ちの答えが出ない（順番待ちの答え・時間の締め切りは、参加者の端末が進める）
- 時刻は書きこむ端末の `RoomkRTDB.now()` で決める。つながった直後は、ほかの端末の帯の表示が少しずれることがある
- 参加者がだれもいなくてホストのタブが裏に回っていると、時間の進みはホストのタブのタイマー（1秒〜1分に1回）まで遅れる
- 端末のない子が押さないままだと、その子も投票する人に数えるので一本が出にくくなる

## メンター向けの心得（画面には出さない）

- **画面共有は「みんなにみせる画面」で**。ホストの画面には、届いた答えにだれの答えかが出る
- 届いた答えは、まずい答え（人をからかう・学校や家のことを持ちこむなど）でなければ、すぐ「みんなに出す」。迷ったら「かくす」。かくした答えは、書いた本人の画面にだけ「ホストがかくした」と出る
- 端末のない子の答えや「おもしろい！」は、**メンターへの個別のチャット**で送ってもらい、代わりに入れる（声で言うと、だれの答えか分かってしまう）
- 一本が出ない時間が続いたら、「答えを締め切る」で区切って次のお題へ。一本になる数を「半分」にすると出やすい
- 答えが出ないときは待つ。「答えが出るのを待っているよ」が出るだけで、急かす表示はない
