# あれください商店 仕様書

## 目的・使用シーン

へんな物ばかりの商店街で、1人が1つずつ自分のお店を持つゲーム（2〜12人）。番の人だけがお客さんになり、ほしい物の名前を言わずに、ヒント2つで聞く。お店の人は、自分のお店から「これかな？」と思う物を出すか、出さないかを決める。

- **core value**: 遊びながら、人に何かをたのむ・たのまれる場面を練習する。相手に伝わるようにことばをえらぶ（ヒント）・わからないときにたずねる（質問）・できないときに角を立てずに断る（「うちにはないです、ごめんね」）が、そのまま遊びの操作になっている。ちがう物が出てきても、笑える場面になる
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・サークルタイム・作戦会議（`data-scenes="bodoge hiroba circle sakusen"`。メンターと子どもの2人でも遊べる）。種類は「当てっこ・協力ゲーム」（`data-genre="atekko"`）
- 着想元の市販ゲームはない（オーナーの「ソーシャルスキルをボードゲームで遊びながら覚えられるゲーム」の依頼から作った）。早見表は系統ラベル「ヒントでたのむ協力系」

> 経緯: 2026-11-15 にオーナーが「ソーシャルスキルをボードゲームを通して遊びながら覚えることができるゲーム」を依頼。案を出して、`drafts/tanonde-todokete/`（「たのんで、とどけて」。1台の画面＋コンピューター3人）で試作した（PR #264。試作のフォルダは、本体にしたあと 2026-11-15 に消した。中身は git の履歴に残っている）。そのあと、オーナーの実機の感想で次のように作り直した: 笑い・時間制限・ポイント制を足す → 絵と動き → 「自分の荷物と届ける荷物がまぎれる」→ 配達の形から**商店街の形**（番の人がお客さん、ほかの人がお店の人。お客さんの番は自分のお店を出さない）→「店員さんが複数いるのがわかりづらい」→ **1人1つのお店** → ボタンの言葉（「お客さんに質問する」「出さない」）→ チームの星をなくして**個人のポイント**に → 12人まで遊べるように品物を60種類に・お店の人が決める時間・合う物を出したお店にも1ポイント。同日、オーナーが本体にすると決め、名前「あれください商店」と DB ルールへの名前空間の追加を承認した（PR #281）。
> 同日、本体を遊んだオーナーから「名前とモノが一致しているものは当てるのが簡単」「2つ以上箱が届いた場合、当てるのに運要素が強すぎる」→ 案を出し、オーナーが「おもしろ要素を足して絵を見て考える」「お店の人がひとことをそえる」を選んだ。品物の名前から特徴の言葉を外して性格のおもしろい言葉に（光るおにぎり→はずかしがりのおにぎり）・お店の札からヒントの印を消す（絵を見て考える）・品物を出すときに箱へ「ひとこと」をそえる・結果の札で特徴3つの答え合わせ・決める時間を30秒に。
> 同日、遊んだ人から「ポイントをもらえるならとりあえず出しておいたほうが得」→ オーナーの選んだ形で、正しく断れたら1・ちがう物がえらばれたら出したお店は1減る、にした。そのあと試算すると、12人では「いつも断る」が「考えて出す」とほぼ同じ点になった（品物が4こなので合う物を持っている番が少なく、点の大半が断った分）。オーナーの「面白くなるようにおまかせ」で、ぴったりを3に・断った分はぴったりが届いた番だけ・品物を出さなかった人の「おすすめ」を足した（12人でも、断った人が毎回、箱のひとことを読んで考えられるように）。
> 同日、オーナー「ひとことは箱が届いたあとに、おいしいよやあつあつだよなどと選べるように」「商品を出したかわかりづらい」「商品を説明する時間がかかりすぎる人がいる。商品を出すまでの時間を設定できるように」→ ひとことを箱が届いたあとのお店の言い方に・「この品物を出す」で決めて出したことを大きく出す・決める時間をホストがえらぶ（15〜60秒）。
> 同日、オーナー「ほしいものを決める時間も選択できるようにしてほしい」→ お客さんがヒントを決める時間をホストがえらぶ（なし・20〜60秒。はじめは、なしで、これまでと同じ）。時間が来たら、えらんだヒントで送る。
> 同日、オーナー「箱に添える一言は不要」→ 箱のひとこと（`r/w`）を外した。箱には出したお店の名前とおすすめの数だけを出す。出したことは「箱に入れて出したよ」で引き続き大きく出す。「閉じるボタンは不要で自動的に進む」→ 結果の札の「とじる」を外した（6秒で自動で閉じる）。
> 同日（11-16）、オーナー「箱を出した後にコメントを選択して送信できるようにしてほしい」→ 案を出し、オーナーが「接客のひとこと」「その箱の下に出す」を選んだ。箱を出したお店の人が、6つの決まった言葉（どうぞ！・これだと思う！・たぶん、これかな・ちょっと自信ないけど…・ちがったらごめんね・おすすめです）から1つえらんで「送る」。品物の特徴は言わない（前のひとことは特徴の言い方で、答えの手がかりになっていた）。お客さんが箱をえらぶまで送りなおせる（`r/m/{席}`）。

## セッション条件（ツール一覧のカードと同じ）

スタッフがツールを選ぶときの条件。値はツール一覧（`apps/index.html`）のカードの札・`data-scenes`・`data-speech`・`data-self` と同じにする。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 2〜12人 |
| 目安時間 | 5〜15分 |
| 利用シーン | ボドゲクラブ・ひろば・サークルタイム・作戦会議 |
| 話す量 | 選ぶだけ・話さなくてよい（ヒント・質問・出す・出さないは、すべて画面のボタンで進む） |
| 自分の話 | 外の題材で遊べる |

## ルール

| 項目 | 内容 |
|---|---|
| お店 | 遊ぶ人が1つずつ。はじめに品物を4こずつ配る（60種類から。のこりは補充の山） |
| ほしい物 | 1人に1つ、ほかの人のお店にある品物から決める（同じ品物を2人がほしがらない）。本人の画面にだけ出す |
| お客さん | 番の人。ヒントを2つ（1つでもよい）えらんで「これください！」。ヒントを決める時間は、ホストが待合室でえらぶ（なし・20・30・45・60秒。はじめは、なし）。時間が来たら、お客さんの端末が、えらんだヒントで送る（1つもえらんでいなければ、ほしい物の特徴3つから1つ。番を飛ばしたり減点したりしない）。前の結果の札を出している間（6秒）は数えない。お店の人が決めたら、出てきた箱から1つ受け取る。どのお店も出さなかったら「べつの物にする」 |
| お店の人 | ほかの人。決める時間は、ホストが待合室でえらぶ（15・20・30・45・60秒。はじめは30秒。お客さんがヒントを送ってから）。「品物を出す」（下の「あなたのお店」の札を押し、「この品物を出す」で決める。出したら「箱に入れて出したよ」と大きく出し、札に「出した」の印）・「お客さんに質問する」（ヒントの言葉を1つえらぶと、はい・いいえが出る。1人のお客さんに2回まで）・「出さない」。時間が来たら、まだ決めていないお店は出さなかったことになる。みんな決めたら、時間を待たずに次へ |
| 箱 | お客さんの画面に、出したお店の名前と、おすすめの数と、お店の人が送ったコメントが出る。中は開けるまでわからない。開くと、出てきた物（ちがう物なら、ほしかった物も）の特徴3つが出る（答え合わせ） |
| ポイント | ぴったり: お客さんと出したお店の人に **3** ずつ。ちがう物: お客さんに1・出したお店は **1減る**（0より下にはしない）。えらばれなかったけれど、ヒントに全部合う物を出したお店: 1（品物はお店に残る）。**ぴったりが届いた番だけ**: ヒントに全部合う物が自分のお店になくて「出さない」をえらんだお店に1（正しく断れた。時間切れで決めなかったお店は0）・ぴったりの箱をおすすめした人に1 |
| おすすめ | 品物を出さなかったお店の人（出さない・時間切れ）は、お客さんが箱をえらぶ間に、ぴったりだと思う箱を1つおすすめできる（変えられる）。お客さん・みんなにみせる画面には、箱ごとのおすすめの数が出る（だれがすすめたかは出さない）。えらぶのはお客さん |
| 次の番 | 出した品物はお客さんの物になり、出したお店は山から1こ補充する。ほしい物は入れかえて、次のお客さんへ（注文のある人の中で、いまいる人を先に） |
| おわり | あそぶ時間（5分・10分・15分・なし。はじめは10分）が0になる・品物がなくなる・ホストの「ここで終わる」 |
| おわりの画面 | 自分のポイントと、1人ずつちがう名前（「名ヒント」「たすけ名人」「びっくり名人」「よく聞く名人」「しつもん名人」「つたえ名人」「みきわめ名人」と、予備8つ。12人まで重ならない）。順位は出さない |

- ルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/arekudasai-shoten/engine.test.cjs`（2〜12人を60回ずつ通して、必ず終わる・品物が重ならない・ポイントの足し算・ルームに置いて読みなおしても同じ・称号が重ならない）
- **品物**: 60種類（試作の24種類＋2026-11-15 に足した36種類）。ヒントは13の言葉から3つずつで、どの2つの品物も3つの組が同じにならない。ヒント2つに当てはまる品物は平均2.9こ・多くて5こ（わざとまぎれるようにしてある）。品物の名前・ヒントを足す・変えるときはオーナーが決める
- **特徴は絵で見る**: 品物の名前に特徴の言葉を入れない（頭は性格を表すおもしろい言葉＋もとの物の名前。例: ねぼすけこたつ・ものしりな冷蔵庫）。お店の札・お客さんのほしい物には、特徴の言葉（ヒントの印）を出さない。絵の飾りで見る: 羽＝とぶ・きらきら＝光る・湯気＝あたたかい・音符＝音が出る・雪の結晶＝つめたい・はねた跡＝はねる・もこもこ＝ふわふわ。大きい・小さい・まるい・ながい・かたい・あまいは形から考える（わかりにくいので、質問とひとことが生きる）。答え・ポイントは、データの特徴3つで決める
- **とりあえず出すほうが得にならないように**（2026-11-15 オーナー。遊んだ人から「ポイントをもらえるならとりあえず出しておいたほうが得」）: 正しく断れたら1・ちがう物がえらばれたら出したお店は1減る。減ったことは、その人の画面にだけ出す（「ちがう物がえらばれたので、あなたは -1ポイント」）。ほかの人の画面・みんなにみせる画面には、だれが減ったかを出さない（ルートの AGENTS.md「否定的な判定を、出した人・出された人と結びつけて目立たせない」）。正しく断れたお店は、みんなの画面に名前を出す
- **ポイントの配慮**（オーナー「ポイントの少ない人が嫌な気持ちにならないように」）: お客さんはちがう物でもポイントが入る・0より下にしない・順位を出さない・自分のポイントだけを出す（「みんなのポイントを見せる」は待合室の設定で、はじめはオフ）・おわりは1人ずつちがう名前。「あなたのこれまでの一番」は、その画面を開いている間だけ覚えている（どこにも残さない）
- **出さない**の言葉は「うちにはないです、ごめんね」。断ることを悪いこととして出さない（合う物が本当になければ1ポイント）

## 画面で気をつけたこと

- **役割をはっきりさせる**（オーナーの実機の感想から3回作り直した）: まんなかの一番上に「今のあなた：お客さん／お店の人」（茶オレンジ／青みどり）。上の商店街の一覧は「○○のお店」が人数分ならび、お客さんだけ「お客さん・お店はお休み」。**お客さんの番は「あなたのお店」を出さない**（ほしい物と持っている物が同じ画面にならないように）
- お店の人のできることは、3つの枠に「いつ使うか」と「言う言葉」をそえて並べる（ボタンの名前だけでは伝わらなかった）
- **運まかせにしない**: 合う箱がいくつも来たときに運だけで決まらないよう、出さなかったお店の「おすすめ」と、ちがう物を出すと1ポイント減る・正しく断ると1ポイントを置いている。以前は箱に出したお店の人の「ひとこと」（お店の言い方。「あつあつだよ」など）をそえていたが、2026-11-15 にオーナーが「不要」として外した（PR #291 の形。データの `r/w` も使わない）
- お客さんのほしい物は、結果の札が出るまで、ほかの人・みんなにみせる画面に出さない（本人の画面にだけ。データはルームにある。性善説）
- 質問と答えは、みんなの画面に出る（「みどりのお店『それは、まるい？』→ あおい『はい』」）
- 結果の札は6秒出して、自動で閉じる（閉じるボタンは置かない。2026-11-15 オーナー「閉じるボタンは不要で自動的に進む」）。箱がゆれてから開く（0.9秒）。お客さんがヒントを決める時間は、札を閉じてから数える
- 動くのは、ほしい物・結果の大きな絵だけ（とぶ・はねる・光る・湯気・音符）。端末の「動きを減らす」設定では止め、箱もすぐ開く
- 音は鳴らさない
- 7人からは、商店街の一覧の顔を小さくする。スマホ幅では一覧を3列に

## 声・端末について

- **マイクを使わない子**: ヒント・質問・出す・出さないが、すべてボタンで進むので、声を出さなくても全部の役ができる。箱を出した人は、決まった言葉の「コメント」をボタンで送れる（ui.md の「ひとこと」と同じ考え方。名前は画面に合わせてコメント）
- **端末なしの参加者は作らない**（rtdb.md「端末のない参加者」の「作らないゲーム」）。12人のとき、お店の人はみんな同時に決める時間の中で決めるので、ホストが何人分ものお店を代わりに決めきれない。また、ホストが代わりに押すと、その子のほしい物（秘密）がホストに見える。端末のない子は、メンターの画面共有（みんなにみせる画面）を見て、声やチャットで加わる形にする

## 画面構成・フロー

```
TOP（screen-top）
 ├── 「ルームを作る」 → 名前（screen-create） → 待合室
 ├── 「ルームに参加する」 → 名前＋ルームコード（screen-join） → 待合室（対決の途中なら、見る番で対決の画面）
 ├── 参加用のリンク `?room=CODE` → 参加画面（コード入力済み）
 └── 「みんなにみせる画面をひらく」 → ルームコード（screen-watch-join） → 見るだけの画面
待合室（screen-waiting）: 遊ぶ人（参加した順にお店の色）・ホストは「ホストも遊ぶ」・あそぶ時間・みんなのポイントを見せる・「はじめる」
  ↓「はじめる」（遊ぶ人が2人以上）
対決（screen-game）: のこり時間・自分のポイント／商店街の一覧／まんなか（場面ごと）／あなたのお店／ホストの「そのほかの操作」
  ↓ 時間が0・品物がなくなる・ここで終わる
おわり（同じ画面のまんなか）: ホストに「もう一回」「待合室へ」。参加者には「ホストが、もう一回あそぶかを決めるよ」
```

- まんなかの場面: `ask`（お客さんがヒントをえらぶ）→ `offer`（お店の人が決める。ホストがえらんだ秒数）→ `pick`（お客さんが箱をえらぶ）→ 結果の札 → 次のお客さんの `ask`。場面はルームの値と時刻から各端末が決める（場面のための書き込みはしない）
- ルームバー: ルームコード・「コードをコピー」・「リンクをコピー」・「QRコードを出す」・「みんなにみせる画面」（ホストだけ）・「退出する」（ホストは「ルームを閉じる」）
- ボタン階層: 塗りつぶしの主ボタンは各画面1つ（トップ「ルームを作る」、待合室「はじめる」、お客さん「これください！」、おわり「もう一回」）
- ホストの「そのほかの操作」: 「この番を飛ばす（次のお客さんにする）」「ここで終わる」「待合室へ」。お客さんの通信が切れているときは、まんなかにも「この番を飛ばす」を出す
- **遊ぶ人**: ルームに参加している人みんな。ホストは「ホストも遊ぶ」（はじめはオン。ホストの画面に出る秘密は、自分のほしい物だけなので）を外すと進行だけ。12人まで（13人目は「このルームはいっぱいだよ」で、みんなにみせる画面を案内する）
- **途中から入った人**は、その回は見る番。「もう一回」で、いま参加している人で遊ぶ人を決めなおすので、そこから入る。いなくなった人は外れる
- **通信が切れた人・退出した人**: お店は残る（品物も）。その人がお客さんの番は、ホストが飛ばす。その人のお店は「通信が切れた」と出て、決める人の数に入れない。ほしい物を新しく決めるときは、いない人のお店の品物を選ばない

## status 遷移

```
waiting ─はじめる→ play（game と play/{id} を作る）
play ─もう一回（ホスト）→ play（新しい game。id が1増える）
play ─待合室へ（ホスト）→ waiting
どこからでも ─ルームを閉じる（ホスト）→ 削除
```

おわり（時間が0・品物がなくなる・ここで終わる）は status を変えない。各端末が `game.startAt`・`game.limit`・`game.endAt`・`play/{id}/over` から決める。

## Firebase データ構造（Realtime Database）

```
arekudasaishoten_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid:     ホストの名前と匿名ID
  ├── hostConnected / hostDisconnectedAt / createdAt
  ├── lastGameId:         number
  ├── set:                { hostPlays, time: 5|10|15|0, showAll, offer: 15|20|30|45|60, ask: 0|20|30|45|60 }
  ├── players/{name}:     { isHost, uid, joinedAt }   # 在室。ゲストは切断で消え、戻ると同じ joinedAt で戻る
  ├── game/                          # 「はじめる」で作り、待合室にもどると消す
  │    ├── id, seats: [名前, …], uids: [匿名ID, …]
  │    ├── limit（分。0 はなし）, showAll, offer（お店の人が決める秒数）, ask（お客さんがヒントを決める秒数。0 はなし）, startAt
  │    └── endAt                     # ホストの「ここで終わる」
  └── play/{game.id}/                # その回の動く部分（engine.js の toRoom / fromRoom）
       ├── h: ["id,id,…", …]         # 席ごとのお店の品物
       ├── o: ["id" または "-", …]   # 席ごとのほしい物
       ├── pt: [数, …]               # 席ごとのポイント
       ├── st: ["hit.give.odd.ask.fit.no.vote", …]   # 席ごとの数（おわりの名前に使う。画面には出さない）
       ├── deck: "id,id,…"           # 補充の山
       ├── turn, hits, odds, over
       ├── r/                        # いまの番
       │    ├── n                    # 番の番号（1から）
       │    ├── h: "ヒント,ヒント"    # お客さんが送ったヒント（送るまでない）
       │    ├── s                    # お客さんがヒントをえらびはじめる時刻（番を決めた端末の時刻＋結果の札の6秒。はじめの番は対決を作った時刻。ヒントを決める時間はここから game.ask 秒）
       │    ├── at                   # ヒントを送った時刻（サーバーの時刻。決める時間はここから game.offer 秒）
       │    ├── d/{席}: "id" | "-"   # お店の人が出した品物・出さない
       │    ├── q/{席}: "ヒント:1,ヒント:0"   # お店の人の質問と答え（1 は、はい）
       │    ├── v/{席}: 箱のお店の席        # 品物を出さなかったお店の人のおすすめ
       │    └── m/{席}: 0〜5                # 箱を出したお店の人のコメント（COMMENTS の番号）
       └── last/                     # 前の番の結果（結果の札に使う）
            └── n, c, none, skip, w（ほしかった物）, h, v（ひとこと）, hit, g（出てきた物）, f（出したお店）, fit: "席,席", no: "席,席"（正しく断れたお店）, vt: "席,席"（ぴったりの箱をおすすめした人）, dl: "席:数,…"（席ごとの増減。減った数は本人の画面にだけ出す）
```

- こわれた値・ルールと合わない値は、その所だけはじめの値で読む。出した品物は、いまもそのお店にある物だけ読む。`game` がこわれているときは `gameOf` が null を返し、待合室の画面になる（ホストは「はじめる」で作りなおせる）

## 書き込みの設計

| 操作 | 実行者 | 書き方 | 検証 → 書き込み |
|---|---|---|---|
| 作成 | ホスト | ルームへ transaction | 空のコード → 初期ルーム（`transactRetry`。送信後の切断のやり直しで、自分が作ったルームならそのまま使う） |
| 参加 | ゲスト | `players/{名前}` へ transaction | 先に読んだ値で、名前が空いている・対決の途中の名前は同じ匿名IDの人だけ・遊ぶ人が12人未満（自分のお店がある人が戻るときは見ない）→ 自分の在室だけを書く。書いたあと、ルームが閉じられていたら在室を消してやめる |
| 在室を戻す（再接続） | ゲスト | `players/{名前}` へ transaction | 参加と同じ確かめ → 在室がなければ書く |
| 在室を戻す（再接続） | ホスト | `update` | 手元の値で、自分がホスト・期限切れでない → `hostConnected`・`hostDisconnectedAt`。切れていた分だけ `game/startAt` と `play/{id}/r/at`（ヒントを送る前は `r/s`）をずらす |
| 設定・ホストも遊ぶ | ホスト | ルームへ transaction | `waiting`（遊ぶ人は12人まで） |
| はじめる | ホスト | ルームへ transaction | `waiting`・遊ぶ人が2〜12人 → `game` と `play/{id}` を作る |
| もう一回 | ホスト | `update` | 手元の値で、自分がホスト・`play`・遊ぶ人が2人以上 → `game`・`play`（新しい番号だけ）・`lastGameId` |
| 待合室へ | ホスト | `update` | `status: waiting`・`game` と `play` を消す |
| ここで終わる | ホスト | `game/endAt` へ `set` | サーバーの時刻 |
| ヒントを送る | お客さん | `play/{id}/r` へ `update` | 手元で、自分がお客さん・まだ送っていない → `h`・`at`（サーバーの時刻）。ヒントを決める時間が来たときも、お客さんの端末が同じ形で送る |
| 出す・出さない | お店の人 | `play/{id}/r/d/{席}` へ `set`（`id` か `-`） | 手元で、`offer` の場面・まだ決めていない・その品物が自分のお店にある |
| おすすめ | 品物を出さなかったお店の人 | `play/{id}/r/v/{席}` へ `set` | 手元で、`pick` の場面・自分は出していない・すすめる箱が出されている → その箱のお店の席 |
| コメント | 箱を出したお店の人 | `play/{id}/r/m/{席}` へ `set` | 手元で、`offer` か `pick` の場面・自分が品物を出している・番号が 0〜5・いまと同じでない |
| 質問 | お店の人 | `play/{id}/r/q/{席}` へ `set` | 手元で、`offer` の場面・まだ決めていない・2回まで → 答えは手元で `E.answer` から決めて、いっしょに書く |
| **番を決める** | お客さん（「この番を飛ばす」はホスト） | `play/{id}` へ **transaction** | `r/n` がいまの番と同じとき（もう決まっていたら書かない）→ 届いている `r/d`・`r/q` から `E.resolve` → 品物・ポイント・ほしい物・次のお客さん・`r: { n: n+1 }`・`last` をまとめて書く |
| 退出 | ゲスト | `players/{名前}` へ transaction | 自分の匿名IDの在室なら消す（お店は残る） |

- **あそんでいる間の書き込みは、ルーム全体の transaction を使わない**。お店の人の決めたこと・質問は、それぞれ自分の席の場所へ。番を決めるのは1回の番に1回だけで、`play/{id}` の transaction（ほかのお店の遅れた書き込みと重なっても、やりなおしで通る）
- **同じ番を2回決めない**: お客さんの「箱をえらぶ」とホストの「この番を飛ばす」が重なっても、`r/n` を見るので先の1回だけが通る
- 決める時間が過ぎたあとに届いた「出す」は、お客さんが箱をえらぶ前なら箱に入る（害はない）。番を決めたあとに届いた分は、`r` が新しくなっているので使われない
- 書き込みの権限は端末の側で確かめる（性善説。ルートの AGENTS.md「セキュリティ方針」）

## 接続・切断・再接続

そろってゴールと同じ作り。

| 役割 | onDisconnect 予約 |
|---|---|
| ホスト | ルームに `update({ hostConnected: false, hostDisconnectedAt: TIMESTAMP })` |
| ゲスト | `players/{name}` を `remove()` |

- `.info/connected` が true になるたびに切断予約を張り直し、在室を書き戻す（3秒に1回まで）
- ホストが切れている間は、参加者の画面は共通のオーバーレイ「ホストの戻りを待っています」で押せない（何も書かない）。時計も止まる。`ORPHAN_TTL_MS = 2 * 60 * 1000`
- 対決の途中の名前は、ほかの人（別の匿名ID）は使えない

## 終了とデータ削除

- 公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用する。おわりの画面でも自動削除しない（もう一回へ続けて遊ぶため）
- 削除経路: ①ホストの「ルームを閉じる」（`cancelRoomOnDisconnect()` を await → `remove()`） ②ホスト切断＋2分 TTL ③次回アクセス時（参加・再接続・ルーム監視）の期限切れ掃除（status の無いゴーストも対象、`applyLocally: false`）

## みんなにみせる画面（画面共有用・見るだけ）

- **入口**: ①ルームバーの「みんなにみせる画面」（ホストだけ）②トップの「みんなにみせる画面をひらく」③アドレスの `?watch=CODE`
- **ルームへの書き込みゼロ**: `state.role === 'spectator'`。players に入らない・切断予約をしない・期限切れのルームも消さない
- お客さんのほしい物は出さない（結果の札で、はじめて出る）。ヒント・決めたお店の数・質問と答え・箱・結果を出す

## メンター向けのメモ（画面には出さない）

- はじめての回は、最初の1回だけ、お客さんの画面とお店の人の画面を画面共有で見せながら進めると、役割が伝わりやすい
- ちがう物が出てきたときは、だれのヒントが悪かったかを話題にせず、「それも使えそう」と出てきた物のほうを話題にする
- 「出さない」を選んだ子には、断れたことをそのまま受け止める（「ちゃんと伝えられたね」）。出さないのも大事な選び方
- 質問は、まよったときの手。質問した子には「たしかめてからにしたんだね」と、たずねたことを受け止める
- 12人のような大人数は、決める時間の間に同時に話すと聞き取れなくなりやすい。声よりも画面のボタンで進む遊びなので、話すのは結果の札が出たあとにすると進めやすい
- ポイントは、はじめは自分の分だけが出る。みんなの分を出すかは、その回の子どもたちの様子で決める
