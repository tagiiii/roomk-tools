# よさマップ

## 目的・使用シーン

自分を知るワーク向けのルーム型ツール。「やさしい」「行動力がある」などの**よさ**（1段め）を選び、そのよさが出る**具体的な場面**（2段め）を選ぶと、名前を真ん中にしたマップが広がる。選ぶだけで作れる。点数・順位・勝ち負け・投票はない。

マップの作り方は2つ（待合室でホストが選ぶ）:

- **それぞれ自分のマップを作って、見せあう**（`own`）: 各自の端末で作り、ホストが1人ずつ大きく出す。「きいてみよう」の質問をきっかけに話す
- **みんなで1人のマップを作る**（`one`）: 1人のマップをみんなの画面に出して、いっしょに足す。本人が選んだ札と、ほかの人から見えた札がまざる。メンターと子どもの2人で使うときもこちら

2026-11-12 にオーナーの依頼（「自分の強みやよさを深掘りできるツール。好きなものマップみたいに、メンターと同時操作をしながら選択式で」）で `drafts/yosa-map/`（BroadcastChannel の試作）を作り、同日「本体化してください」で本体化した。試作の経緯はこの AGENTS.md を正本にする（drafts はリポジトリに入れていない）。

### 作戦会議（1対1）での使い方

- **2人ともルームに入る**: メンターがルームをつくり、子どもがリンクで入る。「みんなで1人のマップを作る」で子どもを選ぶ。子どもは自分の札を足し、メンターは「見えた場面」を点線の札で足す
- **メンターの画面共有だけで使う**: 「くわしい設定」の「端末なしの参加者を足す」で子どもの名前を足し、「みんなで1人のマップを作る」でその名前を選ぶ。メンターが声で聞きながら代わりに押す（ポップアップの「だれが見つけたものとして足す？」は「〇〇さんが選んだ」がはじめの値）

## 技術スタック

Firebase Realtime Database + 匿名認証。分割ファイル（`index.html`・`app.js`（module）・`style.css`・`data.js`）。作成・参加・再接続・切断・退出・ルームのバー・マップの図（`drawMap`）・ポップアップは `apps/suki-mono-map/` をもとにした。`RoomkRTDB.initFirebase()`・`RoomkRTDB.now()`・`copyRoomCode` / `copyRoomLink`・`RoomkQR`・howto・stats を使う。名前空間は `yosamap_rooms`。

## 画面構成・status 遷移

`waiting`（待合室）→ `pick`（作る）→ `show`（見せあう・ながめる）。

- `own`: `pick` → ホストの「見せあいをはじめる」で `show`（`show.order` に参加した順。出さないと決めた人・何も選んでいない人は入らない）→「もう一度作る時間にする」で `pick`（`seq` を1つ進め、`done` だけ外す）／「おしまいにして待合室へ」で `waiting`
- `one`: `pick`（`focus` の人のマップ）→ 本人かホストの「マップを完成する」で `show`（`show.order` はその人だけ）→ ホストの「つぎは、だれのマップを作る？」で `pick`（`focus` を変え、`seq` を1つ進める。前の人のマップは残り、ボタンに「（つづき）」と出る）／「もう一度作る時間にする」で同じ人の `pick`／「おしまいにして待合室へ」で `waiting`
- はじめの画面は入口の型 `.app-entry`。作成・参加・ルームのバーは rtdb.md の共通どおり
- 待合室: 参加する人・「マップの作り方」・（`one` のとき）「だれのマップを作る？」・「くわしい設定」（自分も作る〈`own` のときだけ〉・端末なしの参加者を足す）・「はじめる」。参加する人の画面には「きょうのあそびかた」の要約

### 作る画面

マップだけの画面（好きなものマップと同じ形。オーナーが好きなものマップで3回作り直して決めた形）。

- 真ん中の名前から出ている「＋ よさを足す」を押すと、ポップアップによさの一覧（14こ）。選ぶとマップに足され、ポップアップはそのままそのよさの場面に変わる
- よさごとの丸い「＋」（よさそのものを押しても同じ）で、場面を選ぶポップアップ。札はもう一度押すと外れる。「自分で書く」は1つのよさに3つまで・16文字
- マップの札（× つき）を押すと消える。よさごと消すのはポップアップの下の「『やさしい』をマップから消す」（場面があるときだけ確かめる）
- スマホの幅（マップの場所が 520px 未満）では、上から下へ枝をのばす形で描く。1行に入らない長い札は、入る大きさまで文字を小さくする（12px まで）

### みんなで1人のマップ（だれが何をできるか）

| だれが | できること |
|---|---|
| 本人 | よさ・場面を足す・消す。点線の札（ほかの人から見えた場面）を押して「もらう／このまま置いておく」を選ぶ。「自分で書く」。「マップを完成する」 |
| ほかの人 | よさを足す。場面に「見えた」の印を付ける（点線＋目の印の札で出る）。自分が付けた印を外す（マップの札の ×・ポップアップでもう一度押す）。本人の札は消せない。「自分で書く」・よさを消す・完成はできない |
| ホスト | 本人が入っているときは、ほかの人と同じ。ポップアップの「だれが見つけたものとして足す？」で「〇〇さんが選んだ」に切りかえると、本人の代わりに足せる。本人が端末で入っていないとき（端末なしの参加者・はなれた人）は、こちらがはじめの値で、マップの上でも本人として動かせる（点線の札を押すと「もらう／置いておく／この札を消す」）。よさを消す・「自分で書く」・完成もできる |

- 同じ場面に何人も印を付けられる。札を押すと「みおさん・ホストさんから見えた『やさしい』」と出る
- もらった札は実線（アクセント色のふち）になり、目の印は残る。「置いておく」は何も変えずに閉じる（ことわった形にしない）
- マップの上の動き（札を消す・もらう）は「本人がいるかどうか」だけで決める。足し方の切りかえ（ホスト）は、ポップアップの中だけに効く（試作で、切りかえるとマップの上でも見ている人の動きになり、点線の札をもらえなくなったため）

### 比べっこを出さない

選んだ数・印の数・「同じよさを選んだ人」・「ない」の一覧・タイプ分け・点数は出さない。見せあいに出すかは各自が選べる（`own`）。この理由は画面・あそびかた・更新情報に書かない。

## Firebase データ構造

```
yosamap_rooms/{code}
  status: 'waiting' | 'pick' | 'show'
  host, hostUid, hostConnected, hostDisconnectedAt
  settings: { hostPlays, mode: 'own' | 'one', focus: 待合室で選んでいる人（one） }
  round: はじめた回数, seq: その回で「作る」にもどった回数
  focus: いま作っているマップの人（one。はじめたとき・つぎの人で決まる）
  shown: その回で見せあい・ながめる画面まで進んだか（finish を二重に数えないため）
  players: { 名前: { isHost, uid, joinedAt } }
  proxies: { 名前: { addedAt } }                 … 端末なしの参加者
  maps: { 名前: { r: 回, yosa: [よさのid], items: { よさのid: [ { t: 場面, self: 本人が選んだ・もらった, from: [見えたと付けた人の名前] } ] }, done, share } }
  show: { order: [名前], idx, ask: 質問の文 }
```

- ホストの操作（設定・端末なしの参加者・はじめる・見せあい・つぎの人・質問・作るへもどす・待合室へ）は、どれも `hostUid` を確かめるルームの transaction
- **マップの書きかえは、押した人が1つの操作ごとにルームの transaction で書く**（`editMap`。status・回・`seq`・自分の在室の uid と、書けるマップかを確かめる）。好きなものマップとちがい、作りかけを端末に持たない。みんなで1人のマップは何人もが同じマップを書くため。transaction はその端末の画面にすぐ出るので、押した反応は待たない
- そのため、**通信が切れているあいだに押したものは届かない**（「通信が切れたみたい。つながったら、もう一度押してね」と出す）。好きなものマップの「つながりなおしたら送りなおす」は無い
- RTDB は空の配列を持てないので、場面を選んでいないよさの `items`・印のない札の `from` は無い。読むときは `cleanMap` で空として読む
- ほかの人のマップ・だれが印を付けたかは、参加する人の端末にも届く（性善説）

## ホストも作るか・途中参加・端末なしの参加者

- **ホストも作る（`settings.hostPlays`）: 初期値は「作る」**（`own` のときだけ効く）。秘密の情報がないので、ホストも同じ条件で作れる。進行だけのときは待合室で「進行役」の印、マップを持たない
- `own` は、作る人が1人いれば始められる。`one` は、マップを作る人（ホストでない最初の人がはじめの値）が決まっていれば始められる
- **途中参加**: どの status でも参加できる。作っている途中で入った人はそのまま作れる（`one` では印を付けられる）
- **端末なしの参加者**: ホストが待合室の「くわしい設定」で名前を足す（4人まで）。`own` では、作る画面の上の「だれの分を作る？」で切りかえて、ホストが代わりに作る。`one` では「だれのマップを作る？」に出て、ホストが本人の代わりに押す
- 読み込み直した人・通信が切れてもどった人は、参加した順がいちばん後ろになる（在室を足しなおすため。見せあいの順番・`one` のはじめの人が変わることがある）

## メンター向けの心得（画面には出さない）

- 「きいてみよう」は話のきっかけ。答えたくなさそうなら「ほかの質問にする」か次へ進める。理由を聞きこまない
- マップの大きさ（選んだ数・付いた印の数）を比べる声かけをしない
- **「みんなで1人のマップ」を順番に回すと、札がたくさん集まる子と少ない子の差がマップの大きさで見える**。全員分を回すなら、ホストが先に「わたしから見えた」札を足しておく・1回に回す人数をしぼる、などを考える
- 点線の札を本人が「置いておく」にしても、理由をたずねない。付けた子にも、ことわられたのではないと伝わる声かけをする
- 見せあいに出さなかった子に、その場で理由をたずねない

## 切断時の挙動・削除

好きなものマップと同じ（コードも同じ形）。

- ホスト切断: `hostConnected=false`・`hostDisconnectedAt`。ゲストには「ホストの戻りを待っています」を出し（ひらいていたポップアップは閉じる）、TTL（`ORPHAN_TTL_MS` = 2分）を過ぎたら期限切れとして消す
- 期限のタイマー（参加する人の画面）: はじめに見た切れた時刻の2分後に動く。そのときまだ期限前なら、残りの時間で仕掛けなおす（`armOrphanTimer`。2026-11-12）。切れたままのあいだに切れた時刻だけが新しくなると（ホストの通信が短く揺れたとき）、前は消す処理が「まだ期限前」で何もせず、待つ画面のまま残った。同じ「1回だけ仕掛ける」作りはほかのルーム型にもある（直していない）
- ゲスト切断: `players/{名前}` の `onDisconnect().remove()`。戻ったときは同じ名前で在室を足し直す（マップは名前で持っているのでそのまま続く）。`one` でマップの本人が切れているあいだは、ホストが本人の代わりに押せる
- 再接続: sessionStorage（`yosamap_session`）で同じルームに戻る
- 通信だけが切れているあいだに押したとき（タブは開いたまま。2026-11-12 に E2E で確かめた）:
  - **参加する人**: 押しても札は出ず、「通信が切れたみたい。つながったら、もう一度押してね」と出る（2026-11-12 オーナー判断。それまでは何も出なかった）。つながりなおしても届かない。SDK は、切れた時点で「切断したら在室を消す」の予約を手元の写しにも当てる。`editMap` は在室のない人の書きかえを通さない（`cur.players?.[nick]?.uid !== uid`）ので、そこで止まったときにメッセージを出す（`editMap` と `finishOne`）。つながりなおすと在室がもどり、また押せる。好きなものマップ（作りかけを端末に持ち、もどったら送りなおす）とちがう所
  - メッセージは、ひらいているポップアップがあればその中へ移して出す（`app.js` の `toast`）。共通の `showToast` は body の末尾に出すので、スマホの幅で画面の下まで広がるポップアップ（`showModal`）に隠れていた（2026-11-12 に本番の 375px で見つけた）。出ている3秒ほどは「マップにもどる」に重なる（スマホの幅）。ポップアップの出るときの動きは `backwards`（`both` だと動きのあとも位置の基準がポップアップになり、PC の幅でメッセージがポップアップの中の下端に出ていた。同日に直した）
  - **ホスト**: 押したものはすぐ画面に出て、つながりなおしたときにルームへ届く（ホストの在室は切断で消さない）。完成・「見せあいをはじめる」も同じで、ホストの画面だけ先に進み、もどったときにみんなへ届く
- **自動削除は rtdb.md「公認バリアント: ふりかえり画面滞在中は削除しない」を採用**: 見せあいのあとも続けて作る・待合室へもどることが多いので、終了30秒後の自動削除はしない。(1) ホストの「ルームを閉じる」 (2) ホスト切断の TTL (3) 次回アクセス時の期限切れ掃除 の3経路で消す

## 利用回数

「1回」は、待合室で「はじめる」を押してから、はじめて見せあい・ながめる画面に進むまで。

| 項目 | 数えるとき |
|---|---|
| `room-create` | ルームができた |
| `start`・`players-{N}`・`mode-own` / `mode-one` | ホストの「はじめる」が確定した（N は `own` では作る人の人数、`one` では参加している人の人数。どちらも端末なしの参加者を含む） |
| `finish` | その回ではじめて、見せあい（`own`）・ながめる画面（`one`。完成を押した人の端末で数える）に進んだ |
| `again` | 「おしまいにして待合室へ」が確定した |

## 特有のルール・制約

- 中身は `data.js`（よさ14こ・各6〜8この場面、質問6つ）。よさは短い言葉で書き、「あなたは〜だ」と決めつけない（画面の問いかけ「どんなよさがありそう？」「『やさしい』が出るのは、どんなとき？」に本人が選んで答える）。学校・勉強・人との比べっこ・家族・恋愛・こわい話につながる言葉は入れない
- 同じ場面が別のよさに入っているのは意図どおり（「絵をかくとき」が想像力・手先が器用 など。`scripts/content-audit.mjs` の `CROSS_VARIANT_EXPECTED_TOOLS`）。同じよさの中の重複と空の言葉は `node scripts/content-audit.mjs` が止める
- マップの枝・札の色はよさを見分けるための色（`data.js` の `color`・`pale`・`ink`）で、ボタンには使わない。選んだ印・主ボタン・ほかの人から見えた札は共通のアクセント色
- 理由を書かせる欄は置かない。選んだものは保存しない（待合室にもどる・ルームを閉じると消える）。記録は、ホストの「そのほかの操作」→「このマップをコピー」（チャット用の文・絵文字なし。見えた札には「（〇〇さんから）」）
- 子どもが自由に書ける欄（「自分で書く」）は、自分のマップにだけある。合わない言葉が入ったときは、ホストが次へ進める（1つだけ隠す操作はない）
- 配慮の理由は画面・あそびかた・更新情報に書かない。音は鳴らさない
- つよみカード（`apps/tsuyomi-card/`。1対1・1台・20枚に3択で答える）は別のツールとして残している。つよみカードでは 2026-08-06 にメンターの選択ターンをやめて口頭に一本化したが、このツールでは同時操作を生かすため、ほかの人から見えた札を画面に出している（本人が「もらう」かを選べる形にした）
- コードの中の `mp-node--genre`・`ym-genre`・`p-genres` は1段めの「よさ」を指す（好きなものマップのクラス名・id をそのまま使っている）
