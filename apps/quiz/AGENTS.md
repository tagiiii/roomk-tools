# クイズパック 仕様書

## 目的・使用シーン

雑学3択、連続2択、ことばクイズなどをパック単位で進めるクイズツール。遊び方は2つ。

- **ひとつの画面であそぶ**（従来）: メンターが画面共有し、参加者と相談しながら遊ぶ。オフラインで動く
- **ルームであそぶ**（2026-09-25 追加）: ホスト（メンター）の画面を共有しながら、参加者が各自の端末で答える参加型クイズ。早く正解するほど高得点。仕様は下の「ルームであそぶ」節

## 技術スタック

- `index.html` + `app.js` + `questions.js` + `style.css`（`app.js` と `style.css` は `?v=` 付きで読み込む）
- ひとつの画面であそぶ: オフライン（通信なし）
- ルームであそぶ: Realtime Database＋匿名認証（`rtdb-utils.js`）。Firebase は**ルームの画面を開いたとき、または再読み込みで戻るルームがあるときだけ**初期化する（ひとつの画面モードでは匿名ログインもしない）
- 共通デザインシステムと `shuffle` / `popIn` / `copyToClipboard` を使用
- ルームがあるため `scripts/lint.sh` の `RTDB_HTML_FILES` に登録し、viewport に `maximum-scale=1` を付けている

## 画面構成

```
ひとつの画面:  TOP（パック選択＋問題数・手ごたえ選択） → QUIZ（可変問数。各問題の前に「3・2・1」） → END（結果）
ルーム（ホスト）: TOP →「ルームを作る」→ 待機（パック・問題数・手ごたえ・制限時間・ホストの参加）→（3・2・1）問題 ⇄ 正解発表 → 結果発表 →（もう一度／パックをえらび直す）
ルーム（参加者）: TOP →「ルームに参加する」（名前 → ルームコード）→ 待機 →（3・2・1）問題 ⇄ 正解発表 → 結果発表
みんなにみせる画面: ?watch=CODE ／ TOP の「みんなにみせる画面をひらく」（ルームコード）／ ホストの「みんなにみせる画面をひらく」→ ルームの進み具合を読むだけで映す
```

TOP の「ルームであそぶ」カードはパック一覧より上に置く（参加者がスクロールせずに見つけられるように）。
ルームの待機画面では、TOP のパック選択（`#packPicker`）をそのまま移して使い、制限時間の行だけ表示する。ルームを出るとTOPへ戻す。

## 特有のルール

### 問題数・手ごたえの選択（現場の「問題が少ない／簡単すぎる」への対応）

TOP で **問題数（5問 / 10問 / ぜんぶ）** と **手ごたえ（ふつう / チャレンジ）** を選ぶ。

- 難易度配分（`app.js` の `TARGETS`）
  | | 5問 | 10問 |
  |---|---|---|
  | ふつう | d1:1 / d2:2 / d3:2 | d1:2 / d2:4 / d3:4 |
  | チャレンジ | d1:0 / d2:1 / d3:4 | d1:0 / d2:3 / d3:7 |
- 「ぜんぶ」＝在庫全部。ただしシャッフル系（`isShuffle`）は長すぎるので `SHUFFLE_ALL_CAP`（30問）でキャップし、ボタン表記も「30問」に変える。
- 配分に満たない層は補充（チャレンジ=d3→d2→d1、ふつう=d1→d2→d3）。
- **実質全問出る設定（例：10問パック×10問）では手ごたえを自動で「ふつう」に固定**（配分を変えられないため）。プレビュー行で理由を表示。

### 鮮度・進行

- 出題は**表示した時点**で `usedIds` に記録。**未出題を難易度配分より優先**して抜く（2パス：未出題→足りなければ既出）。「もう一度あそぶ」で重複を避ける。`usedIds` は TOP に戻る／別パック選択でリセット。
- QUIZ 画面の「ここで結果を見る」で途中終了できる。**スコアの分母は回答済み数**（未回答を不正解にしない）。最終問題では「結果を見る」と重なるため中断ボタンは隠す。

### 問題の前のカウントダウン（2026-09-28 追加）

現場の要望「次の問題へ行くときに3・2・1のようなカウントダウンがほしい」で追加。ひとつの画面・ルームの両方に入れている。

- 問題を出す前に3秒（`COUNTDOWN_SEC`）、「3」「2」「1」と数字を出してから問題を出す。「スタート」「もう一度あそぶ」で始まる最初の問題と、「次の問題へ」の両方。結果の画面へ進むとき（「結果を見る」「結果発表へ」「ここで結果を見る／結果発表へ」）には出さない
- 数字の上の一言は、最初の問題が「最初の問題」、最後の問題が「最後の問題」、それ以外は「次の問題」
- 数えている間は、問題文・選択肢・コピー・「次の問題へ」「ここで結果を見る」、ルームの残り時間・「回答 n / N人」・ホストの「締め切って正解を見る」を伏せる（先に問題が見えないように）。飛ばすボタンはない
- 数字が変わるたびに小さく弾ませる。`prefers-reduced-motion` のときは動かさない
- ひとつの画面の出題画面は上寄せにしている（カウントダウンと問題で高さが違っても、パック名・問題番号の位置が上下しないように。ルームの画面と同じ）
- ひとつの画面の問題文の読み上げは、画面に出さない読み上げ用の欄（`#quizAnnounce`、`aria-live`）で行う。問題の欄はカウントダウンの間伏せていて、伏せていた欄に文字が入っても読み上げられないことがあるため

### パック分類

- TOP は「手ごたえあり（`CHALLENGE_PACK_IDS`）／ふつうのパック／まぜこぜ」の3セクション。
- 「ぜんぶシャッフル」は全パックを混ぜて出題。

### 表現

- 問題・解説は学校、成績、恋愛、暴力、ホラーを避ける
- 絵文字は使わず Material Symbols を使う
- スコアは表示するが、END 文言は点数より「面白かった問題」に寄せる（room-K の非評価思想）
- ルームの結果発表も、最後の一言は点数より「話のたね」に寄せる

## ルームであそぶ（2026-09-25 追加）

オーナー依頼「クイズパックを Kahoot! みたいな感じでもできるようにしたい」で追加。着想元は『Kahoot!』。画面にはその名前を出さず、Kahoot! 特有の色・図形のボタンも使わない（選択肢は丸数字のまま）。

### オーナーが決めたこと（2026-09-25）

- **点数と順位は Kahoot! 式**: 正解すると点が入り、早いほど高い。問題ごとにランキング、最後に上位3人を発表する
- **制限時間はホストが選ぶ**: 20秒／30秒／なし（初期値30秒）。全員が答えたらその時点で締め切る。「なし」はホストが締め切る

### 役割と人数

- ホスト（メンター）は待合室で「自分も答える側で参加する」を選べる。**初期値は進行だけ**（答えない）。進行だけのときは、ホストの画面を共有すると、問題・残り時間・答えた人数・正解発表・ランキングを見せられる（「みんなにみせる画面」でもよい）。詳しくは下の「ホストの参加」
- 答える人は、ゲスト（1〜10人、`MAX_GUESTS`）と、参加を選んだホスト（最大11人）。答える人が1人いれば始められる（ホストが答えるならホストひとりでも）。上限を見るのは新しく参加するときだけ。切断から戻る人は上限を超えても戻れる（ゲームの途中で抜けた人を締め出さないため）
- 途中参加できる。問題の途中に入った人はその問題から、正解発表中に入った人は次の問題から、最後の問題の正解発表中・結果発表中に入った人は次のゲームから点数に参加する（`scores/{名前}/fromIndex`）
- 名前は8文字まで・同じルームで重複不可・ホスト名は不可。ゲームの途中で抜けた人の名前は、同じ端末（同じ匿名ID）からだけ使える

### 進行

1. ホストがパック・問題数・手ごたえ・制限時間を選んで「スタート」。デッキはホストの端末で、ひとつの画面モードと同じ `makeDeck()`（難易度配分・未出題優先）で作る
2. 問題は各自の画面にも出す。画面共有には遅れがあるため、色ボタンだけにはしない。答えは1人1回で、押し直しはできない
   - 各問題の前に、全員の画面（ホストも）で「3・2・1」を出す。ホストが「スタート」「次の問題へ」「もう一度あそぶ」を押した時刻（サーバー時刻の推定 `RoomkRTDB.now()`）に3秒足した時刻を `game.startedAt`（問題が出る時刻）として書き、各端末はその時刻まで数字を出してから問題を出す（別の `status` は作らない。ピタハメの `startAt` と同じ、各端末で計算する方式）。各端末は自分のサーバー時刻の推定で数え、数字が変わる瞬間と問題が出る瞬間に合わせて描き直すので、どの端末でもほぼ同じ時刻に問題が出る（推定のずれは通常0.1秒程度）
   - 制限時間と早さの点は `game.startedAt` から数えるので、カウントダウンの間は時間が減らない。カウントダウンの間は答えを送らない
   - 一度問題を出した端末は、そのあと時刻の補正などで `startedAt` が先に見えても、カウントダウンに戻さない（答えもそのまま送れる）
   - 既知の制限: カウントダウンを入れる前の版を開いたまま（再読み込みせずに）入った参加者の端末では、カウントダウンが出ずに問題が先に見え、カウントダウン中に答えると経過0で満点になる。再読み込みで直る。版の自動チェックは入れていないので、公開はルームで遊んでいない時間に行い、公開後の最初の利用では参加する端末を再読み込みしてもらう
   - カウントダウンの間に入った人は、その問題から点数に参加する（`status` は `question` のまま）
3. 締め切りは次の3つ。どれでも同じ集計をする
   - 制限時間が来たとき（通信の遅れぶん `ANSWER_GRACE_MS` = 1秒待つ）
   - 答えられる参加者（接続中で、その問題から参加している人）が全員答えたとき（0.8秒後。締め切る transaction の中で全員回答を確かめ直し、その間に答える人が増えていたら締め切らない）
   - ホストが「締め切って正解を見る」を押したとき（押す直前に送られた答えが届くよう、1秒待ってから締め切る）
4. 正解発表: 正解・選択肢ごとの人数（棒）・解説。ホストの画面にはランキング上位5位（同点は同順位）と今回の加点、参加者の画面には自分の結果と今の順位を出す。ランキングと参加者の順位の行には0点の人を出さない（0点の同順位がたくさん並ぶのを避ける）
   - 答えなかった人への文言は、制限時間を過ぎてから締め切ったときは「時間切れ！」、それ以外は「今回は答えなし」。押したのに集計に間に合わなかった人には「締め切りに間に合わなかったよ」
5. ホストの「次の問題へ」で進む。最後の問題は「結果発表へ」。正解発表中の「ここで結果発表へ」で途中終了できる
6. 結果発表: 点が入った人のうち上位3位（同点を含む）を全員に表示。参加者には自分の順位・点・正解数も出す（0点の人は順位を出さず「0点」だけ）。誰にも点が入らなかったときは表彰を出さない
7. ホストは「もう一度あそぶ」（同じ設定で、ホストの端末で出題済みの問題を避ける）か「パックをえらび直す」（待機へ）を選ぶ
   - 出題済みの記録（`usedIds`）はホストの端末のメモリだけに持つ。ホストが再読み込みしたときは今のゲームで出した問題を記録に戻す。ルームを出てトップへ戻るとリセットする（ひとつの画面モードと同じ）

### チャットで参加する（ルームに入らない人向け）

- ルームに入らない・入れない人も一緒に遊べるよう、ホストの画面にだけ「問題をコピー」（問題中）と「正解つきでコピー」（正解発表中）を置く。文面はひとつの画面モードのコピーと同じ（【問題】と丸数字の選択肢／【正解】【解説】）
- チャットで答えた人に点数はつかない。ルームの点数に入れる仕組みは作らない
- コピーに失敗したときは通知する（共有の `copyToClipboard` は失敗しても何も表示しないため、戻り値を見て知らせる）

### 点数

- 正解だけに点が入る。不正解・未回答は0点で、減点はしない。連続正解ボーナスはない
- 制限時間あり: `round(1000 × (1 − 経過時間 ÷ 制限時間 ÷ 2))`（すぐ答えると1000点、締め切りちょうどで500点）
- 制限時間なし: 正解は一律1000点（急がなくてよい）
- 経過時間は、問題が出た時刻（カウントダウンが終わった時刻。`game.startedAt`。ホストの端末がサーバー時刻を推定して決めた値）と、回答が届いた時刻（`at`。サーバーが付ける時刻）の差。問題の表示も同じ `startedAt` を基準にするので、問題のデータが `startedAt` までに届く限り、届くまでの通信の遅れは経過時間に入らない。カウントダウン中に届いた答え（通常は送れない）は経過0として扱う
- 点数はルーム内の進行状態として持つだけで、ルームを閉じると消える。個人の記録・履歴として保存しない（娯楽ゲームの得点。`docs/audit-prompts.md` §0.5 の内省・成長評価には当たらない）

### データ（`quiz_rooms/{roomCode}`）

| キー | 内容 |
|---|---|
| `status` | `lobby` → `question` ⇄ `reveal` → `final` →（`lobby` または `question`） |
| `host` / `hostUid` / `hostConnected` / `hostDisconnectedAt` | ホスト識別と切断検知 |
| `players/{名前}` | 接続中の人（`isHost` / `uid` / `joinedAt`）。ゲストは切断で消える |
| `settings/hostPlays` | ホストも答える側で参加するか（boolean）。作成時 `false`。キーがない旧ルームも `false`（進行だけ）。ホストだけが待合室（`lobby`）の間だけ transaction で書く |
| `gameSeq` / `setup` | ゲーム番号と、最後に始めた設定（ホスト再読み込み時の選択の復元用） |
| `game` | `id` / `packName` / `limitSec` / `total` / `questions[]` / `index` / `startedAt`（問題が出る時刻＝「3・2・1」が終わる時刻） |
| `answers/g{ゲーム番号}q{問題番号}/{名前}` | 1人に1つの受付枠。出題時は持ち主の匿名IDつきの `{ open: true, uid }`、答えると `choice` と `at` が加わり、締め切りで `open: false`。キーにゲーム番号を入れ、前のゲームの遅れた回答が混ざらないようにする |
| `results/g…q…` | 締め切り時に確定した `counts` / `picks` / `gains` / `answered` / `reason`（`timeout` / `all` / `manual`）/ `timedOut`（制限時間を過ぎてから締め切ったか） |
| `scores/{名前}` | `points` / `correct` / `uid` / `fromIndex`。切断では消さない（退出で消す）。答える側のホストもここに入る |

- 状態の変更（作成・参加・開始・締め切り・次へ・結果発表・待機へ戻る・退出）はすべて `transaction()`。ホストだけが進める
- 受付枠は、出題（開始・次の問題）と同じ transaction で、その問題に答えられる人（`scores` にいて `fromIndex` がその問題以下の人。切断中の人も含む）の分だけ、持ち主の匿名IDつきで作る。問題の途中に参加した人の枠は、参加と同じ transaction で作る。同じ名前で退出した別の人の枠が残っていたら、新しい持ち主の空の枠に差し替える
- 回答は自分の受付枠 `answers/g…q…/{名前}` への transaction。枠が `open: true`・持ち主が自分・まだ答えていないときだけ書ける。人ごとに別のノードなので、同時に押しても互いに待たされず、早さの点がずれない。締め切り後・ルームが消えた後・同じ名前の別の人に枠が移った後に遅れて届いた答えは書き込まない（ルームを部分的に作り直さない）
- 答えには答えた人の匿名ID（`uid`）を付け、`scores/{名前}/uid` と一致する答えだけを使う（表示・全員回答の判定・集計とも）。問題の途中で退出した人と同じ名前で別の人が入っても、前の人の答えを引き継がない（新しい人は答え直せる）
- 締め切り時にホストが全員の受付枠を閉じ（`open: false`）、有効な回答（その問題の参加者・選択肢の範囲内・締め切り＋1秒以内）だけを数えて、`results` と `scores` を同じ transaction で確定する
- 問題の正解もルームに入っている。参加者の画面には正解発表まで出さないが、開発者ツールで見えるのは性善説で許容する（ルート AGENTS.md のセキュリティ方針）

### 切断・再接続・削除

- ホスト切断: `onDisconnect().update({ hostConnected: false, hostDisconnectedAt })`。参加者には「ホストの戻りを待っています」を出し、2分（`ORPHAN_TTL_MS`）で期限切れにする。問題中は答えを送れるので、全面の表示ではなく、選択肢の下の帯で知らせる（選択肢より下なので、出入りしても選択肢の位置はずれず、上の「退出する」も覆わない。「答えはそのまま押せるよ」はまだ答えられるときだけ。問題の前のカウントダウン中も同じ帯を数字の下に出し、まだ答えられないので「押せる」とは言わない）。ほかの場面は全面の表示に「退出する」を置く
- ゲスト切断: `players/{名前}` を `onDisconnect().remove()`。点数（`scores`）は残る
- 再接続: sessionStorage（`quiz_session`）から同じルーム・名前・役割に戻る（匿名IDが一致するときだけ）。ホストは前のゲームの設定を選択状態に戻す
- 古い接続の切断予約が遅れて発火し、接続中なのに「ホスト切断」や「参加者から消えた」状態になったときは、本人の端末が在室に戻す
- 「ルームを作る」「参加する」は、匿名ログインを待つ前に二度押しをロックする（`docs/kaizen-backlog.md` B-20 と同じ）。再読み込みで戻る処理の途中は、トップの「ルームに参加する」「ルームを作る」を押せなくする
- 削除は公認バリアント「**ふりかえり画面滞在中は削除しない**」を採用（結果発表のあとも同じルームで続けて遊ぶため）。ホストの「ルームを閉じる」（確認あり）、ホスト切断2分の期限切れ、次回アクセス時の期限切れ掃除の3経路で消す
- 開発・静的監査から本番 Firebase に書き込まない。同期・切断の確認は隔離したエミュレーター（demo プロジェクト）で行う

### ホストの参加（2026-10-01 追加）

- 待合室の参加者欄に、ホストだけに見えるチェックボックス「自分も答える側で参加する」（`#set-host-plays`）。保存先は `settings/hostPlays`。**初期値は進行だけ**（`hostPlaysOf()` = `settings.hostPlays === true`）。待合室の間だけ変えられ、「もう一度あそぶ」「パックをえらび直す」でも値を引き継ぐ
- 答える人 = `playerNames()`（参加を選んだホスト＋ゲスト）。開始時の `scores` と受付枠、回答 n / N人・全員回答の締め切り（`answerablePlayers()`）、ランキング・上位発表はこれで数える。開始できる最少人数は答える人1人。ゲストの満員判定（10人）はゲストだけで数える（ホストが答えると最大11人）
- 待合室の一覧（ホスト・参加者・みんなにみせる画面）にホストの行を出し、進行だけなら「進行役」、答える側なら「ホスト」と添える。人数は答える人で数える
- 答える側のホストの画面: ゲストと同じ回答の選択肢（1回だけ・押し直しなし）と自分の答えの様子、その下に回答 n / N人。進行の操作（締め切って正解を見る・問題をコピー・次の問題へ・ここで結果発表へ・正解つきでコピー・もう一度あそぶ・パックをえらび直す）は従来どおり。正解発表では自分の結果・順位・「あなた」の印とランキング、結果発表では自分の結果も出す
- 正解は正解発表まで、答える側のホストの画面にも出さない（従来どおり、正解の印・「正解:」・解説は reveal で初めて書く）。デッキはホストの端末で作るが、画面には出さない
- 答える側のホストのタブは画面共有しない。共有は「みんなにみせる画面」で行う。チェックを入れると、待合室の「みんなにみせる画面をひらく」を目立つ形（`btn-secondary`）にする
- 再接続: ホストは `host`・`hostUid` で戻る（`hostPlays` に関係なく）。答える側のホストの点数は `scores` に残っているので、戻ったあとも答えられる
- 古い index.html（キャッシュ）と新しい app.js が組み合わさったときは、ホストの参加の部品がないので従来どおり進行だけとして動く（`HOST_PLAYS_UI`）

### みんなにみせる画面（2026-10-01 追加）

画面共有用の、ルームを読むだけの画面（`#screen-watch`）。ホストの画面と同じ出題の表示（問題・選択肢・残り時間・回答 n / N人・正解発表・ランキング・上位発表）を、ルームに参加しないで出す。ホストが進行だけのときは、従来どおりホストの画面をそのまま共有してもよい。正本の作りは `apps/kaburazu-hint/AGENTS.md` の「観戦専用ビュー（みんなにみせる画面）」。

- 入口は3つ
  1. URL の `?watch=CODE`（最優先）。起動時にこのタブの再読み込み用の記録（`quiz_session`）を消してから開く。コードが正しくない・ルームがない・期限切れのときは、記録に頼らずトースト＋トップ
  2. TOP の「ルームであそぶ」カードの「みんなにみせる画面をひらく」→ ルームコード →「画面をひらく」。開けたら URL を `?watch=CODE` にそろえる（再読み込みで同じ画面に戻る）
  3. ホストの待機画面（ルームコードの下）と正解発表の操作欄の「みんなにみせる画面をひらく」。クリックの中で同期的に `window.open(url, '_blank', 'noopener')`
- 完全分岐・書き込みゼロ: `state.role = 'spectator'`。購読は自分専用（`watch.ref`）で、`handleRoom`・締め切りの自動処理・在室の確認・期限切れの掃除（`removeExpired`）・`onDisconnect`・`players` への読み書きには入らない。匿名ログインはルールのために行うが、ルームにも `stats` にも書かない
- 出すもの（フェーズ別）
  | status | 出すもの | 出さないもの |
  |---|---|---|
  | lobby | ルームコード・参加者 | — |
  | question | 「3・2・1」（`game.startedAt` を同じ時刻基準で数える）→ 問題・選択肢（押せない表示）・残り時間・回答 n / N人 | 正解・だれが何を選んだか |
  | reveal | 正解・選択肢ごとの人数・解説・ランキング上位5位（0点は出さない） | 「あなた」の印 |
  | final | 上位3位（点が入った人だけ） | 各自の結果 |
- 正解（正解の印・「正解:」・解説）を DOM に書くのは reveal だけ。次の問題のカウントダウンに入るときに、前の問題の正解発表の中身も消す
- ホスト切断: 画面をふさがない帯（`#watchHostOff`）で知らせる。2分（`ORPHAN_TTL_MS`）たったら購読を止めて「このルームは終わりました」。ルームは消さない。結果発表を映している間はホストが離れても結果を出したまま
- ルームが消えた（ホストが「ルームを閉じる」など）: 購読とタイマーを止める。結果発表を映していたらその画面を残し、それ以外は「このルームは終わりました」。購読を止めるのは、同じコードが後で別のルームに使われたときに映さないため
- 「トップへ戻る」: 購読を止め、URL から `watch` を外してトップへ。ルームには触らない
- 文言は「みんなにみせる画面」（「観戦」は使わない）

### メンター向けの心得（画面には出さない）

- 早さの点がしんどそうなグループでは、制限時間を「なし」にすると正解は一律1000点になり、急がなくてよくなる
- 問題文は読み上げて補ってよい（漢字まじりの通常表記のため）
- ルームに入りたくない子・端末がない子は、チャットに貼った問題に答えてもらえばよい（点数はつかない）
- 最後の順位より、正解発表の解説や「どれを選んだ人が多かったか」を話のたねにする
- ホストの画面を共有したまま「問題をコピー」などを操作したくないときは、「みんなにみせる画面」を共有する
- ホストが答えるときは、みんなにみせる画面を共有し、ホストのタブは共有しない（自分の答えが映るため）
