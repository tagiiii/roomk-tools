# うそつき辞書 仕様書

## 目的・使用シーン

バルダーダッシュ風の「それっぽい嘘の意味」あてっこパーティーゲーム。
めずらしい実在の日本語が1つ出題され、ゲストは意味の文の「穴」に入ることばをでっちあげて提出する。
本物と嘘を混ぜて一覧表示し、どれが本物かを投票であてっこする。

- メンター（ホスト）が Zoom / Meet などで画面共有しながら進行する。共有には「みんなにみせる画面」（別タブ）を使える
- 対象は小学校中学年〜中学生（不登校の子を含む）
- 「辞書で勉強」ではなく「へんてこなことばで遊ぶ」トーン。読み書きの巧拙が出にくいよう、嘘は穴埋め30文字以内にしている

### 穴埋め方式（2026-07-29 改修）

当初は嘘の意味を一文まるごと自由記述だったが、実戦で「本物だけが辞書口調で、語尾の感じでバレる」問題が出た。
本物側の文体を整えるだけでは嘘側がそろわないため、**意味文をお題ごとの固定テンプレート（pre + 穴 + post）にし、ゲストは穴に入ることばだけを書く**方式に変更した。

- 全員の答えが同じ文の形で表示されるので、文体・語尾・長さでは本物を見分けられない
- 「辞書っぽい文を書く」という文体模倣の負担が消え、中身を考えることに集中できる
- post のカテゴリ情報（「〜、イタチのなかまの動物のこと。」等）は全員に開示される。嘘がカテゴリに沿って書かれるため、投票が「どの特徴が本当か」の推理になる

## 画面構成・フロー

```
TOP（screen-top）
 ├── ホスト → ニックネーム入力 → ルーム作成・ロビー（screen-host-setup）
 ├── ゲスト → ニックネーム＋コード入力 → 待機（screen-waiting）
 └── 「みんなにみせる画面をひらく」→ コード入力（screen-spectate-join）→ みんなにみせる画面（screen-spectator）
                     ↓（ホストが「はじめる」/ 遊ぶ人2〜8人）
           かく（screen-writing）
             全員: ことば＋よみがな＋意味の文の形（穴あきテンプレート）表示、かき終わった人の一覧
             ホスト（進行だけ）: 本当の意味（合成済み・穴を強調）は折りたたみ「タップで見る」表示
             ホスト（遊ぶ）: 本当の意味は出さない。ゲストと同じく入力・「意味を知ってる」
             ゲスト: 穴に入ることばを入力して「だす」。入力中は「できあがりの文」をライブプレビュー
                     本当の意味を知っていたら「意味を知ってる」（押し直すと取り消し）
             ホスト: 「ことばを変える」でお題だけ入れ替え（ラウンド数はそのまま。知ってる人の名前を表示）
                     ↓（全員提出→「投票にすすむ」/ 未提出者がいても「先にすすむ」）
           とうひょう（screen-voting）
             本物＋全員の嘘をシャッフルして丸数字付きで一覧表示
             ゲスト: 本物だと思うものに「投票する」（自分の嘘には投票不可）
             ホスト: 進行（「結果をみる」/「先にすすむ」）。遊ぶときはゲストと同じく投票もする
                     ↓
           けっか（screen-reveal）
             本物はどれか・誰がどの嘘を書いたか・誰が何に投票したか・得点を表示
             ホスト: 「つぎへ」（次ラウンド）/「おわる」
                     ↓
           おしまい（screen-done）
             累計ポイント表示 → 30秒後にルーム自動削除
```

### 参加用のリンク（`?room=CODE`。2026-10-05）

- 参加用のリンク `?room=CODE` と「リンクをコピー」（2026-10-05）。共通仕様は docs/development/rtdb.md「参加用のリンク」。このアプリの入口は末尾の `init()`（`?watch=` → `?room=` → sessionStorage の順）、参加画面は `screen-guest-join`（`openJoinFromLink` がコード欄 `#guest-room-code` に入れ、`#joinLinkHint` を出す）。`?room=` はつないだとき `startRoomListener()` の先頭で外す（みんなにみせる画面では触らない）
- 「リンクをコピー」（`#btnCopyLink`）はホストの待機（`host-step-room`）の「コードをコピー」の下だけ（ゲストの待合室にはもともとコピーのボタンがない）。`copyToClipboard` は共通の `copyRoomCode`（コード専用）なので、文字列用の `copyText` を別に置いている
- 固有: リンクのコードは `SPEC_CODE_RE`（ルームコードの文字集合）で検査する（参加フォームの `/^[A-Z0-9]{6}$/` より狭い）。みんなにみせる画面の記録（`role: 'spectator'`）が同じコードで残っていても再接続を優先しない（記録を消して参加画面へ）。参加画面の欄名に合わせ、ヒント・あそびかたは「名前」でなく「ニックネーム」

## みんなにみせる画面（画面共有用・2026-10-01 追加）

ホストの画面には本当の意味（折りたたみ）が出るため、画面共有には別タブの「みんなにみせる画面」（`#screen-spectator`）を使える。
参加者本人も見る画面なので、**全員が見てよい情報だけ**を出す。正本は `apps/kaburazu-hint/AGENTS.md` の「観戦専用ビュー（みんなにみせる画面）」で、入口・完全分岐・書き込みゼロ・終了時の扱いはそれと同じ。

### 入口（3つ）
1. **URL `?watch=CODE`**（最優先）: 起動時に `normalizeRoomCode()` → 6文字・ルームコードの文字集合（`SPEC_CODE_RE`）で検査。無効・不存在・期限切れはトースト＋TOP で、sessionStorage にはたよらない（watch 入口では先に `clearSession()`）。`?watch=`（空）も同じ扱い。watch がないときだけ参加用のリンク `?room=`・sessionStorage を見る
2. **TOP**: 「みんなにみせる画面をひらく」→ ルームコード（6文字）→「画面をひらく」。入れたら `history.replaceState` で URL を `?watch=CODE` にそろえる（リロードで戻れる）
3. **ホストの画面**: 待合室と、ゲーム中のホスト操作欄（writing / voting / reveal）の「みんなにみせる画面をひらく」。クリックの中で同期的に `window.open(url, '_blank', 'noopener')`

### 完全分岐・書き込みゼロ
- `state.role = 'spectator'`（`nickname` は空）。`startRoomListener()` の入口で `handleSpectator(room)` に分岐し、host/guest の処理（ホスト切断オーバーレイ・期限切れの `remove()`・各 `handleX`）には入らない
- RTDB に一切書き込まない: players に入らない・onDisconnect を予約しない・期限切れルームや終了後のルームを消さない（`tryReconnect()` の spectator 分岐 `reconnectSpectator()` も同じ）
- 匿名認証は使う（ルールが `auth != null`）
- 一覧の HTML（`playerRowsHtml` / `submitChipsHtml` / `revealCardsHtml` / `scoreRowsHtml`）は参加者の画面と共有

### フェーズ別の表示
**本当の意味（`fill`）・だれのうそか（`author`）・だれが何に投票したかを DOM に書くのは reveal だけ。** 折りたたみで隠すのではなく書かない。描画はサブビューごとに `#spec-content` の innerHTML を置き換え、文字は必ず `esc()` を通す。

| status | 出すもの | 出さないもの |
|--------|---------|------------|
| waiting | ルームコード・参加者一覧・待機メッセージ | — |
| writing | ラウンド・ことば＋よみがな・意味の文の形（？？？）・「意味を知ってる人：○○」・かき終わった人数とチップ | 本当の意味・答えの中身 |
| voting | ことば・選択肢（DB のシャッフル順のまま丸数字つき）・投票した人数 | どれが本物か・だれのうそか・だれが投票したか（名前も出さない） |
| reveal | 参加者の画面の結果と同じ（本物・だれのうそか・投票・得点） | — |
| done | おしまい＋みんなのポイント | 操作ボタン |
| それ以外 | 「準備しています…」 | — |

### 終わり方・切断
- 「トップへ戻る」（`spectatorLeave()`）: 購読をやめ、セッションと URL の watch を消し、TOP へ。ルームには触らない
- ホスト切断中（done 以外）は専用オーバーレイ `#spec-host-off-overlay`（ボタンは「トップへ戻る」）。TTL（`ORPHAN_TTL_MS`）を過ぎたら、ルームの更新が来なくてもローカルタイマー（`state.specTimer`）で「このルームは終了しました」に切り替える。消さない
- ルームが消えた: おしまいの画面を出していたらそのまま残す。それ以外は「このルームは終了しました」
- 終わった状態（消えた・TTL 超過）では `stopSpectatorWatch()` で購読とタイマーを止め、表示だけ残す（同じコードが再利用されたとき別のゲームを映さないように）
- 「ことばを変える」・次ラウンドは `wordIndex` と `entries` / `choices` を1つの transaction で書くので、前のお題の答えが新しいお題の画面に混ざらない（この原子性を崩さない）

## status 遷移

```
waiting → writing → voting → reveal ─┬→ writing（次ラウンド）
                                     └→ done（30秒後にルーム削除）
```

| status | 説明 |
|--------|------|
| `waiting` | ロビー。ルームコード表示・参加者一覧。このフェーズのみ入室可 |
| `writing` | お題表示・ゲストが穴に入ることばを入力（1〜30文字・空NG）。ホストは「ことばを変える」でお題を入れ替えられる |
| `voting` | 本物＋嘘をシャッフルした選択肢一覧にゲストが投票 |
| `reveal` | 正解発表・得点反映・累計ポイント表示 |
| `done` | 終了画面。ホスト端末が30秒後に `roomRef.remove()` |

status の更新はすべてホスト操作（`transaction()`）。自動遷移はない。

## Firebase データ構造

```
uso_rooms/{roomCode}/
  ├── host:                string          # ホストのニックネーム
  ├── hostConnected:       boolean
  ├── hostDisconnectedAt:  number | null
  ├── status:              string          # 上記 status 参照
  ├── round:               number          # 現在のラウンド（1始まり）
  ├── wordIndex:           number          # 現在のお題（WORDS のインデックス）
  ├── settings/
  │    └── hostPlays:      boolean         # ホストもプレイヤーとして遊ぶか（作成時 false。キーなし＝false）
  ├── usedWords:           number[]        # 使用済みお題インデックス（全消化でリセット）
  ├── wordRev:             number          # このラウンドで「ことばを変える」をした回数（開始・次ラウンドで0）
  ├── players/
  │    └── {nickname}/
  │         ├── isHost:  boolean
  │         └── score:   number            # 累計ポイント
  ├── entries/                             # 今ラウンドの嘘（穴に入ることばのみ・提出のみ・競合なし）
  │    └── {nickname}: string
  ├── entryKeys/                           # 答えを出したときのキー「ラウンド:お題番号:変えた回数」（entries と同じ update で書く）
  │    └── {nickname}: string
  ├── knows/                               # 「意味を知ってる」を押した人（値は押したときのキー）
  │    └── {nickname}: string
  ├── choices: [                           # voting 遷移時にシャッフルして確定
  │    { text: string, author: string | null }   # text は穴の中身。author が null（RTDB上は欠落）= 本物
  │  ]
  └── votes/                               # 今ラウンドの投票（choices のインデックス）
       └── {nickname}: number
```

### データ操作の注意点

- ルーム作成・参加・開始・各フェーズ遷移は `transaction()` で原子的に行う
- 参加は `status === 'waiting'` かつ遊ぶ人が8人未満のときのみ（transaction 内で判定。進行だけのホストは数えない）
- 嘘の提出は `entries/{nickname}` と `entryKeys/{nickname}` への1回の `update()`（キーが分かれるため競合しない）。投票は `votes/{nickname}` への `set()`
- `entries` / `choices` には**穴の中身だけ**を保存し、表示時に毎回 `composeMeaning()`（pre + 穴 + post）で合成する。提出前に `normalizeEntry()` で空白をまとめ、文末の「。」「、」を取り除く（合成した文が壊れないように）
- `writing → voting` の transaction 内で `entries` ＋本物の穴の中身（`fill`）から `choices` を構築・シャッフルする。提出が1件もないと遷移しない
- `voting → reveal` の transaction 内で得点を計算して `players/*/score` に加算する（原子的）。reveal 画面の表示用の得点内訳は `choices` と `votes` からクライアント側で同じロジック（`calcDeltas`）で再計算する
- 本物がどれか（`choices` の `author` 欠落）は DB を見れば分かるが、共通規約どおり性善説で許容（UIレベルの秘匿のみ）
- 次ラウンド遷移時に `entries` / `entryKeys` / `choices` / `votes` / `knows` を null でクリアする

### 「意味を知ってる」と「ことばを変える」（2026-09-29 追加）

もとの辞書ゲーム（フィクショナリー）の定番ルール「意味を知っている人がいたら、別のことばに変える」をアプリにしたもの。実機で「お題の意味がわかってしまう」という意見が出たため。

- 答え・「知ってる」がどのお題に対するものかは、キー `writingKeyOf()` =「ラウンド:お題番号:変えた回数（`wordRev`）」で区別する。変えた回数を入れるので、同じラウンドでお題が一巡して同じことばに戻っても前のものと一致しない
- ゲストの「意味を知ってる」は `knows/{nickname}` に**押したときのキー**を `set()`、押し直すと `remove()`。表示はキーが今と一致する人だけを数えるので、お題が変わった直後に届いた古い書き込みは無視される
- ホストの「ことばを変える」は `writing` 中だけ。transaction で `wordIndex` を選び直し、`usedWords` に追加し、`wordRev` を1増やし、`entries` / `entryKeys` / `knows` を null にする。`round` は変えない。外したお題は `usedWords` に残るので、一巡するまで出ない
- 答えがすでに出ているときは `confirm()` で「もう出た答えは消えます」と確かめる。確認なしで押したあとに答えが届いていた場合は、transaction の中でそれに気づいて一度止め、確認し直してからもう一度変える。だれも押していなくてもホストの判断で変えられる
- ゲストはキーが変わったら入力欄をリセットし、同じラウンド内の変化なら「ことばが変わりました」をトースト表示する
- ホストが変えたのと同時にゲストが出した答えは、変えたあとに届いて `entries` に残ることがある。答えと同時に書く `entryKeys` が今のキーとちがう答えは、`currentEntries()` で除き、投票の選択肢・かき終わった人・全員完了の判定のどれにも使わない。そのゲストの画面は入力欄に戻り、新しい答えを出せば上書きされる
- `entryKeys` がない答え（公開前から開いていた古い画面が出したもの）は、従来どおり今の答えとして扱う

## 切断時の挙動

- ゲーム中の名前だけによる再参加は拒否し、復帰は同じタブの保存済みsessionによる `tryReconnect()` のみとする（2026-09-09 P-12）。sessionStorageは認証境界ではなく、別端末の本人確認を追加したものではない。待機中の通常参加・ホスト名の参加拒否・既存の保存復帰処理は維持する。

| 役割 | 挙動 |
|------|------|
| ホスト切断 | `hostConnected=false`＋`hostDisconnectedAt=ServerValue.TIMESTAMP`（`onDisconnect().update()`）。ゲストにはカウントダウン付きオーバーレイ表示。`ORPHAN_TTL_MS = 2分` 超過で期限切れ扱い→削除 |
| ゲスト切断 | `onDisconnect().remove()` で `players/{nickname}` のみ削除。`entries` / `votes` は残る |

- 再接続: sessionStorage キー `usojisho_session`（nickname / roomCode / role / score）。ホスト復帰時は `hostConnected=true`・`hostDisconnectedAt=null` を戻す。ゲスト復帰時は `players/{nickname}` が消えていれば保存済みスコアで再登録する（提出・投票は `entries` / `votes` に残っているため復元不要）
- サーバー時刻補正: `RoomkRTDB.initServerTime(db)` を初期化直後に開始し、TTL 判定は `RoomkRTDB.now()` / `RoomkRTDB.isRoomExpired()` を使用
- ゴースト room 対策（2026-07-29）: 30秒後の自動削除では削除の**前**に `cancelRoomOnDisconnect()` で自接続の onDisconnect 予約を取り消す（予約が残ると削除後のタブクローズで `{hostConnected,...}` だけの部分 room が再生成される）。防御として `isRoomExpired()` は `status` を持たない room も期限切れ扱いにする
- `done` 中はゲスト側のホスト切断オーバーレイ・期限切れ判定をスキップする（終了画面を見せたまま自然に閉じられるように）

## 得点ルール

| 行動 | ポイント |
|------|---------|
| 本物の意味に投票した | **+2** |
| 自分の嘘が1票あつめるごとに | **+1** |

- 進行だけのホストは回答も投票もしないため得点対象外（ポイント一覧にも出さない）。遊ぶホストはゲストと同じく得点の対象
- 未提出のゲストもそのラウンドの投票には参加できる（本物を当てれば +2）
- ポイント表示は「順位の強調をしない」控えめな一覧（名前順・順位番号なし）。reveal では今ラウンドの増分（+n）を小さく添える

## お題データ（WORDS）

- 99問（2026-09-29 に50問から入れ替え・拡充）。形式 `{ word, kana, pre?, fill, post }`。`word` には必ず `kana`（よみがな）を併記表示する
- 意味文は `pre + fill + post` で合成する。`fill` が本物の「穴の中身」、`pre`（省略可）と `post` が全員共通のテンプレート
- 実在する日本語のめずらしい言葉のみ。カテゴリ: ようすのことば（やおら・けんもほろろ等）/ 古い道具・もの（ふいご・ねこぐるま等）/ 動物（バビルサ・ツチオオカミ等）/ 食べ物（ぬた・いちご煮等）/ 方言（いずい・だんだん等）/ 自然のことば（かざはな・もがりぶえ等）/ 植物・虫・きのこ（ウラシマソウ・オトシブミ等）/ からだ・くらし（ぼんのくぼ・ひよめき等）
- **post の情報量はお題ごとのダイヤル**。「〜こと。」「〜ようす。」のように薄くすれば自由度が上がり、「〜、イタチのなかまの動物のこと。」のようにカテゴリを明かせば嘘が本物に寄って推理が深まる。濃淡を混ぜる
- 方言は `pre: '「'` + `post: '」という意味の、〜のことば。'` の形（穴＝意味そのもの）。びいどろ・たなごころ等の言い換え系は `post: 'をさす昔のことば。'`（穴＝名詞ひとつ）で、Fibbage 的な短い穴も混ぜている
- `fill` は30文字以内・文末の句読点なし（ゲストの入力と同じ制約）。`post` に「な」「、」など接続もすべて含め、穴には素の語句が入るだけで文が成立するように書く
- 選定基準: 音で聞いて面白い言葉を選ぶ。難読漢字クイズにしない。学校・勉強関連、恋愛・ホラー・侮蔑的な言葉は入れない
- 2026-09-29 の見直し（実機で「意味がわかってしまうお題が多い」）で加えた基準。経緯と外した語・直した語は `docs/reports/uso-jisho-words-2026-09-29.md`
  - 小中学生の多くが知っている言葉（ひしゃく・ずんだ・めんこい等）は入れない
  - 名前の音や字から意味が推測できる言葉（ハダカデバネズミ・がらんどう等）、見える文（pre・post）と合わせると答えがわかる言葉は入れない。名前と意味がずれる言葉（いちご煮・ねこぐるま等）がいちばん向く
  - 別の本当の意味がある言葉（こち＝魚、ヤツガシラ＝里いも等）は避ける。嘘のつもりの答えが本当になってしまう
  - 標準語の意味が暗い言葉（いたましい）、からかいのネタになりやすい言葉（しもつかれ）は避ける
  - 意味は辞書・自治体・農水省・動物園などで1語ずつ裏取りする
  - 方言はその地方の子には日常語なので、当たったら「意味を知ってる」→「ことばを変える」で対応する前提で入れている

## ホストの参加（2026-10-01 オーナー決定: 待合室でホストの参加を選べる（初期値は従来どおり進行だけ））

- 待合室のホストだけに「設定」欄の「自分もプレイヤーとして参加する」（初期値: 外す＝進行だけ）。保存先は `settings/hostPlays`（作成時 `false`）
- 切り替えは待合室（`waiting`）の transaction だけ（`onHostPlaysChange()`）。開始後は拒否する。ゲストがすでに8人いるときは、遊ぶ側への切り替えも transaction の中で拒否する（チェックを戻し「遊べるのは8人までです。ゲストが8人いるので参加できません」）。次のラウンドは待合室を通らないので、選んだ値のまま
- キーがない部屋（旧版が作った部屋）は進行だけとして扱う（`hostPlays === true` のときだけ遊ぶ）
- 遊ぶ人（`playingNames()`）＝ホストが遊ぶなら全員、進行だけならゲストだけ。最少2人・最大8人、参加時の満員、開始ボタンと案内（「あと N 人必要です」「遊ぶ人は8人までです（いま N 人）」）、かき終わった人・投票した人の数と全員完了の判定、「意味を知ってる人」、ポイント一覧はすべて遊ぶ人で数える
- **ホストが遊ぶとき、本当の意味（`#host-secret`）は一切出さない**（オーナー決定。折りたたみも出さず、DOM にも書かない）。ホストもゲストと同じ条件でうそを書いて投票する（自分のうそには投票できない・「じぶんの」バッジ）。「意味を知ってる」も押せる。「ことばを変える」・投票へ・結果へ・つぎへ・おわるの進行操作は従来どおりホストが行う
- 進行だけのホストの答え（`entries`）は `currentEntries()` で数えない。答え・知ってる・投票の書き込みは `isPlaying()` で遊ぶ人に限る
- 待合室の参加者一覧（ホスト・ゲスト・みんなにみせる画面）で、進行だけのホストの行に「進行役」タグ
- ホストが遊ぶときは、ホストのタブは共有しない（共有は「みんなにみせる画面」）。チェックを入れた待合室にも「みんなにみせる画面をひらく」がある
- 再接続: ホストは role で戻るので、遊ぶ・進行だけのどちらでもリロードでホストとして戻れる

## 共通規約からの逸脱

- **初期値ではホストはプレイヤーとして参加しない**（回答・投票・得点なし）。ファシリテーター専任のため。待合室で遊ぶ側にもできる（上記）
- **最小人数は遊ぶ人2人**（進行だけならホスト含め3人）。上限は遊ぶ人8人（transaction 内で判定）
- ゲストが切断しても `entries` / `votes` は削除されない（players の外に置いているため）。書いた本人が離脱していても嘘は選択肢に残り、離脱者に入るはずだった得点は反映されない（players に不在のため加算先がない）

上記以外（ルームコード6桁・ニックネーム8文字/重複NG/空NG・transaction・TTL 2分・30秒後削除・丸数字・esc() など）はすべてルート AGENTS.md の共通規約どおり。

## メンター向け進行のコツ

- 画面共有は「みんなにみせる画面」（ホストの画面の「みんなにみせる画面をひらく」でひらく別タブ）を使うと、本当の意味が映る心配がない
- ホストが遊ぶときは、みんなにみせる画面を共有し、ホストのタブは共有しない（ホストの画面には自分のうそや投票が出る）
- ホストの画面をそのまま共有する場合、本当の意味は折りたたみ表示なので、共有中にうっかり開かないよう注意（開くときは共有を止めるか、口頭で読み上げる）
- 「かく」フェーズで手が止まっている子がいたら、「本当っぽくなくても、笑えるやつでもいいよ」と声をかける。うまい嘘より「それっぽさ」や「面白さ」を拾って笑うのがこのゲームの核
- 「意味を知ってる人：○○」が出たら、基本は「ことばを変える」。知っている子には「物知りだね」と拾って、次のことばへ。何回変えてもよい
- 穴埋め方式のため、嘘どうしがかぶったり、偶然本物とほぼ同じ嘘が出ることがある。事故ではなく笑いどころとして扱う（「ニアピン賞！」など）。本物と嘘の区別は表示された選択肢のとおりに進めてよい
- 全員を待たなくても「先にすすむ」で進行できる。書けなかった子はそのラウンドは投票だけ参加になるので、「次のことばでまた書けばいいよ」と伝える
- 発表のとき、嘘を書いた本人に読み上げてもらうと盛り上がる（強制はしない）
- 点数は控えめ表示にしてある。順位や勝ち負けを煽らず、「この嘘に2人もだまされた！」のようにエピソードで振り返る
- 1ラウンド5分前後。4〜6ラウンドで30分程度が目安
