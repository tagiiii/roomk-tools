# まぎれ絵師 仕様書

## 目的・使用シーン

みんなで1枚の絵を1筆ずつ描いて完成させるお絵かき正体隠匿ゲーム。
ゲストのうち1人だけが「まぎれ絵師」となり、お題を知らないままバレないように描く。
**話さなくても・チャットだけでも主役になれる**のが core value。
描く・見る・投票するだけで参加が成立するため、発話が苦手な子も同じ土俵に立てる。
メンター（ホスト）が Zoom / Meet などで画面共有しながら進行する。対象は小学校中学年〜中学生。

> 原作「エセ芸術家ニューヨークへ行く」にインスパイアされた派生ルールのオンライン版。
> 名称・演出・ルール細部をオリジナルに変更している。

## 画面構成・フロー

```
TOP（screen-top）
 ├── ホスト → ニックネーム入力 → ルーム作成・待機（screen-waiting）
 └── ゲスト → ニックネーム＋コード入力 → 待機（screen-waiting）
                     ↓（ホストが「ゲームを始める」/ ゲスト3人以上）
           お題くばり（screen-reveal）
             ゲスト: タップで役わりカードを見る →「確認した」
               - ふつうのゲスト: お題（例「ねこ」）＋カテゴリ
               - まぎれ絵師: 「君はまぎれ絵師！」＋カテゴリのみヒント
             ホスト: お題・まぎれ絵師を折りたたみ（タップで見る）で確認
                     ↓（全ゲスト確認後、ホストが「描き始める」）
           おえかき（screen-drawing）
             ランダム順で1人ずつ1筆。全員が2周描いたら自動で次へ
                     ↓
           そうだんタイム（screen-discussion）
             完成した絵＋お題（まぎれ絵師以外）を表示。声でもチャットでも
                     ↓（ホストが「投票へ」）
           とうひょう（screen-voting）
             ゲスト全員が「まぎれ絵師だと思う人」に投票（自分には不可）
                     ↓（全員投票で自動開票 / ホストが締め切りも可）
           けっか（screen-result）
             にげきり成功 or 逆転当てフェーズ → 勝敗表示
             ホスト: 「次のラウンドへ」or「終わる」
                     ↓
           おしまい（screen-done） → 30秒後にルーム自動削除
```

- ホスト＝メンター。**描かない・投票しない・まぎれ絵師にならない**（進行係）。
- ゲストは3〜8人を想定（上限は色パレット8色による実質上限。人数制限のハードチェックはしない）。
- ホスト画面は画面共有されうるため、お題とまぎれ絵師の情報は常に `<details>` の折りたたみ
  「タップで見る」で表示する。ラウンドが変わるたびに全折りたたみを自動で閉じ直す。

## status 遷移

```
waiting → reveal_role → drawing → discussion → voting → result
                                                          ↓
                                        次ラウンド: reveal_role（round+1）
                                        ホストが「終わる」: done（30秒後にルーム削除）
```

| status | 説明 |
|--------|------|
| `waiting` | ロビー。このフェーズのみ入室可 |
| `reveal_role` | お題くばり。ゲストが役わりカードを確認 |
| `drawing` | 1人ずつ1筆。`turnIndex` が `drawOrder.length × 2` に達したらホストが自動で discussion へ |
| `discussion` | 相談タイム。ホストの「投票へ」で進む |
| `voting` | ゲスト全員が投票。全員投票で自動開票（ホストの手動締め切りあり） |
| `result` | 開票・逆転当て・勝敗表示。ホストが次ラウンド or 終了を選ぶ |
| `done` | 終了画面。ホスト側で30秒後に予約取消と条件再検査を経た room transaction で削除 |

status 文字列はコード内で `STATUS` 定数に集約している。遷移はすべて `transaction()` で
現在の status を確認してから行う（ホストのみが遷移操作できる UI 制御）。

## Firebase データ構造

```
magire_rooms/{roomCode}/
  ├── host:                string          # ホストのニックネーム
  ├── hostConnected:       boolean
  ├── hostDisconnectedAt:  number | null
  ├── status:              string          # 上記 status 参照
  ├── round:               number          # 現在のラウンド（1始まり。waiting 中は 0）
  ├── usedTopics:          number[]        # 使用済みお題インデックス（全消費で自動リセット）
  ├── players/
  │    └── {nickname}/
  │         ├── isHost:    boolean
  │         ├── confirmed: boolean         # reveal_role で「確認した」を押したか
  │         ├── vote:      string | null   # 投票先ニックネーム
  │         ├── presenceVersion: 1        # 新版ゲストの保持復帰
  │         └── connections/{id}: true    # 接続ごとの remove 予約対象
  └── game/                                # ラウンドごとに丸ごと作り直す
       ├── topicWord:      string          # お題（例「ねこ」）
       ├── topicCategory:  string          # カテゴリ（例「どうぶつ」）。まぎれ絵師へのヒント
       ├── fakeArtist:     string          # まぎれ絵師のニックネーム
       ├── drawOrder:      string[]        # ゲストのシャッフル順（ラウンド中は固定）
       ├── colors:         { [nickname]: string }  # 描画色（drawOrder 順にパレット割り当て）
       ├── turnIndex:      number          # 現在の手番（0 〜 drawOrder.length*2）
       ├── strokes/
       │    └── {pushId}:  { points: [[x,y],...], color: string, by: string }
       └── result/                         # 開票後に生成
            ├── outcome:        'escaped' | 'caught' | 'aborted'
            ├── voteCounts:     { [nickname]: number }
            ├── reversalGuess:  string | null   # 逆転当ての自由入力（最大20文字）
            └── reversalJudge:  'win' | 'lose' | null  # ホストの あたり/はずれ 判定
```

### ストロークの持ち方と同期方式

- キャンバスは**論理サイズ 600×450**。CSS で親幅にレスポンシブ縮小し、Pointer Events の座標は
  `getBoundingClientRect()` で論理座標に変換して保存する（端末間で同じ絵になる）。
- 1筆 = pointerdown〜pointerup の連続した1本の線。描き終わると「これでOK / 描き直す」の
  確認を出し、OK で push キーだけを1回生成する。`{points, color, by}` の追加と手番更新を同じ room transaction で確定する。
  **確定時のみ同期**し、途中経過のリアルタイム同期はしない（転送量削減・Spark 無料枠対策）。
- points は 2px 未満の移動を間引き、1筆あたり最大600点に制限。座標は整数に丸める。
- 手番の進行: 描き始め時の room・round・接続世代・手番と、最新の status・在籍・描く人を検査し、線追加と `game.turnIndex + 1` を原子的に確定する。再試行でも同じキー・線を使い、旧手番から追加しない。
- 全クライアントはルームの `value` リスナーで受け取った `game/strokes` を push キーの昇順に
  ソートして再描画する（child_added リスナーは使わない。ルーム全体の value 購読と二重になるため）。
  再接続時もこの仕組みでそのまま全ストロークが復元される。
- 描画中の誤スクロール防止のためキャンバスは `touch-action: none`。

## 切断時の挙動

| 役割 | 挙動 |
|------|------|
| ホスト切断 | `hostConnected=false` + `hostDisconnectedAt=ServerValue.TIMESTAMP`（`onDisconnect().update()`）。ゲストにはオーバーレイ表示。`ORPHAN_TTL_MS = 2分` 超過で期限切れ扱い・検知時に削除 |
| ゲスト切断 | 接続IDだけを `onDisconnect().remove()` し、参加者・確認・投票・確定済み線を保持する（P-11/B-29の共通規約例外） |

### ゲーム中の切断と明示退出

- 一時切断では在籍を維持し、手番も待つ。まぎれ絵師の一時切断を不成立としたり、投票分母から外したりしない。以下の不在・離脱は明示退出で player が削除された場合を指す。

- `drawOrder` はラウンド開始時に固定し、途中離脱があっても変更しない。
- **手番のゲストが不在**: ホスト端末が検知し、`game/turnIndex` を `transaction()` でスキップ
  （現在値一致ガード付きなので二重スキップしない）。凡例には「（退出）」と表示。
- **とうひょう中の離脱**: 集計は「現在残っているゲストの投票」だけで行う。全員投票の判定も
  残っているゲスト数で見るため、進行は止まらない。
- **まぎれ絵師本人の離脱**: そのラウンドは成立しないため、ホストに警告バナーと
  「このラウンドを終わる」ボタンを表示 → `result`（`outcome: 'aborted'`）に遷移し、
  そこから次ラウンド or 終了を選べる。開票時点で不在だった場合も自動で `aborted` になる。
- 再接続は sessionStorage（`magire_session`）で対応。復帰時は value リスナー経由で
  確定済みストロークを全て再描画し、確認済み・投票済み状態も復元する。

## 勝敗ルール

| 状況 | 結果 |
|------|------|
| 最多票が同数（誰にも絞れない）/ 最多票がまぎれ絵師以外 / 票が1票もない | **まぎれ絵師のかち**（にげきり成功） |
| まぎれ絵師が単独最多票 → 逆転当て（自由入力）→ ホストが「当たり」 | **まぎれ絵師のかち**（逆転当て成功） |
| まぎれ絵師が単独最多票 → 逆転当て → ホストが「外れ」 | **みんなのかち** |
| まぎれ絵師が単独最多票 → 逆転当てに答えがない（退出・入力なし） → ホストが「答えなしで進む」 | **みんなのかち**（逆転失敗として確定。`reversalJudge: 'lose'`・`reversalGuess: null`） |
| まぎれ絵師が途中退出 | ラウンド不成立（勝敗なし） |

- 逆転当ての正誤は表記ゆれ（ひらがな/カタカナ等）があるためホストの人間判定（あたり/はずれ ボタン）。
- 逆転当てが決着するまで、お題はまぎれ絵師本人の画面に出さない。ホスト画面でも折りたたみのまま。
- **未回答の救済（2026-09-04 B-22）**: `outcome: 'caught'` で `reversalGuess` も `reversalJudge` も未確定のあいだ、
  ホスト画面にだけ「答えなしで進む（みんなの勝ち）」を表示する。確認ダイアログののち `game/result` を
  transaction で `reversalJudge: 'lose'` にする（未回答・未判定のときだけ書く）。B-29では room・round も検査する room transaction に移し、回答が先に確定すればスキップを中止、スキップが先に確定すれば遅い回答を中止する。常に回答が優先するという意味ではない。
  新しい status や判定値は増やさず、既存の「外れ」と同じ経路で決着する。これがないと絵師が退出・無入力のとき
  `result` から進めず、`hostAbortRound` も `result` を対象外のため TTL までルームが凍結する。

## お題データ

- `TOPICS` として180個を index.html にインライン同梱（`{ w: お題, c: カテゴリ }`）。
- カテゴリ6種 × 30個: どうぶつ / たべもの / のりもの / しぜん / どうぐ / まち・あそびば。
  （当初は6種×10個＝60個。プレイ回数が増えてお題を予想できる子が出たため2026-08-26に3倍へ拡充）
- まぎれ絵師にはカテゴリだけをヒントとして表示する。
- 選定基準: 絵に描きやすい具体名詞。学校・勉強・恋愛・ホラー・死を連想させるものは入れない
  （ルート AGENTS.md のコンテンツガイドライン準拠）。
- `usedTopics` で使用済みインデックスを管理し、全部使い切ったらリセットして再利用。

## メンター向け進行のコツ

※ この内容は画面には出さない（メンター向け注意書きは AGENTS.md に書く運用）。

- ホスト画面を画面共有する前提の設計。お題・まぎれ絵師の折りたたみは**開いたら必ず閉じる**。
  ラウンドが変わると自動で閉じ直されるが、共有中にうっかり開かないよう注意。
- 「1筆」は線1本。点だけでも成立する。うまい絵を目指すゲームではないので、
  「へたでも大丈夫、1本だけね」と最初に伝えると描くハードルが下がる。
- そうだんタイムは声が出ない子がいても、チャットで「〇〇さんの2筆目があやしい」等を
  拾って読み上げるとチャット参加でも主役になれる。
- まぎれ絵師が当てられたときの逆転当ては盛り上げどころ。「当たり/外れ」の判定は
  多少ゆるめ（ひらがな違い・言い方違いはあたり扱い）にすると悔しさが残りにくい。
- 誰が描くか迷って止まっている子には「まるひとつでもいいよ」と促す。
  一時切断では手番を待つ。明示退出で参加者情報が消えた場合だけ、その手番は従来どおり自動スキップされる。

## ゲスト保持復帰の実装上の境界（2026-09-08 B-29）

- 全7フェーズで同じタブの sessionStorage 復帰を扱う。保存 role・ニックネーム・ルームコードと最新 player/host を state 変更前に検査する。RTDBキー禁止文字は入口と保存情報で拒否し、有効な単一引用符等は既存 esc によって表示する。クライアント判定は本人確認・認証境界ではない。
- `.info/connected` の接続ごとにIDを作り、remove予約の受付後、存在・役割・状態・TTLを検査する room transaction で接続を登録する。古いIDの取消・削除は新IDに触れない。初回 join は一時 value 購読を transaction 完了まで保持し、古い get 結果で room を再生成しない。
- 待機開始と次ラウンドは全在籍ゲストの接続を待つ。最小ゲスト3人、上限ハードチェックなし、2周、色、600×450の論理キャンバス、最大600点、お題180件と秘密情報の折りたたみは変更しない。切断者は一覧・凡例に再接続待ちと表示する。
- pointerdown 時点で room・round・接続世代・手番を捕捉する。未送信の線は保存・復帰の保証外で、切断時に破棄する。確定済みストロークは残す。描画操作の所有 token を検査して、旧 Promise の finally が新ラウンドの線を消すことを防ぐ。
- 確認・投票・逆転回答も最新 room の存在・player役割・TTL・status・round・接続世代を再検査する transaction。確認・投票済み表示は value リスナーを正とし、abort/reject後は再操作できる。投票の300ms演出はクリック時の文脈を捕捉し、次ラウンドへ古い票を送らない。
- hostによる自動手番スキップ・相談移行・開票・中断・逆転判定・次ラウンド・終了にも捕捉した room/round/status の検査を行う。明示退出の不在判定・残存ゲストの投票集計、手動締め切り、まぎれ絵師不在時の不成立は従来どおり。新しい勝敗値を追加しない。
- 初回開始と次ラウンドの transaction は `applyLocally: false`。楽観的に round が描画されると自分の旧roundガードが再試行を中止するため、サーバー確定まで未確定roundを表示しない（独立レビューで確認・修正）。
- 監視中ゲストTTL2分とdone30秒の削除も `applyLocally: false` と捕捉参照・状態の再検査を使う。doneの予約取消を削除より先に行い、room消失時はホストもリスナー・タイマー・予約・sessionを片付ける。初回参加・保存復帰前の期限切れ削除は一時購読による通常transactionである。
- 退出は接続予約の終了を待ってからplayerを削除し、古い非同期処理は無効化する。オフラインでは取消完了まで退出が待機する場合がある。通常ゲーム画面に常設退出ボタンは増やさず、新しいゲスト切断オーバーレイと既存の待機・ホスト切断・doneの導線を使う。
- 旧ページのplayer全体remove予約は新版から取消できない。全員が新版を読み込んだ新しいルームから利用する。`presenceVersion` なしの旧guestは互換表示上は接続扱いだが保持保証対象外。ホストの自動復旧方式・rules・共有コード・他アプリは変更しない。
- 200行超の差分は、接続予約・描画原子化・ゲスト操作・世代無効化・退出・期限切れを片側だけ導入すると欠損／再生成や手番競合が残る不可分のライフサイクル変更のため。実SDK隔離検証と、意図的な遅延を置く補助VMは区別して記録する。
