# みらいの引き出し — アプリ固有仕様

## 目的・使用シーン

- room-K のオンラインメンタリング（1対1）で、メンターが画面共有しながら操作するオフラインツール。
- 世界にはいろんな入口があることを、引き出しをあけるように軽くながめる。1回10〜15分、引き出し3〜5個ひらく程度。
- **興味の入口を広げるツールであり、進路・職業選択のツールではない。** 何かを決めさせる・選ばせるための画面ではなく、「へえ、そんな世界あるんだ」で終わってよい。

## 最重要の設計方針

- **職業名を主役にしない。** 単位は「世界の入口」（海の世界・音の世界・つくる世界など22個）。「こんなことしてる人がいるよ」も職業名でなく活動で書く（例:「魚の名前を図鑑みたいに覚えてる人」）。
- **UI文言に「しょうらい」「しごと」「職業」「しんろ」「夢」を出さない。**「みらい」はアプリタイトルのみ。データ・文言を追加・変更するときも必ずこの禁止語チェックを通すこと。
- 反応は数値でなく3種類:「のぞいてみる」「あとで見る」「今はいい」。**3つは全部同格**で、「今はいい」に否定的な文言・演出・配色をしない（取り消し線・グレーアウト・残念系トースト禁止）。
- 目印は「のぞいてみる」「あとで見る」の引き出しにだけ小さく付く。**集計・件数表示はしない。**
- 「引き出し」の比喩は棚画面の説明一文（「引き出しみたいにならんでいるよ。押すと、中が見られるよ」）で**一度だけ説明**する。ボタン・見出しなどの操作文言は「開く」「中を見る」「一覧にもどる」の素直な動詞を使い、「あける」「たな」などの比喩の派生語を増やさない（challenge-tane の「たね」比喩と同じ整理。実機確認時のフィードバック反映）。
- UI・入口の文言は**通常表記（漢字まじり）**（2026-08-06 ユーザー判断で分かち書きから刷新。ルート AGENTS.md「表記トーン」参照。読めない子にはメンターが読み上げる。「つくる世界」「えがく世界」などかな書きが自然な入口名はそのまま）。

## 技術

- `index.html` + `app.js` + `style.css` の talk-card 型オフライン構成。Firebase 不使用。
- 永続化 API（localStorage / sessionStorage / IndexedDB / Cookie）は一切呼ばない。リロードで反応が消えるのは仕様。
- JSON は**書き出しのみ**（sakusen-kaigi 方式の任意機能）。読み込み（インポート）はない。エクスポートは Blob + `<a download>`、ファイル名 `hikidashi-memo_YYYY-MM-DD.json`。
- 書き出す内容は「のぞいてみる」「あとで見る」に入れた引き出しの `{ name, reaction }` のみ（`app: "mirai-hikidashi"`, `schemaVersion: 1`, `exportedAt` 付き）。「今はいい」は書き出さない。
- 共有 `../shared/css/design-system.css` と Material Symbols Rounded を使う。絵文字は禁止（引き出しのアイコンも Material Symbols から選ぶ）。
- CSS は `mh-` 接頭辞 + BEM。`.screen` / `.active` と `screen-xxx` 命名を使う。600px 以下でレスポンシブ。
- 状態は `const state = { reactions, currentScreen, currentDrawerId, dirty }` にまとめる。
- 動的 HTML への文字列挿入は静的データ由来でも必ず `esc()` を通す。
- 反応が付いていて未エクスポートのときだけ `beforeunload` で警告する。

## 画面フロー

```text
screen-shelf（引き出しの棚・グリッド）
  → 引き出しタップ / 「どれか あけてみる」（ランダム）
  → screen-drawer（中身 + 反応3ボタン + もどるボタン）
  → 反応を押す or もどる → screen-shelf
```

- ランダムボタンは未反応の引き出しを優先して選ぶ（全部に反応済みなら全体から）。
- 引き出しを開く演出は控えめ（0.22s のフェード+スライドのみ）。`prefers-reduced-motion` で無効化。
- 反応はあとから何度でも変えられる。変更に理由は求めない。
- 「たなにもどる（えらばなくてもOK）」で反応を付けずに戻れる。

## コンテンツデータ（DRAWERS）

- 引き出しは22個。各引き出し: `{ id, name, icon, peek(2〜3文), people(活動3〜4個), tries(家でできる入口1〜2個) }`。
- `tries` は動画・図鑑・窓からの観察程度に留め、**外出や購入を前提にしない**。
- 禁止: 学校・勉強・資格・受験の文脈、「なるためには」系の説明、年収・すごさランキング。
- 例示が誘導にならないよう、特定の引き出しをおすすめ扱いしない（並び順にも意味を持たせない）。

## 入れない機能（意図的に未実装）

- localStorage / sessionStorage / IndexedDB / Cookie。
- Firebase、外部 API、外部保存、JSON インポート。
- 職業名リスト、「なるためには」ガイド、適性診断的な集計。
- 件数表示、達成率、進捗バー、ランキング、バッジ。
- 「全部あけよう」系の促し、がんばれ系の応援文言、賞賛・残念演出。

## アクセシビリティ

- 引き出し・反応はすべて `<button>`。引き出しは `aria-label` で名前と現在の反応を読み上げる。
- 反応3ボタンは `role="radiogroup"` + `aria-checked`。選択状態は枠色 + 背景 + check アイコンで表す（色だけにしない）。
- 反応3ボタンには規約どおり ①②③ の丸数字を付ける（画面共有越しに「2番」と答えられるように）。棚の引き出しは名前で答えられるため番号なし。
- Tab / Enter / Space で操作でき、`:focus-visible` を明確に、タップターゲットは最小 44×44px。
- toast は `role="status"`。

## コンテンツガイドライン例外

- なし（共通ガイドラインに全面準拠）。
