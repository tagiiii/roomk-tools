# きょうの2たく（nitaku-board）

## 目的・使用シーン

MetaLife の自由スペースに常設する投票ボード。子どもが自分のスマホ・タブレット・PC で URL を開き、日替わりの2択お題にスタンプを置く。**メンターの進行なしで成立する**ことが前提で、マイクON参加とチャット参加が混在するため操作はすべてタップで完結する。

目的は「来た子が30秒で参加でき、前に来た子のスタンプが残っていることが会話の種になる気配のボード」。roomK のクローズドコミュニティ内でのみ URL を共有する。

## 技術スタック

- Realtime Database 単一ファイル構成（`index.html` のみ、`../shared/js/rtdb-utils.js` を参照）
- design-system.css / Material Symbols Rounded（絵文字禁止）
- CSS 接頭辞: `nb-`（BEM）
- レスポンシブ: 600px 以下対応。スマホ縦持ちを第一に設計

## 既存ガイドライン・共通規約からの例外（常設・非同期型）

このアプリは「セッション終了後にデータを削除する」共通原則の**意図的な例外**。スタンプが残り続けることが価値（気配）なので、セッション単位の削除は行わない。代わりに以下の掃除ルールで無限に増えないようにする。

### 掃除ルール

- アプリ読み込み時（および日付またぎ検知時）に、**今日から数えて 7 日より古い日付キーを削除する**
- セキュリティルールは `$roomId` 単位のため、`nitaku_rooms` 直下の一覧クエリは **permission_denied になる**（実測済み）。そのため存在する日付キーを `nitaku_rooms/_meta/days/{YYYY-MM-DD}: true` のインデックスで管理し、掃除はこのインデックスを読んで古いキーを multi-path update（`{日付キー: null, _meta/days/日付キー: null}`）で消す。`_meta` 自体もワイルドカードの `$roomId` として読み書きできる
- 日付キーの登録（`registerDay`）は起動時と日付またぎ検知時に行う（投票の有無によらず冪等な `set(true)`）
- 「誰かが開くたびに自動でかたづく」方式。cron は使えないため、長期間誰も開かなければ残るが、次に誰かが開いた時点で消える
- 保持されるのは最大で「今日 + 過去7日」の 8 キー + `_meta`

### 上限

- 1 日あたり votes は **100 件まで**。上限チェックと追加は votes ノードへの `transaction()` で原子的に行い、超えたら「きょうはまんいん！また明日」を表示する

### そのほかの共通規約との差分

- **ルームコードなし**。パスは日付キー方式 `nitaku_rooms/{YYYY-MM-DD}/votes/{pushId}`。日付キーが `$app_rooms/$roomId` ワイルドカードの `$roomId` に当たるため、既存セキュリティルールのまま動く
- **ホスト／ゲストの概念がない**ため、`hostConnected` / `onDisconnect` / `ORPHAN_TTL_MS` / status 遷移は持たない。状態管理オブジェクト `state` も `role` / `roomCode` を持たない
- 再接続フローはなく、sessionStorage は「きょう自分が置いたスタンプの記憶」にのみ使う

## データ構造

```
nitaku_rooms/
  _meta/
    days/
      {YYYY-MM-DD}: true   ← 存在する日付キーのインデックス（掃除用）
  {YYYY-MM-DD}/            ← JST 固定の日付キー（端末タイムゾーン非依存）
    votes/
      {pushId}: {
        area: 1 | 2 | 3 | 4,   // ①お題A ②お題B ③どっちも ④どっちでもない
        icon: string,           // Material Symbols 名（12種の許可リスト内）
        color: string,          // HEX（6色の許可リスト内）
        name: string,           // 0〜8文字。空なら「だれか」と表示
        comment: string,        // 0〜20文字。完全に任意
        createdAt: number,      // RoomkRTDB.now()（サーバー時刻補正済み）
      }
```

- 日付・タイムスタンプは `RoomkRTDB.initServerTime(db)` / `RoomkRTDB.now()` を使い、端末時計に依存しない。起動時は `.info/serverTimeOffset` の初回取得を待ってから日付キーを決める
- **起動時は匿名認証の完了を `await` してから DB にアクセスする**。認証前にリスナーを張ると permission_denied でリスナーが死ぬ（実測済み）
- 日付キーは **JST 固定**（`now() + 9時間` を ISO 化）。どの端末でも同じ日に同じキー・同じお題になる

## お題の決め方

- 2択お題 126 問を JS 内の `TOPICS` 配列で保持
- 日付文字列の djb2 ハッシュ `% TOPICS.length` で決定論的に 1 問選ぶ。同じ日はどの端末でも同じお題になり、乱数の保存は不要
- トーンは「どちらを選んでも楽しい軽い2択」のみ。**禁止**: 学校・勉強・宿題・成績・登校の連想、恋愛、怖い話・死、優劣や正誤がつく2択、個人的な事情（家族構成・友だちの有無など）に触れる2択

## 画面構成・フロー

1. 開いたら即、今日のお題とボードが見える（トップ画面・説明画面なし）
2. 投票エリアは 4 つ全部同格: 「① お題A」「② お題B」「③ どっちも」「④ どっちでもない」。丸数字は共通規約の `NUMBERS = ['①','②','③','④']`
3. エリアをタップ → ピッカー（アイコン12種 × 色6色・ニックネーム任意8文字・ひとこと任意20文字）→「ここにおく」
4. すでに自分のスタンプがある日に別エリアをタップすると**おひっこし（移動）**。自分のスタンプをタップすると詳細モーダルから削除できる
5. 「まえの日 / つぎの日」で過去 7 日分をめくって見られる（過去日は**見るだけ**・投票不可）

## 本人確認について（仕様として明記）

- 「自分のスタンプ」は sessionStorage に覚えた pushId だけで判定する**緩い仕組み**であり、厳密な本人確認はしない。タブを閉じれば自分のスタンプも操作できなくなるが、それで困らない設計（翌日また置けばよい）
- `?mentor=1` が付いているときだけ全スタンプに削除ボタンを表示する。これは**簡易的な表示切替であり認証ではない**。クローズドコミュニティ内での性善説運用

## 心理的安全設計（最重要）

- **見るだけで帰るのも正式な使い方**。投票を促すポップアップ・未投票の強調は出さない（「ここにおく」の控えめなヒント表示のみ・全エリア同格）
- 「③どっちも」「④どっちでもない」は①②と同じ大きさ・同じ扱い
- **人数・パーセント・棒グラフ・多い方の強調は一切表示しない**。スタンプが「ならんでいる」だけの画面にする
- ひとこと欄は完全に任意。空でも投稿できる

## 入れない機能（意図的に未実装）

- 集計・勝敗・多数派の演出
- 投票のリマインド・催促
- 過去日への投票・編集
- 厳密な本人認証・重複投票の厳密な防止

## XSS・入力の扱い

- ニックネーム・ひとことは `innerHTML` 挿入時に必ず `esc()`（`'` → `&#39;` 含む）を通す
- `icon` / `color` は DB から来た値でも**許可リスト照合**（`sanitizeIcon` / `sanitizeColor`）してから style / ligature に使う
- 文字数は `maxlength` に加えて**保存時にも** `slice()` で切り詰める（name 8 / comment 20）
