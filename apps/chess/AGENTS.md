# チェス 仕様書

## 目的・使用シーン

2人で白と黒に分かれて交互に駒を動かし、相手のキングをチェックメイトにしたら勝ちの、定番の盤ゲーム。

- **core value**: ルールを知らない子でも、補助（動ける所・駒の名前と動き方・おすすめの手）を見ながら、それぞれの端末で国際ルールどおりのチェスを指せる。動けない所を押すと、そのわけを出す。対戦しない子も、自分の画面や「みんなにみせる画面」で対局を見られる
- 対象: 小学校中学年〜中学生。ボドゲクラブ・ひろば・作戦会議（`data-scenes="bodoge hiroba sakusen"`。メンターと子どもの1対1でも遊べる）
- 対戦は2人。観戦はゲスト20人まで（＋端末なしの参加者4人まで）
- 所要時間: 10〜40分

> 経緯: 2026-11-18 スタッフから「チェスがほしい」という意見。オーナーの依頼は「麻雀のときみたいにルールがわからない人でも参加できるように」。オーナーが選んだこと: ルールは**正式ルールだけ**（かんたんルールは作らない）・**いきなり本体に**（将棋と同じ作りのルーム型。`database.rules.json` の `chess_rooms` もこの回答で承認）・補助は**動ける所を見せる／駒の名前と動き方／おすすめの手**の3つ。
> 名前「チェス」は伝統ゲームの一般名称なので、命名の例外（リバーシ・将棋と同じ。`docs/development/app-registration.md`「アプリ名のつけかた」）に当たる。早見表では系統ラベル「定番の盤ゲーム」で紹介する。

値はツール一覧（`apps/index.html`）のカードの札・`data-scenes`・`data-speech`・`data-self` と同じにする。変えるときはカードと一緒に変える。子ども向けの画面には出さない。

| 項目 | 値 |
|---|---|
| 人数 | 1人〜（CPU と対戦できる。ルームの対戦は2人で、席の片方を CPU にもできる） |
| 目安時間 | 10〜40分 |
| 利用シーン | ボドゲクラブ・ひろば・作戦会議 |
| 話す量 | 選ぶだけ・話さなくてよい |

## ルール（engine.js）

国際チェス連盟（FIDE）のルールに合わせる。盤のルールは `engine.js`（画面と通信に触らない。node でも読める）。テストは `tests/chess/engine.test.cjs`（はじめの局面などからの手の数を既知の値（perft）と照合）。

| 項目 | 内容 |
|---|---|
| はじめの並び | ふつうの並び。白が先に指す。白の人の画面は白が手前、黒の席の人の画面は黒が手前 |
| 指せない手 | 自分のキングが取られる形になる手（チェックをよけない・ピンされた駒を動かす・キングをねらわれた所へ動かす）は指せない（正式ルール。将棋の「うっかりの手を指せる」はない）。押したら理由を画面に出す（`whyIllegal`。駒ごとの動けないわけ・跳びこえ・ポーンのななめ・キャスリングできないわけ4つ） |
| キャスリング | キングを横に2マス動かす手で表す（ルークは自動で動く）。キングとルークが動いていない・間に駒がない・チェックされていない・通るマスと行き先がねらわれていないとき |
| アンパッサン | 相手のポーンが2マス進んだ直後だけ |
| 成る | ポーンが奥まで進むと「ポーンを何にする？」のダイアログ（クイーン・ルーク・ビショップ・ナイト）。「やめる」・Esc で指さない（選んでいたポーンも選ばないにもどす） |
| 勝ち | チェックメイト・投了・時間切れ（相手の駒がキングだけなら、時間切れでも引き分け） |
| 引き分け | ステイルメイト・同じ形（盤・番・キャスリングできるか・アンパッサンで取れるか）が3回・50手（両方で100手）のあいだポーンが動かず駒も取られない・どちらも駒が足りずメイトにできない（キングだけ・キングとビショップかナイト1つ・同じ色のマスのビショップだけ） |
| 表記 | 日本語（「ナイト g1→f3（ポーンを取った）」「キャスリング（キングの側）」）と、国際式（Nf3・exd5・O-O・e8=Q・+・#）を並べて出す。同じ駒が2つそこへ行けるときは Nbd2 のように区別する |
| 場所の言い方 | 盤の左に段の数字（1〜8）、下に列の文字（a〜h）。盤の向きを変えると、どちらも反対から並ぶ |

- **同じ形3回・50手は、本来は申し出て引き分けにするもの（申し出がなければ続く）**。子どもどうしでは申し出の手順が分かりにくく、だらだら続きやすいので、自動で引き分けにした（はじめは AI の判断。2026-11-18 オーナーが「自動のままでいい」と確定）
- 引き分けの申し出（合意の引き分け）・5回・75手の自動の引き分けは入れていない（上の自動の引き分けで先に終わる）
- 取った駒は、相手の駒を札に小さく出す（はじめの駒の数とくらべて数える。成った駒の分もそろえる）

## 補助（はじめての人向け）

2026-11-18 オーナーが選んだ3つ。はじめの値は、ルールを知らない人が遊べるように全部オン（AI の判断）。

| 項目 | 中身 | はじめの値 |
|---|---|---|
| 補助を使う人 | ふたりとも／白だけ／黒だけ／使わない。その人の番のときだけ出る（ハンデにも使える） | ふたりとも |
| 動ける所を見せる | 駒を選ぶと、動ける所に点（取れる所・アンパッサンで取れる所は輪）が出る | オン |
| 駒の名前と動き方を出す | 盤の駒の下に名前（キング・クイーン・ルーク・ビショップ・ナイト・ポーン）。名前は、だれか1人でも使うなら全部の駒に出す（相手の駒の名前も分かるように）。番の人が駒を選ぶと、盤の下の欄にその駒の動き方と、いまできる特別な手（キャスリング・アンパッサン・成る）の説明が出る | オン |
| おすすめの手を見られるようにする | 番の人に「おすすめの手を見る」。押すと CPU（`cpuMove` の `hint`。3手先まで・0.9秒まで・くじなし）が考えた手の2マスを緑の枠で光らせ、その駒を選んだ形にする（光っているマスを押すと指せる）。ルームには書かない（その端末だけ）。押した回数は `hint` で数える | オン |

- 補助がなくても、直前の手（動かした先を濃く・元の所を薄く）・チェック（キングのマスを赤く・「チェック」の札。メイトのあとも赤いまま）・番・指せない理由・相手の駒を押したときの知らせ（「それは相手の駒だよ」）は、いつも出す
- 補助はホストが待合室の「設定を変える」で決め、遊んでいる間も「補助の設定」で変えられる（1台の画面も同じ）
- 「もう一回」「白と黒を入れかえる」では、「白だけ・黒だけ」も入れかえる（補助が人についていく）
- 将棋にある「駒に動ける向きを出す」「取られそうな駒」「王が取られる手を止める」は入れていない（オーナーが選ばなかった。止める補助は、正式ルールで指せないので要らない）

## 端末なしの参加者・ホストも対戦するか

将棋（リバーシ）と同じ。待合室でホストが「端末なしの参加者を足す」（はじめる前だけ・4人まで）。その人の番はホストが代わりに指す。「端末なし」の印はホストの画面にだけ出す。ホストは自分で席に選んだときだけ対戦する（入った順にゲストが白・黒へ）。

## Firebase データ構造（Realtime Database）

```
chess_rooms/{roomCode}/
  ├── status:             'waiting' | 'play'
  ├── host / hostUid / hostConnected / hostDisconnectedAt / createdAt / lastGameId
  ├── aid:                { who: 'both'|'w'|'b'|'none', spots, names, hint }   # 補助（いつでも変えられる）
  ├── clock:              { m: 持ち時間(分), b: 秒読み(秒) }   # 待合室で変更。なしなら置かない
  ├── seats:              { w: 名前, b: 名前 }   # 待合室で選んだ席（w 白・b 黒）。CPU は '#cpu:weak'|'#cpu:normal'|'#cpu:strong'
  ├── players/{name}:     { isHost, uid, joinedAt }
  ├── proxies/{name}:     { joinedAt }           # 端末なしの参加者
  └── game/                                       # 「はじめる」で作り、待合室にもどると消す
       ├── id, seats: {w, b}, uids: {w?, b?}, proxy: {w?: true, b?: true}
       ├── moves: [{ f: 動かす前のます, t: 動かした先, q?: ポーンがなった駒 'Q'|'R'|'B'|'N' }...]
       ├── resign: 'w'|'b'（投了した人）, timeout: 'w'|'b'（時間が切れた人）
       ├── clock: { m, b, used: { w, b }: 使った持ち時間(ms), at: いまの番がはじまった時刻 }   # 持ち時間なしなら置かない
       ├── rev: 局面が変わるたびに増える番号（指す・投了・1手もどす）。古い操作の照合に使う
       └── ended: 一度でもおわった（もどしても消さない。finish を1対局に1回だけ数える）
```

- ますの添字は 行×8＋列（行0 が 8段目、列0 が a の列）
- ルームには指した手の記録だけを置き、局面（盤・番・キャスリング・アンパッサン・同じ形の数・チェック・おわり）は各端末で `engine.js` の手順で作りなおす（`app.js` の `engineOf`。作った局面を覚えておき、1手ずつ足す）
- 読めない手（合法でない手・壊れた値）があれば、そこまでの局面にする。指す・もどすときは、読める手までにそろえて書く
- 時計の `b`（秒読み）と、席の `b`（黒）は別の場所の名前（`clock.b` と `seats.b`・`clock.used.b`）

## transaction 設計・接続・切断・再接続・終了とデータ削除・みんなにみせる画面・持ち時間・ルームの CPU

将棋と同じ（`apps/shogi/AGENTS.md` の各節）。ちがう所:

- 入玉宣言の操作はない。指すときは `E.legalMoves(G)`（正式ルールの合法手）にある手だけを書く
- 1手もどすは、投了があればそれを消し、なければ最後の手を消す（CPU と対戦しているときは人の番までもどす）
- 公認バリアント「**ふりかえり画面滞在中は削除しない**」（「もう一回」のため）。削除経路はホストの「ルームを閉じる」・ホスト切断＋2分・次回アクセス時の期限切れ掃除
- ORPHAN_TTL_MS = 2分・serverTimeOffset・sessionStorage 再接続・認証失敗の知らせも将棋と同じ

## CPU（1台の画面とルームの席）

| 項目 | 内容 |
|---|---|
| 強さ | `engine.js` の `cpuMove`。よわい＝指したあとの形だけを見る（相手の返し手を読まないので、取られる所にも出る。ばらつき大）／ふつう＝2手先まで＋取り合いの読み（0.7秒まで）／つよい＝時間の許すかぎり5手先まで（1.5秒で打ち切り） |
| 点数 | 駒の価値（ポーン100・ナイト320・ビショップ330・ルーク500・クイーン900）・中央に出たナイトとビショップ・前に出たポーン・序盤中盤はキングを奥に（終盤は中央へ） |
| 読み | 速さのため自分のキングを取られる手もふくめた形で読み、いちばん上の手だけは正しい合法手から選ぶ。どの手でもキングが取られる形は、チェックされていなければステイルメイト（0点）として読む。指したあとにメイト・ステイルメイトになるかは、正しく調べる |
| 成る | 読みの中で4つとも調べる（ふつうはクイーン） |
| ほかは将棋と同じ | 0.7秒待ってから考える・CPU の番は時計を止める・ホストの通信が切れている間は指さない・CPU どうしにはできない・CPU は投了しない |

## 利用回数（stats.js）

「1回」は1対局。将棋と同じ項目（`room-create`・`start`・`players-2`・`finish`・`again`・`local-start`・`local-finish`・`clock`・`room-cpu`）から盤の大きさ（`board-5`・`board-9`）を除き、`hint`（「おすすめの手を見る」を押して手が出た。その端末）を足した。

## 意図的な逸脱

- **分割構成の RTDB アプリ**（将棋・リバーシと同じ）。engine.js は DOM に触らない
- **ホスト以外も進行の一部を行う**: 席の人が指す・投了する・最後の手を確定させた端末が `finish` を数える・対局の記録が壊れたらホストの端末が待合室へもどす
- **観戦は参加者として players に入る**（席に入らない人）。見るだけの画面（書き込みゼロ）は別にある
- **終了後の自動削除なし**（公認バリアント「ふりかえり画面滞在中は削除しない」）
- **端末なしの参加者は在室を持たない**（`proxies`）
- **勝ち負けを出す**（定番の対戦ゲームの結果。対戦成績の記録や順位はしない）
- **同じ形3回・50手を自動で引き分けにする**（本来は申し出。2026-11-18 オーナー確定。上の「ルール」）

## 入れない機能

- 音（駒音も鳴らさない）
- かんたんルール（キングを取ったら勝ち など。オーナーが「正式ルールだけ」を選んだ）
- 小さい盤（オーナーが選ばなかった）
- 引き分けの申し出・待ったのやりとり（「1手もどす」はホストと1台の画面だけ）
- 持ち時間の一時停止・フィッシャー（1手ごとに足す方式）
- 棋譜の保存・書き出し、対戦成績の記録、順位、レーティング
- 対局中の新しい対戦者（途中から入った人は観戦）

## 既知の制約（v1）

- 駒の名前は、375px の画面では 8px ほどの小さい字になる（マスが 40px ほどのため）。くわしくは盤の下の「駒の説明」の欄で読む
- おすすめの手を考える間（0.9秒まで）は、その端末の画面が止まる。CPU の「つよい」も、ホストの端末が考える間（1.5秒まで）止まる
- 同じ名前・同じ匿名IDのタブが2つ開いていると、両方が同じ `players/{name}` に切断予約を張る（ほかのルーム型ゲームと共通）

## メンター向けの心得（画面には出さない）

- ルールを知らない子には、補助を全部オンのまま、まず CPU（よわい）か メンターと1対1で。駒を押すと動き方が出るので、「押してみて、点のある所に動かしてみよう」から始める
- 迷っている子には「おすすめの手を見る」をすすめる。おすすめどおりに指さなくてもよいことも伝える
- 動けない所を押すと理由が出るので、まちがえても大丈夫と伝える。キャスリング・アンパッサン・成るは、出てきたときに盤の下の説明を一緒に読む
- 慣れてきたら「白だけ」などにしてハンデとして使う。時間がかかるので、セッションの残り時間を見て持ち時間を選ぶ
- 投了は無理に言わせない。「この対局をやめる」で区切ってもよい。勝ち負けで落ち込む子には、うまく取れた・追いつめかけた場面をほめる
